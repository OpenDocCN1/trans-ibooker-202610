## C.2 设置 Micrometer 和 Prometheus

Spring Boot Actuator 提供了用于监控应用程序的指标。然而，如果我们想要获得更精确的应用程序指标，并获取这些指标，就需要使用 Micrometer 和 Prometheus 等额外工具。

### C.2.1 理解 Micrometer 和 Prometheus

Micrometer 是一个提供应用程序指标的库，其设计初衷是在应用程序的指标收集活动中几乎不增加额外开销。Micrometer 还允许将指标数据导出到任何最流行的监控系统中。

使用 Micrometer，应用程序抽象了所使用的指标系统，如果将来需要，可以更换。另外，Prometheus 是最流行的监控系统之一，它负责收集和存储应用程序暴露的指标数据。它提供了一种数据查询语言，其他应用程序可以通过它来在图表和控制面板中可视化指标。Grafana 是允许查看 Prometheus 提供的数据的工具之一，但 Micrometer 也可以与其他监控系统一起使用，如 Datadog、SignalFx、Influx、New Relic、Google Stackdriver、Wavefront 等。

对于微服务使用 Spring Boot 的一个优势是，它允许我们选择一个或多个包含不同视图的监控系统，以分析和展示我们的结果。借助 Micrometer，我们能够度量各种指标，从而了解我们系统的整体性能；通过单个应用程序的多个组件或集群实例；等等。以下列表包含我们可以通过 Micrometer 获得的一些指标：

- 与垃圾回收相关的统计信息
- CPU 使用率
- 内存使用率
- 线程利用率
- 数据源使用情况
- Spring MVC 请求延迟
- Kafka 连接工厂
- 缓存
- Logback 中记录的事件数量
- 运行时间

在本书中，我们选择 Prometheus 作为监控系统，因为它可以与 Micrometer 和 Spring Boot 2 简单集成。Prometheus 是一个内存中的维度时间序列数据库，也是一个监控和警报系统。当我们谈到存储时间序列数据时，指的是按时间顺序存储数据并随时间测量变量。专注于时间序列的数据库在存储和查询这些数据方面异常高效。Prometheus 的主要目标是作为拉取模型工作，定期从应用程序实例中抓取指标。Prometheus 的一些主要特性如下：

- *灵活的查询语言*——它包含一种自定义查询语言，使我们能够直接地查询数据。
- *高效的存储*——它将时间序列高效地存储在内存和本地磁盘上。
- *多维数据模型*——所有时间序列都通过指标名称和一组键值对来标识。
- *多种集成*——它允许与 Docker、JMX 等第三方集成。

### C.2.2 实现 Micrometer 和 Prometheus

要使用 Spring Boot 2 将数据导出到 Micrometer 和 Prometheus，我们需要添加以下依赖项。（注意，Prometheus 随 Micrometer 包一起提供。）

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-core</artifactId>
</dependency>
```

在本书中，我们为所有微服务启用了所有默认的 Actuator 端点。如果您只想暴露 Prometheus 端点，则应在许可证和组织服务应用程序属性中包含以下属性：

```
management.endpoints.web.exposure.include=prometheus
```
