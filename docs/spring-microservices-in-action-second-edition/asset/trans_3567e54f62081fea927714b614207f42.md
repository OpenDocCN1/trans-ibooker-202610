## 监控

当我们谈论微服务时，监控过程至关重要。微服务是大型复杂分布式系统的一部分，请记住，系统越是分布式，就越难发现和解决问题。想象一下，我们有一个包含数百个微服务的架构，其中一个微服务正在影响其他服务的性能。如果我们没有实施合适的监控过程，如何知道哪个服务不稳定？为了解决这个问题，在附录 C 中，我们将解释如何使用以下工具在我们的架构中实现良好的监控系统。图 A.7 展示了 Micrometer、Prometheus 和 Grafana 之间的交互。

- Micrometer（https://micrometer.io/）是 Spring Boot 2 中的默认指标库，允许我们获取应用程序指标以及 JVM 指标，如垃圾回收、内存池等。
- Prometheus（https://prometheus.io/）是一个开源监控和告警系统，将所有数据存储为时间序列。
- Grafana（https://grafana.com/）是一个指标分析平台，无论数据存储在哪里，都可以让你查询、可视化和理解数据。

## 日志记录

每次想到日志时，都要想到*分布式追踪*。分布式追踪通过定位微服务架构中故障发生的位置，帮助我们理解和调试微服务。

在第 11 章中，我们解释了如何使用 Spring Cloud 实现这一点。在我们架构中发出的请求的可追溯性，是讨论微服务时出现的另一个“新”技术（Spring Cloud Sleuth）场景。在单体架构中，到达应用程序的大多数请求都在同一个应用程序内得到解决。不遵循这一规则的请求是与数据库或其他服务交互的请求。然而，在微服务架构（例如 Spring Cloud）中，我们面对的是一个由多个应用程序组成的环境，一个客户端请求可能经过多个应用程序才能得到响应。

在微服务架构中，我们如何跟踪该请求的路径？我们可以关联一个唯一的请求标识符，然后将其传播到所有调用中，并添加一个中央日志收集系统来查看该客户端请求的所有条目。

## API 网关

API 网关是一种 API REST 接口，为一组微服务和/或已定义的第三方 API 提供中心访问点。换句话说，Spring Cloud API Gateway 本质上将客户端看到的接口与微服务实现解耦。当我们希望避免向外部客户端暴露内部服务时，这尤其有用。请记住，该系统不仅充当网关，你还可以添加其他功能，例如：

- 身份验证和授权（OAuth2）
- 抵御威胁（DoS、代码注入等）
- 分析和监督（哪些人、何时以及如何使用 API）
- 监控进出流量

# 附录 B
OAuth2 授权类型

读完第 9 章后，你可能会觉得 OAuth2 看起来并不太复杂。毕竟，你有一个身份验证服务，它检查用户凭据并向用户返回令牌。反过来，每当用户想要调用受 OAuth2 服务器保护的服务时，都可以出示该令牌。

由于 Web 和基于云的应用程序具有互联的特性，用户开始期望能够在不同服务拥有的各种应用程序之间安全地共享数据并集成功能。这从安全角度来看是一个独特的挑战，因为你希望在不同应用程序之间进行集成，同时又不会强迫用户向每个想要集成的应用程序分享他们的凭据。

OAuth2 是一个灵活授权框架，它提供了多种机制，让应用程序无需强迫用户分享凭据即可对用户进行身份验证和授权。不幸的是，这也是 OAuth2 被认为复杂的原因之一。这些身份验证机制被称为*身份验证授权*。OAuth2 有四种形式的身份验证授权，客户端应用程序可以使用它们对用户进行身份验证、接收访问令牌，然后验证该令牌。这些授权类型是

- 密码模式
- 客户端凭证模式
- 授权码模式
- 隐式模式

在接下来的小节中，我们将详细介绍这每种 OAuth2 授权流程执行期间发生的行为。我们还会讨论何时使用某一种授权类型而不是另一种。
