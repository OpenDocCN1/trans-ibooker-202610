
## `std::unordered_set` 与 Bloom Filter 性能分析

`std::unordered_set` 执行一次哈希操作，或许再进行几次内存访问，即可到达存储的值。而我们使用的 `Bloom filter` 执行三次哈希操作和三次内存访问。从本质上讲，`Bloom filter` 完成的工作量大于哈希表。由于我们的字典仅包含 31,870 个单词，`Bloom filter` 的缓存优势荡然无存。这是另一个例子，说明传统的数据结构分析因缓存机制而与实际结果不符。

### 使用更大或更小容量的 Bloom Filter 有何影响？

当使用更大容量时，哈希冲突和误报率降低，但缓存行为变差。反之，当使用更小容量时，哈希冲突和误报率增加，但缓存行为改善。

### 使用更少或更多哈希函数会发生什么？

使用的哈希函数越多，误报率越低，反之亦然。

### 在什么条件下此版本会比 `Speller2.cpp` 中的版本快得多？

当测试几个位的成本低于在哈希表中访问值的成本时，`Bloom filter` 效果最好。只有当 `Bloom filter` 的位完全适合缓存而字典不适合时，这一条件才成立。
