## 短路逻辑运算符

`&&` 和 `||` 逻辑运算符是**短路**的，这意味着：

*   如果 `||` 运算符的左侧为 `true`，则不计算右侧。
*   如果 `&&` 运算符的左侧为 `false`，则不计算右侧。

将更不可能（或开销更小）的表达式放在左侧，可以减少需要完成的工作量。在下一节中，我们将通过一个练习来学习如何最优地编写逻辑表达式。

```cpp
const uint64_t N = 100000000;

uint64_t sum1()
{
    TIME_IT;
    uint64_t ret = 0;
    for (uint64_t b = 0; b < N; ++b)
    {
        if (b % 3 == 2 || b < N/2)
        {
            ret += b;
        }
    }
    return ret;
}
```

4.  现在，定义另一个名为 `sum2()` 的函数。它必须包含与 `sum1()` 相同的逻辑。唯一的变化是反转 `if` 语句中条件表达式的顺序。编写以下代码实现：

```cpp
uint64_t sum2()
{
    TIME_IT;
    uint64_t ret = 0;
    for (uint64_t b = 0; b < N; ++b)
    {
        if (b < N/2 || b % 3 == 2)
        {
            ret += b;
        }
    }
    return ret;
}
```

注意在 `sum2` 函数中，`b < N/2` 条件有一半的时间为 `true`。因此，第二个条件 `b % 3 == 2` 只在一半的迭代中被计算。如果为简单起见假设两个条件各耗 1 个时间单位，`sum2()` 的总耗时为 `N/2 + (2 * N/2) = N * 3/2`。对于 `sum1()` 函数，左侧条件只有 33% 的时间为 `true`，剩下 66% 的时间两个条件都会被计算。因此估计耗时为 `N/3 + (2 * N * 2/3) = N * 5/3`。我们预期 `sum1` 和 `sum2` 的耗时比为 `5/3` 对 `3/2` —— 即 `sum1` 慢 **11%**。

}

## 分支预测

现代处理器使用流水线架构，类似于工厂流水线，指令沿着流水线流动并由各个工人同时处理。每个时钟周期后，指令移动到流水线的下一阶段。这意味着虽然每条指令从开始到结束可能需要许多周期，但整体吞吐量是每周期完成一条指令。

缺点在于，如果遇到条件分支指令，CPU 不知道该加载哪组后续指令（因为有两种可能的替代方案）。这种情况称为**流水线停顿**，处理器必须等待分支条件完全计算出来，从而浪费宝贵的周期。

为了缓解此问题，现代处理器使用**分支预测**——它们尝试预测分支的走向。随着分支被遇到的次数增多，预测器对分支可能走向的信心也会增强。

尽管如此，CPU 并非全知全能。如果它开始加载某预测分支的指令，但后来条件分支实际上走向了另一条路，则分支指令之后的整个流水线必须被清空，并从头加载实际分支。分支指令下游“流水线”上完成的所有工作都必须丢弃，任何更改都需要撤销。

这是性能的主要瓶颈，但可以避免——最简单的方法是确保分支尽可能总是走同一个方向——就像循环一样。
