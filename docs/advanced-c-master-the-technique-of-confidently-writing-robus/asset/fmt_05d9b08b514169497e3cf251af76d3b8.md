
虽然 **CMake** 有助于管理项目及其依赖项，但体验仍远未达到高级语言的水平——在高级语言中，你只需列出想要使用的库及其版本，其他一切都会自动处理。使用 CMake 时，你仍需负责在开发环境中正确安装库，并需为每个库使用兼容的版本。在拥有庞大包管理器的主流 Linux 发行版中，你可以轻松安装大多数流行库的二进制版本。不过，有时你可能不得不自行编译并安装库。这是 C++ 开发者体验的一部分，你将通过深入了解所选开发平台来积累经验。在此，我们将更多地关注如何正确设置 CMake 项目，包括理解并解决与库相关的问题。

## 构建 CMake 项目

C++ 项目的事实标准是使用 CMake 来组织和构建项目。这里我们将使用一个基本模板项目作为起点。以下是示例模板的文件夹结构：

![图 1.1：示例模板的文件夹结构](image/C14508_01_01.jpg)

**图 1.1：示例模板的文件夹结构**

在上图中，`.gitignore` 文件列出了不应添加到 `git` 版本控制系统的文件模式。这些被忽略的文件包括构建过程的输出，它们是在本地创建的，不应在计算机间共享。

`include` 和 `src` 文件夹中的文件是实际的 C++ 源文件，`CMakeLists.txt` 文件是 CMake 脚本文件，它通过处理**源代码编译规则**、**库依赖项**和其他项目设置将项目粘合在一起。CMake 规则是高层的、平台无关的规则。CMake 利用它们为不同平台创建各种类型的 `make` 文件。

使用 CMake 构建项目是一个两步过程。首先，我们让 CMake 为原生构建系统生成平台相关的配置文件，该系统将编译并构建项目。然后，我们使用生成的文件来构建项目。CMake 可为其生成配置文件的平台相关构建系统包括 `UNIX Makefiles`、`Ninja build files`、`NMake Makefiles` 和 `MinGW Makefiles`。此处的选择取决于所用平台、这些工具的可用性以及个人偏好。`UNIX Makefiles` 是 `Unix` 和 `Linux` 的事实标准，而 `NMake` 是其 `Windows` 和 `Visual Studio` 对应物。另一方面，`MinGW` 是 `Windows` 中类 `Unix` 的环境，其中也使用 `Makefiles`。`Ninja` 是一个现代构建系统，与其他构建系统相比提供了卓越的速度，并支持多平台，我们选择在此使用它。此外，除了这些命令行构建系统，我们还可以为 `Visual Studio`、`XCode`、`Eclipse CDT` 等生成 IDE 项目，并在 IDE 内部构建项目。因此，`CMake` 是一个元工具，它将为实际构建项目的另一个系统创建配置文件。在下一节中，我们将完成一个练习，使用 `CMake` 生成 `Ninja build files`。

## 练习 1：使用 CMake 生成 Ninja 构建文件

在本练习中，我们将使用 `CMake` 生成 `Ninja build files`，它们用于构建 C++ 项目。我们将首先从 `git` 仓库下载源代码，并使用 CMake 和 Ninja 进行构建。本练习的目的是使用 CMake 生成 Ninja 构建文件，构建项目，然后运行它们。

让我们解释一下上述命令的各部分。使用 `-Bbuild`，我们告诉 CMake 使用 `build` 文件夹生成构建产物。由于该文件夹不存在，CMake 将创建它。使用 `-H.`，我们告诉 CMake 使用当前文件夹作为源。通过使用单独的 `build` 文件夹，我们将保持源文件整洁，所有构建产物将位于 `build` 文件夹中，该文件夹因 `.gitignore` 文件而被 Git 忽略。使用 `-GNinja`，我们告诉 CMake 使用 Ninja 构建系统。
