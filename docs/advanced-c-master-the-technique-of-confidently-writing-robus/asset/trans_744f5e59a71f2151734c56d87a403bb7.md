## 活动 1：优化拼写检查算法

在本活动中，我们将开发一个简单的拼写检查演示，并尝试逐步使其更快。您可以使用骨架文件 `Speller.cpp` 作为起点。执行以下步骤以实现此活动：

   ```
   set<string> setDict(vecDict.begin(), vecDict.end());
   ```

2. 遍历文本单词，并使用 `set::count()` 方法检查不在字典中的单词。将拼写错误的单词添加到结果向量中：

7. 对于第三个也是最终版本，即 `Speller3.cpp`，我们将使用布隆过滤器。首先定义一个基于 `BKDR` 函数的哈希函数。添加以下代码以实现这一点：

   ```
   const size_t SIZE = 16777215;

   template<size_t SEED> size_t hasher(const string &s)
   {
       size_t h = 0;
       size_t len = s.size();
       for(size_t i = 0; i < len; i++)
       {
           h = h * SEED + s[i];
       }
       return h & SIZE;
   }
   ```

   这里，我们使用了一个整数模板参数，以便我们可以用相同的代码创建任意数量的不同哈希函数。注意 `16777215` 常量的使用，它等于 `2^24 – 1`。这让我们可以使用快速的按位与运算符，而不是取模运算符，以使哈希后的整数小于 `SIZE`。如果您想更改大小，请将其保持为 2 的幂减 1。

8. 接下来，让我们在 `getMisspelt()` 中声明一个用于布隆过滤器的 `vector<bool>`，并用字典中的单词填充它。使用三个哈希函数。`BKDR` 哈希可以使用 `131`、`3131`、`31313` 等值作为种子。添加以下代码以实现这一点：

   ```
   vector<bool> m_Bloom;
   m_Bloom.resize(SIZE);

   for(auto i = vecDict.begin(); i != vecDict.end(); ++i)
   {
       m_Bloom[hasher<131>(*i)] = true;
       m_Bloom[hasher<3131>(*i)] = true;
       m_Bloom[hasher<31313>(*i)] = true;
   }
   ```

9. 编写以下代码以创建一个检查单词的循环：

   ```
   for(int i = 0; i < vecText.size(); ++i)
   {
       const string &s = vecText[i];
       bool hasNoBloom =
           !m_Bloom[hasher<131>(s)]
           && !m_Bloom[hasher<3131>(s)]
           && !m_Bloom[hasher<31313>(s)];
       if(hasNoBloom)
       {
           ret.push_back(i);
       }
       else if(!setDict.count(s))
       {
           ret.push_back(i);
       }
   }
   ```

   首先检查布隆过滤器，如果它在字典中找到该单词，我们必须像以前一样验证它。

在前述活动中，我们尝试解决一个实际问题并使其更高效。让我们考虑一下三个步骤中每种实现的一些要点，如下所示：

* 对于第一个版本，使用了带有 `std::set` 的最明显的解决方案 – 然而，性能可能较低，因为 set 数据结构基于二叉树，查找元素的复杂度为 `O(log N)`。
* 对于第二个版本，只需切换到 `std::unordered_set` 即可获得巨大的性能提升，后者使用哈希表作为底层数据结构。如果哈希函数良好，性能将接近 `O(1)`。
* 基于 **布隆过滤器** 数据结构的第三个版本需要一些考量。布隆过滤器的主要性能优势在于它是一种紧凑的数据结构，并不实际存储其中的元素，从而提供了非常好的缓存性能。

从实现角度来看，适用以下准则：

* `vector<bool>` 可用作后备存储，因为它是存储和检索位的有效方式。
* 布隆过滤器的误报率应尽可能低 – 超过 5% 将不高效。
* 存在许多字符串哈希算法 – 参考实现中使用了 `BKDR` 哈希算法。包含实现的字符串哈希算法综合列表可在此处找到：[http://www.partow.net/programming/hashfunctions/index.html](http://www.partow.net/programming/hashfunctions/index.html)。
* 所使用的哈希函数数量和布隆过滤器的大小对于获得性能收益至关重要。
* 在决定布隆过滤器应使用什么参数时，应考虑数据集的性质 – 考虑到在本示例中，拼写错误的单词很少，而大多数单词都在字典中。
