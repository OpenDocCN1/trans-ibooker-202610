Figure 12-8. Linearizability of Transactions in Cloud Spanner

Achieving linearizability requires a reliable time source¹⁹ across all nodes. This is not possible using the NTP-style time services, as clock skew across nodes can be of the order of a few hundred milliseconds. From Figure 12.9, transaction T2 may commit at an earlier time than transaction T1 if T2 is using a time source that is behind that of T1.

Cloud Spanner implements a unique solution to this problem, namely the TrueTime service. TrueTime equips Google data centers with satellite-connected GPS and atomic clocks, and provides closely synchronized clocks with a known upper bound clock skew - reportedly around 7 milliseconds. All data objects in Spanner are associated with a TrueTime time stamp that represents the commit time of the transaction that last mutated the object.
