

## Protect

使用良好的加密协议套件，例如 IPSec，并为每个用户创建凭证，严格遵循良好的密码概念。你的选择可能受防火墙或设备的限制，但你应该能够找到一种所有用户及其设备都能支持的方案。

你的策略应包括凭证的过期，通常以月为单位而非年为单位。理想情况下，你为每个用户分配难以猜测的密码，但许多组织会抵制这一点，因为用户无法记住难以猜测的密码，而且很多人不使用密码管理软件。如果你必须使用不太难以猜测的密码，请使用常见单词加上员工可以记住的短数字的组合，例如 Jumpbranch92 或更好的是 Jump$Branch92。我倾向于将大写字母放在开头或结尾以便输入。

如果用户可以访问许多资产，因此带来更高的安全风险，那么这些策略应更严格，难以猜测的密码应更频繁地更改。如果远程用户将始终来自固定 IP，请将其包含在其访问配置文件中以增加另一层保护。

务必启用尽可能多的日志记录，以便你能够访问用户活动的详细报告。

如果用户将远程访问共享文件，请尝试找到一种方法来限制或消除远程用户删除文件甚至写入文件的能力，如果可能的话。只读访问是理想的。如果远程用户必须访问存储在内部数据库中的机密信息，请确保数据库内容已加密。这在很大程度上取决于服务器的操作系统和数据库技术，但请寻找这些解决方案，它们将最大限度地降低你的风险。

虽然通过混淆实现的安全性在总体上是一个薄弱的概念，但在为远程员工访问创建主机名时要聪明。vpn.yourcompany.com 非常明显。它也可能值得为此类事情注册一个单独的域名，该域名不会泄露公司名称。

简单地创建访问方案，使用户只能访问他们需要的资源而不能访问整个网络总是明智的。减少风险的最佳方法是管理最坏情况并最大限度地减少可以远程访问的内容。如果必须远程访问敏感信息，那么你必须让这些用户多受一些不便，增加额外的密码挑战或强制他们从固定 IP 地址访问。

## Recover

恢复损坏或删除的数据是你可以用良好的备份轻松处理的技術功能。更改凭证和访问规则也可以轻松处理。

然而，如果机密信息已被访问，任何事情都不会容易。始终与法律顾问协调，但通常公开泄露情况以及机密信息可能被未经授权人员查看的可能性是更好的。

不幸的是，往往只有在发生泄露后，管理层才会接受更严格的网络策略。现在是时候解决策略和程序，并尽一切可能防止或至少将未来安全事件的损害降到最低。

## Review Questions

以下问题测试你对本章所介绍材料的掌握程度。

- 1. 命名两种类型的 Internet 协议流量并描述每种的优点和缺点。

Answer: 有两种 Internet 协议流量：传输控制协议或 TCP 和用户数据报协议或 UDP。当建立 TCP 连接时，数据可以双向发送。这种连接高度可靠并具有错误检查功能，但会增加传输的负担。UDP 是一种更简单、无连接的协议，其中多个消息作为数据块中的数据包发送。UDP 对于处理大量客户端查询的服务器或速度至关重要的游戏非常有用。UDP 没有错误检查功能，因此无法真正保证传输的数据包会到达目的地。

- 2. 互联网的主要标准组织是什么，它如何制定互联网上使用的标准？

Answer: 互联网工程任务组（IETF）是互联网的主要标准组织。RFC，即征求意见稿，可由任何人提交给互联网 IETF，如果 IETF 认为该说明值得注意，则 RFC 会被分配一个唯一编号。如果该 RFC 引起足够兴趣并形成共识，它可能会演变为互联网标准，但许多 RFC 本质上是大多数互联网协议的事实标准。

- 3. 涉及每种类型互联网连接的连接设备类别是什么，可以承担这一角色的物理设备类型有哪些？

Answer: 每个独立计算机或连接到互联网的局域网都将通过某种类型的网关设备连接。该网关设备通常是路由器，但也可能是具有某种协议转换或转换功能的交换机。网关设备也可能是调制解调器、接入点，甚至是语音 over Internet 协议（VoIP）适配器。
