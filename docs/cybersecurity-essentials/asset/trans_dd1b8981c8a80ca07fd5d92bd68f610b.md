当广播或多播流量压垮网络时，就被称为 *广播风暴* 或 *网络风暴*。由于广播流量会被每个网络设备重新广播，如果交换机和路由器不胜任，持续的流量会迅速使其过载。

与 DoS 攻击一样，监控网络中的广播风暴非常重要。然而，确保网络配置正确，并且拥有足够强大的硬件来快速传输数据并足够快地学习路由以满足组织需求也很重要。

*Teardrop 攻击* 是另一种类型的 DoS 攻击，涉及向目标机器发送分片数据包。目标机器将无法重新组装此类数据包。这会导致数据包相互重叠并最终导致目标网络设备崩溃。

## Lab Answers

- 1. Wireshark Capture 窗口中有哪三个窗格？

  Packet List 面板、Packet Details 面板和 Packet Bytes 面板。

- 2. 一个 PING 涉及多少个数据包？

  对于每个 PING，你会看到两个与 ICMP 相关的包：Echo（PING）请求和 Echo（PING）回复。

- 3. 你应该使用管理员账户运行 Wireshark 吗？

  通常不建议这样做。相反，使用权限较低的账户运行 Wireshark，并在提示时提升权限。

## Identifying and Defending Against Vulnerabilities

*现代互联网的现实之一* 是新的网络漏洞几乎每天都会被发现。你也可以预计这些漏洞在被发现后不久就会被利用。一个庞大的产业正在从这些发现中成长并获利，无论它们是被恶意使用还是用于防止未来被利用。在本章中，你将学习：

- 识别与连接到互联网相关的常见计算机和网络漏洞
- 讨论常见的网络安全漏洞利用和防御措施

### Zero Day Vulnerabilities

在讨论漏洞时，你经常会听到 *零日漏洞* 或 *零日攻击* 这一术语。这些术语指的是产品厂商未知且因此尚无补丁可修复的漏洞。一旦漏洞公开，厂商必须争分夺秒地发布补丁。

漏洞可以通过多种方式被发现。它们可能是偶然发现的，也许是有人以应用程序开发人员未预料的方式使用应用程序。但我们最担心的是被研究并针对利用的漏洞。它们可以通过“模糊测试”或以意想不到的方式与应用程序交互来找到，希望逃脱应用程序的控制。另一种找到漏洞的方法是 *逆向工程* 应用程序，从成品文件倒推以期找到弱点。

我们中的许多人都熟悉每月第二个星期二作为“补丁星期二”，微软通常会在这一天发布其安全补丁。

当你处理大量漏洞时，这个时间表可能足够。然而，一些漏洞严重到需要发布非计划补丁。

Web 浏览器通常提供简单或自动的升级方法。虽然这可能让用户感到烦恼，但这些更新应尽快应用，就像你会保持防病毒软件为最新一样。

### A Word About Hackers

你可能会想知道谁发现这些零日漏洞。这通常是由被称为黑客的个人完成的。黑客一词已演变为指怀有恶意意图的计算机程序员。然而，原本的术语指的是负责在软件程序中查找问题的个人。如今，黑客实际上有不同的“色调”，并非所有黑客都怀有造成伤害的动机。

### Software Exploits

几乎每天你都会看到关于某些流行软件包有更新可用的通知。当然，获取这些更新的公认方法是通過网页浏览器下载。这使得它们既是桌面问题也是应用服务器的问题。

基于 PHP 的软件，如 WordPress、WordPress 插件或 PHPMyAdmin，由于新漏洞被频繁发现，因此更新频繁。曾有单月发布了三项或更多关键 WordPress 安全更新来处理安全问题发现。值得称赞的是，WordPress 通过实现自动更新来应对这一问题。但管理员必须始终保持警惕，如果希望拥有这些软件包并保持软件为最新。

插件也可能受到不同漏洞的影响，且其更新尚未自动。因此，经常手动检查所有服务器软件包的更新非常重要。如果服务器安全绝对关键，重新考虑使用这些软件包也可能是明智的，因为它们被利用的频率很高。

大多数计算机用户至少对 Adobe Flash Player 多年来的众多漏洞有所了解。大多数人会证明这是他们多年来更新最多的单一软件。Adobe 努力跟上新的零日漏洞，但他们在这场战争中绝不是赢家。

### Are You Hosting a PHP Product?

如果你托管 PHP 产品，请考虑使用 suPHP（suphp.org），它可以限制 PHP 执行。

虽然一些漏洞可能只是在浏览器中注入广告，但其他漏洞会将勒索软件安装到易受攻击的计算机上，如第二部分所述。一旦安装，勒索软件将加密用户数据全部或部分并要求巨额金钱来解密文件。

虽然在统计上对 Windows 系统的威胁更大，但 Mac 和 Linux 用户同样容易受到 Flash 漏洞的影响。Flash 软件会频繁检查更新，但许多用户会放弃这些更新或至少延迟它们，因为它们确实需要一些时间来完成。有时连续的多次更新会导致一些更新疲劳的用户禁用自动更新或简单地取消并忽略更新警告。

由于 Flash 在浏览器中运行，用户可能甚至没有意识到他们正在查看某些 Flash 内容。他们可能认为，因为他们没有观看电影或演示文稿，所以它没有被使用。教育用户及时更新此软件的重要性以及不要禁用自动更新。

Adobe 不仅要担心 Flash 漏洞，Adobe Reader（前称 Acrobat Reader）漏洞也变得越来越常见。这些漏洞可能导致任意代码执行、沙箱绕过或通常通过内存损坏导致的简单拒绝服务。

Adobe 从 Flash 中吸取了教训，开发了良好的更新机制；但与 Flash Player 一样，此更新可能需要用户干预，因此可能被忽略。此产品应包含在你的用户教育演示中。

微软也经常更新其软件，而不仅仅是在前面描述的“补丁星期二”。Windows 并不是唯一有风险的产品，应用程序软件也可能被利用。因此，鼓励用户允许其 Microsoft 更新运行并完成至关重要。Windows 的每个新版本都试图使这一过程更不显眼和透明，但继续规避此过程的用户最终会意识到这些更新为何至关重要。
