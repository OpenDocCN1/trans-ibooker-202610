# Perimeter Security: Review Questions and Hands-On Exercises

*Review the summary points* before proceeding to the “Review Questions” and “Exam Questions” sections to make sure you are comfortable with each point. After completing the review, answer the review questions that follow to verify your knowledge of the material covered in this chapter.

## Summary Points

- 有两种类型的 Internet 协议流量：传输控制协议（TCP）和用户数据报协议（UDP）。当建立 TCP 连接时，数据可以双向发送。这种连接高度可靠，具有错误检查功能，但会增加传输的负担。UDP 是一种更简单、无连接的协议，其中多个消息作为数据块中的数据包发送。
- *单播消息*是将消息发送到单个网络地址。*广播消息*是指将消息发送到所有可能的目的地。*多播消息*使用特殊地址分配将消息发送到特定的一组地址。
- 除了网络地址外，许多协议还可能指定一个 *端口* 或端口号。协议或应用程序可能以不同的方式响应特定端口。
- 理解端口对于管理网络安全至关重要。最小化不需要的扫描或限制访问的最简单方法是使用特定端口和 *端口阻塞*。
- *路由* 只是选择通过网络或在网络之间传输数据的最佳路径的过程。
- *路由器* 主要处理 IP 地址，但它们也可以处理 MAC 地址，这可以是限制访问的另一种方式。
- *域* 是由互联网名称与数字地址分配机构（ICANN）授权的代理 *注册商* 分配的唯一领域。
- 大多数公司和家庭用户都会向 Internet 服务提供商（ISP）订阅 Internet 访问服务。该服务通常按特定服务级别或潜在传输速度以及至少一个 IP 地址签订合同。然而，该服务还可能包括电子邮件、网络托管、一些安全服务，甚至更大的 IP 地址块。
- 许多 ISP 会通过缓存服务器或缓存设备 *代理* 您的网络连接，以最大限度地减少带宽利用率。
- 一些 ISP 还会阻止某些端口，以错误地尝试最大限度地减少恶意软件、病毒和蠕虫的影响。
- Internet 工程任务组（IETF）是 Internet 的主要标准组织。
- 有许多组织参与维护网络漏洞资源，其方式与病毒和恶意软件资源类似。许多商业实体已发展起来以满足这一重要需求，但也有许多公开可用的资源和标准。
- 真正的安全意识转变始于第一批计算机病毒开始传播时。随着这种转变，单个用户可以运行一段恶意代码并影响整个公司网络，甚至可能在不知情的情况下通过与所有联系人共享该病毒而助长该病毒的传播。
- 网络硬件是 Internet 访问的组成部分，通常可以兼具提供一定网络安全性的双重功能。
- *网关* 设备通常提供良好的安全功能，即使在开箱即用、未配置的情况下，它们通常也会为普通家庭或小型办公室用户提供“足够好”的安全性。
- 每个独立计算机或连接到 Internet 的局域网都将通过某种类型的网关设备连接。该网关设备通常是路由器，但也可能是具有一些协议转换（或转换器）的交换机，以为以太网或无线客户端提供 ISP 提供的技术访问。
- 路由器还可能支持 DMZ，提供来自外部网络的相对自由访问。通常，这里放置的是 Web 服务器或邮件服务器，以便异地用户可以轻松访问，同时您仍可以控制内容和硬件。
- *代理服务器* 允许客户端进行间接网络连接。客户端连接到代理服务器，有或没有有意识的身份验证，并请求来自不同服务器的资源。然后，代理服务器将通过从缓存返回请求的资源或将请求转发到其他服务器来处理请求。
- 这种概念最常见的用途是缓存 *Web 代理*，其中本地服务器会缓存 Web 资源，然后智能地使它们过期。
- Web 代理有助于节省 Internet 带宽并加快连接速度，但它们也可以用于过滤内容甚至重新格式化内容。
- *透明代理* 使原始 IP 地址在 HTTP 标头中可用。透明代理通常是用户甚至不知道他们正在使用的东西。
- 恶意代理服务器已被用于各种目的，包括恶意软件投递、广告注入，以及简单的信息收集。虽然代理服务器可能不会传递您的 IP 地址，但它仍然会知道您的 IP 地址，并且也可能以某种方式使用此信息。
- 通常会在 *反向代理服务器* 后放置一群 Web 服务器，该服务器将处理对 Web 资源的公共请求，然后将其转发到一个或多个服务器。对请求者来说，此过程看起来就像直接访问这些 Web 服务器一样。
- 连接到 Internet 的网络中最常见也是第一道防线是 *防火墙*。
- 一个好的防火墙将使用定义的规则提供 *数据包过滤*，以拒绝或接受传入和传出的数据包。防火墙规则对于大多数网络的安全至关重要。
- 防火墙通常是实施或评估 Internet 安全的起点。大多数管理员配置所需的防火墙功能，然后尝试使它们安全。然而，安全确实需要是首要考虑因素。
- 越来越多地，路由器和交换机被集成到 *智能交换机* 中，甚至与传统操作系统结合，创建被称为 *智能网络设备* 的设备。
- 安全设备也被称为 *统一威胁管理（UTM）设备*，具有网关、防病毒、防火墙、入侵预防和检测，以及可能更多功能于单一产品中。
- *数据安全* 部署用于通过加密或实时捕获防止数据误导。它还用于防止扫描传入的数据包或文件，以及在数据被接受后对计算机上的数据进行监控和扫描。
- *加密* 是一种简单的方法，可以确保数据不会被第三方拦截并被不当使用。它正迅速成为保护任何网络几乎必需的步骤。
- 所有级别的安全始终涉及某种类型的身份验证过程。
- 用户可以通过要求他们提供用户名和密码、检查其 MAC 地址，或如果他们分配了静态 IP 地址则通过其网络地址进行身份验证。
- 在用户经过身份验证后，我们通常希望确定其授权，这本质上涉及经过身份验证的用户有权访问的资源以及他们可以执行的操作。
- 最为人所知的身份验证方法是密码身份验证，这是一种 *单因素身份验证*，代表可用的最低安全级别。
- *双因素身份验证* 涉及要求提供另一个身份验证组件——理想情况下是用户拥有的物理物品或其拥有的物品。




*数字证书*（也称为公钥证书）就是一种数字验证，用于确认加密消息的发送者确实为其所声称的身份。要获得数字证书，必须向受信任的证书颁发机构（CA）申请。

*安全套接层（SSL）*是一种协议，用于管理客户端与服务器之间的身份验证和通信，同时使用公钥和私钥。

*传输层安全（TLS）*是 SSL 的继任者，尽管两者经常被互换使用，甚至统称为 SSL/TLS。然而，它们并不能互操作。TLS 握手协议允许客户端和服务器在交换任何数据之前交换密钥并处理加密算法。

*哈希表*本质上是一种查找表，使用哈希函数将键映射到值，其中哈希函数会将键转换为哈希值。无需顺序搜索数据表来查找特定值，可以对查找键执行*哈希函数*，该函数将返回所寻找哈希值的索引。这可以节省大量的数据搜索时间。

*超级 Cookie* 已成为另一种隐私困扰。超级 Cookie 只是第三方 Cookie，但比其他类型的 Cookie 更难删除。其中许多并不使用传统的 Cookie 存储方法，而是使用本地浏览器 HTML5 数据库存储，甚至使用 Adobe Flash 数据存储。

在传统身份验证方案中添加 *CAPTCHA（验证码）* 可以潜在地消除任何形式的自动化密码攻击。

*网络分段*（也称为分区）出于多种原因可能是一个有用的概念。网络分段本质上是将网络划分为子网络，每个子网络成为一个网段。

对网段的访问通常通过访问控制列表提供，只有符合某些条件或通过身份验证的用户才被允许访问。这被称为*白名单*。

- 对网段的访问中，只拒绝符合某些条件或通过身份验证的用户访问，这被称为*黑名单*。
- 允许外部用户进入网络时，始终遵循“最小权限”和“必需知道”的原则。给予每个用户尽可能少的访问权限，并且仅限于他们必须访问的网络区域。
- 网络*虚拟化*改变了我们看待网络分段的方式。软件定义网络（SDN）这一相对较新的概念正在兴起，它本质上分析任意两个节点之间的连接，并可以根据定义的策略过滤该连接。
- 通过软件，单个硬件可以支持多个*虚拟实例*，每个实例都能像原始主机硬件一样运行。可以根据需要启用虚拟实例以应对需求和可扩展性，或提供极大的可移植性。
- *VLAN*（即虚拟局域网）简单来说就是一个由软件配置的网络，其中的主机即使并未连接到同一物理网络，也会表现得如同连接在一起。这允许多个网络或广播域在虚拟层面上像一个统一的局域网和广播域一样工作。
- *网络地址转换（NAT）*简单来说就是将一个网络中使用的 IP 地址转换为在另一个网络中已知的 IP 地址。通常，这用于将网络外部的 IP 地址映射到网络内部的地址。
- NAT 可以通过基于策略的路由（PBR）执行，其中映射决策由任意数量的规则决定，这些规则可以基于多种不同的标准。如果希望允许外部访问网络，这些规则对安全性至关重要。
- *端口地址转换（PAT）*支持将多个内部（或私有）设备或 IP 映射到单个外部（或公共）IP 地址的概念。路由器会分配一个端口号并附加到 IP 地址上，使每个地址实际上成为唯一地址，即使它们共享同一个 IP 地址。

- 防火墙设备使用*状态化数据包检测*或动态数据包过滤来进一步分析数据包——查看 IP 地址、端口号等。它们跟踪这些信息以便控制端口，仅在内部请求需要时才允许端口打开。
- *虚拟专用网络（VPN）*允许远程用户通过公共网络（如互联网）连接到专用网络，然后像直接连接一样在专用网络上进行身份验证并执行任务。
- VPN 中最广泛使用的协议是*点对点隧道协议（PPTP）*。PPTP 不提供任何加密，并使用取自*点对点协议（PPP）*的简单密码身份验证。
- *第 2 层隧道协议（L2TP）*也使用 PPP，且本身不加密，但可以在隧道中传递另一种加密协议。通常，底层协议会与 L2TP 结合，例如 L2TP/IPSec 配置。
- *互联网协议安全（IPsec）*是一种常用于 VPN 的开放标准，它实际上采用一组协议来加密和认证 IP 通信。
- NAT/PAT 最强的特性是，默认情况下不会通过设备转换或“转发”任何内容。要让数据包通过设备，必须在设备上显式创建规则，将所需协议端口转发（或映射）到局域网中的私有 IP 地址和端口。
- 网络监控工具可用于确保服务器（甚至服务器上的特定服务）已启动并正常运行，也可用于仅监控数据流量。
- 网络监控工具主要分为两大类：可用性和性能监控工具，以及数据包分析器。

- *零日漏洞*和*零日攻击*这两个术语指的是产品供应商未知的漏洞，因此尚无可用的补丁修复。一旦该漏洞公开，供应商必须争分夺秒地发布补丁。

- *点击劫持攻击*利用欺骗性的框架技术，诱骗用户点击其内容，而非预期的内容。
- *字典攻击*是一种系统性的暴力破解攻击，它将字典中的每个单词用作密码。这种攻击很容易消除，只需限制在给定时间段内可执行的登录尝试次数即可。
- *泪滴攻击*是一种 DoS 攻击，其中分片数据包被发送到目标系统。较旧的操作系统在其 TCP/IP 重组机制中存在缺陷，导致分片数据包重叠并使设备崩溃。
- *分布式拒绝服务（DDoS）攻击*利用多个不同网络上受感染的系统（称为僵尸网络）来发动攻击。
- 在*分布式反射和放大拒绝服务（DRDoS）攻击*中，攻击者能够利用相对较小的僵尸网络对反射服务器发起分布式攻击，反射服务器会重定向收到的查询，使其看起来像是真正的源。随后，反射服务器会因传入查询与相应响应的结合而不堪重负。
- *Smurf 攻击*与 DoS 攻击类似，因为它们都使用中间放大器。攻击者将使用目标被伪造的源 IP 地址，向中间系统的广播地址发送大量 ICMP 流量。
- *ICMP 隧道*也可用于传递恶意数据包。此处最佳防御是配置网络设备不响应 ICMP 回显请求。另一种选择是直接阻止所有 ICMP 流量以及入站广播流量。
- *Fraggle 攻击*使用 UDP 数据包而不是 ICMP，但概念和缓解措施与 Smurf 攻击类似。
- *第 7 层攻击*专注于应用层，通常针对网站的特定区域，以期耗尽资源。这种攻击可能很难识别，因为它看起来像是正常的。




网络流量达到一定程度。攻击者会找到网站上的一个表单或功能，该功能可能消耗更多资源，并从僵尸网络中针对该功能发起攻击。

- 另一种可能的 DoS 攻击解决方案是通过一种称为 *tarpitting* 的技术，也被称为粘性 *honeypot*。为了缓解 HTTP 攻击，其概念是在初始响应连接时表现正常，但使用非常小的 TCP 窗口大小。

- *Spammers* 通常被认为是最低级的黑客形式，并且经常执行目录收割攻击（DHAs），他们只是猜测域中的电子邮件地址，然后连接到该域的电子邮件服务器。

### Professional Feedback

此时，将你的观察结果与一名在职安全专家进行比较，以提高你对该主题的理解。

在某些时候，我们可能需要考虑安全检查点和键盘等。随着大量来自不同部门的内部用户访问网络，我们需要确保网络使用交换机进行分段，以促进在整个网络中创建访问控制程序。

显然需要一个强大的防火墙路由器。在这里，我们将禁止来自 WAN（互联网）一侧的所有 IP 流量，然后仅允许我们可能需要的特定服务和端口。

如果需要对服务器进行公共访问，那么我们需要创建一个周界网络或 DMZ，并将这些功能转移到位于该网络内的服务器上。如果主防火墙无法处理额外的接口，那么为周界网络使用一个更简单的防火墙也是一个好主意，这样我们既可以为公共服务器提供 VPN 访问，又可以限制可以进入 DMZ 的服务。

所有授权用户必须使用加密的 VPN 来访问 DMZ 或内部网络资产。一旦用户获得 VPN 访问权限，则必须使用凭据或基于 IP 的控制的访问控制来保护其他资产。理想情况下，你的 VPN 可以为用户分配唯一的 IP 地址，这样你就可以按 IP 对网络进行保护和监控，从而按用户进行管理，因此很少需要求助于凭据。

对于 DMZ 防火墙或接口，我们将只启用所需的端口，例如基于 Web 的系统的 80 和 443，以及我们需要提供的最小邮件服务端口。理想情况下，邮件仅通过 VPN 提供，但如果在 DMZ 服务器上提供 Web 邮件服务并且该服务器负责接收邮件，则必须打开适当的端口。

存储在 DMZ 服务器上的所有敏感信息必须加密存储。如果发生任何入侵，你希望确保数据通过良好的加密得到保护。

对于网络防火墙或接口，我们希望可以禁止所有服务，仅允许 VPN 访问。然后我们创建防火墙规则，根据用户的 VPN IP 地址限制对各个网络段的访问。还在防火墙上关闭 ICMP 和其他不必要的服务。即使我们已经限制了对网络的访问，锁定服务器上的每个服务仍然是一个好主意。

## Detect

我们的防火墙路由器或设备将在保护方面发挥重要作用，但在检测方面作用不大。DMZ 资产应尽可能严格锁定，但通常如果发生某种入侵，入侵者会寻找某些 PHP 漏洞并反复尝试使用简单凭据登录。安全软件可以配置为查找此类内容并阻止访问并通知管理员。

简单的宕机检测对于内部和 DMZ 服务器都是一个好主意，通过受保护的资产轮询关键服务器，并在它们变得不可用甚至过载时通知管理员。

我建议使用开源入侵检测系统（IDS），甚至可能不止一个来协助此过程。Snort 和 Tripwire 等产品可以帮助及早检测入侵，以便及时处理。Linux 软件包如 Security Onion 可以提供一系列工具，可以补充你与安全设备或防火墙所拥有的功能。

## Respond

在创建策略和政策声明时，假设你的受众是非技术人员，并将行话降到最低。他们需要了解 VPN 等某些概念，但他们可能需要在过程中接受教育，了解为什么某些问题很重要。当你的用户更好地理解安全时，你的网络会更安全。

IT 员工需要接受入侵通知的教育，并制定严格的政策，说明在收到通知时如何处理。如果你使用 DDoS 攻击缓解服务，那么与攻击期间如何处理相关的政策也很重要。这些相同的 IT 员工还必须接受教育，以便为网络用户提供用户友好的建议，以便他们了解如何处理诸如网络钓鱼请求等更微妙的攻击。

教育非常重要，因此你应该创建教育材料来补充网络政策和程序。你的用户需要了解为什么良好的密码很重要，为什么他们应该对任何可能是网络钓鱼攻击的东西保持怀疑，为什么他们不应与任何人共享凭据等。

确保你有健全的备份程序，最好备份到不属于网络本身的服务器。备份服务器可以访问服务器，但反之则不行，因此最大限度地减少任何入侵的影响。基于云和异地备份机制理想情况下应补充本地备份。

## Recover

如果你正在遭受拒绝服务类型的攻击并且不使用缓解服务，那么在你努力识别攻击时，你应该断开网络与互联网的连接。如果攻击分布广泛，可能没有什么可做的，只能等待它过去。较小的攻击如果运气好，可能可以通过阻止几个 IP 来应对。

如果你有更强大的路由器，你可能能够进行一定程度的过滤，并且你始终可以将网络访问转移到不同的 IP 等，但这通常取决于你的业务性质而变得不切实际。

你的公共可用服务越关键，你就越应该考虑 DDoS 缓解服务。如果你精通 DNS 设置，你可以进行区域更改来规避攻击，但这仍会导致一些网络可用性问题。缓解服务可以帮助最大限度地减少这种情况。

从许多攻击或入侵中恢复通常只是从备份中恢复。这就是你不希望理想情况下依赖基于云的备份的原因，因为通常恢复需要很长时间。理想情况下，你有一个可以本地访问的驱动器，可以在服务离线时用来恢复数据。

如果你已被入侵并且数据已被泄露，你必须迅速评估损害。查看你的日志并确定可能已被访问的数据，并通常假设最坏的情况。虽然当然你可能需要更改网络上的凭据，但你可能还需要通知你的客户。如果所有客户数据都已加密，你应该没问题，因为你永远不会将密钥存储在可能被入侵的任何东西上。

## Protect

使用良好的加密协议套件，例如 IPSec，并为每个用户创建凭证，严格遵循良好的密码概念。你的选择可能受防火墙或设备的限制，但你应该能够找到一种所有用户及其设备都能支持的方案。

你的策略应包括凭证的过期，通常以月为单位而非年为单位。理想情况下，你为每个用户分配难以猜测的密码，但许多组织会抵制这一点，因为用户无法记住难以猜测的密码，而且很多人不使用密码管理软件。如果你必须使用不太难以猜测的密码，请使用常见单词加上员工可以记住的短数字的组合，例如 Jumpbranch92 或更好的是 Jump$Branch92。我倾向于将大写字母放在开头或结尾以便输入。

如果用户可以访问许多资产，因此带来更高的安全风险，那么这些策略应更严格，难以猜测的密码应更频繁地更改。如果远程用户将始终来自固定 IP，请将其包含在其访问配置文件中以增加另一层保护。

务必启用尽可能多的日志记录，以便你能够访问用户活动的详细报告。

如果用户将远程访问共享文件，请尝试找到一种方法来限制或消除远程用户删除文件甚至写入文件的能力，如果可能的话。只读访问是理想的。如果远程用户必须访问存储在内部数据库中的机密信息，请确保数据库内容已加密。这在很大程度上取决于服务器的操作系统和数据库技术，但请寻找这些解决方案，它们将最大限度地降低你的风险。

虽然通过混淆实现的安全性在总体上是一个薄弱的概念，但在为远程员工访问创建主机名时要聪明。vpn.yourcompany.com 非常明显。它也可能值得为此类事情注册一个单独的域名，该域名不会泄露公司名称。

简单地创建访问方案，使用户只能访问他们需要的资源而不能访问整个网络总是明智的。减少风险的最佳方法是管理最坏情况并最大限度地减少可以远程访问的内容。如果必须远程访问敏感信息，那么你必须让这些用户多受一些不便，增加额外的密码挑战或强制他们从固定 IP 地址访问。
