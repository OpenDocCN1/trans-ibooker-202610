领域驱动设计（DDD）提出从不同角度攻击失败软件项目的根本原因。 有效的沟通是领域驱动设计工具和实践的核心主题，你将在本书中学习这些工具和实践。 DDD 可以分为两个部分：战略和战术。

DDD 的战略工具用于分析业务领域和战略，并促进不同利益相关者之间对业务的共同理解。 我们还将利用对业务领域的这一认知来驱动高层设计决策：将系统分解为组件并定义它们的集成模式。

领域驱动设计的战术工具解决沟通问题的不同方面。 DDD 的战术模式允许我们以反映业务领域、解决其目标并使用业务语言的方式编写代码。

DDD 的战略和战术模式与实践都使软件设计与业务领域保持一致。 这就是名称的由来：（业务）领域驱动（软件）设计。

领域驱动设计并不会像《黑客帝国》中那样直接将新 JavaScript 库的知识安装到你的大脑中。 然而，它会通过缓解理解业务领域的过程并根据业务战略指导设计决策，使你成为更有效的软件工程师。 正如你将在本书后面的章节中了解到的，软件设计与其业务战略之间的联系越紧密，维护和演进系统以满足业务未来需求就越容易，最终导致更成功的软件项目。

## Part I. Strategic Design

> *There is no sense in talking about the solution before we agree on the problem, and no sense talking about the implementation steps before we agree on the solution.*
> 
> —Efrat Goldratt-Ashlag¹

领域驱动设计（DDD）方法论可以分为两个主要部分：战略设计和战术设计。 DDD 的战略方面涉及回答“是什么？”和“为什么？”的问题——我们构建什么软件以及为什么构建它。 战术部分则完全关于“如何”——每个组件如何实现。

我们将从探索领域驱动设计战略设计模式和原则开始我们的旅程：

- 在第 1 章中，你将学习分析公司的业务战略：它为消费者提供什么价值以及它如何在行业中与其他公司竞争。 我们将识别更细粒度的业务构建块，评估其战略价值，并分析它们如何影响不同的软件设计决策。
- 第 2 章介绍了领域驱动设计获取对业务领域理解的基本实践：*通用语言*。 你将学习如何培养通用语言并利用它在所有项目相关利益相关者之间促进共同理解。
- 第 3 章讨论了另一个领域驱动设计核心工具：*有界上下文*模式。 你将学习为什么该工具对于培养通用语言至关重要，以及如何使用它将发现的知识转化为业务领域的模型。 最终，我们将利用有界上下文来设计软件系统的粗粒度组件。
- 在第 4 章中，你将学习影响系统组件如何集成的技术和社会约束，以及解决不同情况和限制的集成模式。 我们将讨论每种模式如何影响软件开发团队之间的协作以及组件 API 的设计。

本章结尾将介绍*上下文映射*：一种图形表示法，绘制系统有界上下文之间的通信，并提供项目集成和协作环境的鸟瞰图。

## Chapter 1. Analyzing Business Domains

如果你和我一样，你喜欢编写代码：解决复杂问题、提出优雅的解决方案，并通过精心设计规则、结构和行为来构建全新的世界。 我相信这就是你对领域驱动设计感兴趣的原因：你希望在自己的技艺上做得更好。 然而，本章与编写代码无关。 在本章中，你将学习公司如何运作：它们为什么存在、追求什么目标，以及实现目标的战略。

当我在领域驱动设计课程中教授这些材料时，许多学生实际上会问：“我们需要知道这些材料吗？ 我们在编写软件，而不是经营企业。” 对他们问题的回答是响亮的“是”。 要设计和构建有效的解决方案，你必须理解问题。 在我们的上下文中，问题是我们必须构建的软件系统。 要理解问题，你必须理解其存在的上下文——组织的业务战略，以及它通过构建软件寻求获得什么价值。

在本章中，你将学习领域驱动设计用于分析公司业务领域及其结构的工具：其核心、支持和通用子领域。 这些材料是设计软件的基础。 在剩余的章节中，你将学习这些概念如何影响软件设计。

### What Is a Business Domain?

业务领域定义了公司的主要活动领域。 一般来说，它是公司为客户提供的服务。 例如：

- FedEx 提供快递递送服务。
- Starbucks 最为人所知的是其咖啡。
- Walmart 是最广为人知的零售机构之一。

一家公司可以在多个业务领域运营。 例如，Amazon 提供零售和云计算服务。 Uber 是一家拼车公司，同时还提供食品配送和自行车共享服务。

需要注意的是，公司可能会经常改变其业务领域。 一个典型的例子是诺基亚，多年来它曾在木材加工、橡胶制造、电信和移动通信等多种不同的领域运营。

### What Is a Subdomain?

为了实现其业务领域的目标和指标，公司必须在多个*子领域*中运营。 子领域是业务活动的细粒度领域。 公司的所有子领域构成了其业务领域：它为客户提供的服务。

仅实现单个子领域不足以使公司成功；它只是整体系统中的一个构建块。 子领域必须相互交互才能实现公司在其业务领域中的目标。 例如，Starbucks 可能因其咖啡而最受认可，但要建立成功的咖啡连锁店，仅仅知道如何制作优质咖啡是不够的。 你还必须在有效的位置购买或租赁房地产、招聘人员并管理财务，等等。 这些子领域中的任何一个单独都不会使公司盈利。 只有它们全部结合起来，公司才能在其业务领域中竞争。
