# Part I. Strategic Design

> *There is no sense in talking about the solution before we agree on the problem, and no sense talking about the implementation steps before we agree on the solution.*
> 
> —Efrat Goldratt-Ashlag¹

领域驱动设计（DDD）方法论可以分为两个主要部分：战略设计和战术设计。 DDD 的战略方面涉及回答“是什么？”和“为什么？”的问题——我们构建什么软件以及为什么构建它。 战术部分则完全关于“如何”——每个组件如何实现。

我们将从探索领域驱动设计战略设计模式和原则开始我们的旅程：

- 在第 1 章中，你将学习分析公司的业务战略：它为消费者提供什么价值以及它如何在行业中与其他公司竞争。 我们将识别更细粒度的业务构建块，评估其战略价值，并分析它们如何影响不同的软件设计决策。
- 第 2 章介绍了领域驱动设计获取对业务领域理解的基本实践：*通用语言*。 你将学习如何培养通用语言并利用它在所有项目相关利益相关者之间促进共同理解。
- 第 3 章讨论了另一个领域驱动设计核心工具：*有界上下文*模式。 你将学习为什么该工具对于培养通用语言至关重要，以及如何使用它将发现的知识转化为业务领域的模型。 最终，我们将利用有界上下文来设计软件系统的粗粒度组件。
- 在第 4 章中，你将学习影响系统组件如何集成的技术和社会约束，以及解决不同情况和限制的集成模式。 我们将讨论每种模式如何影响软件开发团队之间的协作以及组件 API 的设计。

本章结尾将介绍*上下文映射*：一种图形表示法，绘制系统有界上下文之间的通信，并提供项目集成和协作环境的鸟瞰图。
