"Take a look at the HTML code again," Simon continued. "All three menus that Emily added and the input line are between the opening tag <form> and the closing tag </form>. Emily did a great job indenting them for readability.

Now we can clearly see that they are inside the form. That means they all are parts of the same form. And that means when you click Submit they will be passed to the program altogether.

In the program we'll be able to read them using the request.form dictionary, exactly as we did in our simple program."

"As in request.form['drink']?" Erik asked.

"Yes, right," Simon answered. "Look, Emily gave them names: 'flavor' and 'topping' so we can use them as keys for the dictionary in our program. Let's open again our first_app.py and look where we have to make changes. Remember what we do here? We get the form dictionary and copy the value for the key drink to the variable drink. For example, if the customer chooses 'chocolate' then it will be assigned to the variable drink. And that variable will be passed to the form called print.html to be displayed—or, sometimes people say rendered--on the page."

### Listing 11.4 First version of order() in first_app.py

```
@app.route("/order", methods=("GET", "POST"))
def order():
    if request.method == "POST":
        drink = request.form["drink"]
        print("Drink: ", drink)
        return render_template("print.html", drink=drink)

    return render_template("forms.html")
```
