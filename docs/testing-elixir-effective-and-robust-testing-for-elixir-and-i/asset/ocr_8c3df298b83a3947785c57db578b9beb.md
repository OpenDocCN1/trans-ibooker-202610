# Executing Tests

When executing a single test, the test case does roughly this:

+   1. Runs all the setup callbacks in the order they were defined.
+   2. Runs the test body.
+   3. Runs all the on_exit callbacks in the order they were registered.

Let's look at each of these steps separately.

The first thing a test case does when running a test is spawn a new process to run that test in. All the setup callbacks are run sequentially inside that process.

After the setup callbacks are executed, the test case runs the body of the test itself inside the test process.

Once the test body exits (by finishing or by exiting explicitly, for example through an exception), it's time to run the on_exit callbacks. A new process is spawned for the purpose of running all on_exit callbacks. All on_exit callbacks are executed in that process, one after the other (that is, sequentially). on_exit callbacks are not executed in the test process because, after all, the test process just exited so it's not alive anymore.
