## 嵌入式分析

本节非常简短，仅旨在向您介绍嵌入仪表板的概念。组织可以将仪表板嵌入到其应用程序或 Web 门户中，以便用户无需登录 AWS 控制台即可访问 QuickSight 来探索 QuickSight 仪表板。

这让团队的生活更简单，因为他们现在可以在 Web 门户上发布高级仪表板和可视化，并具有增强的用户交互。QuickSight 支持三种不同的嵌入方式：

- **QuickSight 控制台**：将整个 QuickSight 控制台嵌入到 Web 门户中，以便用户可以创建和发布仪表板。团队可以使用它将 QuickSight 作者体验嵌入到其 Web 门户中，并为其员工添加附加功能。
- **仪表板和可视化**：嵌入在 QuickSight 控制台中开发的仪表板，用户只能查看和与仪表板交互。团队可以使用它在 Web 应用程序中向客户发布高级仪表板。
- **QuickSight Q**：将 QuickSight Q 搜索栏嵌入到 Web 应用程序中。

QuickSight 支持一键仪表板嵌入。步骤记录在此博文中：https://docs.aws.amazon.com/quicksight/latest/user/1-click-embedding.html。

为了启用一键公共嵌入，您需要将 QuickSight 订阅更改为基于会话的模型。

## 数据摄取的前提条件

为了执行前述用例的数据整理活动，我们首先需要将数据摄取到数据湖中。为了将数据从本地数据库摄取到云环境中，我们有以下选项：

1. 使用诸如 AWS Glue 之类的服务或部署在 Elastic Kubernetes Service (EKS)/Elastic Container Service (ECS) 上的容器，使用 SQL 查询以编程方式提取数据。

这种方法的优点如下：

- 只要有用于连接数据库的包/库，它就可以与大多数数据库一起使用
- 它不需要除具有所需权限的登录凭据以外的任何额外设置即可提取数据
- 这种方法直接从表中读取数据，因此服务器无需创建用于捕获数据更改 (CDC) 流式传输实用程序所需的数据库日志文件，从而不会产生额外的工作负载

这种方法的局限性如下：

- 数据使用 SQL 查询提取，并且需要额外的书签列来增量提取后续运行的数据。如果有一个时间戳列表示记录上次更新的时间，我们可以使用它仅提取新数据。
- 管理书签列状态的额外负担也由用户承担。因此，用户必须将元数据存储在数据库中，例如 DynamoDB，以获取上次成功数据提取的值。
- 已删除的记录无法使用书签列提取，并且需要额外的设置，这在数据库中资源密集。
- DDL 更改也无法通过这种方法捕获。
- 由于提取过程使用 SQL 脚本完成，它会与用户查询竞争数据库资源，并可能影响数据库性能。
