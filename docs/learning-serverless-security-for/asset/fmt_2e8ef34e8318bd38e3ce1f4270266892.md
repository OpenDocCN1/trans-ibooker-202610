## Establishing Persistence with New IAM User Credentials

In this section, you will simulate an attacker establishing long-term access by generating new credentials for an existing IAM user that belongs to the `Administrators` group. You will start by using the `assumed-lambda-role` profile from the previous section to enumerate IAM groups and identify potential target IAM users. After that, you will create new long-term credentials for a user in the `Administrators` group. Finally, you will configure a CLI profile with those credentials to emulate an attacker preserving access to a compromised AWS account.

From a defensive security standpoint, you should regularly perform a thorough audit of IAM principals, attached policies, and trust relationships in your AWS account(s). It’s best to dive deep and look for unexpected users, long-lived access keys, overly permissive role trust policies, as well as newly added inline or managed policies that grant excessive permissions, as these are common indicators of persistence and privilege escalation attempts. In addition, you should enforce MFA across *all* IAM user accounts and implement strict least-privilege access controls to reduce the risk of unauthorized access as well as privilege escalation by attackers.
