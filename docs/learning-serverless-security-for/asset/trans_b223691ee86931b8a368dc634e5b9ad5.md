

想象一下拥有一个无服务器的 CI/CD 管道，当新的提交推送到代码仓库时，它会自动安装依赖项、运行测试并部署你的应用程序。如果管道配置了过度的权限，并且被破坏的 `bignum` 包被包含在依赖项中，攻击者就可以从管道资源内部窃取敏感凭据、提升权限，并可能完全控制云账户。

### Note
如 [GitHub Advisory Database](https://oreil.ly/UPZwk) 中所述，`bignum` NPM 包的新版本不再使用 `node-pre-gyp` 下载二进制文件，也不不再支持下载预编译的二进制文件，以避免下载恶意二进制文件的风险。

供应链攻击甚至可能让经验丰富的开发团队措手不及，因为恶意代码可能隐藏在开发者所依赖的依赖项中。如果团队没有保持高度警惕并且没有部署自动化的安全控制，这些攻击可能在很长时间内都未被发现。我们将在 [Chapter 13](#ch13.html#chap-13-title) 中更深入地探讨供应链攻击，并探索策略和防御措施，以帮助保护你的项目免受恶意依赖项的侵害。

# Chapter 4. Exploiting and Securing Exposed AWS IAM Credentials
身份和访问管理 (`IAM`) 是定义和控制无服务器架构中每个组件被允许访问哪些资源的首要机制。尽管其重要性，IAM 在开发过程中经常被配置错误且被忽视。你可以犯的最关键错误之一就是由于不安全或设计不良的架构而暴露具有完全访问权限的 IAM 凭据。这相当于锁上你的门并把钥匙贴在门把手上。

在本章中，你将使用一个有意设计为易受攻击的无服务器应用程序，以亲眼看到攻击者如何滥用暴露的 IAM 凭据。你将探索攻击者如何从客户端代码中提取暴露的密钥，利用过于宽松的 IAM 策略和角色来禁用 CloudTrail 日志记录，甚至创建具有完全管理权限的后门 IAM 用户。^[1](#ch04.html#id532) 此外，你将看到如何从攻击者账户执行未经授权的 Bedrock 模型调用。^[2](#ch04.html#id533) 最后，你将学习如何审计 CloudTrail 和 Bedrock 模型调用日志以检测和响应此类攻击。

# Reviewing Technical Prerequisites
要跟随本章，以及第 [5](#ch05.html#chap-05-title)、[6](#ch06.html#chap-06-title) 和 [7](#ch07.html#chap-07-title) 章，你需要以下内容：
* 两个 AWS 账户：一个用于设置和托管有意设计为易受攻击的无服务器实验室环境（`Serverless Lab account`）^[3](#ch04.html#id535)，另一个用于运行模拟利用（`Attacker account`）。强烈建议使用全新的账户且没有预先存在的资源，以最大程度地减少与安全相关的副作用并确保实验室环境按预期运行。如果你还没有这些账户，可以使用 [AWS Free Tier](https://oreil.ly/ECp5R) 创建新账户。确保两个账户都已准备就绪并在单独的浏览器会话（或隐身/私人窗口）中打开，以避免会话冲突。
* 在继续之前，在 `Serverless Lab account` 中访问 Amazon Bedrock 模型 `Claude 3.5 Sonnet`。^[4](#ch04.html#id537)
* 在本地机器上安装代码编辑器——例如 Visual Studio Code (`VS Code`) 或 `Sublime Text`——以查看、修改和运行本章提供的代码示例。

如果你使用的是 Microsoft Windows，请确保你有一种运行 macOS 或 Linux 命令的方法——例如使用 Windows Subsystem for Linux (`WSL`)、`Git Bash` 或带有 Linux 发行版的 VM。
