

根据经验，监控和日志的用量，以及每个所用服务的计费模式，也会对整体成本产生相当大的影响。在某些情况下，你甚至可能会遇到监控和日志服务的成本高于无服务器计算和数据库服务的项目。

在考虑为下一个项目使用无服务器架构时，整体基础设施成本占据了很大一部分，因此你可能会发现采用 `serverless-first` 的思维方式更为实用，这样你就可以在最有意义的地方考虑无服务器方法。^[10](#ch01.html#id337) 关键在于认识到无服务器表现优异的场景，并确定其他架构和方法的适用之处。

到目前为止，你可能对无服务器是什么有了更清晰的理解。现在我们已经定义了概念并讨论了无服务器表现优异的场景，是时候驳斥一些常见的神话和误解，以消除任何困惑。

## 神话 1：无服务器意味着不涉及任何服务器

术语 `serverless` 具有误导性，因为它并不意味着不涉及任何服务器；相反，管理这些服务器的责任被转移给了平台。

相信这种神话可能导致以下不切实际的期望：

*   认为故障转移、重试和扩展将始终自动发生
*   预期基础设施责任为零，例如监控系统性能
*   忽视在部署无服务器资源的位置需要安全的网络配置

实际上，如果你正在从事使用无服务器架构的项目，你仍然有责任确保安全、处理系统故障并优化应用程序代码的性能。根据无服务器架构中使用的服务，你可能有配置特定运行时环境、内存分配、并发限制和其他配置参数的选项。

了解无服务器服务的内部机制虽然是可选的，但对于优化应用程序性能和管理潜在挑战，例如冷启动延迟，是必不可少的。^[12](#ch01.html#id341) 在某些情况下，云平台会提供对这些服务内部运行的可见性，以帮助开发人员就安全、扩展和资源管理做出明智的决策。

## 神话 2：无服务器等同于 FaaS

普遍的误解是无服务器计算仅限于且等同于 FaaS。事实上，当谈到无服务器计算时，人们首先想到的就是 FaaS 服务，例如 `AWS Lambda`、`Azure Functions` 和 `Google Cloud Run` 函数。^[13](#ch01.html#id342) 使用这些服务时，开发人员通常只需要专注于编写由事件触发的自定义函数代码，这些事件来自 HTTP 请求以及其他云资源等来源。

在这些函数内部，你可以执行以下操作：

*   编写并实现自定义业务逻辑代码。
*   使用包含在应用程序运行时环境中并安装的库和包。
*   通过应用程序编程接口 (`APIs`) 和软件开发工具包 (`SDKs`) 利用云平台的其他服务和功能来执行专门任务。这些任务可能涉及处理和转换数据、使用由人工智能 (`AI`) 驱动的服务分析图像，甚至使用托管云服务训练机器学习 (`ML`) 模型。
*   使用 `APIs` 和 `SDKs` 创建、管理和修改或删除云平台中的其他资源。例如，无服务器函数可以通过使用若干 `基础设施即代码` (`IaC`) 服务，根据配置文件自动创建 DevOps 流水线。
*   触发其他无服务器函数。
*   与其他非无服务器资源（如虚拟机 (`VM`) 实例和数据库）协同工作。

如果你想知道这些函数是如何实现的，[示例 1-1](#ch01.html#EX1) 展示了 `AWS Lambda` 函数在 Python 中的实现。

### 示例 1-1. Python 中示例 AWS Lambda 函数实现

```
import json

# ... (insert imports here) ...

def lambda_handler(event, context):
    role = event.get('role')
    endpoint_name = event.get('endpoint_name')
    package_arn = event.get('package_arn')

    model_name = random_string()
    create_model(model_name, package_arn, role)
    endpoint_config_name = create_endpoint_config(model_name)

    create_endpoint(endpoint_name, endpoint_config_name)

    return {
        'statusCode': 200,
        'body': json.dumps(event),
        'model': model_name
    }
```

该函数通过使用名为 `Amazon SageMaker AI` 的托管 ML 服务，自动配置并 provision 一个无服务器 ML 驱动的端点。该函数使用从另一个文件导入的其他自定义实用函数，例如 `random_string`、`create_model`、`create_endpoint_config` 和 `create_endpoint`。

#### 注

正如你在 [第 2 章](#ch02.html#chap-02-title) 中将会看到的，`Amazon SageMaker AI` 不被视为无服务器服务。然而，它具有无服务器选项来部署无服务器推理端点，使你能够在无需配置或管理服务器的情况下部署和扩展 ML 模型。虽然 FaaS 是无服务器架构的核心组件，但你也可以在非无服务器实现中技术上使用它。

[示例 1-1](#ch01.html#EX1) 中显示的函数在由另一个云资源触发的事件触发时执行。该云资源可能是接受来自浏览器的 HTTP 请求并将请求“转换”为包含触发无服务器函数所需输入参数集的事件的 `Amazon API Gateway` HTTP API。 [图 1-5](#ch01.html#fig_serverless_trigger) 描绘了此示例。

![](assets/lsse_0105.png)

函数执行完毕后，它会将函数返回值发送回 `Amazon API Gateway` HTTP API。然后 HTTP API 将该函数返回值转换为 HTTP 响应。

#### 注

无服务器函数资源在执行后会自动释放。这允许基础设施资源在应用程序空闲或无流量时缩减至零。

无服务器计算与 FaaS 相同这一误解通过忽略无服务器架构中经常使用的组件和策略来简化了概念 ([图 1-6](#ch01.html#fig_venn_diagram_serverless_faas))。FaaS 是无服务器计算的核心部分，但并非所有无服务器计算都必然是 FaaS。
