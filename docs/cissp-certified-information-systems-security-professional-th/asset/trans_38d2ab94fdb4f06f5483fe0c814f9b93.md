
许多组织正选择以漏洞赏金或披露奖励的形式向道德黑客提供经济激励。由于罪犯通常受利润驱动，为负责任的披露付费会改变经济状况，使其有利于合法研究和负责任的披露。存在第三方公司来管理道德披露流程以及对已识别漏洞的付款。这些服务提供了经过验证的安全研究人员库的优势，使用漏洞赏金提供商可以成为组织安全测试和评估策略的有价值补充。

如果安全研究人员或组织在不拥有或控制的系统中发现漏洞，则需要考虑与道德披露相关的四种情况。关于这些安全研究以及漏洞披露的规则、法律和法规在不同司法辖区差异很大且不断演变，因此任何进行安全研究的个人或组织都应为其活动寻求法律指导。负责任披露发现的特殊情况包括以下内容：
* **非披露：** 可能存在合同或法律义务阻止披露漏洞；例如，当披露漏洞可能损害正在进行的刑事调查时。
* **完全披露：** 这是一种哲学论点，即任何时候发现弱点时，都应尽快完整、透明地向负责修复的组织报告。虽然改善安全的目标是值得称赞的，但许多供应商可能对试图报告漏洞的研究人员持敌对态度。
* **负责任披露：** 这一原则规定发现者有责任及时向组织报告弱点，并在公开披露之前给予组织足够的时间修复漏洞。
* **强制报告：** 在某些情况下，向执法部门或其他当局报告发现的漏洞可能是强制性的。世界各地的法律和监管框架各不相同，因此如果发现者位于一个司法辖区，而负责软件或系统的组织位于另一个司法辖区，这可能是一个困难的情况。
* **举报：** 举报人是指感到有道德义务报告危险或非法情况的人，许多司法辖区都有法律旨在保护举报人免受报复。在发现安全漏洞的情况下，如果举报人遵循披露发现漏洞的正确渠道，则可能免于因版权侵权或其他数字犯罪而被起诉。

# 进行或促进安全审计
安全从业人员通常负责进行或促进审计，在这两种情况下，目标是相同的：对照标准比较组织的某个方面。进行审计或担任审计员需要对审计中使用的流程、目标和技术有透彻的理解和知识。促进审计不需要那么多的知识，但在审计前准备时，了解审计流程会有所帮助。

## 设计审计计划
组织的审计计划可以设计为进行内部审计、促进外部审计，或根据需要两者兼顾。适当的资源、监督和管理层的支持至关重要，同样重要的是执行审计的现实时间表。一次性、特定时间点的审计提供了安全计划的有用快照，但定期审计计划允许随时间跟踪计划并显示改进。

### 常见审计框架
如果组织正在追求特定类型的审计，例如 FedRAMP 或 SOC 2，则审计计划将由标准决定，因为这是外部审计员必须遵循的内容。审计框架也可以用作设计内部计划时最佳实践的指南。事实上，设计与外部审计员使用的相同标准保持一致的内部计划是有意义的，因为它允许组织发现外部审计员可能发现的相同问题。

这些是提供可据此执行审计标准的常见信息安全框架：
* **SSAE 18** 是《鉴证业务准则声明》，审计员在执行 SOC 2 审计时使用。
* **ISO/IEC 15408-1:2009**，“信息技术 — 安全技术 — 信息技术安全评估准则”，是通用标准认证的基础，通用标准认证是对技术产品按照一组定义的安全功能要求进行的正式评估流程。本文件和 ISO/IEC 18045 可免费获取。
**ISO/IEC 18045:2008**，“信息技术 — 安全技术 — 信息技术安全评估方法”，是 ISO 15048 的配套文件，并提供了一致的准则和评估方法的标准。
* **ISO/IEC 27006:2015**，“信息技术 — 安全技术 — 信息安全管理体系审核和认证机构的要求”，是审计员执行针对 ISO 27001 的认证审核的官方要求和指导集合。
* **NIST 特刊 (SP) 800-53A**，“评估联邦信息系统和组织中的安全和隐私控制”，是评估 NIST SP 800-53 中概述的控制措施的指南。它引入了一套简单的测试程序来评估控制有效性：测试、检查或访谈。虽然适用于美国政府机构，但可免费获取，任何组织都可改编使用。
**NIST 网络安全框架 (CSF)** 和 **FedRAMP 安全评估框架 (SAF)** 也可免费获取，可用于执行与 NIST SP 800-53A 中类似的评估方法进行评估。

## 抽样
在设计审计计划时，收集信息和获得保证的工作成本应与风险可见性的收益相平衡。抽样是审计中使用的技术，用于在保持识别缺陷的保证的同时减少工作量。例如，配置审计可能会从 1,000 台服务器的总体中选择 100 台以减少所需工作量。样本应具有代表性——如果组织在 Windows 和 Linux 之间平均分配，则应检查每种服务器类型各 50 台。

## 内部审计
内部审计由组织员工执行，提供审计员熟悉流程、工具和人员的好处。这种同样的熟悉程度也可能是内部审计的缺点，因为熟悉环境的人可能会无意中忽略问题——对问题进行第二双眼睛的检查通常能发现问题。然而，专门负责执行审计和管理补救的团队成员可能比交付报告后不再有进一步互动的外部审计员更有效。

内部审计员也可能缺乏进行客观评估的足够独立性。发现可能影响财务绩效或审计员与团队成员关系的重要问题可能会产生淡化发现问题的动机。在某些组织中，这可以通过将审计员设为公司内的独立团队来解决，但对于小型组织而言，这可能不是可行的选择。
