The preceding command will log you inside the newly spun container and leave you a command prompt.

In Kubernetes, DNS-based service discovery defines a specification, or a DNS schema, that defines the DNS name used to locate the services running in the cluster. All DNS records in a Kubernetes cluster fall under a single domain referred to as the *cluster domain*, which is usually set to `cluster.local` by default in most Kubernetes clusters. The DNS specification defines that for each IP assigned to a service (i.e., the cluster IP), an A record exists that contains the cluster IP with a name derived from the service name and namespace as `service.namespace.svc.cluster-domain`. So, to access the Nginx Pod that we created, you can issue the following command from the `infoblox/dnstools` container:

```
dnstools# curl nginx.default.svc.cluster.local
```
