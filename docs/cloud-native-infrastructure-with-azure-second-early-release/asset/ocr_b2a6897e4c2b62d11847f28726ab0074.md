The CoreDNS Kubernetes plug-in watches the Kubernetes services and endpoint resources and caches that data. When a request is made, the CoreDNS plug-in will see whether a resource corresponding to the requested name exists, and then it will return the appropriate data. The response records are built on the fly based on incoming requests by using the watch feature of the Kubernetes API server.

Let’s take a look at how CoreDNS assists in service discovery over a Kubernetes cluster. Suppose you are running a simple Nginx Pod in a Kubernetes cluster as follows:

```
$ kubectl get pods
NAME    READY   STATUS    RESTARTS   AGE
nginx   1/1     Running   0          3m20s
```

```
$ kubectl get services
NAME         TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)   AGE
kubernetes    ClusterIP   10.0.0.1        <none>        443/TCP   41m
nginx         ClusterIP   10.0.148.122    <none>        80/TCP    3m26s
```

To access this Nginx server, you need to run an infoblox/dnstools Pod that has some DNS utilities, such as dig and curl. To run this Pod, you can use the following command:

```
$ kubectl run --restart=Never -it --image infoblox/dnstools
dnstools
If you don't see a command prompt, try pressing enter.
dnstools#
```
