```
HTTP/1.1 200 OK
Content-Type: text/plain
Connection: Keep-Alive
Content-Length: 0
```

Since we are currently passing the action as `login`, we can check the logs at the location to verify that they have been printed:

```
2020-12-21 12:31:31.529967000 +0530 myapp.test:
{"action":"login","user":2}
```

If you try to post an action as a `logout` in the following `curl` command, it will get dropped based on the filter rule we specified, and you won’t be able to see any logs being printed:

```

HTTP/1.1 200 OK
Content-Type: text/plain
Connection: Keep-Alive
Content-Length: 0
```

# Fluentd on Kubernetes

By default, in Kubernetes the logs from containers are written to standard output and the standard error stream. This is basic I/O logging, which Kubernetes offers out of the box. The Container engine redirects the streams to a logging driver configured in Kubernetes to write the logs to a file in JSON format. As a user, if you wish to see the logs you can use the `kubectl logs` command.
