## Exploring the Azure infrastructure with Terraform

Now that we’ve created a basic infrastructure with Terraform, let’s dig deeper and create additional infrastructure.

In Example 2-1, we showed you how to store your state locally. Though this is not a recommended process, it is sufficient for basic usage, as in the case of the resource group creation example (test.tf). It is better to use remote

storage, like Azure blob storage, which provides both durability and safety for your infrastructure configurations.

> WARNING
> 
> Terraform states are the source of truth and should always be stored in a backend such as Consul or Amazon DynamoDB Azure storage because this will safely store your infrastructure state along with version control for easier management or rollback in case of a disaster. States should not be checked in the Git version control system, because Git contains secrets.

In the following subsections, we will create blob storage in our Azure account to store all our infrastructure states. We will also follow the “Don’t repeat yourself” (DRY) principle by ensuring that we make use of Terraform’s module. We will be going over the creation of virtual networks and virtual machines. You can find the modules in the repo https://bit.ly/2ZSVSze.

## Creating an Azure virtual network and instances.

Now we will create a virtual network on Azure following the Terraform configuration in https://bit.ly/3bHE342.

We will also explain the syntactic flow of the virtual network module, which will give you a better understanding of the simplicity of the code.

Take a closer look at the Virtual_network module in the directory /Modules/Services/Virtual_network and you’ll see the step-by-step process of virtual network creation:

- Create a network security group using azurerm_network_security_group.
- Add the security rule and attach it to the security group in step 1.
- Create a DDOSprotection plan.
- Create a virtual network.
- Create four different subnets inside the virtual network.
- Create a network interface and attach it to a subnet (private).
- Create public IPs.
- Create a public subnet by attaching a public IP to it.
