

| TSP 参考编号 | 信任服务标准及关注点 |
|---|---|
| CC6.8 | *实体实施了控制措施，以防止或检测未经授权或恶意软件的引入，并采取措施以达成实体的目标。* |
|  | **以下关注点专门适用于使用信任服务标准的所有鉴证业务，强调了与该标准相关的重要特征：** |
|  | • *限制应用程序和软件安装* — 安装应用程序和软件的能力仅限于授权人员。 |
|  | • *检测软件及配置参数的未经授权更改* — 已建立流程以检测对软件和配置参数的更改，这些更改可能表明存在未经授权或恶意软件。 |
|  | • *使用定义的变更控制流程* — 使用管理层定义的变更控制流程来实施软件。 |
|  | • *使用杀毒和反恶意软件* — 实施并维护杀毒和反恶意软件，以提供拦截、检测恶意软件及进行修复的能力。 |
|  | • *扫描来自实体外部的信息资产以检测恶意软件和其他未经授权软件* — 已建立程序以扫描已转移或归还至实体保管的信息资产，检测其中的恶意软件和其他未经授权软件，并在其在网络上实施之前移除任何检测到的项目。 |
|  | **系统运维** |
| CC7.1 | *为达成其目标，实体使用检测和监控程序来识别 (1) 导致新漏洞引入的配置更改，以及 (2) 对新发现漏洞的易感性。* |
|  | **以下关注点专门适用于使用信任服务标准的所有鉴证业务，强调了与该标准相关的重要特征：** |
|  | • *使用定义的配置标准* — 管理层已定义配置标准。 |
|  | • *监控基础设施和软件* — 实体监控基础设施和软件是否符合标准，不符合标准可能会威胁到实体目标的达成。 |
|  | • *实施变更检测机制* — IT 系统包含变更检测机制（例如，文件完整性监控工具），以便在关键系统文件、配置文件或内容文件遭到未经授权修改时向人员发出警报。 |
|  | • *检测未知或未经授权组件* — 已建立程序以检测未知或未经授权组件的引入。 |
|  | • *执行漏洞扫描* — 实体定期以及在环境发生重大变更之后执行旨在识别潜在漏洞或配置错误的漏洞扫描，并及时采取行动以修复已识别的缺陷。 |
| CC7.2 | *实体监控系统组件及其操作中的异常，这些异常可能表明存在影响实体达成目标能力的恶意行为、自然灾害或错误；对异常进行分析以确定它们是否代表安全事件。* |
|  | **以下关注点专门适用于使用信任服务标准的所有鉴证业务，强调了与该标准相关的重要特征：** |
|  | • *实施检测策略、程序和工具* — 定义并实施检测策略和程序，并在基础设施和软件上实施检测工具，以识别操作异常或系统中的异常活动。程序可能包括 (1) 定义安全事件检测和治理流程，包括资源提供；(2) 利用情报来源识别新发现的威胁和漏洞；以及 (3) 记录异常的系统活动。 |
|  | • *设计检测措施* — 检测措施旨在识别可能由实际或试图 (1) 突破物理屏障；(2) 授权人员的未经授权行为；(3) 使用被破坏的标识和身份验证凭据；(4) 从系统边界外部进行的未经授权访问；(5) 授权外部方被破坏；以及 (6) 实施或连接未经授权硬件和软件所导致的异常。 |
|  | • *实施过滤器以分析异常* — 管理层已实施程序以过滤、汇总和分析异常，以识别安全事件。 |
|  | • *监控检测工具的有效运行* — 管理层已实施流程以监控检测工具的有效性。 |
| CC7.3 | *实体评估安全事件，以确定它们是否可能或已经导致实体未能达成其目标（安全事故），如果是，则采取行动以防止或解决此类失败。* |
|  | **以下关注点专门适用于使用信任服务标准的所有鉴证业务，强调了与该标准相关的重要特征：** |
|  | • *响应安全事故* — 已建立程序以响应安全事故，并定期评估这些策略和程序的有效性。 |
|  | • *沟通和审查检测到的安全事件* — 检测到的安全事件会传达给负责安全管理的人员并进行审查，如有必要则采取行动。 |
|  | • *制定和实施分析安全事故的程序* — 已建立程序以分析安全事故并确定系统影响。 |
|  | **仅适用于使用隐私信任服务标准的鉴证业务的额外关注点：** |
|  | • *评估对个人信息的影向* — 评估检测到的安全事件，以确定它们是否可能或已经导致个人信息的未经授权披露或使用，以及是否违反了适用的法律或法规。 |
|  | • *确定使用或披露的个人信* — 当发生个人信息的未授权使用或披露时，识别受影响的信息。 |
| CC7.4 | *实体通过执行定义的事件响应计划来响应已识别的安全事故，以了解、遏制、修复和沟通安全事故，如适当。* |
|  | **以下关注点专门适用于使用信任服务标准的所有鉴证业务，强调了与该标准相关的重要特征：** |
|  | - *分配角色和责任* — 分配事件响应计划的设计、实施、维护和执行的角色和责任，包括在必要时使用外部资源。 |
|  | - *遏制安全事故* — 已建立程序以遏制主动威胁实体目标的安全事故。 |
|  | - *缓解持续的安全事故* — 已建立程序以缓解持续安全事故的影响。 |
|  | - *终止安全事故带来的威胁* — 已建立程序通过关闭漏洞、移除未经授权访问和其他修复行动来终止安全事故带来的威胁。 |
|  | - *恢复运营* — 已建立程序以将数据和业务运营恢复到允许达成实体目标的临时状态。 |
|  | - *制定和实施安全事故沟通协议* — 制定并实施向受影响方沟通安全事故及所采取行动的协议，以达成实体目标。 |
|  | - *获取事故性质了解并确定遏制策略* — 获取对安全事故性质（例如，事故发生的方式和受影响的系统资源）和严重程度的了解，以确定适当的遏制策略，包括 (1) 确定适当的响应时间框架，以及 (2) 确定和执行遏制方法。 |
|  | - *修复已识别的漏洞* — 通过制定和执行修复活动来修复已识别的漏洞。 |
|  | - *沟通修复活动* — 根据事件响应计划记录和沟通修复活动。 |
