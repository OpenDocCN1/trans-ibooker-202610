| **P4.0** | **与使用、保留和处置相关的隐私标准** |
| **P4.1** | **实体将个人信息的使用限制在实体与隐私相关的目标所确定的用途范围内。** |
|  | **以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征：** |
|  | • *将个人信息用于预期目的* — 个人信息仅用于收集时的预期目的，且仅在获得默示或明确同意后使用，除非法律或法规另有明确规定。 |
| **P4.2** | ***实体保留个人信息应符合实体与隐私相关的目标。*** |
|  | **以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征：** |
|  | • _保留个人信息_ — 个人信息的保留时间不得超过实现所述目的所需的时间，除非法律或法规另有明确规定。 |
|  | • _保护个人信息_ — 已实施政策和程序，以在指定的信息保留期内保护个人信息免遭删除或销毁。 |
| **P4.3** | ***实体安全地处置个人信息，以满足实体与隐私相关的目标。*** |
|  | **以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征：** |
|  | • _捕获、识别和标记删除请求_ — 捕获个人信息删除请求，并识别和标记与请求相关的信息以供销毁，以满足实体与隐私相关的目标。 |
|  | • _处置、销毁和编辑个人信息_ — 不再保留的个人信息将以防止丢失、盗窃、滥用或未经授权访问的方式进行匿名化、处置或销毁。 |
|  | • _销毁个人信息_ — 实施政策和程序，以删除或以其他方式销毁已确定销毁的个人信息。 |
| P5.0 | 与访问相关的隐私标准 |
| P5.1 | 实体允许已识别和认证的数据主体访问其存储的个人信息以供审查，并根据请求向数据主体提供该信息的物理或电子副本，以满足实体与隐私相关的目标。如果访问被拒绝，应按照要求告知数据主体拒绝访问及拒绝原因，以满足实体与隐私相关的目标。 |
|  |  |
|  | 以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征： |
|  |  |
|  | • 认证数据主体身份 — 在允许数据主体访问其个人信息之前，对请求访问的数据主体的身份进行认证。 |
|  | • 允许数据主体访问其个人信息 — 数据主体能够确定实体是否维护有关他们的个人信息，并可根据请求获得对其个人信息的访问。 |
|  | • 在合理时间内提供易于理解的个人信息 — 以可理解的形式、在合理的时间范围内并以合理的费用（如有）向数据主体提供个人信息。 |
|  | • 告知数据主体访问是否被拒绝 — 当数据主体被拒绝访问其个人信息时，实体及时告知他们拒绝及拒绝原因，除非法律或法规禁止。 |
|  |  |
| P5.2 | 实体根据数据主体提供的信息更正、修改或追加个人信息，并按照承诺或要求将此类信息传达给第三方，以满足实体与隐私相关的目标。如果更正请求被拒绝，应告知数据主体拒绝及拒绝原因，以满足实体与隐私相关的目标。 |
|  |  |
|  | 以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征： |
|  |  |
|  | • *传达访问请求被拒绝的决定* — 以书面形式告知数据主体其访问个人信息的请求被拒绝的原因、实体拒绝访问的法律权利来源（如适用），以及个人在法律或法规特别允许或要求的情况下质疑该拒绝的权利（如有）。 |
|  | • *允许数据主体更新或更正个人信息* — 数据主体能够更新或更正实体持有的个人信息。实体根据与隐私相关的目标，向先前获得数据主体个人信息的第三方提供此类更新或更正后的信息。 |
|  | • *传达更正请求被拒绝的决定* — 以书面形式告知数据主体个人信息更正请求被拒绝的原因以及他们如何申诉。 |
|  |  |
| P6.0 | **与披露和通知相关的隐私标准** |
| P6.1 | *实体在获得数据主体明确同意后向第三方披露个人信息，并在披露前获得此类同意，以满足实体与隐私相关的目标。* |
|  |  |
|  | **以下关注点仅适用于使用隐私信任服务标准的业务，突出说明了与此标准相关的重要特征：** |
|  |  |
|  | • *向第三方传达隐私政策* — 向被披露个人信息的第三方传达隐私政策或其他处理个人信息的特定指示或要求。 |
|  | • *仅在适当时披露个人信息* — 仅出于收集或创建个人信息的目的，且仅在获得数据主体默示或明确同意后，才向第三方披露个人信息，除非法律或法规另有明确规定。 |
