使用最适合你需求的数据类型。让我们将我们门的 数据类型与图 **2-7** 中的进行比较。在我们的门类中，我们正在复制 **openAmount**，它将是一个 *0 - 1* 的值，或者也许将来我们会添加破坏门的能力，在这种情况下我们可以使用 *-1*。因此，**openAmount** 永远的整个范围是 -1 到 1。

我们的 **openAmount** 属性目前是 double 数据类型。double 数据类型允许具有高小数精度的巨大范围。然而，这种增加的数据量是有代价的。那么什么其他数据类型能让我们在所需范围内拥有小数？查看图 **2-7** 并试着弄明白。

查看图表，我们需要一种支持我们范围内数字且能支持小数分数的数据类型。我们也不需要广泛的范围。因此，这里理想的数据类型是 float。

float 会花费我们 4 字节的数据，而不是 double 类型的 8 字节。这就是所需数据的一半，很棒！

让我们以每扇门每位玩家每 2 秒 4 字节重新计算，这就降到每扇门每位玩家每秒 2 字节。这就把实现门的带宽成本降到了每月 ~$2,896。相比之下是每月近 $2 百万。

### Network Topologies

所以我们开始了解设备如何向另一台设备发送数据。如果我们有两台已连接的设备，会发生什么当我们想要添加第三台时？第三台设备如何融入这种网络关系？这就是网络拓扑发挥作用的地方。

网络拓扑是网络上设备的排列方式。你的家庭网络就是一个很好的例子。你家里可能有一个连接到互联网的路由器。连接到你的路由器的是你所有的设备。这就是星型拓扑的绝佳例子。

端口号始终与 IP 地址相关联，通常与 IPv4 地址一起表示如下：

`192.168.10.1:4000`

在前面的示例中，我们知道 IP 地址是 192.168.10.1，端口号为 4000。需要注意的是，对于 TCP，只能有一个进程绑定到特定的 IP 和端口组合。对于使用 TCP 通信的程序，如果两个应用程序绑定到相同的 IP 地址和端口，将会出现冲突，称为端口冲突，这将导致不期望的效果。

那么如果我们使用 TCP，我们如何知道要在哪个端口号上托管我们的游戏？我们如何知道端口号不会与客户可能使用的其他运行软件冲突？65,535 个端口并不是很多。

答案是与其他开发者一起合作；选择端口号时有几个标准。这些标准由互联网号码分配机构（IANA）制定。

完整的注册端口列表可以在 IANA 网站上找到，[https://iana.org](https://iana.org)，在服务名称和传输协议端口号注册表中。
