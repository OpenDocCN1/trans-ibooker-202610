
## 转移模型

![](assets/rele_0204.png)

请记住，状态和奖励是随机变量，而非确定值，因为大多数环境是随机的。例如，你的智能体可能会选择在自动驾驶汽车中转动方向盘，但无法保证汽车真的会转向；它可能正处于冰面上。为了适应这种情况，引入了 `transition model`（转移模型）的概念。在某些书籍中，这也被称为 MDP 的 `dynamics`（动力学）。转移模型如[公式 2-4](#ch02.html#eq_transition-model)所示，是在给定先前状态和执行动作的情况下，到达新状态并获得奖励的概率。符号已简化以强调动作的因果效应。

### 公式 2-4. MDP 的转移模型

`p(s', r | s, a)`

[公式 2-4](#ch02.html#eq_transition-model) 是 MDP 的关键。在马尔可夫决策过程中，转移模型描述了环境的动力学。下一个状态和奖励仅取决于先前的状态和动作。MDP 与传统马尔可夫链（也称为 `Markov process` 马尔可夫过程）的唯一区别在于增加了动作和奖励参数。动作是一种 `decision`（决策），这就是 MDP 中“D”的含义。

### 提示

我喜欢将 MDP 视为一个接口。它是智能体与环境之间的契约。智能体只能观察状态并建议一个动作。作为回报，环境会给你一个新状态和一个表示你表现如何的值。这听起来可能很受限，但它允许接口双方都有极大的灵活性。环境可以根据需要变得任意复杂。它可以是用户点击按钮的模拟、Atari 游戏，甚至是现实生活。智能体也可以根据需要变得任意复杂。它可以是决定显示绿色还是红色按钮、在游戏中向左还是向右移动，或者搬到乡下是否是个好主意。

我用撇号表示时间向前迈进一步。但该时间不必是固定间隔。它仅用于使动作区分开来。换句话说，每当你感到需要做决策时，那就是你迈步的时候。将动作视为航向修正，将时间视为时间戳的记录。

## 库存控制

用强化学习术语定义问题是数据科学背景人员常见的问题。在转向解决 MDP 的其他方法之前，在问题定义阶段积累更多经验是值得的。库存控制是一个很好的切入示例，因为它既实用又易于理解。该示例与定价、最优停止（出售资产）、维护等有直接类比关系。我从一个非常简单的示例开始，然后将其扩展为更复杂的版本。

想象你拥有一家小店。这家店非常小，你只有一种产品。每天顾客都会购买你的产品，所以你需要补货。如果缺货，你就无法销售产品赚钱；你不想缺货。你租用店铺，每平方米需要一定费用。你不想囤积数百万件商品，因为那需要更大的场所。我可以定义许多高层问题，比如场所的最佳大小，或最小化运费，但为简单起见，我将问题定义为决定最佳补货时机。

设 `s` 表示某天的库存数量。这是环境的状态。为尽可能保持简单，我假设有三种可能状态：无库存、一件库存、两件库存，`S ≐ {0,1,2}`（此处花体字母表示集合）。

给定当前状态，智能体可以执行一个动作。保持简单，假设智能体可以采取两种动作之一。要么 `restock`（补货），订购 1 件新产品，要么什么都不做：`A ≐ {restock, none}`。如果当前状态为 1 且智能体执行动作，下一个状态将变为 2。还假设当你处于满容量时无法订购任何库存。

[公式 2-4](#ch02.html#eq_transition-model) 中缺失的下一项是转移概率。智能体从一个状态转移到另一个状态的概率是多少？既然你在模拟环境，你必须选择这些概率，但它们也可能来自你对店铺的观察。假设一天内发生单笔销售的概率 `p(sale)` 为 0.7。未来你可以预测售出的商品数量。但目前我再次使用伯努利分布。这意味着在每个状态下，有 70% 的概率发生销售，30% 的概率无销售。

### 注意

这是一个纯假设的例子。当然，现实中补货需要时间。简化是工程中必不可少的部分，尤其是在开发早期阶段。一旦你有了可工作的原型，就可以着手去除其中一些简化。

你需要的最后一项是奖励 `r`。你的店需要赚钱，所以每次卖出产品你都可以给自己奖励。但只有当产品当时有库存，或者你刚好及时补货时，销售才可能发生。这意味着奖励取决于当前状态和是否发生销售；无销售意味着无奖励。你可以在[公式 2-5](#ch02.html#eq_inventory_reward_definition)中看到该定义的数学形式。

### 公式 2-5. 库存控制奖励定义

$$
r \doteq \begin{cases} 
1 & \text{if } s > 0 \text{ and a sale} \\
1 & \text{if } a = \text{restock} \text{ and a sale} \\
0 & \text{otherwise}
\end{cases}
$$

### 转移表

下一个任务是定义系统中所有可能的状态转移，你可以用三种不同的方式来做。第一种方式是将所有可能的组合呈现为表格，称为 `transition table`（转移表），如[表 2-1](#ch02.html#tab_simple_transition)所示。

**表 2-1. MDP 转移表**

| s | a | s' | p(s'|s,a) | r |
|---|---|---|---|---|
| 0 | none | 0 | 1 - p(sale) | 0 |
| 0 | none | 0 | p(sale) | 0 |
| 0 | restock | 1 | 1 - p(sale) | 0 |
| 0 | restock | 0 | p(sale) | 1 |
| 1 | none | 1 | 1 - p(sale) | 0 |
| 1 | none | 0 | p(sale) | 1 |
| 1 | restock | 2 | 1 - p(sale) | 0 |
| 1 | restock | 1 | p(sale) | 1 |
| 2 | none | 2 | 1 - p(sale) | 0 |
| 2 | none | 1 | p(sale) | 1 |
| 2 | restock | 2 | p(sale) | 1 |

在[表 2-1](#ch02.html#tab_simple_transition)中，每一行对应当前状态 `s`、动作 `a`、下一状态 `s'` 以及给定先前状态和动作下转移到该状态的概率 `p(s'|s,a)` 的每一种可能组合；进行该转移的奖励在最后一列 `r` 中。你可以使用此表来追踪智能体的 `trajectory`（轨迹）。

### 注意

状态 2（两件商品）只有三种可能的转移，因为我省略了最终补货且无销售的情况。我在说当库存已满时补货是不可能的。

### 转移图

表示该信息的另一种方式是通过有向图，称为 `transition graph`（转移图），如[图 2-5](#ch02.html#fig_simple_transition_graph)所示。

![](assets/rele_0205.png)

该图有两种类型的节点（称为顶点）：一种代表状态，用圆圈表示，圆圈内标注状态名称；另一种代表动作，用实心圆表示。它们通过链接（称为边）连接，边上标注了采取动作后沿该链接的概率（转移概率）以及沿该链接获得的奖励。
