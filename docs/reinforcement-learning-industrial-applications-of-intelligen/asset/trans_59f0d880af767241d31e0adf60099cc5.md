
RL 智能体有时会控制危险设备，如机器人或汽车，这增加了做出错误选择的风险。一个称为*安全 RL*的子领域试图应对这一风险。RL 智能体也面临攻击风险，就像任何联网系统一样。但 RL 在传统软件和机器学习漏洞之外，又增加了几个新的攻击向量。我认为工程师是应对伦理问题的第一道防线，并且应该主动考虑这些问题，所以我认为在这里讨论它很重要。

### 安全 RL

安全 RL 的目标是在预定义的安全约束内运行，同时学习一个能最大化奖励的策略。这些约束在训练和运行期间可能存在，也可能不存在。这个定义的问题在于，它包含了关于防止灾难性更新的想法，从奖励的角度来看。已经设计出了一些算法来内在地解决这个问题，例如信任域方法（参见[“信任域方法”](#ch06.html#sec_trust_region_methods)）。另一种研究形式涉及外在方法，防止某些动作造成物理伤害、金钱损失或任何其他导致不良后果的行为，这正是我将在此总结的内容。显而易见的切入点是从本书中已经描述过的技术开始。^([34](#ch10.html#idm46428618344792))

如果你的问题存在安全顾虑，且可以自然地描述为约束，那么你可以使用任何执行约束优化的算法。`TRPO` 和 `PPO` 是不错的选择，你可以调整优化函数以纳入你问题的约束。例如，如果你正在训练一个算法来部署 Web 服务的副本以满足需求，它部署的数量不应超过基础设施的可用容量。此信息可以作为约束提供给优化函数。Ha 等人展示了一个使用受约束版本的 `SAC` 训练机器人防止跌倒的好例子。^([35](#ch10.html#idm46428618342584))

同样，你可以通过塑造奖励来惩罚特定行为。例如，机械臂在完全伸展时会承受巨大的应力。为了延长机器人的寿命，你应该防止可能导致金属疲劳的伸展动作。你可以在奖励函数中加入一个惩罚伸展的元素。

这两种方法的问题在于它们是硬编码的，在更复杂的问题中很可能是次优的。更好的方法可能是使用模仿学习或逆向 RL，从专家那里学习最优的约束动作。

然而，所有上述方法都无法保证安全，尤其是在学习期间。只有在充分训练后，安全性才能得到近似保证。从根本上说，这些方法是通过执行不安全行为来学习如何安全行事的，就像一个孩子——或成年人——触摸热杯子，尽管你告诉他们杯子是热的。

一组较新的方法通过定义一个超级*安全状态集*来使用安全的外部定义。例如，你可以定义机器人允许操作的最大范围，或跟车算法中车辆之间的最小允许距离。鉴于此定义，外部过滤器可以评估动作是否安全并予以阻止。

一个粗糙的过滤器可以完全阻止动作，并因智能体采取该动作而对其进行惩罚，这基本上与奖励塑造相同，不同之处在于你阻止了危险动作的发生。但这并没有将安全集的知识纳入优化过程。采用这种方法，例如，在你确定某些动作不安全之前，你必须从树的各个高度跳下来——允许我建议用根安全绳。

更务实的方法是构建能够中止并安全重置智能体的模型。你通常可以通过定义来设计训练，以避免不安全动作。例如，Eysenbach 等人制造了一个腿足机器人，并通过将目标设定为远离不安全状态来训练它行走。例如，如果它向左移动太远，目标就会被改为在右侧。他们还学习了一个重置控制器，以提供一种自动化方法来返回安全状态。^([36](#ch10.html#idm46428618334840))

研究人员已经研究了多种纳入此信息的方法。一个建议是使用 rollout（展开/模拟轨迹）来预测不安全事件的概率，并偏好那些导致安全轨迹的动作。^([37](#ch10.html#idm46428618332776)) 这可以通过将价值近似参数推向安全状态来纳入基于价值的 RL 算法，并通过将梯度步骤引向安全状态（并进行修正以解释有偏策略生成）来纳入策略梯度方法。^([38](#ch10.html#idm46428618330936))

另一组称为*形式约束 RL*的建议试图通过数学定义来保证安全，但这些方法往往依赖于不安全状态的完美符号表示，而这仅在玩具示例中才可能。Hunt 等人的一个实际实现采用了模型驱动的动作过滤技术。^([39](#ch10.html#idm46428618325448)) 毫无疑问，这仍然是一个开放性问题，我预计未来会有更多改进。

### 安全性 RL

如果攻击者能够篡改应用程序的源代码，他们就能注入恶意代码。这被称为*白盒*攻击。软件部署通过代码库上的严格访问控制机制来缓解这一风险。但如果开发者将软件暴露在公共互联网上，则面临攻击者可能探测并发现弱点从而改变应用程序运行的风险。这种外部方法被称为*黑盒*攻击。

机器学习或任何数据驱动过程也容易受到攻击。这些攻击大致分为针对*训练阶段*或*预测阶段*的攻击。在训练阶段，攻击者可能能够篡改或操纵训练数据，以便利用这些数据产生已知结果。这通常被称为*投毒*。例如，如果攻击者能将一封带有错误标签的垃圾邮件引入公共垃圾邮件数据集，那么攻击者可能会重复使用类似的邮件来推销据称能增强性欲的药丸，而基于该数据训练的任何模型都会将其分类为非垃圾邮件。

预测攻击通过提供或增强输入数据来产生无效结果。许多方法是白帽技术，并假设了解底层模型。^([40](#ch10.html#idm46428618312696)) 但最近研究人员发现了黑盒技术，例如攻击者可以创建一个与第一个模型相似的第二个模型。一旦训练完成，攻击者就可以为第二个模型生成白帽攻击，并用它们来攻击第一个模型。这种方法表明攻击是可迁移的。^([41](#ch10.html#idm46428618310872)) 这些统称为*对抗攻击*。

RL 智能体也可能以所有相同的方式受到攻击。你的第一步应该是打好基础。如果攻击者能在你的服务器上发现开放的 `SSH` 端口，或者有人的 GitHub 凭证被钓鱼窃取而你未启用多因素认证，他们就不会费心去创建一个训练好的副本模型。接下来，确保你建立了稳健的数据完整性测试和监控；使用速率限制和拒绝服务保护来限制黑盒攻击者能探索模型的程度。确保你的模型尽可能简单且鲁棒。考虑进行一次研究探索，以调查如何改进为你的 ML 模型设置的对抗措施。
