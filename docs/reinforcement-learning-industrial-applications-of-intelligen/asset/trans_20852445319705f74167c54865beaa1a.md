
绝大多数示例、文献、博客文章和框架都假设你的智能体正在进行*在线*学习。这意味着智能体与真实或模拟环境交互，并同时进行学习。到目前为止，本书我只讨论了这种模式。这种方法的主要问题之一是样本效率，即学习最优策略所需与环境交互的次数。在过去的几十年里，研究人员一直在通过改进探索和学习保证来追求样本效率。但从根本上说，探索始终会带来开销、由随机近似导致的采样延迟，以及至关重要的稳定性问题。直到最近，他们才开始考虑从日志中学习。

## 离线或批量学习

直到最近，人们认为所有学习都必须在线进行，因为智能体的动作与环境的反应之间存在内在耦合。^([3](#ch09.html#idm46428619371144))但研究人员发现，可以从存储数据的*批次*中学习，就像经验回放缓冲区中的数据一样。因为这些数据不再与环境交互，所以这也被称为*离线*学习或*批量*学习。[图 9-4](#ch09.html#fig_batch_rl) 展示了这一想法。首先，使用某个策略（可能是随机的）在线生成数据并保存在缓冲区中。然后离线地，在缓冲区的数据上训练一个新策略。最后将新策略部署使用。

![](assets/rele_0904.png)

离线学习的主要优势是提高了样本效率。你可以采集或记录一组数据，并随意用它训练模型任意次数，而对环境零影响。在采集新样本昂贵或不安全的许多领域中，这是一个极其重要的特性。

但等等。如果我收集并基于数据的静态快照进行训练，那这不就是纯监督学习吗？答案是肯定的，某种程度上。从某种意义上说它是监督的，因为你拥有一批带有标签转移和奖励的数据。但这并不意味着你可以使用任何旧的回归或分类算法。这些数据（假设）是由马尔可夫决策过程（MDP）生成的，因此设计用于寻找 MDP 最优策略的算法仍然有用。主要区别在于它们无法再进行探索。

如果智能体无法探索，就无法尝试通过“填补空白”来改进策略，而这是过去十年强化学习快速进步的主要原因。类似的论点是，这阻止了智能体针对动作提出反事实问题。同样，这是一种理论方法，通过允许智能体提出“如果……会怎样”的问题来提供更稳健的策略。从根本上说，训练数据（针对状态、动作和奖励）的分布与部署时观察到的分布不同。想象一下这会如何影响典型的监督学习算法。

原则上，通过移除算法中的探索部分，*任何*离策略 RL 算法都可用作离线 RL 算法。然而，由于多种原因，这在实践中是有问题的。基于价值的方法举步维艰，因为它们依赖准确的价值估计。但许多状态或动作不会出现在缓冲区中，因此估计充其量只是不准确。策略梯度方法因分布偏移而举步维艰，这充其量会产生指向错误方向的梯度，最坏的情况会导致梯度爆炸。当你使用过度指定的模型（如深度学习）时，这些问题会变得更糟。^([4](#ch09.html#idm46428619359944))

在撰写本书时，研究人员正在努力解决这些问题，以在样本效率上取得下一个重大突破。一个研究方向是进一步完善基础 RL 算法的稳定性保证，使它们在遇到不稳定分布或欠采样的状态或动作时不会表现异常。在使用深度学习时提供更好的理论保证，是一个显而易见的方向，将极大地改善现状。其他方法尝试使用模仿学习等技术来学习产生正奖励的策略。^([5](#ch09.html#idm46428619354712))一个更简单的方法是在缓冲区上训练一个自编码器，以创建一个智能体*可以*在其中探索的模拟环境。^([6](#ch09.html#idm46428619351880))实际上，这些技术已被应用并显示出令人印象深刻的结果，尤其是在[机器人学](https://oreil.ly/cXXDc)领域。^([7](#ch09.html#idm46428619348872))从实践角度来看，你可能会发现 [DeepMind RL Unplugged 基准测试](https://oreil.ly/hdtXK) 是一个寻找或原型化想法的有用工具。^([8](#ch09.html#idm46428619345688))

## 并发学习

文献中包含了一系列介于多智能体 RL (MARL) 和多进程框架之间的学习技术，但它们足够有趣，值得在此提及。

反馈周期的长度由问题的复杂性决定；挑战越难，解决所需的时间越长。这在一定程度上是由于模型复杂性的增加，但主要是一个探索问题。大规模状态和动作空间需要更多探索来“填补空白”。

许多研究人员专注于改进单智能体情况下的探索，这效果显著。但这只能扩展到一定程度。最终智能体仍然需要访问整个状态-动作空间。一种选择是同时运行多个智能体（参见[“扩展 RL”](#ch10.html#sec_scaling_rl)），但如果它们使用相同的探索算法，往往会探索相同的空间，随着状态-动作空间扩大，这又会抵消效率。

相反，为什么不*并发*地探索，让智能体团队共同承担探索状态-动作空间的*联合*任务。但要注意，这个术语被过度使用了；研究人员用*并发*一词来表示从协作 MARL 到 RL 并发编程的任何含义。^([9](#ch09.html#idm46428619336248),[10](#ch09.html#idm46428619334120))我用这个术语来表示对同一环境进行协调探索的目标，这最早于 2013 年提出。^([11](#ch09.html#idm46428619332600))

这一想法的实现在一定程度上取决于领域。举个例子，许多公司并行地与成千上万或数百万客户交互，并试图最大化针对该客户的局部奖励，如终身价值或忠诚度。但这些客户处于同一环境的范围内；公司只有有限的库存产品，且你拥有每个客户大致相同的人口统计信息。从一个客户那里获得的经验应迁移给其他客户，这意味着要么集中学习，要么至少共享参数。

我认为没有唯一的标准答案，因为有许多小挑战需要独特的适配。例如，如果你引入了通过电子邮件或广告重定向客户的能力，会发生什么？这会改善性能指标，但奖励可能会延迟。所以你必须构建“跳过”动作的能力并处理部分可观测性。

Dimakopoulou 和 Van Roy 于 2018 年形式化了这一想法，并证明了协调探索既能提高学习速度，又能扩展到大量智能体。^([12](#ch09.html#idm46428619328296))他们的解决方案出奇地简单：确保每个智能体都有一个能最大化探索的随机种子。这种方法的好处是你可以使用标准 RL 算法，且每个智能体都独立致力于寻求最优性能。它也能很好地适应新数据，因为初始条件被反复随机化。然而，挑战在于最优种子采样技术因问题而异。
