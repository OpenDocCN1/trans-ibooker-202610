*多样性就是一切* (DIAYN) 是一个新颖的想法，它促进了低层级策略的无监督发现。Eysenbach 等人提出技能应该是可区分的，因此它们应旨在产生访问不同状态的策略，并且由此产生的技能应尽可能多样化。为了鼓励随机性，你可以最大化以状态、动作或两者为条件的熵度量。[图 8-4](#ch08.html#fig_diayn) 展示了该过程的简化描述。^([17](#ch08.html#idm46428619804808))

## 在 HRL 中使用技能

给定一个技能库，如何训练 HRL 算法来解决特定问题？我可以想象，预训练的技能可以通过让几乎所有 RL 算法专注于环境探索，而不是探索如何探索，从而提供帮助。这在智能体本身具有大量复杂性的环境中尤其如此。

*基于优势奖励的 HRL* (`HAAR`) 是一种利用预训练技能显著改善初始探索从而加速学习的算法。Li 等人还引入了使用优势作为奖励信号的想法，而不是像 `HIRO` 那样使用到状态的欧几里得距离。原因在于状态空间不一定映射到到达目标的真实距离。例如，如果你使用摄像头，像素距离不等于物理距离。因此，他们提议使用高层策略的优势估计来重新训练和奖励低层技能。这样，产生正优势的技能——即在高层任务中表现良好的技能——会比那些表现不好的技能得到更多提升。^([18](#ch08.html#idm46428619792424))

另一个有趣的想法是逐渐减少每个技能重复的时间量，以进一步鼓励长距离探索。

## HRL 总结

当你的问题足够复杂，以至于拆分策略能获益时，构建策略层级是有用的。从工程角度来看，如果你能想象拆分策略有助于简化问题或构建更稳健的抽象，那么 HRL 可能很合适。分层策略的潜力很难发现。寻找智能体必须操纵复杂领域的情况。机器人技术是一个显而易见的例子，但其他领域同样复杂，比如处理文本的智能体。^([19](#ch08.html#idm46428619787208)) 相反，在许多现实问题中，复杂的是环境而非智能体，因此 HRL 可能无益。

在极端情况下，HRL 类似于一个图问题，其中微子策略之间的连接形成一个大图。最近的研究尝试将状态视为图，并将拓扑特征与图卷积神经网络结合使用，以帮助解决基于网格的问题。^([20](#ch08.html#idm46428619784808))

#### 提示

即使你不处理复杂智能体，我认为 HRL 表明无监督学习在 RL 中扮演着重要角色。而这只是刚刚开始引起研究人员的关注。^([21](#ch08.html#idm46428619782216)) 花点时间考虑一下你的问题是否能从初始技能库或预训练中受益；这可能会显著提高学习速度。

另一个有趣的问题是你需要对策略施加多大影响？HRL 生成的技能不是由专家决定的，因此它们可能会产生陌生的、意想不到的，甚至是不想要的动作序列。当然，它们是由无监督或有监督奖励的定义指导的，所以你可以通过这种方式影响技能。但一个开放性问题——这可能取决于具体问题——是你应该干预以产生人类“构想”的策略，还是允许智能体自行发现。我怀疑在大多数现实问题中，这两者是结合的。你不想过于规定性，因为那正是 RL 的重点——你无法在复杂问题中手工编写最优策略。但你也需要约束问题并限制智能体，以免它过拟合而变得脆弱。

# 多智能体强化学习

贯穿全文，我一直考虑的是单个智能体。但许多问题涉及不止一个玩家/智能体，如果你系统地从多智能体角度建模问题，很有可能提高性能。

多智能体强化学习 (MARL) 解决的是多个自主智能体在共同环境中运行的序贯决策问题。每个智能体试图通过与环境和其他智能体交互来优化长期回报。

MARL 应用主要分为三大类：合作、竞争或两者的混合。在合作设定中，智能体试图协作以优化共同的长期目标。例如，合作 MARL 可以模拟并优化税收政策。^([22](#ch08.html#idm46428619769848)) 在竞争设定中，全局奖励通常总和为零，因为智能体只能以牺牲另一个智能体为代价来改进自己的策略。这种情况常见于包含价格竞价的领域，如交易和广告。最后，环境可能同时包含前两种情况。例如，广告市场希望同时最大化全局收入和长期用户参与度，这意味着合作模型是最优的，但广告商希望以最少的钱获得最高的影响力，这给环境增加了竞争因素。

文献通常在游戏背景下讨论 MARL，通常是国际象棋或扑克等传统游戏，越来越多的是计算机游戏。像标准 RL 一样，使用游戏的原因是它们易于模拟和验证。现实生活或工业案例较少见，但正在涌现。例如，应用包括使用 MARL 正式定义政府政策、低层 TCP 数据包拥塞缓解和多机器人人机协作辅助。^([23](#ch08.html#idm46428619766728),[24](#ch08.html#idm46428619764632),[25](#ch08.html#idm46428619762504))

文献倾向于用两种方式之一来建模 MARL 问题，你可以在 [图 8-5](#ch08.html#fig_marl_framework) 中看到。

[图 8-5](#ch08.html#fig_marl_framework)(b) 说明了第一个 MARL 框架是 `MDP` 的一种扩展，称为 `马尔可夫博弈` (`MG`)，其中多个智能体并行运行。智能体提交唯一的动作并接收唯一的奖励，但环境的状态是全局的。在 RL 背景下，这是对 `MDP` 最明显的扩展。
