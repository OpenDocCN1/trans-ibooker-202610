
# Instacart 购物车环境

Instacart [从其购物平台开源了三百万订单](https://oreil.ly/-g1ix)。我执行了大量的数据清洗，得到的状态由 `one-hot` 编码的星期几和一天中的小时组成。它还包括距离上次订单以来的天数，归一化为值 1。动作是一个包含 50,000 个 `one-hot` 二进制编码产品的列表。要订购产品，你需将该产品的列设为 1。我保持奖励简单。每匹配一个客户实际订购的产品，你将获得 +1 的奖励。每订错一个产品，你将获得 -1 的奖励。目标是订购客户想要的东西，且仅订购这些东西。每个订单是一步，单个客户的所有订单构成一个回合。

这是对现实世界发生情况的简化。实际奖励不太可能像 +/– 1 这样简单。向客户推荐新产品可能会促使他们未来购买更多，而如果产品易腐烂且无法转售，一个错误可能代价高昂。我受限于数据集提供的特征。其他特征可能更有信息量。例如，Stitch Fix 拥有你的偏好库。你应该建立一个流程来收集用户关于食物喜好的偏好。

但最大的问题是模拟使用的是静态数据。理想情况下，智能体应该探索客户想要哪些产品。客户自己可能还不知道。但有了固定数据，你就是在优化求解一个静态解。换句话说，你可以使用标准机器学习技术。可执行的探索是 `RL` 的核心，而在这个例子中没有探索。`RL` 不仅仅是预测。

一个潜在的解决方案是对客户购买行为建模。例如，你可以构建一个 `generative adversarial network` 来模拟客户在模拟但动态环境中的购买行为。然后你可以将学到的策略迁移到实时环境中（参见[“延伸阅读”](#ch05.html#sec_ch05-further-reading)）。为求简单，我使用静态数据。

## 预期

该环境中的状态和动作都是二进制的，所以你可以使用像 `Q-learning` 这样的表格技术。但为了延续本章的主线，我将使用 `eligibility actor-critic policy gradient algorithm`（参见[“资格迹行动者-评论家”](#ch05.html#sec_eligibility_actor_critic)）。智能体必须生成与产品数量相同的二进制动作。我对每个动作使用带有 `logistic function` 的 `linear policy`。注意 `softmax` 不合适，因为它会将所有动作归一化为总值为 1。我还将 `value function` 建模为 `linear function`。两者都是为求简单。你可以使用更复杂的模型。

让我暂停一下，设定一些预期。购买产品的倾向是客户画像的函数。你可以想象，如果客户有婴儿，他们可能更倾向于购买婴儿用品。如果他们是素食者，他们不太可能订购肉类。如果他们年轻，他们购买的产品可能与老年人不同。所有这些都是潜在特征。它们无法直接从他们的行为中观察到。正是由于这个原因，线性模型在实际测试中不太可能表现得很好。线性模型将学习客户购买产品的频率，而忽略*为什么*购买它们。

### 提示

通过减少潜在特征的数量来简化问题。创建显式特征。

在实际应用中，如果你投资构建一个更复杂的模型来代表客户，而不仅仅是产品，将会大有裨益。给定足够的数据，你也应该考虑深度学习来表示这些高层特征。

另一个问题是线性模型没有记忆。当我大量囤积洗衣粉时，下次购物很少再买。例外是孩子们决定在泥里搭床单窝的时候。但线性权重看到我买了很多洗衣粉，可能会推荐更多。要了解人们以不同速率购买产品，你必须引入一些记忆。最简单的方法之一是将之前的订单包含在状态中。这就是 `DQN` 在 Atari 环境中表现如此出色的原因，例如。研究人员发现，四帧像素足以提供记忆的代理。更高级的解决方案包括使用有状态神经网络，如 `recurrent` 和 `long short-term memory` 神经元（参见[“常见神经网络架构”](#ch04.html#sec_nn_architectures)）。

## 购物车环境的结果

同样，为求简单，我坚持使用线性实现。为了应对规模问题——50,000 个动作——我只允许智能体购买最受欢迎的产品。

你可以在[图 5-9](#ch05.html#fig_simple_shopping_single_customer)中看到初步结果。在这个初始实验中，我将数据集限制为单个客户。我选择保留该客户最受欢迎的 15 种产品，并训练智能体 50 个回合。你也可以看到一个随机订购产品的智能体，作为参考。在这个例子中，该客户在 71 个订单中购买了 358 件热门产品。因此可能的最高奖励是 358。

![](assets/rele_0509.png)

智能体获得的最高奖励是 57，表明智能体购买了客户真正想要的产品。但这远低于 358 件产品的最高可能奖励。随机智能体表现持续不佳，因为它反复订购客户不想要的产品。

在[图 5-10](#ch05.html#fig_simple_shopping_random_customers)中，我重复相同的实验，但这次使用 50 位拥有不同订单数量的随机客户。换句话说，智能体无法过拟合单个客户。它必须尝试泛化到所有客户。这次智能体达到的最大奖励是 -1。与之前的实验相比，这有点令人失望。这表明智能体对于任何给定的随机客户，大致只能做到收支平衡。但你必须记住智能体有多简单。智能体只有少量的线性参数，但在有限程度上，它能够捕捉购物过程的复杂性。我发现这很了不起。

[图 5-11](#ch05.html#fig_simple_shopping_number_of_products) 展示了当改变智能体可选产品数量时，同一智能体在随机客户上的表现。换句话说，我是在改变动作的数量。当产品数量增加时，智能体获得的奖励减少。然而，性能似乎是渐近的。随着训练时间增加，性能可能会收敛。

![](assets/rele_0510.png)![](assets/rele_0511.png)

最后，我想演示一种称为 `transfer learning` 的东西。目标是训练一个模型解决一个问题，然后将同一个模型应用到一个不同但相关的问题上。这种范式在 `RL` 中效果很好，因为你可以潜在地从离线数据或模型中学习，并使用在线数据进行微调。

例如，我可以使用在随机客户上训练的购物车模型（[图 5-10](#ch05.html#fig_simple_shopping_random_customers)），然后将学到的模型迁移到新客户身上。[图 5-12](#ch05.html#fig_simple_shopping_transfer_learning) 展示了此类实验的结果。
