# Summary

This wraps up the tour of data components in your cloud native application stack. Adding analytics rounds off the total data picture by giving you the ability to find insights in larger volumes of data that can complement other parts of your application.

Analytics is at the frontier of cloud native data innovation and for this reason “Big Data” isn’t something you should assume fits into Kubernetes in the same way as other data infrastructure. There are a lot of special considerations when deploying tools like Apache Spark. Not every problem is solved but the knowledge is available to help you deploy with confidence. Projects such as Apache YuniKorn and Volcano.sh are already leading the way in open source to give Kubernetes a better foundation for analytic workloads. New analytic engines such as Dask and Ray are emerging that may be a better choice for your use case, and they can be used in combination with other tools.

Analytic workloads may not have been in your original plans for deployment in Kubernetes, but in order to build the complete picture of a virtual data center, purpose-designed to run your application, they can’t be skipped. To use compute, network, and storage at utility-scale Kubernetes is the future.
