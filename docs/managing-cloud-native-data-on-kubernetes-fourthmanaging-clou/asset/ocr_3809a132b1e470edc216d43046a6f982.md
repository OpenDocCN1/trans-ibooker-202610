# Streaming on Kubernetes with Apache Pulsar™

Apache Pulsar™ is an exciting project to watch for cloud native streaming applications. Streaming software has mostly been built in an era before Kubernetes and cloud native architectures. Pulsar was originally developed at Yahoo! which is no stranger to high scale cloud native workloads. Donated to the Apache Software Foundation, it was accepted as a top level project in 2018. There are additional projects, like Apache Kafka or RabbitMQ, that may suit your application’s needs, but they will require more planning and well-written operators to function at the level of efficiency of Pulsar. In terms of the streaming definitions we covered previously, Pulsar supports the following characteristics

+   - Types of delivery: one-to-one and pub/sub
+   - Delivery guarantees: at-least-once, at-most-once, exactly-once
+   - Feature scope for streaming: Message broker, analytics (through functions)

So what makes Pulsar a good fit for Kubernetes?

We use Kubernetes to create virtual data centers to efficiently use compute, network, and storage. Pulsar was designed from the beginning with a separation of compute and storage resource types linked by the network, similar to a microservices architecture.
