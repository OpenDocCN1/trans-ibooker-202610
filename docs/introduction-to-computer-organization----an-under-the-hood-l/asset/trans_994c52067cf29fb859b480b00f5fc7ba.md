
我们将 `write` 系统调用的编号传递给 `eax` 寄存器中的 `int 0x80` 处理程序 3。`write` 系统调用的参数与我们在第 13 章调用 `write` C 语言封装函数时使用的参数相同（参见[清单 13-2](#c13.xhtml#listing13-2)），但我们需要将它们传递到[表 21-2](#c21.xhtml#table21-2) 2 中指定的寄存器中。

你可能会注意到，在调用 `int 0x80` 处理程序时，我们只使用了寄存器的 32 位部分。该机制是为 32 位环境设计的。尽管它在我们的 64 位环境中也能工作，但 x86 架构的 64 位增强增加了一条用于进行快速系统调用的指令，我们将在下一节讨论。

### `syscall` 指令

除了增加更多寄存器外，x86 架构的 64 位增强还增加了一些指令，其中之一是*快速系统调用* `syscall`。`syscall` 指令绕过了中断描述符表。它是在 64 位模式下进行系统调用的首选方法：

#### `syscall`——快速系统调用

`syscall` 将 `rip` 的内容移至 `rcx`，然后将 `LSTAR` 寄存器的内容移至 `rip`。将 `rflags` 移至 `r11`。切换到特权级 0。

`LSTAR` 寄存器是一个特殊的 CPU 寄存器，操作系统在其中存储 `syscall` 处理程序的地址。

与 `int 0x80` 指令不同，`syscall` 不使用中断描述符表，也不在栈上保存信息，从而节省了多次内存访问。它的所有操作都在 CPU 的寄存器中进行。这就是为什么它被称为*快速系统调用*。当然，这意味着如果 `syscall` 处理程序使用 `rcx` 和 `r11` 寄存器，它必须保存它们的内容，并在返回前将它们恢复为原始值。

从 `syscall` 处理程序返回是通过 `sysret` 指令完成的，该指令将 `r11` 移至 `rflags`，将 `rcx` 移至 `rip`，并将 CPU 特权级设置为 3。

你必须按照[表 21-4](#c21.xhtml#table21-4) 所示，通过寄存器传递 Linux 中 `syscall` 系统调用的参数。请务必注意，参数传递的寄存器与 `int 0x80` 系统调用不同。

**表 21-4：`syscall` 系统调用指令的寄存器用法**

| 系统调用号 | 参数 1 | 参数 2 | 参数 3 | 参数 4 | 参数 5 | 参数 6 |
| --- | --- | --- | --- | --- | --- | --- |
| `rax` | `rdi` | `rsi` | `rdx` | `r10` | `r8` | `r9` |

`syscall` 的系统调用编号列在 Linux 文件 `unistd_64.h` 中。在我使用的 Ubuntu 版本（20.04 LTS）中，该文件位于 `/usr/include/x86_64-linux-gnu/asm/unistd_64.h`。[表 21-5](#c21.xhtml#table21-5) 列出了几个常用的系统调用编号。

**表 21-5：`syscall` 指令的一些 Linux 操作**

| 操作 | `rax` | `rdi` | `rsi` | `rdx` |
| --- | --- | --- | --- | --- |
| `read` | 0 | 文件描述符 | 存放输入的地址 | 读取的字节数 |
| `write` | 1 | 文件描述符 | 待输出首字节的地址 | 写入的字节数 |

[清单 21-2](#c21.xhtml#listing21-2) 展示了使用 `syscall` 指令的“Hello, World!”程序。

```
# helloWorld-syscall.s
# Hello World program
# ld -e myStart -o helloWorld3_int80 helloWorld3_int80.o
        .intel_syntax noprefix
# Useful constants
        .equ    STDOUT, 1           # screen
      1 .equ    WRITE, 1            # write system call
        .equ    EXIT, 60            # exit system call
        
        .text
        .section  .rodata           # read-only data
message:
        .string "Hello, World!\n"
        .equ    msgLength, .-message-1

# Code
        .text                       # code
        .globl  myStart

myStart:
      2 mov     rdx, msgLength      # message length
        lea     rsi, message[rip]   # message address
        mov     rdi, STDOUT         # the screen
        mov     rax, WRITE          # write the message
        syscall                     # tell OS to do it

        mov     rax, EXIT           # exit program
        syscall
```

清单 21-2：使用 `syscall` 指令的“Hello, World!”程序

汇编和链接[清单 21-2](#c21.xhtml#listing21-2) 中程序的命令如下：

```
$ as --gstabs -o helloWorld_syscall.o helloWorld-syscall.s
$ ld -e myStart -o helloWorld-syscall helloWorld-syscall.o
```

该程序仅执行 `write` 和 `exit` 操作，为了可读性，在代码开头为它们赋予了符号名称 1。它在执行 `syscall` 指令 2 之前，将 `write` 操作的参数存储在正确的寄存器中。

## 你学到了什么

1.  **特权级**：操作系统通过在较低的 CPU 特权级运行应用程序来维持对硬件的控制。
2.  **门描述符**：一条包含中断处理程序地址和运行中断处理程序的 CPU 特权设置的记录。
3.  **中断描述符表**：门描述符的数组。中断或异常编号是数组的索引。
4.  **外部中断**：其他硬件设备可以中断 CPU 的常规执行周期。
5.  **异常**：CPU 中的特定条件可能导致 CPU 中断其常规执行周期。
6.  **软件中断**：导致 CPU 中断其常规执行周期的特定指令。
7.  **中断处理程序**：当发生中断或异常时，由 CPU 调用的操作系统中的一个函数。
8.  `int 0x80`：Linux 中用于执行系统调用的软件中断。
9.  `syscall`：用于在 64 位 Linux 中执行快速系统调用的指令。

这只是对中断和异常的简要概述。细节复杂，需要对你正在使用的特定 CPU 型号有透彻的了解。
