
# ModR/M 字节与寄存器编码

两个 Mod 位指定四种可能的寻址模式之一。Reg/Opcode 位指定一个寄存器或操作码的附加位。R/M 位指定一个寄存器，该寄存器由指令以不同方式使用，具体取决于 Mod 位中指定的寻址模式。

本书不会列出 ModR/M 字节的所有可能情况，因为手册中已有这些信息。我们将通过几条指令来了解它们的编码方式，这应该能帮助你弄清如何阅读手册。

表 12-1 和表 12-2 给出了指令中任意部分所用寄存器的代码。[表 12-1](#c12.xhtml#table12-1) 显示了用于指定前八个寄存器 `rax`–`rdi` 的 8 位、16 位和 32 位部分的代码。

## 表 12-1：8 位、16 位和 32 位寄存器代码

| **8 位寄存器** | **16 位寄存器** | **32 位寄存器** | **代码** |
|---|---|---|---|
| `al` | `ax` | `eax` | `000` |
| `cl` | `cx` | `ecx` | `001` |
| `dl` | `dx` | `edx` | `010` |
| `bl` | `bx` | `ebx` | `011` |
| `ah` | `sp` | `esp` | `100` |
| `ch` | `bp` | `ebp` | `101` |
| `dh` | `si` | `esi` | `110` |
| `bh` | `di` | `edi` | `111` |

你可能会想，CPU 如何区分具有相同代码的寄存器的三种尺寸。默认操作数大小为 32 位。如果你使用 16 位寄存器，汇编器会在操作码前插入 `0x66` 前缀字节，这会覆盖默认值，导致该指令使用 16 位操作数。8 位和 32 位操作的区别在于使用不同的操作码。

[表 12-2](#c12.xhtml#table12-2) 显示了完整 64 位寄存器集的寄存器代码。正如你在下一节将看到的，大多数 64 位操作是通过在操作码前添加 REX 前缀字节来完成的。

## 表 12-2：64 位寄存器代码

| **寄存器** | **代码** | | **寄存器** | **代码** |
|---|---|---|---|---|
| `rax` | `0000` | | `r8` | `1000` |
| `rcx` | `0001` | | `r9` | `1001` |
| `rdx` | `0010` | | `r10` | `1010` |
| `rbx` | `0011` | | `r11` | `1011` |
| `rsp` | `0100` | | `r12` | `1100` |
| `rbp` | `0101` | | `r13` | `1101` |
| `rsi` | `0110` | | `r14` | `1110` |
| `rdi` | `0111` | | `r15` | `1111` |

你可能注意到的关于 [表 12-2](#c12.xhtml#table12-2) 中寄存器代码的第一件事是它们是四位，但 ModR/M 字节仅允许三位用于代码。如果指令仅使用前八个寄存器 `eax` 到 `edi` 的 32 位部分，则高位为 `0` 且不需要。剩余的三位适合放入 ModR/M 字节中。稍后你将看到，当指令使用 `r8`–`r15` 寄存器的任何部分或 16 个寄存器 `rax`–`r15` 中任意一个的完整 64 位时，第四位位于何处。

[清单 12-1](#c12.xhtml#listing12-1) 第 12 行的指令是另一个仅使用 32 位寄存器的示例。它与第 11 行的指令具有相同的操作码 `0x89`，但它们操作不同的通用寄存器。寄存器在 ModR/M 字节中指定：`11 001 000` 表示从 `ecx` 移动到 `eax`，`11 110 111` 表示从 `esi` 移动到 `edi`。我在位模式中插入了空格，以便你能看到每个字节中对应 [图 12-2](#c12.xhtml#figure12-2) 的三个字段。Mod 字段 `11` 指定用于移动的寄存器到寄存器模式。查阅 [表 12-1](#c12.xhtml#table12-1)，我们可以看到第 12 行 Reg/Opcode 字段中的三位 `110` 指定源寄存器 `esi`，而 R/M 字段中的三位 `111` 指定目标寄存器 `edi`。

第 13 行的指令仅将 16 位从 `cx` 移动到 `ax`。它不使用不同的操作码，而是用前缀字节 `0x66` 来表示这种与 32 位移动的差异。在第 14 行，我们仅将 8 位从 `cl` 移动到 `al`，这使用了不同的操作码 `0x88`。

第 15 行显示了一个 32 位移动，但这次我们使用的是从 32 位 CPU 设计升级到 64 位时新增的寄存器之一 `r8d`。现在我们需要四位来指定 `r8` 寄存器，这要求汇编器用 REX 前缀修改指令。

# REX 前缀字节

大多数涉及 64 位操作数或 `r8` 到 `r15` 寄存器之一的指令都需要 *REX 前缀* 字节。[图 12-3](#c12.xhtml#figure12-3) 显示了 REX 前缀的格式。

![图 12-3：REX 前缀格式](image_fi/500099c12/f12003.png)

**图 12-3：REX 前缀格式**

REX 前缀字节以高位四位 `0100` 开头。对于 64 位操作数，W 位设为 `1`；对于任何其他大小，设为 `0`。如果指令使用了任何 64 位寄存器 `r8` 到 `r15`，则每个寄存器的高位（见 [表 12-2](#c12.xhtml#table12-2)）存储在 R、X 或 B 位中，具体取决于寄存器在指令中的用法。（其余三位存储在 ModR/M 字节中，如前所述。）

通过比较第 11 行和第 16 行的指令，我们可以看到 W 位的用法。它们都将数据从 `rcx` 寄存器移动到 `rax` 寄存器，但第 11 行的指令移动 32 位，而第 16 行的指令移动 64 位。两条指令的唯一区别是 64 位指令增加了 REX 前缀字节 `01001000`（W = `1`）。

第 15 行的指令仅移动 32 位，但源寄存器是为从 32 位 CPU 升级到 64 位而新增的寄存器之一。因此，汇编器添加了 REX 前缀 `01000100`。W 位为 `0`，表示 32 位移动，但 R 位为 `1`。执行此指令时，CPU 将这个 `1` 用作 ModR/M 字节 `11 000 111` 中源寄存器字段的高位，得到 `1000`，即 `r8`（见 [表 12-2](#c12.xhtml#table12-2)）。由于 W = `0`，该指令仅移动 32 位。

到目前为止，我们只考虑了用于将值从一个 CPU 寄存器移动到另一个寄存器的指令寻址模式。当然，首先需要有一种方法将值移入寄存器。接下来我们将研究一种可用于将常量值移入寄存器或内存的寻址模式。

# 立即寻址模式

最多 64 位的单个数据项可以作为指令的一部分存储。指令使用 *立即寻址* 模式访问它（*立即* 是因为数据项位于指令操作部分之后的紧邻地址）。数据值可以移入寄存器或内存位置。这里我们只看移入寄存器的情况。[清单 12-2](#c12.xhtml#listing12-2) 提供了一些使用立即寻址模式在寄存器中存储常量的示例。
