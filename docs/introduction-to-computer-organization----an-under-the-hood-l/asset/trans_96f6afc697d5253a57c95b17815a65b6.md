### 让编译器编写构造函数和析构函数

如果我们只需要一个默认构造函数来初始化数据成员，甚至不需要编写构造函数或析构函数。Bjarne Stroustrup 和 Herb Sutter 维护了一份优秀的 C++ 编写建议清单。他们的建议 C.45 ([https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rc-default/](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rc-default/)) 指出：“不要定义仅初始化数据成员的默认构造函数；应改用类内成员初始化器。”他们指出，编译器会为我们“生成该函数”，这“可能更高效”。我读过的大多数 C++ 书籍给出的建议基本相同。

在本节中，我们将遵循这一建议。我们将通过删除构造函数和析构函数，修改来自 [Listing 18-1](#c18.xhtml#listing18-1)、[Listing 18-3](#c18.xhtml#listing18-3) 和 [Listing 18-5](#c18.xhtml#listing18-5) 的代码。然后我们将利用汇编语言知识来查看编译器为我们生成了什么。[Listing 18-7](#c18.xhtml#listing18-7) 展示了没有构造函数或析构函数的 `fraction` 类，改用*类内成员初始化器*。

```
// fraction.hpp
// Simple fraction class.

#ifndef FRACTION_HPP
#define FRACTION_HPP
// Uses the following C functions
extern "C" int writeStr(char *);
extern "C" int getInt(int *);
extern "C" int putInt(int);

class fraction
{
  1 int num{0};              // numerator
    int den{1};              // denominator
  public:
    void get();              // gets user's values
    void display();           // displays fraction
    void add(int theValue);   // adds integer
};
#endif
```

Listing 18-7：来自 [Listing 18-1](#c18.xhtml#listing18-1) 的 `fraction` 类，移除了构造函数和析构函数

我们将不再使用构造函数来初始化 `fraction` 对象中的数据成员，而是使用 C++ 的*大括号初始化*语法 1。C++ 还允许以下语法进行数据成员初始化：

```
int num = 0;
int num = {0};
```

我喜欢大括号初始化语法，因为它传达了这样的信息：直到对象被实例化时，实际的赋值操作才会发生，我们稍后就会看到。这些差异在本章开头引用的 Josh Lospinoso 的书中有讨论。

我们不会更改 [Listing 18-3](#c18.xhtml#listing18-3) 中的代码，并将从 [Listing 18-5](#c18.xhtml#listing18-5) 中移除构造函数和析构函数（`fraction()` 和 `~fraction()`）。这些更改为我们提供了 [Listing 18-8](#c18.xhtml#listing18-8) 中所示 `main` 函数的编译器生成汇编语言。

C++ 在栈帧中创建对象，就像我们编写自己的构造函数时一样 1。但编译器不会编写单独的构造函数。相反，它会在实例化对象的函数中直接初始化数据成员 2。

由于 `fraction` 对象使用的唯一资源是栈上的内存，函数尾声中的正常栈清理会删除该对象。因此，编译器不需要做任何特殊操作来析构我们的 `fraction` 对象 3。

将 [Listing 18-8](#c18.xhtml#listing18-8) 中的代码与 [Listing 18-4](#c18.xhtml#listing18-4) 中的代码进行比较，我们可以看到编译器节省了八条指令，包括两次函数调用。所以它确实为我们创建了一个更高效的构造函数。但汇编语言也向我们展示了，说编译器生成了一个*内联构造函数*而不是构造函数功能更为准确。当然，C++ 语言规范允许其他编译器以不同方式处理此事。

最后，我想指出的是，如果我们需要另一个接受参数的构造函数，那么我们也必须提供自己的默认构造函数。编译器不会为我们处理默认构造。
