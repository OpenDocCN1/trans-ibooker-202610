首先要注意的是，编译器包含了 `inb` 和 `outb` 函数的汇编语言 1。这些函数不是 C 标准库的一部分。它们旨在用于操作系统代码，而不是应用程序。它们特定于运行在 x86-64 计算机上的 Linux 内核。

接下来，我们看到实际的 `in` 和 `out` 指令是由宏 2 插入到代码中的。这些宏以 AT&T 语法插入这两条指令（请参见第 10 章末尾的 AT&T 语法）：

```
        inb     dx, al        ## at&t syntax
        outb    al, dx
```

正如我们在本章前面看到的，这些指令以 Intel 语法编写如下：

```
        in      al, dx        ## intel syntax
        out     dx, al
```

这里的问题是 Linux 内核使用的汇编语言是用 AT&T 语法编写的，而我们使用的是 Intel 语法。如果我们在不使用 `-masm=intel` 选项的情况下生成汇编语言，所有汇编语言都将是 AT&T 语法。如果我们使用 `io.h` 中的 C 函数进行端口映射 I/O，就不能使用 `-masm=intel` 编译器选项。

## 你学到了什么

1. 内存时序：内存访问与 CPU 的时序同步。
2. I/O 时序：I/O 设备比 CPU 慢得多，且具有广泛的特性，因此我们需要对其访问进行编程。
3. 总线时序：总线通常以层次化方式排列，以更好地匹配各种 I/O 设备之间的时序差异。
4. 端口映射 I/O：在这种技术中，I/O 端口拥有自己的地址空间。
5. 内存映射 I/O：在这种技术中，I/O 端口被分配主内存地址空间的一部分。
6. 轮询 I/O：程序在循环中等待，直到 I/O 设备准备好传输数据。
7. 中断驱动 I/O：当 I/O 设备准备好传输数据时，它会中断 CPU。
8. 直接内存访问：I/O 设备可以在不使用 CPU 的情况下向主内存传输数据。

在下一章中，你将了解允许 CPU 保持对 I/O 硬件的控制并防止应用程序在不经过操作系统的情况下访问硬件的 CPU 特性。

# 第 21 章：中断和异常

![](image_fi/book_art/chapterart.png)

到目前为止，我们将每个应用程序视为独占使用计算机。但像大多数操作系统一样，Linux 允许多个应用程序并发执行。操作系统以交织的方式管理硬件，在任何给定时间为每个应用程序以及操作系统本身提供所需的硬件组件的使用。

这里有两个问题。首先，为了执行其管理任务，操作系统需要保持对应用程序与硬件之间交互的控制。它通过使用 CPU 中的*权限级别*系统来实现这一点，该系统允许操作系统控制应用程序与操作系统之间的网关。其次，我们在上一章末尾看到，大多数 I/O 设备在准备好输入或准备好接受输出时，可以中断 CPU 的正在进行的活动。CPU 有一种机制，通过这个网关引导 I/O 中断，并调用受操作系统控制的函数，从而允许操作系统保持对 I/O 设备的控制。

我们将首先看看 CPU 如何使用权限级别来强制执行其控制。然后我们将看看 CPU 如何对中断或异常做出反应，包括通知 CPU 其服务被 I/O 设备或应用程序需要的三种方式：*外部中断*、*异常* 或 *软件中断*。我们将通过讨论应用程序如何通过使用软件中断直接调用操作系统服务来结束本章。

## 权限级别

为了执行其管理任务，操作系统需要保持对应用程序与硬件之间交互的控制。它通过使用 CPU 中的*权限级别*系统来实现这一点，操作系统使用该系统在应用程序和硬件之间维护一个网关。在任何给定时间，CPU 都在四个可能的权限级别之一中运行。表 21-1 显示了从最高权限到最低权限的级别。

表 21-1：CPU 权限级别

| 级别 | 用途 |
| --- | --- |
| 0 | 提供对所有硬件资源的直接访问。仅限于最底层的操作系统功能，如 I/O 设备和内存管理。 |
| 1 | 对硬件资源的访问受到一定限制。可能被某些库例程和控制不需要完全硬件访问权限的 I/O 设备的软件使用。 |
| 2 | 对硬件资源的访问受到更多限制。可能被某些库例程和控制不需要比级别 1 更少访问权限的 I/O 设备的软件使用。 |
| 3 | 无法直接访问硬件资源。应用程序在此级别运行。 |
