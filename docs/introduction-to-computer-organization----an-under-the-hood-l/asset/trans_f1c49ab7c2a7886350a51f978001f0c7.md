
从被调用函数接收输出稍微复杂一些。一种方法是使用`return value`（返回值），在我们的环境中，它被放置在`eax`寄存器中。使用`eax`寄存器假设返回值是一个`int`；对于返回较大值有其他规则，本书不作深入探讨。你已经在本书的大多数示例程序中看到了这种技术的应用。`main`函数几乎总是向调用它的操作系统中的函数返回0。

被调用函数从调用函数接收输出的其他技术要求调用函数将存储输出位置的地址传递给被调用函数。这可以在高级语言中实现为`pass by pointer`（传指针）或`pass by reference`（传引用）。区别在于，使用`pass by pointer`时，程序可以更改指针以指向另一个对象，而在`pass by reference`中，指针不能被程序更改。`C`和`C++`都支持`pass by pointer`，但只有`C++`支持`pass by reference`。在`assembly language`（汇编语言）层面，这些是相同的——存储输出位置的地址被传递给被调用函数。区别由高级语言强制执行。

### 在 C 中传递参数

我们将编写与清单[14-1](#c14.xhtml#listing14-1)、[14-3](#c14.xhtml#listing14-3)和[14-4](#c14.xhtml#listing14-4)中相同的程序，但这次我们将在`main`函数中将变量定义为局部变量，并将它们作为参数传递给`subfunction`，如清单[14-6](#c14.xhtml#listing14-6)所示。

```c
/* sumInts.c
 * Adds two integers using local variables
 */

#include <stdio.h>
#include "addTwo.h"

int main(void)
{
1 int x = 0, y = 0, z;
  
  printf("Enter an integer: ");
  scanf("%i", &x);
  printf("Enter an integer: ");
  scanf("%i", &y);
  addTwo(x, y, 2&z);
  printf("%i + %i = %i\n", x, y, z);

  return 0;
}
```

清单 14-6：求两个整数之和，局部变量

在函数体内部定义变量 1 使它们仅对该函数可见。`x`和`y`变量的值是`addTwo`函数的输入，所以我们传递这些变量的副本。`addTwo`函数将把其结果存储在我们作为第三个参数传递的地址`&z` 2 处。

清单[14-7](#c14.xhtml#listing14-7)展示了`addTwo`函数的头文件。

```c
/* addTwo.h
 * Adds two integers and outputs sum.
 */

#ifndef ADDTWO_H
#define ADDTWO_H
void addTwo(int a, int b, int *c);
#endif
```

清单 14-7：`addTwo`函数的头文件

清单[14-8](#c14.xhtml#listing14-8)展示了该函数的定义。

```c
/* addTwo.c
 * Adds two integers and outputs sum.
 */

#include "addTwo.h"

void addTwo(int a, int b, int *c)
{
  int temp;
  
  temp = a + b;
  *c = temp;
}
```

清单 14-8：`addTwo`函数

该函数的第三个参数`c`是一个指向`int`的指针。我们需要解引用变量`*c`，以将计算结果存储在`c`中传递的地址处。

清单 14-9：编译器为`sumInts`中的`main`函数生成的汇编语言

根据第11章的[表11-2](#c11.xhtml#table11-2)，我们了解到第三个参数通过寄存器`rdx`传递。我们可以看到，当编译器将该地址加载到`rdx` 1 中时，它在`rbp`偏移-12处分配了空间。

接下来，我们将查看`addTwo`函数的编译器生成的汇编语言，如清单[14-10](#c14.xhtml#listing14-10)所示。

```asm
        .file   "addTwo.c"
        .intel_syntax noprefix
        .text
        .globl  addTwo
        .type   addTwo, @function
addTwo:
        push    rbp
        mov     rbp, rsp
      1 mov     DWORD PTR -20[rbp], edi   ## store a
        mov     DWORD PTR -24[rbp], esi   ## store b
        mov     QWORD PTR -32[rbp], rdx   ## address of c
        mov     edx, DWORD PTR -20[rbp]
        mov     eax, DWORD PTR -24[rbp]
        add     eax, edx                  ## a + b
        mov     DWORD PTR -4[rbp], eax    ## sum = a + b;
      2 mov     rax, QWORD PTR -32[rbp]   ## address of c
        mov     edx, DWORD PTR -4[rbp]    ## load sum
      3 mov     DWORD PTR [rax], edx      ## *c = sum;
      4 nop
        pop     rbp
        ret
        .size   addTwo, .-addTwo
        .ident  "GCC: (Ubuntu 9.3.0-17ubuntu1~20.04) 9.3.0"
        .section        .note.GNU-stack,"",@progbits
```

清单 14-10：编译器为`addTwo`函数生成的汇编语言

你可能注意到的关于这个函数的第一件事是，它没有在栈上为局部变量分配空间，但它正在使用栈上的一个区域来存放`sum`局部变量。此外，它将三个输入参数存储在通常放置局部变量的栈区域中 1。`System V Application Binary Interface`（System V 应用程序二进制接口）定义了栈指针之外的128字节——即地址低于`rsp`寄存器中地址的128字节——为`red zone`（红区）。操作系统不允许使用此区域，因此函数可以用它来临时存储在调用另一个函数时不需要保存的值。特别是`leaf functions`（叶子函数），即不调用其他函数的函数，可以在不移动栈指针的情况下在此区域存储局部变量。
