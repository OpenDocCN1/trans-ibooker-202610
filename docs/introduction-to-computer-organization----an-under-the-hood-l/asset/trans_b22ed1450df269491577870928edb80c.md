
当然，由于求和是从右向左计算的，因此存在时间延迟。通过更复杂的电路设计预先计算 `CF` 进位和 `OF` 的值，可以显著减少计算时间，但本书不深入探讨此类细节。让我们转向下一种电路类型。

## 解码器

计算机中的许多场合都需要根据一个数字从多个连接中选择一个。例如，正如几章后你将看到的，CPU 拥有少量组织在 `registers`（寄存器）中的内存，用于计算。x86-64 架构有十六个 64 位寄存器。如果一条指令使用其中一个寄存器，指令中的四位必须用于选择这十六个寄存器中的哪一个。

这种选择可以用 `decoder`（解码器）来完成。解码器的输入是寄存器的四位编号，输出是十六个可能的连接之一，连接到指定的寄存器。

解码器有 `n` 个二进制输入，最多可产生 2^n 个二进制输出。最常见的解码器类型，有时称为 `line decoder`（行解码器），对于每种输入位模式，仅选择一条输出线设置为 `1`。解码器包含一个 Enable（使能）输入也很常见。[表 6-3](#c06.xhtml#table6-3) 中带使能输入的 3 × 8（3 个输入，8 个输出）解码器的真值表展示了其工作原理。当 Enable = `0` 时，所有输出线均为 `0`。当 Enable = `1` 时，输入端的三位数 `x` = `x`[2]`x`[1]`x`[0] 选择哪条输出线设置为 `1`。因此，该解码器可用于通过三位数选择八个寄存器之一。（此处未使用 x86-64 架构中的十六个寄存器，以保持表格大小合理。）

解码器的通用性乍看之下可能被低估。每一种可能的输入都可以视为一个最小项（关于最小项的复习，请参见第 4 章）。[表 6-3](#c06.xhtml#table6-3) 中的行解码器显示，仅当一个最小项评估为 `1` 且 Enable 为 `1` 时，才有一个输出为 `1`。因此，解码器可以被视为“最小项发生器”。从本书前面我们知道，任何逻辑表达式都可以表示为最小项的或（OR），因此可以通过对解码器的输出进行或运算来实现任何逻辑表达式。

例如，如果你回顾全加器的卡诺图（图 6-2 和图 6-4），你可能会看到 `Sum` 和 `Carry` 可以表示为最小项的或，

![c06m0005](image_fi/500099c06/c06m0005.png)

`Sum_i(Carry_i, x_i, y_i) = m1 ∨ m2 ∨ m4 ∨ m7`  
`Carry_i+1(Carry_i, x_i, y_i) = m3 ∨ m5 ∨ m6 ∨ m7`

其中，`x`、`y` 和 `Carry` 上的下标 `i` 指的是位片，`m` 上的下标是最小项表示法的一部分。我们可以用一个 3 × 8 解码器和两个四输入或门来实现全加器的每个位片，如 [图 6-9](#c06.xhtml#figure6-9) 所示。

[图 6-8](#c06.xhtml#figure6-8) 中的解码器电路需要八个与门和三个非门。[图 6-9](#c06.xhtml#figure6-9) 中的全加器增加了两个或门，总共需要十三个逻辑门。将其与 [图 6-5](#c06.xhtml#figure6-5) 中的全加器设计相比，后者仅需五个逻辑门（两个异或、两个与、一个或），似乎使用解码器构建全加器增加了电路的复杂性。但请记住，设计通常基于其他因素，例如元件的可获得性、成本等。
