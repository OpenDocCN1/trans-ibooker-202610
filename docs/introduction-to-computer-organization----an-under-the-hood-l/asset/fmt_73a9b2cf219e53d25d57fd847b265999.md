
## Assembler Directives Summary

The first byte of memory allocated by the `.comm` directive is named `label`, which has global scope in the program. The operating system zeros the `size` bytes of memory associated with `label` when the program is first loaded.

The `.int` and `.long` directives do the same thing—allocate 32 bits in our environment set to the value of `expression`, which must be an integral value. The `.byte` directive must also evaluate to an integral value. These directives can allocate multiple `expression`s, each separated by a comma.

This is only a summary of these directives. You need to consult the `info` page for `as` to read the details.

## What You’ve Learned

1. **Global variables** — Accessible from any function in the program and persist during the entire life of the program.
2. **Automatic local variables** — Accessible only from within the function where they are defined and last only during the execution of their function.
3. **Static local variables** — Accessible only from within the function where they are defined and persist between calls to their function.
4. **Passing arguments** — The first six are passed in registers. Any additional arguments are passed on the stack.
5. **Pass by value** — A copy of the value is passed.
6. **Pass by pointer** — The address of the variable is passed. The address can be changed.
7. **Pass by reference** — The address of the variable is passed. The address cannot be changed.
8. **Stack frame** — Creation of the stack frame begins in the calling function and is completed in the called function.
9. **Frame pointer** — Items placed in the stack frame by the calling function are accessed using positive offset from the frame pointer. Items placed in the stack frame by the called function are accessed using negative offsets.

## Recursion

Many computer solutions involve repetitive actions. We saw how to use iteration—`while`, `for`, and `do-while` loops—to perform repetitive actions in Chapter 14. While iteration can be used to solve any repetitive problem, some solutions are described more succinctly using *recursion*. A *recursive algorithm* is an algorithm that calls itself to compute a simpler case of the problem and uses that result to compute the more complex case at hand. The recursive calls continue until the simpler case reaches a *base case*. At this point, the recursive algorithm returns the base case value to the next more complex case where the value is used in that computation. This return/compute process continues, performing the increasingly complex computations along the way, until we’re back at the original case.

Let’s look at an example. In mathematics, we denote the factorial operation on positive integers with an `!`, which can be defined recursively:

![c15m0001](image_fi/500099c15/c15m0001.png)

<p class="MathEquation"><span class="MText">n</span><span class="MText">!</span><span class="Malign"/><span class="mathalign">= </span><span class="mathalign">n</span><span class="mathvariant"> × </span><span class="Md"><span class="MDelimiter">(</span><span class="MEquation"><span class="MText">n</span><span class="mathvariant"> – 1</span></span><span class="MDelimiter">)</span></span><span class="mathalign">!</span><br/><span class="mathvariant">0!</span><span class="Malign"/><span class="mathvariant"> = 1</span></p>

The first equation shows that *n*! is defined by computing a simpler case of itself, (*n* – 1)!. This computation is performed repetitively until we reach the base case of *n* = 0. Then we work our way back out, computing each *n*! along the way.

For comparison, the iterative definition of the factorial operation is as follows:

![c15m0002](image_fi/500099c15/c15m0002.png)

<p class="MathEquation"><span class="MText">n</span><span class="MText">!  = </span><span class="MText">n</span><span class="mathvariant"> × </span><span class="Md"><span class="MDelimiter">(</span><span class="MEquation"><span class="MText">n</span><span class="mathvariant"> – 1</span></span><span class="MDelimiter">)</span></span><span class="mathvariant"> × </span><span class="Md"><span class="MDelimiter">(</span><span class="MEquation"><span class="MText">n</span><span class="mathvariant"> – 2</span></span><span class="MDelimiter">)</span></span><span class="mathvariant"> × ⋯ 1</span><br/><span class="mathvariant">0!  = 1</span></p>

Although both forms of defining the factorial operation involve the same number of computations, the recursive form is more concise and perhaps more intuitive to some people.

Listings [15-1](#c15.xhtml#listing15-1), [15-2](#c15.xhtml#listing15-2), and [15-3](#c15.xhtml#listing15-3) show a program that uses a function, `factorial`, to compute 3!. You’ll see the reason for using a small, fixed value when we use `gdb` to examine the behavior of the following function:

```c
/* threeFactorial.c
 */
#include <stdio.h>
#include "factorial.h"

int main(void)
{
  unsigned int x = 3;
  unsigned int y;
  
  y = factorial(x);
  printf("%u! = %u\n", x, y);
  return 0;
}
```

**Listing 15-1:** Program to compute 3!

The mathematical factorial function is defined for non-negative integers, so we use `unsigned int`s.

There is nothing remarkable about the header file for the `factorial` function, shown in [Listing 15-2](#c15.xhtml#listing15-2).

```c
/* factorial.h
 */
 
#ifndef FACTORIAL_H
#define FACTORIAL_H

#endif
```

**Listing 15-2:** Header file for `factorial` function

[Listing 15-3](#c15.xhtml#listing15-3) shows that the `factorial` function calls itself to perform a simpler computation, (*n* – 1), so it can easily compute *n*!.

```c
/* factorial.c
 */
#include "factorial.h"

unsigned int factorial(unsigned int n)
{
  unsigned int current = 1; /* assume base case */
  if (n != 0)
  {
    current = n * factorial(n - 1);
  }
  return current;
}
```

**Listing 15-3:** Function to compute n!

The `factorial` function first checks for the base case of *n* = 0 1. If we’re at the base case, the current result is 1. If we’re not at the base case, the `factorial` function calls the `factorial` function to compute (*n* – 1)! and multiplies that by *n* to get *n*! 2.

The assembly language for the `main` function is unremarkable, but let’s look at the assembly language the compiler generated for the `factorial` function; see [Listing 15-4](#c15.xhtml#listing15-4).

```asm
        .file   "factorial.c"
        .intel_syntax noprefix
        .text
        .globl  factorial
        .type   factorial, @function
factorial:
        push    rbp
        mov     rbp, rsp
        sub     rsp, 32
      1 mov     DWORD PTR -20[rbp], edi ## store n
        mov     DWORD PTR -4[rbp], 1    ## current = 1;
        cmp     DWORD PTR -20[rbp], 0   ## base case?
        je      .L2                     ## yes, current good
        mov     eax, DWORD PTR -20[rbp] ## no, compute n - 1
        sub     eax, 1
      2 mov     edi, eax
        call    factorial               ## compute (n - 1)! 
        mov     edx, DWORD PTR -20[rbp] ## load n
      3 imul    eax, edx                ## n * (n - 1)!
        mov     DWORD PTR -4[rbp], eax  ## store in current
.L2
        mov     eax, DWORD PTR -4[rbp]  ## load current
        leave
        ret
        .size   factorial, .-factorial
        .ident  "GCC: (Ubuntu 9.3.0-17ubuntu1~20.04) 9.3.0"
        .section        .note.GNU-stack,"",@progbits
```
