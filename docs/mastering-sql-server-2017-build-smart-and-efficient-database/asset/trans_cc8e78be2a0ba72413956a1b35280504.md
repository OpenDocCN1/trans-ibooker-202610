## 内存OLTP

内存OLTP（代号Hekaton）在SQL Server 2014中引入。在SQL Server 2014发布时，SQL Server内部实现超高性能数据处理这一承诺是一个重要特性。正如意料之中的第一版特性，初始版本存在诸多限制，这使得许多客户无法采用该技术。到SQL Server 2017，其中大量限制要么提升到更高阈值，要么已完全移除。内存OLTP在功能集上已达到所需的成熟度和扩展性，使其能够胜任重要的生产环境部署。

## SQL Server工具

访问或管理SQL Server中的数据与开发数据解决方案是两个不同的领域，各自对SQL Server有特定的关注点。因此，Microsoft创建了两种不同的工具，分别针对这些领域的流程和方面量身定制。

SQL Server Management Studio（SSMS），顾名思义，是DBA/开发人员与SQL Server之间的主要管理界面。该工具最初随SQL Server 2005发布，用以替代并整合旧的查询分析器和企业管理器工具。与任何不产生收入的软件一样，SSMS多年来只获得极少的关注，对于SQL Server中的许多新功能存在局限性并缺乏配套工具。自SQL Server 2016起，Microsoft的重心发生了转变，SSMS已从SQL Server自身的发布周期中解耦。这种解耦使得SSMS和SQL Server都能独立开发，无需等待彼此或受发布窗口限制。SSMS的新版本基于更新版本的Visual Studio构建，自SQL Server 2016推向市场以来，几乎每月都有更新发布。

**SQL Server数据工具（SSDT）**也是一款基于Visual Studio框架的应用程序。SSDT专注于应用程序/数据开发领域。SSDT在结构和提供的功能上与Visual Studio的契合度更高。这一专注点包括创建完整数据库项目和解决方案文件的能力、更轻松地集成到源代码管理系统、将项目连接到自动化构建流程的能力，以及总体上提供一个熟悉Visual Studio的开发人员为中心的开发环境。在SSDT中，可以使用关系引擎、Analysis Services、Integration Services、Reporting Services以及当然还有Azure SQL数据库来设计和创建面向SQL Server的解决方案。

有关SQL Server工具的更多详细信息，请参阅第2章《SQL Server工具》。

## 商业智能

商业智能是IT领域的一大板块，至少自SQL Server 2005以来便一直是SQL Server产品的基石。随着商业智能领域市场和技术的发展，SQL Server也必须与时俱进。基于云的数据分析系统的出现以及近期围绕*大数据*的热议，成为所有数据平台提供商的驱动力，Microsoft也不例外。虽然SQL Server 2016的商业智能部分有多项增强，但我们将重点关注一个受众比数据分析师更广泛的功能：SQL Server中的R语言。

## SQL Server中的R

过去几年，数据分析一直是IT领域最热门的话题，新的细分领域几乎与技术发展速度同步被加冕为信息科学的巅峰。然而，IT领域确实有一些经受住时间考验且仍被广泛使用的坚定*经典*。SQL（及其多种形式）是我们在SQL Server世界中非常熟悉的语言。另一个这样的语言是简洁命名的 **R**。R语言是一种数据挖掘、机器学习和统计分析语言，自1993年以来就存在。

许多专业人士，如数据科学家、数据分析师或统计学家，使用R语言及该领域的工具已有同样悠久的历史。Microsoft认识到，尽管他们可能希望全世界的数据库都置于SQL Server之内，但这既不可行也不合理。像R这样的外部数据源和语言是客观存在的，需要以集成的方式使其可被访问。

为了实现这一点，Microsoft于2015年决定收购Revolution Analytics（一家生产分叉版*Revolution R*的商业实体），随后能够将该语言和服务器进程集成到SQL Server 2016中。这种集成允许*普通*T-SQL开发人员以原生方式与极其强大的R服务交互，并允许对其数据执行更高级的数据分析。

## 发布周期

过去5年中，Microsoft进行了几项重大的面向公众的变革。这些变革包括告别其主打产品的较长发布周期，并转向基于订阅的服务（例如Office 365和Azure服务）。围绕持续交付和敏捷软件开发的理念也塑造了Microsoft交付其旗舰集成开发环境Visual Studio的方式，大约每六个月发布一次。这种理念上的转变正逐步流入SQL Server的开发周期。由于云版SQL Server（Azure SQL数据库）类似的持续发布周期，人们希望尽可能保持该产品的云版本和本地版本接近。因此，看到之前的每三到五年发布周期正被更短的间隔所取代也就不足为奇了。一个明确的例子是：SQL Server 2016于2016年6月发布，SQL Server 2017的**社区技术预览版（CTP）**于2016年11月发布，而SQL Server 2017的**向市场发布（RTM）**则在2017年10月完成。技术进步的浪潮不会为任何人停留。这在SQL Server身上体现得尤为明显！

## SQL Server工具

作为开发人员，我们习惯于在软件项目中使用**集成开发环境（IDE）**。Visual Studio多年来（甚至几十年来）一直是IDE领域的主要参与者，它让开发人员能够使用最新的软件开发流程，进一步提高软件项目的质量和效率。另一方面，服务器管理在过去对于许多产品来说通常被当作“二等公民”。总的来说，这一点即使不被认同，也是可以理解的。IDE是设计和创建能为企业带来收入的软件的工​​具，而管理工具通常只能提供某种成本节约的好处，而不是直接创造收入。

过去的SQL Server工具（2005版之前）非常侧重于满足管理和查询SQL Server实例及数据库的要求，但在使这些工具使用起来更*舒适*甚至愉悦方面却没有投入多少精力。高级IDE明确属于应用程序开发领域，而应用程序开发人员认为数据库充其量只是一个存储系统，因此不需要精致的工具来处理。

幸运的是，SQL Server 2005的到来，以及.NET Framework的发布，促使Microsoft中的一些人投入了更多时间和资源，为开发人员和DBA提供改进的数据库和数据管理界面。**SQL Server Management Studio（SSMS）**应运而生，统一了两个遗留工具的功能：**查询分析器**和**企业管理器**。任何自2005版以来使用过SQL Server的人都会认出这个应用程序，无论他们使用的是2005版还是最新的2016版本。
