You should note that the abstraction introduced by a design pattern is not necessarily introduced by means of a base class. As I will show you in the following sections and chapters, this abstraction can be introduced in many different ways, for instance by means of templates, or simply by function overloading. Again, a design pattern does not imply any specific implementation.

As a counter example, let us consider the std::make_unique() function:

```
namespace std {

template< typename T, typename... Args >
unique_ptr<T> make_unique( Args&&... args );

} // namespace std
```

In the C++ community we often talk about the std::make_unique() function as a factory function. It is important to note that although the term factory function gives the impression that std::make_unique() is one example for the Factory Method design pattern, this impression is incorrect. A design pattern helps you to decouple by introducing an abstraction, which allows you to customize and defer implementation details. In particular, the intent of the Factory Method design pattern is to introduce a customization point for the purpose of object instantiation. std::make_unique() does not provide such a customization point: if you use std::make_unique(), you know that you will get a std::unique_ptr to the type you are asking for and that the instance will be created by means of new:

```
// This will create a 'Widget' by means of calling 'new'
auto ptr = std::make_unique<Widget>( /* some Widget arguments */ );
```
