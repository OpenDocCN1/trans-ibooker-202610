Note, that CustomAllocator publicly inherits from std::pmr::memory_resource in order to qualify as a C++17 allocator. Due to that, you can establish an instance of CustomAllocator as the new system-wide default allocator by means of the std::pmr::set_default_resource() function (4):

```
#include <CustomAllocator.h>

int main()
{
    // ...
    CustomAllocator custom_allocator{ /*...*/ };

    std::pmr::set_default_resource( &custom_allocator );  4
    // ...
}
```

While the std::pmr::memory_resource base class resides on the highest level of the architecture, CustomAllocator is logically introduced on the lowest architectural level (see Figure 10-4). Thus, the Strategy pattern causes an inversion of dependencies (see “Guideline 9: Pay Attention to the Ownership of Abstractions”): despite the Singletonness of the allocators, despite representing global state, you depend on an abstraction instead of the concrete implementation details.
