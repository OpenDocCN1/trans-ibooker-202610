Semantically, this is the equivalent to the pointer approach, but we do not pay the cost of dynamic memory allocation and we do not have to deal with lifetime management. 32 This solution is semantically clear, understandable, and efficient.

# Prefer to Use Value Semantics to Implement Design Patterns

“And what about design patterns?”, you ask. “Almost all GoF patterns are based on inheritance hierarchies and therefore *reference semantics*. How should we deal with this?” That is an excellent question. And it provides us with a perfect bridge to the next guideline. To still give a short answer here: you should prefer to implement design patterns by means of a *value semantics* solution. Yes, seriously! These solutions usually lead to more comprehensive, maintainable code and (often) better performance.

# GUIDELINE 22: PREFER VALUE SEMANTICS TO REFERENCE SEMANTICS

+   - Be aware that *reference semantics* make it harder to understand code;
+   - Prefer the semantical clarity of *value semantics*.
