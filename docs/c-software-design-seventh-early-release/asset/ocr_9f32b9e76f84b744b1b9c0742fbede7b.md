```
class WildTurkey : public Turkey
{
public:
    void gobble() override { /*...*/ }
    void fly() override { /*...*/ }
};
```

Turkeys are represented by the abstract Turkey class, which of course is implemented by many different kinds of specific Turkeys, for instance the WildTurkey. To make things worse, for some reason ducks and turkeys are expected be used together.⁷ One possible way to make this work, is to pretend that a turkey is a duck. After all, a turkey is pretty similar to a duck. Well, ok, it does not quack, but it can gobble (the typical turkey sound), and it can also fly (not for a long distance, but yes, it can fly). So what you could do, is to adapt turkeys to ducks by means of the TurkeyAdapter:

```
//---- <TurkeyAdapter.h> -------------

#include <memory>

class TurkeyAdapter : public Duck
{
public:
    explicit TurkeyAdapter( std::unique_ptr<Turkey> turkey )
        : turkey_{ std::move(turkey) }
    {}

    void quack() override { turkey_->gobble(); }
    void fly() override { turkey_->fly(); }

private:
    std::unique_ptr<Turkey> turkey_;  // This is an example for an object adapter
};
```

While this is an amusing interpretation of duck typing, this example nicely demonstrates, that it is way to easy to integrate something alien into an existing hierarchy. A Turkey is simply not a Duck, even if we want it to be. I would argue that likely both the quack() and the fly() function violate the LSP. Both functions do not really do what I would expect them
