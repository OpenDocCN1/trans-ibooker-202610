```
for( auto const& shape : shapes )
{
    std::visit( Draw{}, shape );
}
}
```

The drawAllShapes() function is refactored to make use of std::visit(). In this function we now apply the Draw visitor onto all variants stored in a vector.

The job of std::visit() is to perform the necessary type dispatch for you. In case the given std::variant contains a Circle, it would call the Draw::operator() for circles. Otherwise it would call the Draw::operator() for squares. If you wanted to, you could manually implement the same dispatch by means of std::get_if():

```
void drawAllShapes( Shapes const& shapes )
{
    for( auto const& shape : shapes )
    {
        if( Circle* circle = std::get_if<Circle>(&shape) ) {
            // ... Drawing a circle
        }
        else if( Square* square = std::get_if<Square>(&shape) ) {
            // ... Drawing a square
        }
    }
}
```

That would result in the same maintenance nightmare as an enum-based solution.” I completely agree with you: from a software design perspective, this would be a terrible idea. Still, and I have to say that it is difficult to admit in the context of this book, there may be a good reason to do that (sometimes): performance.
