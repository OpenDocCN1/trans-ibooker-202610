+   - if the implementation details of the exportToJSON() function change because of a direct dependency to the used JSON library;
+   - if the signature of the exportToJSON() function changes because the underlying implementation changes;
+   - if the ByteStream class changes because of a direct dependency to this class;
+   - if the implementation details of the serialize() function change because of a direct dependency to the implementation details;
+   - if a new type of document is introduced because of the direct dependency on the DocumentType enumeration.

Obviously this design promotes more changes and every single change would be harder. And of course, in the general case, there is the additional danger that orthogonal aspects are artificially coupled inside documents, which would further increase the complexity to make a change. In addition, some of these changes are definitely not restricted to a single place in the code base. In particular, changes to the implementation details of exportToJSON() and serialize() would not be restricted to only one class, but likely all kinds of documents (PDF, Word, ...). Therefore a change would affect a significant number of places all over the code base, which poses a maintenance risk.
