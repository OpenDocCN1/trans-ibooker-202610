In summary: although the *External Polymorphism* design pattern may not satisfy your expectation in a simple or value-based solution, it must be considered a very important step towards decoupling software entities. From the perspective of reducing dependencies, this design pattern appears to be a key ingredient to loose coupling and is a marvelous example for the power of separation of concerns. It also gives us one key insight: using this design pattern, you can non-intrusively equip any type with polymorphic behavior, i.e. virtual functions, so *any* type can behave polymorphically, even a simple value type such as `int`. And this realization opens up a completely new, exciting design space, which we will continue to explore in the next chapter.
