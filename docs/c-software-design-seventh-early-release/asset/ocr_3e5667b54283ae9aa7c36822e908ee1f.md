You are weighing your options, then you come up with your first idea: “Well, the easiest approach would be to test the function via some other, public member function that internally calls the updateCollection() function.” That sounds like an interesting first idea. So let us assume that the collection needs to be updated when a new Blob is added to it. So calling the addBlob() member function would trigger the updateCollection() function:

```
class Widget
{
public:

    void addBlob( Blob const& blob, /*...*/ )
    {
        // ...
        updateCollection( /*...*/ );

    }

private:

    std::vector<Blob> blobs_;
    /* Potentially other data members */
};
```

Although this sounds like a reasonable thing to do, it is also something that you should avoid if possible. What you are suggesting is a so-called white box test. A white box test is a test that knows about the internal implementation details of some function and tests based on that knowledge. And this introduces a dependency: a dependency of the test code on the implementation details of your production code. The problem with this approach is that software changes. Code changes.
