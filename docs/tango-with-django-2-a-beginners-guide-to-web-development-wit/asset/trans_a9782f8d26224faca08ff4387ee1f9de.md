

## 1.4 Rango：初始设计与规格说明

本书的重点是开发一个名为 *Rango* 的应用程序。在开发这个应用程序的过程中，我们将涵盖构建任何 Web 应用程序时需要开发的核心组件。要查看该应用程序的完整功能版本，你可以访问我们的[如何与 Django 共舞网站](http://www.tangowithdjango.com/)¹⁹。

### 设计简报

让我们设想一下，我们希望创建一个名为 *Rango* 的网站，让用户通过浏览用户自定义的分类来访问各种网页。在[西班牙语中，rango 一词](https://www.vocabulary.com/dictionary/es/rango)²⁰ 用来表示"*按质量排名的联盟*"或"*社会层级中的位置*"——所以我们可以想象，在某个时候，我们会希望对 Rango 中的网页进行排名。

- 对于 Rango 网站的**主页**，你的客户希望访问者能够看到：
  - *浏览次数最多的五个页面；*
  - *浏览次数最多（或被 rango 化）的五个分类；*以及
  - *某种让访问者浏览和/或搜索分类的方式。*
- 当用户查看**分类页面**时，你的客户希望 Rango 能够显示：
  - *分类名称、访问次数、点赞数*，以及该分类中关联页面的列表（显示页面标题，并链接到其 URL）；以及
  - *一些搜索功能（通过搜索 API）*，用于查找可以链接到该分类的其他页面。
- 对于**特定分类**，客户希望：*记录分类的名称；* *每个分类页面被访问的次数；* 以及有多少用户*点击了"点赞"按钮*（即该页面被 rango 化，并在社会层级中被投票提升）。
- *每个分类都应当能通过可读的 URL 访问*——例如，`/rango/books-about-django/`。
- 只有*注册用户*才能搜索页面并将页面添加到分类中。因此，网站访问者应该能够注册账户。

乍一看，要开发的这个指定应用程序似乎相当简单。本质上，它只是一个链接到页面的分类列表。然而，还有一些复杂性和挑战需要解决。首先，让我们通过制定一些高层设计，试着更清楚地了解需要开发的内容。

### 页面与 URL 映射

根据规格说明，我们已经确定了应用程序在不同时间点将向用户呈现的两个页面。要访问每个页面，我们需要描述 URL 映射。可以把 URL 映射理解为用户为了访问某个页面而需要在浏览器地址栏中输入的文字。Rango 的基本 URL 映射如下所示。

- `/` 或 `/rango/` 将指向主 `/` 索引页面。
- `/rango/about/` 将指向关于页面。
- `/rango/category/<category_name>/` 将指向 `<category_name>` 对应的分类页面，其中分类可能是：
  - `games`；
  - `python-recipes`；或
  - `code-and-compilers`。

### 注意！

养成记录你所作出的任何工作假设的习惯，就像我们在上面假设的一对多关系假设一样。你永远不知道它们什么时候会回过头来给你带来麻烦！通过将它们记录下来，你可以与开发团队沟通，并确保该假设是合理的，而且他们乐意在这样的假设下继续推进。

基于这个假设，我们可以生成一系列表格，更详细地描述每个实体。这些表格包含每个实体中字段的信息。我们使用 Django `ModelField` 类型来定义每个字段的类型（即 `IntegerField`、`CharField`、`URLField` 或 `ForeignKey`）。请注意，在 Django 中，*主键*是隐式的，Django 会为每个 Model 添加一个 id，但我们将在后面的[模型与数据库章节]中更详细地讨论这一点。

### 复制粘贴编码

在阅读本教程的过程中，你很可能会想把书中的代码剪切并粘贴到你的代码编辑器中。**然而，最好还是手动输入代码。**我们知道这很麻烦，但它会帮助你记住流程，并让你熟悉那些你会反复使用的命令。

此外，剪切和粘贴 Python 代码是在自找麻烦。空白最终可能会被解释为空格、制表符或空格与制表符的混合。这将导致各种奇怪的错误，而且不一定是缩进错误。如果你确实剪切和粘贴代码，请务必警惕这一点。特别要注意制表符和空格的问题——将它们混用很可能会导致 TabError。

大多数代码编辑器会显示"隐藏字符"，这些字符进而会显示空白是制表符还是空格。如果你的编辑器有这个选项，请将其打开。你很可能会因此避免很多困惑。

## 2. 准备与 Django 共舞

在我们开始编码之前，正确设置你的开发环境非常重要，这样你才能轻松地*与 Django 共舞*。你需要确保计算机上已安装所有必要的组件，并且它们已正确配置。本章概述了你需要了解、设置和使用的六个关键组件。它们是：

- [终端](https://en.wikipedia.org/wiki/Terminal_emulator)（在 macOS 或 UNIX/Linux 系统上），或[命令提示符](https://en.wikipedia.org/wiki/Cmd.exe)（在 Windows 上）；
- *Python 3*，包括如何编写和运行 Python 脚本；
- Python 包管理器 *pip*；
- *虚拟环境*；
- 你的*集成开发环境（IDE）*，如果你选择使用的话；以及
- 名为 *Git* 的*版本控制系统（VCS）*。

我们还会简要讨论*单元测试*的优点，探讨能够在不同节点测试你的实现如何帮助你保持正轨。

如果你已经在计算机上安装了 Python 3 和 Django 2，并且熟悉上面列出的技术，你可以直接跳到[Django 基础章节](#)。如果你不熟悉所列的部分或全部技术，我们在下面提供了每一项的概述。这些内容与后面的[补充章节](#)相辅相成，该章节提供了一系列关于如何设置不同组件的指导，如果你需要这方面的帮助。
