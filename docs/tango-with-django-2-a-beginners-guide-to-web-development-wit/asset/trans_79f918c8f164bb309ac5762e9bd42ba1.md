

## 你的开发环境很重要！

搭建开发环境可能是一个繁琐且令人沮丧的过程。这并非你每天都会做的事情。我们在本章（以及[补充章节](#)）中提供的指引，将帮助你让一切进入可工作的状态。你现在为确保一切正常运转所付出的努力，将确保后续开发不受阻碍，无需你回头再修补问题。

根据经验，我们也可以自信地说，在搭建环境时，最好记下你所采取的步骤。你很可能有一天会再次用到这套流程——也许你买了新电脑，或者被要求帮朋友搭建环境。*不要只考虑眼前，要放眼长远！*

### 2.1 Python 3

要使用 Tango with Django，我们要求你的电脑上安装有 *Python 3* 编程语言。Python 3.5 或更高版本应该可以与 Django 2.0、2.1 和 2.2 正常配合使用——尽管 Django 官方网站建议你安装最新版本的 Python。因此，我们建议你安装 *Python 3.7*。在撰写本文时，最新版本是 *Python 3.7.2*。如果你不确定如何安装 Python 并希望获得一些帮助，请查看[我们关于如何安装 Python 的快速指南](#)。

#### 你使用的是 macOS、Linux 还是 UNIX？

在 macOS、Linux 或 UNIX 系统上，你会发现电脑上已经安装了 Python——尽管是较旧的版本，通常是 2.x 版本。你的操作系统需要这个版本来执行下载和安装更新等基本任务。虽然你可以使用这个版本，但它与 Django 2 不兼容，你需要安装一个较新版本的 Python，使其与旧安装*并排*运行。*如果系统中已存在 Python 2.x，请勿卸载或费尽心思去删除它*；否则你可能会弄坏操作系统！

#### Django 2.0、2.1 还是 2.2？

在本书中，我们明确使用 Django 2.1.5 版本。不过，我们也已对 2.0.13、2.1.10 和 2.2.3 版本提供了的说明进行了测试。因此，如果你愿意，也可以使用 2.2 版本！如果你确实使用了不同版本，请将 2.1.5 替换为你所使用的版本。

我们会定期检查所提供的说明与未来 Django 版本的兼容性。如果你发现后续版本存在任何问题，欢迎随时与我们联系。你可以[给我们发推文](https://twitter.com/tangowithdjango)、[在 GitHub 上提交 issue](https://github.com/leifos/tango_with_django_2/issues)，或给我们发送电子邮件——我们的地址可以在 [www.tangowithdjango.com](https://www.tangowithdjango.com) 网站上找到。

但你必须确保使用的是*至少* Python 3.5 版本。3.4 及以下版本与这些 Django 版本不兼容。

#### Python 技能生疏了？

如果你以前没有用过 Python——或者只是想复习一下技能——那么我们强烈建议你查看并学习以下一个或多个指南：

- [官方 Python 教程](https://docs.python.org/3/tutorial/)；
- Allen B. Downey 所著的《[像计算机科学家一样思考 Python：Think Python](https://greenteapress.com/wp/think-python-2e/)》；或
- Stavros 所著的《[10 分钟学会 Python](https://www.stavros.io/tutorials/python/)》；
- Jennifer Campbell 和 Paul Gries 的《[学习编程](https://www.coursera.org/course/programming1)》。

这些指南将帮助你熟悉 Python 的基础知识，从而可以开始使用 Django 进行开发。请注意，你不需要成为 Python 专家才能使用 Django——Python 使用起来非常直接，你可以边学边用，尤其是如果你已经至少精通另一种编程语言的话。

### 2.2 虚拟环境

在成功安装 Python 3（以及相应的基础编程技能）之后，我们现在可以为将在本教程中创建的 Django 项目（名为 Rango）设置环境了。我们*强烈鼓励*你使用的一个超级有用的工具是虚拟环境。虽然并非严格必需，但它在你的电脑 Python 安装与用于开发 Rango 的环境之间提供了有用的隔离。

虚拟环境允许多个 Python 包安装在独特的 *Python 环境*中和谐共存。为什么这很有用？假设你有一个项目 `projectA` 要在 Django 1.11 中运行，另一个项目 `projectB` 是为 Django 2.1 编写的。这就会产生问题，因为通常你一次只能安装所需软件的一个版本。通过为每个项目创建虚拟环境，你可以在每个独立环境中安装相应版本的 Django（以及任何其他所需的 Python 软件）。这确保了一个环境中安装的软件不会干扰另一个环境中安装的软件。

你需要为你的 Rango 开发环境创建一个使用 Python 3 的虚拟环境。将该环境命名为 `rangoenv`。如果你不确定如何操作，请在继续之前查阅详细介绍[如何设置虚拟环境](#)的补充章节。如果你确实选择使用虚拟环境，请记得通过执行以下命令来激活它。

```shell
$ workon rangoenv
```

此后，你在终端或命令提示符中的所有提示符前面都会出现虚拟环境的名称，以提醒你它处于开启状态。请看下面的示例，了解我们所说的情况。

```bash
$ workon rangoenv
(rangoenv) $ pip install django==2.1.5
...
(rangoenv) $ deactivate
$
```

上面示例的倒数第二行演示了如何在用完后关闭虚拟环境——请注意提示符前缺少 `(rangoenv)`。同样，有关如何设置和使用虚拟环境的更多信息，请[参阅本书附录中的系统设置章节](#)。

### 2.3 Python 包管理器

与虚拟环境相辅相成，我们还将使用 Python 包管理器 *pip* 来为我们的开发环境安装几个不同的 Python 软件包——包括 Django。具体来说，我们需要安装两个包：Django 2 和 *Pillow*。Pillow 是一个 Python 包，提供处理图像文件（例如 `.jpg` 和 `.png` 文件）的支持，我们将在本教程后面用到它。

包管理器，无论是用于 Python、你的[操作系统](#)¹⁰ 还是[其他环境](#)¹¹，都是一种软件工具，可自动执行*软件包*的安装、升级、配置和移除过程——即你可以用于电脑上提供某些功能的软件包。这与手动下载、安装和维护软件形成对比。

维护 Python 包相当痛苦。大多数包通常都有*依赖项*——即你的包运行所需的附加包！这很快就会变得非常复杂。包管理器会为你处理所有这些，以及诸如不同版本包之间冲突等问题。幸运的是，*pip* 会为你处理所有这一切。

尝试运行命令 `$ pip` 来执行包管理器。请确保在虚拟环境激活状态下执行。全局环境下，你可能需要使用 `pip3` 命令。如果这些都不起作用，说明你的环境设置有误——请参阅我们的 [pip 设置指南](#) 寻求帮助。

在虚拟环境开启的情况下，执行以下两条命令来安装 Django 和 Pillow。

```bash
$ pip install django==2.1.5
$ pip install pillow==5.4.1
```

安装这两个包就足以让你开始了。在完成本教程的过程中，我们还需要另外几个包。我们会告诉你在需要时安装它们。现在，你可以开始行动了。

#### 安装 `pillow` 时遇到问题？

在安装 Pillow 时，你可能会收到一个错误，指出由于缺少 JPEG 支持而导致安装失败。此错误显示如下：

```text
ValueError: jpeg is required unless explicitly disabled using
            --disable-jpeg, aborting
```

如果你收到此错误，请尝试在*不*启用 JPEG 支持的情况下安装 Pillow，使用以下命令。

```bash
pip install pillow==5.4.1 --global-option="build_ext" --global-option="--disable-jpeg"
```

虽然你显然会缺少处理 JPEG 图像的支持，但 Pillow 应该可以顺利安装。安装完成 Pillow 就足以让你开始本教程了。有关更多信息，请查看 [Pillow 文档](https://pillow.readthedocs.io/en/stable/installation.html)¹²。

#### 在虚拟环境中工作

在虚拟环境中工作时，请将 pip3 替换为 pip。pip 命令已为你该虚拟环境正确设置了别名。
