## 应用性能管理

APM 提供了一个框架，用于通过衡量有关应用程序的指标来监控和管理软件应用程序性能，其目标是在问题出现时甚至之前就捕获问题。使用的确切指标可能有所不同，但随着应用程序越来越多地迁移到云，确保 API 保持高效并满足用户实时期望变得越来越复杂。我们需要确保我们的应用程序在需要时始终可用，并且能够在负载增加或减少时处理而不损失性能。

您的业务可能为客户提供 API，或为员工使用的应用程序提供内部 API。您也可能为自己的业务需求使用外部供应商的 API。无论细节如何，您都需要确保使用这些 API 的应用程序具有可接受的响应性和流畅性，以便用户不必等待数分钟页面加载。这归结为 API 对用户请求响应的速度。如果 API 突然变慢，APM 框架会自动提醒负责团队，以便他们可以调查、找到根本原因并解决它。完整的可见性使团队能够在问题导致业务收入损失之前快速识别和修复问题。

APM 的好处是：

### 广泛的可见性

在今天我们拥有的 DevOps 工具兴起之前，监控基础设施在功能上有限且难以使用。软件和硬件是分开监控的，造成了脱节的体验。APM 在整个部署周期中引入了广泛的可见性，并在一个统一的框架下统一。

### 增强的可观测性

当监控触发警报时，团队会通过修复来解决问题。然而，定位源可能很繁琐且重复，尤其是在警报实际上是预期而不是意外时。超越可见性，APM 提供了额外的根本原因调试支持，称为 *可观测性*。例如，通过可观测性，应用程序性能下降可能归因于集群中的节点无法处理请求，而不是代码本身的问题。

### 明确的责任归属

APM 使 DevOps 工程师能够通过可观测性和明确的责任归属来管理生产代码的端到端生命周期。责任归属的清晰度允许指定专门的人员，以便快速响应问题。

### 迭代速度

最终，流程的简化、明确的利益相关者和广泛可见性的监控工具的可用性使您的团队能够快速部署、识别和修复问题，从而减少迭代之间的时间并最大化每次迭代的影响。

## 应用性能指标

通常用于衡量应用性能的指标有：

### API 延迟

系统执行操作所需的时间，通常以毫秒（ms）为单位衡量

### 每秒查询数（QPS）

API 每秒被调用的次数

这些指标对于应用程序团队监控其应用程序能够处理的规模和负载至关重要。它们也是任何自动警报或基于触发的事件的基础，例如系统故障转移，并且可以馈入自动扩展管理解决方案，例如集群调整大小或节点池调整大小（一种管理 API 用于处理其请求所使用的计算机数量的方式）。随着云计算变得越来越普及，公司正在将许多应用程序和工作负载迁移到云中，使得监控这些指标变得越来越重要。

可能有一天——比如黑色星期五——您的系统会被请求淹没，导致应用程序崩溃。通过使用 APM 框架模拟此类流量并在事前衡量系统在任何给定 QPS 下的延迟，您的团队可以捕获任何问题并提前设计以防止任何故障或性能下降。这被称为负载测试，可以帮助扩展系统。

实时流数据、历史回放和出色的可视化工具是当今 APM 解决方案的标准部分。流行的 APM 产品不仅提供对简单统计数据的洞察，而且还具有可用于业务的 API 和组件集成。

## MLOps 的兴起

随着应用程序开始采用更先进的决策算法和模型，确保高性能所需的管理和工具变得更加复杂。对于以代码为中心的应用程序，测试它们是否按预期工作相对简单。但 ML 和 AI 模型是以数据为中心的，这增加了传统 DevOps 团队不习惯处理的许多挑战（例如确保数据完整性和有效性）。这就是 MLOps 发挥作用的地方。

机器学习运维，或简称 MLOps，是围绕数据及其使用、数据科学和工具的文化实践的融合，旨在快速迭代模型版本或快速运行实验以测试不同的假设。MLOps 不独立于 DevOps 存在，它们需要携手合作以确保所有方面都得到覆盖，并且任何问题都可以用最少的团队精力得到解决和解决。我们将在本报告的第 3 章介绍 ML 生命周期和一些 ML 方面，但现在让我们看看 MLOps 与 DevOps 的比较。

## MLOps 与 DevOps 的比较

MLOps 和 DevOps 都源于相同的根基，并专注于快速迭代和持续改进。没有基于这些哲学的框架，团队将很难建立高效的周期，并且会产生很少的有益成果。MLOps 和 DevOps 都建议在系统发布前进行验证和测试。然而，它们在可观测性和监控方面存在不足。这就是 APM 在 DevOps 中大放异彩的地方，因为它提供了对应用程序的完全可见性，使团队能够在问题变得明显时立即找到根本原因。

ML/AI 模型本质上是黑盒；数据科学家并不总是知道模型为何以及如何工作。但这种缺乏可见性无法通过一刀切的解决方案解决，因为每个模型都是独特的。因此，您需要执行大量规划和工作来正确监控模型所需的测试和验证。

## 模型性能指标

有许多不同类型的机器学习（ML）模型，每个模型都有其自己的细微差别和需要跟踪的指标。ML 模型高度依赖于数据，并且依赖于输入数据的质量和一致性。以下是当今 ML 模型复杂性的一些来源示例：

- *多功能性*

ML 服务于广泛的用例——反洗钱、职位匹配、临床诊断和行星监视，仅举几例。

### 架构

ML 算法可以采用多种形式，解释起来更容易或更难；它们范围从简单的逻辑回归和决策树到用于深度学习的先进神经网络。

### 多样性

ML 模型有许多种类（表格、时间序列、文本、图像、视频和音频），并且这些模态通常在某些领域中混合，进一步增加了跟踪模型性能复杂性。

### 数据量

云计算的兴起使团队能够并行使用更多数据训练多个模型，这使得更难跟踪训练数据。

团队必须能够监控数据分布的突然变化，这可能导致偏差。其他问题可能源于模型训练数据过少或过多，导致性能不佳。跟踪可能影响模型性能的所有参数比跟踪代码库中的代码更改要困难得多。

通常用于跟踪模型性能的指标有：

### 准确率

实际正确的预测占总预测的百分比

### 精确率

正确识别的阳性案例占阳性案例的百分比

### 负预测值

正确识别的阴性案例占阴性案例的百分比
