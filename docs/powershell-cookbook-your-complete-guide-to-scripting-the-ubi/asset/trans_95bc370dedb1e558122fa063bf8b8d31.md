
# Get-ScriptCoverage

源自 *PowerShell 食谱*（O'Reilly），作者 Lee Holmes (http://www.leeholmes.com/guide)

## 概要

使用条件断点来获取有关脚本运行时执行了哪些区域的信息。

## 示例

```powershell
PS > Get-Content c:\temp\looper.ps1

param($userInput)

for($count = 0; $count -lt 10; $count++)
{
    "Count is: $count"
}

if($userInput -eq "One")
{
    "Got 'One'"
}

if($userInput -eq "Two")
{
    "Got 'Two'"
}

PS > $action = { c:\temp\looper.ps1 -UserInput 'One' }
PS > $coverage = Get-ScriptCoverage c:\temp\looper.ps1 -Action $action
PS > $coverage | Select Content,StartLine,StartColumn | Format-Table -Auto

Content   StartLine StartColumn
-------   --------- -----------
userInput         1           7
Got 'Two'        15           5
```

此示例运行 'looper.ps1' 脚本，并提供一些用户输入。输出表明我们没有执行“Got 'Two'”语句。

## 参数

```powershell
param(
    ## 要监视的脚本路径
    $Path,

    ## 用于运行脚本的命令
    [ScriptBlock] $Action = { & $path }
)
```

## 脚本主体

```powershell
Set-StrictMode -Version 3

## 确定脚本中的所有标记
$scriptContent = Get-Content $path
$ignoreTokens = "Comment","NewLine","StatementSeparator","Keyword",
    "GroupStart","GroupEnd"
$tokens = [System.Management.Automation.PsParser]::Tokenize(
    $scriptContent, [ref] $null) |
    Where-Object { $ignoreTokens -notcontains $_.Type }
$tokens = $tokens | Sort-Object StartLine,StartColumn

## 创建一个变量来保存 PowerShell 实际命中的标记
$visited = New-Object System.Collections.ArrayList

## 遍历所有标记
$breakpoints = foreach($token in $tokens)
{
    ## 创建一个新的动作。此动作记录我们命中的标记。
    ## 我们调用 GetNewClosure()，以便 $token 变量获取 $token 变量的 _当前_ 值，
    ## 而不是断点被命中时的值。
    $breakAction = { $null = $visited.Add($token) }.GetNewClosure()

    ## 在当前标记的行和列上设置断点。
    ## 我们使用上面的动作，它只是记录我们命中了该标记。
    Set-PsBreakpoint $path -Line `
        $token.StartLine -Column $token.StartColumn -Action $breakAction
}

## 调用运行脚本的动作
$null = . $action

## 移除我们设置的临时断点
$breakpoints | Remove-PsBreakpoint

## 对我们命中的标记进行排序，并将它们与脚本中的所有标记进行比较。
## 输出该比较的结果。
$visited = $visited | Sort-Object -Unique StartLine,StartColumn
Compare-Object $tokens $visited -Property StartLine,StartColumn -PassThru

## 清理我们的临时变量
Remove-Item variable:\visited
```

有关运行脚本的更多信息，请参阅 [食谱 1.2](#ch01.xhtml#run_programs_scripts_and_existing_tools)。

# 第 15 章. 追踪与错误管理

## 15.0 简介

如果一切不按计划进行怎么办？这是任何系统中错误管理的核心问题，在编写 PowerShell 脚本时也起着重要作用。

虽然这是许多系统的主要关注点，但 PowerShell 对错误管理的支持提供了几项独特功能，旨在使您的工作更轻松。主要优势在于区分终止性错误和非终止性错误。

运行复杂脚本或场景时，最不希望发生的情况是，脚本无法打开其操作的成千上万个文件中的一个，导致整个世界崩塌。虽然系统应让您知晓故障，但脚本仍应继续处理下一个文件。这就是非终止性错误的一个示例。但如果脚本在运行备份时耗尽磁盘空间呢？那绝对应该是一个导致脚本退出的错误——也称为终止性错误。

鉴于这一有用的区别，PowerShell 提供了多项功能，让您管理脚本和程序生成的错误，也允许您自行生成错误。

## 15.1 确定上一条命令的状态

### 问题

您想要获取有关您执行的上一条命令的状态信息，例如它是否成功。

### 解决方案

使用 PowerShell 提供的两个变量之一来确定您执行的上一条命令的状态：`$lastExitCode` 变量和 `$?` 变量。

`$lastExitCode`
: 一个数字，表示上一个退出的脚本或应用程序的退出代码/错误级别

`$?`（读作“dollar hook”）
: 一个布尔值，表示上一条命令的成功或失败

### 讨论

`$lastExitCode` PowerShell 变量类似于 DOS 中的 `%errorlevel%` 变量。它保存最后退出的应用程序的退出代码。这使您能继续与使用退出代码作为主要通信机制的传统可执行文件（如 `ping`、`findstr` 和 `choice`）进行交互。PowerShell 还扩展了该变量的含义，使其包含脚本的退出代码，脚本可使用 `exit` 语句设置其状态。[示例 15-1](#ch15.xhtml#interacting_with_the_dollarlastexitcode_) 演示了这种交互。

#### 示例 15-1. 与 $lastExitCode 和 $? 变量交互

```powershell
PS > ping localhost

Pinging MyComputer [127.0.0.1] with 32 bytes of data:

Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128

Ping statistics for 127.0.0.1:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss),
Approximate round trip times in milliseconds:
    Minimum = 0ms, Maximum = 0ms, Average = 0ms
PS > $?
True
PS > $lastExitCode
0
PS > ping missing-host
Ping request could not find host missing-host. Please check the name and try again.
PS > $?
False
PS > $lastExitCode
1
```

`$?` 变量以更通用的方式描述上一个应用程序的退出状态。在以下错误条件下，PowerShell 将此变量设置为 `False`：

- 应用程序以非零退出代码退出。
- Cmdlet 或脚本向其错误流写入任何内容。
- Cmdlet 或脚本遇到终止性错误或异常。

对于不指示错误条件的命令，PowerShell 将 `$?` 变量设置为 `True`。

如果您希望根据管道中前一条命令的成功与否将多个命令链接在一起，可以使用 PowerShell 的管道链运算符。有关这些运算符的更多信息，请参阅 [食谱 2.1](#ch02.xhtml#pipeline_commands_based_on_success)。
