
# 启用历史记录持久化

## 脚本

```powershell
##############################################################################
##
## Enable-HistoryPersistence
##
## From PowerShell Cookbook (O'Reilly)
## by Lee Holmes (http://www.leeholmes.com/guide)
##
##############################################################################

<#

.SYNOPSIS

Reloads any previously saved command history, and registers for the
PowerShell.Exiting engine event to save new history when the shell
exits.

#>

Set-StrictMode -Version 3

## Load our previous history
$GLOBAL:maximumHistoryCount = 32767
$historyFile = (Join-Path (Split-Path $profile) "commandHistory.clixml")
if (Test-Path $historyFile)
{
    Import-CliXml $historyFile | Add-History
}

## Register for the engine shutdown event
$null = Register-EngineEvent -SourceIdentifier `
    ([System.Management.Automation.PsEngineEvent]::Exiting) -Action {

    ## Save our history
    $historyFile = (Join-Path (Split-Path $profile) "commandHistory.clixml")
    $maximumHistoryCount = 1kb

    ## Get the previous history items
    $oldEntries = @()
    if (Test-Path $historyFile)
    {
        $oldEntries = Import-CliXml $historyFile -ErrorAction SilentlyContinue
    }

    ## And merge them with our changes
    $currentEntries = Get-History -Count $maximumHistoryCount
    $additions = Compare-Object $oldEntries $currentEntries `
        -Property CommandLine | Where-Object { $_.SideIndicator -eq "=>" } |
        Foreach-Object { $_.CommandLine }

    $newEntries = $currentEntries | ? { $additions -contains $_.CommandLine }

    ## Keep only unique command lines. First sort by CommandLine in
    ## descending order (so that we keep the newest entries,) and then
    ## re-sort by StartExecutionTime.
    $history = @($oldEntries + $newEntries) |
        Sort -Unique -Descending CommandLine | Sort StartExecutionTime

    ## Finally, keep the last 100
    Remove-Item $historyFile
    $history | Select -Last 100 | Export-CliXml $historyFile
}
```

## 说明

此脚本可以执行任何操作，但在此示例中，我们用它来保存命令历史记录，并在启动 PowerShell 时恢复它。为什么要这样做？因为有了丰富的历史记录缓冲区，我们可以更轻松地查找和重用之前运行过的命令。有关这方面的两个示例，请参阅配方 [1.21](#ch01.xhtml#access_and_manage_your_console_history) 和 [1.23](#ch01.xhtml#invoke-command-history)。

`Enable-HistoryPersistence` 执行两个主要操作。首先，我们加载存储的命令历史记录（如果存在）。然后，我们注册一个自动操作，以便在引擎生成 `PowerShell.Exiting` 事件时进行处理。该操作本身相对简单，尽管导出新历史记录确实需要一点技巧。如果你同时打开多个会话，每个会话在退出时都会更新保存的历史记录文件。因为我们不想覆盖其他 Shell 保存的历史记录，所以我们先从磁盘重新加载历史记录，并将其与当前 Shell 的历史记录合并。

获得合并后的命令行列表后，我们对它们进行排序并挑选出唯一的命令行，然后再存回文件。

有关使用 PowerShell 引擎事件的更多信息，请参阅 [配方 31.2](#ch31.xhtml#respond_custom_events)。

# 第 2 章 管道

## 2.0 简介

Shell 中的基本概念之一称为 *管道*。它也是 PowerShell 最重要的进步之一的基础。管道是一个简单概念的大名——一系列命令，其中一个命令的输出成为下一个命令的输入。Shell 中的管道很像工厂里的装配线：它在各个阶段之间传递时逐步优化某些内容，如 [示例 2-1](#ch02.xhtml#a_powershell_pipeline) 所示。

### 示例 2-1. PowerShell 管道

```powershell
Get-Process | Where-Object WorkingSet -gt 500kb | Sort-Object -Descending Name
```

在 PowerShell 中，你可以使用管道符 (`|`) 来分隔管道中的每个阶段。

在 [示例 2-1](#ch02.xhtml#a_powershell_pipeline) 中，`Get-Process` cmdlet 生成代表系统上实际进程的对象。这些进程对象包含有关进程名称、内存使用量、进程 ID 等信息。当 `Get-Process` cmdlet 生成输出时，它会将输出传递下去。同时，`Where-Object` cmdlet 直接处理这些进程，轻松测试出内存使用量超过 500 KB 的进程。它在处理时立即将这些进程传递下去，使 `Sort-Object` cmdlet 也能直接处理这些进程，并按名称降序排序。

这个简短的例子说明了管道功能的重大进步：PowerShell 沿管道传递高保真对象，而不是它们的文本表示形式。

相比之下，所有其他 Shell 都在各阶段之间传递纯文本数据。从纯文本输出中提取有意义的信息，使得编写管道变成了一种黑魔法。在传统的基于 Unix 的 Shell 中表达前面的示例非常困难，在 `cmd.exe` 中几乎是不可能的。

传统的基于文本的 Shell 之所以使编写管道变得如此困难，是因为它们要求你深入了解管道中每个命令的输出格式特性，如 [示例 2-2](#ch02.xhtml#a_traditional_text-based_pipeline) 所示。

### 示例 2-2. 传统的基于文本的管道

```bash
lee@ubuntu-20-04:~$ ps -F | awk '{ if($5 > 500) print }' | sort -r -k 64,70
UID        PID  PPID  C    SZ   RSS PSR STIME TTY             TIME CMD
lee       8175  7967  0   965  1036   0 21:51 pts/0       00:00:00 ps -F
lee       7967  7966  0  1173  2104   0 21:38 pts/0       00:00:00 -bash
```

在这个例子中，你必须知道，对于每一行，第 5 组代表内存使用量。你必须了解另一种语言（即 `awk` 工具的语言）来按该列进行筛选。最后，你必须知道包含进程名称的列范围（在此系统上为第 64 到 70 列），然后将其提供给 `sort` 命令。而这只是一个简单的例子。

基于对象的管道开启了巨大的可能性，使系统管理既更简单又更强大。

## 2.1 根据命令的成功或失败链接命令

### 问题

你希望根据管道中前一个命令的成功与否，将多个命令链接在一起。

### 解决方案

使用 `&&` 和 `||` 管道链接运算符：

```powershell
PS > Invoke-Command localhost { "Some output" } && "Connection successful!"
Some command output
Connection successful!

PS > Invoke-Command missing_computer { "Some output" } && "Connection successful!"
OpenError: [missing_computer] Connecting to remote server missing_computer failed...

PS > Invoke-Command missing_computer { "Some output" } || "Connection failed."
OpenError: [missing_computer] Connecting to remote server missing_computer failed...
Connection failed.
```

### 讨论

如果你希望根据管道中其他命令的成功与否来链接多个命令，可以使用 PowerShell 的管道链接运算符。`&&` 运算符仅在前一个命令成功时才执行下一个命令。`||` 运算符仅在前一个命令失败时才执行下一个命令。

对于管道链接运算符，命令的成功与否由 `$?`（“美元钩子”）自动变量决定。有关 `$?` 自动变量的更多信息，请参阅 [配方 15.1](#ch15.xhtml#determine_the_status_of_the_last_command)。
