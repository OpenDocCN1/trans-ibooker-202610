

请注意，[示例 13-6](#ch13.xhtml#import_localizeddataps1) 中的 `Greeting` 消息使用 `{0}` 样式的占位符（以及 PowerShell 的字符串格式化运算符）来输出包含可替换文本的字符串。使用此技术远比使用字符串拼接（例如，`$messages.GreetingBeforeName` + " World " + `$messages.GreetingAftername`）要好得多，因为它在本地化句子结构不同的语言时提供了额外的灵活性。

要在不同语言下测试脚本，可以使用 [示例 13.8](#ch13.xhtml#program_invoke_a_script_block_with_alter)，如下例所示：

```
PS > Use-Culture de-DE { Invoke-LocalizedScript }
Guten Tag, World
Auf Wiedersehen.
```

有关脚本国际化的更多信息，请键入 `Get-Help` `about_Script_Internationalization`。

# 13.8 程序：使用备选区域性设置调用脚本块

鉴于 PowerShell 多元化的用户社区，您共享的脚本通常会在设置为英语以外语言的系统上运行。为确保脚本在其他语言中正常运行，在该区域性下进行测试运行会很有帮助。[示例 13-8](#ch13.xhtml#use-cultureps1) 允许您在指定的区域性中运行所提供的脚本块。

### 示例 13-8. Use-Culture.ps1

```
#############################################################################
##
## Use-Culture
##
## From PowerShell Cookbook (O'Reilly)
## by Lee Holmes (http://www.leeholmes.com/guide)
##
#############################################################################

<#

.SYNOPSIS

在给定区域性下调用脚本块

.EXAMPLE

PS > Use-Culture fr-FR { Get-Date -Date "25/12/2007" }
mardi 25 decembre 2007 00:00:00

#>

param(
    ## 用于评估给定脚本块的区域性
    [Parameter(Mandatory = $true)]
    [System.Globalization.CultureInfo] $Culture,

    ## 要在给定区域性上下文中调用的代码
    [Parameter(Mandatory = $true)]
    [ScriptBlock] $ScriptBlock
)

Set-StrictMode -Version 3

## 用于设置当前区域性的辅助函数
function Set-Culture([System.Globalization.CultureInfo] $culture)
{
    [System.Threading.Thread]::CurrentThread.CurrentUICulture = $culture
    [System.Threading.Thread]::CurrentThread.CurrentCulture = $culture
}

## 记录原始区域性信息
$oldCulture = [System.Threading.Thread]::CurrentThread.CurrentUICulture

## 如果用户的脚本遇到错误，
## 则恢复原始区域性信息。
trap { Set-Culture $oldCulture }

## 将当前区域性设置为用户提供的
## 区域性。
Set-Culture $culture

## 调用用户的脚本块
& $ScriptBlock

## 恢复原始区域性信息。
Set-Culture $oldCulture
```

有关运行脚本的更多信息，请参阅 [示例 1.2](#ch01.xhtml#run_programs_scripts_and_existing_tools)。

# 13.9 访问宿主应用程序 UI 的功能

## 问题

您想要与宿主应用程序 UI 中的功能进行交互，但 PowerShell 没有直接为它们提供 cmdlet。

## 解决方案

要访问宿主 UI 的功能，请使用 `$host.UI.RawUI` 变量：

```
$host.UI.RawUI.WindowTitle = Get-Location
```

## 讨论

PowerShell 本身由两个主要组件组成。第一个是解释命令、执行管道并执行其他类似操作的引擎。第二个是宿主应用程序——用户与 PowerShell 引擎交互的方式。

默认 Shell `pwsh.exe` 是基于传统 Windows 控制台的 UI。图形化的 Visual Studio Code 在图形用户界面中承载 PowerShell。事实上，PowerShell 使开发人员能够相对简单地构建自己的宿主应用程序，甚至将 PowerShell 引擎功能嵌入到他们自己的应用程序中。

您（以及您的脚本）始终可以依赖通过 `$host.UI` 变量提供的功能，因为该功能对所有宿主都保持不变。[示例 13-9](#ch13.xhtml#functionality_available_through_the_doll) 显示了在所有宿主中可用的功能。

### 示例 13-9. 通过 $host.UI 属性可用的功能

如果您（或您的脚本）想要与特定于当前宿主的 UI 部分进行交互，PowerShell 通过 `$host.UI.RawUI` 变量提供该访问权限。[示例 13-10](#ch13.xhtml#functionality_available_through_the_defa) 显示了在 PowerShell 控制台宿主中可用的功能。

# 13.10 为脚本添加图形用户界面

## 问题

您想要创建一个脚本，为用户可视化复杂信息或支持高级用户交互。

## 解决方案

将 `System.Windows.Forms` 库添加到脚本中，然后使用其类型和对象创建图形界面：

```
Add-Type -Assembly System.Windows.Forms

$form = New-Object Windows.Forms.Form
$form.Size = New-Object Drawing.Size @(600,300)
$form.Text = "Hello Window Title!"

$label = New-Object Windows.Forms.Label
$label.Text = "Hello World!"
$label.Size = New-Object Drawing.Size @(550,200)
$label.TextAlign = "MiddleCenter"
$form.Controls.Add($label)

$form.ShowDialog()
```

## 讨论

尽管本章其余部分提供的技术通常已足够，但有时提供图形用户界面与用户交互会很有帮助。

由于 PowerShell 完全支持传统可执行文件，简单的编译应用程序通常可以满足此需求。如果在 Visual Studio 等环境中创建简单程序不方便，通常可以使用 PowerShell 直接创建这些应用程序。

[示例 13-11](#ch13.xhtml#select-graphicalfilteredobjectps1) 演示了仅使用 PowerShell 脚本开发 Windows 窗体应用程序的技术。该功能本身现在已由 PowerShell 中的 `Out-GridView` cmdlet 覆盖，但它演示了几种有用的技术。
