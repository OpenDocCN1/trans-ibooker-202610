
## Format-Hex Cmdlet

PowerShell 的 `Format-Hex` cmdlet 通过在报表中显示内容来启用这两种方案，该报表显示所有这些信息。最左侧的列显示内容中的偏移量，每次增加 16 字节。中间的 16 列显示该位置字节在内容中的十六进制表示。每列的标题显示该字符在 16 字节块中的偏移量。最右侧的列显示该行字符的 ASCII 表示。

要确定输入中字节的位置，将行最左侧的数字加上该字符所在列顶部的数字。例如，`0000000000000010`（显示在最左侧）+ `0A`（显示在列顶部）= `000000000000001A`。因此，此示例中的字节位于内容中的偏移量 `1A` 处。

除了这种基于文本的视图外，PowerShell 的 `Format-Hex` cmdlet 还返回结构丰富的对象。例如，要查看输出第二行（集合中的索引 1）中字节的十六进制表示，可以输入：

```
PS > $output = Format-Hex unicode.txt
PS > $output[1].HexBytes
6F 00 72 00 6C 00 64 00 0D 00 0A 00
```

有关与二进制数据交互的详细信息，请参阅 [Recipe 9.6](#ch09.xhtml#parse_and_manage_binary_files)。

# 第 10 章 结构化文件

## 10.0 简介

在纯文本系统管理的世界中，管理结构化文件通常很麻烦。例如，处理（或编辑）XML 文件意味着要么将其加载到编辑器中手动修改，要么编写一个自定义工具来完成此任务。更糟的是，这可能意味着像修改纯文本一样修改文件，同时希望不破坏 XML 本身的结构。

在同一个世界中，处理逗号分隔值（CSV）格式的文件意味着你要自己遍历文件，按其中的逗号拆分每一行。这看似是个好方法，直到你发现自己面对的数据并非最简单的情况。

结构和结构化文件不仅来自其他程序。编写脚本时，一个常见目标是保存结构化数据以便稍后使用。在大多数脚本（和编程）语言中，这要求你设计一种数据结构来保存数据，设计一种方式将其存储到磁盘并从中检索，并在你想再次使用时将其恢复为可用形式。

幸运的是，有了 PowerShell，处理 XML、CSV 甚至你自己的结构化文件变得容易得多。

## 10.1 访问 XML 文件中的信息

### 问题

你想要处理并访问 XML 文件中的信息。

### 解决方案

使用 PowerShell 的 XML 强制转换将纯文本 XML 转换为更易于处理的形式。在本例中，我们使用从 PowerShell 博客下载的 RSS 源：

```
PS > $xml = [xml] (Get-Content powershell_blog.xml)
```

#### 注意

有关如何使用 PowerShell 下载此文件的更多详细信息，请参阅 [Recipe 12.1](#ch12.xhtml#download_a_file_from_the_internet)：

```
Invoke-WebRequest https://devblogs.microsoft.com/powershell/feed/ `
    -OutFile powershell_blog.xml
```

与其他丰富对象一样，当你探索时，PowerShell 会显示 XML 的属性。这些属性是 XML 中的子节点和属性，如 [示例 10-1](#ch10.xhtml#accessing_properties_of_an_xml_document) 所示。

#### 示例 10-1. 访问 XML 文档的属性

```
PS > $xml
xml                     xml-stylesheet            rss
---                     --------------            ---
                                                  rss

PS > $xml.rss

version : 2.0
dc      : http://purl.org/dc/elements/1.1/
slash   : http://purl.org/rss/1.0/modules/slash/
wfw     : http://wellformedweb.org/CommentAPI/
channel : channel
```

如果多个节点共享同一名称（如 RSS 源中的 item 节点），则该属性名代表一个节点集合：

```
PS > ($xml.rss.channel.item).Count
15
```

你可以单独访问这些项，就像正常处理数组一样，如 [示例 10-2](#ch10.xhtml#accessing_individual_items_in_an_xml_doc) 所示。

#### 示例 10-2. 访问 XML 文档中的单个项

```
PS > ($xml.rss.channel.item)[0]

              management-framework-is-here.aspx

              618

```
PS > ($xml.rss.channel.item)[0].title

### 讨论

PowerShell 原生的 XML 支持提供了一种轻松浏览和访问 XML 文件的绝佳方式。通过将 XML 层次结构作为属性公开，你可以执行大多数任务，而无需求助于纯文本处理或自定义工具。

事实上，PowerShell 对 XML 交互的支持不仅限于以对象友好的方式呈现数据。`[xml]` 强制转换创建的对象实际上代表了来自 .NET Framework 的功能齐全的 `System.Xml.XmlDocument` 对象。生成对象的每个属性也代表来自 .NET Framework 的 `System.Xml.XmlElement` 对象。底层对象提供了大量额外功能，可用于对 XML 文件执行常见和复杂的任务。

支持你的 XML 的底层 `System.Xml.XmlDocument` 和 `System.Xml.XmlElement` 对象本身也提供了有用的属性：`Attributes`、`Name`、`OuterXml` 等。

```
PS > $xml.rss.Attributes

#text
-----
2.0
http://purl.org/dc/elements/1.1/
http://purl.org/rss/1.0/modules/slash/
http://wellformedweb.org/CommentAPI/
```

有关使用底层 .NET 对象执行更高级任务的详细信息，请参阅 [Recipe 10.2](#ch10.xhtml#perform_an_xpath_query_against_an_xml_fi) 和 [Recipe 10.4](#ch10.xhtml#modify_data_in_an_xml_file)。

有关在 PowerShell 中处理 XML 的详细信息，请参阅 [附录 F](#app06.xhtml#selected_net_classes_and_their_uses) 中的 [表 F-11](#app06.xhtml#xml-id001)。
