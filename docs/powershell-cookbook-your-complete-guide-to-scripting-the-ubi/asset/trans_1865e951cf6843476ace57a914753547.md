# 25.2 管理正在运行的服务

## 问题

您想要管理正在运行的服务。

## 解决方案

要停止服务，请使用 `Stop-Service` cmdlet：

```
PS > Stop-Service AudioSrv -WhatIf
What if: Performing operation "Stop-Service" on Target "Windows Audio
(AudioSrv)".
```

同样，使用 `Suspend-Service`、`Restart-Service` 和 `Resume-Service` cmdlet 分别挂起、重启和恢复服务。

## 讨论

`Stop-Service` cmdlet 允许您通过名称或显示名称停止服务。

有关 `Stop-Service` cmdlet 的详细信息，请输入 `Get-Help Stop-Service`。如果要挂起、重启或恢复服务，请分别参阅 `Suspend-Service`、`Restart-Service` 和 `Resume-Service` cmdlet 的帮助。

### 注意

请注意，解决方案在 `Stop-Service` cmdlet 上使用了 `-WhatIf` 标志。此参数可让您查看运行命令时会发生什么，但不会实际执行该操作。

要配置服务（例如其描述或启动类型），请参阅 [配方 25.3](#ch25.xhtml#configure_a_service)。除了允许您配置服务外，该配方中描述的 `Set-Service` cmdlet 还允许您在远程计算机上停止服务。

# 25.3 配置服务

## 问题

您想要配置服务的属性或启动行为。

## 解决方案

要配置服务，请使用 `Set-Service` cmdlet：

```
Set-Service WinRM -DisplayName 'Windows Remote Management (WS-Management)' `
    -StartupType Manual
```

要创建新服务或卸载现有服务，请使用 `New-Service` 和 `Remove-Service` cmdlet。

## 讨论

`Set-Service` cmdlet 允许您管理服务的配置：其名称、显示名称、描述和启动类型。

如果您更改了服务的启动类型，自然的下一步是验证更改是否已正确应用。[配方 25.1](#ch25.xhtml#list_all_running_services) 展示了如何查看服务的属性，包括启动类型。

# 第 26 章 Active Directory

# 26.0 简介

可以说，Windows 平台上系统管理的独特之处在于它与 Active Directory 的交互。作为 Windows 网络的集中授权、身份验证和信息存储，Active Directory 自动化构成了许多企业管理任务的核心。

在核心 PowerShell 语言中，与 Active Directory 交互的主要方式是通过其对 Active Directory Service Interface (ADSI) 类型快捷方式的支持。

此外，Active Directory 团队创建了一个功能极其丰富的 PowerShell 模块来管理 Active Directory 域。Active Directory 模块包括一个 PowerShell 提供程序 (`Set-Location AD:\`) 和近 100 个特定任务的 PowerShell cmdlet。

使用 Active Directory 模块有两个要求：

**服务器支持**

: 此模块适用于已启用 Active Directory Web Services 功能的任何域。Windows Server 2008 R2 默认在 Active Directory 实例上启用此功能，您也可以在从 Windows Server 2003 开始的任何较新服务器操作系统上安装它。

**客户端支持**

: 该模块本身包含在 Windows 7 远程服务器管理工具 (RSAT) 包中。下载并安装该包后，您可以通过控制面板中的“启用或关闭 Windows 功能”对话框来启用它。

如果可以使用 Active Directory 模块，请导入它并使用其命令。`Get-Command` 和 `Get-Help` 命令应该是您入门所需的两个关键步骤。除了内置在命令中的帮助外，MSDN 还提供了 [Active Directory 模块的优秀任务型介绍](https://oreil.ly/JiH6q)。

如果无法使用 Active Directory 模块，PowerShell 通过其内置的 `[adsi]` 和 `[adsisearcher]` 类型快捷方式提供了与 Active Directory 的无缝集成。本章介绍它们在最常见的 Active Directory 任务中的用法。

# 26.1 在本地安装上测试 Active Directory 脚本

## 问题

您想要针对本地安装测试 Active Directory 脚本。

## 解决方案

要针对本地系统测试脚本，请安装 Active Directory 轻型目录服务 (AD LDS) 及其示例配置。

## 讨论

对于大多数用途，Active Directory 轻型服务可作为 Active Directory 的轻量级版本工作。尽管它不支持 Active Directory 的任何基础设施功能，但其编程模型足够接近，您可以轻松地使用它来试验 Active Directory 脚本。在早期，Active Directory 轻型目录服务被称为 Active Directory 应用程序模式 (ADAM)，因此在学习使用它时，您可能会发现对 ADAM 的引用。要针对本地安装测试脚本，您需要启用 AD LDS 可选 Windows 功能（如 [图 26-1](#ch26.xhtml#enabling_adlds) 所示），然后创建一个测试实例。
