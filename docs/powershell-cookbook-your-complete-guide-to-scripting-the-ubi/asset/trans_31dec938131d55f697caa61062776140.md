
## 标记器 API

如果没有标记器 API 的支持，工具作者通常需要构建复杂的正则表达式来尝试模拟 PowerShell 引擎。虽然这些正则表达式在许多情况下很有帮助，但在更复杂的脚本上往往会失效。

作为该问题的一个示例，请参考[图 10-2](#ch10.xhtml#tokenization_error)的第一行。`Write-Host` 是 `Write-Host` cmdlet 的参数，但被解析为字符串。第二行虽然仍然向 `Write-Host` cmdlet 提供参数，但处理方式不同。事实上，因为它匹配 cmdlet 名称，该参数被着色为对 `Write-Host` cmdlet 的另一次调用。在随后的 `here` 字符串中，`Write-Host` cmdlet 名称再次被高亮显示，尽管它实际上只是字符串的一部分。

![](Images/wps4_1002.png)

因为标记器 API 遵循与 PowerShell 引擎相同的规则，它避免了基于正则表达式方法的陷阱，同时生成的输出更易于使用。在相同输入下运行时，它会生成[示例 10-8](#ch10.xhtml#successfully_tokenizing)所示的输出。

### 示例 10-8. 成功标记化复杂脚本

```
PS > [Management.Automation.PsParser]::Tokenize($content, [ref] $errors) | ft -auto

Content                           Type StartLine StartColumn EndLine EndColumn
-------                           ---- --------- ----------- ------- ---------
Write-Host                     Command    1           1       1        11
Write-Host                      String    1          12       1        24
...                            NewLine    1          24       2         1
Write-Host                     Command    2           1       2        11
Write-Host             CommandArgument    2          12       2        22
...                            NewLine    2          22       3         1
...                            NewLine    3           1       4         1
Write-Host Write-Host           String    4           1       4        24
...                            NewLine    4          24       5         1
...                            NewLine    5           1       6         1
testContent                   Variable    6           1       6        13
=                             Operator    6          14       6        15
Write-Host Hello World          String    6          16       8         3
...                            NewLine    8           3       9         1
```

这为您与 PowerShell 脚本交互的方式增加了全新的维度。一些自然的结果包括：

*   语法高亮
*   自动化脚本编辑（例如，将别名命令替换为其展开的等效命令）
*   脚本样式和格式验证

如果脚本包含任何错误，PowerShell 会将它们捕获在您必须提供的 `$errors` 集合中。如果您不想跟踪错误，可以为该参数提供 `[ref] $null` 作为值。

有关标记器 API 实际应用的示例，请参阅[食谱 8.7](#ch08.xhtml#program_show_colorized_content)。

### AST 生成

PowerShell 解析脚本中的文本标记后，会生成一个树结构来表示脚本的实际结构。例如，脚本不仅仅包含松散的标记集合，它们还有 `Begin`、`Process` 和 `End` 块。这些块可能包含 `Statements`，后者又可以包含带有 `Commands` 的 `PipelineElements`。例如：

```
PS > $ast = { Get-Process -Id $pid }.Ast
PS > $ast.EndBlock.Statements[0].PipelineElements[0].CommandElements[0].Value
Get-Process
```

正如解决方案所示，检索命令 AST 的最简单方法是访问其脚本块上的 `AST` 属性。例如：

```
PS C:\Users\Lee> function prompt { "PS > " }
PS > $ast = (Get-Command prompt).ScriptBlock.Ast
PS > $ast

IsFilter   : False
IsWorkflow : False
Name       : prompt
Parameters :
Body       : { "PS > " }
Extent     : function prompt { "PS > " }
Parent     : function prompt { "PS > " }
```

如果要从文本内容创建 AST，请使用 `[ScriptBlock]::Create()` 方法：

```
PS > $scriptBlock = [ScriptBlock]::Create('Get-Process -ID $pid')
PS > $scriptBlock.Ast


ParamBlock         :
BeginBlock         :
ProcessBlock       :
EndBlock           : Get-Process -ID $pid
DynamicParamBlock  :
ScriptRequirements :
Extent             : Get-Process -ID $pid
Parent             :
```

有了 PowerShell AST，高级脚本分析变得前所未有的简单。下面是一个使用 `[Ast]::FindAll()` 方法查找脚本中具有完全相同文本 `$pid` 的节点的简单示例：

```
$scriptBlock.Ast.FindAll( {
    param($Ast)
    if($Ast.Extent.Text -eq '$pid')
    {
        return $true
    }
}, $true)
```

要了解有关 PowerShell AST 公开的方法和属性的更多信息，请参阅[食谱 3.12](#ch03.xhtml#learn_about_types_and_objects)。

# 第 11 章. 代码重用

## 11.0 简介

令许多人惊讶的一件事是，仅从交互式提示符就能在 PowerShell 中完成如此多的工作。由于 PowerShell 让将其强大的命令组合成更强大的组合变得非常容易，爱好者们逐渐喜欢上了这种简洁性。事实上，大多数脚本爱好者的心中都有一个特殊的位置，专门留给最紧凑的力量表达：*单行命令*。

尽管交互式操作效率很高，但您可能不想每次需要时都重新输入所有绝妙的想法。当您想要保存或重用编写的命令时，PowerShell 提供了多种途径来支持您：脚本、模块、函数、脚本块等。

## 11.1 编写脚本

### 问题

您想将命令存储在脚本中，以便稍后共享或重用。

### 解决方案

要编写 PowerShell 脚本，请使用您喜欢的编辑器创建一个纯文本文件。将 PowerShell 命令添加到该脚本中（与您在交互式 Shell 中使用的相同 PowerShell 命令），然后使用 `*.ps1` 扩展名保存。

### 讨论

关于 PowerShell 最重要的一点是，运行脚本和在命令行工作本质上是等效的操作。如果您在脚本中看到它，可以在命令行中输入或粘贴。如果您在命令行中输入了它，可以将其粘贴到文本文件中并称之为脚本。

编写脚本后，PowerShell 允许您以调用其他程序和现有工具的相同方式调用它。运行脚本的效果等同于运行该脚本中的所有命令。

#### 注意

PowerShell 引入了一些与运行脚本和工具相关的功能，如果您不了解它们，起初可能会感到困惑。有关如何调用脚本和现有工具的更多信息，请参阅[食谱 1.2](#ch01.xhtml#run_programs_scripts_and_existing_tools)。

您第一次尝试在 PowerShell 中运行脚本时，可能会看到以下错误消息：

```
File c:\tools\myFirstScript.ps1 cannot be loaded because the execution of
scripts is disabled on this system. Please see "get-help about_signing" for
more details.
At line:1 char:12
+ myFirstScript <<<<
```

由于相对较少的计算机用户编写脚本，PowerShell 的默认安全策略会阻止脚本运行。但是，一旦您开始编写脚本，就应该将此策略配置为限制较少的设置。有关如何配置执行策略的信息，请参阅[食谱 18.1](#ch18.xhtml#enable_scripting_through_an_execution_po)。
