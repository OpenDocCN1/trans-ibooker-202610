
# Search-Registry

源自 *PowerShell Cookbook* (O'Reilly) 作者 Lee Holmes (http://www.leeholmes.com/guide)

## 概要

在注册表中搜索与特定值匹配的键或属性。

## 示例

```powershell
PS > Set-Location HKCU:\Software\Microsoft\
PS > Search-Registry Run
```

## 参数

- **Pattern** (必需): 要搜索的文本

## 脚本

```powershell
param(
    ## 要搜索的文本
    [Parameter(Mandatory = $true)]
    [string] $Pattern
)

Set-StrictMode -Off

## 用于创建表示此脚本注册表匹配项的新对象的辅助函数
function New-RegistryMatch
{
    param( $matchType, $keyName, $propertyName, $line )

    $registryMatch = New-Object PsObject -Property @{
        MatchType = $matchType;
        KeyName = $keyName;
        PropertyName = $propertyName;
        Line = $line
    }

    $registryMatch
}

## 遍历注册表中的每个项目
foreach($item in Get-ChildItem -Recurse -ErrorAction SilentlyContinue)
{
    ## 检查键名是否匹配
    if($item.Name -match $pattern)
    {
        New-RegistryMatch "Key" $item.Name $null $item.Name
    }

    ## 检查键属性是否匹配
    foreach($property in (Get-ItemProperty $item.PsPath).PsObject.Properties)
    {
        ## 如果是 PowerShell 添加的属性则跳过
        if(($property.Name -eq "PSPath") -or
            ($property.Name -eq "PSChildName"))
        {
            continue
        }

        ## 搜索属性的文本
        $propertyText = "$($property.Name)=$($property.Value)"
        if($propertyText -match $pattern)
        {
            New-RegistryMatch "Property" $item.Name `
                $property.Name $propertyText
        }
    }
}
```

有关运行脚本的更多信息，请参阅 [Recipe 1.2](#ch01.xhtml#run_programs_scripts_and_existing_tools)。

# 21.10 获取注册表键的 ACL

## 问题

您想要检索注册表键的 ACL。

## 解决方案

要检索注册表键的 ACL，请使用 `Get-Acl` cmdlet：

```powershell
PS > Get-Acl HKLM:\Software

Path                     Owner                   Access
----                     -----                   ------
Microsoft.PowerShell.... BUILTIN\Administrators  CREATOR OWNER Allow ....
```

## 讨论

正如 [Recipe 20.20](#ch20.xhtml#get_the_acl_of_a_file_or_directory) 中所述，`Get-Acl` cmdlet 检索项目的安全描述符。然而，此 cmdlet 不仅适用于注册表。任何支持安全描述符概念的提供程序（例如文件系统提供程序）也支持 `Get-Acl` cmdlet。

`Get-Acl` cmdlet 返回一个表示项目安全描述符的对象，该对象特定于包含该项目的提供程序。在注册表提供程序中，这将返回一个 .NET `System.Security.AccessControl.RegistrySecurity` 对象，您可以进一步探索它以获取更多信息。有关使用此结果更改注册表键 ACL 的示例，请参阅 [Recipe 21.11](#ch21.xhtml#set_the_acl_of_a_registry_key)。有关使用 ACL 的脚本示例，请参阅 [Recipe 20.20](#ch20.xhtml#get_the_acl_of_a_file_or_directory)。

有关 `Get-Acl` 命令的更多信息，请输入 `Get-Help Get-Acl`。有关使用 .NET Framework 类的更多信息，请参阅 [Recipe 3.8](#ch03.xhtml#work_with_net_objects)。

# 21.11 设置注册表键的 ACL

## 问题

您想要更改注册表键的 ACL。

## 解决方案

要在注册表键上设置 ACL，请使用 `Set-Acl` cmdlet。此示例授予帐户对 `HKLM:\Software` 下注册表键的写入访问权限。这对于将数据写入注册表仅限管理员区域的程序特别有用，这会阻止它们在非管理员帐户下运行：

```powershell
##############################################################################
##
## Grant-RegistryAccessFullControl
##
## From PowerShell Cookbook (O'Reilly)
## by Lee Holmes (http://www.leeholmes.com/guide)
##
##############################################################################

<#

.SYNOPSIS

为指定的注册表键授予用户完全控制访问权限。

.EXAMPLE

PS > $registryPath = "HKLM:\Software\MyProgram"
PS > Grant-RegistryAccessFullControl "LEE-DESK\LEE" $registryPath

#>

param(
    ## 要授予完全控制权限的用户
    [Parameter(Mandatory = $true)]
    $User,

    ## 应修改权限的注册表路径
    [Parameter(Mandatory = $true)]
    $RegistryPath
)

Set-StrictMode -Version 3

Push-Location
Set-Location -LiteralPath $registryPath

## 从注册表键检索 ACL
$acl = Get-Acl .

## 准备访问规则，并设置访问规则
$arguments = $user,"FullControl","Allow"
$accessRule = New-Object Security.AccessControl.RegistryAccessRule $arguments
$acl.SetAccessRule($accessRule)

## 将修改后的 ACL 应用到注册表键
$acl | Set-Acl  .

Pop-Location
```

## 讨论

正如 [Recipe 20.21](#ch20.xhtml#set_the_acl_of_a_file_or_directory) 中所述，`Set-Acl` cmdlet 设置项目的安全描述符。然而，此 cmdlet 不仅适用于注册表。任何支持安全描述符概念的提供程序（例如文件系统提供程序）也支持 `Set-Acl` cmdlet。

`Set-Acl` cmdlet 要求您提供要应用于项目的 ACL。虽然可以从头构建 ACL，但通常最简单的方法是预先从项目检索它（如解决方案中所示）。要检索 ACL，请使用 `Get-Acl` cmdlet。一旦您修改了 ACL 上的访问控制规则，只需将它们通过管道传递给 `Set-Acl` cmdlet 即可使其永久生效。

在解决方案中，我们提供给 `RegistryAccessRule` 构造函数的 `$arguments` 列表显式在 `LEE-DESK` 计算机的 `Lee` 帐户上设置了一个 `FullControl` 权限的 `Allow` 规则。有关使用 .NET Framework 类（如 `RegistryAccessRule` 类）的更多信息，请参阅 [Recipe 3.8](#ch03.xhtml#work_with_net_objects)。

虽然 `Set-Acl` 命令功能强大，但您可能已经熟悉提供类似功能的命令行工具（如 `SubInAcl.exe`）。当然，您可以继续在 PowerShell 中使用这些工具。

有关 `Set-Acl` cmdlet 的更多信息，请输入 `Get-Help Set-Acl`。有关 `Get-Acl` cmdlet 的更多信息，请参阅 [Recipe 21.10](#ch21.xhtml#get_the_acl_of_a_registry_key)。
