
# Scientific Notation and Literal Strings

Displays the input in scientific notation. The number of zeros that follow the `E` define the minimum length of the exponent field:

```
PS > "{0:##.#E000}" -f 2.71828
27.2E-001
```

| Format specifier | Name | Description | Example |
|------------------|------|-------------|---------|
| `'`*`text`*`'` | Literal string | Inserts the provided text literally into the output without affecting formatting | `PS > "{0:#.00'##'}" -f 2.71828`<br>`2.72##` |
| `"`*`text`*`"` | Literal string | Inserts the provided text literally into the output without affecting formatting | `PS > "{0:#.00'##'}" -f 2.71828`<br>`2.72##` |
| `;` | Section separator | Allows for conditional formatting.<br><br>If your format specifier contains no section separators, the formatting statement applies to all input.<br><br>If your format specifier contains one separator (creating two sections), the first section applies to positive numbers and zero, and the second section applies to negative numbers.<br><br>If your format specifier contains two separators (creating three sections), the sections apply to positive numbers, negative numbers, and zero: | `PS > "{0:POS;NEG;ZERO}" -f -14`<br>`NEG` |
| `Other` | Other character | Inserts the provided text literally into the output without affecting formatting | `PS > "{0:$## Please}" -f 14`<br>`$14 Please` |

# Appendix E. .NET DateTime Formatting

`DateTime` format strings convert a `DateTime` object to one of several standard formats, as listed in [Table E-1](#table-e-1-standard-datetime-format-strings).

## Table E-1. Standard DateTime Format Strings

| Format specifier | Name | Description | Example |
|------------------|------|-------------|---------|
| `d` | Short date | The culture's short date format | `PS > "{0:d}" -f [DateTime] "01/23/4567"`<br>`1/23/4567` |
| `D` | Long date | The culture's long date format | `PS > "{0:D}" -f [DateTime] "01/23/4567"`<br>`Friday, January 23, 4567` |
| `f` | Full date/short time | Combines the long date and short time format patterns | `PS > "{0:f}" -f [DateTime] "01/23/4567"`<br>`Friday, January 23, 4567 12:00 AM` |
| `F` | Full date/long time | Combines the long date and long time format patterns | `PS > "{0:F}" -f [DateTime] "01/23/4567"`<br>`Friday, January 23, 4567 12:00:00 AM` |
| `g` | General date/short time | Combines the short date and short time format patterns | `PS > "{0:g}" -f [DateTime] "01/23/4567"`<br>`1/23/4567 12:00 AM` |
| `G` | General date/long time | Combines the short date and long time format patterns | `PS > "{0:G}" -f [DateTime] "01/23/4567"`<br>`1/23/4567 12:00:00 AM` |
| `M` or `m` | Month day | The culture's `MonthDay` format | `PS > "{0:M}" -f [DateTime] "01/23/4567"`<br>`January 23` |
| `o` | Round-trip date/time | The date formatted with a pattern that guarantees the string (when parsed) will result in the original `DateTime` again | `PS > "{0:o}" -f [DateTime] "01/23/4567"`<br>`4567-01-23T00:00:00.0000000` |
| `R` or `r` | RFC1123 | The standard RFC1123 format pattern | `PS > "{0:R}" -f [DateTime] "01/23/4567"`<br>`Fri, 23 Jan 4567 00:00:00 GMT` |
| `s` | Sortable | Sortable format pattern. Conforms to ISO 8601 and provides output suitable for sorting | `PS > "{0:s}" -f [DateTime] "01/23/4567"`<br>`4567-01-23T00:00:00` |
| `t` | Short time | The culture's `ShortTime` format | `PS > "{0:t}" -f [DateTime] "01/23/4567"`<br>`12:00 AM` |
| `T` | Long time | The culture's `LongTime` format | `PS > "{0:T}" -f [DateTime] "01/23/4567"`<br>`12:00:00 AM` |
| `u` | Universal sortable | The culture's `UniversalSortable DateTime` format applied to the UTC equivalent of the input | `PS > "{0:u}" -f [DateTime] "01/23/4567"`<br>`4567-01-23 00:00:00Z` |
| `U` | Universal | The culture's `FullDateTime` format applied to the UTC equivalent of the input | `PS > "{0:U}" -f [DateTime] "01/23/4567"`<br>`Friday, January 23, 4567 8:00:00 AM` |
| `Y` or `y` | Year month | The culture's `YearMonth` format | `PS > "{0:Y}" -f [DateTime] "01/23/4567"`<br>`January, 4567` |

# Custom DateTime Format Strings

You can use the custom `DateTime` format strings listed in [Table E-2](#table-e-2-custom-datetime-format-strings) to format dates in ways not supported by the standard format strings.

> **Note**
>
> Single-character format specifiers are by default interpreted as a standard `DateTime` formatting string unless they are used with other formatting specifiers. Add the `%` character before them to have them interpreted as a custom format specifier.

## Table E-2. Custom DateTime Format Strings

| Format specifier | Description | Example |
|------------------|-------------|---------|
| `d` | Day of the month as a number between 1 and 31. Represents single-digit days without a leading zero | `PS > "{0:%d}" -f [DateTime] "01/02/4567"`<br>`2` |
| `dd` | Day of the month as a number between 1 and 31. Represents single-digit days with a leading zero | `PS > "{0:dd}" -f [DateTime] "01/02/4567"`<br>`02` |
| `ddd` | Abbreviated name of the day of week | `PS > "{0:ddd}" -f [DateTime] "01/02/4567"`<br>`Fri` |
| `dddd` | Full name of the day of the week | `PS > "{0:dddd}" -f [DateTime] "01/02/4567"`<br>`Friday` |
| `f` | Most significant digit of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:%f}" -f $date`<br>`0` |
| `ff` | Two most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:ff}" -f $date`<br>`09` |
| `fff` | Three most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:fff}" -f $date`<br>`093` |
| `ffff` | Four most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:ffff}" -f $date`<br>`0937` |
| `fffff` | Five most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:fffff}" -f $date`<br>`09375` |
| `ffffff` | Six most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:ffffff}" -f $date`<br>`093750` |
| `fffffff` | Seven most significant digits of the seconds fraction (milliseconds) | `PS > $date = Get-Date`<br>`PS > $date.Millisecond`<br>`93`<br>`PS > "{0:fffffff}" -f $date`<br>`0937500` |
| `F`<br>`FF`<br>`FFF`<br>`...`<br>`FFFFFFF` | Most significant digit of the seconds fraction (milliseconds). When compared to the lowercase series of `f` specifiers, displays nothing if the number is zero | `PS > "{0:|F FF FFF FFFF|}" -f [DateTime] "01/02/4567"`<br>`|   |----` |
| `%g` or `gg` | Era (e.g., A.D.) | `PS > "{0:gg}" -f [DateTime] "01/02/4567"`<br>`A.D.` |
| `%h` | Hours, as a number between 1 and 12. Single digits do not include a leading zero | `PS > "{0:%h}" -f [DateTime] "01/02/4567 4:00pm"`<br>`4` |
| `hh` | Hours, as a number between 01 and 12. Single digits include a leading zero. Note: this is interpreted as a standard `DateTime` formatting string unless used with other formatting specifiers | `PS > "{0:hh}" -f [DateTime] "01/02/4567 4:00pm"`<br>`04` |
| `%H` | Hours, as a number between 0 and 23. Single digits do not include a leading zero | `PS > "{0:%H}" -f [DateTime] "01/02/4567 4:00pm"`<br>`16` |
| `HH` | Hours, as a number between 00 and 23. Single digits include a leading zero | `PS > "{0:HH}" -f [DateTime] "01/02/4567 4:00am"`<br>`04` |
| `K` | `DateTime.Kind` specifier that corresponds to the kind (i.e., local, UTC, or unspecified) of input date | `PS > "{0:%K}" -f [DateTime]::Now.ToUniversalTime()`<br>`Z` |
| `m` | Minute, as a number between 0 and 59. Single digits do not include a leading zero | `PS > "{0:%m}" -f [DateTime]::Now`<br>`7` |
| `mm` | Minute, as a number between 00 and 59. Single digits include a leading zero | *(example continues)* |
