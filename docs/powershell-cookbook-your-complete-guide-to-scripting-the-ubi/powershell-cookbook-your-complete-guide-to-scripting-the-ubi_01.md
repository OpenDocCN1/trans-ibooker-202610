# 前言

欢迎阅读《*Windows PowerShell 食谱*》第四版！

哎呀。我说错了。让我再试一次。

欢迎阅读《*Windows PowerShell 食谱*》第四版！

名称的变化说明了一切。正如《*Windows PowerShell 食谱*》理应占据每位 Windows 管理员桌面一席之地，《*PowerShell 食谱*》也理应占据每位管理员桌面一席之地。

PowerShell 团队始终专注于为管理员提供成为公司英雄所需的工具。但该团队隶属于微软，正如前微软 CEO 史蒂夫·鲍尔默常说的：“Windows 是我们呼吸的空气。”这就是为什么本书前三版名为《*Windows PowerShell 食谱*》。

从一开始，团队就希望支持 Linux。我们知道，碎片化的技术会导致碎片化的组织。公司不再设立统一的管理员团队，而是分裂成孤立的 Windows 管理员团队和 Linux 管理员团队。我们想要提供一个统一的工具供所有管理员使用，无论平台（Windows 或 Linux）、技能水平（简单交互用户、初学者脚本编写者、高级系统开发人员）或管理对象（Azure、AWS、Google、VMware 等）。但我们的雄心受限于 .NET 依赖。当 .NET 开始移植到 Linux 时，一切都变了。.NET Core 的首个版本是跨平台的，我们尽快将其移植过来。结果诞生了 PowerShell Core v6，它可在 Windows 和 Linux 上运行。业界关注到了这一点。我们的发布合作伙伴包括 VMware、Google 和 AWS：这并非典型的微软合作伙伴阵容。

PowerShell Core 很适合 Linux，但 .NET Core 库数量较少，意味着在几个重要领域它不如 Windows PowerShell v5 强大。Windows 用户面临选择：Windows PowerShell 还是 PowerShell Core。2020 年 PowerShell v7 的发布改变了一切。它基于 .NET Core 3.1 构建，极大地提高了 Windows 上的兼容性。结合我们大量的工作，推出了一个无妥协的版本。我们更改了名称，去掉了“Windows”和“Core”。有了版本 7，只有“PowerShell”——供所有团队管理其环境中任何内容的单一工具。

正如 Windows PowerShell 进化以更好地满足想要管理一切的管理员需求一样，本书也进化以更好地满足这些管理员的需求。这是一个主要版本，删除了 30,000 多处，新增了 35,000 多处。Lee 以 PowerShell 导览 开篇。在其中，他向读者介绍 PowerShell 的关键概念，并奠定思考问题和使用 PowerShell 解决问题的基础。随后是 基础，深入探讨八个关键 PowerShell 概念。有了这个基础，你就可以解决一些问题了。接下来的 10 个章节专注于代码重用、调试、跟踪和错误管理等常见任务。我喜欢开玩笑说，“解决问题”和“以一种一个月后不后悔的方式解决问题”是两码事。这些章节教你后者。这些是如何为生产环境编写无悔 PowerShell 的来之不易的经验教训。接下来的 12 个章节涵盖处理文件和目录、Windows 注册表、Active Directory 和远程处理等特定管理员任务。

虽然以前的版本涵盖了许多这些主题，但本版结合 PowerShell 生态系统中最新、最棒的工具（包括 Windows Terminal、Visual Studio Code 和 SSH），以及只有经过几十年一线实战经验才能获得的教训和视角，将这些内容更新到了最新状态。俗话说：“聪明人不从自己的错误中学习，聪明人从别人的错误中学习。”所以你可以花未来二十年从自己的错误中学习，也可以阅读本书，向 Lee 学习——自从他加入最初的 v1 团队那天起，他就是团队中的超级明星。

我最喜欢《PowerShell 食谱》的地方在于它教会读者如何思考问题。是的，书中有数百页针对特定问题的解决方案，仅此一点就足以使其成为每位管理员的必备书籍。但 Lee 拥有“授人以渔”的心态，他的每个解决方案都让你能够解决一整类问题。

那么，如何阅读一本超过一千页的书呢？

当然，许多人通过阅读 PowerShell 导览 和 基础，然后在遇到问题时跳转到特定章节，能获得很多收获。




# 前言 (重复)

我认为，对于初学者而言，建立在列夫·维果茨基活动理论基础上的方法会更好。维果茨基区分了*胜任力*与*表现*。他指出，当我们在*专家*的指导下时，我们的*表现*可以超越我们的*胜任力*。设想这样一种情况：我想查找某个日期之前修改的所有文件，却不懂任何 PowerShell——我（目前）不具备执行此任务的*胜任力*。但因为我有远见买了这本书，我所要做的就是翻开食谱 20.3。在那里我看到了解决方案。我输入命令，并*执行*了一项非常复杂的任务。李（专家）帮我解决了一个复杂的问题（表现），尽管我不懂 PowerShell（胜任力）。

尽管这很棒，但神奇的时刻发生在下一步。既然我现在能够成功执行一项复杂任务，我就可以开始实验，而在实验中，我建立并提升了自己的胜任力。

我运行这些命令。然后我故意犯个错，看看错误消息是什么。下次再见到该错误消息，我就知道自己犯了什么错。从这里，我使用 `Get-Help` 查找命令，探索还能使用哪些其他参数。李的“解决方案”提供了一个成功的滩头阵地。然后我们利用好奇心去探索——这又如何？我想知道……为什么不？也许……？这就是正道。而且简直太有趣了。

我们的好奇心驱动着我们的学习、理解和胜任力。在各个阶段，我们的好奇心都会遇到需要深入探索的问题。此时，我们可以回到 PowerShell 指南之旅 和 基础知识 章节。因真实问题而阅读这些章节，会让它们更加相关、难忘且极具影响力。

# 序言

2002 年底，Slashdot 发布了一则关于微软正在开发“下一代 Shell”的传闻故事。作为 Shell 及其脚本语言所释放威力的长期爱好者，这则帖子立刻引起了我的兴趣。这个 Shell 能否提供我长久以来在 Unix 系统上喜爱的命令行威力和生产力？

既然我六个月前刚加入微软，我抓住机会终于弄清了一个源自 Slashdot 的“微软谜团”。帖子提到与 .NET Framework 的强集成，所以我向一个内部 C# 邮件列表发布了询问。我得到回复，该项目代号为“Monad”，我随即用它找到了一个内部原型构建版。

“原型”算是个客气的说法。在早期阶段，该构建版主要是一个概念验证。想清屏？没问题！只要靠着 Enter 键不放，直到之前的命令和输出滚出视野即可！但即使在这些早期阶段，也立刻清楚地表明 Monad 标志着命令行 Shell 的一场革命。与许多这种规模的事物一样，它的美妙不言自明。Monad 在其命令之间传递全保真 .NET 对象。对于甚至最复杂的命令，Monad 废除了（直到那时为止的标准）对脆弱的基于文本解析的需求。简单而强大的数据操作工具支持这一新模型，创造了一个既强大又易用的 Shell。

不久后，我加入了 Monad 开发团队，尽自己的一份力将这项技术杰作带给世界其他地方。从那时起，Monad 发展成为一个真实、有形的产品——现在称为 PowerShell。

那么为什么要写一本关于它的书？为什么要写*这本*书？

许多用户学习 PowerShell 是为了学习 PowerShell 本身。任何切实的好处都是副作用。但其他人可能更倾向于在新技术解决其需求时，机会主义地学习它。如何使用 PowerShell 导航文件系统？如何管理文件和文件夹？如何检索网页？

这本书专注于通过针对您最迫切问题的基于任务的解决方案，帮助您学习 PowerShell。阅读一个食谱、一章或整本书——无论如何，您都能学到东西。

## 适读人群

这本书帮助您使用 PowerShell *完成工作*。它包含数百个针对特定真实问题的解决方案。对于系统管理，您将找到大量示例，展示如何管理文件系统、Windows 注册表、事件日志、进程等。对于企业管理，您将找到两章完整内容，专门介绍 Windows Management Instrumentation (WMI)、Active Directory 和其他面向企业的任务。

在此过程中，您还将学到大量关于 PowerShell 的知识：其特性、命令及其脚本语言——但最重要的是，您将解决问题。

## 本书结构

本书由五个主要部分组成：PowerShell 指南之旅、PowerShell 基础知识、常见任务、管理员任务和详细参考。

### 第 I 部分

PowerShell 指南之旅 从高层快速浏览 PowerShell。它介绍 PowerShell 的核心特性：

* 交互式 Shell
* 新的命令模型
* 基于对象的管道
* 专注于管理员的敏锐焦点
* 统一的学习与发现模型
* 无处不在的脚本编写
* 与关键管理技术的集成
* 统一的数据存储交互模型

该指南帮助您整体熟悉 PowerShell。这种熟悉感将为您理解本书其余部分的解决方案创建一个心智框架。

### 第 II 部分

第 1 章至第 8 章涵盖支撑本书解决方案的基础知识。本部分向您介绍 PowerShell 交互式 Shell、基本管道和对象概念，以及 PowerShell 脚本语言的许多特性。

### 第 III 部分

第 9 章至第 19 章涵盖您在开始用 PowerShell 解决更复杂问题时最常遇到的任务。这包括处理简单和结构化文件、联网脚本、代码重用、用户交互等。

### 第 IV 部分

第 20 章至第 31 章专注于系统和企业管理中最常见的任务。第 20 章至第 25 章专注于单个系统：文件系统、注册表、事件日志、进程、服务等。第 26 章和第 27 章专注于 Active Directory，以及管理联网或加入域的系统中最典型的任务。第 28 章和第 29 章专注于稳健多机管理的两个关键方面：WMI 和 PowerShell 远程处理。

### 第 V 部分

许多书籍在附录中堆砌无用信息仅为增加页数。然而在本书中，详细参考支撑起了一个学习和使用 PowerShell 不可或缺的重要资源。附录涵盖：

* PowerShell 语言和环境
* 正则表达式语法和 PowerShell 侧重示例
* XPath 快速参考
* .NET `string` 格式化语法和 PowerShell 侧重示例
* .NET `DateTime` 格式化语法和 PowerShell 侧重示例
* 管理员友好的 .NET 类及其用法
* 管理员友好的 WMI 类及其用法
* 管理员友好的 COM 对象及其用法
* 精选事件及其用法
* PowerShell 标准动词

## 使用本书所需条件





本书的大部分需要的只是一个可用的 `PowerShell` 安装。所有受支持的 Windows 版本（Windows 7 及更高版本，以及 Windows Server 2012 及更高版本）默认都包含 `Windows PowerShell`。然而，比这个默认安装显著提升的是开源的 `PowerShell Core`。您可以在食谱 1.1 中了解更多关于升级到 `PowerShell Core`（或简称为 `PowerShell`）的信息。

第 26 章中给出的 Active Directory 脚本在应用于企业环境时最为有用，但食谱 26.1 展示了如何安装额外软件（Active Directory 轻型目录服务，或 Active Directory 应用程序模式），以便您能针对本地安装运行这些脚本。
