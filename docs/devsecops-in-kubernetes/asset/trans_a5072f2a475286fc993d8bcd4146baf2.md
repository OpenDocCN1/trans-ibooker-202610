# Introduction

你知道安全很重要。无论你的系统是云原生、已以传统架构迁移到云中，还是刚刚开始这段旅程，你都知道进入云端让安全变得比以往任何时候都更复杂。更重要的是，安全现在是每个人的工作。

几十年来，软件开发和交付都是缓慢的过程。早期的企业软件是手工交付给客户，并由受过训练的技术人员安装。云服务提供商改变了这一切，利用规模经济提供许多组织自身无法实现的能力，并使使用虚拟化技术变得更便宜、更容易。

幸运的是，随着越来越多的应用托管外包给云服务提供商，所带来的变化使设计、开发、测试、部署和管理团队更加紧密地联系在一起。这很重要，因为虽然虚拟化提供了令人惊叹的机会和能力，但也意味着比过去有更多活动的部件。为了应对这一点，你不仅需要强大的管理能力——你还需要自动化。

在云中，自动化通常被称为编排，因为中间有一个部分必须保持所有元素在节奏和关键上。使用 Kubernetes 之类的工具来编排容器化应用的开发、部署和运行阶段，可以在很大程度上帮助自动化和扩展应用交付，但这不是魔法。你仍然需要把参与开发、编排和部署的所有团队聚集在一起，因为他们每个人都会有不同且重要的见解。例如，当你引入编排时，这意味着需要开发工作来创建脚本和配置。然后这些需要被测试，当然，负责部署的团队需要发表意见，看看他们是否拥有所需的一切。

这很复杂，但通过组织内部的文化变革和观点转变，你可以将合适的人、视角和见解汇聚到一个团队中。这就是 DevOps 总体上，以及 DevSecOps 模型特别可以提供帮助的地方。别担心，如果你现在还不确定这意味着什么。我会在 [Chapter 1](#ch01.xhtml#chapter1) 向你介绍 DevOps，到 [Chapter 3](#ch03.xhtml#chapter3) 我们将深入 DevSecOps。沿途，我们将使用 Kubernetes 作为与 DevSecOps 文化配合良好的技术的例子。

我们稍后会深入了解这些云原生技术，但 Kubernetes 可以支持云原生的两个主要方面。第一个是自动化。Kubernetes 原生支持你所有元素的自动化，因此应用部署更容易、更易于管理。在自动化之上，Kubernetes 带来了抽象。软件开发长期以来一直试图尽可能地从硬件抽象出来，应用开发和管理中更细粒度的虚拟化水平让我们远离硬件。Kubernetes 支持这种抽象，使开发人员能够专注于功能，而无需担心所有不同组件如何组合在一起。

如果你现在只知道 DevSecOps 的一件事，那就是：安全不是孤立团队的工作。安全需要在整体开发生命周期的每一步中融入，并由开发和运营团队与安全团队一样拥有。这需要工作来识别你的应用设计和实现所需的正确工具、流程和要求。本报告将引导你了解如何做到这一点，从一开始生成需求开始，贯穿生命周期的其余部分。把它看作是增强安全性的第一步。

如果你的工作涉及或管理软件开发生命周期 SDLC 的任何部分，本报告适合你。在前半部分，我们将研究软件开发方法和架构设计，重点是如何将安全措施作为整体集成到这些流程中。然后，在后半部分，我们将深入 DevSecOps 以及将安全嵌入 SDLC 以识别和应对威胁的艺术和科学。到本报告结束时，你将更好地理解采用 DevSecOps 思维如何使你的团队和组织从头到尾更强大、更有韧性、更安全。沿途，我们将研究 Kubernetes 等技术如何被利用以更好地实现 DevSecOps 哲学和实践。

# Chapter 1. Software Development Life Cycles
