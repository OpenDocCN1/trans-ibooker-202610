Figure 6.29 – Security

You can enable a couple of very useful services here, as follows:

- **Binary Authorization**: Disallows running unsigned images on your cluster
- **Shielded GKE Nodes**: Provides a strong cryptographic identity for nodes in the cluster
- **Confidential GKE nodes**: Encrypts the memory of your nodes with keys that Google does not have access to
- **Application-layer Secrets Encryption**: Uses Cloud KMS to encrypt secrets stored in etcd databases
- **Workload Identity**: Allows you to use your workloads to access the Google API securely by mapping Kubernetes service accounts to Google service accounts
- **Google Groups for RBAC**: Maps the Google Groups to the roles and cluster roles in your cluster

There are also some legacy security options that you should not use unless you have a special use case and you are confident with the security tradeoffs.
