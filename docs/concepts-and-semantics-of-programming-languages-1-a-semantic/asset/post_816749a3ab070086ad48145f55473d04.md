
found in this instruction and of the postconditions associated with the programs found in the two branches of the instruction. For example, we have:

```
(Aff) {y=0} x := y {↓x=0}           (Aff) {not y=0} x := 0 {↓x=0}
(ConsG) {true}                     (ConsG) {true}
       {                           }
       and                         and
       x := y {↓x=0}               x := 0 {↓x=0}
       y = 0                       not y = 0
(Cond) -----------------------------------------------------------
      {true} if y=0 then x := y else x := 0 {↓x=0}
```

Finally, considering a property \(P_I\), the rule \((W_P)\) establishes that:

- \(P_I\) is verified at the beginning of the execution of a loop;
- if both \(P_I\) and the condition to enter the loop are verified, \(P_I\) remains true after executing the body of the loop, then after the execution of the loop, \(P_I\) holds and the condition to enter the loop is no longer satisfied.

\(P_I\) is known as a *loop invariant* and is used to express properties of the computation done by the loop. For example:

```
(Aff) {↓x+1 ≤ b} x := ↓x + 1 {↓x ≤ b}
                \(P_1'\)
(ConsG) {↓x ≤ b and ↓x < b} x := ↓x + 1 {↓x ≤ b} (\(P_1 \Rightarrow P_1'\))
                \(P_1\)
(W_P) --------------------------------------------------------------------
      {↓x ≤ b} while ↓x < b do x := ↓x + 1 {↓x ≤ b and not ↓x < b}
                                          \(P_2'\)
(ConsD) -------------------------------------------------------------------
                    (\(P_2' \Rightarrow P_2\))
                  {↓x ≤ b} while ↓x < b do x := ↓x + 1 {↓x = b}
                                          \(P_2\)
```

## 4.7.2.1.2. Validity and completeness

A program \(c\) is partially correct with regard to precondition \(P_1\) and postcondition \(P_2\) if and only if for every state that satisfies \(P_1\) and in which the execution of \(c\) terminates, the state obtained after execution satisfies \(P_2\). Since the operational semantics presented in section 4.4.1 can be used to characterize terminating executions and the states resulting from these executions, we can establish that provable Hoare triples \(\{P_1\}c\{P_2\}\) (with the extensional approach used here) correspond exactly to triples expressing the partial correctness of \(c\) in relation to \(P_1\) and \(P_2\). First, the inference system \( c \) can be shown to be valid (if a triple is provable, then the program is partially correct):

```
\(\{P_1\}c\{P_2\}\)
\(\Rightarrow \forall (\text{Env}, \text{Mem}) \in \mathbf{E} \times \mathbf{M} \left( \begin{matrix} \} \end{matrix} \right) \Rightarrow \} = 1\)
```

Second, we can show that this system is complete (if a program is partially correct, then the corresponding Hoare triple is provable):

```
\(\left( \begin{matrix} \forall (\text{Env}, \text{Mem}) \in \mathbf{E} \times \mathbf{M} \left( \begin{matrix} \} \end{matrix} \right) \Rightarrow \} = 1 \right)\)
\(\Rightarrow \{P_1\}c\{P_2\}\)
```

Proofs of these two properties can be found in [NIE 07].

## 4.7.2.2. Total correctness

Partial correctness of a program relates to properties of the states obtained when the execution of the program terminates. For non-terminating executions, the properties that are obtained are not correct, even if the inference trees of the associated Hoare triples are finite. A typical example of this is the program **while** \( \text{true} \) **do** \( \text{skip} \), for which it is possible to prove the two triples \(\{ \text{true} \} \mathbf{while} \text{true} \mathbf{do} \text{skip} \{ \text{true} \}\) and \(\{ \text{true} \} \mathbf{while} \text{true} \mathbf{do} \text{skip} \{ \text{false} \}\) :

```
\(\frac{}{(\text{Skip}) \{ \text{true} \} \text{skip} \{ \text{true} \}}\)
\(\frac{(\text{Cons}_G) \{ \text{true and true} \} \text{skip} \{ \text{true} \}}{((\text{true} \text{ and } \text{true}) \Rightarrow \text{true})}\)
\(\frac{(\text{W}_P) \{ \text{true} \} \mathbf{while} \text{true} \mathbf{do} \text{skip} \{ \text{true and not } \text{true} \}}{\{ \text{true} \} \mathbf{while} \text{true} \mathbf{do} \text{skip} \{ \text{true / false} \} (I)}\)
```

since the expression \( \text{true} \text{ and not } \text{true} \) is never verified, so \( I \) can correspond to each of the implications \( (\text{true and not } \text{true}) \Rightarrow \text{true} \) and \( (\text{true and not } \text{true}) \Rightarrow \text{false} \).

A program \( c \) is totally correct with respect to a precondition \( P_1 \) and postcondition \( P_2 \) if and only if for any state satisfying \( P_1 \), the execution of \( c \) in this state terminates in a state that satisfies \( P_2 \). To characterize provable triples expressing the total correctness of a program, we simply modify rule (W<sub>P</sub>) (as non-termination results from the construction **while** \( e \) **do** \( c \) alone). The new rule

```
\((\text{W}_T) \frac{\{ P_I \text{ and } e \text{ and } V = n \} c \{ P_I \text{ and } V < n \}}{\{ P_I \} \mathbf{while} \ e \mathbf{do} \ c \{ P_I \text{ and not } e \}} (P_I \Rightarrow V \ge 0)\)
```

introduces a _loop variant_ \( V \) that must be positive when the invariant \( P_I \) is verified, and must strictly decrease at each iteration of the loop. This guarantees that the loop will terminate, as no strictly decreasing infinite sequence exists over the set of natural numbers IN. For example, we can prove the total correctness expressed by the following triple:

```
{ ↓ x ≤ b } while ↓ x < b do x := ↓ x + 1 { ↓ x = b }
```

by considering the variant V = b − ↓ x. The precondition guarantees that V ≥ 0 and V strictly decreases at each iteration of the loop (as ↓ x is strictly increasing).

```
(Aff)
----------------
{ ↓ x + 1 ≤ b and b − ↓ x − 1 < n }
x := ↓ x + 1 { A5 }
          A6
(ConsG)
---------------------------------- (I3)
{ ↓ x ≤ b and ↓ x < b and b − ↓ x = n } x := ↓ x + 1 { ↓ x ≤ b and b − ↓ x < n }
          A4                                      A5
(W_T)
{ A1 } while ↓ x < b do x := ↓ x + 1 { ↓ x ≤ b and not ↓ x < b }
                                   A3
(ConsD)
---------------------------------- (I1)
{ ↓ x ≤ b } while ↓ x < b do x := ↓ x + 1 { ↓ x = b }
      A1                           A2
```

The choice of rules (ConsG) and (ConsD) is correct, as I1 and I3 are implications A3 ⇒ A2 and A4 ⇒ A6, which are easy to verify. Rule (W_T) is also used correctly, as I2 corresponds to the implication ↓ x ≤ b ⇒ b − ↓ x ≥ 0.
