If a call-by-value strategy produces a finite evaluation tree, then a call-by-name strategy will also produce a finite tree. On the other hand, obtaining a finite tree using a call-by-name strategy does not imply that a finite tree will necessarily be produced using call-by-value. For example, the evaluation of the expression ((fun x ↦ 3) (e$_{foo}$ 2)) does not terminate using a call-by-value strategy (see section 3.3.2), whereas the value 3 is obtained using call-by-name:

```
(F'14) Env |- fun x -> 3 ~~ <x, 3, Env> (F1) (x, [(e_foo 2), Env]) ⊕ Env |- 3 ~~ 3
(F'16) -------------------------------------------------------------------------------
Env |- ((fun x -> 3) (e_foo 2)) ~~ 3
```

The two strategies also differ in their capacity to share evaluations of subexpressions. For example, using call-by-value, ((fun x ↦ x + x) e) is evaluated as follows:

```
(F15) Env |- e_f ~~ <x, x + x, Env> (R) ... ∇
(F17) -------------------------------------------------------------------------------
Env |- ((fun x -> x + x) e) ~~ v
       e_f
```

where ∇ is the tree:

```
(F11) Env_1 |- x ~~ v_e (F11) Env_1 |- x ~~ v_e
(F4) -------------------------------------------------------------------------------
       (x, v_e) ⊕ Env |- x + x ~~ v
       Env_1
```

Here, the value v is obtained by computing the value v_e of e of only once. Using a call-by-name mechanism, on the other hand, we obtain:

```
(F'14) ... (F11) ... ∇ ... (F11) ... ∇ ...
       Env |- e ~~ v_e   Env |- e ~~ v_e
(F4)   Env_1 |- x ~~ v_e   Env_1 |- x ~~ v_e
       -------------------------------------------------------------------------------
       (x, [e, Env]) ⊕ Env |- x + x ~~ v
       Env_1
(F'16) -------------------------------------------------------------------------------
Env |- ((fun x -> x + x) e) ~~ v
       e_f
```

The value v_e of e is computed twice to obtain the value v of the expression x + x. The call-by-need strategy is an implementation of the call-by-name strategy which attempts to maximize sharing of subexpressions, in order to evaluate the arguments of functions once only.
