

所使用的算法在很大程度上取决于语言所做的选择。不同的形式，例如运算符重载、函数和过程重载、常量重载和方法重载，可能会也可能不会被包含，彼此独立。重载解析方法可以非正式地描述如下。设 $exp$ 为包含重载标识符 $f$ 的表达式。为对该表达式进行类型化并从而确定使用哪个值的 $f$，我们必须：

- 1) 将一个类型变量与每个出现的 $f$ 关联，表示该标识符的可能类型之一；
- 2) 建立这些变量必须满足的方程组，使用语言的类型化规则。也可以使用其他信息，例如形式参数的名称（如果在传递实际参数时使用这些参数）；
- 3) 在此步骤结束时，每个类型变量都关联到至少一个类型；
- 4) 验证方程组只有一个解。为此，我们逐个将每个类型变量替换为其关联类型之一。如果没有解，则 $exp$ 类型错误。如果存在多个解，则存在歧义，$exp` 将被类型化过程拒绝。

请考虑以下示例，该示例使用一种伪语言编写，允许对函数和定义枚举类型的常量进行重载，即由一组明确命名且不可变的值定义的类型：

```
type color is (blue, green, red)
type light is (green, red)
function F(c:color):light = ...
function F(x:light):color = ...
```

设 F_a 为 F 的第一个声明，F_b 为第二个声明。设 green_C 和 red_C 为类型 color 的重载值，green_F 和 red_F 为类型 light 的重载值。表达式 F(blue) 显然是可类型化的，选择 F_a 作为 F，因为 blue 显然且明确地属于类型 color。另一方面，表达式 F(green) 和 F(F(green)) 明显存在歧义，因此将被拒绝。

该歧义在 F(F(green)) = F(blue) 中被消除：对该表达式进行类型化引导我们解决 F 和 green 的重载。为此，我们将表达式写成形式 F_1(F_2(green)) = F_3(blue)。设 $\tau_1 = \tau_{11} \rightarrow \tau_{12}$ 为 F_1 的类型，$\tau_2 = \tau_{21} \rightarrow \tau_{22}$ 为 F_2 的类型，$\tau_3 = \tau_{31} \rightarrow \tau_{32}$ 为 F_3 的类型，其中 $t_{ij}$ 表示类型变量。$\tau_1$ 的可能值为 light $\rightarrow$ color 和 color $\rightarrow$ light。由于 F_1 作用于 F_2 的结果，我们推导出方程 $\tau_{11} = \tau_{22}$。F_1 和 F_3 的结果必须具有相同的类型，从而得到方程 $\tau_{12} = \tau_{32}$。由于 F_3 作用于 blue，我们有 $\tau_{31} =$ color，因此 \(\tau_{32} = \text{light}\)，因此 \(\tau_{12} = \text{light}\) 和 \(\tau_{11} = \tau_{32} = \text{color}\)，从而 green 的类型为 light。然后，类型化算法在解析后分析表达式 F(F(green)) = F(blue)，将其视为 F_a(F_b(green)) = F_a(blue)。

重载解析中使用的规则在函数可能具有可变数量的参数、存在可选参数、以及语言包含允许与继承和子类化交互的方法重载的对象特性时可能更加复杂。Volume 2 的第 1 章和第 3 章简要介绍了重载，该主题也与 Volume 2 第 2 章和第 4 章中介绍的每种语言相关联。请注意，C 语言不允许重载。

重要的是要注意，虽然重载使编写程序变得更容易，但也可能使程序难以审查；用户必须对相关语义有深入了解，语义可能因语言而异。这一点将在 Volume 2 的第 3 章和第 4 章中进一步阐述。

## 数据类型

### 6.1. 基本类型

我们用来描述语义和类型化概念的语言 Exp2、...、Lang3 仅考虑两种数据类型：整数和布尔值。然而，大多数编程语言包含更多基本类型。在本节中，我们将介绍最普遍的数据类型，以及它们在语言之间的差异。

### 6.1.1. 布尔值

对于某些语言，例如 OCaml、Java、Ada 和 Pascal，布尔类型 bool 是类型代数的构造子，并具有两个可能的值：true 和 false。其他语言，例如 C 和 C++，将布尔值编码为整数，值 0 通常用于表示“false”，任何其他值都对应“true”。这些语言中的一些，例如 C++，包含类型 bool 和预定义标识符 false 和 true，但这些值与整数值完全兼容。任何整数表达式都可用作循环或 if-then-else 的条件。任何布尔表达式都可用作数组索引，或作为算术运算的操作数。这使得源文本更难以理解，并可能导致难以检测的错误。

Python 的行为有所不同。它提供两个值 True 和 False，但允许整数和布尔值混合。因此，可以测试整数值是否等于或不等于布尔值，或使用整数值作为条件的测试。不推荐这些做法，请参见以下示例。请记住，整数（例如示例 6.1 中的值 2）可能是对更复杂表达式求值的结果。如果将此值 2 用作布尔值导致执行错误，则可能难以在源代码中找到其来源。

### EXAMPLE 6.1.--

```
$ python3.7
>>> 0 == True
False
>>> 0 == False
True
>>> 1 == True
True
>>> 1 == False
False
>>> 2 == True
False
>>> 2 == False
False
```

示例 6.1 显示 Python 3.7 版本将 False 解释为值 0，将 True 解释为值 1。值得注意的是，值 2（或任何不是 0 或 1 的其他值）既不是 True 也不是 False。因此，示例 6.2 中的两个表达式（具有相同的直观语义）给出了不同的结果。

### EXAMPLE 6.2.--

```
>>> if 2 == True :
...     print ("2 == True")
... else :
...     print ("2 != True")
...
2 != True
>>> if 2 == False :
...     print ("2 != True")
... else :
...     print ("2 == True")
...
2 == True
```

由于测试 2 == True 和 2 == False 始终为 false，这两个表达式都计算 else 分支，显示出矛盾的结果。但是，如果直接将整数值 2 用作条件，则将计算 then 分支，仿佛 2 等效于 True。

### EXAMPLE 6.3.--

```
>>> if 2 :
...     print ("Then branch")
... else :
...     print ("Else branch")
...
Then branch
```

### 6.1.2. 整数

鉴于寄存器的有限大小，只能表示有限数量的二进制配置。由于每个整数都以二进制（基数 2）编码，寄存器只能编码有限数量的整数。

对于正整数，二进制配置中第 n 位表示值 2^n。由二进制配置编码的整数的值是其幂的和。例如，8 位上的配置 01100101 对应 2^6+2^5+2^2+2^0 = 101。

正整数和负整数通过使用符号位进行区分，符号位是整数二进制表示中最高有效位 (MSB)。此外，负整数使用补码编码。为了获得正数的相反数，我们反转绝对值二进制表示的位，然后在结果上加 1。因此，值 4 用 4 位表示为 0100，值 – 4 表示为 1100。这种编码保证了值 0 的唯一性，并提供了一条与操作数符号无关的加法指令。

### 6.1.2.1. 整数大小

到目前为止，我们只使用了一个整数类型 int，表示有符号整数。某些语言，例如 C、C++ 和 Java，包含多个整数类型：char、short、long、long long 和 int。它们在用于编码值的位数方面有所不同。在 Java 中，每个整数类型的位数明确指定；在 C 中，标准的连续版本仅指示每个整数类型的最小大小。C/C++ 中 int 的值通常以 32 位编码，long int 的值以 64 位编码，至少在当前架构中是如此。

| Java | 位 | C/C++ | 位 |
| :--- | :--- | :--- | :--- |
| byte | 8 | char | ≥ 8 |
| short | 16 | short (int) | ≥ 16 |
| int | 32 | int | ≥ 16 |
| long | 64 | long (int) | ≥ 32 |
| | | long long (int) | ≥ 64 |

在其他语言中，例如 OCaml 或 Python 3（Python 2 允许指定 long），无法指定整数大小，而是由语言标准设定。无论如何，用户都应牢记整数大小，以避免某些错误。
