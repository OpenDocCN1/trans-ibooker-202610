
If Env \vdash e \rightsquigarrow v has been obtained using rule F15 (respectively, F16), then e = fun x \mapsto e_f and v = \langle x, e_f, \text{Env} \rangle (respectively, e = rec f \ x = e_f and v = \langle f, x, e_f, \text{Env} \rangle) and since F15 (respectively, F16) is the only applicable rule for evaluating a function (respectively, a recursive function), then v = v'.

If Env \vdash e \rightsquigarrow v has been obtained using rule F17 (respectively, F18), then e = (e_1 e_2) and:

Env \vdash e_1 \rightsquigarrow \langle x, e_f, \text{Env}_f \rangle (respectively, Env \vdash e_1 \rightsquigarrow \langle f, x, e_f, \text{Env}_f \rangle)

Env \vdash e_2 \rightsquigarrow v_2

(x, v_2) \oplus \text{Env}_f \vdash e_f \rightsquigarrow v (respectively, (f, \langle f, x, e_f, \text{Env}_f \rangle) \oplus (x, v_2) \oplus \text{Env}_f \vdash e_f \rightsquigarrow v)

By induction hypothesis, if:

Env \vdash e_1 \rightsquigarrow v'_1 \text{ then } v'_1 = \langle x, e_f, \text{Env}_f \rangle (respectively v'_1 = \langle f, x, e_f, \text{Env}_f \rangle)

and if:

Env \vdash e_2 \rightsquigarrow v'_2 \text{ then } v'_2 = v_2

Hence:

(x, v'_2) \oplus \text{Env}_f = (x, v_2) \oplus \text{Env}_f

(respectively (f, v'_1) \oplus (x, v'_2) \oplus \text{Env}_f = (f, \langle f, x, e_f, \text{Env}_f \rangle) \oplus (x, v_2) \oplus \text{Env}_f)

The only applicable rule is F17 (respectively, F18) and, by induction hypothesis, since:

(x, v_2) \oplus \text{Env}_f \vdash e_f \rightsquigarrow v

(respectively, (f, \langle f, x, e_f, \text{Env}_f \rangle) \oplus (x, v_2) \oplus \text{Env}_f \vdash e_f \rightsquigarrow v)

we obtain v = v'.

If Env \vdash e \rightsquigarrow v has been obtained using rule F19, then e = (e_1 e_2), Env \vdash e_1 \rightsquigarrow v_1, Env \vdash e_2 \rightsquigarrow v_2, v_1 \in \text{IF}, v_2 \in \text{IE} and v = v_2. By induction hypothesis, if Env \vdash e_1 \rightsquigarrow v'_1, then v'_1 = v_1 \in \text{IF} and if Env \vdash e_2 \rightsquigarrow v'_2, then v'_2 = v_2 \in \text{IE}. Rule F19 is the only applicable rule for evaluating e and we obtain v' = v'_2 = v_2 = v.

If Env \vdash e \rightsquigarrow v has been obtained using rule F20, then e = (e_1 e_2), Env \vdash e_1 \rightsquigarrow v_1, v_1 \notin \text{IF} and v = \text{Err}_T. By induction hypothesis, if Env \vdash e_1 \rightsquigarrow v'_1, then v'_1 = v_1 \notin \text{IF}. Rule F20 is the only applicable rule for evaluating e and we obtain v' = v.

The proposition below establishes an equivalence between the semantics defined by the evaluation function [[\_]] and the operational semantics with call-by-value defined in Box 3.2 and Box 3.3.

## PROPOSITION 3.2. Equivalence:

∀e ∈ **Exp₂** ∀Env ∈ **E** ∀v ∈ V [[e]]_Env = v ⇔ Env ⊢ e ↝ v

The implication ⇒ can be proved using the LFP theory but it is out of the scope of this book. The proof of the implication ⇐ is obtained using the same technique applied for proposition 3.1, by induction over the evaluation tree for Env ⊢ e ↝ v. For each rule:

```
(Fᵢ) Env₁ ⊢ e₁ ↝ v₁ ... Envₙ ⊢ eₙ ↝ vₙ
--------------------------------------
Env ⊢ e ↝ v
```

of the inference system S_**Exp₂**, which defines the big-step operational semantics of expressions in **Exp₂**, we must prove that [[e]]_Env = v, under the induction hypothesis that [[e₁]]_Env₁ = v₁, etc., [[eₙ]]_Envₙ = vₙ. This proof is immediate, as the rules for evaluating the operational semantics were defined following exactly the same choices used to define the evaluation function.

## 3.5. Semantic properties

The usual techniques used to prove semantic properties over expressions in a programming language are presented as follows.

### 3.5.1. Equivalent expressions

### DEFINITION 3.3. Equivalent expressions:

two expressions are equivalent if and only if, in each environment, their evaluations return the same value:

∀e₁, e₂ ∈ **Exp₂** e₁ ≡ e₂ ⇔ (∀Env ∈ **E** [[e₁]]_Env = [[e₂]]_Env) [3.8]

In this definition, we used the evaluation function [[__]]_ for the evaluation of the expressions. The relation ↝ for evaluating big-step operational semantics can also be used to define the notion of equivalent expressions:

∀e₁, e₂ ∈ **Exp₂**
e₁ ≡ e₂ ⇔ (∀Env ∈ **E** ∀v ∈ V Env ⊢ e₁ ↝ v ⇔ Env ⊢ e₂ ↝ v) [3.9]

Using this second definition, proving that e₁ ≡ e₂ amounts to proving how the evaluation tree for Env ⊢ e₂ ↝ v can be obtained from the tree for Env ⊢ e₁ ↝ v and vice versa. Following proposition 3.2, these two approaches are equivalent. We can easily prove that ≡ defines a congruence, i.e. an equivalence relation compatible with the internal composition laws of **Exp₂**. For example, if e₁ ≡ e₂ and e'₁ ≡ e'₂, then (e₁ + e'₁) ≡ (e₂ + e'₂).

### 3.5.2. Equivalent environments

As we said informally in section 3.1.4, the result of evaluating an expression \( e \) in an environment ENV depends only on the values associated with the free variables of \( e \) by ENV. In other terms, the evaluation result of \( e \) is the same in all environments, which associate the same values with the free variables of \( e \). Giving a formal definition of this property requires the introduction of the notion of equivalent environments over a set of variables as follows:

### DEFINITION 3.4. Equivalent environments:

let \( F \subseteq \mathbf{X} \) be a set of variables and ENV\(_1\) and ENV\(_2\) two environments:

ENV\(_1 \equiv_F\) ENV\(_2 \Leftrightarrow \forall x \in F \, \) ENV\(_1(x) = \) ENV\(_2(x)\)

Obviously, given two subsets of \(\mathbf{X}\), \( F_1 \) and \( F_2 \), if \( F_1 \subseteq F_2 \) and ENV\(_1 \equiv_{F_2}\) ENV\(_2\), then ENV\(_1 \equiv_{F_1}\) ENV\(_2\). It is now possible to express, formally, that for any expression \( e \), the value of [[e]]_{\text{Env}} depends only on the values bound in ENV to the free variables of \( e \) (\( \mathcal{F}(e) \)).

### PROPOSITION 3.3.

For any expression \( e \in \mathbf{Exp}_2 \):

\(\forall \text{ENV}_1, \text{ENV}_2 \in \mathbf{E}\)
ENV\(_1 \equiv_{\mathcal{F}(e)}\) ENV\(_2\)
\(\Rightarrow\)
\(\left( \begin{aligned} [[e]]_{\text{ENV}_1} = [[e]]_{\text{ENV}_2} \\ \text{or} [[e]]_{\text{ENV}_1} = \langle x, e', \text{ENV}'_1 \rangle \text{ and } [[e]]_{\text{ENV}_2} = \langle x, e', \text{ENV}'_2 \rangle \\ \text{and } \text{ENV}'_1 \equiv_{\mathcal{F}(e)\backslash \{x\}} \text{ENV}'_2 \\ \text{or} [[e]]_{\text{ENV}_1} = \langle f, x, e', \text{ENV}'_1 \rangle \text{ and } [[e]]_{\text{ENV}_2} = \langle f, x, e', \text{ENV}'_2 \rangle \\ \text{and } \text{ENV}'_1 \equiv_{\mathcal{F}(e)\backslash \{x\}} \text{ENV}'_2 \end{aligned} \right)\)

The proof of this proposition is long and complex. Exercise 3.5 establishes this property for a language containing no functional expressions. In this case, proof is obtained by induction over the syntactic structure of the expression. In cases where functional values are present, this induction is no longer sufficient, and the proof requires the use of theorems of the fixpoint theory.
