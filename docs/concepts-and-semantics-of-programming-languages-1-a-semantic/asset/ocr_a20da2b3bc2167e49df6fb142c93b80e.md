But, by definition, Mem[Env(y) := n - m] <Env Mem, and by induction hypothesis, we obtain the tree V2 :

```
::
(Ci) <Mem[Env(y) := n - m], cw> →Env Mem'
```

b) if m > n, then we can build the tree V1 :

```
[[e]]MemEnv = (false, Mem) (C1) [[↓x - ↓y]]EnvMem = (m - n, Mem)
(C5) <Mem, c2> →Env Mem[Env(x) := m - n]
-------------------------------------------
<Mem, cw> →Env Mem[Env(x) := m - n]
```

Once again, we obtain Mem[Env(x) := m - n] <Env Mem, and using the induction hypothesis, we obtain the tree V2 :

```
::
(Cj) <Mem[Env(x) := m - n], cw> →Env Mem'
```

In all cases, we get the result since we can construct the following tree:

```
[[ew]]MemEnv = (true, Mem) V1 V2
(C6) -----------------------------------
<Mem, c> →Env Mem'
```

This proof is typically used to show that a program terminates: first, a well-founded order must be built (a point which is not always immediately obvious), then the proof can be done by well-founded induction.

# 4.5.3. Determinism of program execution

To ensure that the same program executed from the same state will always produce the same result, we prove that the execution of instructions is deterministic.

PROPOSITION 4.1. – Determinism of instruction execution:

```
∀ c ∈ Lang3 ∀ Env ∈ E ∀ Mem, Mem1, Mem2 ∈ M
(<Mem, c> →Env Mem1 and <Mem, c> →Env Mem2) ⇒ Mem1 = Mem2
```

We first attempt to prove this proposition by induction over the program structure. For the program while e do c, by induction hypothesis, we may suppose that the property is verified for c. Using the following two trees

```
(V1) (Cj) :: ... (V2) (Cj') :: ...
```

we therefore obtain Mem1 = Mem'1.
