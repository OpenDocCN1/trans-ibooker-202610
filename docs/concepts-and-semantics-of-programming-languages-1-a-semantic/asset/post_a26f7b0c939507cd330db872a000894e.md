## Box 4.7. Denotational semantics

The definition of $[[c]]_{\text{Env}}$ is given in Box 4.7. The assignment instruction $x := e$ is associated with the function that transforms a memory state by storing the result of evaluating the expression $e$ (if this does not raise an error) at the location denoted by $x$ (if $x$ denotes a reference). The function associated with the instruction $\mathbf{skip}$ is the identity function. For the sequence $c_1 ; c_2$, we compose the two functions associated with $c_1$ and $c_2$; moreover, if one of these is applied to a state for which it is undefined, then the result of applying the composition is also undefined. The function associated with if $e$ then $c_1$ else $c_2$ uses the function $\mathbf{cond}(f_b, f_1, f_2)$ which, given a memory state, selects which function to apply to this state ($f_1$ or $f_2$) according to the result of the boolean function ($f_b$) in this state. Finally, consider the instruction $\mathbf{while}\ e\ \mathbf{do}\ c$. Using the big-step operational semantics formalism, it is easy to show (see exercise 4.1) that:

\(\mathbf{while}\ e\ \mathbf{do}\ c \equiv \text{if } e \text{ then } (c; \mathbf{while}\ e\ \mathbf{do}\ c) \text{ else skip}\)

and thus, using the definitions given above, the function associated with the loop while e do c could be:

\([[\mathbf{while}\ e\ \mathbf{do}\ c]]_{\text{Env}} = \mathbf{cond}([[e]]_{\text{Env}}, [[\mathbf{while}\ e\ \mathbf{do}\ c]]_{\text{Env}} \circ [[c]]_{\text{Env}}, id)\)

However, such a definition using $[[\mathbf{while}\ e\ \mathbf{do}\ c]]_{\text{Env}}$ is not compositional. One solution to this problem is to abstract the function $[[\mathbf{while}\ e\ \mathbf{do}\ c]]_{\text{Env}}$ to get the function:

\(F : f \mapsto \mathbf{cond}([[e]]_{\text{Env}}, f \circ [[c]]_{\text{Env}}, id)\)

This function $F$ is known as a functional as its argument is itself a function. Its body uses only components of $\mathbf{while}\ e\ \mathbf{do}\ c$, $F$ is therefore compositional. Furthermore, it verifies:

\(F([[ \mathbf{while}\ e\ \mathbf{do}\ c ]]_{\text{Env}}) = [[ \mathbf{while}\ e\ \mathbf{do}\ c ]]_{\text{Env}}\)

In other words, $[[\mathbf{while}\ e\ \mathbf{do}\ c]]_{\text{Env}}$ is a fixpoint of $F$. To adopt such an approach, we must establish the existence of at least one fixpoint for $F$ and, when several fixpoints exist, determine which to use.

For example, consider the program $\mathbf{while}\ \downarrow x = 0\ \mathbf{do}\ \mathbf{skip}$, which may be associated with the functional $F : f \mapsto \mathbf{cond}((\downarrow x = 0)_{\text{Env}}, f, id)$ as $[[\mathbf{skip}]]_{\text{Env}} = id$ and $f \circ id = f$. According to the definition of $\mathbf{cond}$, we therefore have:

\(F : f \mapsto \left( \text{Mem} \mapsto \begin{cases} f(\text{Mem}) & \text{if } \text{Mem}(\text{Env}(x)) = 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{Mem} & \text{if } \text{Mem}(\text{Env}(x)) \neq 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{undef} & \text{else} \end{cases} \right)\)

Given a function $h : \mathbf{M} \rightarrow \mathbf{M}$, we define the following function $g_h : \mathbf{M} \rightarrow \mathbf{M}$:

\(g_h : \text{Mem} \mapsto \begin{cases} h(\text{Mem}) & \text{if } \text{Mem}(\text{Env}(x)) = 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{Mem} & \text{if } \text{Mem}(\text{Env}(x)) \neq 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{undef} & \text{else} \end{cases}\)

According to the definition of $F$, we therefore have:

$$
F(g_h) : \text{Mem} \mapsto \left\{\begin{array}{ll} g_h(\text{Mem}) & \text{if } \text{Mem}(\text{Env}(x)) = 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{Mem} & \text{if } \text{Mem}(\text{Env}(x)) \neq 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{undef} & \text{else} \end{array}\right.
$$

and from the definition of $g_h$ we obtain:

$$
F(g_h) : \text{Mem} \mapsto \left\{\begin{array}{ll} h(\text{Mem}) & \text{if } \text{Mem}(\text{Env}(x)) = 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{Mem} & \text{if } \text{Mem}(\text{Env}(x)) \neq 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{undef} & \text{else} \end{array}\right.
$$

Hence $F(g_h) = g_h$ and so for every function $h : \mathbf{M} \nrightarrow \mathbf{M}$, $g_h$ is a fixpoint of $F$. This example shows that there exist several fixpoints of the functional $F$.

We now need to determine which of these fixpoints characterize exactly the same states as the operational semantics (see property [4.13]). For a memory state Mem such that $\text{Mem}(\text{Env}(x)) = 2$, the body of the loop is not executed, and the memory is not modified. For a memory state Mem such that $\text{Mem}(\text{Env}(x)) = 0$, the body of the loop is executed an infinite number of times and the program does not terminate, so we wish that $[[\text{while } \downarrow x = 0 \text{ do skip}]]_{\text{Env}}(\text{Mem}) = \text{undef}$. From the function $k : \text{Mem} \mapsto \text{undef}$, we define $g_k$ :

$$
g_k : \text{Mem} \mapsto \left\{\begin{array}{ll} \text{Mem} & \text{if } \text{Mem}(\text{Env}(x)) \neq 0 \text{ and } \text{Env}(x) \in \mathbf{R} \\ \text{undef} & \text{else} \end{array}\right.
$$

We see that $g_k$ is a fixpoint of $F$, and this is the fixpoint that we wish to associate to $[[\text{while } \downarrow x = 0 \text{ do skip}]]_{\text{Env}}$.

For any other fixpoint $g_h$ in $F$, if $g_k(\text{Mem}) \neq \text{undef}$, then $g_k(\text{Mem}) = g_h(\text{Mem})$. As we will see, by defining a partial order relation over partial functions from $\mathbf{M}$ to $\mathbf{M}$, this fixpoint corresponds to the least fixpoint of the functional $F$, denoted as $\text{lfp}(F)$. The proofs of the existence and uniqueness of this fixpoint, along with a procedure used to compute it, are presented in the following.
