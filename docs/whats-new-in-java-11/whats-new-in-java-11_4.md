## Performance and Security

开发人员通常会寻找新 Java 版本中那些直接影响并改善日常工作流程的闪亮、便捷功能。另一方面，非功能性方面如性能和安全，在你将项目发布到生产环境后变得极其重要。运行缓慢的应用程序不会赢得客户。运行时环境中的安全漏洞会导致用户信任度下降。Java 11 在这方面也能提供支持。首先，我们来看性能改进。

## Garbage Collection

垃圾收集是 Java 的内置功能，负责对象的创建和销毁。让我们首先回顾一下对默认垃圾收集器的改进。稍后，我们将分析本次发布中添加的新实验性垃圾收集器。

### IMPROVEMENTS TO THE DEFAULT G1 COLLECTOR

Java 7 引入了 Garbage-First (G1) 收集器。它后来在 Java 9 中成为默认垃圾收集器。G1 针对高概率和吞吐量进行了优化。正如 Thomas Schatzl 所提到的，Java 11 在 x64 处理器上将暂停时间提高了高达 60%，同时内存占用大幅减少。对于准备将 Java 11 升级到生产系统的人来说，这是一个巨大的提升。

此外，本次 Java 发布引入了两个实验性垃圾收集器。让我们看看它们能带来什么。我们从 ZGC 开始。

### ZGC: A SCALABLE, LOW-LATENCY GARBAGE COLLECTOR

垃圾收集是 Java 的一项引人注目的功能。作为开发人员，你无需在不再使用对象后手动标记对象以便移除。垃圾收集器会在幕后处理此事。你可能会遇到的问题之一是垃圾收集启动时的暂停时间。这会导致糟糕的客户体验，因为用户必须等待应用程序响应。对于致力于响应性、高吞吐量和可用性并具有约定服务级别的任务关键型应用程序来说，等待时间更是致命的。

Z 垃圾收集器（ZGC）是一个可扩展、低延迟的垃圾收集器。这在实际中意味着什么？尽管 ZGC 并未完全消除暂停时间，但它保证了最大暂停时间为 10 毫秒。此外，它可以处理从小到大的堆（数 TB 级）。另一个值得提及的重要优化是，使用 ZGC 时，暂停时间不会随堆大小增加。这些条件使得 ZGC 非常适合处理大量数据、对内存需求高的应用程序。

你想尝试使用 ZGC 运行 Java 程序吗？你可以通过提供 VM 选项 -XX:+UnlockExperimentalVMOptions -XX:+UseZGC 来启用该垃圾收集器。ZGC 已被标记为实验性，因此将其用于生产系统时需谨慎。更多信息，请参阅 ZGC 文档页面。

Java 11 添加了另一个实验性垃圾收集器：Epsilon。在下一节中，我们将简要介绍其用例和性能标准。

## 无操作垃圾收集器：EPSILON

Java 11 中可用的第二个实验性垃圾收集器称为 Epsilon 垃圾收集器。Epsilon 是一个低开销的垃圾收集器，也被称为无操作（no-op）垃圾收集器。你可能已经猜到这意味着什么。它不会在空间分配后回收内存。

虽然这种行为乍一听有些奇怪，但在某些用例中应用 Epsilon 确实是有意义的。例如，短生命周期程序，如只执行单个命令然后关闭 JVM 的命令行应用程序，或者希望进行程序性能测试的场景。

要为程序启用 Epsilon，请使用 VM 选项 -XX:+UnlockExperimentalVMOptions -XX:+UseEpsilonGC。更多信息，请参见增强提案文档 JEP 318。

## TLS 1.3 与加密算法支持

安全性对于任何软件系统都至关重要。随着 2018 年 8 月发布的最新传输层安全性（TLS）版本，HTTPS 性能变得比以往更快、更安全。Java 11 能够立即纳入对 TLS 1.3 协议的支持

## Oracle JDK 和 OpenJDK 在功能上趋同

主要区别在于，Oracle JDK 要求用户为生产环境购买许可证。Java 现在采用六个月的主要版本发布周期。此外，每个主要版本之间会有两个补丁版本，用于修复严重错误。Java 11 是一个 LTS 版本。Oracle JDK 的付费客户将获得额外的次要版本和补丁版本。OpenJDK 继续作为免费的开源发行版提供。

## 最新功能和 API 增强

Java 11 中最大的功能可能是 HTTP 客户端实现，这是一种适用于现代应用程序开发的 HTTP 通信 API。我们探讨了无需编译代码即可运行单文件 Java 程序的能力。如果你想快速尝试 Java 代码片段以进行原型设计，此功能非常有用。Java 团队向标准模块添加了便捷方法。因此，开发人员可以不再依赖实现类似辅助方法的外部库。Java 11 还采用了 Unicode 10、基于嵌套的访问控制以及开源分析工具 Java Flight Recorder 和 Java Mission Control。

## 已移除的 API 和弃用项

Java 11 中有许多被移除的 API 和 Java EE 模块，当你从较早的 Java 版本升级项目时，这会产生很大影响。但还有其他外部库选项可以替代它们。期待已久，但随着 Java 11 的到来，Applet 和 Java Web Start 终于被移除了。将 JavaFX 从 JDK 中解耦将有助于确保 Java 的一致性和定期发布。许多功能也已被标记为在将来的版本中移除。

## 性能与安全

Java 11 使默认垃圾收集器更加高效，并引入了两个新的实验性垃圾收集器：ZGC（适用于内存密集型应用程序）和 Epsilon（面向可预测的短期内存占用程序）。Java 11 支持最新版本的传输层安全性协议 TLS 1.3，使 HTTPS 通信比以往更快、更安全。虽然整合可能需要一些工作，但我认为 Java 11 中的新功能、更改和优化是值得付出努力的，因为它们促进了更高效的编程风格，并在生产中提供了改进的性能和安全性。
