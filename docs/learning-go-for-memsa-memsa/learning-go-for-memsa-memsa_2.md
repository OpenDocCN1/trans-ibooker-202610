# Chapter 1. Predeclared Types and Declarations

现在你已经设置好了开发环境，是时候开始了解 Go 的语言特性和如何最好地使用它们了。试图弄清楚“最好”意味着什么时，有一个 overriding 原则：以使你的意图清晰的方式编写程序。在我介绍特性并讨论选项时，我会解释为什么我认为某种方法能产生更清晰的代码。

我将首先查看 Go 内置的类型以及如何声明这些类型的变量。虽然每个程序员都对这些概念有经验，但 Go 在某些方面做得不同，并且 Go 与其他语言之间存在细微差异。

## The Predeclared Types





Go 语言内置了许多类型。这些被称为 *预声明* 类型。它们类似于其他语言中常见的类型：布尔值、整数、浮点数和字符串。对于从其他语言转过来的开发者来说，以惯用的方式使用这些类型有时会是一个挑战。你将查看这些类型并了解它们在 Go 中如何最好地工作。在我回顾这些类型之前，让我们先介绍一些适用于所有类型的概念。

## 零值

Go 与大多数现代语言一样，会为声明但未赋值的任何变量分配默认的 *零值*。显式的零值使代码更清晰，并消除了在 C 和 C++ 程序中发现的错误来源。在我讨论每种类型时，我也会介绍该类型的零值。你可以在 [《Go 编程语言规范》](https://oreil.ly/3d3e6) 中找到有关零值的详细信息。

## 字面量

Go 的 *字面量* 是显式指定的数字、字符或字符串。Go 程序有四种常见的字面量类型。 [我将在讨论复数时介绍一种罕见的第五种字面量。]

一个 *整数字面量* 是数字序列。整数字面量默认为十进制，但使用不同的前缀来表示其他进制：`0b` 表示二进制（基数 2），`0o` 表示八进制（基数 8），或 `0x` 表示十六进制（基数 16）。前缀可以使用大写或小写字母。前面带 `0` 且后面没有字母的写法是表示八进制字面量的另一种方式。不要使用它，因为它非常令人困惑。

为了更轻松地阅读较长的整数字面量，Go 允许你在字面量中间放置下划线。这使你能够例如在十进制中按千位分组（`1_234`）。这些下划线对数字的值没有影响。下划线的唯一限制是它们不能出现在数字的开头或结尾，并且不能彼此相邻。你可以在字面量的每个数字之间放置下划线（`1_2_3_4`），但不要这样做。利用它们来提高可读性，通过在十进制数字的千位处断开，或在 1、2 或 4 字节边界处断开二进制、八进制或十六进制数字。

一个 *浮点字面量* 具有小数点以指示值的分数部分。它们也可以使用字母 `e` 和正负数指定指数（例如 `6.03e23`）。你也可以选择使用 `0x` 前缀和字母 `p` 表示指数的方式以十六进制书写它们（`0x12.34p5`，等于十进制的 `582.5`）。与整数字面量一样，你可以使用下划线来格式化浮点字面量。

一个 *符文字面量* 表示一个字符，并用单引号包围。与许多其他语言不同，在 Go 中单引号和双引号 *不可* 互换。符文字面量可以写成单个 Unicode 字符（`'a'`）、8 位八进制数（`'\141'`）、8 位十六进制数（`'\x61'`）、16 位十六进制数（`'\u0061'`）或 32 位 Unicode 数（`'\U00000061'`）。还有几个反斜杠转义的符文字面量，其中最有用的有换行（`'\n'`）、制表符（`'\t'`）、单引号（`'\''`）和反斜杠（`'\\'`）。

从实际角度来说，使用十进制来表示整数和浮点字面量。八进制表示很少见，主要用于表示 POSIX 权限标志值（例如 `0o777` 表示 rwxrwxrwx）。十六进制和二进制有时用于位过滤器或网络和基础设施应用。避免使用符文字面量的任何数字转义，除非上下文使你的代码更清晰。

表示 *字符串字面量* 有两种方式。大多数时候，你应该使用双引号创建 *解释型字符串字面量*（例如，键入 `"Greetings and` `Salutations"`）。它们包含零个或多个符文字面量。它们被称为“解释型”，因为它们将符文字面量（数字和反斜杠转义）解释为单个字符。

#### Note

一个符文字面量反斜杠转义在字符串字面量中是非法的：单引号转义。它被双引号的反斜杠转义所取代。

在解释型字符串字面量中不能出现的唯一字符是未转义的反斜杠、未转义的换行符和未转义的双引号。如果你使用解释型字符串字面量并且希望你的问候与致敬在不同行，并且希望“Salutations”出现在引号中，你需要键入 `"Greetings and\n\"Salutations\""`.

如果需要在字符串中包含反斜杠、双引号或换行符，使用 *原始字符串字面量* 更容易。这些字面量用反引号（`` ` ``）分隔，可以包含除反引号之外的任何字符。原始字符串字面量中没有转义字符；所有字符都按原样包含。使用原始字符串字面量时，你可以这样写多行问候语：

```
`Greetings and
"Salutations"`
```

字面量被视为 *无类型*。我将在 “字面量是无类型的” 中更深入地探讨这一概念。正如你在 “var 与 :=” 中所看到的，Go 中存在类型未显式声明的情况。在这些情况下，Go 使用字面量的 *默认类型*；如果表达式中没有任何内容使字面量的类型明确，字面量将默认为一种类型。我将在讨论不同的预声明类型时提及字面量的默认类型。

## 布尔值

`bool` 类型表示布尔变量。`bool` 类型的变量可以有两个值之一：`true` 或 `false`。`bool` 的零值是 `false`：

```
var flag bool // no value assigned, set to false
var isAwesome = true
```

很难在不展示变量声明的情况下谈论变量类型，反之亦然。我将首先使用变量声明，并在 “var 与 :=” 中描述它们。

## 数值类型

Go 有大量数值类型：12 种类型（以及一些特殊名称）分为三类。如果你来自像 JavaScript 这样只用单一数值类型就能应付的语言，这可能会显得很多。事实上，有些类型使用频繁，而其他类型则更偏门。我将先从整数类型开始，然后再介绍浮点类型和非常不寻常的复数类型。

### 整数类型

Go 提供从一到八字节的各种大小的有符号和无符号整数。它们在 表 1-1 中显示。

表 1-1. Go 中的整数类型

| Type name || Value range |

| --- | --- |

| `int` || platform dependent |

| --- | --- |

| `int8` || –128 to 127 |

| `int16` || –32768 to 32767 |

| `int32` || –2147483648 to 2147483647 |

| `int64` || –9223372036854775808 to 9223372036854775807 |

| `uint` || platform dependent |

| `uint8` || 0 to 255 |

| `uint16` || 0 to 65535 |

| `uint32` || 0 to 4294967295 |

| `uint64` || 0 to 18446744073709551615 |

可能从名称就能看出来，所有整数类型的零值都是 `0`。

### 特殊的整数类型

Go 确实有一些整数类型的特殊名称。`byte` 是 `uint8` 的别名；`byte` 与 `uint8` 之间可以合法地进行赋值、比较或数学运算。然而，你很少在 Go 代码中看到 `uint8` 的使用；只需称之为 `byte` 即可。

第二个特殊名称是 `int`。在 32 位 CPU 上，`int` 是 32 位有符号整数，如同 `int32`。在 64 位 CPU 上，`int` 是 64 位有符号整数，就像 `int64`。由于 `int` 在不同平台上不一致，因此在没有类型转换的情况下，将 `int` 与 `int32` 或 `int64` 进行赋值、比较或数学运算是编译时错误（有关更多详细信息，请参阅 “显式类型转换”）。整数字面量默认为 `int` 类型。

第三个特殊名称是 `uint`。它遵循与 `int` 相同的规则，只是它是无符号的（值始终为 0 或正数）。





除了 `rune` 和 `uintptr` 这两种整数类型的特殊名称外。你之前看过 `rune` 字面量，我将在 “品尝字符串和字符” 中讨论 `rune` 类型，并在第 16 章中讨论 `uintptr`。

### 选择使用哪种整数

Go 提供的整数类型比某些其他语言更多。面对这么多选择，你可能会想知道何时使用每一种。你应遵循三条简单规则：

* 默认情况下，使用 `int`。
* 如果你正在处理具有特定大小或符号的整数的二进制文件格式或网络协议，请使用相应的整数类型。
* 如果你正在编写应适用于任何整数类型的库函数，请利用 Go 的泛型支持，并使用泛型类型参数来表示任何整数类型（我在第 5 章中更详细地讨论函数及其参数，并在第 8 章中更详细地讨论泛型。）

#### Note

你可能会发现遗留代码中有一对执行相同功能的函数，但一个使用 `int64` 作为参数和变量，另一个使用 `uint64`。原因是该 API 在 Go 添加泛型之前创建。在没有泛型的情况下，你需要编写名称略有不同的函数，以使用不同类型实现相同的算法。使用 `int64` 和 `uint64` 意味着你可以编写一次代码，让调用者使用类型转换来传递值并转换返回的数据。

你可以在 Go 标准库的 `strconv` 包中的 `FormatInt` 和 `FormatUint` 函数中看到这种模式。由于兼容性承诺，这些函数永远不会消失，但它们实现了过时的风格。

### 整数运算符

Go 整数支持通常的算术运算符：`+`、`-`、`*`、 `/`，以及 `%` 用于取模。整数除法的结果是整数；如果你想得到浮点结果，你需要使用类型转换将整数转换为浮点数。另外，请注意不要用 0 除整数；这会导致 panic（我在 Panic Recover 部分更详细地讨论 panic）。

#### Note

Go 中的整数除法遵循向零截断。取模遵循相同的规则；`-7 % 2 == -1`。请参阅 Go 规范中关于 [算术运算符](https://oreil.ly/zp3OJ) 的部分以了解完整细节。

你可以将任何算术运算符与 `=` 结合来修改变量：`+=`、`-=`、`*=`、 `/=` 和 `%=`。例如，以下代码使 `x` 的值为 20：

```
var x int = 10
x *= 2
```

Go 还包括 `++` 和 `--` 运算符来递增和递减变量的值。与 Java、C++ 和其他几种语言不同，Go 要求这些运算符出现在变量之后。

```
var x int = 10
x ++ // ok
++x  // syntax error, does not compile
```

你可以使用 `==`、`!=`、`>`、`>=`、`<` 和 `<=` 比较整数。有三个一元整数运算符：`+`、`-` 和 `^`。前两个使数字为正或负，而第三个对整数执行按位 NOT。

Go 还为整数提供了位操作运算符。你可以使用 `<<` 和 `>>` 进行左移和右移，或使用 `&`（按位 AND）、 `|`（按位 OR）、 `^`（按位 XOR）和 `&^`（按位 AND NOT）进行位掩码。与算术运算符一样，你也可以将所有位运算符与 `=` 结合来修改变量：`&=`、`|=`、`^=`、`&^=`、`<<=` 和 `>>=`。

## 整数溢出

与许多其他语言一样，Go 允许你将整数变量递增和递减超出其限制。对设置为类型的最大值变量加一会返回该类型的最小值，从最小值减一会返回最大值。在编写代码时要小心；不要假设 `x + 1` 总是大于 `x` 且 `x - 1` 总是小于 `x`。

```
var x uint = 0
x--
fmt.Println(x) // prints 18446744073709551615
x++
fmt.Println(x) // prints 0
```

### 浮点类型

Go 有两种浮点类型，如 表 1-2 所示。

表 1-2. Go 中的浮点类型

| 类型名称 | 最大绝对值 | 最小（非零）绝对值 |
| --- | --- | --- |
| `float32` | 3.40282346638528859811704183484516925440e+38 | 1.401298464324817070923729583289916131280e-45 |
| `float64` | 1.797693134862315708145274237317043567981e+308 | 4.940656458412465441765687928682213723651e-324 |

与整数类型一样，浮点类型的零值为 0。

Go 中的浮点与其它语言中的浮点数学类似。Go 使用 IEEE 754 规范，提供大范围和有限精度。选择使用哪种浮点类型很简单：除非你必须与现有格式兼容，否则使用 `float64`。浮点字面量的默认类型为 `float64`，因此始终使用 `float64` 是最简单的选择。它还有助于缓解浮点精度问题，因为 `float32` 只有六到七位十进制精度的精度。除非你使用分析器确定它是问题的重要来源，否则不必担心内存大小的差异。（测试和分析在 第 2 章 中介绍。）

更大的问题是你是否应该使用浮点数。在许多情况下，答案是否定的。就像其他语言一样，Go 浮点数具有巨大的范围，但它们不能存储该范围内的每个值；它们存储最接近的近似值。因为浮点数不精确，所以它们只能用于不精确值可接受或浮点规则被很好理解的情况。这将它们限制在图形、统计和科学运算等事物中。一些早于泛型的函数使用 `float64` 参数作为为所有浮点和整数类型提供单一实现的方式，例如标准库 `math` 包中的 `Min` 和 `Max` 函数。这是过时的模式（并且对于超出 -2⁵³ 到 2⁵³ 范围的 64 位整数无法正确工作）。

#### Warning

浮点数无法精确表示十进制值。不要用它们来表示货币或任何必须具有精确十进制表示的值！在第 10 章中，你将学习如何使用第三方 `shopspring/decimal` 模块来处理精确的十进制值。

你可以使用所有标准的数学和比较运算符与浮点数一起使用，除了 `%`。浮点除法有一些有趣的特性。将非零浮点变量除以 0 会返回 `+Inf` 或 `-Inf`（正或负无穷大），取决于数字的符号。将设置为 0 的浮点变量除以 0 会返回 `NaN`（非数字）。

虽然 Go 允许你使用 `==` 和 `!=` 比较浮点数，但不要这样做。因为浮点数的非精确性，两个浮点值可能在你认为应该相等时并不相等。相反，定义一个最大允许差异，并查看两个浮点数的差是否小于该值。此值（有时称为 *epsilon*）取决于你的精度需求；我无法给出简单的规则。如果你不确定，请咨询你友好的本地数学家寻求建议。如果你找不到，[The Floating Point Guide has a “Comparison” page](https://oreil.ly/n9ws3) 可以帮助你（或可能说服你在绝对必要时避免浮点数）。另一个陷阱是，根据定义，`NaN` 不等于任何东西，包括它本身。你可以在 [The Go Playground](https://go.dev/play/p/LK8aj87-vSI) 上看到此演示。如果浮点变量可能为 `NaN`，请使用函数 `math.IsNaN()` 来测试它。

### 复杂类型（你可能不会用到这些）





还有一种数值类型，它相当不寻常。Go 对复数提供了第一类支持。如果你不知道复数是什么，你就不是这个特性的目标用户；请随意跳过。

Go 中复数支持的内容并不多。Go 定义了两种复数类型。`complex64` 使用 `float32` 值来表示实部和虚部，而 `complex128` 使用 `float64` 值。两者都使用 `complex` 内置函数声明：

```
var complexNum = complex(20.3, 10.2)
```

`complex` 返回的类型取决于其参数。如果两个参数都是 `float32`，或一个参数是 `float32` 而另一个是无类型常量或字面量且能容纳在 `float32` 中，则返回 `complex64`。否则，函数返回 `complex128`。

所有标准浮点算术运算符都适用于复数。与浮点数一样，你可以使用 `==` 或 `!=` 来比较它们，但它们具有相同的精度限制，因此最好使用 epsilon 技术。你可以使用 `real` 和 `imag` 内置函数分别提取复数的实部和虚部。`math/cmplx` 包提供了用于操作 `complex128` 值的其他函数。

两种复数类型的零值都将实部和虚部都赋值为 0。

示例 1-1 显示了一个简单的程序，演示了复数的工作方式。你可以在 [The Go Playground](https://go.dev/play/p/rRofeSJAazA) 上自行运行它，或在 [Chapter 2 repository](https://oreil.ly/zXZqI) 中的 `sample_code/complex_numbers` 目录中运行。

### 示例 1-1. 复数

```
func main() {
	x := complex(2.5, 3.1)
	y := complex(10.2, 2)
	fmt.Println(x - y)
	fmt.Println(real(x))
	fmt.Println(imag(x))
	fmt.Println(cmplx.Abs(x))
}
```

运行此代码会得到以下结果：

```
(-7.699999999999999+1.1i)
2.5
3.1
3.982461550347975
```

你可以在结果中看到浮点数不精度的表现。

如果你在想第五种原始字面量是什么，Go 支持虚数字面量来表示复数的虚部。它们看起来就像浮点数字面量，但后缀为 `i`。

尽管复数是预声明的类型，但 Go 并不是数值计算的流行语言。采用率有限，因为其他特性（如矩阵支持）不是语言的一部分，库必须使用低效的替代方案，如切片的切片。 （你将在第 3 章了解切片，以及在第 6 章了解它们的实现。）但如果你需要在较大程序中计算曼德布罗集，或实现二次方程求解器，复数支持就在那里为你提供。

你可能想知道为什么 Go 包含复数。答案很简单：Go（和 Unix）的创建者之一 Ken Thompson 认为它们会很有趣 [interesting](https://oreil.ly/eBmkq)。曾有关于 [removing complex numbers](https://oreil.ly/Q76EV) 从 Go 的讨论，但兼容性承诺意味着它们将继续存在。

#### Note

如果你确实想在 Go 中编写数值计算应用程序，请使用第三方 [Gonum](https://www.gonum.org) 包。它利用了复数，并为线性代数、矩阵、积分、图和统计等提供了有用的库。其他语言具有更好的数值计算支持，但 Go 对软件工程的关注可能对大型项目来说是一个优势。

## A Taste of Strings and Runes

这就引出了字符串。与大多数现代语言一样，Go 将字符串作为内置类型包含在内。字符串的零值为空字符串。Go 支持 Unicode；正如我在 “Literals” 中展示的那样，你可以将任何 Unicode 字符放入字符串中。与整数和浮点数一样，字符串使用 `==` 比较相等，使用 `!=` 比较不等，或使用 `>`、`>=`、`<` 或 `<=` 比较顺序。它们使用 `+` 运算符连接。

Go 中的字符串是不可变的；你可以重新分配字符串变量的值，但不能更改分配给它的字符串的值。

Go 还具有表示单个代码点的类型。*rune* 类型是 `int32` 类型的别名，正如 `byte` 是 `uint8` 的别名一样。你可能可以猜到，rune 字面量的默认类型是 rune，而字符串字面量的默认类型是 string。

如果你指的是一个字符，请使用 rune 类型，而不是 `int32` 类型。它们对编译器来说可能相同，但你希望使用能阐明代码意图的类型：

```
var myFirstInitial rune = 'J' // good - the type name matches the usage
var myLastInitial int32 = 'B' // bad - legal but confusing
```

我将在下一章中更多地谈论字符串，涵盖一些实现细节、与字节和 rune 的关系，以及高级特性和陷阱。

### Explicit Type Conversion

大多数具有多种数值类型的语言在需要时会自动从一种类型转换为另一种类型。这称为 *automatic type promotion*，虽然看起来很方便，但事实证明，正确转换一种类型到另一种类型的规则可能很复杂并产生意外结果。作为一种重视意图清晰和可读性的语言，Go 不允许变量之间进行自动类型提升。你必须在变量类型不匹配时使用 *type conversion*。即使不同大小的整数和浮点数也必须转换为相同类型才能交互。这使得你想要的类型非常明确，而无需记住任何类型转换规则（参见 示例 1-2）。

### 示例 1-2. 类型转换

```
var x int = 10
var y float64 = 30.2
var sum1 float64 = float64(x) + y
var sum2 int = x + int(y)
fmt.Println(sum1, sum2)
```

在此示例代码中，你定义了四个变量。`x` 是一个值为 10 的 `int`，`y` 是一个值为 30.2 的 `float64`。由于这些不是相同类型，因此你需要将它们转换后才能相加。对于 `sum1`，你使用 `float64` 类型转换将 `x` 转换为 `float64`，对于 `sum2`，你使用 `int` 类型转换将 `y` 转换为 `int`。运行此代码时，它会打印出 40.2 40。

对于不同大小的整数类型也适用相同的行为（参见 示例 1-3）。

### 示例 1-3. 整数类型转换

```
var x int = 10
var b byte = 100
var sum3 int = x + int(b)
var sum4 byte = byte(x) + b
fmt.Println(sum3, sum4)
```

你可以在 [The Go Playground](https://oreil.ly/VoE7H) 上运行这些示例，或在 [Chapter 2 repository](https://oreil.ly/dGtos) 中的 `sample_code/type_conversion` 目录中运行。





这种对类型的严格性还有其他影响。由于 Go 中的所有类型转换都是显式的，你不能将另一种 Go 类型当作布尔值处理。在许多语言中，非零数字或非空字符串都可以被解释为布尔值 `true`。就像自动类型提升一样，“真值”的规则因语言而异，可能会令人困惑。毫不奇怪，Go 不允许真值。事实上，*没有任何其他类型可以隐式或显式地转换为 bool*。如果你想将其他数据类型转换为布尔值，必须使用其中一个比较运算符（`==`、`!=`、`>`、`<`、`<=` 或 `>=`）。例如，要检查变量 `x` 是否等于 0，代码应为 `x == 0`。如果你想检查字符串 `s` 是否为空，请使用 `s == ""`。

#### Note

类型转换是 Go 选择在简洁性上增加一点冗长，以换取大量简洁性和清晰度的地方之一。你会多次看到这种权衡。惯用的 Go 更看重可理解性而非简洁性。

## min and max

Go 提供了两个用于比较数字和字符串的内置函数，`min` 和 `max`。两者都接受一个或多个值，所有值必须为同一类型。`min` 返回最小值，`max` 返回最大值。

除了内置函数外，Go 在标准库中还提供了几个查找数字最小值或最大值的函数。不幸的是，它们在处理 `NaN`、`Inf` 和 `-Inf` 时的行为不同。对于内置的 `min` 和 `max` 函数，如果传递给函数的值中任一值为 `NaN`，函数将返回 `NaN`，即使其他值包含 `Inf` 或 `-Inf`。`slices.Min` 和 `slices.Max` 函数的行为相同。然而，`math.Min` 和 `math.Max` 函数则相反。它们将负无穷视为最小值，正无穷视为最大值。你可以在 [The Go Playground](https://go.dev/play/p/YdKF8pk3rde) 上看到此演示。

应使用哪个函数取决于具体情况。如果需要与 `math.Min` 和 `math.Max` 的行为兼容，请使用它们。如果比较的值数量可能变化，请使用 `slices.Min` 和 `Max`。在任何其他情况下，首选内置函数。

#### Note

为什么 `min` 和 `max` 是内置函数？你可以阅读它们实现前的 [长讨论](https://github.com/golang/go/issues/59488) 来了解历史。其中有两个原因突出，一个是实际的，一个是哲学的。首先，将 `min` 和 `max` 实现为内置的可变参数函数可以避免每次调用时分配内存（内存分配在第 6 章中介绍）。也许更重要的是，人们认为这些是基本操作，如加法或减法，而基本操作应该是内置的。正如 Russ Cox 所说，“这最终是设计直觉和判断的问题。”

## Literals Are Untyped

虽然你不能将两个整数变量相加，如果它们被声明为不同类型的整数，但 Go 允许你在浮点表达式中使用整数字面量，甚至将整数字面量赋给浮点变量：

```
var x float64 = 10
var y float64 = 200.3 * 5
```

这是因为，正如我之前提到的，Go 中的字面量是无类型的。Go 是一种实用的语言，让类型在开发者指定之前保持未指定是有意义的。这意味着它们可以与任何与字面量兼容类型的变量一起使用。当你在第 7 章查看用户定义类型时，你会看到你甚至可以将字面量与基于预定义类型的用户定义类型一起使用。无类型是有一定限制的。你不能将字符串字面量赋给数值类型的变量，也不能将数字字面量赋给字符串变量，也不能将浮点字面量赋给 `int`。这些都会被编译器标记为错误。还存在大小限制。虽然你可以编写大于任何整数可容纳的数字字面量，但尝试将值溢出的字面量赋给指定变量是编译时错误，例如尝试将字面量 1000 赋给类型为 `byte` 的变量。

## var Versus :=

对于一种小型语言来说，Go 有很多种声明变量的方式。这是有原因的：每种声明方式都传达了变量使用方式的信息。让我们回顾一下在 Go 中声明变量的方式，并看看何时使用每种方式。

在 Go 中声明变量最冗长的方式使用 `var` 关键字、显式类型和赋值。它看起来像这样：

```
var x int = 10
```

如果 `=` 右侧的类型是变量预期的类型，你可以省略 `=` 左侧的类型。由于整数字面量的默认类型是 `int`，以下代码将 `x` 声明为类型为 `int` 的变量：

```
var x = 10
```

反之，如果你想声明一个变量并将其赋值为零值，你可以保留类型并去掉右侧的 `=`：

```
var x int
```

你可以使用 `var` 一次声明多个变量，它们可以是同一类型：

```
var x, y int = 10, 20
```

你可以声明同一类型的全部零值：

```
var x, y int
```

或不同类型：

```
var x, y = 10, "hello"
```

使用 `var` 还有一种方式。如果一次声明多个变量，你可以将它们包装在 *声明列表* 中：

```
var (
    x    int
    y        = 20
    z    int = 30
    d, e     = 40, "hello"
    f, g string
)
```

Go 还支持一种简短的声明和赋值格式。当你在函数内部时，可以使用 `:=` 运算符替换使用类型推断的 `var` 声明。以下两个语句完全相同——它们都将 `x` 声明为值为 10 的 `int`：

```
var x = 10
x := 10
```

与 `var` 一样，你可以使用 `:=` 一次声明多个变量。这两行都将 10 赋给 `x`，将 “hello” 赋给 `y`：

```
var x, y = 10, "hello"
x, y := 10, "hello"
```

`:=` 运算符可以做 `var` 做不到的一件事：它允许你同时为现有变量赋值。只要 `:=` 左侧至少有一个新变量，其他变量就可以已经存在：

```
x := 10
x, y := 30, "hello"
```

使用 `:=` 有一个限制。如果你在包级别声明变量，必须使用 `var`，因为 `:=` 在函数外部是非法的。

你如何知道使用哪种风格？一如既往，选择最能表达你意图的。函数内部最常见的声明风格是 `:=`。在函数外部，在极少数需要声明多个包级变量的情况下，使用声明列表。

在函数内的某些情况下，应避免使用 `:=`：

*   当将变量初始化为其零值时，使用 `var x int`。这表明零值是故意为之。

*   当将无类型常量或字面量赋给变量，而常量或字面量的默认类型不是你想要的变量类型时，使用带指定类型的长 `var` 形式。虽然使用类型转换指定值的类型并使用 `:=` 编写 `x := byte(20)` 是合法的，但惯用写法是 `var x byte = 20`。

*   因为 `:=` 允许你同时为新变量和现有变量赋值，所以它有时会在你以为是在重用现有变量时创建新变量（详见 [Link to Come]）。在这些情况下，请使用 `var` 显式声明所有新变量以明确哪些变量是新的，然后使用赋值运算符（`=`）为新旧变量赋值。

虽然 `var` 和 `:=` 允许你在同一行声明多个变量，但仅在为函数返回的多个值赋值或使用逗号 ok 惯用法（见第 5 章）时使用这种风格。





你应该很少在函数之外声明变量，这被称为 *包块*（见第 4 章）。包级变量的值会发生变化是不好的做法。当你在函数之外有一个变量时，很难追踪对其所做的更改，这使得很难理解数据如何在你的程序中流动。这可能导致难以察觉的错误。作为一般规则，你只应在包块中声明那些本质上不可变的变量。

#### Tip

避免在函数之外声明变量，因为它们会使数据流分析变得复杂。

你可能会想知道：Go 是否提供了一种 *确保* 值不可变的方法？它确实提供了，但与你在其他编程语言中看到的方式有点不同。是时候学习关于 `const` 了。

## Using const

许多语言都有一种声明值不可变的方法。在 Go 中，这通过 `const` 关键字完成。乍一看，它似乎与在其他语言中的工作方式完全相同。尝试在 [The Go Playground](https://oreil.ly/FdG-W) 上运行 示例 1-4 中的代码，或在 [第 2 章仓库](https://oreil.ly/QxTTT) 的 `sample_code/const_declaration` 目录中运行。

#### Example 1-4. `const` declarations

```
package main

import "fmt"

const x int64 = 10

const (
    idKey   = "id"
    nameKey = "name"
)

const z = 20 * 10

func main() {
    const y = "hello"

    fmt.Println(x)
    fmt.Println(y)

    x = x + 1 // this will not compile!
    y = "bye" // this will not compile!
    fmt.Println(x)
    fmt.Println(y)
}
```

运行此代码时，编译会失败并出现以下错误信息：

```
./prog.go:20:2: cannot assign to x (constant 10 of type int64)
./prog.go:21:2: cannot assign to y (untyped string constant "hello")
```

正如你所见，你可以在包级或函数内声明常量。就像 `var` 一样，你可以（并且应该）在括号内声明一组相关的常量。

请注意，Go 中的 `const` 非常有限。Go 中的常量是为字面量命名的一种方式。它们只能保存编译器能在编译时确定的值。这意味着它们可以被赋值为：

*   数字字面量
*   `true` 和 `false`
*   字符串
*   字符
*   内置函数 `complex`、`real`、`imag`、`len` 和 `cap` 返回的值
*   由运算符和前述值组成的表达式

#### Note

我将在下一章介绍 `len` 和 `cap` 函数。另一个可以用在 `const` 中的值称为 `iota`。我将在第 7 章讨论创建自己的类型时谈论 `iota`。

Go 不提供指定运行时计算得到的值不可变的方法。例如，以下代码将无法编译，错误为 `x + y (value of type int) is not constant`：

```
x := 5
y := 10
const z = x + y // this won't compile!
```

正如你将在下一章看到的，没有不可变的数组、切片、映射或结构体，也没有办法声明结构体字段不可变。这听起来限制性没那么大。在函数内部，很清楚变量是否被修改，因此不可变性就不那么重要了。在第 5 章，你将看到 Go 如何防止对作为函数参数传递的变量进行修改。

#### Tip

Go 中的常量是为字面量命名的一种方式。在 Go 中 *没有* 办法声明变量不可变。

## Typed and Untyped Constants

常量可以是有类型的或无类型的。无类型常量与字面量完全一样；它本身没有类型，但在无法推断出其他类型时，会使用默认类型。有类型常量只能直接赋给该类型的变量。

是否使常量有类型取决于声明常量的原因。如果你为一个数学常量命名，该常量可能用于多种数值类型，则保持常量无类型。一般来说，让常量保持无类型会给你更多灵活性。在某些情况下，你希望常量强制一个类型。当我在第 7 章介绍使用 `iota` 的枚举时，你会看到有类型常量的用途。

这是一个无类型常量声明的示例：

```
const x = 10
```

以下所有赋值都是合法的：

```
var y int = x
var z float64 = x
var d byte = x
```

这是一个有类型常量声明的示例：

```
const typedX int = 10
```

此常量只能直接赋给 `int`。将其赋给任何其他类型都会产生如下编译时错误：

```
cannot use typedX (type int) as type float64 in assignment
```

## Unused Variables

Go 的目标之一是让大型团队更轻松地协作编写程序。为此，Go 有一些在编程语言中独有的规则。在第 1 章中，你看到 Go 程序需要以特定方式格式化，使用 `go fmt`，以便更轻松地编写代码操作工具并提供编码标准。另一个 Go 要求是 *每个声明的局部变量都必须被读取*。声明局部变量却不读取其值是 *编译时错误*。

编译器的未使用变量检查并不详尽。只要变量被读取一次，编译器就不会抱怨，即使有对变量的写入从未被读取。以下是一个有效的 Go 程序，你可以在 [The Go Playground](https://oreil.ly/8JLA6) 上运行，或在 [第 2 章仓库](https://oreil.ly/FqALl) 的 `sample_code/assignments_not_read` 目录中运行：

```
func main() {
    x := 10 // this assignment isn't read!
    x = 20
    fmt.Println(x)
    x = 30 // this assignment isn't read!
}
```

虽然编译器和 `go vet` 没有捕获对 `x` 的 10 和 30 的未使用赋值，但第三方工具可以检测到它们。我将在代码质量部分谈论这些工具。

#### Note

Go 编译器不会阻止你创建未读取的包级变量。这又是一个你应该避免创建包级变量的原因。

## Naming Variables and Constants

Go 对命名变量的规则与 Go 开发者在命名变量和常量时遵循的模式之间存在区别。与大多数语言一样，Go 要求标识符名称以字母或下划线开头，名称可以包含数字、下划线和字母。Go 对“字母”和“数字”的定义比许多语言更宽泛。任何被视为字母或数字的 Unicode 字符都是允许的。这使得 示例 1-5 中的所有变量定义都是完全有效的 Go。

#### Example 1-5. Variable names you should never use

```
_0 := 0_0
_𝟙 := 20
π := 3
ａ := "hello" // Unicode U+FF41
__ := "double underscore" // two underscores
fmt.Println(_0)
fmt.Println(_𝟙)
fmt.Println(π)
fmt.Println(ａ)
fmt.Println(__)
```





你可以在 [Go Playground](https://oreil.ly/VIYOk) 上测试这段糟糕的代码。虽然它能运行，但不要使用这种变量名。这些名字被认为是非惯用的，因为它们违背了确保代码能表达其所做之事这一基本规则。这些名字令人困惑，或在许多键盘上难以输入。形似的 Unicode 代码点是最阴险的，因为即使它们看起来是同一个字符，它们也代表完全不同的变量。你可以在 [The Go Playground](https://oreil.ly/hrvb6) 上运行 示例 1-6 所示的代码，或在 [第 2 章仓库](https://oreil.ly/7nLfx) 的 `sample_code/look_alike_code_points` 目录中运行。

### 示例 1-6. 使用形似代码点作为变量名

```
func main() {
    ａ := "hello"   // Unicode U+FF41
    a := "goodbye" // standard lowercase a (Unicode U+0061)
    fmt.Println(ａ)
    fmt.Println(a)
}
```

运行此程序时，你会得到：

```
hello
goodbye
```

尽管下划线是变量名中的有效字符，但很少使用，因为惯用的 Go 不使用 snake case（像 `index_counter` 或 `number_tries` 这样的名字）。相反，当标识符名称由多个单词组成时，惯用的 Go 使用驼峰命名法（像 `indexCounter` 或 `numberTries` 这样的名字）。

#### Note

单独的下划线（`_`）在 Go 中是一个特殊的标识符名称；我将在第 5 章讲解函数时详细介绍它。

在许多语言中，常量总是以全大写字母书写，单词之间用下划线分隔（像 `INDEX_COUNTER` 或 `NUMBER_TRIES` 这样的名字）。Go 不遵循这种模式。这是因为 Go 使用包级声明名称的首字母大小写来确定该项是否可在包外访问。我将在第 10 章讲解包时再次讨论这个问题。

在函数内部，优先使用简短的变量名。变量的作用域越小，用于它的名字就越短。在 Go 中，使用单字母变量名与 `for` 循环一起出现是很常见的。例如，名称 `k` 和 `v`（分别代表 key 和 value 的缩写）被用作 `for-range` 循环中的变量名。如果你使用标准的 `for` 循环，`i` 和 `j` 是索引变量的常用名称。还有其他惯用的方式来命名常见类型的变量；我在讲解标准库的更多部分时将会提到它们。

一些类型系统较弱的语言鼓励开发者在变量名中包含变量的预期类型。由于 Go 是强类型语言，你不需要这样做来跟踪底层类型。然而，你可能会看到 Go 代码中以类型的首字母作为变量名（例如整数用 `i`，浮点数用 `f`）。当你定义自己的类型时，类似的模式也适用，尤其是在命名接收者变量时（将在第 7 章介绍）。

这些简短的名字有两个目的。第一，它们消除了重复的输入，使代码更简短。第二，它们可作为代码复杂度的检查。如果发现很难跟踪简短命名的变量，你的代码块可能做了太多事情。

在包块中命名变量和常量时，使用更具描述性的名称。类型仍应从名称中排除，但由于作用域更广，你需要一个更完整的名称来阐明该值所代表的内容。

有关 Go 命名建议的更多讨论，请阅读 [Google 的 Go 风格决策中的命名部分](https://oreil.ly/6AUc_)。
