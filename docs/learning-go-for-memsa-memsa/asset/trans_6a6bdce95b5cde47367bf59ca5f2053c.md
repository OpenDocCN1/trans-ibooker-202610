### 选择使用哪种整数

Go 提供的整数类型比某些其他语言更多。面对这么多选择，你可能会想知道何时使用每一种。你应遵循三条简单规则：

* 默认情况下，使用 `int`。
* 如果你正在处理具有特定大小或符号的整数的二进制文件格式或网络协议，请使用相应的整数类型。
* 如果你正在编写应适用于任何整数类型的库函数，请利用 Go 的泛型支持，并使用泛型类型参数来表示任何整数类型（我在第 5 章中更详细地讨论函数及其参数，并在第 8 章中更详细地讨论泛型。）

#### Note

你可能会发现遗留代码中有一对执行相同功能的函数，但一个使用 `int64` 作为参数和变量，另一个使用 `uint64`。原因是该 API 在 Go 添加泛型之前创建。在没有泛型的情况下，你需要编写名称略有不同的函数，以使用不同类型实现相同的算法。使用 `int64` 和 `uint64` 意味着你可以编写一次代码，让调用者使用类型转换来传递值并转换返回的数据。

你可以在 Go 标准库的 `strconv` 包中的 `FormatInt` 和 `FormatUint` 函数中看到这种模式。由于兼容性承诺，这些函数永远不会消失，但它们实现了过时的风格。

### 整数运算符

Go 整数支持通常的算术运算符：`+`、`-`、`*`、 `/`，以及 `%` 用于取模。整数除法的结果是整数；如果你想得到浮点结果，你需要使用类型转换将整数转换为浮点数。另外，请注意不要用 0 除整数；这会导致 panic（我在 Panic Recover 部分更详细地讨论 panic）。

#### Note

Go 中的整数除法遵循向零截断。取模遵循相同的规则；`-7 % 2 == -1`。请参阅 Go 规范中关于 [算术运算符](https://oreil.ly/zp3OJ) 的部分以了解完整细节。

你可以将任何算术运算符与 `=` 结合来修改变量：`+=`、`-=`、`*=`、 `/=` 和 `%=`。例如，以下代码使 `x` 的值为 20：

```
var x int = 10
x *= 2
```

Go 还包括 `++` 和 `--` 运算符来递增和递减变量的值。与 Java、C++ 和其他几种语言不同，Go 要求这些运算符出现在变量之后。

```
var x int = 10
x ++ // ok
++x  // syntax error, does not compile
```

你可以使用 `==`、`!=`、`>`、`>=`、`<` 和 `<=` 比较整数。有三个一元整数运算符：`+`、`-` 和 `^`。前两个使数字为正或负，而第三个对整数执行按位 NOT。

Go 还为整数提供了位操作运算符。你可以使用 `<<` 和 `>>` 进行左移和右移，或使用 `&`（按位 AND）、 `|`（按位 OR）、 `^`（按位 XOR）和 `&^`（按位 AND NOT）进行位掩码。与算术运算符一样，你也可以将所有位运算符与 `=` 结合来修改变量：`&=`、`|=`、`^=`、`&^=`、`<<=` 和 `>>=`。

## 整数溢出

与许多其他语言一样，Go 允许你将整数变量递增和递减超出其限制。对设置为类型的最大值变量加一会返回该类型的最小值，从最小值减一会返回最大值。在编写代码时要小心；不要假设 `x + 1` 总是大于 `x` 且 `x - 1` 总是小于 `x`。

```
var x uint = 0
x--
fmt.Println(x) // prints 18446744073709551615
x++
fmt.Println(x) // prints 0
```

### 浮点类型

Go 有两种浮点类型，如 [表 1-2](#ch01.html#table2_2) 所示。

表 1-2. Go 中的浮点类型

| 类型名称 | 最大绝对值 | 最小（非零）绝对值 |
| --- | --- | --- |
| `float32` | 3.40282346638528859811704183484516925440e+38 | 1.401298464324817070923729583289916131280e-45 |
| `float64` | 1.797693134862315708145274237317043567981e+308 | 4.940656458412465441765687928682213723651e-324 |

与整数类型一样，浮点类型的零值为 0。

Go 中的浮点与其它语言中的浮点数学类似。Go 使用 IEEE 754 规范，提供大范围和有限精度。选择使用哪种浮点类型很简单：除非你必须与现有格式兼容，否则使用 `float64`。浮点字面量的默认类型为 `float64`，因此始终使用 `float64` 是最简单的选择。它还有助于缓解浮点精度问题，因为 `float32` 只有六到七位十进制精度的精度。除非你使用分析器确定它是问题的重要来源，否则不必担心内存大小的差异。（测试和分析在 [第 2 章](#ch02.html#unique_chapter_id_15) 中介绍。）

更大的问题是你是否应该使用浮点数。在许多情况下，答案是否定的。就像其他语言一样，Go 浮点数具有巨大的范围，但它们不能存储该范围内的每个值；它们存储最接近的近似值。因为浮点数不精确，所以它们只能用于不精确值可接受或浮点规则被很好理解的情况。这将它们限制在图形、统计和科学运算等事物中。一些早于泛型的函数使用 `float64` 参数作为为所有浮点和整数类型提供单一实现的方式，例如标准库 `math` 包中的 `Min` 和 `Max` 函数。这是过时的模式（并且对于超出 -2^53 到 2^53 范围的 64 位整数无法正确工作）。

#### Warning

浮点数无法精确表示十进制值。不要用它们来表示货币或任何必须具有精确十进制表示的值！在第 10 章中，你将学习如何使用第三方 `shopspring/decimal` 模块来处理精确的十进制值。

你可以使用所有标准的数学和比较运算符与浮点数一起使用，除了 `%`。浮点除法有一些有趣的特性。将非零浮点变量除以 0 会返回 `+Inf` 或 `-Inf`（正或负无穷大），取决于数字的符号。将设置为 0 的浮点变量除以 0 会返回 `NaN`（非数字）。

虽然 Go 允许你使用 `==` 和 `!=` 比较浮点数，但不要这样做。因为浮点数的非精确性，两个浮点值可能在你认为应该相等时并不相等。相反，定义一个最大允许差异，并查看两个浮点数的差是否小于该值。此值（有时称为 *epsilon*）取决于你的精度需求；我无法给出简单的规则。如果你不确定，请咨询你友好的本地数学家寻求建议。如果你找不到，[The Floating Point Guide has a “Comparison” page](https://oreil.ly/n9ws3) 可以帮助你（或可能说服你在绝对必要时避免浮点数）。另一个陷阱是，根据定义，`NaN` 不等于任何东西，包括它本身。你可以在 [The Go Playground](https://go.dev/play/p/LK8aj87-vSI) 上看到此演示。如果浮点变量可能为 `NaN`，请使用函数 `math.IsNaN()` 来测试它。
