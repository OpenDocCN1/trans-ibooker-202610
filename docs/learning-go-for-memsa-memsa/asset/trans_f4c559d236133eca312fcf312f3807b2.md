### 示例 1-6. 使用形似代码点作为变量名

```
func main() {
    ａ := "hello"   // Unicode U+FF41
    a := "goodbye" // standard lowercase a (Unicode U+0061)
    fmt.Println(ａ)
    fmt.Println(a)
}
```

运行此程序时，你会得到：

```
hello
goodbye
```

尽管下划线是变量名中的有效字符，但很少使用，因为惯用的 Go 不使用 snake case（像 `index_counter` 或 `number_tries` 这样的名字）。相反，当标识符名称由多个单词组成时，惯用的 Go 使用驼峰命名法（像 `indexCounter` 或 `numberTries` 这样的名字）。

#### Note

单独的下划线（`_`）在 Go 中是一个特殊的标识符名称；我将在第 5 章讲解函数时详细介绍它。

在许多语言中，常量总是以全大写字母书写，单词之间用下划线分隔（像 `INDEX_COUNTER` 或 `NUMBER_TRIES` 这样的名字）。Go 不遵循这种模式。这是因为 Go 使用包级声明名称的首字母大小写来确定该项是否可在包外访问。我将在第 10 章讲解包时再次讨论这个问题。

在函数内部，优先使用简短的变量名。变量的作用域越小，用于它的名字就越短。在 Go 中，使用单字母变量名与 `for` 循环一起出现是很常见的。例如，名称 `k` 和 `v`（分别代表 key 和 value 的缩写）被用作 `for-range` 循环中的变量名。如果你使用标准的 `for` 循环，`i` 和 `j` 是索引变量的常用名称。还有其他惯用的方式来命名常见类型的变量；我在讲解标准库的更多部分时将会提到它们。

一些类型系统较弱的语言鼓励开发者在变量名中包含变量的预期类型。由于 Go 是强类型语言，你不需要这样做来跟踪底层类型。然而，你可能会看到 Go 代码中以类型的首字母作为变量名（例如整数用 `i`，浮点数用 `f`）。当你定义自己的类型时，类似的模式也适用，尤其是在命名接收者变量时（将在第 7 章介绍）。

这些简短的名字有两个目的。第一，它们消除了重复的输入，使代码更简短。第二，它们可作为代码复杂度的检查。如果发现很难跟踪简短命名的变量，你的代码块可能做了太多事情。

在包块中命名变量和常量时，使用更具描述性的名称。类型仍应从名称中排除，但由于作用域更广，你需要一个更完整的名称来阐明该值所代表的内容。

有关 Go 命名建议的更多讨论，请阅读 [Google 的 Go 风格决策中的命名部分](https://oreil.ly/6AUc_)。

# Chapter 2. Writing Tests

自 2000 年代以来，自动化测试的广泛采用可能比任何其他软件工程技术都更能提高代码质量。作为一种专注于提高软件质量的语言和生态系统，Go 将测试支持作为其标准库的一部分也就不足为奇了。Go 让测试代码变得如此简单，没有理由不去做。

在本章中，你将看到如何测试 Go 代码，如何将测试分组为单元测试和集成测试，如何检查代码覆盖率，如何编写基准测试，以及如何使用 Go 数据竞争检测器检查代码中的并发问题。在此过程中，我将讨论如何编写可测试的代码以及为什么这能提高我们的代码质量。

## Understanding the Basics of Testing

Go 的测试支持分为两部分：库和工具。标准库中的 `testing` 包提供了编写测试的类型和函数，而随 Go 捆绑的 `go test` 工具则运行你的测试并生成报告。与许多其他语言不同，Go 将其测试放在与生产代码相同的目录和包中，因此它们可以访问和测试未导出的函数和变量。你稍后会看到如何编写测试以确保你只是在测试公共 API。

#### Note

本章的完整代码示例可在 [第 15 章仓库](https://github.com/learning-go-book-3e/ch15) 找到。

让我们编写一个简单的函数，然后编写一个测试来确保该函数正常工作。在 `sample_code/adder` 目录中，`adder.go` 文件中有以下内容：

```
func addNumbers(x, y int) int {
    return x + x
}
```

对应的测试在 `adder_test.go` 中：

```
func Test_addNumbers(t *testing.T) {
    result := addNumbers(2,3)
    if result != 5 {
        t.Error("incorrect result: expected 5, got", result)
    }
}
```

每个测试都写在一个文件名以 `_test.go` 结尾的文件中。如果你要对 `foo.go` 编写测试，请将测试放在名为 `foo_test.go` 的文件中。

测试函数以 `Test` 开头，并接受单个类型为 `*testing.T` 的参数。按惯例，该参数命名为 `t`。测试函数不返回任何值。测试的名称（除了以“Test”开头之外）旨在记录你正在测试的内容，因此请选择能解释你正在测试内容的名称。在为单个函数编写单元测试时，惯例是以 `Test` 加上函数名来命名单元测试。在测试未导出函数时，有些人会在 `Test` 和函数名之间使用下划线。

还要注意，你使用标准的 Go 代码来调用被测试的代码并验证响应是否符合预期。当结果不正确时，你使用 `t.Error` 方法报告错误，其工作原理类似于 `fmt.Print` 函数。你稍后会看到其他错误报告方法。
