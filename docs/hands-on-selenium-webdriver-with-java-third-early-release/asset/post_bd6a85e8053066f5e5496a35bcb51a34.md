## What Strategy Should You Use?

In this section, we reviewed the different alternatives the WebDriver API allows for locating elements in a web page. This topic is one of the most fundamental routines for browser automation with Selenium WebDriver. Maybe you are asking yourself: *what is the best strategy I should use?* As Dr. Alfred Lanning (character of the novel and movie “I, Robot”) would say: “That, detective, is the right question.” In my opinion, that is a difficult question, and it has no simple answer. In other words, the answer to this question could be “it depends.” In this section, I present several hints to identify a suitable locator strategy for common use cases. First, Table 3-8 provides a comparison of the different locating strategies.

Table 3-8. Pros, cons, and typical use case

| Locator strategy | Ease of use | Availability or limitation | Use case |
|---|---|---|---|
| By attribute (id, name, class) | Easy to use | These attributes are not always available | Elements which define these attributes in an immutable manner (i.e., they do not change dynamically) |
| By link text (total or partial) | Easy to use | Only available for links | For text links |
| By tag name | Easy to use | Hard to select one specific element when the tag repeatedly appears on the page | When the tag is unique, or the resulting DOM node has a fixed position |
| By CSS selector or by XPath | Very powerful | It can be difficult to write robust selectors | For complex locators |
| Compound locators | Easy way to compose existing locators | Limited to specific situations | When looking for id or name (`ByIdOrName`), when looking for nested elements (`ByChained`), and when using several strategies at the same time (`ByAll`) |
| Relative locators | Human-language approach | They need to be combined with other locators | Find an element based on the relative position (above, below, near, etc.) of a known element |

As you can see in this table, CSS selectors and XPath share the same pros, cons, and use cases. Does it mean these strategies are the same? The answer is no. Both of them are very powerful and allow the creation of complex locators. Nevertheless, there are relevant distinctions between them. Table 3-9 summarizes these differences.

## Table 3-9. Some Differences Between XPath and CSS Selectors

| XPath is slower in terms of performance | CSS has better performance than XPath |
| XPath allows the identification of visible text on the screen using the `text()` function | CSS does not allow locating elements by their text content |

## Keyboard Actions

As introduced in Table 3-3, two main methods in WebDriver objects allow impersonating keyboard user actions: `sendKeys()` and `clear()`. Example 3-17 shows a test using these methods.

## Example 3-17. Test Impersonating Keyboard Events

```java
@Test
void testSendKeys() {
    driver.get(
        "https://bonigarcia.dev/selenium-webdriver-java/web-form.html");

    WebElement inputText = driver.findElement(By.name("my-text")); ①
    String textValue = "Hello World!";
    inputText.sendKeys(textValue); ②
    assertThat(inputText.getAttribute("value")).isEqualTo(textValue); ③

    inputText.clear(); ④
    assertThat(inputText.getAttribute("value")).isEmpty(); ⑤
}
```

- ① We use the practice web form to locate the input text named `my-text`.
- ② We simulate keyboard typing in it using the `sendKeys()` method.
- ③ We assess that the input value is as expected.
- ④ We reset its content using `clear()`.
- ⑤ We assess that the input value is empty.

## File Uploading

There are several use cases in which we will need to impersonate keyboard actions when interacting with web pages through Selenium WebDriver. The first one is file uploading. The standard mechanism to upload files for web applications is using `<input>` elements with `type="file"`. For instance, the practice web form contains one of these elements:

```html
<input class="form-control" type="file" name="my-file">
```
