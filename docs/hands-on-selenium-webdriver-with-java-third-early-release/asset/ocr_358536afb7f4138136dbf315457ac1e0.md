At some moment, a script (typically a test case) will try to start a new session to drive a browser automatically. Figure 6-5 describes the communication required to carry out this process in a fully distributed Selenium Grid, namely:

+   1. A script/test using the Selenium WebDriver API sends a request to the Router to create a new session (i.e., to drive a browser programmatically).
+   2. The Router creates a new entry in the Session Queue to store this new session request.
+   3. The Distributor asks the Session Queue for incoming new sessions requests in intervals.
+   4. Once the Distributor discovers a new session request, it checks if some node can support this session. If the session is possible (i.e., some node, previously registered in the Distributor, offers the required capabilities), the Distributor creates a new session with the node.
+   5. The Distributor uses the Event Bus to send a message to the Session Map to store the new session.
+   6. The Session Map stores a unique session identifier (*session id*) that unequivocally associates the node executing the browser session.
