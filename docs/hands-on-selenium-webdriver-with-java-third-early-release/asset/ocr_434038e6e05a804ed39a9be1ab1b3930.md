L10n is part of a broader concept called *internationalization* (i18n), which is the process of designing and developing an application that enables easy l10n for heterogeneous target audiences. Common practices to enable i18n are using Unicode for text encoding or adding CSS support for vertical text or non-Latin typographies.

*Localization testing* is a form of non-functional testing where a SUT is verified for specific locale settings. The WebDriver API allows us to make localization testing based on the browser language by setting the capability `intl.accept_languages`. This capability allows to specify the locale identifier, such as *en_US* for American English or *es_ES* for European Spanish, to name a few. **Example 5-20** shows a test setup that configures this capability in Chrome. We can use the same syntax in Edge, although we specify this capability as a preference in Firefox (see **Example 5-21**).
