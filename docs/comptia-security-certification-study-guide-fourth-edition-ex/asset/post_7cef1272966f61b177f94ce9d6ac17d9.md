## Network Reconnaissance and Discovery

Penetration testers have a number of tools they can use to perform reconnaissance (profiling) on a company and discovery of information and systems. The following are some common reconnaissance and discovery tools used by penetration testers.

### Discovery Tools

There are a number of tools that are used to discover systems on the network, a system’s IP address, network connections, and public information on the Internet about a company. The following is a list of discovery tools to know for the exam.

- **tracert/traceroute** — Used to trace the path a packet takes on the network. When the packet reaches a router, a response is sent back, letting you know how many routers the packet is traveling through. Sample usage is **tracert www.gleneclarke.com**.
- **nslookup/dig** — DNS lookup tools; nslookup is common on both Windows and Linux systems, while dig is found on Linux systems.
- **ipconfig/ifconfig** — Used to display the TCP/IP settings on a Windows system or Linux system, respectively.
- **netstat** — Used to view a list of ports open on a system or to view who is connected to that system. To view all open ports, use **netstat -na**.
- **theHarvester** — An OSINT tool used to collect employee e-mail addresses, domain names, server names, and open ports on systems from public Internet sources.

### Pingers and Scanners

Part of assessing the network is to locate systems that are up and running, what ports are open on a running system, and any vulnerabilities that might exist. The following are tools used to ping systems on the network, do a port scan, and a vulnerability scan.

- **ping/pathping** — Both ping and pathping are used to test connectivity with a remote system, but pathping will show each hop the packet takes. Sample usage is **ping 192.168.1.1** and **pathping 192.168.1.1**.
- **hping** — Hping is a pinger that allows you to craft the packet so you can bypass firewalls. For example, if a system is blocking ICMP packets, which is preventing you from pinging the system, you could use hping and specify the protocol TCP and a port you feel would be open in order for the ping messages to slip through the firewall.
- **IP scanners** — IP scanners are used to perform scans on the network to detect what systems are up and running and their IP addresses.

- **tail** Similar to the head command, but this Linux command is used to print the last ten lines on the screen.
- **cat** Used to display the contents of one or more text files in Linux.
- **grep** Used to search for a specific string within a file.
- **chmod** Used to change the permissions on a file.
- **logger** Allows you to add log entries to the /var/log/syslog file.

## Shell and Script Environments

As a penetration tester you may be required to create your own scripts to automate tasks performed during the penetration test. The following are some scripting environments used by pentesters.

- **SSH** A secure shell environment used to gain remote access to a system using a secure channel.
- **PowerShell** A scripting environment within Windows that can be used to create scripts to automate common tasks.
- **Python** Another scripting environment that is very popular in the security field. Many security tools, such as sn1per, are Python scripts used to automate tasks during a penetration test.
- **OpenSSL** A secure library that can be used by applications to establish a secure communication channel over the network.

## Packet Capture and Replay

The purpose of packet capture software, or a sniffer program, is to *passively* capture traffic traveling the network in order to view or analyze that traffic. The purpose of using a sniffer when performing a security assessment is to see if you can capture sensitive information being sent on the network in clear text. If you find that passwords and other sensitive information are in the packet capture, as shown in Figure 20-11, you should recommend that the organization encrypt network traffic.

> **on the job**
> 
> Years ago, while I was working for a large national company, the employees were told that their e-mails were encrypted on the network. After a few years, though, we found out that our e-mails were not actually encrypted—the server administrators thought they had enabled encryption, but somehow had not and had never verified it. We found this out only because some of the trainers learning how to monitor traffic discovered e-mails from the manager of the company that were in transit. Using a packet sniffer is a great way to verify that data is actually encrypted in transit.

Here are some common tools that can be used to capture packets on the network:

- **Wireshark** Probably the most commonly used packet capturing tool can be downloaded for free from wireshark.org. You can capture packets on the network, filter the packets, and analyze them to determine activity on the network.
- **tcpdump** A Linux command used to capture traffic. For example, you can use the following command to display captured packets on the screen: `tcpdump -i eth0`, where `-i eth0` is the interface to capture traffic from.
- **tcpreplay** A Linux command used to replay captured traffic on the network. The traffic is first captured with tcpdump and can then be resent on the network with tcpreplay.

## Other Common Tools

The Security+ objectives make reference to some other common tools and frameworks you should be aware of:

- **Exploitation frameworks** A common assessment tool for pentesters is the exploitation framework, which has a number of tools to exploit flaws within different products. Common examples of exploitation frameworks are the Web Application Attack and Audit Framework (w3af) and Metasploit.
- **Password crackers** You can find various password-cracking tools out there. For example, you can crack passwords using John the Ripper, Medusa, Hydra, and hashcat, to name a few. All of these tools come with Kali Linux.
- **Data sanitization** You can use data sanitization tools to ensure that all data is securely erased from drives. This is an important step when disposing of drives or using drives as the target for a forensic image.

## CERTIFICATION SUMMARY

In this chapter, you learned about performing security assessments and that there are two major types of assessments—a penetration test and a vulnerability assessment. The following are some key points to remember when preparing for the Security+ exam:

- Different types of assessments can be performed, such as a threat assessment, configuration assessment, vulnerability scan, and penetration test.
- A penetration test is considered an active test because you are actually trying to compromise the system and bypass security controls. A vulnerability assessment is a passive test that simply identifies security issues with the configuration of the system.
- You can use tools such as Kali Linux (previously known as BackTrack) and Metasploit to do a penetration test, as well as password crackers such as John the Ripper.
- You can use many different techniques to determine security issues. You can perform a code review on an application that your company has created, a design review on a solution you create to make sure it meets the initial requirements, or an architecture review on a system to ensure it is a secure environment.
- A penetration test should follow the steps of the hacking process.
- Ensure that a legal document has been drafted and signed by all parties giving you permission to perform a penetration test.
- You can use a number of tools, such as a port scanner, network sniffer, vulnerability scanner, wireless scanner, wireless cracker, and a honeypot, to perform an assessment.

With a strong understanding of the material presented in this chapter, you will have no problems with the security assessment questions on your exam. Not only is the material presented here important for the exam, but it will also be important after you ace the exam and continue with your career as a security professional.
