
## General Security Controls for the Cloud

General security controls are controls you have as part of your subscription to the cloud and don't necessarily apply to storage or network specifically. Be sure to know these general security controls for the Security+ exam:

- **High availability across zones** When you create different resources with a cloud service provider, you can select the level of high availability you would like. You can have high availability within your region or across regions.
- **Resource policies** As mentioned earlier, you can put policies on resources, such as limiting the cost of a resource per month, compliance policies to secure the resource, and policies to clean out unused resources over time.
- **Secrets management** Within the cloud portal are tools used to manage the authentication credentials used (known as secrets), such as passwords, application tokens, and keys.
- **Integration and auditing** You can configure cloud auditing on resources to help you track who is using what resource and from where.

## Storage Security Controls

One of the big benefits of cloud is that you can store data in the cloud that can then be accessed from anywhere in the world. This means you should also take extra steps to secure those resources by implementing the following different storage security controls:

- **Permissions** You can limit access to data by placing permissions on the data to control who can access it.
- **Encryption** You can encrypt the data so that unauthorized individuals cannot access the data. Ensure data is encrypted both at rest (in storage) and in transit. Many cloud service providers encrypt data by default.
- **Replication** You can replicate the data to another cloud region so that you can get high availability of the data and business continuity if there is a regional disruption.
- **High availability** High availability ensures that data is always available. Cloud service providers implement high availability features in the background on different services, but you can also replicate your data to another region to ensure high availability.

## Network Security Controls

A number of security controls can be implemented within the cloud to provide security to your cloud networking environment:

- **Virtual networks** Within the cloud you are able to create multiple virtual networks and connect different systems to each one. For example, you can create a virtual network for just the accountants and run the accounting server VM on that network.
- **Public and private subnets** You can create a number of public and private subnets. A public subnet is a network that allows communication out to the Internet (essentially a gateway to the Internet). You can also divide your cloud infrastructure into multiple private subnets that do not have direct access to the Internet.
- **Segmentation** You can segment your resources into different virtual networks to control communication to those resources.
- **API inspection and integration** Cloud service providers offer a number of APIs that can be used to inspect elements within the cloud for compliance. For example, Google Cloud has a data loss prevention (DLP) API that can be called to inspect data stored in the cloud and verify that no sensitive data is stored there. You could also use APIs that allow you to inspect network traffic within the cloud.

## Compute Security Controls

In the cloud environment, a compute resource is a resource such as a virtual machine, container, or application service (such as a database service) in the cloud. You can use a number of security controls to secure these compute resources:

- **Security groups** You can create different security groups that have different levels of permissions to the resource.
- **Dynamic resource allocation** A big feature of cloud compute is that a virtual machine only uses the RAM and disk space that is needed. If there is a high volume of activity, those resources are increased on the fly to handle the workload and then lowered again when the load is lessened.
- **Instance awareness** You want to implement security controls that can differentiate between instances of an application service running in the cloud. If you are using a security control that does not understand instances, it is possible that an attacker could create a rogue instance of an application service and possibly perform data exfiltration attacks.
- **Virtual private cloud (VPC) endpoint** A virtual private cloud (VPC) is a private network of resources in the cloud. VPC endpoints allow you to communicate with application services over private addresses.
- **Container security** Ensure that you are securing your container environment by following security best practices, such as locking down the operating systems running within the container, including securing the root or administrator account.

## Cloud Security Solutions

You can use a number of security solutions within the cloud to implement cloud security. The following are some common cloud security solutions:

- **CASB** A cloud access security broker (CASB) is a security service that sits between your on-premises environment and your cloud provider's environment. The CASB allows you to define security policies that apply to network traffic flowing outside your current on-premises environment to the cloud.
- **Application security** Look for security solutions for your applications in the cloud. You want to use solutions that give you visibility into what is happening in the application and the data it contains. You also want to know the access control settings on your sensitive data so you can closely monitor who has access to that data. Cloud service providers typically offer a number of compliance features that allow you to monitor these elements.
- **Next-generation secure web gateway (SWG)** A secure web gateway (SWG) is a gateway product that all traffic funnels through, and it prevents users from accessing web sites on the Internet or in the cloud that may have malware that could infect their system or the internal network/cloud network.

## Firewall Considerations in a Cloud Environment

When you're looking for firewall products that work with cloud environments, a number of considerations should be put in place to help with your decision:

- **Cost** The cost of the firewall solution.
- **Need for segmentation** If you need a firewall solution that allows you to work with multiple network segments and control traffic between these segments.
- **Open Systems Interconnection (OSI) layers** The layer of the OSI model that the firewall runs at and what type of data you wish to filter traffic by. For example, if you want to be able to inspect the payload of the packet, you will want to use an application layer firewall (layer 7) versus a packet-filtering firewall (layer 3).

## Cloud Native Controls vs. Third-Party Solutions

One last point to make about implementing security controls within the cloud is that you should first investigate security controls that come with the cloud solution (native controls) before looking to third-party solutions. CSPs are constantly improving the features of their cloud solutions and increasing the number of security controls that are built into their products.

### Virtualization and Virtualization Security

- Virtualization allows you to run multiple operating systems on a single host computer.
- Ensure that each virtual machine is patched and secured. Be sure that the host computer is physically secured.
- VM sprawl is when a company loses track of the number of virtual machines that have been created within the organization, and there is no process in place for the creation, management, and decommissioning of virtual machines.
- VM escape is a security risk to virtualization environments that are unpatched. VM escape allows an application to access the host system from within the VM. For the exam, remember that you need to patch your virtualization environment to protect against VM escape.
