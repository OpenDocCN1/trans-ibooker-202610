In this section you will learn about the purpose of virtualization and the security concerns with virtualization. You can expect a question or two regarding this topic on the Security+ certification exam.

### Introducing Virtualization

Virtualization is the concept that instead of having a different server or computer to run each of the different operating systems or services, you can run each of these in a separate virtual machine (VM) on a single computer. A virtual machine is provided by virtualization software such as VMware’s ESXi or Microsoft’s Hyper-V, and it allows you to run each operating system in an isolated environment, even though all systems are running on the same physical computer. ### Benefits to Virtualization

Virtualization technology offers huge benefits, with the primary benefit being that you are better utilizing server resources, because traditionally servers have been underutilized. For example, in the past, a company would purchase a file server, which put little load on the system. Then when the company needed an intranet server, it would purchase another physical server for that. Both servers in this case may only be using 20 percent of their CPU, meaning that the company is not really getting its money’s worth out of the servers. With virtualization, you can purchase just one physical server, run two VMs (one for the file server and the other for the intranet server) on it, and use 40 percent of the CPU power, thus making better use of the company assets and wasting less money.

If you are in a support role and need to assist clients that run different operating systems (OSs), this gives you a method to have a copy of each licensed operating system installed on a single computer. If you need to answer a support call for a specific operating system, you’ll have the OS in front of you.

Testing and training environments benefit from virtualization because you can install different servers and clients on the same physical machine to create a mockup of a network environment.

Management also benefits from virtualization technology. You can consolidate dozens of servers down to only a few physical servers because you simply run each server in its own VM, which requires fewer physical servers. One of my customers consolidated 26 servers down to four or five physical servers. As a result, the company saved a lot of money in hardware upgrades and maintenance with only four or five physical servers to maintain.

An environmental benefit to using virtualization is the consumption of less power because fewer physical servers are involved. This also saves money for the organization. One of my customers consolidated servers via virtualization because it was reaching maximum power consumption!

### Hypervisor

The virtualization of systems is provided by the hypervisor, which is also known as the virtual machine monitor (VMM) and is the software component that allows you to create and run virtual machines on the system. When you install the hypervisor on a system, that system is then known as the host system, while each virtual machine is known as a guest system.

There are different types of hypervisors:

- **Type I** This hypervisor type is software that runs directly on top of the hardware, which then has the host operating system running as a parent virtual machine. This allows the hypervisor to control access to the hardware from the host and the guest systems. Microsoft’s Hyper-V and VMware’s ESXi Server are examples of type I hypervisors. These hypervisors are also known as bare-metal hypervisors because they run directly on top of the hardware.
- **Type II** A type II hypervisor involves having the OS installed on top of the hardware, and then installing virtualization software that will create VMs. Examples of type II hypervisors are VMware Workstation and Oracle VM VirtualBox.

Here are other terms you should be familiar with when working with virtualization technology and managing virtual machines:

- **Application containers** Application containers are a feature that allow you to run an application in an isolated environment that has its own resources assigned to it. Containers are just like VMs, but they share the OS kernel of the host system, so they perform better than VMs (but provide the isolation features of a VM). Docker is an example of software that provides application containers and is a feature of Windows 10.
- **VM sprawl avoidance** VM sprawl occurs when an organization has a large number of VMs being created without any process in place for building VMs. The problem is that the number of VMs being created outpaces the capability of network administrators to manage all of them. Having VMs pop up all over the place with no central management means no one is able to ensure that all those systems are patched when needed. Remember that a system that is unpatched could create a security hole in your network. Centrally managing VM host systems is the key to solving VM sprawl with management software used to deploy VMs.
- **VM escape protection** VM escape allows someone to access the host operating system from the guest OS of the VM. Virtualization vendors create patches for any VM escape vulnerabilities that exist within their products, so be sure to keep your virtualization software patched.

> **Exam Watch** For the exam, remember that VM sprawl is when the number of virtual machines within a company gets out of hand. VM management software should be used to manage the virtual machines across host systems. Also remember that VM escape is when software can make calls from within a VM to a host system, which is a huge security risk! Patch the virtualization platform on a regular basis to get rid of VM escape vulnerabilities.

### Security Issues with Virtualization

Remember these key points regarding virtualization technology as it relates to security:

- **Less hardware to secure** A huge benefit to virtualization is that you will run multiple systems on one physical server, which means that you have less hardware to secure. Be sure to follow physical security practices with the host system, but the benefit is that it is only one system.
- **Disk space** Virtualization technology allows you to create snapshots of a system so that you can revert to the snapshot at any point in time. This is a great feature because if you make a mistake in the configuration of a system, you can revert to the snapshot. Keep in mind, though, that each snapshot uses up disk space.
- **Patching** Although all of the VMs are running on the same physical system, patching the host system does not patch the VMs. You are responsible for patching each virtual machine.

> **Exam Watch** For the exam, remember that a benefit of virtualization is that you have fewer systems whose physical security you need to worry about. Ensure that you follow physical security best practices with the host system, but it is nice to worry about less hardware!

Most organizations today are using virtualization software to host multiple virtual machines on a single server, thus saving money on hardware purchases and consuming less power. The following are some security best practices in regard to virtualization:

- **Snapshots** Taking snapshots gives you a point to which you can revert should something go wrong with the virtual machine. For example, if you make a wrong configuration change or the VM is hit with malware, you can revert to a previous snapshot to restore the state of the VM.
- **Patch compatibility** Ensure that the patches are tested and compatible before applying them to production systems in a virtualized environment.
- **Host availability/elasticity** Be sure you have implemented high availability of the host system, because if it fails, then all the virtualized servers running on that host are unavailable. One of the benefits of virtualization solutions is *elasticity*, which is the launching of new servers to handle increased load demands while also easily reducing the number of running servers when the load decreases. Elasticity is an important feature of cloud computing as well (more on cloud computing in the next section).
