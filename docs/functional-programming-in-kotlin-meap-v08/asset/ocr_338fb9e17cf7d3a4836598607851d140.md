# Lazy initialization

*Lazy initialization* is the tactic of delaying the creation of an object, the calculation of a value, or some other expensive process until the first time it is needed. The full definition can be found here on Wikipedia: [en.wikipedia.org/wiki/Lazy_initialization](en.wikipedia.org/wiki/Lazy_initialization)

This language feature is implemented in Kotlin by way of a builtin function called `lazy`. An instance of `Lazy<T>` (with T being the type of the value to be assigned) is returned when this function is invoked with a lambda thunk as argument. This `Lazy` object serves as delegate for implementing a lazy property. Delegation is expressed by using the `by` keyword.

```
val x: Int by lazy { expensiveOp() }

fun useIt() =
    if (x > 10) "hi"
    else if (x == 0) "zero"
    else ("lo")
```

+   1. The `by` keyword is used to bind the `Lazy<Int>` returned by `lazy` to x
+   2. When x is evaluated in the conditional statement, the call to `expensiveOp` will be made and the result cached
+   3. Cached value is used instead of making another call to `expensiveOp`

The lazy property x is initialized on first access by executing `expensiveOp` inside the lambda thunk that was passed into the `lazy` function. The result is then cached inside the delegate object for subsequent evaluations to take advantage of.

Access to the thunk is thread-safe by default using concurrent locks, but the behavior can be altered by using different lazy thread-safe modes. The use of these modes is beyond the scope of this sidebar, but is well documented on the Kotlin website²⁴.
