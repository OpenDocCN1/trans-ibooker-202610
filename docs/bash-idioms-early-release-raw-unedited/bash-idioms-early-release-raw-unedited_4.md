Bash 提供了许多不同的方式来做同一件事——以及一些几乎相同的语法来做完全不同的事情。通常，只是一个或几个特殊字符的区别。我们已经看到 `${VAR}` 和 `${#VAR}`，其中第一个表达式返回变量的值，但第二个返回其字符串长度。其他 bash 习惯用法可能会让你想知道：什么时候应该使用两个或只有一个方括号？甚至不用？`(( ... ))` 和 `$(( ... ))` 有什么区别，如果有的话？通常符号在各种用途中都有共同含义，这暗示了语法背后的一定合理性。有时表达式的选择更多是出于历史原因。让我们看看是否能解释一些这些习惯用法和算术表达式。

## Arithmetic

虽然 bash 在很大程度上是一个以字符串为导向的语言，但每当你在 bash 中看到双括号时，就意味着正在进行算术求值——用数字而不是字符串算术。这你从使用双括号的 for 循环变体中就熟悉了：

```
for((i=0; i<size; i++))
```

注意我们在双括号内使用变量名时不需要在前面加上 $。这在 bash 中使用双括号时始终如此。那么我们还在哪里使用双括号呢？

首先，我们可以使用美元符号和双括号来对 shell 变量进行算术计算以创建值，像这些：

```
max=$((intro + body + outro - 1))
median_loc=$((len / 2))
```

再次注意，变量在双括号内使用时不需要美元符号引用。

其次，考虑双括号的这种用法：

```
if (( max - 3 > x * 4 )) ; then
  # do something here
fi
```

这次我们使用的是没有前导美元符号的双括号。为什么？有什么不同？

在第一种情况下，用于变量赋值，我们想要表达式的值，所以就像变量一样，美元符号表示我们想要值。在第二种情况下，if 语句，我们不使用美元符号，因为我们只需要做出决策的真/假二进制。如果双括号内（没有美元符号）的表达式是非零值，则





## 关于空格的提醒

在 bash 变量赋值中，等号前后不允许有空格。对于变量赋值而言，从语法上讲，它必须全部是一个“单词”。不过，在括号内部使用空格是可以的，因为括号定义了该“单词”的边界。

现在还有一个算术变体——可能是出于历史原因。你可以使用 shell 内置的 let 来像双括号那样工作，但不需要美元符号。比较下面这些等价的语句：

```
(( step++ ))    # is the same as:
let "step++"

(( median_loc = len / 2 ))    # is the same as:
let "median_loc = len / 2"

(( dist *= 4 ))    # is the same as:
let "dist*=4"
```

但要小心——如果你没有对 let 表达式使用引号，那么最好在该表达式中完全不要有空格。（我们示例中的第一个 let 不需要引号，但养成始终使用引号的好习惯。）空格会将你的命令拆分为单独的词，而 let 只接受一个词，所以如果有不止一个词，你会得到语法错误。

## 不需要括号

我们说过 bash 是一个面向字符串的语言，但有一种方法可以例外。你可以这样声明一个变量为整数：declare -i MYVAR，并且在这样做之后，你可以在不使用双括号且变量名前不加 $ 的情况下对其进行算术赋值以赋予其值。下面是一个例子，脚本 seesaw.sh：

```
declare -i SEE
X=9
Y=3
SEE=X+Y            # only this one will be arithmetic
SAW=X+Y            # this is just a literal string
SUM=$X$Y           # this is string concatenation
echo "SEE = $SEE"
echo "SAW = $SAW"
echo "SUM = $SUM"
```

如果你运行这些语句，会看到 bash 大多是面向字符串的。SAW 和 SUM 的值是通过字符串操作形成的。只有 SEE 是通过算术运算赋值的。

```
$ bash seesaw.sh
SEE = 12
SAW = X+Y
SUM = 9+3
$
```

这表明你可以在不需要双括号的情况下进行算术运算——但我们通常会避免这种做法，因为它要求你将赋值的变量声明为整数。如果你忘记了 declare 语句，或者将此类表达式赋给未如此声明的变量，你不会得到任何错误信息——只会得到不想要的结果。

## 仅限整数

bash shell 只使用整数运算。它的主要用途是计数：迭代次数、文件数量、字节大小。如果想要或需要浮点计算怎么办？毕竟 sleep 命令现在允许分数值：`sleep 0.25` 会休眠四分之一秒。如果想休眠四分之一秒的倍数怎么办？你可能想写：`sleep $(( 6 * 0.25 ))` 但这行不通。

最简单的解决方案是使用另一个程序如 `bc` 或 `awk` 来进行计算。例如，这里有一个名为 `fp` 的脚本，你可以把它放在你的 `~/bin` 目录或 `PATH` 上的其他位置（并赋予执行权限）：

```
#### /bin/bash -
#### fp - provide floating point, via awk
#### usage:  fp "expression"

awk "BEGIN { print $* }"
```

有了它之后，你就可以写：`sleep $(fp "6 * 0.25")` 来得到期望的浮点计算。可能不是 bash 在做计算，但 bash 帮助你完成了计算。

## 复合命令

你可能非常熟悉在脚本中看到一行单独的命令。你可能也熟悉在 `if` 语句的条件中使用单个命令来查看命令是否成功，并根据结果采取行动。如果你读过第 1 章，你也见过“无 if” 的 `if` 语句惯用法。现在让我们看看简单的单命令 if 语句，它看起来像这样：

```
if cd $DIR ; then # do something ...
```

那这些呢：

```
if [ $DIR ]; then # do something ...
if [[ $DIR ]]; then # do something ...
```

为什么这个第二个例子中有方括号而第一个没有？有什么区别？一对方括号和两对方括号有什么区别；你应该在什么时候使用哪一种，为什么？

如果没有方括号，发生的事情是执行一个命令（我们示例中的 cd）。该命令的成功或失败会作为 if 在其决策分支中使用的 true 或 false 返回，在 then 或 else（如果有）之间进行选择。在 bash 中，你可以在 if 语句中放置整个命令管道（例如 cmd | sort | wc ）。是管道中最后一个命令的返回状态决定了 if 语句是 true 还是 false。

单对方括号语法实际上也在运行一个命令，即 shell 内置的 test 命令。单左方括号是 shell 内置的 test 命令的另一种形式，但有一个区别：需要一个最终参数 ]。双对方括号语法在技术上是一个 bash 关键字，它表示一个复合命令，其行为与单对方括号和 test 命令非常相似，但并不完全相同。

我们使用单对方括号或双对方括号语法来进行一些逻辑和比较，即条件表达式。我们用它们来检查事物的状态，例如文件是否存在，或具有某些权限，或 shell 变量是否有值或没有。有关可以进行的测试和检查的完整列表，请参阅 bash 手册页中“CONDITIONAL EXPRESSIONS”部分。

我们上面的例子是在检查 DIR 变量是否具有非空值。另一种写法是：

```
if [[ -n $DIR ]]; then ...
```

以查看值是否非空，即长度不为零。

相反，要查看变量的值是否为零长度，即未设置或为空，使用：

```
if [[ -z $DIR ]]; then ...
```

那么单对方括号测试和双对方括号测试之间有什么区别呢？只有少数几个，但它们可能很重要。

也许最大的区别是双对方括号语法支持一个额外的比较运算符 =~，它允许使用正则表达式。

```
if [[ $FN =~ .*xyzz*.*jpg ]]; then ...
```

## 正则表达式

这是 bash 中唯一可以找到正则表达式的地方！记住：不要将正则表达式放在引号中，否则你将逐字匹配这些字符，而不是作为正则表达式。

单对方括号和双对方括号之间的另一个区别更具风格，但会影响可移植性。这两种形式做同样的事情。

```
if [[ $VAR == "literal" ]]; then ...
```

```
if [ $VAR = "literal" ]; then ...
```

对于 C 和 Java 程序员来说，使用单等号进行比较可能看起来不自然，但在 bash 条件表达式中，= 和 == 含义相同。单等号在单对方括号语法中是首选，以符合 POSIX 标准（bash 手册页是这样说的）。

## 一种微妙的差异

在双对方括号内，< 和 > 运算符使用“当前区域设置进行词法比较”，而 test（和 [ ）使用简单的 ASCII 顺序进行比较。

你在使用单对方括号时也可能需要转义这些运算符（像这样：if [ $x \> $y ] ），否则它们将被视为重定向。为什么？因为单对方括号（和 test 命令）是内置命令而不是关键字，所以 bash 将其视为运行命令——而运行命令时可以重定向 I/O。然而，当 bash 看到双对方括号时，这是一个关键字，它知道要期望此类运算符并且不会将其视为重定向。因此，在这两种语法形式中，我们更喜欢双对方括号语法。

单对方括号和双对方括号表达式都可以使用一种更旧的、更像 FORTRAN 的语法来进行数值比较。例如，它们使用 -le 表示小于或等于比较。这里又出现了一个区别。单对方括号表达式中该运算符两侧的参数必须是简单的整数。使用双对方括号时，每个操作数可以是一个更大的算术表达式，尽管如果未加引号则不能有空格。例如：

```
if [[ $OTHERVAL*10 -le $VAL/5 ]] ; then ...
```



如果要进行算术表达式和比较运算，更好的选择是使用双括号语法。这样可以获得更熟悉的 C/Java/Python 风格的比较运算符，并且对空格的使用更自由：

```
if (( OTHERVAL * 10 <= VAL / 5 )) ; then ...
```

## Style and Readability

面对如此多的选择，你应该选择哪种 if 语句风格？我们选择最适合所考虑计算的风格。当表达式非常数学化时，我们使用双括号。由于在双括号内部获取变量值时不需要使用 $，我们会尽量一致地省略它们。对于文本密集的比较，我们使用双括号，特别是因为这样可以让我们使用正则表达式。

对于算术表达式，有些人可能更喜欢在表达式周围使用双括号，与 if 语句保持一致。然而，对于其他人来说，简单的 let 内置命令读起来更清晰简洁。虽然 bash 在变量声明为仅整数时允许不使用括号或 let 的算术运算，但我们避免这种风格。很容易混用变量，其中一些可能未声明为整数。由此会产生混淆。将表达式放在双括号中（或使用 let）可以保证它始终保持算术求值。

## Summary

作为一条规则，在 bash 中，双括号表示正在进行算术运算。美元符号表示你想要返回表达式的值，否则你只会得到成功/失败的结果状态。但运算符丰富的 bash 使得使用以下两种方式做类似的事情成为可能

双括号语法或 `let` 内置命令。你可以冒险通过将变量声明为整数来跳过双括号，但我们不能推荐这样做。

对于条件判断，更新的 [ [ 语法要比 [ 好得多。然而，如果你的条件是算术比较，更好的选择甚至是 ( ( 语法。
