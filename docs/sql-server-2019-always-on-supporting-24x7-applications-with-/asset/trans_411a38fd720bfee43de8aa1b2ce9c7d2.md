
# SQL Server 故障转移群集向导安装

## Microsoft Update 页面

全局规则现在将被检查，以确保设置支持文件可以成功安装。当所有检查通过后，如图 [4-4](#394392_3_En_4_Chapter.xhtml#Fig4) 所示的向导的 Microsoft Update 页面，将提示您选择是否希望 Windows Update 检查 SQL Server 补丁和热修复。此处的选择将取决于您组织的补丁策略。一些组织实施严格的补丁制度用于补丁的测试和验收，然后是补丁周期，这通常由 `WSUS`（Windows Server Update Services）等软件支持。如果您组织中存在此类制度，则不应选择此选项。 ![图 4-4 ¶ 安装 SQL Server 故障转移群集向导 – Microsoft Update 页面](images/394392_3_En_4_Chapter/394392_3_En_4_Fig4_HTML.jpg)

## 产品更新页面

如果您选择检查更新，并且发现任何可用更新，则向导的产品更新页面将列出找到的任何可用更新。您应使用复选框确认是否应安装它们。

在设置支持文件和任何产品更新（如果适用）下载、提取并安装后，将检查故障转移群集实例的安装规则，并将结果显示在向导的安装故障转移群集规则页面上，如图 [4-5](#394392_3_En_4_Chapter.xhtml#Fig5) 所示。 ![图 4-5 ¶ 安装 SQL Server 故障转移群集向导 – 安装故障转移群集规则](images/394392_3_En_4_Chapter/394392_3_En_4_Fig5_HTML.jpg)

图 4-5 ¶ 安装 SQL Server 故障转移群集向导 – 安装故障转移群集规则

如果您看到 Windows 防火墙的警告，这可能只是因为防火墙已打开。它并不表示所需的端口未打开。有关为 SQL Server 配置防火墙的更多信息，我推荐 Apress 出版的书籍 *Securing SQL Server 2nd Edition: DBAs Defending the Database*，该书可从 [`www.apress.com/gb/book/9781484241608`](http://www.apress.com/gb/book/9781484241608) 获取。

在此实例中，我们看到群集验证的警告。这是在群集验证通过但带有警告时造成的。在我们的例子中，这是因为群集节点上的修补程序未更新。理想情况下，应在继续之前解决此问题。

## 功能选择页面

在向导的功能选择页面上，如图 [4-6](#394392_3_En_4_Chapter.xhtml#Fig6) 所示，您将选择要安装的 SQL Server 2019 产品套件的功能。为本书的目的，我们将选择安装数据库引擎和 SQL Server Integration Services (`SSIS`)。 ![图 4-6 ¶ 安装 SQL Server 故障转移群集向导 – 功能选择页面](images/394392_3_En_4_Chapter/394392_3_En_4_Fig6_HTML.jpg)

图 4-6 ¶ 安装 SQL Server 故障转移群集向导 – 功能选择页面

值得注意的是，`SSIS` 不具备群集感知功能，也不是为群集而设计的。在某些情况下，您可能会决定对 Integration Services 服务进行群集，如果是这种情况，则可以通过创建类型为 `Generic` 的群集角色并将 Integration Services 服务添加为依赖项来解决此限制。然而，在大多数情况下，管理群集实例上的 `SSIS` 的最合适方法是在群集的每个节点上将 Integration Services 服务作为独立服务安装。

此外，向导的功能选择页面要求您指定实例根文件夹和共享功能文件夹的位置。您可能希望将它们移动到不同的驱动器，以便将 `C:\\` 驱动器留给操作系统。这可能是出于空间原因的考虑，或者只是为了将 SQL Server 二进制文件与其他应用程序隔离。

实例根目录通常包含您在服务器上创建的每个实例的文件夹，并且数据库引擎、`SSAS` 和 `SSRS` 安装将有单独的文件夹。与数据库引擎关联的文件夹将称为 `MSSQL15.[InstanceName]`，其中实例名称是实例的名称，或对于默认实例为 `MSSQLSERVER`。文件夹名称中的数字 15 与 SQL Server 的版本相关，对于 SQL Server 2019 为 15。

该文件夹将包含一个名为 `MSSQL` 的子文件夹，其中反过来将包含存储与实例关联的文件的文件夹，包括一个名为 `Binn` 的文件夹，其中包含与实例关联的应用程序文件、应用程序扩展和 XML 配置；一个名为 `Backup` 的文件夹，将是数据库备份的默认位置；以及一个名为 `Data` 的文件夹，将是系统数据库的默认位置。

`TempDB`、用户数据库和备份的默认文件夹可以在安装过程中稍后修改，将这些数据库拆分到单独的卷中通常是一个良好的实践，但如果您的数据位于 SAN 上（如第 [3](#394392_3_En_3_Chapter.xhtml) 章所述），则可能不是必要的（甚至不可能）。这里还将创建其他文件夹，包括一个名为 `LOGS` 的文件夹，将是错误日志和默认扩展事件运行状况跟踪文件的默认位置。

如果您在 64 位环境中安装 SQL Server，您将被要求输入共享功能目录的 32 位和 64 位版本的文件夹。这是因为某些 SQL Server 组件始终作为 32 位进程安装。32 位和 64 位组件不能共享目录，因此要继续安装，您必须为这些选项中的每一个指定不同的文件夹。共享功能目录成为所有 SQL Server 实例共享的功能的根级目录，例如 `SDKs` 和管理工具。

## 实例配置页面

检查所选功能的安装规则，如果所有规则都通过，则将显示实例配置页面，如图 [4-7](#394392_3_En_4_Chapter.xhtml#Fig7) 所示。在向导的此页面上，您将指定实例的名称。由于实例将被群集，此页面还要求您指定实例的网络名称。在此场景中，我们将安装 SQL Server 的默认实例，这意味着我们无需指定实例名称。我们将分配 `ALWAYSON-SQL-C` 作为网络名称。 ![图 4-7 ¶ 安装 SQL Server 故障转移群集向导 – 实例配置页面](images/394392_3_En_4_Chapter/394392_3_En_4_Fig7_HTML.jpg)

图 4-7 ¶ 安装 SQL Server 故障转移群集向导 – 实例配置页面

### 提示

SQL Server 使用术语群集资源组来描述群集角色。群集角色是 Microsoft 的较新术语，在本章中，这两个术语应视为同义。

## 群集资源组页面

在向导的群集资源组页面上，我们可以选择现有群集资源组（这提供了 Windows 管理员预先创建资源组的选项）或输入新资源组的名称，然后由设置创建。在我们的例子中，我们将指定 `ALWAYSON-SQL-C` 作为新资源组的名称。这如图 [4-8](#394392_3_En_4_Chapter.xhtml#Fig8) 所示。 ![图 4-8 ¶ 安装 SQL Server 故障转移群集向导 – 群集资源组页面](images/394392_3_En_4_Chapter/394392_3_En_4_Fig8_HTML.jpg)

图 4-8 ¶ 安装 SQL Server 故障转移群集向导 – 群集资源组页面

### 提示

现有资源组将在 Qualified 列中用红色或绿色指示器标记。如果标记为红色，则意味着无法将该资源组用于 SQL Server 实例。在这种情况下，Message 列将指示原因。
