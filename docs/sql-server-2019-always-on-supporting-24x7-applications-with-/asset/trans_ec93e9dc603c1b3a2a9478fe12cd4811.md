
# 启用 AlwaysOn 可用性组

配置 AlwaysOn 可用性组的首要步骤是在 SQL Server 服务上启用此功能。要从 GUI 启用该功能，我们打开 SQL Server 配置管理器，依次展开 SQL Server 服务，并从 SQL Server 服务的上下文菜单中选择属性。这样操作后，服务属性会显示出来，我们导航到 Always On 可用性组 选项卡，如图 [5-1](#394392_3_En_5_Chapter.xhtml#Fig1) 所示。![图 5-1 ¶ Always On 可用性组选项卡](images/394392_3_En_5_Chapter/394392_3_En_5_Fig1_HTML.jpg)

图 5-1 ¶ Always On 可用性组选项卡

在此选项卡中，我们勾选“启用 AlwaysOn 可用性组”复选框，并确保 Windows 故障转移群集名称 框中显示的群集名称正确。然后我们需要重启 SQL Server 服务。因为 AlwaysOn 可用性组使用的是独立实例，这些实例安装在每个群集节点上，而非跨多个节点的故障转移群集实例，因此我们需要对群集上托管的每个独立实例重复这些步骤。

我们也可以使用 PowerShell 来启用 AlwaysOn 可用性组。为此，我们使用列表 [5-2](#394392_3_En_5_Chapter.xhtml#PC2) 中的 PowerShell 命令。该脚本假定 `CLUSTERNODE1` 为服务器名称，`PROD` 为 SQL Server 实例名称。

```
Enable-SqlAlwaysOn -Path SQLSERVER:\\SQL\\CLUSTERNODE1\\PROD
```

下一步是对将成为可用性组一部分的所有数据库进行完整备份。在完成此操作之前，我们无法将它们添加到可用性组。在本章中，我们将创建三个独立的可用性组。然而在第一个示例中，我们将创建一个名为 `HR` 的可用性组，为 `HR` 数据库提供高可用性。因此，我们需要备份 `HR` 数据库。我们通过运行列表 [5-3](#394392_3_En_5_Chapter.xhtml#PC3) 中的脚本来完成此操作。

```
BACKUP DATABASE HR TO DISK = N'C:\\Backups\\HR.bak' WITH NAME = N'HR-Full Database Backup' ; GO
```

## 使用新的可用性组向导

当备份成功完成后，我们通过在 SSMS 中的对象资源管理器中依次展开 AlwaysOn 高可用性，并从可用性组文件夹的上下文菜单中选择“新建可用性组向导”来调用新建可用性组向导。向导的“介绍”页会显示出来，为我们概述需要执行的操作步骤。

在“指定名称”页（见图 [5-2](#394392_3_En_5_Chapter.xhtml#Fig2)）中，我们会被提示输入可用性组的名称。我们还将选择 Windows Server 故障转移群集 作为群集类型。群集类型的其他选项包括 external，它支持 Linux 上的 Pacemaker，以及 None，用于无群集可用性组。数据库级运行状况检测 选项将在组内任何数据库脱机时导致可用性组故障转移。每数据库 DTC 支持 选项将指定是否使用 MSDTC（Microsoft 分布式事务协调程序）支持跨数据库事务。关于配置 DTC 的完整讨论超出了本书范围，但更多详细信息可在 [https://docs.microsoft.com/en-us/previous-versions/windows/desktop/ms681291(v=vs.85)](https://docs.microsoft.com/en-us/previous-versions/windows/desktop/ms681291%2528v%253Dvs.85%2529) 找到。![图 5-2 ¶ 指定名称页](images/394392_3_En_5_Chapter/394392_3_En_5_Fig2_HTML.jpg)

图 5-2 ¶ 指定名称页

在“选择数据库”页中，我们会被提示选择希望参与可用性组的数据库，如图 [5-3](#394392_3_En_5_Chapter.xhtml#Fig3) 所示。在此屏幕上请注意，我们无法选择 Sales、Customers 或 Accounts 数据库，因为我们尚未对这些数据库进行完整备份。![图 5-3 ¶ 选择数据库页](images/394392_3_En_5_Chapter/394392_3_En_5_Fig3_HTML.jpg)

图 5-3 ¶ 选择数据库页

“指定副本”页包含五个选项卡。我们使用第一个选项卡“副本”将辅助副本添加到拓扑中。勾选“同步提交”选项会使数据在主副本上提交之前先在辅助副本上提交。（这也被称为在主副本之前对辅助副本 *硬化日志*。）这意味着在发生故障转移时不会发生数据丢失，即我们可以满足 RPO（恢复点目标）为零的 SLA（服务级别协议）。然而，这也意味着性能会下降。如果我们选择异步提交，则副本以异步提交模式运行。这意味着数据在辅助副本上提交之前先在主副本上提交。这可以避免性能下降，但也意味着在发生故障转移时，RPO 是不确定的。

当我们勾选“自动故障转移”选项时，如果尚未选择，则“同步提交”选项也会自动被选中。这是因为自动故障转移仅在同步提交模式下才可能实现。我们可以将“可读辅助副本”下拉菜单设置为 No、Yes 或 Read-intent。当设置为 No 时，数据库在处于辅助角色的副本上不可访问。当设置为 Read-intent 时，可用性组侦听器可以将只读工作负载重定向到此辅助副本，但前提是应用程序在连接字符串中指定了 `Application Intent=Read-only`。将其设置为 Yes 可使侦听器重定向只读流量，而不管应用程序的连接字符串中是否存在 Application Intent 参数。尽管我们可以在配置副本进行自动故障转移的同时通过 GUI 更改 Readable Secondary 的值而不会报错，但这只是向导的一个怪癖。实际上，副本不可访问，因为在配置为自动故障转移时不支持活动辅助副本。副本选项卡如图 [5-4](#394392_3_En_5_Chapter.xhtml#Fig4) 所示。为了满足对 `HR` 数据库实现高可用的要求，我们已将同一站点内的辅助服务器配置为同步副本。这意味着数据中心之间的延迟不会加剧与同步提交相关的性能下降。![图 5-4 ¶ 副本选项卡](images/394392_3_En_5_Chapter/394392_3_En_5_Fig4_HTML.jpg)

图 5-4 ¶ 副本选项卡

在“指定副本”页的“端点”选项卡中，如图 [5-5](#394392_3_En_5_Chapter.xhtml#Fig5) 所示，我们为每个端点指定端口号。默认端口为 5022，但如果需要，我们可以指定不同的端口。在此选项卡中，我们还指定在端点之间传输数据时是否应加密。通常最好勾选此选项，如果勾选，则使用 AES（高级加密标准）作为加密算法。![图 5-5 ¶ 端点选项卡](images/394392_3_En_5_Chapter/394392_3_En_5_Fig5_HTML.jpg)

图 5-5 ¶ 端点选项卡

可选地，您还可以更改所创建端点的名称。然而，由于每个实例只允许一个数据库镜像端点，并且默认名称相当具有描述性，因此不总是需要更改它。一些 DBA 选择重命名它以包含实例名称，因为这可以简化多个服务器的管理。如果您的企业在同一群集上的多个实例中拆分了多个可用性组，这是一个好主意。
