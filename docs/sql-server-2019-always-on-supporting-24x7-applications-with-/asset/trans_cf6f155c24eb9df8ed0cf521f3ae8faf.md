
# Azure 负载均衡器配置

## 概述和层级选择

Azure 负载均衡器有两个层级，功能各不相同。Basic 是较便宜的层级，功能更有限，而 Standard 是较高的层级。由于我们的服务器位于可用区，因此必须使用标准负载均衡器。

## 创建负载均衡器

要创建负载均衡器，请在 Azure 中导航到“负载均衡器”刀片并选择“添加”按钮，以创建新的负载均衡器。在“创建负载均衡器”页面的第一部分中，如图 [7-13](#394392_3_En_7_Chapter.xhtml#Fig13) 所示，我们指定要创建负载均衡器的订阅和资源组。这应与您的 VM 所在的资源组相匹配。 ![图 7-13 ¶ 创建负载均衡器（第 1 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig13_HTML.jpg)

图 7-13 ¶ 创建负载均衡器（第 1 部分）

然后我们为负载均衡器提供名称并指定其应创建的区域。这应与您的 VM 的位置相匹配。我们还选择要创建的负载均衡器的层级。

## 网络配置

在页面的下一部分（图 [7-14](#394392_3_En_7_Chapter.xhtml#Fig14)），我们指定负载均衡器的网络详细信息。具体来说，我们指定其应驻留的虚拟网络，这应与您的 VM 的虚拟网络相匹配。我们还指定应使用静态还是动态 IP 地址。对于我们的目的，我们需要静态 IP 地址，因此需要指定该地址应为哪个地址。最后，我们指定负载均衡器的公共 IP 地址是否应创建在可用区中，或是否应使用区域冗余路径。 ![图 7-14 ¶ 创建负载均衡器（第 2 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig14_HTML.jpg)

图 7-14 ¶ 创建负载均衡器（第 2 部分）

在“标签”页面，我们可以根据公司政策指定键/值对，然后在“查看”页面上查看我们的配置。

## 后端池

现在我们需要为负载均衡器创建一个后端池。这可以通过在 Azure 门户中导航到负载均衡器刀片的“后端池”选项卡并使用“添加”按钮来实现，以调用如图 [7-15](#394392_3_En_7_Chapter.xhtml#Fig15) 所示的“添加后端池”页面。 ![图 7-15 ¶ 添加后端池](images/394392_3_En_7_Chapter/394392_3_En_7_Fig15_HTML.jpg)

图 7-15 ¶ 添加后端池

## 健康探测

现在我们可以创建一个健康探测，它将对每个节点执行连接检查。我们可以通过导航到负载均衡器刀片上如图 [7-16](#394392_3_En_7_Chapter.xhtml#Fig16) 所示的“健康探测”选项卡来完成此操作。在这里，我们为探测指定名称并提供协议和未使用的端口，健康检查将使用该端口连接到节点。然后我们指定健康检查应运行的频率以及导致节点被标记为不健康的同时失败次数。如果节点被标记为不健康，负载均衡器将不会向其发送任何请求。 ![图 7-16 ¶ 添加健康探测](images/394392_3_En_7_Chapter/394392_3_En_7_Fig16_HTML.jpg)

图 7-16 ¶ 添加健康探测

## 负载均衡规则

接下来，我们将使用负载均衡器刀片的“负载均衡器规则”选项卡上的“添加”按钮配置新的负载均衡规则。在此刀片的第一部分（图 [7-17](#394392_3_En_7_Chapter.xhtml#Fig17)）中，我们将为规则指定名称，以及负载均衡器应使用 IPv4 还是 IPv6。前端 IP 地址是我们之前配置的负载均衡器的 IP 地址。HA 端口允许后端池的所有端口进行负载均衡，但我们不想这样做，因此我们将保持该框未选中并选择 TCP 作为协议。 ![图 7-17 ¶ 配置负载均衡规则（第 1 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig17_HTML.jpg)

图 7-17 ¶ 配置负载均衡规则（第 1 部分）

在此页面的第二部分，如图 [7-18](#394392_3_En_7_Chapter.xhtml#Fig18) 所示，我们将配置负载均衡器将监听的端口，然后是后端池中服务器将监听的端口。在我们的例子中，这两者都将是端口 1433。我们将选择我们刚刚创建的服务器后端池和健康探测。 ![图 7-18 ¶ 配置负载均衡规则（第 2 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig18_HTML.jpg)

图 7-18 ¶ 配置负载均衡规则（第 2 部分）

会话持久性指定应如何处理来自客户端的连续请求。如果我们选择客户端 IP，则来自同一 IP 地址的连续请求将由同一服务器处理。如果我们选择客户端 IP 和协议，则来自同一客户端的连续请求将由同一服务器处理，但前提是使用相同的协议进行连接。对于可用性组而言，会话持久性不是必需的，因此我们将选择“无”。这表示同一客户端的连续请求可以由后端池中的任何服务器处理。

空闲超时表示在客户端未发送消息的情况下连接将被保持打开的最小时间长度，我们将保持 TCP 重置处于禁用状态。最后，我们将选择浮动 IP，这会更改 IP 地址映射模式，允许多个侦听器，这对于可用性组侦听器是必需的。

您应重复此过程为核心集群添加前端端口和负载均衡规则。

## 可用性组侦听器

然后我们将处于可以配置可用性组侦听器的位置。我们将从集群管理器中执行此操作。从“销售角色”的上下文菜单中，钻取“添加资源”并选择“客户端访问点”。这将导致显示“新建资源客户端访问点”向导。在此向导的第一页上，为客户端访问点提供名称并分配 IP 地址。由于我们为每个 VM 创建了不同的子网，因此我们需要为每个子网提供 IP 地址，如图 [7-19](#394392_3_En_7_Chapter.xhtml#Fig19) 所示。 ![图 7-19 ¶ 创建新的客户端访问点 – 客户端访问点页面](images/394392_3_En_7_Chapter/394392_3_En_7_Fig19_HTML.jpg)

图 7-19 ¶ 创建新的客户端访问点 – 客户端访问点页面

当我们进入向导的确认页面时，我们的网络设置将被验证。确认页面显示我们将要配置的摘要。

一旦创建了客户端访问点，我们应使用角色的资源选项卡下“其他资源”中显示的可用性组资源的属性对话框的“依赖项”选项卡来添加对客户端访问点的依赖项，如图 [7-20](#394392_3_En_7_Chapter.xhtml#Fig20) 所示。 ![图 7-20 ¶ 添加依赖项](images/394392_3_En_7_Chapter/394392_3_En_7_Fig20_HTML.jpg)

您还应重复此过程使客户端访问点依赖于 IP 地址资源。

## 集群与负载均衡器的集成

接下来，我们需要配置集群以与 Azure 负载均衡器配合使用。我们可以使用列表 [7-2](#394392_3_En_7_Chapter.xhtml#PC2) 中的脚本来完成此操作。此脚本使用负载均衡器 IP 和健康探测端口更新每个 IP 地址资源。

**注意**
请务必在运行脚本之前将其更新以匹配您自己的配置。

```powershell
$ClusterNetworkName = 'AlwaysOnAzure'
$LoadBalancerIP = '10.0.10.10'
[int]$LoadBalancerProbePort = 50001
Get-ClusterResource 'IP Address 10.0.0.35' | Set-ClusterParameter -Multiple @{"Address"="$LoadBalancerIP";"ProbePort"=$LoadBalancerProbePort;"SubnetMask"="255.255.255.0";"Network"="$ClusterNetworkName";"EnableDhcp"=0}
Get-ClusterResource 'IP Address 10.0.0.35' | Set-ClusterParameter -Multiple @{"Address"="$LoadBalancerIP";"ProbePort"=$LoadBalancerProbePort;"SubnetMask"="255.255.255.0";"Network"="$ClusterNetworkName";"EnableDhcp"=0}
```
