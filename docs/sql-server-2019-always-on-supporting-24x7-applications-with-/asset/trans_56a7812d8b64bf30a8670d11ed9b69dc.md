
在摘要页面上单击“完成”会返回到创建群集向导，在那里您会看到“用于管理群集的访问点”页面。此屏幕在图 [3-15](#394392_3_En_3_Chapter.xhtml#Fig15) 中示意。在此页面上，您需要输入群集的虚拟名称。我们将把群集命名为 `ALWAYSON-C`。如果网络卡配置为自动获取 IP 地址，则 IP 地址将通过 DHCP 分配。否则，您需要手动输入 IP 地址。这称为静态 IP，因为它会保持不变，而通过 DHCP 分配的 IP 地址可能会更改。我强烈建议为群集访问点使用静态 IP 以避免动态路由问题，但在群集创建后也可以更改。

![图 3-15 ¶ 用于管理群集的访问点页面](images/394392_3_En_3_Chapter/394392_3_En_3_Fig15_HTML.jpg)

图 3-15 ¶ 用于管理群集的访问点页面

注意
虚拟名称和 IP 地址绑定到当前活动的节点，这意味着在故障转移情况下群集始终可访问。

在我们的例子中，群集位于一个简单的域、一个站点和一个子网内。但是，如果您正在配置多子网群集，则向导会检测到这一点，并且每个子网都需要 IP 地址。在这种情况下，您需要为每个子网输入一个 IP 地址。

注意
节点内的两块 NIC 配置在不同的子网上，以便节点之间的心跳与公共网络隔离。但是，只有当群集节点的数据 NIC 位于不同的子网中时，群集才被视为多子网。

提示
如果您的群集将位于域中，并且您没有权限在包含群集的 OU（组织单位）中创建 AD（Active Directory）对象，则群集的 VCO（虚拟计算机对象）必须已存在，并且您必须已分配“完全控制”权限。

## 配置群集

许多群集配置可以根据您环境的需求进行更改。本节演示如何更改一些更常见的配置。

### 更改仲裁

如果我们在故障转移群集管理器中检查群集存储，通过钻取 `ALWAYSON-C` ➤ 存储 ➤ 磁盘并突出显示分配给仲裁的磁盘，我们可以看到见证已正确配置为使用仲裁卷。这在图 [3-18](#394392_3_En_3_Chapter.xhtml#Fig18) 中示意。

![图 3-18 ¶ 群集卷](images/394392_3_En_3_Chapter/394392_3_En_3_Fig18_HTML.jpg)

图 3-18 ¶ 群集卷

我们可以通过进入群集的上下文菜单并选择“更多操作” ➤ “配置群集仲裁设置”来修改此设置，这将调用“配置群集仲裁向导”。在图 [3-19](#394392_3_En_3_Chapter.xhtml#Fig19) 所示的“选择仲裁配置选项”页面上，我们选择“选择仲裁见证”选项。

![图 3-19 ¶ 选择仲裁配置选项页面](images/394392_3_En_3_Chapter/394392_3_En_3_Fig19_HTML.jpg)

图 3-19 ¶ 选择仲裁配置选项页面

在“选择仲裁见证”页面上，我们选择要配置的仲裁类型。当群集中有偶数个节点并且所有节点都位于同一数据中心时，或当主数据中心中有偶数个节点且在辅助数据中心中还有另一个节点时，磁盘见证最为合适。

当节点分布在两个数据中心，并且您有权访问第三个数据中心，在那里可以提供文件共享作为仲裁时，文件共享见证最为合适。Windows Server 2019 支持在任何支持 SMB 2.0 或更高版本的设备上的文件共享。这包括可以连接到网络路由器的 USB 密钥。

当节点分布在两个数据中心，并且没有第三个数据中心可用于设置文件共享见证时，云见证最为合适。要使用云见证，您必须拥有 Azure 存储帐户，因为见证将创建在 Azure BLOB 存储中。

当单个数据中心中有奇数个节点时，最合适的做法是不配置见证。

对于我们的场景，我们将选择配置磁盘见证的选项。这在图 [3-20](#394392_3_En_3_Chapter.xhtml#Fig20) 中示意。

![图 3-20 ¶ 选择仲裁见证页面](images/394392_3_En_3_Chapter/394392_3_En_3_Fig20_HTML.jpg)

图 3-20 ¶ 选择仲裁见证页面

在向导的“配置存储见证”页面上，我们可以选择用作仲裁的正确磁盘。在我们的例子中，这是磁盘 4，如图 [3-21](#394392_3_En_3_Chapter.xhtml#Fig21) 所示。

![图 3-21 ¶ 配置存储见证页面](images/394392_3_En_3_Chapter/394392_3_En_3_Fig21_HTML.jpg)

图 3-21 ¶ 配置存储见证页面

向导的摘要页面详细说明将对群集进行的配置更改。它还强调动态仲裁管理已启用，并且所有节点加上仲裁磁盘在仲裁中都有投票权。

我们还可以使用清单 [3-3](#394392_3_En_3_Chapter.xhtml#PC3) 中的 PowerShell 命令从命令行执行此配置。在这里，我们使用 `Set-ClusterQuorum` cmdlet 并传入群集的名称，然后是希望配置的仲裁类型。因为磁盘包含在此仲裁类型中，所以我们还可以传入计划使用的群集磁盘的名称，正是这一方面使我们能够更改仲裁磁盘。

提示
如果使用 PowerShell 按照演示操作，请记住更改磁盘编号以匹配您自己的配置。

```
Set-ClusterQuorum -Cluster ALWAYSON-C -NodeAndDiskMajority "Cluster Disk 4"
```
