## 摘要

AlwaysOn 故障转移群集实例可以使用 SQL Server 安装中心或通过 `PowerShell` 安装。使用 SQL Server 安装中心时，流程与独立实例的安装非常相似；但是，您需要指定其他详细信息，例如网络名称、IP地址和资源组配置。

# 5. 在 Windows 上实现 AlwaysOn 可用性组

Peter A. Carter ([1](#394392_3_En_5_Chapter.xhtml#Aff2)) (1) Botley, UK
End Abstract

AlwaysOn 可用性组提供了一种灵活的选项，用于实现高可用性、从灾难中恢复以及扩展只读工作负载。该技术在数据库级别同步数据，健康监控和仲裁通常由 Windows 群集提供，尽管 Windows 群集不是强制性的。

AlwaysOn 可用性组有不同的变体。传统版本位于 Windows 故障转移群集上，但如果 SQL Server 安装在 Linux 上，则可以使用 Pacemaker。AlwaysOn 可用性组也可以在没有群集的情况下配置。这对于卸载报表是可以接受的，但不是有效的高可用性（HA）或灾难恢复（DR）配置。使用 SQL Server 2019 与 Windows Server 2019 时，可用性组甚至可以为容器化 SQL 配置，使用 Kubernetes。

本章重点介绍在 Windows 故障转移群集上配置可用性组，以提供 HA 和 DR 以及扩展只读工作负载。Linux 上的可用性组将在第 [6](#394392_3_En_6_Chapter.xhtml) 章中探讨。

### 注

对于本章中的演示，我们将使用第 [3](#394392_3_En_3_Chapter.xhtml) 章中构建的群集，但已向群集添加了两个额外节点：`CLUSTERNODE3` 和 `CLUSTERNODE4`。我们将不使用第 [4](#394392_3_En_4_Chapter.xhtml) 章中配置的故障转移群集实例。相反，每个节点上都安装了 SQL Server 的独立实例，名称如下：`CLUSTERNODE1\PROD`、`CLUSTERNODE2\SYNCHA`、`CLUSTERNODE3\ASYNCDR` 和 `CLUSTERNODE4\READSCALE`。群集节点 1 和 2 位于名为 Site1 的子网内，群集节点 3 和 4 位于名为 Site2 的不同子网内。实例将数据库数据和日志文件存储在 `C:\` 卷上。群集内的共享存储未用于这些实例。

在本章中，我们将执行以下活动：

* 创建 Sales、Customers、Accounts 和 HR 数据库。
* 在我们的实例上启用可用性组。
* 使用新建可用性组向导为 HR 数据库创建可用性组。此可用性组将仅配置为 HA。
* 使用新建可用性组对话框为 Sales 和 Customers 数据库创建可用性组。这将配置为 HA、DR 和只读扩展。
* 使用 `T-SQL` 为 Accounts 数据库创建可用性组。此可用性组将配置为 HA 和 DR，而不进行任何只读扩展。
* 我们还将讨论如何使用 `PowerShell` 创建可用性组。

## 准备实现 AlwaysOn 可用性组
