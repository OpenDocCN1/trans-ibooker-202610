
### 设置集群
第二个命令是 setup。该命令用于注册集群名称以及集群中的每个节点。集群名称使用 `--name` 参数指定，后跟节点列表。清单 [6-18](#394392_3_En_6_Chapter.xhtml#PC18) 说明了在我们的场景中如何使用 setup 命令。

**提示**
也可以指定 `--start` 参数来启动集群服务，但我们将选择使用单独的命令启动集群，以帮助说明完整流程。

```
sudo pcs cluster setup --name LinuxCluster LinuxProd LinuxSyncHA LinuxConfig
```
清单 6-18

### 启动集群服务
下一个命令是 start。正如您所期望的，它用于启动集群服务。该命令要么接受 `--all` 参数以在所有节点上启动服务（清单 [6-19](#394392_3_En_6_Chapter.xhtml#PC19) 中演示），要么接受节点列表，指定应在其中启动集群服务的节点。

```
sudo pcs cluster start --all
```
清单 6-19

### 检查集群状态
运行此命令后，服务启动前可能会有延迟。因此，在继续操作之前，您应运行 status 命令以确保集群已启动，如清单 [6-20](#394392_3_En_6_Chapter.xhtml#PC20) 所示。

```
sudo pcs cluster status
```
清单 6-20

### 启用集群服务
最后，我们将为每个节点配置集群服务在启动时运行。这可以通过使用 enable 命令实现，如清单 [6-21](#394392_3_En_6_Chapter.xhtml#PC21) 所示。该命令接受 `--all` 参数或节点列表。

```
sudo pcs cluster enable --all
```
清单 6-21

### 安装资源代理
现在集群已经创建，我们可以安装 SQL Server 资源代理。这允许 Pacemaker 与可用性组松散集成。具体来说，每当发生配置更改，例如故障转移或添加新副本时，它都会在 `sys.available_groups` 目录视图中递增一个序列号。然后在故障转移时查询该序列号，以在故障转移发生前确定节点是否是最新的。这允许在序列号不是最高时拒绝故障转移。清单 [6-22](#394392_3_En_6_Chapter.xhtml#PC22) 演示了如何安装资源代理。

```
sudo apt-get install mssql-server-ha
```
清单 6-22

### 保存 Pacemaker 凭据
接下来，我们需要为 Pacemaker 授予对可用性组的权限。我们在清单 [6-12](#394392_3_En_6_Chapter.xhtml#PC12) 中为 Pacemaker 创建了一个登录名。现在我们需要在集群中的所有节点上运行清单 [6-23](#394392_3_En_6_Chapter.xhtml#PC23) 中的脚本，将凭据保存在操作系统中。

```
echo 'pacemakerLogin' >> ~/pacemaker-passwd
echo 'Pa$$w0rd' >> ~/pacemaker-passwd
sudo mv ~/pacemaker-passwd /var/opt/mssql/secrets/passwd
sudo chown root:root /var/opt/mssql/secrets/passwd
sudo chmod 400 /var/opt/mssql/secrets/passwd
```
清单 6-23

### 创建集群资源
我们现在需要创建集群资源，既用于可用性组，也用于虚拟 IP 地址。这可以通过运行清单 [6-24](#394392_3_En_6_Chapter.xhtml#PC24) 中的脚本来实现。脚本中的第一个命令为 `LinuxAOAG` 可用性组创建可用性组资源。
脚本中的第二个命令为我们希望使用的 IP 地址创建资源。请注意，我们同时指定了 IP 地址和网络的网络掩码。网络掩码使用 CIDR 表示法指定。CIDR 表示法超出了本书的范围，但可以在 [www.controltechnology.com/Files/common-documents/application_notes/CIDR-Notation-Tutorial](http://www.controltechnology.com/Files/common-documents/application_notes/CIDR-Notation-Tutorial) 找到 CIDR 教程。

```
sudo pcs resource create LinuxAOAG ocf:mssql:ag ag_name=LinuxAOAG meta failure-timeout=60s master meta notify=true
sudo pcs resource create VirtualIP ocf:heartbeat:IPaddr2 ip=10.0.0.25 cidr_netmask=24
```
清单 6-24

**警告**
由于 Pacemaker 没有网络名称的概念，因此 IP 地址和所需名称必须手动在 DNS 中注册。

### 创建同位置约束
资源应在哪个节点上运行的决策基于分数，这些分数在资源级别计算。这意味着虚拟 IP 地址可能被移动到与可用性组资源不同的节点存在风险。为了降低此风险，我们需要添加一个同位置约束，以确保资源始终位于同一节点上。约束也有分数，低于无穷大的任何数字都是偏好，无穷大则是绑定要求。清单 [6-25](#394392_3_En_6_Chapter.xhtml#PC25) 中的命令将创建所需的约束。

```
sudo pcs constraint colocation add VirtualIP LimuxAOAG INFINITY with-rsc-role=Master
```
清单 6-25

### 创建排序约束
由于此命令将虚拟 IP 地址资源列在可用性组资源之前，当资源移动时，虚拟 IP 地址将被移动并上线，然后才移动并上线可用性组资源。这意味着虚拟 IP 地址可能暂时指向错误的节点。此风险可以通过添加排序约束来缓解，该约束强制在虚拟 IP 地址上线之前先移动可用性组资源。清单 [6-26](#394392_3_En_6_Chapter.xhtml#PC26) 演示了如何配置此约束。

```
sudo pcs constraint order promote LinuxAOAG then start VirtualIP
```
清单 6-26

### 创建可用性组侦听器
最后，我们可以创建可用性组侦听器。侦听器将使用我们在 Pacemaker 集群中创建的虚拟 IP 地址资源的 IP 地址。重要的是要记住，当可用性组配置在 Pacemaker 集群上时，可用性组侦听器的唯一目的是提供一个抽象，为副本提供单一入口点。它不会掩盖中断，因为在故障转移期间，在虚拟 IP 地址资源在另一个集群节点上启动时，它将暂时不可用。我们可以通过使用清单 [6-27](#394392_3_En_6_Chapter.xhtml#PC27) 中的脚本创建可用性组侦听器。

```
USE master
GO
ALTER AVAILABILITY GROUP LinuxAOAG ADD LISTENER 'LinuxAOListener'
(
    WITH IP (
        (N'10.0.0.25', N'255.255.255.0')
    )
    , PORT=1433
);
GO
```
清单 6-27

## 摘要
可用性组可以在基于 Linux 的实例上以与在基于 Windows 的实例上配置可用性组类似的方式进行配置。它们可以在没有底层集群的情况下配置，也可以使用基于 Linux 的集群技术。
如果需要高可用性或灾难恢复，则必须使用 Pacemaker 等 Linux 集群技术。Pacemaker 集群由多个组件组成，包括 `pcs`，用于管理 Pacemaker 集群的命令行实用程序；`Corosync`，提供节点之间的心跳；用于 fencing 的 `STONITH`；以及 `Pacemaker`，核心集群管理器。
Pacemaker 集群支持可用性组侦听器，但其功能有限。IP 地址资源在移动到新节点时暂时离线。因此，可用性组侦听器提供了一个抽象，但不会掩盖故障，因为它在一段时间内将无法访问。
