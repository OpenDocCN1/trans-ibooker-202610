
# 可用性组配置

仅配置节点不包含用户数据库的副本，但可用性组元数据会使用同步提交模式进行同步。仅配置节点可以使用任何版本的 `SQL Server`，包括 `SQL Server Express edition`，以避免额外成本。单个实例也可以作为多个可用性组的见证者。然而，单个可用性组永远只能有一个仅配置节点。

图 [6-2](#394392_3_En_6_Chapter.xhtml#Fig2) 显示了新建可用性组对话框的备份首选项页面。在这里，我们已配置从主节点获取备份。 ![图 6-2 ¶ 新可用性组对话框 – 备份首选项选项卡](images/394392_3_En_6_Chapter/394392_3_En_6_Fig2_HTML.jpg)

图 6-2 ¶ 新可用性组对话框 – 备份首选项选项卡

由于我们仅配置高可用性，因此无需配置只读路由。关于只读路由以及本文未讨论的其他配置选项的讨论，可在第 [5](#394392_3_En_5_Chapter.xhtml) 章找到。

另外，我们也可以通过 T-SQL 创建可用性组，使用列表 [6-8](#394392_3_En_6_Chapter.xhtml#PC8) 中的脚本。

```
USE master
GO
CREATE AVAILABILITY GROUP LinuxAOAG WITH (
      AUTOMATED_BACKUP_PREFERENCE = PRIMARY,
      DB_FAILOVER = OFF,
      DTC_SUPPORT = NONE,
      CLUSTER_TYPE = EXTERNAL,
      REQUIRED_SYNCHRONIZED_SECONDARIES_TO_COMMIT = 0
) FOR DATABASE Sales
REPLICA ON
      'linuxconfig' WITH (
            ENDPOINT_URL = 'TCP://linuxconfig.AlwaysOn.com:5022',
            AVAILABILITY_MODE = CONFIGURATION_ONLY
      ),
      'linuxprod' WITH (
            ENDPOINT_URL = 'TCP://linuxprod.AlwaysOn.com:5022',
            FAILOVER_MODE = EXTERNAL,
            AVAILABILITY_MODE = SYNCHRONOUS_COMMIT,
            SESSION_TIMEOUT = 10,
            BACKUP_PRIORITY = 50,
            SEEDING_MODE = MANUAL,
            PRIMARY_ROLE(ALLOW_CONNECTIONS = ALL),
            SECONDARY_ROLE(ALLOW_CONNECTIONS = NO)
      ),
      'linuxsyncha' WITH (
            ENDPOINT_URL = 'TCP://linuxsyncha.AlwaysOn.com:5022',
            FAILOVER_MODE = EXTERNAL,
            AVAILABILITY_MODE = SYNCHRONOUS_COMMIT,
            SESSION_TIMEOUT = 10,
            BACKUP_PRIORITY = 0,
            SEEDING_MODE = MANUAL,
            PRIMARY_ROLE(ALLOW_CONNECTIONS = ALL),
            SECONDARY_ROLE(ALLOW_CONNECTIONS = NO)
      )
;
GO
```

## 配置集群

在创建集群之前，我们需要在将参与可用性组的每个 SQL Server 实例中创建一个将由 Pacemaker 账户使用的登录名，并为其分配所需的权限。这可以通过使用列表 [6-12](#394392_3_En_6_Chapter.xhtml#PC12) 中的脚本来实现。

```
CREATE LOGIN Pacemaker WITH PASSWORD = 'Pa$$w0rd'
GO
GRANT ALTER, CONTROL, VIEW DEFINITION ON AVAILABILITY GROUP::LinuxAOAG TO Pacemaker ;
GRANT VIEW SERVER STATE TO Pacemaker
```

配置 Pacemaker 登录

接下来，我们需要配置防火墙。集群所需的端口在表 [6-1](#394392_3_En_6_Chapter.xhtml#Tab1) 中详细说明。

表 6-1

集群所需的端口

| 端口 || 描述 |
| --- | --- |
| TCP 2224 || 所有节点均需。`pcsd` Web UI 和节点间通信 |
| --- | --- |
| TCP 3121 || 如果 Pacemaker 具有远程节点，则所有节点均需。用于 `crmd` 与 `pacemaker_remoted` 守护进程之间的通信 |
| TCP 21064 || 所有节点均需。由需要 DLM 的资源使用 |
| UDP 5405 || 所有节点均需。由 Corosync 使用 |
| TCP 1433 || 所有节点均需。本章中的示例将 SQL 实例监听在 1433 上；然而，您应将其更改为与您自己的环境相匹配 |
| TCP 5022 || 所有节点均需。本章中的示例将 AlwaysOn 端点设在 5022 上；然而，您应将其更改为与您自己的环境相匹配 |

列表 [6-13](#394392_3_En_6_Chapter.xhtml#PC13) 提供了在 Ubuntu 中配置防火墙规则的示例。

```
sudo ufw allow 2224/tcp
sudo ufw allow 3121/tcp
sudo ufw allow 21064/tcp
sudo ufw allow 5405/udp
sudo ufw allow 1433/tcp
sudo ufw allow 5022/tcp
sudo ufw reload
```

安装 Pacemaker 组件

**警告**

对于生产系统，请确保还安装 `fence-agents` 用于节点隔离。

在安装 `pcs` 组件期间，会创建 `hacluster`。您应使用 `passwd` 命令为此用户设置密码，如列表 [6-15](#394392_3_En_6_Chapter.xhtml#PC15) 所示。运行命令后，您将被提示输入并确认新密码。

**注意**

重要的是在每个节点上设置相同的密码。

```
Sudo passwd hacluster
```

列表 6-15

设置 hacluster 密码

我们现在可以使用列表 [6-16](#394392_3_En_6_Chapter.xhtml#PC16) 中的脚本启用 `pcsd` 和 `pacemarker` 服务。您会注意到在启用 pacemaker 之前，我们会发出销毁任何现有集群的命令。这是因为在安装 `pcs` 时创建了名为 `/etc/cluster/corosync.conf` 的文件，然而，启用 pacemaker 会尝试创建此文件。使用 `cluster destroy` 命令会删除此文件，以避免在启用 pacemaker 时出现失败。

```
sudo systemctl enable pcsd
sudo systemctl start pcsd
sudo pcs cluster destroy
sudo systemctl enable pacemaker
```

列表 6-16

启用 pcs 和 pacemarker

现在 pacemaker 已启用，我们可以构建集群。此过程包括运行五个 `pcs cluster` 命令。第一个是 `auth`。它用于将 `pcs` 身份验证到所有节点上的 `pcs` 守护进程。该命令期望一个节点列表，后跟在安装期间创建的 `pcs` 用户的用户名和密码。列表 [6-17](#394392_3_En_6_Chapter.xhtml#PC17) 演示了在我们的场景中如何使用该命令。

```
sudo pcs cluster auth LinuxProd LinuxSyncHA LinuxConfig –u hacluster
```

列表 6-17

对 pcs 守护进程进行身份验证

由于您运行此命令时未指定 `–p` 参数，您将被提示输入 `hacluster` 的密码。
