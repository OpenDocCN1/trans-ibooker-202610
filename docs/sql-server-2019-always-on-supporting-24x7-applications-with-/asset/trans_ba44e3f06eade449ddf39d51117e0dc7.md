
分布式可用性组可用作混合云场景中域无关可用性组的替代方案。此外，它们还提供了跨平台分发数据的灵活性。例如，数据可以在基于 Windows 的可用性组和基于 Linux 的可用性组之间复制。

基础可用性组提供了在运行 SQL Server Standard Edition 的实例上配置可用性组的选项。然而，如果你选择使用此功能，则功能有限。仅支持两个副本，并且每个可用性组只能有一个数据库。此外，没有使用只读路由的选项。

# 8. 管理 AlwaysOn

Peter A. Carter^([1](#394392_3_En_8_Chapter.xhtml#Aff2) ) (1) Botley, UK 结束摘要 

本章将讨论如何管理 AlwaysOn 功能。我们首先将介绍集群维护，包括滚动修补程序升级和删除实例。然后我们将讨论可用性组的管理，包括如何同步和异步故障转移。我们还将研究如何对分布式可用性组进行故障转移。

还将讨论其他维护任务，例如同步实例级对象、对应用程序进行安全状态设置，以及向可用性组添加多个侦听器。本章最后将讨论如何暂停数据移动以及如何从可用性组中删除数据库。

## 管理集群

从管理角度来看，安装集群并不是终点。你仍需定期执行维护任务。以下各节描述了一些最常见的维护任务。

### 在节点之间移动实例

除了防止计划外中断之外，实现高可用性技术的一个好处是，它可显著减少维护任务（例如修补程序）的停机时间。这可以是操作系统级别或 SQL Server 级别。

如果您有一个双节点集群，请先将修补程序应用于被动节点。一旦您确信更新成功，请故障转移实例，然后将修补程序应用于另一个节点。此时，您可能希望或不希望故障转移回原始节点，这取决于环境的需要。例如，如果实例可用性的优先级高于一切，则可能不希望故障转移回来，因为这会造成另一次短暂中断。

要使用故障转移群集管理器将实例移动到不同的节点，请从包含实例的角色的上下文菜单中选择 Move ➤ Select Node。这将导致“移动群集角色”对话框显示。在此处，您可以选择要移动角色到的节点，如图 [8-1](#394392_3_En_8_Chapter.xhtml#Fig1) 所示。 ![图 8-1 ¶ 移动群集角色对话框](images/394392_3_En_8_Chapter/394392_3_En_8_Fig1_HTML.jpg)

图 8-1 ¶ 移动群集角色对话框

然后角色将被移动到新节点。如果您在故障转移群集管理器中查看角色的资源窗口，则会看到每个资源依次经过 Online ➤ Offline Pending ➤ Offline 状态。新节点现在显示为所有者，然后资源依次经过 Offline ➤ Online Pending ➤ Online 状态。资源将按照其依赖关系顺序离线并重新上线。

我们也可以使用 PowerShell 对角色进行故障转移。为此，我们需要使用 `Move-ClusterGroup` cmdlet。列表 [8-1](#394392_3_En_8_Chapter.xhtml#PC1) 通过使用 cmdlet 将 MSDTC 集群角色故障转移到 ClusterNode2 来演示这一点。我们使用 `-Name` 参数指定要移动的角色，使用 `-Node` 参数指定要移动到的节点。
```
Move-ClusterGroup -Name ALWAYSON-MSDTC-C -Node ClusterNode2
```

### 滚动修补程序升级

如果您有一个超过两个节点的集群，则在为 SQL Server 应用更新时，请考虑执行滚动修补程序升级。在此场景中，您可以降低不同节点（这些节点可能是角色的可能所有者）运行不同版本或修补程序级别的 SQL Server 的风险。

首先，您应该列出所有可能是该角色所有者的节点。然后，选择其中 50% 的节点并将其从“可能所有者”列表中移除。您可以通过从名称资源的上下文菜单中选择“属性”，然后在“高级策略”选项卡中取消选中可能所有者列表中的节点来实现，如图 [8-2](#394392_3_En_8_Chapter.xhtml#Fig2) 所示。 ![图 8-2 ¶ 删除可能所有者](images/394392_3_En_8_Chapter/394392_3_En_8_Fig2_HTML.jpg)

图 8-2 ¶ 删除可能所有者

要使用 PowerShell 实现相同的效果，我们可以使用 `Get-ClusterResource` cmdlet 导航到名称资源，然后管道输入 `Set-ClusterOwnerNode` 来配置可能所有者列表。这在列表 [8-2](#394392_3_En_8_Chapter.xhtml#PC2) 中进行了演示。如果您配置多个可能所有者，则可能所有者列表以逗号分隔。
```
Get-ClusterResource "SQL Network Name (ALWAYSON-SQL-C)" | Set-ClusterOwnerNode -Owners clusternode1
```

一旦 50% 的节点被移除为可能所有者，您应该将更新应用于这些节点。更新在此半数节点上验证后，您应重新配置它们以再次成为可能所有者。

下一步是将角色移动到您已升级的节点之一。故障转移成功完成后，在将更新应用于这些节点之前，从首选所有者列表中移除另一半节点。更新在此半数节点上验证后，您可以将它们返回到可能所有者列表。

提示 

只能在资源上设置可能所有者。如果您使用 `-Group` 参数针对角色运行 `Set-ClusterOwnerNode`，则您配置的是首选所有者而不是可能所有者。

### 从集群中删除节点

注意 

如果您希望遵循本书中的后续演示，请勿遵循本节中的演示。

如果您希望卸载 AlwaysOn 故障转移群集实例，则不能像卸载独立实例那样从控制面板执行此操作。相反，您必须在集群的每个节点上运行“删除节点”向导。您可以通过在 SQL Server 安装中心中的“维护”选项卡中选择“从 SQL Server 故障转移群集删除节点”选项来调用此向导。

向导首先运行全局规则检查，然后运行删除节点的规则检查。然后，在图 [8-3](#394392_3_En_8_Chapter.xhtml#Fig3) 所示的“群集节点配置”页面上，您将被要求确认要删除节点的实例。如果群集托管多个实例，您可以从下拉框中选择适当的实例。 ![图 8-3 ¶ 群集节点配置页](images/394392_3_En_8_Chapter/394392_3_En_8_Fig3_HTML.jpg)
