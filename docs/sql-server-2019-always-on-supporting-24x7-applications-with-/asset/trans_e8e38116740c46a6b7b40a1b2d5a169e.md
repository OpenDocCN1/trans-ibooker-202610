
## 磁盘页

在磁盘页上，如图 [7-7](#394392_3_En_7_Chapter.xhtml#Fig7) 所示，我们可以配置 VM 的存储选项。页面第一部分中，我们可以指定要使用的存储层级，可在 Standard HDD、Standard SSD . 或 Premium SSD 中选择。我推荐为托管 SQL Server 的 VM 使用 Premium SSD，这可能不会令人意外，尽管您的选择可能还有其他因素，例如公司政策或预算限制。 ![图 7-7 ¶ 创建虚拟机 – 磁盘页](images/394392_3_En_7_Chapter/394392_3_En_7_Fig7_HTML.jpg)

图 7-7 ¶ 创建虚拟机 – 磁盘页

页面“高级”部分中，我们可以指定是否要使用托管磁盘或非托管磁盘，以及是否要使操作系统磁盘为临时磁盘。通常推荐使用托管磁盘，因为它们带来诸如自动跨故障域和更新域拆分等优势。如果 VM 是在可用性集中构建的，这些域也可以与可用性集的域保持一致。在我们的案例中，必须使用托管磁盘，因为当可用性选项配置为可用性区域时，这是唯一的选择。

临时磁盘使用非常快的存储，且不具备终止抗性。因此，它们适用于无状态应用程序，但不适用于运行 SQL Server 的 VM。在我们的案例中，我们甚至无法为操作系统选择临时磁盘，因为我们的映像太大而无法支持它。

## 网络页

在网络页（图 [7-8](#394392_3_En_7_Chapter.xhtml#Fig8)）上，我们可以指定 VM 应附加到的 vnet 和子网，以及配置应使用的公共 IP 地址和安全组。在此页面上，还有一些未说明的选项，允许您配置加速网络，这是一项功能，可实现对 VM NIC（网络接口卡）的低延迟和高吞吐量，但仅适用于较大 VM，并且还允许您将 VM 置于预配置的负载均衡器之后。此选项不适用于 SQL Server。 ![图 7-8 ¶ 创建虚拟机 – 网络](images/394392_3_En_7_Chapter/394392_3_En_7_Fig8_HTML.jpg)

图 7-8 ¶ 创建虚拟机 – 网络

## 管理页

在管理页上，如图 [7-9](#394392_3_En_7_Chapter.xhtml#Fig9) 所示，我们可以配置 VM 的诊断设置。具体而言，我们可以选择是否捕获启动诊断和来自来宾操作系统的诊断，以及诊断应保存到的存储帐户。 ![图 7-9 ¶ 创建虚拟机 – 管理页](images/394392_3_En_7_Chapter/394392_3_En_7_Fig9_HTML.jpg)

图 7-9 ¶ 创建虚拟机 – 管理页

我们还可以指定是否要使用系统分配的托管标识。如果选择此选项，则 VM 可以在无需在代码中存储服务凭据的情况下对原生 Azure 服务（如 Key Vault）进行身份验证。最后，我们可以指定是否要在特定时间关闭 VM。如果选择此选项，则会出现额外的对话框，允许我们指定关闭计划以及是否希望收到关闭通知。

### 提示

创建 VM 时，只能添加关闭计划，但没有创建启动计划的选项。这可以通过使用 Azure Automation 帐户来实现。

## 高级页

就我们的目的而言，在高级页上没有需要配置的内容。但是，此页面可用于将配置文件传递到 VM 内的已知位置，安装 VM 的扩展，例如 Puppet Agent，以实现 VM 的配置管理。如果您希望 VM 位于就近组上，或希望它驻留在现有的专用主机上，则这些选项也可以在此页面上配置。

## SQL Server 设置

由于我们正在构建 SQL Server VM，因此我们有一个 SQL Server 设置页，如果我们从标准 Windows Server 映像构建 VM，则该页不会出现。在此页的第一部分（图 [7-10](#394392_3_En_7_Chapter.xhtml#Fig10)）中，我们可以配置 SQL 连接。这将为我们提供使 SQL Server 实例仅在 VM 内、在我们的 vnet 内或在 Internet 上公开可用的选项。毋庸置疑，将实例公开给 Internet 是不可取的，通常即使在开发/测试场景中也是如此。 ![图 7-10 ¶ 创建虚拟机 – SQL Server 设置（第 1 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig10_HTML.jpg)

图 7-10 ¶ 创建虚拟机 – SQL Server 设置（第 1 部分）

我们还可以指定实例应监听的端口以及是否要启用 SQL Server 身份验证（而不仅仅是 Windows 身份验证）。如果选择此选项，我们可以指定所需管理员帐户的用户名和密码。

我们还可以选择是否要将实例与 Azure Key Vault 集成。如果选择此选项，则必须提供 Key Vault 服务的 URL 和凭据信息。

在页面的下一部分中，我们会看到 SQL Server 的默认存储选项。使用“更改配置”链接将调用“配置存储”页，如图 [7-11](#394392_3_En_7_Chapter.xhtml#Fig11) 所示。在此页上，有针对通用、OLTP 和数据仓库工作负载配置文件的预设，可以根据您的要求进行自定义。您可以指定 TempDB 和日志文件是否应使用同一驱动器或共享数据驱动器。您还可以指定每个磁盘的大小和存储类型。 ![图 7-11 ¶ 创建虚拟机 – SQL Server 设置（第 2 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig11_HTML.jpg)

图 7-11 ¶ 创建虚拟机 – SQL Server 设置（第 2 部分）

在页面的最后一部分中，如图 [7-12](#394392_3_En_7_Chapter.xhtml#Fig12) 所示，我们可以指定要为 SQL Server 使用的许可模型（BYOL 或 SPLA），以及指定修补窗口并选择是否要启用自动备份。最后，我们可以指定是否要安装 R Services，该服务提供自 SQL Server 2017 起可用的数据库内机器学习功能。 ![图 7-12 ¶ 创建虚拟机 – SQL Server 设置（第 3 部分）](images/394392_3_En_7_Chapter/394392_3_En_7_Fig12_HTML.jpg)

图 7-12 ¶ 创建虚拟机 – SQL Server 设置（第 3 部分）

## 标签和审核页

在标签页上，我们可以按键/值对添加标签，如本章“创建可用性集”部分所述。在审核页上，我们可以在创建虚拟机之前审核所选配置。

就我们的目的而言，我们应重复此过程以创建第二个 VM，这次在可用性区域 2 中并驻留在 vnet 内的另一个子网上。

## 配置可用性组

一旦两个服务器构建完成，您需要将服务器加入域并配置防火墙规则等设置。然后，您可以使用本书第 [3](#394392_3_En_3_Chapter.xhtml) 章中演示的方法创建群集。由于我们正在实施可用性组而不是故障转移群集实例，因此群集中不需要任何共享存储。

群集配置完成后，我们可以通过创建 Sales 数据库来构建可用性组，然后使用本书第 [5](#394392_3_En_5_Chapter.xhtml) 章中讨论的方法配置可用性组。为本次练习的目的，节点应配置为同步复制和自动故障转移。请注意，您此时不应创建可用性组侦听器。

在 Azure 中，可用性组侦听器将需要 Azure 负载均衡器，以保存可用性组侦听器和故障转移群集的 IP 地址。我们应在创建可用性组侦听器之前创建负载均衡器。
