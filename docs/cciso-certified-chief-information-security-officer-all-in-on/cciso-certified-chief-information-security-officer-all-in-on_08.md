# 术语表

**scope（范围）** 要执行的工作边界的定义。

**scope creep（范围蔓延）** 项目范围的不受控制增长。

**security（安全）** 安全的状态或免受潜在伤害的自由。

**security business drivers（安全业务驱动因素）** 对安全产生影响的业务特征。

**security control（安全控制）** 也称为保障措施或对策，一种为降低风险并保护资产的机密性、完整性或可用性而实施的机制（如流程或技术）。

**security engineering（安全工程）** 解决系统需求、设计和实施中安全问题的工程领域。

**security operations（安全运营）** 专注于主动执行日常职能，以预防、检测和响应安全风险与威胁。

**security situational awareness（安全态势感知）** 了解组织拥有哪些资产、资产位于何处以及每个资产的安全状况如何的实践。

**Service Organization Controls (SOC) audit（服务组织控制（SOC）审计）** 由第三方对服务组织（如云服务提供商）执行的审计，该第三方评估服务组织的内部控制。

**Single Loss Expectancy (SLE)（单次损失期望值）** 单次威胁事件的潜在损失价值。该事件可适用于单个资产或一组资产。公式为 `Asset Value (AV) × Exposure Factor (EF) = Single Loss Expectancy (SLE)`。

**social engineering（社会工程学）** 利用欺骗手段诱使某人做可能不符合其最佳利益的事情。多年来罪犯一直在使用这种技术，它是许多网络攻击不可或缺的一部分。

**standard（标准）** 一个经批准的模型，定义了用作比较基础的质量或特征。例如，*系统配置标准* 规定了给定系统的经批准的配置设置。

**steganography（隐写术）** 一种将秘密信息隐藏在显而易见之处的技术，通常隐藏在看似无害的数字文件中。这是通过使用特殊软件将消息嵌入图像、视频、音频、文本或其他文件中来实现的。

**subject（主体）** 访问对象的主动实体，如个人、系统、进程或设备。

**SWIFT** 结构化假设分析技术，一种结构化的群体协作流程。它涉及使用引导词和其他元素进行头脑风暴会议，以描述系统、识别和评估风险，并提出将风险降低到可接受水平的行动。

**systems development life cycle (SDLC)（系统开发生命周期 (SDLC)）** 用于开发或管理系统、产品或服务的生命周期模型。SDLC 的示例包括瀑布模型、敏捷模型和增量模型。

**technical controls（技术控制）** 提供安全控制功能的硬件或软件实现。示例包括加密、密码强制策略、多因素认证、入侵检测系统 (IDS)、入侵防御系统 (IPS) 和防火墙。技术控制也称为 *logical controls（逻辑控制)*。

**threat（威胁）** 与漏洞利用相关的任何潜在危险。威胁在于有人或某物会识别出特定漏洞并将其用于攻击组织或个人。

**Trojan（特洛伊木马）** 伪装成有用程序的恶意软件。

**virtual local area network (VLAN)（虚拟局域网 (VLAN)）** 一个逻辑网络，可能与其他网络共享物理介质。

**virus（病毒）** 为执行其恶意任务而感染合法程序的程序或代码段。

**vulnerability（漏洞）** 可能被利用的弱点。它可以是软件、硬件、程序或人为的弱点。

**vulnerability management（漏洞管理）** 在组织环境中识别、确定优先级、修复和缓解漏洞的持续过程。

**warm site（温站）** 一个备用数据处理中心，其资源处于不完全就绪状态。

**waterfall（瀑布模型）** 一种分阶段的开发生命周期，以线性顺序的不同步骤为特征，每个步骤必须在后续步骤开始前完成。此方法也常被称为 *traditional（传统)* 或 *phased（分阶段)* 方法。

**work breakdown structure (WBS)（工作分解结构 (WBS)）** 一种项目管理工具，将项目分解为分层的工作要素（任务、子任务和交付成果）。

**work factor（工作因子）** 克服安全防护并实施网络攻击所需的时间和资源量。

**worm（蠕虫）** 一种能自我传播到其他系统的病毒。

**Zachman Framework（扎克曼框架）** 以其创建者 John Zachman 命名，一种用于查看和定义企业架构的框架。
