GraphQL allows *schema federation*, or organizing your schemas as a single data graph to provide a unified interface for querying all of your backing data sources. Again, don't fall into the trap of creating an enterprise data model or a central gateway model. If you want to know more about this, I encourage you to read *Visual Design of GraphQL Data: A Practical Introduction with Legacy Data and Neo4j* by Thomas Frisendal (Apress).

The GraphQL services in an API architecture can be deployed only within a domain, or as a capability for domain-to-domain communication. In the latter setup, all of the principles discussed in Chapter 2 should be followed: all GraphQL endpoints should follow the same design and governance principles.
