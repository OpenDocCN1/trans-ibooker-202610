To address capability duplication concerns, enterprises often choose one central (domain-oriented) data platform over many deployed components that are all managed by individual teams. This is also where I see many overlaps with, for example, data lakehouse architectures.4 In such a scenario, there’s a central and shared data platform that handles all data ingestion, storage, transformation, and output of data in one logical data lake. Data organization and alignment with source systems or domains happens within the central platform.
