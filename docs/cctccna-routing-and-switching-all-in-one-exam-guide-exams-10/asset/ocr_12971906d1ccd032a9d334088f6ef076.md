You could also set up all of your switches in server mode, which is the default setting for VTP. You could even mix and match these options—set up a couple of server switches, and have the remaining switches as clients, or set your switches initially as servers and clients, add all your VLANs on the server switch, allow the clients to acquire this information, and then change all the switches to transparent mode. This process allows you to populate your switches’ configurations easily with a consistent VLAN configuration during the setup process. Note that if you don’t specify the VTP mode for your switch, it will default to *server*. As you can see, a wide range of VTP configuration options is available.

# VTP Messages

If you use a client/server configuration for VTP, these switches can generate three types of VTP messages:

+   - Advertisement request
+   - Subset advertisement
+   - Summary advertisement

An *advertisement request* message is a VTP message a client generates to acquire VLAN information, to which a server will respond. When the server responds to a client’s request, it generates a *subset advertisement*. This subset advertisement contains detailed VLAN configuration information, including the VLAN numbers, names, types, and other information. The client will then configure itself appropriately.

A *summary advertisement* is also generated by a switch in VTP server mode. Summary advertisements are generated every 5 minutes (300 seconds) by default, or when a configuration change takes place on the server switch. Unlike a subset advertisement, a summary advertisement contains only summarized VLAN information.
