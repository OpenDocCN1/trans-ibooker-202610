

一个团队过去的回顾会议上会列出许多不满：测试耗时太长、用户故事过大、部署存在问题。他们会兜圈子讨论并点头，但下一个冲刺到来时，同样的问题又出现了。没有任何改变。意识到这一点后，Scrum Master 重启了他们的回顾方式。

在一场会议中，他们只集中关注一个问题：代码评审缓慢。他们发现开发人员过度预订，且某些 PR 处于闲置状态。他们制定了一个具体计划：“下一个冲刺，每周指定一名轮换的评审伙伴，其主要工作是在数小时内评审 PR。Mark 先上。”他们写了下来。在下一次回顾中，他们检查了：PR 周转时间有所改善。团队感到振奋——一个问题被识别并得到解决。随后的回顾中，他们着手部署流程：他们决定自动化一个导致延迟的步骤，并指派两人来编写脚本。

经过几个冲刺，团队养成了一个习惯：识别一到两个关键痛点，解决它们，检查是否改善，然后重复。诸如“用户故事过大”之类的问题通过一个行动得到解决：“如果在计划中看起来工作量超过三天，就拆分用户故事。”一个接一个，许多反复出现的抱怨从回顾看板上消失了，而新的抱怨则更加细微。团队现在期待回顾会议，因为那是他们掌控流程的时候。

## 回顾会议作为持续改进的引擎

Scrum 和敏捷方法论强调适应流程。回顾会议就是实现这一点的工具。但只有当实际发生适应时才有效。正如一个敏捷原则所述，团队应定期反思，并据此 *调整和改进* 行为。回顾会议必须产生这种调整。

为了确保回顾会议产生行动，一些团队将改进纳入其完成定义或团队工作协议中。例如，如果回顾行动是“每个 PR 必须至少有一个自动化测试”，团队可以将该项添加到其完成定义检查清单中。这确保了行动不会只持续一个冲刺，而是成为正常实践的一部分。

总之，不要仅仅把回顾会议当作一种宣泄性的对话，而应将其视为改进流程的计划会议。用对待产品工作冲刺计划同样的严肃态度来对待它。如果本冲刺某件事很痛苦，回顾会议就是你找出补救措施并进行规划的地方。通过一 sprint 接一 sprint 坚持不懈地这样做，一个平庸的团队可以成为高绩效团队。你将解决问题的根本原因，而不是无休止地灭火。团队会感觉对自己的命运更有掌控力，这会提升士气。最重要的是，它创造了一种持续改进的文化——高效工程团队的标志。随着时间的推移，你可能会发现需要修复的重大问题越来越少，而需要微调的事情越来越多，这是一个很好的状态。这时你就知道你的回顾实践已经将反思转化为有意义的行动。

通过积极解决这些团队层面的反模式，你将把团队文化从反复摩擦和风险的文化转变为韧性、共同拥有和持续改进的文化。这创造了一个更有效——也更愉快——的工作环境。团队内部动态同样重要的是它如何适应现代工作场所的更广泛背景。在 [第 11 章](#ch11.html#ch11_thriving_in_modern_work_environments_1768431690039634) 中，我们将探讨在当今工作环境中蓬勃发展的策略，包括远程工作，以及保持长期福祉。

# 第 11 章. 在现代工作环境中蓬勃发展

软件工程工作的性质不断变化，受新技术、不断演变的团队结构和不断变化的文化规范的影响。为了保持有效，工程师必须不仅适应他们的技术技能，还要适应他们的工作习惯。

本章重点关注在现代技术环境中蓬勃发展。我们将介绍在分布式和远程团队中取得成功的实用策略、保护心理健康以确保可持续职业的方法，以及技术影响力中沟通技能日益增长的重要性。

## 远程工作策略：在分布式环境中蓬勃发展

远程和分布式工作在软件工程中变得越来越普遍，提供灵活性和获取全球人才的机会。然而，远程工作会带来独特挑战，如果不加以解决，这些挑战会成为反模式：沟通差距、孤立感、工作与生活边界模糊，以及跨时区协调困难。有效的软件工程师会调整策略，在分布式环境中蓬勃发展，将潜在的陷阱转化为生产力和协作优势。

远程工作中一些常见的挑战包括以下内容：

沟通中断

没有面对面互动，很容易导致信息孤岛或误解。细微差别在文字中会丢失，远程团队可能缺乏自发的知识共享（没有走廊对话或听到同事讨论）。

孤立和团队凝聚力下降

远程工程师可能感觉与同事联系较少。社交联结和团队文化在非共址的情况下需要刻意努力。人们可能会开始感觉像独自操作者而不是团队的一员，如果没有社交互动的话。

边界模糊和过度工作

在家工作可能导致工作时间更长，因为没有明确的“离开办公室”事件。一些远程工作者难以切换状态，最终一直在线。 [研究表明](https://oreil.ly/R2BEZ) 远程员工可能难以断开连接，导致工作日变长并可能导致倦怠。相反，其他人可能有相反的边界问题：太多家庭干扰导致生产力不足。两者都是边界问题。

时区差异

在跨区域的分布式团队中，同步协作很困难。一个人的工作时间可能是另一个人的夜晚。如果管理不当，一些团队成员可能会感觉永远跟不上进度，或被迫在奇怪的时间参加会议。

技术或后勤问题

糟糕的网络、不合适的办公空间或缺乏适当的设备会阻碍远程生产力。此外，并非每个人都善于有效地使用远程协作工具——有些人可能在视频上感到害羞或在电话会议上不发言，导致贡献不平衡。

尽管存在这些挑战，只要有正确的策略，远程工作可以非常高效和令人满意。

### 在远程工作中蓬勃发展的关键策略

在远程工作环境中蓬勃发展需要的不仅仅是强大的技术技能——它需要有意的沟通、有纪律的例行程序，以及跨时区和工具集协作的能力。本节中的策略旨在帮助你在任何地方工作时保持联系、高效和平衡。

#### 过度沟通，但要有效

在远程设置中，最好在合理范围内分享过多信息，而不是过少。这并不意味着写冗长的电子邮件没人读；它意味着主动向利益相关者更新、书面澄清期望，并让你的工作可见。例如，使用项目管理工具或每日站会消息发布状态更新（“已完成 API 集成，现在开始 UI”）。如果某事被卡住，请在聊天或站会中明确说明。在办公室里，经理可能会看到你挣扎或看起来沮丧；远程时，除非你告诉他们，否则他们不会知道。此外，记录决策和讨论，以便不在场的人可以跟上。许多成功的远程团队遵循 *默认透明* 的信条：会议记录、设计文档等默认广泛共享。

#### 为不同目的使用多种沟通渠道
