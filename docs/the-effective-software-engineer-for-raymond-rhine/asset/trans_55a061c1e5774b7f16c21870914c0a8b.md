

过去一年里，一个软件团队完全转为远程办公。起初，他们举步维艰——消息被遗漏、任务从缝隙中溜走，一些开发者感到孤独且脱节。认识到这些痛点后，团队实施了一些改变：他们设立了一个晨间仪式，要求每位成员在聊天频道中发布一条简短消息，说明自己正在处理什么（在聊天频道中异步模拟每日站会）。他们设定了核心工作时间（例如上午10点至下午2点的重叠时间）用于任何实时讨论，其余时间则保持灵活以便进行深度工作。他们创建了轮换的“虚拟咖啡”配对——每周，应用会随机将团队成员配对进行15分钟的非工作聊天，这极大地提升了团队的凝聚力。团队还制定了一条规则：任何人都不得被期望在正常工作时间之外回复非紧急消息（以对抗总是在线的倾向）。

几个月后，这些策略显著改善了他们的凝聚力和产出。团队成员表示感觉更亲近、压力更小。由于沟通期望清晰且一致，工作得以更顺畅地完成。他们将原本混乱的远程实验转变为一个运作良好的分布式团队。

远程工作已成常态，且是一把双刃剑。为了避免远程工作的反模式（沟通不畅、孤立、倦怠），你必须有意地培养良好的习惯和团队约定。最好的远程工程师是主动的沟通者、自律的、富有同理心的合作者。他们确保自己不仅仅是在家孤立地编码，而是仍然是团队中不可或缺、可见的一部分。通过设定明确的边界，他们保护自己的心理健康并防止倦怠（与[第9章](#ch09.html#ch09_avoiding_burnout_and_sustaining_long_term_success_1768431689638761)紧密相关）。通过磨练书面和异步协作技能，他们常常发现自己能在更少的干扰下完成更多工作。通过在虚拟环境中培养团队关系，他们将一群分散的个人转变为一支统一的力量。简而言之，他们掌控自己的环境和工具，而不是让远程挑战控制他们。

有了深思熟虑的策略，远程工作可以带来卓越的效果——你可以拥有更集中的注意力、接触更广泛的同事范围，并享受更好的工作生活和谐。许多高效的工程师通过遵循这些原则远程工作，证明了当方法正确时，距离并不是成功的障碍。

# 公共演讲与工程师的沟通技巧：成为有影响力的技术传播者

成为一名有效的软件工程师不仅仅是写代码——还在于传达想法和影响他人。无论是向团队解释你的设计、向管理层倡导新技术，还是与更广泛的社区分享知识，沟通技巧都能放大你的影响力。公共演讲和有效的写作可以将工程师从一名扎实的贡献者转变为真正的技术领导者。相反，缺乏这些技能可能成为一种反模式，导致精彩的想法被埋没或沟通不畅导致项目受挫。

沟通技能对个人贡献者至关重要，原因有几点：

* 你经常需要说服他人——也许你看到了更好的架构，但你必须有说服力地呈现它才能获得认同。
* 你分享知识并进行指导——你的专业知识只有在你能够清晰地传达时才能帮助团队，这需要清晰的解释。
* 你代表你的工作——在与利益相关者的会议或在会议上，你如何阐述技术概念可以决定它们是否被理解和采纳。
* 沟通差距可能导致工程返工或浪费精力——例如，误解需求或没有及时提醒他人风险。
* 高级个人贡献者（员工、首席级别）的职业发展在很大程度上涉及影响力，而影响力来自沟通。[正如 Fran Soto 所说](https://oreil.ly/ZjigP)，“我们经常假设我们的工作会为自己说话，但这很少为真。沟通和可见性与技术能力一样对职业成长至关重要。”

公共演讲，特别是在——发表演讲、演示，甚至主持会议——是一种高杠杆的沟通形式。它可能令人望而生畏（公众演讲恐惧很常见），但它提供了许多好处：

它提升你的可见性和信誉。

当你就某个主题发表演讲时，人们会认为你在该领域有知识。一次在会议或外部大会上出色的演讲展示了你的专业知识。Fran Soto 还指出，“公共演讲机会是被公司领导者看到的免费门票。他们没有时间深入研究我们的拉取请求，但一次出色的演讲可以展示你的技术见解并引起关注，让你成为值得倾听的人。”这可以开启职业机会（例如，被咨询其他项目或被考虑担任技术领导角色）。

它迫使你加深理解。

教学或演讲需要组织你的思路并预见问题。在准备过程中，你经常填补知识空白，这使你成为更好的工程师。解释一个概念有助于你理解它。

它改善团队沟通。

如果你能清晰地对一群人讲话，你在单独交流或设计文档中也会更清晰。公共演讲在所有表达形式中建立自信。你会成为能够阐明想法的人——因此队友会在讨论中纳入你，因为他们知道你能澄清复杂问题。

*它倍增你的影响力*。

与其多次单独解释某事，不如对团队做一次演讲。例如，向团队介绍新的编码标准可确保每个人一起听到其理由，避免零散采用。如果你在一场会议上演讲或写博客（一种公共沟通形式），你可能会影响远超你公司的工程师，在行业中传播好主意或最佳实践。

它增强领导力气场。

即使作为个人贡献者，如果你能有效地向上级管理层或跨职能团队传达信息，你往往会成为这些情况下的事实领导者，因为你能很好地代表团队的技术观点。许多员工工程师认为沟通是他们能够推动大型计划的关键技能——他们可以通过有说服力的沟通而不仅仅是技术正确性来协调不同的利益相关者。

本质上，强大的沟通技巧将你的技术专长从一件独奏乐器转变为一支管弦乐力量，能够领导和协调整个团队。

## 工程师常见的障碍及如何克服

工程师在发展强大的沟通技能时，尤其是在高风险或不熟悉的环境中，常常面临独特的挑战。认识这些常见障碍——并知道如何应对——可以使工程师成为更自信、更有影响力和更有效的沟通者。让我们讨论一些这些障碍。

### 舞台恐惧或焦虑

这是自然的。即使是经验丰富的演讲者也会紧张。关键在于准备和练习。从小开始：在你熟悉的主题上向你的团队（一个支持性的观众）演讲。独自或与朋友多次练习你的演讲。对材料的熟悉可以减少大脑空白的恐惧。最初如果需要可以使用笔记。记住观众通常是支持的——同事希望你成功并分享知识。一些紧张感实际上有助于你充满活力地表现。随着每次演讲，它会减少。考虑加入 Toastmasters 等团体在低风险环境中练习。
