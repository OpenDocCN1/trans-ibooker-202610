

# 高级工程师

高级工程师的工作范围会大幅扩展。与其根据详细规格实现功能，你通常会被赋予高层级的业务需求（与产品团队紧密合作），并期望将其拆解为技术任务、设计解决方案并协调其实施。例如，你可能会被要求“提高我们的结账流程转化率”，并负责分析当前系统、识别瓶颈、提出解决方案、与产品和设计团队协调，并在多个服务中实施更改。

领导力成为你角色的核心部分，即使你不直接管理人员。你指导初级和中级工程师，不仅仅是回答他们的问题，而是教他们如何系统地思考问题。你可能会领导一个小型功能团队，或担任项目的技术负责人，做出架构决策并确保团队在技术方向上保持一致。这包括在开发过程中做出判断，而无需不断向经理升级，并在需求并不完全明确的模糊情况下能够游刃有余。

你的技术能力，并且能够向技术和非技术受众传达状态。

可靠性成为你区别于他人的特征。当同事遇到复杂问题或需要技术决策指导时，他们会转向你。你能够在压力下排查生产问题，在时间紧迫时做出明智的判断，并在事故期间提供技术领导。你的估算值得信赖，因为你既了解技术复杂性，也了解可能出现的潜在障碍。

正如 Gergely Orosz 所指出的，“高级意味着你开始在自己的工作之外产生影响……指导他人并主动改善团队流程。” 你开始塑造的不仅是代码，还有团队的工程文化和实践。

## 员工工程师

员工工程师（通常拥有八年或以上的经验，在大型科技公司有时被指定为 L6 或更高级别）代表了第一个真正的技术领导层级，你的影响力从个人贡献扩展到组织影响力和战略技术方向。虽然你仍然是个体贡献者，但该角色要求从关注个人功能向更广泛的成果和战略考虑转变，同时保持深度技术能力。

### Note
需要注意的是，并非每个人都会或应该晋升到员工工程师角色——这是一种根本不同类型的工作，强调组织影响力和技术领导力，类似于管理是一条不同的职业道路。许多优秀的高级工程师在高级层面继续深化专业知识，会发现极大的满足感和影响力。

你的范围扩展到多个团队或整个产品领域，在那里你解决最复杂和模糊的技术挑战。员工工程师通常处理影响众多团队的横向问题，例如设计新的数据平台、领导从单体到微服务的迁移，或在整个组织内建立安全标准。你可能会设计多个高级工程师实施的系统，在多个团队之间协调技术决策，并确保工程组织的各个部分能够有效协作。

员工工程师的影响力延伸至整个工程组织，甚至超出组织范围。你可能会引领新框架或技术在团队中的采用，建立编码标准和最佳实践，主持重大事故的复盘，并推动公司范围的技术改进。你的技术意见具有重要分量，你通常担任影响多个团队的复杂技术决策的最终裁决者。

员工工程师通过在问题变得关键之前识别重要问题并召集必要的人力和资源来解决它们，展现出卓越的自主性。这通常涉及在没有直接管理责任的情况下领导——在你没有直接管理权限的团队之间产生影响和协调。你可能会认识到公司的部署流程正成为瓶颈，并主动设计并实施一个涉及多个团队并需要高层支持的解决方案。

在这一层级，技术广度变得至关重要。虽然你可能在某一领域保持深厚专业知识，但你需要跨栈的足够知识来对复杂系统做出明智决策。你对前端、后端、基础设施、数据和安全都有足够的了解，能够监督跨越所有这些领域的项目。这种广度使你能够看到他人可能错过的联系和机会。

指导和文化塑造成为正式职责。你通常指导来自不同层级和团队的多个工程师，帮助培养下一代技术领导者。你通过直接指导以及在解决问题、沟通和协作方式上树立榜样来影响工程文化。员工工程师充当力量倍增器，在担任全组织公认的技术权威的同时放大同事的能力。

晋升中的关键区别变得清晰：中级工程师专注于正确且按时完成功能；高级工程师确保整个项目成功交付，同时提升团队能力；员工工程师确保在与业务战略一致的情况下开展正确的项目，并且多个团队能够有效地执行它们。这是从以代码为中心到以成果和战略为中心工作的演变，需要技术深度和组织意识。

理解这些逐步扩展的期望有助于规划你的职业成长。例如，如果你目前处于中级水平并瞄准高级，开始寻求领导小型项目、指导新团队成员以及更积极地参与技术设计讨论的机会。如果你从高级瞄准员工级别，寻找跨团队的倡议，提出影响多个团队的技术改进，并开始在更广泛的工程组织中建立关系，同时始终在经理的支持和指导下进行。

# 个体贡献者与管理：两条道路

随着你的成长，你可能会想：我应该留在 IC 轨道上，可能晋升到员工工程师角色，还是成为工程经理（EM）？这是在高级级别左右许多人面临的关键职业决策。
