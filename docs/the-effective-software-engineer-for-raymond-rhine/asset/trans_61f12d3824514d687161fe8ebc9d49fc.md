# 在没有权威的情况下施加影响：作为个人贡献者的领导力

作为一名资深 IC，你被期望展现领导力，往往是对你没有直接控制的事物和人员。如何在你不是“负责人”的情况下推动改变或凝聚人心？以下是一些建议：

## 通过能力和理解建立信任。

人们会倾听那些证明了自己懂行并且考虑他人观点的人。如果你持续产出优质工作、帮助他人并认可团队成员的贡献，你就会建立起声誉。然后，当你提出建议或担忧时，人们会认真对待。这种信任就是你的非正式权威。

## 识别关键利益相关者并了解他们的动机。

假设你认为团队应该投资于一种新的基础设施工具。利益相关者可能包括你的经理（关注：团队产出）、产品经理（关注：功能时间线）以及其他工程师（关注：学习曲线、技术是否酷）。要影响他们：

1. 与你的经理沟通时，可以表述为“这将使我们从长远来看能够更快交付功能/减少运营负担”（与他们对生产力的目标挂钩）。
2. 与产品经理说，“现在做这件事将减少功能 X 的 bug 和维护工作，因此当我们下个季度尝试扩展到更多用户时，我们不会分心”（与即将到来的发布所需的可靠性挂钩）。
3. 与同事交流时，或许可以诉诸技术价值：“这解决了我们大家在当前系统上感受到的痛点，而且这是一个学习我们许多人感兴趣的现代技术的机会。”

通过将你的提案的好处与每个利益相关者所关心的事项保持一致，你让它成为他们的双赢。

## 使用数据和原型。

如前几章所述，证据是强大的。不要说“我认为我们应该重构这个”，你可以演示重构一小部分后性能提升了 30%，这意味着做更多会带来收益。或者如果你想采用一个新库，也许可以创建一个示例集成来展示它是可行的并且解决了问题。现在你不是要求人们盲目相信你的话——你有概念验证。

## 以身作则。

如果你想改变团队的流程（比如增加代码评审或改进文档），就先以一种有帮助且不带评判的方式自己开始做。其他人往往会跟进，尤其是当他们看到它运作良好时。例如，开始为你自己的功能编写设计文档；当其他人看到它如何帮助及早发现问题并使实现更顺畅时，他们也可能会尝试。*做*比仅仅说教更容易影响行为。

## 指导并建立好感。

影响力往往来自于人们尊重并喜欢你。花时间帮助他人——指导一名初级工程师，协助一名卡在 bug 上的同事（即使这不是“你的责任”）。这会创造好感。人们自然更倾向于采纳过去曾帮助过他们的人的建议。（这不是操纵；这只是人性以及建立积极的团队文化。）

## 选择你的战场并愿意妥协。

如果你反对一切或过于固执，人们会开始忽视你。把你的影响力资本留给真正重要的事情。有时你不会如愿——那也没关系。支持该决定并尽可能使其成功。这会表明你是一个团队成员，而不仅仅是在推动个人议程，这反过来会增加你未来意见的分量。

## 使用沟通技巧。

影响力的关键在于清晰而有说服力的沟通。结构化你的论点；如果有帮助，使用视觉辅助（为两种方案绘制架构图进行比较）；自信地发言但倾听担忧。考虑参加如果提供的关于影响力或谈判的工作坊——这些技能是可以学习的。为了提升商务写作和结构化沟通，可以参考 Barbara Minto（Prentice Hall）著的《金字塔原理》或商务写作课程，帮助你构建更有说服力的论点。

让我们看一个例子：假设你是一名资深工程师，坚信代码库需要一次大规模重构以支持新功能。即使没有权威，你也可以采取一些可能影响结果的行动：

1. 写一份简要文件概述当前问题（附带数据：例如，“由于逻辑交织，功能 A 花了四周时间；在我上一家公司，类似功能在更好的分离下只用了一周”）。
2. 提出一个分阶段的重构计划，允许在并行交付用户价值（这样产品经理就不那么害怕了）。
3. 展示你在某个模块中完成的小型重构，它已经将代码量减半并将一类 bug 减少到零（证明它有效）。
4. 与几名同事一对一讨论，以纳入他们的反馈并悄悄获得盟友（“你觉得这个方法怎么样？”）。
5. 然后集体向团队和管理层展示，重点说明它如何惠及每个人（少谈这是*你的*想法，多谈“我们的代码将更容易使用，我们都讨厌功能 X 做得多么困难……这将有所帮助”）。

很有可能，你会成功影响团队进行重构。这就是作为 IC 的领导力——看到所需的改变，并通过说服而非命令来号召人们追求它。

# 管理向上：与管理层协作

*管理向上*一词意味着主动与你的经理合作，以在目标上保持一致、沟通进展并建立牢固的工作关系。这对 IC 来说是一项关键技能，因为它有助于你获得信任和自主权，从而真正有效。

对于初级工程师，这通常始于清晰的沟通和主动寻求反馈的方法。对于资深工程师，这演变为一种更具战略性的合作伙伴关系，专注于影响团队的优先事项和方向。

以下是 IC 在各个层级可以有效实践管理向上的几种方式：

## 主动沟通。

让你的经理了解进展和问题——不要让他们追着你要状态更新。如果你预见到截止日期会延误，尽早告诉他们（如果可能，附带缓解计划）。这建立信任；他们知道你不会让他们措手不及。

## 了解你的经理的目标。

你的经理是否担心团队速度？系统稳定性？是否达到关键截止日期？如果你知道他们的压力，你就可以相应地调整你的影响策略（如上所述）并选择在哪里投入额外精力。例如，如果稳定性是很大的担忧，你可能会优先处理那个提高可靠性的重构任务。表明你考虑他们的优先事项。这有效地“管理向上”，因为它让你的经理的工作更轻松（他们不必催促你去做那些重要但不光鲜的事情）。

## 寻求反馈并付诸行动。
