Finally, navigate to the ConfigureServices() method and add the following line:

```
services.ConfigureApiServiceWrapper(Configuration);
```

# Build the API CarsController

The current version of the CarsController is tightly bound to the repos in the data access library. The next iteration of CarsController will instead use the service wrapper to communicate with the database. Rename CarsController to CarsDalController (including the constructor) and add a new class named CarsController to the Controllers directory. The class is almost an exact copy of CarsController. I kept them separate to help clarify the differences between using the repos and the service.

> Note Rarely will you use a data access layer and a service layer together when accessing the same database. I show both options so you can decide which approach is best for you.

Update the using statements to the following:

```
using System.Threading.Tasks;
using AutoLot.Dal.Repos.Interfaces;
using AutoLot.Models.Entities;
using AutoLot.Services.ApiWrapper;
using AutoLot.Services.Logging;
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Rendering;
```

Next, make the class public, inherit from Controller, and add the Route attribute. Create a constructor that accepts an instance of IAutoLotServiceWrapper and IAppLogging and assign both instances to class-level variables. The starter code is shown here:

```
namespace AutoLot.Mvc.Controllers
{
[Route("[controller]/[action]")]
public class CarsController : Controller
{
    private readonly IApiServiceWrapper _serviceWrapper;
    private readonly IAppLogging<CarsController> _logging;
    public CarsController(IApiServiceWrapper serviceWrapper, IAppLogging<CarsController> logging)
    {
        _serviceWrapper = serviceWrapper;
        _logging = logging;
    }
}
```
