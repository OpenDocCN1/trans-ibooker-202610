
To test this behavior, add another method to the ValuesController as follows:

    return NotFound();
}
```

Run the app and use the Swagger UI to execute the new Error endpoint. The result is still a 404 (NotFound) status code, but additional information is returned in the body of the response. The following shows an example response (your traceId will be different):

```

This behavior can be disabled through configuration in the ConfigureServices() method of the Startup.cs class.

When the behavior is disabled, the call to the Error endpoint returns a 404 without any additional information.

## Update the Swagger/OpenAPI Settings

Swagger (also known as OpenAPI) is an open standard for documenting RESTful APIs. Two of the main choices for adding Swagger into the ASP.NET Core APIs are Swashbuckle and NSwag. ASP.NET Core 5 now includes Swashbuckle as part of the new project template. The swagger.json documentation generated for AutoLot.Api contains information for the site, each endpoint, and any objects involved in the endpoints.

Swagger UI is a web-based UI that provides an interactive interface for examining an application’s endpoints as well as testing them (as you did earlier in this chapter). This experience can be enhanced by adding documentation into the generated swagger.json file.

### Update the Swagger Calls in the Startup Class

The default API template added the code to generate the swagger.json file into the ConfigureServices() method in Startup.cs.

services.AddSwaggerGen(c =>

The generated XML comments must be added into the swagger.json generation process. Start by adding the following using statements to the Startup class:

services.AddSwaggerGen(c =>

### Additional Documentation Options for API Endpoints

There are additional attributes that augment the Swagger documentation. To use them, start by adding the following using statement to the ValuesController.cs file:

```
using Microsoft.AspNetCore.Http;
using Swashbuckle.AspNetCore.Annotations;
```

The Produces attribute indicates the content-type for the endpoint. The ProducesResponseType attribute uses the StatusCodes enumeration to indicate a possible return code for an endpoint. Update the Get() method of the ValuesController to specify application/json as the return type and that the action result will return either a 200 OK or a 400 Bad Request.

```
[HttpGet]
[Produces("application/json")]
[ProducesResponseType(StatusCodes.Status200OK)]
[ProducesResponseType(StatusCodes.Status400BadRequest)]
public ActionResult<IEnumerable<string>> Get()
{
    return new string[] { "value1", "value2" };
}
```
