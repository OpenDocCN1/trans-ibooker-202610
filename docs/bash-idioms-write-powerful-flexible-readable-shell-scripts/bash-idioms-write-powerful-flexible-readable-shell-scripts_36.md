## 布局

以下是与布局相关的风格指南：

- 对齐！bash 中多个空格几乎无关紧要（= 两侧除外），并且对齐相似的命令使阅读更容易，也更容易看到相似性和差异。
- *不要允许尾随空白！* 这以后会在 VCS（版本控制系统）中造成噪音，当被移除时。
- 使用四个空格缩进，但在 here-documents 中根据需要使用 TAB。
- 在大约 78 列处断开长行，续行缩进两个空格，并在 | 或 > 之前断开，以便这些部分在向下扫描代码时突出。
- 打开块的代码放在一行中，例如：
  - if expression; then
  - for expression; do
- case..esac 中的列表元素缩进四个空格，关闭的 ;; 与该缩进级别相同。每个项目的块也缩进四个空格。
  - 一行元素应与 ;; 在同一行关闭。
  - 尽量对齐每个元素中的 )，除非变得杂乱或失控。
  - 请参阅示例代码中的 Example 8-4。

断开你的行。

在重要部分之前断开它们，这样当你向下扫描列的左侧时，续行会跳出来。我们也喜欢对断开的行使用通常缩进的一半。我们无法在此书中做一个好的（坏的？）长行示例，因为它只会在奇怪的地方断开。但我们可以提供一个简单、我们认为可读的示例：

```
... Lots of code, indented a ways...
    /long/path/to/some/interesting/command \
    | grep "$re_stuff_we_care_about" \
    | grep -v "$re_stuff_to_ignore" \
    | /path/to/email_or_log_command ...
...more code
```
