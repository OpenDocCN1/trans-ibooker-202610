## 名称

命名 *很重要*。我们不能再强调这一点。`$file` 和 `$critical_process_daily_log_file` 之间的区别现在看起来除了多打字之外什么都不是 *现在*，当所有细节都在你脑海中时。但我们保证，如果你花额外的时间真正思考你命名的含义以及它在代码中读起来的样子，这很快就会得到回报，减少编码错误，并且在将来重读、调试和增强时也会有回报。以下是与名称相关的风格指南：

- 好的名字至关重要！
- 全局变量和常量使用大写。
  - 尽量不要更改全局变量，但有时这样做要简单得多（KISS）。
  - 对常量使用 `readonly` 或 `declare -r`。
- 其他变量使用小写。
- 函数使用 Mixed_Case。
- 使用 "_" 而不是 CamelCase 来代替空格（记住，“-” 不能用于变量名）。
- 谨慎使用 bash 数组；它们可能难以阅读（参见第 7 章）。`for var in $regular_var` 通常也同样有效。
- 尽快用可读的名称替换 $1, $2, .. $N。
  - 这样会使一切更易于调试和阅读，但也使设置默认值和添加或重新排列参数变得容易。
- 在指代类型之间进行区分，例如 $input_file 与 $input_dir。
- 使用一致的“FIXME”和“TODO”标签，如有必要加上名称和工单号。

考虑一下将这些混淆并使用（或出现差一错误）错误的一个有多容易：

```
file1='/path/to/input'
file2='/path/to/output'
```

这更直观易读，也更难打错：

```
input_file='/path/to/input'
output_file='/path/to/output'
```

另外，不要为了省打字而省略两个字符；请完整拼写出 $filename，以免以后出错。它是 $filenm 还是 $flname 还是 $flnm 还是别的什么？
