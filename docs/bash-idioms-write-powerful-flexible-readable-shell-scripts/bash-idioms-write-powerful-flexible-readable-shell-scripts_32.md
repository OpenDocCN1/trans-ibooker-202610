## 注释

关于注释的写法、时机、位置等已经写了很多。以下是与注释相关的风格指南：

- *始终使用头部。*
- 为一年后加入团队的新人写注释。
- 对你的函数进行注释。
- 不要注释你做了什么。注释你为什么做或不做某事。
  - 例外：当 bash 本身晦涩时，注释你做了什么。
- 考虑添加关于外部程序选项的注释，尤其是当它们简短或晦涩时。
- 在注释的第一词开头使用大写字母，但除非注释超过一句话，否则省略结束标点。

添加 *有用* 的注释来解释 *为什么* 你做某事以及你的意图！例如：

```
continue # To the next file in for loop
```

理论上，如果你写出清晰的代码，就不需要解释 *某物* 做什么。但有时 bash 本身就很繁琐或晦涩，例如变量替换（参见第 33 页的“Path or Prefix Removal”），像：

```
PROGRAM=${0##*/}  # Basename in bash
```

分隔符对于分隔代码的逻辑块通常很有用。但不要在底部添加结束分隔符来“框”住它；这只会增加混乱并减少你屏幕上的代码行数 1 行。不管怎样，*绝对不要* 在右侧用字符构建框！完全没有必要，你会浪费大量时间让它“看起来正确”。更糟的是，这会强烈阻碍以后修复或更新注释，因为你又得重新修复框。

不要这样做：





##################################################
# 请不要像这样构建框！            #
#                                                #
# 这样做在以后编辑注释时会非常痛苦，因为 #
# 现在你必须担心右侧的结束字符。 这个例子还不算太糟糕，但很快就会 #
# 失控。                           #
##################################################

这样做：

##################################################
# 请像这样构建框！
#
# 这样更容易编辑，因为虽然你仍然需要担心文本换行，但它只是一个简单的行首 "#" 当
# 你重新换行时。
