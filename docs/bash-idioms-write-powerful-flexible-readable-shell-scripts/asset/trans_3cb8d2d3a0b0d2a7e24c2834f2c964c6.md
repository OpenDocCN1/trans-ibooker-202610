

## 名称

- 好的名称至关重要！
- 全局变量和常量使用大写。
  - 尽量不要修改全局变量，但有时这样做更简单（KISS）。
  - 对常量使用 `readonly` 或 `declare -r`。
- 其他变量使用小写。
- 函数使用 Mixed_Case。
- 用 “_” 代替空格（记住，“-” 不能用于变量名）。
- 谨慎使用 bash 数组；它们可能难以阅读（参见第 7 章）。`for var in $regular_var` 通常也能工作。
- 尽快用可读的名称替换 $1, $2, .. $N。
  - 这样会让一切更易调试和阅读，同时也便于设置默认值和增删或重新排列参数。
- 区分引用类型的不同，例如 $input_file 与 $input_dir。
- 使用一致的 “FIXME” 和 “TODO” 标签，如有需要加上名称和工单号。

## 函数

- *始终使用头部注释。*
- 好的名称至关重要！
- 函数必须在被使用前定义。
  - 将它们分组放在顶部，并在每个函数之间使用两行空白和函数分隔符。
  - 不要在函数之间穿插代码！
- 使用 Camel_Case 和 “_” 使函数名与变量名区分开来。
- 使用 `function My_Func_Name {` 而不是 `My_Func_Name() {`，因为它更清晰，也更容易 `grep -P '^\s*function '`。
- 每个函数都应有注释说明其作用、输入（包括 GLOBALS）和输出。
- 当你有有用的独立代码片段，或任何在多次使用相同（或基本相同）的代码块时，都应将其做成函数。如果它们很常见，如日志或邮件发送，请考虑创建一个“库”，即一个可按需 source 的单一公共文件。
- 为“库”函数加上前缀 “_”，如 _Log 或其他前缀。
- 如有意义，可考虑为可读性在参数中使用“填充”词，然后将其定义为 `local junk1="$2" # Unused filler`，例如：
  - `_Create_File_If_Needed "/path/to/$file" containing important value`
- 在函数中设置变量时请使用 `local` 内置命令。
  - 但要注意，一旦“局部化”成功，它会掩盖失败的返回码，因此在使用命令替换时请分开声明和赋值，如 `local my_input` 然后 `my_input="$(some-command)"`。
- 对于超过约 25 行的任何函数，用 `} # End of function MyFuncName` 关闭它，以便在屏幕上更容易追踪代码位置。对于少于 25 行的函数，这不是必须的但推荐，除非会显得杂乱。
- 不要使用 `main` 函数；它几乎总是多余的一层。
  - 尽管如此，对 Python 和 C 程序员来说使用“main”是有意义的，或如果代码也用作库，并且如果你做大量单元测试时可能需要。
- 考虑在主部分上方使用两行空白和主分隔符，尤其是在顶部有大量函数和定义时。

## 引号

- 对变量和字符串加上引号，因为它能让它们更突出并明确你的意图。
  - 除非变得过于杂乱。
  - 或它们需要不加引号以便展开。
- 不要给整数加引号。
- 除非需要插值，否则使用单引号。
- 不要使用 `${var}` 除非必要；它太杂乱了。
  - 但有时是需要的，例如 `${variable}_suffix` 或 `${being_lower_cased,,}`。
- 对命令替换加引号，如 `var="$(command)"`。
- *始终* 对任何测试语句的两边都加引号，如 `[[ "$foo" == 'bar' ]]`。
  - 除非其中一边是整数。
- 并且除非你使用 ~=，在这种情况下你不能给正则表达式加引号！
- 考虑在 echo 语句中对变量使用单引号，如 echo "cd to '$DIR' failed." 因为当变量意外未定义或为空时它会很明显。
  - 或 echo "cd to [$DIR] failed." 随你喜欢。
  - 如果使用 set -u，变量未定义时会报错——但如果变量已定义只是意外为空则不会。
- 在 printf 格式中优先使用单引号（参见第 56 页的“POSIX Output”以及第 55 页的“Time for printf”其余部分）。

## 布局

- 对齐！bash 中多余的空格几乎无关紧要（= 两侧除外），对齐相似的命令使阅读更容易，也能看出相似性和差异。
- 不要允许尾随空白！这会在 VCS（版本控制系统）中在后续删除时产生噪音。
- 使用四个空格缩进，但在 here-documents 需要时使用 TAB。
- 在约 78 列处断开长行，续行缩进两个空格，并在 | 或 > 之前断开，这样在扫描代码时这些部分会突出。
- 打开块的代码放在一行，如：
  - if expression; then
  - for expression; do
- case..esac 中的列表元素缩进四个空格，关闭的 ;; 与该缩进级别相同。每个项目的块也缩进四个空格。
  - 单行元素应在同一行用 ;; 关闭。
  - 尽量对齐每个元素中的 )，除非变得杂乱或失控。
  - 参见示例 8-4 中的示例代码。

## 语法

- 编写 bash 代码时使用 #!/bin/bash - 或 #!/usr/bin/env bash，不要使用 #!/bin/sh。
- 除非你确定需要 $*，否则使用 $@。
- 为减少与赋值的混淆，使用 == 而不是 = 进行相等比较。
- 使用 `$( )` 而不是 `` 反引号/反单引号。
- 使用 [[ 而不是 [（除非你需要 [ 用于可移植性，例如 dash）。
- 根据需要使用 (( )) 和 $(( )) 进行整数运算；避免使用 let 和 expr。
- 当简单且可读时，使用 [[ expression ]] && block 或 [[ expression ]] || block。不要使用 [[ expression ]] && block || block，因为它不按你想的那样工作；对于这种情况请使用 if .. then .. (elif ..) else .. fi。
- 考虑使用“非官方 bash 严格模式”（参见第 96 页的“Unofficial bash Strict Mode”）。
  - set -euo pipefail 将防止或暴露许多简单错误。
  - 注意这一点，并谨慎使用（如果你使用的话）：IFS=$'\n\t'。

## 其他

- 对于“系统”脚本，记录到 syslog，让操作系统处理最终目标、日志轮转等。
- 错误信息应发送到 STDERR，如 echo 'A Bad Thing happened' 1>&2。
- 使用 [ -x /path/to/tool ] || { ...error code block... } 检查外部工具是否可用。
- 失败时提供有用的信息。
- 设置退出码，尤其是在失败时。
