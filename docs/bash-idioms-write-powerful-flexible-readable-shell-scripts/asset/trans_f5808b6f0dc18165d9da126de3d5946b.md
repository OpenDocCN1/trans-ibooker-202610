## 关于空格的提醒

在 bash 变量赋值中，等号两边不允许有空格。对于变量赋值而言，从语法上讲，它必须全部是一个“单词”。不过，在括号内部，空格是可以的，因为括号定义了该“单词”的边界。

现在还有一个算术变体——可能是出于历史原因。你可以使用 shell 内置的 let 来像双括号那样工作，但不需要美元符号。比较下面这些等价的语句：

```
(( step++ ))  # Is the same as:
let "step++"

(( median_loc = len / 2 ))  # Is the same as:
let "median_loc = len / 2"

(( dist *= 4 ))  # Is the same as:
let "dist*=4"
```

但要小心——如果你没有对 let 表达式使用引号（单引号或双引号），那么最好表达式中完全不要有空格。（我们示例中的第一个 let 不需要引号，但养成始终使用引号的好习惯。）空格会将你的命令分割成多个单词，而 let 只接受一个单词，所以如果有多于一个单词就会得到语法错误。

## 不需要括号

我们说过 bash 是一个面向字符串的语言，但有一种例外方式。你可以这样声明一个变量为整数：declare -i MYVAR，声明后，你就可以在不使用双括号且变量名前不加 $ 的情况下，对其进行算术赋值。这里有一个例子，脚本 seesaw.sh：

```
declare -i SEE
X=9
Y=3
SEE=X+Y        # Only this one will be arithmetic
SAW=X+Y        # This is just a literal string
SUM=$X+$Y      # This is string concatenation
echo "SEE = $SEE"
echo "SAW = $SAW"
echo "SUM = $SUM"
```

运行这些语句得到的结果显示了 bash 大多是面向字符串的。SAW 和 SUM 的值是通过字符串操作形成的。只有 SEE 是通过算术运算赋值的：

```
$ bash seesaw.sh
SEE = 12
SAW = X+Y
SUM = 9+3
$
```

这表明你可以在不需要双括号的情况下进行算术运算——但我们通常会避免这种做法，因为它要求你声明要赋值的变量为整数。如果你忘记了 declare 语句，或者将此类表达式赋给未声明的变量，不会得到任何错误信息——只会得到不想要的结果。

## 复合命令

你可能非常熟悉在脚本中看到一行单独的命令。你可能也熟悉在 if 语句的条件中使用单个命令来判断命令是否成功，并根据结果采取行动。如果你读过第 1 章，你也见过“无 if”的 if 语句惯用法。现在让我们来看一下简单的单命令 if 语句，它看起来像这样：

```
if cd $DIR ; then # Do something ...
```

那这些呢：

```
if [ $DIR ]; then # Do something ...
if [[ $DIR ]]; then # Do something ...
```

为什么这两行里有方括号，而第一个例子中没有？它们之间有区别吗？单括号和双括号有什么区别，应该在什么时候使用？

没有方括号时，发生的是命令的执行（我们示例中的 cd）。该命令的成功或失败会被返回，实际上作为 if 用于其决策分支的 true 或 false。如果有 else 分支的话。 在 bash 中，你可以在 if 语句中放置整个命令管道（例如 cmd | sort | wc）。是管道中最后一个命令的返回状态决定了 if 语句是真还是假。（这可能会掩盖很难找到的错误；请参阅第 96 页的“非官方 bash 严格模式”中的 set -o pipefail。）

单括号语法实际上也在运行一个命令，即 shell 内置的 test 命令。左单括号是 shell 内置的 test 命令，但有一个区别：需要一个最终参数 ]。双括号语法在技术上是一个 bash 关键字，表示一个复合命令，其行为与单括号和 test 命令非常相似，但并不完全相同。

我们使用单括号或双括号语法来进行逻辑和比较，即条件表达式。我们用它们来检查事物的状态，比如文件是否存在或具有某些权限，或 shell 变量是否有值。有关可以进行的完整测试和检查列表，请参阅 bash 手册页中的“Conditional Expressions”，以及 help test 以快速回顾。

我们之前的示例是在检查 DIR 变量是否具有非空值。另一种写法是：

```
if [[ -n "$DIR" ]]; then ...
```

以查看值是否非空，即长度不为零。相反，要查看变量的值长度是否为零，即未设置或为空，使用：

```
if [[ -z "$DIR" ]]; then ...
```

那么单括号和双括号测试之间有什么区别呢？只有几处，但可能很显著。

也许最大的区别是双括号语法支持额外的比较运算符 =~，它允许使用正则表达式：

```
if [[ "$FILE_NAME" =~ .*xyzZ*.*jpg ]]; then ...
```

### 正则表达式

这是 bash 中唯一能找到正则表达式的地方！记住：不要对正则表达式加引号，否则你将逐字匹配那些字符，而不是作为正则表达式。

单括号和双括号之间的另一个区别更偏向风格，但会影响可移植性。这两种形式做的是同一件事：

```
if [[ $VAR == "literal" ]]; then ...
```

```
if [ $VAR = "literal" ]; then ...
```

对于 C 和 Java 程序员来说，使用单等号进行比较可能显得不自然，但在 bash 条件表达式中，= 和 == 含义相同。单等号在单括号语法中是首选，以符合 POSIX 规范（bash 手册页如此说明）。

### 一种微妙的差异

在双方括号内，< 和 > 运算符使用“当前区域设置进行词法比较”，而 test（和 [ ）使用简单的 ASCII 排序进行比较。

你在使用单括号时也可能需要转义这些运算符（例如这样：if [ $x \> $y ]），否则它们会被当作重定向。为什么？因为单括号与 test 命令一样是内置命令而不是关键字，所以 bash 将其视为运行命令——而运行命令时可以重定向 I/O。然而，当 bash 看到双括号这个关键字时，它知道会期望此类运算符，不会将其视为重定向。因此，在这两种语法形式中，我们更偏爱双括号语法。

单括号和双括号表达式都可以使用一种更旧、更像 Fortran 的语法来进行数值比较。例如，它们使用 -le 表示小于或等于比较。这里又出现了另一个区别。单括号表达式中该运算符两侧的参数必须是简单的整数。使用双括号时，每个操作数可以是一个更大的算术表达式，尽管如果不加引号则不能有空格。例如：

```
if [[ $OTHERVAL*10 -le $VAL/5 ]] ; then ...
```

如果你要进行算术表达式和比较，更好的选择是使用双括号语法。这会给你更熟悉的 C/Java/Python 风格的比较运算符，并且对空格有更大的自由度：

```
if (( OTHERVAL * 10 <= VAL / 5 )) ; then ...
```

## 风格和可读性：回顾

面对如此多的变体，我们应该选择哪种 if 语句风格？我们选择最适合所考虑计算的风格。

当它是数学表达式时，我们使用双括号。作为一条规则，在 bash 中，双括号表示正在进行算术运算。美元符号表示你想要返回表达式的值，否则你只会得到成功/失败的结果状态。但运算符丰富的 bash 使得使用双括号语法或 let 内置命令都能实现类似的功能。由于在双括号内部不需要在变量前加 $ 来获取其值，我们会尽量一致地省略它们。

对于算术表达式，有些人可能更喜欢在表达式周围使用双括号，与 if 语句保持一致。然而，对于其他人来说，简单的 let 内置命令读起来更清晰简洁。你可以冒险跳过双括号，通过声明变量为整数来实现，但我们不能推荐
