## 函数

以下是与函数相关的风格指南：

- *始终使用头部。*
- 好的名字至关重要！
- 函数必须在被使用前定义。
  - 将它们分组放在顶部，并在每个函数之间使用两行空白和一个函数分隔符。
  - 不要在函数之间穿插代码！
- 使用 Camel_Case 和“_”使函数名与变量名区分开来。
- 使用 function My_Func_Name { 而不是 My_Func_Name() { 因为它更清晰，也更容易 grep -P '^\s*function '。
- 每个函数都应有注释，定义它做什么，输入（包括 GLOBALS）和输出。
- 当你有有用的、独立的代码片段，或任何时候你使用相同（或基本相似）的代码块超过一次时，将它们做成函数。如果它们很常见，比如日志记录或邮件发送，请考虑创建一个“库”，即一个你可以按需 source 的单一公共文件。
  - 为“库”函数加上前缀“_”，如 _Log 或其他前缀。
- 如果有意义，请考虑在参数中使用“填充”词以提高可读性，然后将其定义为本地 junk1="$2" # 未使用的填充，例如：
  - _Create_File_If_Needed "/path/to/$file" containing *important value*
- 在函数中设置变量时请使用 local 内置命令。
  - 但要注意，由于成功“本地化”，它会掩盖失败的返回码，因此如果使用命令替换，请将声明和赋值分开写，例如 local my_input 然后 my_input="$(some-command)"。
- 对于大约 25 行以上的任何函数，用 } # End of function MyFuncName 关闭它，以便在屏幕上更容易跟踪你在代码中的位置。对于少于 25 行的函数，这不是必须的，但鼓励这样做，除非变得过于杂乱。
- 不要使用 main 函数；它几乎总是多余的一层。
  - 话虽如此，使用“main”对 Python 和 C 程序员来说是有意义的，或者如果代码也用作库，并且如果你做大量单元测试时可能需要它。
- 考虑在主部分上方使用两行空白和一个主分隔符，尤其是在顶部有大量函数和定义时。

另外，在你的库中定义一个单一的日志函数（例如，_Log），并使用它！否则你最终会得到各种各样的日志函数、样式和目的地。理想情况下，正如我们之前所说，将日志记录到 syslog，让操作系统担心最终目的地、日志轮转等。
