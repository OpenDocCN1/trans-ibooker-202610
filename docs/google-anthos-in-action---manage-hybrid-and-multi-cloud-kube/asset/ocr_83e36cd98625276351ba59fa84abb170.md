The approach would be the same regardless of the technology stack you originally used to build your application. Also keep in mind that this is a simple example, your application may consist of multiple application components or services that all need to interact to create the end to end application user experience. Based on the criteria listed above, you will need to decide which application components you will replatform into containers and which ones you will keep as VMs. Then we will work through our modernization plan as illustrated. The outline below adds a little more clarity to each step.

+   - Step 0, identify the target application or component to be modernized
+   - Step 1, if the application is suitable we will leverage Anthos Migrate (Chapter 19) to containerize the target application
+   - Step 2, if the application is too complex then we will manually containerize the application, we will go into more detail on this approach in the next section
+   - Step 3, updated your existing CI/CD pipeline or build a new one that will build, test and deploy the application to Anthos
+   - Step 4, operate your application using Anthos to manage configuration, security and connectivity to legacy applications
+   - Step 5, refactor your application into a microservices architecture
+   - Step 6, move legacy applications not currently suited for container to Compute Engine, then modernize by refactoring the application into microservices leveraging modern open source frameworks design for cloud native applications
+   - Legacy applications not in scope for the modernization plan will remain in their current form and likely remain in a legacy data center. We will leverage Anthos Service Mesh for securing connections to these workloads. e.g. ERP system, core mainframe application, etc.
