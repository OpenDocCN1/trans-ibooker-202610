Anthos Identity Service allows users to authenticate using existing corporate credentials both through GCP Console and kubectl (in that case gcloud CLI is used to authenticate and create a kubeconfig file containing the id token to be used by kubectl).

The `authentication:` section in the cluster configuration file contains the following parameters to configure authentication to the cluster using OIDC:

+   - **name**: The name you want to use to identify this configuration, typically the identity provider name.
+   - **issuerURI**: The url of the OpenID provider, it’s where gcloud CLI and GCP Console send authentication requests and it’s used by Kubernetes API server to discover public keys for verifying tokens. For example, for Active Directory Federation Server this is usually [https://SERVERFQDN/adfs](https://SERVERFQDN/adfs), while for Google Cloud Identity it’s [https://accounts.google.com](https://accounts.google.com)
+   - **clientID**: Client ID assigned to the application on the OIDC provider configuration. This is usually created automatically when you create the application on the OIDC provider.
+   - **clientSecret**: Client secret assigned to the client application on the OIDC provider configuration. This is usually created automatically when you create the application on the OIDC provider.
+   - **kubectlRedirectURI**: Callback/redirect url for gcloud CLI, this is `http://localhost:PORT_NUMBER/callback` where `PORT_NUMBER` is any port number greater than 1024 you can choose. This needs to be also added to the OIDC provider configuration
+   - **userClaim**: JWT claim to use as the username, this is optional, "sub" is used if not set.
+   - **userPrefix**: Optional. Prefix prepended to user claims to prevent clashes with existing names.
+   - **groupPrefix**: Optional. Prefix prepended to group claims to prevent clashes with existing names.
+   - **scopes**: Additional scopes to send to the OpenID provider as a comma-delimited list.
