Anthos introduced capabilities to centralize management and unify tool sets that can be used keeping at the same time flexibility to integrate external tools into the pipeline. The goal for modern CI/CD platforms is to support enterprise ready and secure GitOps implementations. That means every component must be described as a set of configuration files and definitions stored in the version control system. Each set is managed and maintained by separate team. It was already mentioned that the modern CI/CD platform relies on shared responsibility. In such models there are always touch points for all parties via common interfaces like code repository, image build and Kubernetes manifest definition stage.

Modern application delivery relies on Kubernetes orchestration and microservice based architecture. In such, there must be separation between developers and operator playground. Implementation depends on defined requirements. We can use single cluster with multiple namespaces for single site or non production setups. If services we are delivering must be highly available, deliver high latency across a globe or we must limit infrastructure lifecycle activities impact, consider multiple Anthos clusters.
