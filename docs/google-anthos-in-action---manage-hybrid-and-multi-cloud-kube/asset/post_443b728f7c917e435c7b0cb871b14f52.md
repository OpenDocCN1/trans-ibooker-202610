
# Network Functions

## Introduction to Network Functions Virtualization (NFV)

Traditionally, Network Operators used to implement network functions on dedicated, proprietary hardware appliances. From the mid 2010s, the concept of Network Functions Virtualization (NFV) emerged as telcos looked at virtualizing their networking functionality, following the same pattern that led to virtualization of IT Servers, to consolidate many network equipment types onto industry standard high volume servers, switches and storage in order to reduce costs and increase efficiency, agility and resilience.

A trend started to transform Network Appliances in Virtual Network Functions (VNF), Virtual Machines deployed on industry standard x86 servers through an hypervisor.

The 3 Main working domains of a NFV Architecture are:

- Virtualized Network Functions (VNFs): x86 compliant virtual machine versions of the network appliances.
- Network Function Virtualized Infrastructure (NFVI): All hardware (servers, storage, network gear) and software components (Virtualization sw) that build up the environment hosting the Virtual Network Functions.
- Management and Orchestration (MANO): Lifecycle Management and Orchestration of physical or software resources that support the infrastructure virtualization and the lifecycle management of the Virtual Network Functions.

## NFV Use Cases

Some Virtualized Network Functions that were created as part of this initiative, with different success in the adoption, were:

- vCPE: Virtualization of Home and Enterprise CPE (Customer Premises Equipment) Routers into the operator network. With this approach, the advanced routing and network functions are moved from the Access Router, that traditionally Service Providers deployed in Enterprise premises or in consumer homes, to VNFs running on industry standard hardware in the provider own NFVI, while the customer on-premise appliance is replaced with a simpler hardware.
- **vPE:** Virtualization of PE (Provider Edge) Routers. In this approach, the routers deployed in the Service Provider Edge that typically connect with the ones deployed in customer premises are also virtualized.
- **vEPC:** EPC (Evolved Packet Core) Virtualization: Virtualization of Network Functions that are part of Mobile Core Networks and IP Multimedia Subsystem (IMS) as Mobility Management Entity (MME), Serving Gateway (SGW), Packet Data Network Gateway (PGW).
- **vCDN:** Virtualization of CDNs. This use case aims at virtualization of the 3rd party CDN appliances usually deployed in operator premises.
- **vRAN:** Virtualization of Mobile base stations in Radio Access Network (RAN) was initially considered as an use case for NFV, mainly because mobile base stations are some of the components that account for most of the TCO and energy consumption of mobile networks. This approach didn’t effectively materialize in NFV but the aim to get the benefits of containerized workloads described above and the need of new Radio Network Functions related to 5G is pushing the transformation of these functions to CNFs.

## Evolution to Cloud Native Network Functions

Telco operators and Network Functions vendors are looking at container based **Cloud Native Network Functions**, as an evolution of VNFs, to fully realize the above mentioned NFV expected benefits and add the improvements carried by cloud native based applications in terms of portability, agility, manageability and efficiency.

Inside Cloud Native Computing Foundation (CNCF) there are various initiatives that aim to support Telecom Operators (and network vendors) in obtaining the benefits touted by cloud native technologies, these are mainly carried on by the Telecom User Group ( https://github.com/cncf/telecom-user-group ), that produced various assets, including a whitepaper available in the repository and the following **definition for Cloud Native Network Functions**:

A cloud native network function (CNF) is a cloud native application that implements network functionality. A CNF consists of one or more microservices and has been developed using Cloud Native Principles including immutable infrastructure, declarative APIs, and a “repeatable deployment process”

## 5G as the Enabler of New Edge Applications

Some 5G Networks characteristics such as: it's larger contiguous spectrum, more advanced radio antenna technologies (Massive MIMO), better modulation schemes, and changes/optimization of signaling flows between core and RAN will provide network capabilities with significant higher bandwidth and lower latency.

Telco service providers and applications / digital services developers are looking to leverage the above characteristics with applications in which more devices will be connected and will exchange information at a very high speed, enabling scenarios in areas as: autonomous driving, smart cities, smart factories, smart video surveillance, augmented reality, virtual reality, remote healthcare/surgery.

To align with the above described topology and latency requirements, these workloads will be deployed, in many cases, in edge locations, near to the end-devices or user, in order to do near real-time data processing and analysis of data, allowing smart devices to act and respond to inputs without sending that data to the cloud and back.

This kind of application will largely be deployed as containerized workloads. 5G Networks in general will be mainly software defined, continuing the transformation started with NFV, have a further need for automation, due the speeds and volumes they will handle, and will be based on open source software.

## Edge Computing

Edge computing will allow applications to respond quickly providing near real-time insights, be less dependent on the network connection to the central datacenter or cloud, and reduce the amount of data that is transmitted centrally.

Gartner predicts that by 2025 75% of enterprise-generated data will be created and processed outside a traditional centralized data center or cloud: https://www.gartner.com/smarterwithgartner/what-edge-computing-means-for-infrastructure-and-operations-leaders/.

Edge infrastructure will be deployed in locations that have a widespread distribution and in many cases will be smaller than central datacenter as:

- Telco Edge: Telco operators small data centers, Points of Presence, Network Cabinets
- Public Cloud Edge: Cloud providers / global broadcasters points of presence and CDN edges.
- Enterprise Edge: Enterprise / End users locations as branch offices, retail stores, warehouses, factories

## Edge Application Examples

Here are some examples of applications and use cases that will take advantage in being deployed at edge locations and perform analysis and predictions on images, video, audio and other types of data also through local execution of AI models:

- **Predictive maintenance:** analyzing manufacturing plants and machine data on-site to predict faults before they happens and optimize uptime and maintenance teams work
- **Manufacturing quality check:** analyzing pictures and videos of products out of the assembly line to check conformance to quality standards.
- **Worker Safety:** analyzing correct security measures implementation and safety equipment usage through pictures and videos.
- **Diagnostic services and patient monitoring:** using a computer vision solution deployed to the edge to process imaging could improve diagnostic accuracy and exam efficiency.
- **Queue and shelf management in retail stores:** analyzing video feeds to check how many people are in line or the availability of goods on shelves and open cash registers or fill goods accordingly.
- **Self driving cars and industrial vehicles:** Low latency processing for data ingested and gathered by autonomous vehicles.
- **Manufacturing workers guidance and training through AR/VR:** AI models deployed on the edge that recognize equipment framed by workers and provide updated information and instructions.
- **Logistics tracking:** AI models that recognize packages, items, pellets, vehicles in transit from images and videos and update tracking systems.
- **Inventory management and production planning:** Near real time analysis of asset status through images to provide inputs to production and supply chain fulfillment.
