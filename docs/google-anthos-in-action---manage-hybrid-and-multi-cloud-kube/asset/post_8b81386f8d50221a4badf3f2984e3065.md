## 9.2.2 GCP integration capabilities

In previous sections we talked about compute and network architecture of Anthos on VMware. In this section, we will cover different integration capabilities of the GCP services to leverage a single pane of glass for all Anthos clusters regardless of their deployment on premises or in other clouds.

If you have already noticed during deployment, one admin and user clusters are mandatory to define a GCP project. This enables the connect agent to properly establish communication with GCP, as described in detail in Chapter 6 - Operations Management in Anthos. In addition, it enables the management of activities, connectivity, and authentication to register new clusters.

![](img/fb3bebce7b5f593bca1a7f8a1371be06_296_0.png)

The use of purpose-dedicated service accounts is recommended. These sections are mandatory for you to properly define the user. Workload Identity enables your service account to authenticate without requiring a key.

```yaml
gkeConnect:
  projectID: "My-awsome-project"
  registerServiceAccountKeyPath: register-key.json
```

> **Note:** Connect can also be used to configure services in GKE on Google Cloud, including Anthos clusters, and can be integrated with GCP services such as Cloud Monitoring and Cloud Logging.

Cloud Operations on VMware provides the ability to monitor and manage Anthos clusters. It enables you to view metrics and logs from the cluster and integrate with GCP Cloud Monitoring. You can also choose to enable Stackdriver metrics for your clusters.

```yaml
stackdriver:
  projectID: "My-awsome-project"
  clusterLocation: gcp-region-name
  enableVPC: false/true
  serviceAccountKeyPath: monitoring-key.json
  disableVsphereResourceMetrics: true/false
```

Another integration feature can be applied to your admin and user clusters to enable Stackdriver services. As previously described, you can choose the project and region where your service account will be used for integrating with Cloud Operations.

```yaml
cloudAuditLogging:
  projectID: "My-awsome-project"
  clusterLocation: gcp-region-name
  serviceAccountKeyPath: audit-key.json
```

Cloud Audit Logging provides a feature to track actions performed on your clusters. It can be enabled to stream audit logs from Anthos clusters to Cloud Audit Logging. This includes audit logs for user actions and control plane activities. Integration with Google Cloud Audit Logging can also be configured through the service account key.

```yaml
cloudRun:
  enabled: true/false
```

Cloud Run can be deployed on Anthos clusters. This enables you to run serverless containers on your cluster, with management features provided by Google Cloud. Cloud Run can also be used to expose workloads and is compatible with your existing cluster, such as the example in Cloud Source Repositories.

```yaml
usageMetering:
  bigQueryProjectID: "My-awsome-project"
  bigQueryDatasetID: dataset-name
  bigQueryServiceAccountKeyPath: metering-key.json
  enableConsumptionMetering: false/true
```

## 9.3 Summary

In this chapter we talked that Anthos on VMware is a great option to consume cloud native capabilities on top of existing vSphere infrastructure and learned the following:

- Architecture is composed from two elements:
  - user clusters that are responsible for delivery of resources for hosted applications
  - admin control plane that is responsible for management and control of deployed user clusters
- It can be used as an add-on to co-hosted Virtual Machines as well as dedicated on prem Kubernetes implementations that are ready for hybrid cloud implementation of cloud native journey.
- We can leverage existing VMware skills for infrastructure management, keep full visibility of Cloud Operations and consume GCP services if needed from your own data center.
- Setup can be independent and self contained in use of bundled features like MetalLB or integrated into existing infrastructure and what automation capabilities and constraints it brings
- Cluster configurations may vary depending on purpose, size and availability requirements.

## 10 Anthos, at the edge and telco world

by Giovanni Galloro

### This chapter covers:

- Evolution of Telco Network Functions towards Cloud Native Network Functions
- Edge Applications use cases
- Anthos specific capabilities for supporting Telco and Edge workloads
- Google Distributed Cloud Edge

This chapter is about using Anthos as an enabling platform for edge and telco workloads, where these workloads fall mainly in 2 categories:

1. **Cloud Native Network Functions:** An evolution of Telecom Network Functions, either already virtualized or still deployed as physical appliances, towards containerized workloads to reach greater efficiency, performance, and ease of management. This evolution will be driven also by new 5G related Network Functions.
2. **New Edge Applications:** Workloads to be deployed in edge locations, near to the end-customer, to reduce latency at minimum and enable new types of applications such as: autonomous driving, smart cities, smart video surveillance, augmented reality, virtual reality, remote healthcare/surgery. Often this type of applications will benefit and be powered by 5G networks and in large part will be deployed as containerized workloads.
