# Observability

Google Cloud Operations can be used to collect logs and monitoring metrics for Anthos on bare metal, just like other Anthos deployment environments. By default, system components logs are sent to Cloud Logging and system components metrics are sent to Cloud Monitoring. Cloud Operations can also collect application logs and metrics by enabling it in the cluster configuration.

As an alternative to Cloud Operations, other solutions can be used if preferred, such as Prometheus/Grafana, Elastic Stack, Sysdig, Datadog or Splunk.

# Identity Integration

Anthos on bare metal can integrate, through the Anthos Identity Service authentication proxy, with any identity provider that supports OpenID Connect (OIDC) or LDAP to manage user and group authentication to clusters using existing user identities and credentials.

With this integration it’s possible to manage access to an Anthos on bare metal cluster by using standard procedures in your organization for creating, enabling, and disabling accounts.

Kubernetes Role Based Access Control can be used to bind specific roles to users and groups defined in the identity provider in order to authorize them to perform specific actions on specific resources.

# 21.3 Installation and Configuration overview

In this section, we will provide an overview of the requirements to deploy a cluster. Understanding the requirements is an important step before attempting to deploy a cluster, which we will discuss in the next section.

Google has made deploying Anthos on bare metal an easy process. Similar to the VMware deployment, you configure the cluster options in a configuration file and the deployment is done using a single binary executable called bmctl.

Anthos requires you to meet requirements for both software and hardware. The requirements are easily met by most organizations, but you should always verify that your infrastructure meets all requirements before deploying.

# 21.3.1 Operating Systems and software requirements

As described in the introduction and architecture sections, Anthos on bare metal is installed on servers provided and configured by the customer. Servers can be physical or virtual as long as they have one of the supported operating systems, configured to meet the Anthos requirements.

Servers to be used as Anthos on bare metal nodes need to have one of the following operating systems:

- CentOS 8.1/8.2/8.3/8.4
- Red Hat Enterprise Linux (RHEL) 8.1/8.2/8.3/8.4
- Ubuntu 18.04 & 20.04

Each supported version requires slightly different configurations. If you are using RHEL or CentOS, the firewalld service must be configured to allow traffic to TCP and UDP ports, these will be covered in the Internal Connectivity requirements under the Networking Requirements section. On these operating systems, if SELinux is enabled in enforcing mode, a policy for container isolation and security is configured during the Anthos on Bare Metal setup. If you are running the nodes on Ubuntu, the Uncomplicated Firewall (UFW) service must be disabled.

Time is very important for a cluster. To ensure that all nodes have their clocks in sync, all servers need to have a NTP service configured and enabled.

Finally, since the installation establishes a SSH connection to the nodes, a SSH key pair is needed to access each node with root privileges.

# 21.3.2 Hardware Capacity Requirements

Anthos on bare metal will work on any hardware compatible with one of the supported operating systems.

The number of nodes required for an Anthos on bare metal installation depends on the chosen deployment and load balancing model, as described in the architecture paragraph. The number of worker nodes required will depend on the capacity requirements of the applications that the cluster(s) will host.

The following table describes the minimum and recommended hardware requirements for each node, whatever is its role, using the default profile, excluding the applications capacity requirements that should be added.

| Resource | Minimum | Recommended |
|---|---|---|
| CPUs / vCPUs | 4 core | 8 core |
| RAM | 16 GB | 32 GB |
| Storage | 128 GB | 256 GB |

The following table describes the hardware requirements for the **edge profile** introduced in Anthos on Bare Metal version 1.8

| Resource | Minimum | Recommended |
|---|---|---|
| CPUs / vCPUs | 2 core | 8 core |
| RAM | Ubuntu: 4 GB<br>CentOS/RHEL: 6 GB | Ubuntu: 8 GB<br>CentOS/RHEL: 12 GB |
| Storage | 128 GB | 256 GB |

# 21.3.3 Admin Workstation

Besides the nodes, it’s suggested to have an additional workstation to run the installation tool.

This workstation must have the same Linux operating system running on cluster nodes with Docker 19.03 or later configured to be managed by non-root users.

In addition to Docker, the machine must have:

- gcloud with anthos-auth and kubectl installed
- More than 50 GB of free disk space.
- L3 connectivity to all cluster node machines.
- Access to all cluster node machines through SSH via private keys with passwordless root access. Access can be either direct or through sudo.
- Access to the control plane VIP.

# 21.3.4 Networking Requirements

Anthos has different requirements for external and internal network connectivity.

# External Connectivity requirements

All Anthos on bare metal nodes will need outbound https connectivity to the internet, in order to:

- Register to GCP console and be managed from there through GKE Connect
- Send metrics and logs to Cloud Operations endpoints
- Pull images from Google Container Registry

This connectivity can use the public internet, a http proxy, or a private connection like Google Cloud VPN or Dedicated Interconnect.
