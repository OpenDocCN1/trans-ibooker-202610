# Cluster type

Depending on the chosen cluster deployment model, set the type spec value in the Cluster custom resource accordingly, choosing between admin, hybrid or standalone as in the example below:

```
```yaml
---
apiVersion: baremetal.cluster.gke.io/v1
kind: Cluster
metadata:
  name: admin-cluster
  namespace: cluster-admin-cluster
spec:
  type: hybrid
```
```

# Control plane configuration

Depending on the chosen control plane architecture, add the ip address/addresses of the target control plane node/nodes in the nodePoolSpec: specification in the controlPlane: section, below an example is shown with an HA architecture based on three control plane nodes. Remember, if you want to enable a highly available control plane, you need to supply at least three IP addresses.

```
```yaml
controlPlane:
  nodePoolSpec:
    nodes:
      # Control plane node pools. Typically, this is either a single
      # or 3 machines if using a high availability deployment.
      - address: 172.16.0.3
      - address: 172.16.0.4
      - address: 172.16.0.5
```
```

# Pod and Services CIDR Blocks

The clusterNetwork: section includes the CIDR ranges assigned to pods and Kubernetes Service objects inside the cluster; these ranges are visible only inside the cluster and are never used externally. Change the defaults only if there is any overlap with existing services on your network that any running pod in the cluster could need to contact.
