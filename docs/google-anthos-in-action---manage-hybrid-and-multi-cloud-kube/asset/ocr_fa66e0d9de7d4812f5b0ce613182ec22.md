With eBPF in GKE, you can now enforce real-time policy as well as correlate policy actions (allow/deny) to pod, namespace, and policy names at line rate with minimal impact on the node’s CPU and memory resources. As packets come into the VM, specialized eBPF programs can be installed in the kernel to decide how to route the packet. Unlike IPTables, eBPF programs have access to Kubernetes-specific metadata including network policy information. This way, they can not only allow or deny the packet, they can also report annotated actions back to user space. These events make it possible for you to generate network policy logs.
