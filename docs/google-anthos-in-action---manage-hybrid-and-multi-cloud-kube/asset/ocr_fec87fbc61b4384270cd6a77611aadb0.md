While Figure 14.5 shows all the steps in the workflows the below list shows all the Skaffold Skaffold Pipeline stages that can be used to execute those steps:

+   - **Init** generates basic Skaffold configuration
+   - **Build** builds images with builders of choice
+   - **Test** tests images with structure-tests[13]
+   - **Tag** tags images based on different policies
+   - **Deploy** deploys the application with kubectl, kustomize or helm
+   - **File Sync** syncs changed files directly to running containers
+   - **Log Tailing** tails logs from containers
+   - **Port Forwarding** forwards ports from services to localhost
+   - **Cleanup** cleanups manifests and images

As we see we have a complete pipeline that allows us to deploy and preview Anthos applications.

# Supported environments

Skaffold supports both local and remote Kubernetes clusters. You can use a local development cluster like Minikube or an Anthos/Kubernetes cluster deployed in a remote location.

To connect to a remote Kubernetes cluster you need to set a context in the kubeconfig file like you would need to connect to any Kubernetes cluster. The default context can be overwritten by running the command skaffold dev --kube-context <myrepo>

or by updating the skaffold.yaml file deploy.kubeContext attribute e.g:

```
deploy:
  kubeContext: minikube
```
