After cluster creation you can get the kubeconfig to connect to it using kubectl from the secret created in the user cluster namespace by the installation process. Here is an example command to extract the kubeconfig:

```
kubectl --kubeconfig ADMIN_KUBECONFIG get secret USER_CLUSTER_NAM
```

You can also connect from the GCP Console using a bearer token or, if you configured the cluster for identity integration, users will be able to authenticate with the cluster from the GCP console and gcloud CLI following the steps described in the previous section, *Connect to a cluster* in the *admin/hybrid cluster section.*

# 21.5 Upgrading Clusters

When a new version of Anthos on bare metal is released you can upgrade your clusters: in non-standalone cluster installations you need to upgrade first the admin/hybrid cluster and then the user clusters.
