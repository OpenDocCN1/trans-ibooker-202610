Last capability to highlight there is **monitoring**. Understanding the health of the system and monitoring is critical to mitigate possible problems before they occur. Proactive failure notifications based on threshold or rate of change warnings build operational knowledge about the system’s status. Extended by logging and monitoring, failure alerts routed to teams or systems introduce a chance to react to these events in a timely manner and prevent outages and downtimes.

**Full stack monitoring** allows support teams to debug systems and measure systems’ behaviors against defined patterns or changes. **Historical monitoring data** allows us to introduce continuous improvements fast, which improves efficiency of the continuous integration and continuous delivery pipelines.

# 14.1.1 Continuous Delivery vs Continuous Deployment

We talked a lot about continuous delivery that often is mixed with continuous deployment. Even though they are hidden behind the same CD abbreviation there is a subtle difference between both concepts. Continuous Deployment extends Continuous Delivery by adding auto deployment of delivered artifacts to user environments without manual intervention. Though continuous delivery is applied to all kinds of software, business applications, mobile apps and firmware; continuous deployment is applicable mostly when code changes can be immediately applied to production.
