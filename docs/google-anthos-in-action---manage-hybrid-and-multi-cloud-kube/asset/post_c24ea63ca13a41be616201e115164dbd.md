## Working with Skaffold

User interacts with Skaffold using a `Command Line Interface` (CLI). A complete guide for Skaffold can be found here: [https://skaffold.dev/docs/references/cli/](https://skaffold.dev/docs/references/cli/). To have a quick overview of how to work with Skaffold let's have a look at the basic steps. We will see how we can deploy the “Hello world” application written in Go.

### Installing Skaffold

Installing Skaffold varies depending on the underlying Operating System. Skaffold can be installed as a component of gcloud. It is also available as a container image `gcr.io/k8s-skaffold/skaffold:latest` which can be used directly in cloud native CI/CD tools. All installation options are explained in the official site [11]. For local preview you can use Minikube which will allow you to deploy your application on your laptop.

### Skaffold configuration file

Skaffold uses a single configuration YAML file `skaffold.yaml` to define the steps in a CD pipeline. It resembles a Kubernetes resource manifest. Let’s have a look at a very basic sample config file:

```yaml
apiVersion: skaffold/v2beta8
kind: Config
build:
  artifacts:
    - image: skaffold-example
deploy:
  kubectl:
    manifests:
      - k8s-*
```

There are two phases defined in the above pipeline: **build** and **deploy**. In the build phase Skaffold will look for a Dockerfile definition and use it to build a container image with the name `skaffold-example`. In the deploy phase Skaffold uses kubectl to deploy all objects defined in the YAML files starting with the “k8s-” prefix.

A very comprehensive explanation of the configuration file structure can be found on the Skaffold site [12].

### Initiating Skaffold

You can generate a `skaffold.yaml` configuration automatically by running:

```bash
skaffold init
```

This will detect the source files in the current folder and create a very simple configuration file with build and deploy sections. Let’s create three files:

- `Dockerfile` - container image definition
- `main.go` - simple “Hello world” Go application
- `k8s-pod.yaml` - Kubernetes pod definition

https://skaffold.dev/docs/references/yaml/

**Dockerfile content:**

```dockerfile
FROM golang:1.12.9-alpine3.10 as builder
COPY main.go .
ARG SKAFFOLD_GO_GCFLAGS
RUN go build -x -gcflags="${SKAFFOLD_GO_GCFLAGS}" -o /app main.go
FROM alpine:3.10
ENV GOTRACEBACK=single
CMD ["./app"]
COPY --from=builder /app .
```

**`main.go` content:**

```go
package main
import (
    "fmt"
    "time"
)

func main() {
    for {
        fmt.Println("Hello world!")
        time.Sleep(time.Second * 1)
    }
}
```

**`k8s-pod.yaml` content:**

```yaml
apiVersion: v1
kind: Pod
metadata:
    name: getting-started
spec:
    containers:
    - name: getting-started
      image: skaffold-example
```

This will generate a `skaffold.yaml` file that we have already seen in the previous section with two phases:

```yaml
apiVersion: skaffold/v2beta3
kind: Config
metadata:
    name: getting-started
build:
    artifacts:
    - image: skaffold-example
deploy:
    kubectl:
        manifests:
        - k8s-pod.yaml
```

You can take it from here and expand the file as per your needs with use of Skaffold documentation.

### Developing with Skaffold

So we ended up having four files in the folder including the Skaffold config file. Now we can start to do continuous development where Skaffold will be watching the source folder for changes and perform all the steps defined in the `skaffold.yaml` file.

To start the development run the command:

```bash
skaffold dev
```

Skaffold will automatically tail the logs from the deployed container to the console.

Now if you change the source file `main.go` to print “hello from Skaffold” instead of “hello world”, Skaffold will automatically detect the change, rebuild the image, push it to the registry and deploy. As the logs tail to the console, you should see the message “hello from Skaffold”.

### Single run with Skaffold

While `skaffold dev` has been continuously watching the source files, you can also perform a single execution of the workflow by running the `skaffold run` command. This is useful when you want to run the execution only once and not to trigger the flow every time your code is modified.

### Supported features

By now we should have a basic understanding of how to start development with Skaffold so let's have a look at other useful features available.

### Pipeline stages

Till now, we have looked only at the basic functionalities of Skaffold, however the tool has more capabilities that can address advanced pipeline stages. As an example a developer might not want to rebuild the images after every code change. In such a case Skaffold can synchronize the files, such as the `main.go` source file, into the container. To achieve this, you would use the File Sync feature. Below you can find a list of all the currently available stages:

**Figure 14.5 Skaffold workflow**

![](img/fb3bebce7b5f593bca1a7f8a1371be06_487_0.png)

While Figure 14.5 shows all the steps in the workflow, the list below shows all the Skaffold Pipeline stages that can be used to execute those steps:

- **Init** generates basic Skaffold configuration
- **Build** builds images with builders of choice
- **Test** tests images with structure-tests[13]
- **Tag** tags images based on different policies
- **Deploy** deploys the application with kubectl, kustomize or helm
- **File Sync** syncs changed files directly to running containers
- **Log Tailing** tails logs from containers
- **Port Forwarding** forwards ports from services to localhost
- **Cleanup** cleans up manifests and images

### Supported environments

Skaffold supports both local and remote Kubernetes clusters. You can use a local development cluster like Minikube or an Anthos/Kubernetes cluster deployed in a remote location.

To connect to a remote Kubernetes cluster you need to set a context in the `kubeconfig` file like you would need to connect to any Kubernetes cluster. The default context can be overwritten by running the command `skaffold dev --kube-context <myrepo>` or by updating the `deploy.kubeContext` attribute in the `skaffold.yaml` file, e.g:

```yaml
deploy:
  kubeContext: minikube
```

### Supported build tools

If you need to use another tool to build container images, the `build` section of the `skaffold.yaml` configuration file can be configured for custom builders. To use a custom builder, define the proper options for using that builder in the `build` section. Details about custom builders are at [https://skaffold.dev/docs/pipeline-stages/builders/](https://skaffold.dev/docs/pipeline-stages/builders/)

The following tools are currently supported:

- Docker
- Jib[^14]
- Bazel[^15]
- Buildpacks[^16]

You can also use custom scripts that are in line with the Skaffold-defined standard.

### Using Skaffold in CI/CD pipelines

Skaffold can be used as a tool in your CI/CD pipelines. There is already an existing community-maintained builder [^17] that can be directly used with Cloud Build, which is a native Google CI tool (we will have a look at it in detail in the next section). Some of the most useful Skaffold commands in CI/CD workflows are:

- `skaffold build` - builds and tags your image(s)
- `skaffold deploy` - deploys the given image(s)
- `skaffold delete` - cleans up the deployed artifacts
- `skaffold render` - builds and tags images, and outputs templated Kubernetes manifests
