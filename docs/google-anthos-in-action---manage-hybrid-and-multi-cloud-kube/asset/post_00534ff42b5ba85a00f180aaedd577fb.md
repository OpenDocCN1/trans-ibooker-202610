## 14.3.1 Cloud Source Repositories

Cloud Source Repositories[^21] are fully featured, private Git repositories hosted on Google Cloud. The service helps developers to privately host, track, and manage changes to large codebases on Google Cloud Platform. It’s designed to integrate easily with GCP services like Anthos, GKE, Cloud Run, AppEngine and Cloud Functions. You can configure an unlimited number of repositories, and also mirror Bitbucket and GitHub repositories. Changes in Cloud Source Repositories are monitored and can trigger event notifications to Cloud Pub/Sub or a Cloud Function. One of the differentiators of Code Source Repositories is that you can use regex expression to search[^22] for phrases in your repository. Cloud Source Repository audit logs are available in Cloud Operations so you always know who and when has accessed you repository.

## 14.3.2 Artifact Registry

Artifact Registry is a next iteration of the Google Container Registry service.
On top of being able to store container images Artifact Registry can store
other packages like Maven[23], npm[24], and Python[25] with more capabilities
to come soon. The services are fully integrated with the Google Cloud
Platform ecosystem. This means you can control access to your artifacts
using IAM policies, access Cloud Source Repositories, trigger automatic
builds using Cloud Build and deploy to Google Kubernetes Engine, App
Engine and Cloud Functions.

Artifact Repositories can be created in regions closest to your workloads so
you can leverage the high speed Google network to pull your artifacts.

From the security standpoint your containers can be scanned for
vulnerabilities and Binary Authorization can be used to approve the images that can be pushed to production.

You can use native tools to interact with Artifact Repositories so it is easy to make it integrate it into CI/CD pipelines.

## 14.3.3 Cloud Build

We have already seen how we can version the Anthos application code and build container images. Now let's have a look at how we can create a continuous integration pipeline.

Cloud Build is a GCP native CI/CD Platform and is an alternative for tools like Gitlab CI/CD, Jenkins or CircleCI. It allows you to deploy, test and build your application on all Google compute services including Anthos GKE and Cloud Run for Anthos. The Cloud Build pipelines steps are run as containers:

Cloud Build pipelines can either be triggered manually or by code repositories pull requests.

Now that we have understood the basis of how Cloud Build works let's have a look at Cloud Builders.

## Cloud Builders

As we have already learned, Cloud Build runs a series of steps defined in the `cloudbuild.yaml` file. Those steps are executed within containers. The containers are deployed using container images defined in the name attribute of each step. Those container images are called Cloud Builders. They are specially packaged images that run a specific tool like docker, git or kubectl etc. with a set of user defined attributes. There are free types of builders.

- Google supported builders
- Community supported builders
- Custom developed builders

Let’s have a look at each type:

## Google supported builders

You can find a full list of Google supported builders on Github: [https://github.com/GoogleCloudPlatform/cloud-builders](https://github.com/GoogleCloudPlatform/cloud-builders). All the images are available in a container registry under: gcr.io/cloud-builders/<builder name>. Some of the most important builders in the context of Anthos are:

- docker
- git
- gcloud
- gke-deploy
- kubectl

## Community supported builders

If there is no official builder that fits your requirements you can use community builder. There are builders available with tools like *Helm*, *Packer*, *Skaffold*, *Terraform*, *Vault* etc. The complete list of the community Cloud builders can be found here:
https://github.com/GoogleCloudPlatform/cloud-builders-community

## Custom developed builders

You can create your own custom builder for use in your builds. A custom builder is a container image that the Cloud Build pulls and runs with your source. Your custom builder can execute any script or binary inside the container, as such it can do anything a container can do. For instructions on creating a custom builder, see:
https://cloud.google.com/cloud-build/docs/create-custom-build-steps
