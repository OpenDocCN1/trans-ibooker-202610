# Cluster type

Set the type spec value in the Cluster to user as in the example below:

```
---
apiVersion: baremetal.cluster.gke.io/v1
kind: Cluster
metadata:
  name: user-cluster
  namespace: cluster-user-cluster
spec:
  # Cluster type. This can be:
  type: user
```

# Load Balancer config

Next, you need to supply the configuration for the user cluster load balancer. The addresses used in this cannot overlap with IP’s assigned to the first cluster’s load balancing.

```
# Sample user cluster config for load balancer and address pools
loadBalancer:
  vips:
    controlPlaneVIP: 10.200.0.71
    ingressVIP: 10.200.0.72
  addressPools:
  - name: pool1
    addresses:
  - 10.200.0.72-10.200.0.90
```

# Create the cluster

After you complete the cluster configuration file you can create the first cluster with the following command:

```
bmctl create cluster -c CLUSTER_NAME --kubeconfig ADMIN_KUBECONFI
```

Once the user cluster deployment completes, you can use the kubeconfig that is generated to connect to the new cluster.
