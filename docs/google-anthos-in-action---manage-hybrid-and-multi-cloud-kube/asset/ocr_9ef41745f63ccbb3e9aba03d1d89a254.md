Modern software development processes are complex. Producing high quality software at a consistent pace, in a sustainable manner involves a number of processes and tools. The implementation of a CI/CD pipeline is one of the best practices to achieve this. **Continuous Integration (CI)** is the practice of software development where developers check in their code frequently, integrating regularly –at least once a day, and each integration is followed by a validation, that is an automated process to build and test integrated change[^1]. It allows us to achieve reliable, repeatable and reusable builds with constant speed and at a proper level while preventing chaos and improving efficiency.

Continuous Integration is only one aspect of the software delivery process, for a successful pipeline driven development CI must be followed by Continuous Delivery (CD). **Continuous Delivery (CD)**[^2] is the ability to get changes of all types, including new features, configuration changes, bug fixes and experiments, into production safely and quickly in a sustainable way. It applies to infrastructure configurations, application deployment and mobile app publishing, database and static resource modifications. Continuous Delivery can be used in any environment, regardless of the regulatory requirements for a particular organization. A Continuous Delivery pipeline improves delivery of software from source to production by making this process more automated, thus improving reliability, predictability and visibility of the pipeline, which reduces risks[^3].
