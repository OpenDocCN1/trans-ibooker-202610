# Reusability

Enable teams to scale up, simplify and speed up development workflows. A CI/CD pipeline should be implemented in such a way that allows reusing components of the pipeline for similar applications. This not only reduces cost of setting up new pipelines but also improves developers’ efficiency when working with multiple applications across the enterprise.

# Automated tests

In a high quality delivery process it is critical to validate developed systems architecture and functionality. That can be achieved by implementation of a robust automated testing flow as an integral part of the Continuous Delivery pipeline. Modern delivery pipelines should have as many automated tests as possible. These include not only unit, component, system functional tests but also non-functional ones that check capability, availability and security compliance. Automated tests provide almost immediate feedback to developers, decreasing the amount of bugs and error rate for production deployments.

# Trunk based development

Continuous delivery can be significantly slowed down when developers are working in “split brain” environments, where feature or bugfix code branches have a very long lifetime. As a result in big teams code changes can cause conflicts when integrating long live branches. This may require manual activities, grinding CI processes to a halt.
