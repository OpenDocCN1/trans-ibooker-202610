Developers consume infrastructure and do not care how is it delivered. It must meet their requirements related to namespaces and managed services. Responsible team must create a CI/CD pipeline that can be used by for application hosting purposes and have full flexibility to test any changes.

To achieve the goal we can use multiple different tools. If our teams are familiar with Terraform we can utilize already available knowledge and integrate it into out CI/CD pipeline. Such an approach is fully inline with DORA's State of DevOps research program [30]. It defines that one of key success factors for implementation of DevOps in organization is freedom in choice of tools developers and operation people are using. There is one more question, can I deliver such infrastructure even simpler? As we are using GCP managed resources instead of using external tools we can leverage Anthos Config Connector capability described in detail in Chapter “Anthos Configuration Management” to deliver Secret Manager, Cloud Memorystore and Cloud SQL as declared objects in our code repository.

In case of requirement to deliver services for other sources like Anthos on-prem it is important to introduce infrastructure changes starting from day 1 in automated way.
