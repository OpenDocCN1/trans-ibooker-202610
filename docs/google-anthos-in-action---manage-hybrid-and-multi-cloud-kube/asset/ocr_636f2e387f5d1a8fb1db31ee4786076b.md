Now that we have a fully populated configuration file, we can deploy the cluster using the bmctl *create cluster* option:

```
```bash
bmctl create cluster -c CLUSTER_NAME
```
```

Replace **CLUSTER_NAME** with the name of your cluster you defined when you created the cluster configuration file.

This process will take some time, and once the cluster has been successfully created, you will be able to connect it by using the generated kubeconfig file.

# Connect to the cluster

After cluster creation is completed, you can use the kubeconfig file created by the installation tool inside the bmctl-workspace/CLUSTER_NAME folder to connect to it using kubectl.

You can also connect from the GCP Console using a bearer token. Many kinds of bearer tokens are supported. The easiest method is to create a Kubernetes service account (KSA) in the cluster, and use its bearer token to log in.

If you configured the cluster for identity integration with an identity provider it’s possible to authorize existing users and groups to perform specific actions on specific resources creating RoleBindings or ClusterRoleBindings to assign them to roles that have the desired permissions.

After you have created the needed bindings you can log in to the cluster from the GCP console by selecting the option “Authenticate with Identity Provider configured for the cluster”.
