## Anthos Config Management

Anthos Config Management capabilities are described extensively in the Anthos Config Management chapter. Here we recall a couple of them that are especially useful for managing applications and Network Functions deployments on a large fleet of clusters:

- Multiple repository mode
- Cluster Selectors

### Multiple repository mode

Enabling multi repository mode on Anthos Config Management allows to sync configuration from multiple repositories to the same set of clusters. A single **root repository**, typically managed by a central platform team, hosts cluster and centrally defined namespace-scoped configurations, while optional **namespace repositories** are used to configure objects in specific namespaces. This capability extends ACM usage, beyond platform configuration and policies management, to the deployment of applications: it is possible to delegate the setup and control of a namespace repository to an application release team. Centrally defined namespace resources are inherited while the application team is free to configure application-related ones (deployments, config maps, etc.), if there are conflicts between root and the namespace repository only the declaration in the root repository is applied to the cluster.

## 10.2.3 Solution architecture example: Smart Retail

In addition to the deployment examples disseminated in the Architecture Foundations section, here we will describe an edge application architecture built on Anthos for a retailer.

One of the goals of the retailer was to have the smallest possible infrastructure deployed in stores, leaving only end-points as video cameras. The application deployed is a real time queue management. It starts with a video camera monitoring the checkout line at the cash register streaming the video feed in real time through a 5G modem in the store over a 5G connection to a Telecom operator edge location. Telecom operator Network Edge receives all 5G traffic, the software there intelligently sends the retail store traffic to an Anthos Bare Metal cluster deployed in this edge where a container-based ML app runs machine learning inference on the incoming video feed and detects how many people are in line at the retail store, if that number crosses a certain threshold, a notification to open another cash register is sent back to the store over the same low-latency 5G path on which the video feed came in.

In addition to this, the AI/ML app also sends metadata about this and other events to Google Cloud. At a later time, Google Cloud securely processes this information to provide insight to the retailer and be leveraged to train future iterations of the models. With Google Cloud’s sophisticated AI/ML product suite, we can easily train and deploy highly accurate models for any applications anywhere.

Figure 10.10: High Level Architecture for an Edge Smart Retail solution

![](img/fb3bebce7b5f593bca1a7f8a1371be06_329_0.png)

This architecture can be extended to other “Smart Retail” applications, such as per-customer personalization and digital signage, real-time recommendations, contactless checkout, auto restocking of shelves.

All the latency-sensitive processing, as video or image ML inference, happens at the Telecom edge while all the non-real-time components, like model training and data analytics run in the cloud.

## 10.3 Summary

- Market trends and continuously evolving platform capabilities that are driving telco network functions and edge applications towards Kubernetes and Anthos as the ideal deployment platform.
- NFV had the goal of transitioning telco network functions from dedicated, proprietary hardware appliances to virtual machines deployed on industry standard x86 servers, this transformation has probably started but not completely materialized as expected.
- The evolution towards Cloud Native Network Functions (CNFs), deployed as containers on Kubernetes, is poised to provide big improvements in terms of portability, agility, manageability and efficiency and finally realize the promise of NFV.
- 5G is driving the rise of new applications, deployed on edge locations as containerized workloads, and leveraging 5G networks’ higher bandwidth and lower latency, providing near-real-time data processing and allowing smart devices to act and respond to inputs without sending that data to the cloud and back.
- Anthos provides specific capabilities that are key enablers for the deployment, execution and management of Edge and Telco workloads: VM runtime, hardware accelerators, multiple network interfaces per pod, large fleet management.
- Google Distributed Cloud Edge (GDCE) is a fully managed solution from Google, based on Anthos on Bare Metal, designed to support Telco Virtualized and Cloud Native Network Functions and Edge applications, and including software, OS and hardware in Google-managed racks. It can be deployed in Google, Telco or Enterprise Edge.
