Your first task is to install the Google Cloud SDK on your local machine. This can be on a Linux, macOS (workstation or server), or Windows 10 machine.

Once you have installed the SDK, you can now download the gkeadm utility. Before you install this utility, download the latest version using the command below.

```bash
gsutil cp gs://gke-on-prem-release-public/gkeadm/{Anthos on VMware version number}/linux/gkeadm ./
```

If you are using Linux, you will need to make the binary executable using chmod.

```bash
chmod +x gkeadm
```

Once you have downloaded the file, you can deploy the admin workstation.

## Deploying the Admin Workstation

Deploying the admin workstation is based on a single YAML configuration file, in which you will need to include the following:

- vSphere
- Network
- proxyUrl
- adminWorkstation

The vSphere/vCenter connection is a dedicated configuration element. You will need to provide your vCenter credentials and the `componentAccessServiceAccountKeyPath`, which defines a key for a service account. Also provide credentials that have the right to access vCenter in your project and the related project.

```yaml
gcp:
  componentAccessServiceAccountKeyPath: "whitelisted-key.json"
```

The service account key file is used to authenticate with vCenter Server. If your service account has not been authorized on the vCenter Server, create a service account key with the required roles and specify it in the credential file. A sample credential file is shown below.

```yaml
apiVersion: v1
kind: CredentialFile
items:
- name: vCenter
  username: "myaccount@mydomain.local"
  password: "Th4t1$4Nth05"
```

The required vSphere information includes your datacenter name, datastore name, cluster name, network, and the vCenter root certificate. Typically, a customer provides the vSphere certificate in a ZIP file, which is then specified in the vCenter configuration.

```yaml
vCenter:
    credentials:
        address: "10.10.10.10"
        fileRef:
            path: credential.yaml
            entry: vCenter
    datacenter: "MY-DATACENTER"
    datastore: "MY-DATASTORE"
    cluster: "MY-CLUSTER"
    network: "MY-VM-NETWORK"
    folder: "MY-FOLDER"
    resourcePool: "MY-POOL"
    caCertPath: "vcenter-root.cert"
```

If you use a CA-signed certificate for the vCenter server, the certificate needs to be added to the `caCertPath` value. It can be obtained by using the following command:

```bash
curl -k "https://{SERVER_ADDRESS}/certs/download.zip" > download.zip
```

Once downloaded, unzip the file, which will extract the vCenter certificate into a local certificate folder.

If your environment requires you to use a proxy server to access the internet, you can configure a proxy service. This information can be supplied by passing it to the gkeadm command during a CLI deployment.

```yaml
proxyUrl: "https://my-proxy.example.local:3128"
```

If you use a proxy, you will need to add the appropriate addresses to your DNS to set the `no_proxy` variable. This information is specific to your exact company and deployment — a full explanation of how to use a proxy server with all of its options is beyond the scope of this book. As a starting point, you should add the vCenter server, the local registry (if configured), and the IP ranges for the cluster nodes.

The next section lists the following configuration information required for the deployment:

- vSphere username
- vSphere password
- Load balancer IP
- vSphere cluster
- Number of nodes in the cluster
- Kubernetes version installed

## NOTE

Always ensure the folder where new VMs are created exists. Be sure to create it manually first.

The admin workstation can be assigned an IP address using a static IP management policy with a vSphere server. This setting is defined in the network configuration file using the `ipAllocationMode` property.

If your VMs use DHCP, the rest of the child network configuration elements remain undefined.

When using static IP addressing, the `ipAllocationMode` property must be set to “static”, followed by the IP, gateway, netmask, and DNS configuration. The DNS value can be defined as an array of properties with multiple values.

Finally, provide the NTP server address to the admin workstation. It is a mandatory setting to use; any difference in the environment will cause a deployment failure.

An example configuration file is shown below; the first one is configured with a static IP, and the second one is configured with a DHCP address.

```yaml
adminWorkstation:
  name: "gke-admin-ws-200617-113711"
  cpus: 4
  memoryMB: 8192
  diskGB: 50
  dataDiskName: "gke-on-prem-admin-workstation-data-disk/gke-admin"
  dataDiskMB: 512
  network:
    ipAllocationMode: "static"
    hostConfig:
      ip: "10.20.20.10"
      gateway: "10.20.20.1"
      netmask: "255.255.255.0"
      dns:
        - "172.16.255.1"
        - "172.16.255.2"
  proxyUrl: "https://my-proxy.example.local:3128"
  ntpServer: "myntp.server.local"
```

```yaml
adminWorkstation:
  name: "gke-admin-ws-200617-113711"
  cpus: 4
  memoryMB: 8192
  diskGB: 50
  dataDiskName: "gke-on-prem-admin-workstation-data-disk/gke-admin"
  dataDiskMB: 512
  network:
    ipAllocationMode: "dhcp"
    hostConfig:
      ip: ""
      gateway: ""
      netmask: ""
      dns: []
  proxyUrl: "https://my-proxy.example.local:3128"
  ntpServer: "myntp.server.local"
```

Now you can create the admin workstation on the vSphere infrastructure using the gkeadm utility.

```bash
./gkeadm create admin-workstation --auto-create-service-accounts
```

Adding the `--auto-create-service-accounts` flag will also automatically create the required service accounts in your project.

Once the admin workstation has been created, you can use it to deploy the admin cluster. In the next section, we will walk you through the steps to create your admin cluster.

## Creating an Admin Cluster

The admin cluster is the core component of the Anthos control plane. It is responsible for the provisioning and management of your clusters. It’s deployed as a Kubernetes cluster using a single control plane node and two worker nodes [Figure 9.4].

The control plane node provides the Anthos API server for the admin cluster control plane, the admin cluster health checks, and the bootstrap components needed by worker nodes. Worker nodes are used for providing resources such as CPU, memory, and storage to the Anthos on-premises nodes. In addition to the admin control plane and nodes, the admin cluster hosts your vSphere control planes. As a cluster, the host cluster provides the API server, workloads, and management/monitoring functions for the nodes in the admin cluster.

To create an admin cluster, you will need to SSH into your admin workstation that was created in the first section. SSH into the admin workstation using the key that was created when you deployed your admin workstation, located at `.ssh/gke-admin-workstation`.

| Property key | Property description |
|---|---|
| `networkName` | vSphere portgroup name where admin cluster nodes and user cluster master nodes are assigned to. |

An example configuration is shown below.

```yaml
network:
  ipMode:
    type: dhcp
  serviceCIDR: 10.96.232.0/24
  podCIDR: 192.168.0.0/16
  vCenter:
    networkName: "My Anthos on VMware admin network"
```

If you do not want to use DHCP IP addressing, you can configure a static IP configuration file. The path to the file must be specified via the `ipBlockFilePath` option, and `ipMode.type` must be set to `static`. You can optionally specify DNS and NTP server addresses for hosts defined in the file, as shown in the example below.

```yaml
network:
  ipMode:
    type: "static"
    ipBlockFilePath: "myAdminNodeHostConFile.yaml"
  hostConfig:
    dnsServers:
      - "8.8.8.8"
    ntpServers:
      - "myNTPServer"
    searchDomainsForDNS:
      - "myDomain.local"
```

The static block configuration file is built using the following configuration option: specify one block for each node. For a hostConfig, you can define information about vSphere servers, DNS servers, and NTP servers. The block defined in hostConfig must contain the same IP addresses as those defined in the corresponding IP block file; otherwise, the IP address will not be assigned to the correct node.
