# Fig. 16.14 Host Kernel change allowed from a running container

```
[root@localhost ~]# kubectl exec -it root-demo sh
/ # sysctl kernel.domainname=test.com
kernel.domainname = test.com
```

This time, the kernel change worked for two reasons, the first is that the container is running as the root user and the second is that the container was allowed to start up as a privileged container.

For the last scenario, the manifest has been edited to run as user 1000, who does not have root privileges, and to start as a privileged container.

```
apiVersion: v1
kind: Pod
metadata:
  name: root-demo
spec:
  containers:
  - name: root-demo
    image: busybox
    command: [ "sh", "-c", "sleep 1h" ]
    securityContext:
      privileged: true
      runAsUser: 1000
```

Since the container is running as a standard user, and the container is running as a privileged container, any kernel change will be denied.
