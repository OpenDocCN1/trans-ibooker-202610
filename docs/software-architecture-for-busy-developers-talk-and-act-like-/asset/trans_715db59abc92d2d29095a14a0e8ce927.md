

- **在解决方案交付过程中发挥积极作用：** 与开发团队保持密切跟进，并对瀑布和敏捷方法论有良好的理解，无疑会带来更顺畅的交付。
- **主动关注技术以识别新趋势和范式转变：** 技术是赋能者。大多数数字原生公司都善于利用技术，并因此成为 Netflix、Facebook 等。优秀的软件架构师必须始终关注不断演进的技术格局。

更重要的是，优秀的软件架构师必须具备良好的判断力。他们不应盲目应用框架 x 或 y，也不应盲目应用模式 a 或 b。他们必须结合上下文明智地运用自己的技能。让我们现在来发现各种架构学科。

## 介绍不同的架构学科

有如此多的架构师类型，我们很容易迷失并疑惑企业中谁负责什么。由于这种理解是一项必备资产，让我们先回顾一下不同的学科，我将在下一节中将软件架构定位其中。下面的图表展示了一些最常见的架构学科及其主要职责：

![](img/78092c233296cbd7723546ae74eec12d_18_0.png)

图 1.1 – 架构学科：主要职责

从前述图表的顶部到底部，您可以按优先级顺序找到主要职责。并非所有学科都已列出，但主要学科都有。值得注意的例外是云架构，我们稍后会谈到。我们将在下一章讨论其中一些相关框架。现在让我们关注每个学科的范围。

## EA

**企业架构师**负责监督 IT 和业务战略，并确保每个 IT 举措都与企业业务目标保持一致。他们直接向 IT 领导层汇报，有时分散在各业务线中。他们也是为各自公司构建连贯一致的整体 IT 格局的守护者。

大多数情况下，企业架构师对 IT 格局有整体的视野，并不关心技术细节。他们的首要重点是识别和设计业务能力。他们得到业务架构师的帮助，后者通常也是 EA 职能的一部分。他们的角色包括定义战略方向并确保其标准在团队中得到贯彻。他们通常使用**The Open Group Architecture Framework (TOGAF)**来定义流程，并使用 ArchiMate 来构建不同领域的视觉模型。在某些组织中，EA 职能可能会为大型项目或计划指派专门的企业架构师。

## 解决方案架构 (SolAr)

解决方案架构师帮助不同团队构建解决方案。他们拥有所谓的*T 型*技能，因为他们负责监督解决方案的**端到端 (E2E)** 设计。他们主要关注 NFR，以确保解决方案适合使用。与软件架构师一样，他们也会关注 FR（确保其适合目的），但他们不参与功能的实际开发。

## 基础设施架构 (IA)

基础设施架构师专注于构建和运营跨工作负载共享的特定应用基础设施和平台。他们的一项职责是保持系统运行，确保邮件系统和与工作场所相关的服务等通用服务正常运行。基础设施围绕**IT 服务管理 (ITSM)** 组织起来，这大多数时候基于**IT 基础设施库 (ITIL)**。基础设施部门还提供服务台功能。许多组织已经开始转向（或已转向）ServiceNow，这是一种更现代化的 ITSM 处理方式。

## 安全架构 (SA)

在这个高度互联的世界中，网络安全的重要性大大提升。SA 处理监管或内部合规要求。在现代，越来越多的工作负载部署到云中，这通常会强调安全问题，因为许多组织仍处于云迁移的途中，或正准备开始。

安全领域分为不同的子学科，例如**安全运营中心 (SOCs)**、专用安全硬件和软件的管理、**身份和访问管理 (IAM)**，以及整体安全治理，也称为**安全态势**。在中大型组织中，您可以找到蓝队（防御）和红队（攻击），由技术安全专家组成。他们与 SOC 一起评估企业整体韧性的稳健性。SA 实践通常由**首席信息安全官 (CISO)** 管理，尽管该角色有时也由**首席信息官 (CIO)** 承担。

根据您所在的行业，安全通常是较少为人所知的 NFR，业务方对其理解不足，导致在该方面完全缺乏业务需求。安全意识培训通常是必要的，以提醒企业安全的重要性。简而言之，安全实践的开展方式在很大程度上取决于文化、风险偏好和组织的 DNA。

## 数据架构 (DA)

数据架构师负责监督整个数据格局。他们主要专注于为存储、洞察和高级分析设计数据平台。他们处理数据建模、数据质量和**商业智能 (BI)**，后者包括从数据中提取有价值的洞察以实现实质性业务收益。组织良好的数据架构最终应提供**数据-信息-知识-智慧 (DIKW)** 金字塔，如下图所示：

![](img/78092c233296cbd7723546ae74eec12d_21_0.png)

图 1.2 – DIKW 金字塔

组织拥有大量数据，他们试图从中提取有价值的信息和知识，并随着时间的推移获得智慧。金字塔攀升得越高，价值越大。请考虑以下场景以理解 DIKW 金字塔：

| 级别 | 示例 |
|---|---|
| **数据** | 31, 3, 3000<br><br>31, 3, 3100<br><br>31, 3, 3500 |
| **信息** | Day: 31, Month: March, Concurrent Users: 3000 |
| **知识** | 3000 concurrent users visited our web site on March 31. We know that this is way above our daily average, which is about 650 concurrent users. March 31 is always a busy day, year after year. |
| **智慧** | We’ll make sure to restock warehouses before March 31. |

图 1.3 – DIKW 金字塔示例

这表明，数据架构师的工作之一是帮助组织从数据中学习。

## 应用架构 (AA)

应用架构师专注于构建业务要求的特性。他们确保开发的应用*适合目的*。他们强制执行编码模式和指南，以使应用易于维护和阅读。他们的首要关注点是与各种框架和生态系统集成。他们的角色类似于软件架构师，但在我看来，其范围更有限。现在让我们将软件架构定位在各种学科中。

## 总结

在本章中，我通过在不同公司和行业中的真实经验，阐述了我对软件架构的理解。我们回顾了在定位软件架构时出现的不同架构学科，我希望你能意识到，要成为一名成功的软件架构师，你需要了解其他所有学科的一点知识。我希望你能理解本书的价值主张，并准备好踏上这段软件架构之旅。
