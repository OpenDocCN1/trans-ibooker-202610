
监控结果在仪表板中显示，但当它们触发警报和纠正措施时，可以带来更显著的价值。例如，模型漂移指示可以启动再训练流程，改变模型集成中的权重，或向管理员发送关键通知以纠正问题。因此，解决方案应提供一种机制来轻松定义条件、阈值和操作。

模型监控的解决方案有两种类型，将在以下章节中描述：
* *集成*: 数据科学或 MLOps 平台的组成部分。通常功能较少，但不需要胶水逻辑和单独管理。
* *独立*: 专用监控解决方案通常功能丰富，但需要手动集成和单独管理。

## 集成模型监控解决方案

数据科学或 MLops 平台支持开发和部署模型所需的任务。当您部署模型时，平台通常提供基础模型监控，可通过最少的配置进行操作。集成监控解决方案显示模型端点的重要性能和健康信息。大多数平台支持漂移检测，只有少数平台支持额外的监控类别。

### AWS SageMaker

[AWS SageMaker](https://docs.aws.amazon.com/sagemaker/latest/dg/model-monitor.xhtml) 支持数据和模型漂移检测（请参阅 [图 6-9](#ch06.xhtml#sagemaker-model-monitor-architecture) 中的架构）。模型端点将传入请求和模型结果捕获到 S3 对象中，并将其与基线和真实数据集进行比较以计算漂移和准确率指标。

![](assets/sagemaker-model-monitor-architecture.png)

在 SageMaker 中，您手动生成并将参考数据集上传到 S3，然后定义一个计划的模型监控作业（请参阅 [示例](https://sagemaker-examples.readthedocs.io/en/latest/sagemaker_model_monitor/introduction/SageMaker-ModelMonitoring.xhtml)）。

您可以在 SageMaker UI 中查看模型指标和漂移指示（请参阅 [图 6-10](#ch06.xhtml#sagemaker-model-monitor-ui)）。

![](assets/sagemaker-model-monitor-ui.png)

### Google Vertex AI

Google [模型监控](https://cloud.google.com/vertex-ai/docs/model-monitoring/overview) 支持将模型请求和结果跟踪到 BigQuery 表中，并在指定阈值被超过时发出电子邮件警报。[图 6-11](#ch06.xhtml#vertex-ai-monitoring) 演示了用户如何启用监控、设置监控策略并上传参考数据（模式和统计信息）。

![](assets/vertex-ai-monitoring.png)

关键的模型端点指标和漂移信息在 UI 中可视化（请参阅 [图 6-12](#ch06.xhtml#vertex-ai-endpoints) 和 [图 6-13](#ch06.xhtml#vertex-ai-endpoints-skew)），您可以通过 BigQuery 访问完整数据。

![](assets/vertex-ai-endpoints.png)![](assets/vertex-ai-endpoints-skew.png)

### MLRun Model Monitoring

MLRun 开源 MLOps 包含用于批处理和实时工作负载的集成 [监控服务](https://docs.mlrun.org/en/latest/concepts/monitoring.xhtml)。如 [图 6-14](#ch06.xhtml#mlrun-monitoring-arch) 所示，MLRun 模型服务端点将性能、输入、输出和用户定义指标写入流中。然后，实时无服务器 Nuclio 函数读取并处理数据，并将结果写入不同类型的存储（键/值、时序数据库和 parquet 文件）。计划的 MLRun 作业定期运行，读取数据，计算各种指标（漂移、准确率等），并触发适当的警报。

![](assets/mlrun-monitoring-arch.png)

您可以在 MLRun UI 中查看模型端点信息（请参阅 [图 6-15](#ch06.xhtml#mlrun-model-endpoints-histogram)），或在 Grafana 中查看（请参阅 [图 6-16](#ch06.xhtml#mlrun-monitoring-grafana)）以及生产数据集存储在 MLRun 的特征存储中，可用于生产后分析（例如分析数据质量、偏差和可解释性）或用于重新训练模型。

![](assets/mlrun-model-endpoints-histogram.png)![](assets/mlrun-monitoring-grafana.png)

MLRun 通过自动生成参考和生产数据集、管理数据资产和生命周期、调度和扩展监控任务等，消除了许多工程工作。

当您在 MLRun 中训练模型时，参考数据（模式、统计信息等）会自动生成并与模型一起保存。您也可以通过 API 手动更新参考数据。要操作监控功能，您应在服务函数中应用 `_set_tracking()` 选项。

MLRun 支持监控插件，并具有可扩展性以支持结构化和非结构化数据的先进监控应用。

## 独立模型监控解决方案

有几种专门用于模型监控的解决方案。它们通常比集成选项具有更先进的功能和用户界面，但需要与数据资产、服务和训练框架进行手动集成。此外，它们需要使用多个管理控制台。

商业产品的示例包括 [Aporia](https://www.aporia.com/)、[Arize](https://arize.com/)、[Whylabs](https://whylabs.ai/) 和 [Mona Labs](https://www.monalabs.io/)。

商业框架通常支持多种监控应用（漂移、准确率、数据质量等）、友好且丰富的用户界面、高级策略以及多种警报和触发选项（电子邮件、Slack、webhooks 等）。

您可以在 [图 6-17](#ch06.xhtml#aporia-wizard) 中看到创建新监控任务的示例 Aporia UI 向导。

![](assets/aporia-wizard.png)

挑战在于将预测和参考数据上传到存储并管理数据生命周期，而不是像 MLRun 等集成平台那样开箱即用。请参阅 [示例 6-17](#ch06.xhtml#aporia-upload-data) 中的代码示例，了解如何上传批量预测数据。（实时预测数据需要额外一步将流转换为 parquet 文件）。

### 示例 6-17. 将预测输入和输出写入 parquet 文件（来源 Aporia）

```
import fastparquet

# Preprocess & predict
X = preprocess(...)
y = model.predict(X_pred)

# Concatenate features, predictions and any other metadata

# Store predictions
fastparquet.write(
    filename=f"s3://my-models/{MODEL_ID}/{MODEL_VERSION}/serving.parquet",
    data=df,
    append=True,
)
```

Aporia 监控仪表板的示例显示在 [图 6-18](#ch06.xhtml#aporia-monitor) 中。

![](assets/aporia-monitor.png)

一个流行的开源模型监控框架是 [Evidently](https://www.evidentlyai.com/)，它监控漂移和数据质量。Evidently 将参考数据集与预测数据集进行比较并生成精美的静态 HTML 报告。此外，它可以将结果指标写入 Prometheus 并在预设计的 Grafana 仪表板中显示。

[示例 6-18](#ch06.xhtml#evidently-code) 演示了如何生成报告，将参考数据与预测输入和输出数据（`current_data`）进行比较。在 [图 6-19](#ch06.xhtml#evidently-reports) 中您可以看到报告示例。
