## 运行、跟踪和比较 ML 作业

从很多方面来看，对于传统软件工程师而言，运行、跟踪和比较 ML 作业的概念并没有什么新意。软件工程师在部署服务时会关注 `CPU`、`Memory`、`Disk I/O` 以及微服务响应时间。机器学习运维非常适合软件工程监控的传统范围。

让我们以 Azure Databricks 作为运行、跟踪和比较 ML 作业的简化玩具示例 [图 5-3](#ch05.xhtml#Figure-5.8-databricks-mlops)。从高层次来看，这是一个端到端的 MLOps 解决方案，允许您使用 `AutoML` 创建实验、提供模型，然后在许多不同的环境中提供模型，包括通过 Databricks 端点在 Databricks 本身中提供，或在 Azure、AWS、GitHub Codespace 或更多环境中的容器化部署。

![](assets/5.8-databricks-mlops.png)

让我们进一步分解并讨论每一步。注意，Kaggle 上关于 [分类虚假新闻](https://www.kaggle.com/datasets/ruchi798/source-based-news-classification) 的数据集开始了这一旅程。接下来，该数据集上传到 `DBFS`（`Databricks File System`）。`DBFS` 是一个挂载到 Databricks 工作区并在 Databricks 集群上可用的分布式文件系统。您可以使用许多简单的 Kaggle 数据集来尝试此工作流。在 [图 5-4](#ch05.xhtml#Figure-5.9-databricks-ui) 中，数据砖 UI 基本上绘制了该管道中的许多顺序步骤，从数据到计算到模型再到服务等。

### 使用模型工件保存必要的元数据

如 [以下示例](https://github.com/noahgift/mlflow-project-best-practices/blob/main/download-model.py) 所示，还有另一种方法可以在 Databricks 中处理使用 `AutoML` 创建的模型。将模型下载到基于云的环境中可以提供更多利用推理的方式。在此示例 [示例 5-1](#ch05.xhtml#download_model) 中，模型使用 `mlflow` API 本地下载。

##### 示例 5-1. 下载模型 (`download-model.py`)

```
from mlflow.store.artifact.models_artifact_repo import ModelsArtifactRepository
from mlflow.tracking import MlflowClient

client = MlflowClient()
my_model = client.download_artifacts("68baff0203344dfebe89a6c73c6d6cfe", path="model")
print(f"Placed model in: {my_model}")
```

您可以按如下 API 调用所示列出模型 [示例 5-2](#ch05.xhtml#list_model)，这使您可以搜索符合您在类型、准确率等方面要求的模型。

##### 示例 5-2. 列出模型 (`list-models.py`)

```
from pprint import pprint
from mlflow.tracking import MlflowClient

client = MlflowClient()
for rm in client.list_registered_models():
    pprint(dict(rm), indent=4)
```
