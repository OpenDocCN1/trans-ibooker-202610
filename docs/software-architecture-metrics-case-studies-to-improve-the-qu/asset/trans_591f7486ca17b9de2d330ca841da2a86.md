
上下文很重要，而找到合适的指标是旅程中的一步。复制其他组织使用的指标行不通，因为上下文不同。发现适合自己组织的指标是对有意为之的投入，随着组织的发展，这种投入会得到回报。

指标趋势至关重要，可以揭示超出技术层面的信号。它们与社会技术架构密切相关，因为归根结底，是人类设计、构建和维护软件。我真诚地相信，一代新的软件架构师正在崛起，他们具备应对这些社会技术挑战的技能。

# 第7章. 软件架构中的度量作用

Eoin Woods

软件架构有很多定义，但在实践中，大多数具有架构意义的决策都与实现满足利益相关者的系统质量有关，包括性能、弹性 和 安全性。架构师通常将这些称为质量属性或非功能性质量。

这些重要而复杂的决策往往难以做出，因为它们涉及不同质量之间重大的权衡。例如，优先考虑弹性可能意味着降低性能。利益相关者常常难以确定自己需要哪些质量属性。

架构师过去解决这些复杂问题的方式是进行大量的“前期”设计和时间与磁盘使用。考虑何时可以执行每项工作以及它们能提供什么见解是有用的。[图 7-2](#ch07.html#types_of_measurem) 显示了一些沿两个轴分类的度量示例：制品/运营和外部/内部度量。

![](assets/sarm_0702.png)

*外部度量* 对系统交付和运营团队之外的人可见，或对其有直接影响。*内部度量* 对交付和运营团队可见，或对其有直接影响。在交付周期的不同点测量这些指标可提供不同类型的见解。让我们逐一查看每个象限：

### 外部制品度量
