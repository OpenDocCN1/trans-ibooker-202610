

我们还必须记住，`TAG` 仅在创建和更新操作期间执行，*而不*用于删除 `stack instances`。

## 总结

在本章中，我们了解了 `StackSets`、它们的用例、如何部署它们以及如何处理故障。

`StackSets` 是一项很有前景的功能，尽管它们引入了一些复杂性，并且不易与持续交付系统集成。尽管如此，当你想要在多个区域甚至多个账户中预置相同的堆栈时，它们非常实用。

当你被要求将相同的环境和资源部署给客户时，请考虑使用 `StackSets`——例如，如果你提供 B2B SaaS 平台，或希望自动化开发、测试、预发布和生产环境的部署。如果你需要在各个国家和大洲都有接入点，`StackSets` 对于跨多个区域复制应用程序也很有用。

在下一章中，我们将使用 `cfn-init`（CloudFormation 的辅助脚本）在 `EC2` 资源上安装软件。敬请期待！

## Introducing cfn-init（cfn-init 简介）

CloudFormation 是一种声明式工具。这意味着模板中的所有内容都是对 CloudFormation 状态中应有内容的声明。既然你使用资源属性来声明基础设施，也必须将配置存储在其中，无论是 `Lambda` 函数中的源代码，还是 `EC2` 启动模板、启动配置或实例中的 `user-data`。

使用 `user-data` 过程非常简单，但很难在其中声明配置。最终你将编写大量 Shell 代码，这不像配置管理应有的那样可靠。

幸运的是，CloudFormation 有一组所谓的 `helper scripts`（辅助脚本）——这些工具可以从 CloudFormation 的元数据或堆栈获取数据，对其进行处理并对资源执行操作。其中之一称为 `cfn-init`。

> **Important note**（重要提示）
>
> `cfn-init` 工具（以及任何其他辅助脚本）仅作为发行版的一部分包含在 Amazon Linux AMI 中。对于其他 Linux 或 Windows 发行版，你必须先安装它。有关更多信息，请阅读 AWS 关于辅助脚本的文档：[https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-helper-scripts-reference.html](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-helper-scripts-reference.html)。

`EC2` 实例支持引导以进行初始配置和软件安装。这种引导称为 `user-data`，一个简单的 Bash 脚本，在实例启动后立即在 root 用户下运行。

`cfn-init` 实际上是如何应用于 user-data 的？它只是被添加到资源声明中的 user-data 块里。例如，我们可以通过添加命令和参数（如下面的代码所示）来指示 `EC2` 资源运行 `cfn-init`：

```
UserData: !Base64
  'Fn::Join':
    - ''
    - - |
        #!/bin/bash -xe
      - |
        # Install the files and packages from the metadata
      - '/opt/aws/bin/cfn-init -v '
      - '            --stack '
      - !Ref 'AWS::StackName'
      - '            --resource MyInstance '
      - '            --configsets DeploySoftware '
      - '            --region '
      - !Ref 'AWS::Region'
      - |+
```

在前面的代码片段中，我们可以看到 root 用户将运行 `cfn-init` 命令，并向其提供必要的参数，如堆栈名称、要引用的资源、`ConfigSets` 和 `AWS` 区域。

但这些数据是从哪里获取的？查看参数，我们可能会注意到 `cfn-init` 正试图与堆栈对话。

你可能还记得在[第 2 章](#B10533_02_Final_NM_ePUB.xhtml#_idTextAnchor031) *Advanced Template Development*（高级模板开发）中，我们研究了堆栈或资源 `metadata`（元数据）。`Metadata` 包含关于资源或整个堆栈的具体细节。元数据有特定的键，我们将要使用的一个键称为 `AWS::CloudFormation::Init`。

此 `AWS::CloudFormation::Init`（为简单起见，我将其称为 `init`）元数据只能包含在 `EC2` 资源中，如实例、启动配置或启动模板。

`Init` 是一个简化的配置管理系统，可对 `EC2` 资源执行以下操作：

* 运行命令
* 将文件写入磁盘（例如，配置文件）
* 创建组
* 创建用户
* 安装软件包
* 启动、启用和停止服务
* 从各种来源下载数据（`GitHub` 或 `S3`）

假设我们要在 `EC2` 实例上安装并运行 Apache Web 服务器。为此，我们的 init 元数据应如下所示：

```
Web server:
  Type: AWS::EC2::Instance
  Metadata:
    AWS::CloudFormation::Init:
      configSets:
      - "Deploy"
      Deploy:
        InstallAndRun:
          packages:
            yum:
              httpd: []
          services:
          # this is a key for init metadata.
          # cfn-init will use init.d or systemd if necessary
            sysvinit:
              httpd:
                enabled: "true"
                ensureRunning: "true"
```

在这里，我们在资源的元数据中声明 `init`，并使用两个 init 键：`packages` 和 `services`。这些键（例如，要执行的操作）在 `ConfigSet` `InstallAndRun` 下声明。现在我们要做的就是将 `cfn-init` 添加到 `UserData` 块中：

```
Webserver:
  Type: AWS::EC2::Instance
  # Metadata block…
  Properties:
  # some properties…
    UserData: !Base64:
      Fn::Join:
        - ""
        - - |
            #!/bin/bash -xe
          - |
```
