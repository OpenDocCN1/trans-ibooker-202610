Remember that we said a client was the method by which you access the resource. In our case, our client is our UWP application; however, it could be a web application, a console application, or even an application written in Python or Go – it doesn't have to be .NET.

You'll recognize the client ID and the client secret from the client (typically, you would set the server up first and then use that information for the client, not the reverse, like we've done here).

We've set the grant type – we'll return to this later and discuss it in more detail – and we've set the scope. The scope tells IdentityServer what this client is allowed to do. This means that you can have multiple clients logging onto a system and restrict access purely based on the client.
