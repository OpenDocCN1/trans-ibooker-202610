
# F3EAD：情报驱动的事件响应循环

为了促进这一过程，F3EAD 使用了联合情报与行动循环的修改版本：Find（发现）、Fix（锁定）、Finish（终结）、Exploit（开发利用）、Analyze（分析）、Disseminate（传播）。正如你将看到的，这意味着要经历事件响应循环，将结果反馈到情报循环中，然后将这些结果再连接回一个新的事件响应循环。

## Find

**Find（发现）** 阶段包含行动的 *targeting（目标确定）* 阶段，即确定你将应对的威胁。这可以来自许多来源，例如供应商情报或开源情报。理想情况下，你自己之前的情报循环也应该反哺这一过程。根据行动或投资的不同，该阶段可能由 IR 团队自身决定，配合情报团队，甚至与这些团队之外的群体合作，如 SOC 或管理层。这与事件响应循环的 Preparation（准备）阶段相呼应。

## Fix

基于 Find 阶段的信息，**Fix（锁定）** 阶段建立遥测数据，确定对手在网络中的位置以及我们能检测到的任何外部存在。澄清一下，*fix* 并不意味着修复（我们最初也困惑过！）；它指的是识别对手在网络中的作战存在。这涉及获取可用信息，弄清对手可能攻陷了哪些系统、服务或资源，他们的通信渠道是什么，以及他们如何在你的网络中横向移动。我们可以将其视为事件响应循环的 Identification（识别）阶段。

## Finish

**Finish（终结）** 阶段包含实际的事件响应行动（这与该流程最初军事版本中预期的更具动能和致命性的行动形成对比——请勿执行那些行动）。这是你对对手采取决定性行动的时刻，执行事件响应循环中的 Containment（遏制）、Mitigation（缓解）和 Eradication（根除）阶段。

F3EAD 的主要转变在于 IR 行动的结束并不代表循环的终结。无论组织是在团队间转移资源和职责，还是同一团队改变自身活动重心，Finish 阶段的结束都标志着 Exploit 阶段的开始。F3EAD 流程的情报半程由此启动。

## Exploit

**Exploit（开发利用）** 阶段大致对应情报循环的 Collection（收集）阶段，主要区别在于该阶段激光聚焦于循环作战阶段从对手处收集的信息。对于情报驱动的事件响应，以下信息特别有用：

- 任何指标（IOC），包括 IP 地址、URL、哈希值和电子邮件地址
- IOC 的自动化扩充（如获取给定 IP 的反向 DNS 或收集 WHOIS 数据）
- 漏洞利用投递样本
- 恶意软件样本
- 常见漏洞与暴露（CVE）及漏洞利用代码
- 用户和事件报告
- 对手的通信记录
- 先前已识别的 TTP
- 对手的目标、意图和动机

不可能列出所有可能有用的内容，但分析师应尽可能收集关于攻击各个阶段的更多信息。结合 Kill Chain（杀伤链）思考，并尝试在可能的情况下收集每个阶段的信息。

## Analyze

**Analyze（分析）** 阶段映射到（毫不意外）情报循环的 Analyze 阶段。此阶段的目标是评估收集的信息对短期和长期活动影响的启示。这通过以下几种方法实现：

- 总结战术、技术与程序（TTP）
- 将数据放入模型或框架中以便进一步分析
- 解读时间线和杀伤链以得出可执行的建议

与通用情报阶段一样，Analyze 阶段本身也是循环的。恶意软件分析可能产生更多 IOC，这些 IOC 本身可以被扩充，并可能导致发现更多恶意软件。总体目标是建立对行动者及其 TTP 的完整图景，重点关注如何检测、缓解和修复其行动。

## Disseminate

只有在正确的时间、以正确的格式将情报传递给正确的受众，使其有足够时间吸收并采取行动，情报才有用。传播不仅仅是推送信息——它是识别决策者所需的信息，以他们可消费的方式交付，并随时准备回答问题或接受后续信息请求。情报传播主要关注受众，而非个人分析师偏好的工作方式。因此，理解受众至关重要，受众通常分为以下类别：

**Tactical（战术层面）**
: 情报最直接的受众是事件响应团队，反馈到下一个 F3EAD 循环的开端。他们关注 IOC 和汇总的 TTP。

**Strategic（战略层面）**
: 通常只需一次重大事件，管理层就会开始对 IR 和威胁情报团队产生强烈投入和兴趣。他们的兴趣在于高度概括的 TTP（更关注战役而非单一事件）和目标行动。此情报应为未来的资源分配和更大规模的业务规划提供决策支持（例如，为风险评估提供依据）。

**Third party（第三方）**
: 许多组织参与某种形式的威胁情报共享小组。每个组织必须确定自己的参与交战规则。与领导层和法务团队合作，确定最佳执行方式。根据目标和合作意愿，这可能包含任何抽象层级的情报。

无论情报层级或受众如何，你都希望传播的信息清晰、简洁、准确且可执行。

## Using F3EAD

F3EAD 是可以实施的最强大概念之一，能同时改进安全运营的威胁情报和事件响应两侧。它也是最困难的概念之一。很难解释为什么一个大多数人甚至不知道如何发音的晦涩特种部队首字母缩写，应该成为 IT 部门标准操作程序的一部分，但它提供了一个关键的缺失拼图：行动如何产出更好的情报，反之亦然。

在思考其具体形态时，不要纠结于细节，而应关注整体概念：安全运营和事件响应成为威胁情报的输入，威胁情报成为安全运营和事件响应的输入。每当安全运营团队的任何部分（无论是 SOC、CIRT 还是个人工程师）完成一次事件响应，其所有输出、文档、笔记、取证工件、恶意软件和研究都应传递给情报团队。随后，情报团队开发利用并分析这些信息。基于该事件的输出应反馈给运营团队，循环由此持续。这最终形成了一种安全运营/威胁情报 OODA 循环——Observe（观察）、Orient（判断）、Decide（决策）、Act（行动）。安全运营团队利用情报的速度越快，完成运营任务的速度就越快，进而驱动更多情报产出。
