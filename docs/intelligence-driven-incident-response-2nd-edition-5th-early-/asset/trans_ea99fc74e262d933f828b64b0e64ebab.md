
# 情报周期

## 分析阶段

分析阶段的目标是回答情报周期中方向阶段确定的问题。答案的类型将由问题的性质决定。在某些情况下，分析可能会生成一种新的情报产品，形式为报告；也可能简单到只是一个是/否的答案，通常伴随着一个置信度值。在开始分析之前，了解输出内容将是什么非常重要。

分析不是一门完美的科学，通常必须在信息不完整和不确定性的情况下进行。分析师识别并清楚地说明其分析中的任何信息缺口非常重要，以便决策者能够了解分析中潜在的盲点。信息缺口还可以驱动收集过程，以识别新来源来减少这些缺口。如果缺口大到分析师认为凭借当前信息无法完成分析，则可能有必要返回收集阶段并收集更多数据。推迟最终分析总比提供分析师明知有缺陷的评估要好得多。

重要的是要注意，所有情报分析都是由人生成的。如果是自动化的，那实际上是处理，这是情报周期中的关键步骤，但本身不构成分析。

## 传播

此时，流程已生成真正的情报：对方向阶段提出问题的情境化回答。一份包含答案的报告，在共享给相关利益相关者（即能够使用该情报的人）之前是毫无用处的。在许多有据可查的情报失败案例中，分析非常准确，但传播却失败了。必须以利益相关者认为最有用的形式与他们共享情报。这使得传播取决于受众。如果产品面向高管，考虑篇幅和措辞很重要。如果面向技术系统实施（如 IDS 或防火墙），这可能需要特定供应商的编程格式。无论如何，情报必须可被相关利益相关者使用。

## 反馈

反馈阶段常被遗忘，但它是持续情报工作的关键。反馈阶段询问生成的情报是否成功回答了方向要求。这会导致两种结果之一：

**成功**

: 如果情报流程回答了问题，周期可能就结束了。不过在许多情况下，成功的情报流程会根据新问题或基于给定答案采取的行动，引出对更多情报的请求。

**失败**

: 在某些情况下，情报流程失败了。在这种情况下，反馈阶段应重点关注识别原始方向中未得到妥善回答的方面。后续的方向阶段应特别注意解决失败的原因。这通常归结为：结构不佳的方向阶段未能充分缩小目标；或不完整的收集阶段无法收集足够数据来回答问题；或不当的分析未能从可用数据中提取正确（或至少有用）的答案。

# 使用情报周期

让我们考虑如何利用情报周期开始了解一个新的对手。

首席信息安全官（通常缩写为 CISO）最常问的问题之一（希望在别人问她之前）是：“我们对这个我听说的威胁组织了解多少？”CISO 将希望基本了解某组织的能力和意图，以及其与特定组织的相关性评估。那么在这种情况下，情报流程是什么样的呢？以下是情报周期各步骤为满足 CISO 需求所涉及内容的示例：

## 方向

这来自关键利益相关者：CISO。“我们对 `X` 威胁组织了解多少？”真正寻求的答案是一个目标包，我们稍后将详细探讨。

## 收集

从原始来源开始，最可能是新闻文章或报告。该文档通常将为开始收集提供至少一些背景。如果源材料包含关于特定入侵或攻击的信息，了解更多关于被攻击实体的情况，并识别入侵的潜在动机或目标，会很有帮助。如果存在指标（IP、URL 等），请通过关联和丰富尽可能深入地探索它们。来源本身可能指向包含 IOC、战术、技术和程序 (TTP) 或其他分析的额外报告。

## 处理

这非常依赖于工作流/组织。将所有收集到的信息放入一个可以最有效使用的地方，可能只是简单地将所有信息放入单个文本文档，也可能需要将所有信息导入分析框架。可以使用与该组织相关的技术细节进行额外的丰富。此外，可能需要翻译报告或其他文档。

## 分析

利用收集到的信息，分析师将首先尝试回答关键问题：

* 这些攻击者对什么感兴趣？
* 他们通常使用什么战术和工具？
* 防御者如何检测这些工具或战术？
* 这些攻击者是谁？（虽然这始终是一个问题，但并不总是值得花时间去回答。）

## 传播

对于这种有特定请求者（CISO）的产品，一封简单的电子邮件可能就足够了。虽然在某些情况下将回复限制在此范围内是合理的，但用于主动分发给他人的真正产品几乎总是能创造更大的价值。

## 反馈

关键问题：CISO 对结果满意吗？这是否会引出其他问题？这些反馈有助于闭环，并可能开启新一轮收集。

情报周期是一个通用模型，可用于回答大大小小的问题。然而，重要的是要注意，遵循这些步骤不会自动产生良好的情报。

# 良好情报的特质

情报的质量主要依赖于两件事：收集来源和分析。在网络威胁情报中，我们很多时候最终处理的是我们自己并未收集的数据，因此我们必须尽可能多地了解该信息，这至关重要。当我们自己生成情报时，也需要确保我们了解收集来源，并解决分析中的偏见。以下是应考虑的一些事项，以确保产出高质量情报：

## 收集方法

了解信息主要是从事件或调查中收集，还是从蜜罐或网络传感器等自动化收集系统中收集，这很重要。虽然了解收集的确切细节并非绝对必要——一些提供商倾向于保密其来源——但可以在不损害收集资源的前提下，基本了解数据来源。你掌握的关于信息收集方式的细节越多，你对该信息的分析就会越好。例如，知道数据来自蜜罐是好的；但知道它来自一个配置为识别针对远程 Web 管理工具暴力破解尝试的蜜罐会更好。
