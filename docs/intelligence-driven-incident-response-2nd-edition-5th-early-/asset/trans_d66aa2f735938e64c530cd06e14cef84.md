

# 杀伤链

杀伤链是抽象对手 TTP（战术、技术与过程）的好方法。它提供了一种结构来理解攻击的抽象动作。

尽管杀伤链的早期阶段，特别是目标确定和侦察，有时对防御者来说是不透明的，通常难以检测且依赖具体情境，但它们值得理解。防御者倾向于认为对手每次都能零成本成功。这与事实相去甚远。事实上，我们稍后破坏这些入侵前阶段的能力，可能是防御者拥有的最强优势之一。

## 目标确定

在杀伤链正式开始之前，对手必须决定攻击什么（例如，潜在目标是谁）。在许多情况下，这发生在与某种形式的发起方或利益相关者协商过程中，通常作为其自身情报或作战需求的一部分。作为防御者，我们通常将目标视为受害组织，但在许多情况下，这不如被瞄准的信息或能力重要。

目标确定是杀伤链中一个有趣的方面，因为它关乎动机，从而揭示了对手的大类（尽管不一定是具体的身份识别或归因）。例如，想要窃取资金的对手需要去有钱的地方。了解被瞄准的内容有助于洞察对手的企图（对手的最终目标），并可能带来更好的防御技术（稍后在“主动防御”中讨论）。

## 侦察

在决定*什么*和*谁*是目标后，对手开始进行侦察。在*侦察*阶段（或简称为*侦察*），对手尽可能多地收集关于计划受害者的信息。根据所寻求的数据类型（硬数据与软数据）和收集方法（被动与主动），侦察可分为多个类别。

### 硬数据与软数据

正如我们在第 2 章讨论的那样，情报界有多种基于主题（SIGINT 信号情报、TECHINT 技术情报等）划分信息的方式，但对于计算机网络行动，我们可以考虑得更简单一些。

*硬数据* 包括关于网络技术层面及其连接系统的信息。对于对手（以及调查对手的防御者）来说，这通常包括开源情报：

*   目标网络的足迹绘制或枚举
*   DNS 信息，如反向 DNS
*   操作系统和应用程序版本
*   系统配置信息
*   安全系统信息

*软数据* 包括网络及其系统背后的组织信息：

*   组织架构图、公共关系和其他层级文档
*   业务计划和目标
*   招聘信息，这往往会泄露正在使用的技术等信息
*   员工的职业和个人信息，用于社会工程学攻击

### 主动与被动收集方法

对手可能使用不同的信息收集方法。我们可以将这些方法分为*主动*或*被动*：

*主动方法* 需要直接与目标交互。主动硬情报收集示例是直接对系统进行端口扫描。主动软收集示例是发起社会工程学攻击以收集内部层级和联系信息。

*被动方法* 基于在不直接与目标交互的情况下收集信息，通常通过从第三方信息服务（如 DNS 或 WHOIS）收集信息。被动硬收集可能利用公共服务的域信息。软被动收集从 LinkedIn 等网站收集组织信息，人们在那里经常分享大量信息（甚至包括不该分享的信息）。

防御者检测这种侦察活动的能力差异巨大。例如，主动方法比被动方法更容易检测，大多数网络防御者对硬信息的控制比软信息更多。以端口扫描形式检测主动硬收集，比以阅读描述组织使用特定技术的职位发布形式检测软被动收集要容易。在某些情况下，对手可以通过公共服务代理或反弹其侦察活动，其中一些服务应用用户请求执行主动方法，如网络扫描或 DNS 询问。这种匿名性或隐藏在噪音中的优势，对防御者和对手都有利，因为许多此类工具双方都在使用。

## 武器化

如果所有安全控件，或一般所有软件，都能按预期工作（即按设计者设想的方式工作，而非构建出来的样子），那么对手几乎总会失败。因此，对手的目标是找到意图与实现不匹配的地方——漏洞。然后必须可靠地利用该漏洞，并将其打包成可交付给目标的形式（例如恶意文档或漏洞利用工具包）。寻找漏洞、制作漏洞利用代码并将其与载荷结合的过程称为*武器化*。

### 漏洞挖掘

鉴于武器化的漏洞子阶段对可攻击目标的影响，它尤为有趣。这迫使对手做出决定。某些广泛部署的软件几乎存在于任何环境中，例如 Adobe Acrobat 和 Reader 或 Microsoft Windows 和 Office。这意味着针对它们的漏洞利用具有广泛的适用性。然而，这些软件已遭受多年攻击，其相关公司已投入大量精力识别和缓解漏洞。另一种选择是攻击更冷门的软件，这类软件可能防护较弱，但部署也不广泛。这限制了对手的使用范围。这一过程可与网络杀伤链的*侦察*阶段联系起来。对手愿意投入的精力也可能受其自身指令和情报需求影响。

作为这种权衡的一个例子，考虑“震网”事件，未经证实的对手使伊朗纳坦兹核设施内的离心机瘫痪。其中部分内容包括针对西门子设备中可编程逻辑控制器（PLC）部署漏洞利用。虽然这种设备在大多数组织中并不广泛部署，但它存在于目标环境中。这些 PLC 中的漏洞因此为对手执行任务提供了载体。

作为防御者，我们通过使用以开发为中心的安全方法不断破坏这一过程。良好的开发实践，如 [Microsoft 安全开发生命周期](https://www.microsoft.com/en-us/sdl/)，可减少成为漏洞的不匹配的引入。应用安全团队和相关审查不断在源代码中搜寻这些漏洞。强大的补丁管理有助于消除环境中的旧漏洞。

每修补一个漏洞，就能在一定程度上限制对手，迫使他们寻找新的漏洞利用。这是一个耗时且昂贵的过程。漏洞在野外存在的时间越长，因其更长的有效生命周期，对对手的价值就越大。反过来，破坏漏洞的投资回报率（ROI）就能带来防御价值。

想象一下，对手拥有一个 Windows 95 的提权漏洞。对手使用了多年，直到 Windows 7 才最终修复。这意味着对手可以跨多个版本使用该漏洞利用多年。持续时间越长，对手从漏洞挖掘和漏洞利用创建工作中获得的投资回报率就越高。
