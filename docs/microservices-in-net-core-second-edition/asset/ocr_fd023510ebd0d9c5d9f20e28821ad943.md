This is the lambda middleware you’ve seen a few times before:

```
next =>
ctx =>
{
    System.Console.WriteLine("Got request");
    return next(ctx);
}
```

next is a RequestDelegate.

The inner lambda is a RequestDelegate and takes in an HttpContext.

In Startup.cs, we can add middleware to the pipeline by calling the Use method on the application builder:

```
public class Startup
{
    public void Configure(IApplicationBuilder app)
    {
        app.Use(next => ctx =>
        {
            Console.WriteLine("Got request in lambda middleware");
            return next(ctx);
        })
        ...
    }
}
```

Use adds a piece of middleware to the pipeline.

That’s all we need to do to add a piece of middleware to the pipeline. Now every incoming request runs through our little piece of middleware.

# 11.6.2 Middleware classes

Writing middleware as lambda functions works, but it becomes somewhat difficult when the middleware is more complex. In such cases, it’s nicer to use a class to implement the middleware.

To use a class to implement middleware, you can create a class that has a method whose signature is a RequestDelegate.

# Listing 11.8 Middleware implemented in a class

```
public class ConsoleMiddleware
{
    private readonly RequestDelegate next;

    public ConsoleMiddleware(RequestDelegate next)
    {
        this.next = next;
    }

    public Task Invoke(HttpContext ctx)
    {
        Console.WriteLine("Got request in class middleware");
        return this.next(ctx);
    }
}
```

Holds onto next when instantiated

Has the RequestDelegate signature
