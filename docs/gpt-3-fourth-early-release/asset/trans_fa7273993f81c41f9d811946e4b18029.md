截至2022年初，无代码平台工具的行业标准是 Bubble，这是一种开创性的视觉编程语言和应用开发程序，使用户无需编写一行代码即可创建功能齐全的网络应用程序。其影响所产生的涟漪推动了一个全新的行业开始形成。用创始人 Josh Haas 的话说，Bubble 是“一个平台，用户只需用简单的语言描述他们想要什么以及如何实现，就能无需任何代码自动化开发。”Haas 在一次采访中解释说，他受到启发，是因为注意到“想要用技术创造、建立网站、建立网络应用程序的人数与工程人才等可用资源之间存在巨大不匹配”。

目前，构建、开发和维护网络应用程序（如 Twitter、Facebook 或 Airbnb 等大型应用）需要具备广泛技术专长的 talent。独立的准开发者如果从初学者水平开始，必须从零学习编程才能真正构建任何东西。这需要时间和精力。“对大多数人来说，这是一个如此耗时的过程，以至于构成了巨大的进入壁垒，”Haas 说。

这意味着没有开发、软件工程或编程背景，但拥有绝佳的应用创意并希望围绕它建立公司的企业家，必须依赖拥有该专业知识的人——并说服他们参与这个想法。Haas 指出，正如你可能预期的那样，“说服某人为一个未经证实的想法仅凭股权工作，即使这是一个好主意，也是非常困难的。”

Haas 认为内部人才至关重要：虽然可以与独立承包商合作，但这需要大量来回沟通，并且往往会损害产品质量和体验。Haas 创立 Bubble 的目标是降低企业家进入市场的技术壁垒，并使技术技能的学习曲线尽可能快速顺畅。Haas 说，他对无代码工具感到兴奋的是，它有可能“将普通人变成程序员或软件开发者”。事实上，惊人的 40% 的 Bubble 用户没有任何编程背景。虽然 Haas 承认“编程方面的先前经验肯定有助于平滑学习曲线并减少掌握所需的时间”，但即使是没有任何经验的用户也能在数周内达到完全的 Bubble 熟练度并创建复杂的应用程序。

无代码代表了编程演进的一大步：我们已经从低级编程语言（如汇编语言，你必须理解特定的机器语言才能给出指令）发展到抽象的高级语言，如 Python 和 Java（语法类似于英语）。低级语言提供粒度化和灵活性，但转向高级编程使得能够在数月而不是数年内大规模开发软件应用程序成为可能。

无代码的支持者将这一趋势向前推进，认为无代码创新可以将这一周期进一步缩短，从数月缩短到数天。“今天即使是许多工程师也在使用 Bubble 来构建应用程序，因为它更快更直接，”Haas 说，他希望看到这一趋势继续下去。

致力于人工智能民主化的人们——其中许多人，我们强调，来自非技术背景——充满了突破性的想法：例如，创造一种人类与人工智能交互的通用语言。这种语言将使没有技术培训的人更容易与人工智能交互并构建工具。我们已经可以在 OpenAI API Playground 界面中看到这一强大的趋势，它使用自然语言且不需要编码技能。我们相信将这一想法与无代码应用程序结合起来可以创造真正革命性的成果。

Haas 同意这一点：“我们认为我们的工作是定义一种词汇，让你能够与计算机对话。”Bubble 的初始重点是开发一种语言，允许人类就程序的需求、设计和其他元素与计算机进行沟通。第二步将是教会计算机如何使用这种语言与人类交互。Haas 说，“目前，你必须在 Bubble 中手动绘制和组装工作流程才能构建某些东西，但如果能通过输入英文描述就让它自动出现，那将是令人惊叹的加速。”

在当前状态下，Bubble 是一个视觉编程界面，能够构建完全功能的软件应用程序。Haas 预测，将其与 Codex（你在第 6 章中了解过）集成将产生一个交互式无代码生态系统，它能够理解上下文并根据简单的英文描述构建应用程序。“我认为这就是无代码最终发展的方向，”Haas 说，“但短期挑战是训练数据的可用性。我们看到 Codex 能与 Javascript 应用程序一起工作，因为有大量的公共代码仓库，其中补充了注释、说明以及训练大语言模型所需的一切。”

使用无代码，你可以通过视觉编程和界面中的拖放来开发应用程序，这种方式平滑了学习曲线并减少了对任何先决条件的需求。大型语言模型能够像人类一样理解上下文，并且只需人类的一点提示就能生成代码。Haas 说，我们刚刚看到将它们结合起来的“初始潜力”。“我相当确定，如果你五年后采访我，我们将内部使用它们。两者之间的集成将使无代码更具表现力且更容易学习。它将变得更聪明一些，并对用户试图完成的事情产生同理心。”

你在第 5 章学到了关于 GitHub Copilot 的知识。这种代码生成具有由数十亿行常规编程语言（如 Python 和 Javascript）代码组成的大型训练数据集的优势。同样，随着无代码开发提速并创建越来越多的应用程序，它们的代码将成为大型语言模型训练数据的一部分。无代码应用程序逻辑的视觉组件与生成的代码之间的逻辑连接将作为模型训练过程的词汇。这种词汇然后可以输入到大型语言模型中，以高层次的文本描述生成完全功能的应用。“这基本上只是时间问题，直到在技术上可行，”Haas 说。

## 访问和模型即服务

正如我们在本书中所述，获取人工智能的途径正在全面变得更加容易。模型即服务是一个蓬勃发展的领域，其中强大的人工智能模型如 GPT-3 以托管服务的形式提供。任何人都可以通过简单的 API 使用该服务，而无需担心收集训练数据、训练模型、托管应用程序等。

YouTube 明星 Kilcher 告诉我们，“我认为与这些模型或人工智能交互所需知识水平会迅速下降。”他解释说，像 TensorFlow 这样的工具的早期版本几乎没有文档且“超级繁琐”，所以“我们现在在编码方面的舒适程度真是令人惊叹。”他引用了 Hugging Face Hub 和 Gradio 以及 OpenAI API 等工具，指出这些工具提供了“关注点分离：‘我不擅长运行模型。我就让别人去做。’”然而，模型即服务也存在潜在缺点：Kilcher 指出 API 和类似工具可能造成“瓶颈”。

Kilcher 的同事 Awan 表示他对模型即服务对创作者的“解放效应”感到兴奋。他指出许多人难以写作，“无论是因为专注力、注意力持续时间还是其他原因。但他们是出色的思想家，将从在传达思想方面的支持中受益”，借助“可以帮助你把文字写在纸上的 AI 工具”。

Awan 期待模型的未来迭代，尤其是在“音乐、视频、平面设计师和产品设计师”等媒介中，他预测他们将“从中协同受益，并以我们根本无法概念化的方式推动他们各自的媒介向前发展。”
