清单 2-9：生命周期可以存在空洞。

生命周期在①处开始，此时我们获取了对 `x` 的引用。接着，我们在③处将 `x` 移出，这会结束生命周期 `'a`，因为它已经不再有效。借用检查器通过将 `'a` 视为在②处结束来接受这次移动，因为这样在③处就不会存在从 `x` 流出的冲突。然后，我们通过在④处更新 `z` 中的引用来重新开始生命周期。无论代码此时是循环回到②，还是继续执行最后的打印语句，这两种使用方式现在都有一个有效值可供流出，并且不存在冲突流，因此借用检查器接受这段代码！

同样，这与我们之前讨论的内存数据流模型完全一致。当 `x` 被移动时，`z` 就停止存在。稍后我们重新赋值给 `z` 时，实际上创建了一个全新的变量，它只从那一刻起存在。基于这个模型，这个例子并不奇怪。

## 泛型生命周期

有时，你需要在自定义类型中存储引用。这些引用需要具有生命周期，这样借用检查器才能在它们被该类型的各种方法使用时检查其有效性。如果你希望类型中的某个方法返回一个生命周期长于对 `self` 的引用的引用，这一点尤其重要。

Rust 允许你让类型定义对一个或多个生命周期参数具有泛型性，就像允许你让类型定义对类型参数具有泛型性一样。Steve Klabnik 和 Carol Nichols 所著的《Rust 程序设计语言》（No Starch Press，2018 年）较为详细地介绍了这一主题，因此我不会在这里重复基础内容。不过，当你编写更复杂的此类类型时，需要注意这类类型与生命周期交互时的两个细节。

首先，如果你的类型还实现了 `Drop`，那么丢弃该类型会被视为使用了类型所泛型化的任何生命周期或类型。实际上，当你的类型的一个实例被丢弃时，借用检查器会在丢弃它之前检查：使用该类型的任意泛型生命周期是否仍然合法。如果你的丢弃代码确实使用了其中某些引用，这是必需的。如果你的类型没有实现 `Drop`，丢弃该类型就不算作一次使用；只要之后不再使用这些引用，用户就可以自由地使存储在类型中的引用失效，就像清单 2-7 中看到的那样。我们将在第 10 章进一步讨论与丢弃相关的这些规则。

其次，虽然一个类型可以对多个生命周期参数具有泛型性，但这样做往往只会给类型签名带来不必要的复杂性。通常，让一个类型对单个生命周期参数具有泛型性就足够了；对于插入该类型中的任何引用，编译器会将这个生命周期解析为这些引用生命周期中较短的那个。只有当一个类型包含多个引用，并且其方法返回的引用应当只与其中某一个引用的生命周期绑定时，你才真正需要使用多个泛型生命周期参数。

请考虑清单 2-10 中的类型，它为你提供了一个迭代器，用于遍历由某个特定字符串分隔的字符串片段。

```
struct StrSplit<'s, 'p> {
    delimiter: &'p str,
    document: &'s str,
}
impl<'s, 'p> Iterator for StrSplit<'s, 'p> {
    type Output = &'s str;
    fn next(&self) -> Option<Self::Output> {
        todo!()
    }
}
fn str_before(s: &str, c: char) -> Option<&str> {
    StrSplit { document: s, delimiter: &c.to_string() }.next()
}
```

清单 2-10：需要对多个生命周期参数具有泛型性的类型

构造这种类型时，你必须提供要搜索的分隔符和文档，这两者都是对字符串值的引用。当你请求下一个字符串时，会得到一个指向文档内部的引用。请考虑一下，如果在这个类型中使用单个生命周期，会发生什么。迭代器生成的值将同时与文档和分隔符的生命周期绑定。这会使 `str_before` 无法编写：返回类型将带有一个与函数内部局部变量相关联的生命周期——也就是 `to_string` 生成的 `String`——而借用检查器会拒绝这段代码。

## 生命周期方差

方差是程序员经常接触、却很少知道其名称的概念，因为它大多是不可见的。乍看之下，方差描述了哪些类型是其他类型的子类型，以及何时可以用子类型代替超类型（反之亦然）。一般来说，如果类型 A 至少和类型 B 一样有用，那么 A 就是 B 的子类型。方差解释了为什么在 Java 中，如果 `Turtle` 是 `Animal` 的子类型，就可以将 `Turtle` 传递给接受 `Animal` 的函数；也解释了为什么在 Rust 中，可以将 `&'static str` 传递给接受 `&'a str` 的函数。

虽然方差通常隐藏在幕后，但它出现得足够频繁，以至于我们需要掌握其基本知识。`Turtle` 是 `Animal` 的子类型，因为 `Turtle` 比某个未指定的 `Animal` 更“有用”——`Turtle` 能做 `Animal` 能做的一切，而且很可能还能做更多。同样，`'static` 是 `'a` 的子类型，因为 `'static` 的存活时间至少和任意 `'a` 一样长，因此更有用。或者更一般地说，如果 `'b: 'a`（`'b` 的生命周期长于 `'a`），那么 `'b` 就是 `'a` 的子类型。这显然不是形式化定义，但已经足够接近，具有实际应用价值。

所有类型都有方差，它定义了哪些其他相似类型可以替代该类型。方差有三种：协变、不变和逆变。如果可以直接用子类型替代某个类型，那么该类型就是协变的。例如，如果一个变量的类型是 `&'a T`，你可以向它提供类型为 `&'static T` 的值，因为 `&'a T` 关于 `'a` 是协变的。`&'a T` 关于 `T` 也是协变的，因此你可以将 `Vec<&'static str>` 传递给接受 `&Vec<&'a str>` 的函数。

有些类型是不变的，这意味着你必须提供完全相同的类型。`&mut T` 就是一个例子——如果某个函数接受 `&mut Vec<&'a str>`，你就不能向它传递 `&mut Vec<&'static str>`。也就是说，`&mut T` 关于 `T` 是不变的。如果允许这样做，该函数就可以将一个生命周期较短的字符串放入 `Vec`，而调用者会继续使用这个 `Vec`，并认为它的类型是 `Vec<&'static str>`，从而错误地认为其中的字符串是 `'static` 的！任何提供可变性的类型通常出于同样的原因而是不变的，例如，`Cell<T>` 关于 `T` 就是不变的。

最后一种类别是逆变，它会出现在函数参数中。如果函数参数可以是“不那么有用”的类型，函数类型就会更有用。当你对比参数类型本身的方差与它们作为函数参数时的方差，这一点会更清楚：

```
let x: &'static str; // 更有用，存活时间更长
let x: &'a str; // 不那么有用，存活时间更短

fn take_func1(&'static str) // 限制更严格，因此不那么有用
fn take_func2(&'a str) // 限制不那么严格，因此更有用
```

这种关系发生了反转，说明 `Fn(T)` 关于 `T` 是逆变的。

那么，为什么学习生命周期时还需要了解方差？当你考虑泛型生命周期参数如何与借用检查器交互时，方差就变得相关了。请考虑清单 2-11 所示的类型，它在单个字段中使用了多个生命周期。

```
struct MutStr<'a, 'b> {
    s: &'a mut &'b str
}
let mut s = "hello";
① *MutStr { s: &mut s }.s = "world";
println!("{}", s);
```

清单 2-11：需要对多个生命周期参数具有泛型性的类型

乍看之下，这里的两个生命周期似乎没有必要——我们没有任何方法需要像清单 2-10 中的 `StrSplit` 那样区分结构不同部分的借用。但如果你将这里的两个生命周期替换为单个 `'a`，代码就无法再编译！这一切都是由方差导致的。

在①处，编译器必须确定生命周期参数应当被设置为何值。如果有两个生命周期，`'a` 会被设置为对 `s` 的借用的待确定生命周期，而 `'b` 会被设置为 `'static`，因为所提供字符串 `"hello"` 的生命周期就是 `'static`。如果只有一个生命周期 `'a`，编译器就会推断出该生命周期必须是 `'static`。
