## 2 基础

![](img/bbeab1f2edc3d45a3e6f7f6efbbb1747_4_0.png)

当你深入 Rust 更高级的领域时，确保自己对基础知识有扎实的理解非常重要。在 Rust 中，如同在任何编程语言中一样，当你开始以更复杂的方式使用语言时，各种关键字和概念的精确含义就变得至关重要。在本章中，我们将逐一讲解 Rust 的许多原语，并尝试更清晰地定义它们的含义、工作原理，以及它们为何恰恰是现在这个样子。具体来说，我们将研究变量和值的区别、它们在内存中的表示方式，以及程序所拥有的不同内存区域。然后，我们将讨论所有权、借用和生命周期方面的一些微妙之处，这些内容你需要在继续阅读本书之前掌握。

你可以从上到下通读本章，也可以将其作为参考资料，用来复习那些你不太确定的概念。我建议你只有在完全熟悉本章内容后再继续阅读，因为对这些原语工作方式的误解很快就会妨碍你理解更高级的主题，或者导致你错误地使用它们。

## 谈论内存

并非所有内存都是平等的。在大多数编程环境中，你的程序可以访问栈、堆、寄存器、文本段、内存映射寄存器、内存映射文件，或许还有非易失性 RAM。在特定情况下选择使用哪一种，会影响你可以在其中存储什么、它保持可访问的时间有多长，以及你使用什么机制来访问它。这些内存区域的确切细节因平台而异，超出了本书的范围，但其中一些对于你如何推演 Rust 代码至关重要，值得在此介绍。

### 内存术语

在我们深入探讨内存区域之前，你首先需要了解值（value）、变量（variable）和指针（pointer）之间的区别。Rust 中的值是类型与该类型值域中一个元素的组合。值可以通过其类型的表示转换为字节序列，但就其本身而言，你可以将值更多地理解为“你作为程序员所表达的含义”。例如，`u8` 类型中的数字 6 是数学整数 6 的一个实例，它在内存中的表示是字节 `0x06`。类似地，`str` "Hello world" 是所有字符串值域中的一个值，其表示是其 UTF-8 编码。值的含义与这些字节存储的位置无关。

值存储在一个“场所”（place）中，这是 Rust 术语，指“可以保存值的位置”。这个位置可以在栈上、堆上，或许多其他位置。存储值最常见的场所是变量，即栈上命名的值槽。

指针是保存某个内存区域地址的值，因此指针指向一个场所。指针可以被解引用，以访问其所指向内存位置中存储的值。我们可以将同一个指针存储在多个变量中，从而让多个变量间接引用内存中的同一位置，进而引用同一个底层值。

考虑清单 2-1 中的代码，它说明了这三个元素。

```rust
let x = 42;
let y = 43;
let var1 = &x;
let mut var2 = &x;
var2 = &y;
```

*清单 2-1：值、变量和指针*

这里有四个不同的值：42（一个 `i32`）、43（一个 `i32`）、x 的地址（一个指针）和 y 的地址（一个指针）。还有四个变量：x、y、var1 和 var2。后两个变量都持有指针类型的值，因为引用就是指针。虽然 var1 和 var2 初始存储相同的值，但它们存储的是该值的独立副本；当我们改变 var2 中存储的值时，var1 中的值不会改变。特别要注意，`=` 运算符将右侧表达式的值存储到左侧命名的场所中。

一个体现变量、值和指针之间区别的有趣例子是如下语句：

```rust
let string = "Hello world";
```

尽管我们向变量 string 赋值了一个字符串值，但该变量的*实际*值是指向字符串值 "Hello world" 第一个字符的指针，而不是字符串值本身。此时你可能会说：“等等，那么字符串值存储在哪里？指针指向哪里？”如果你这样问，那你的眼光很敏锐——我们马上就会讲到。

## 深入变量

我之前给出的变量定义较为宽泛，本身可能不太有用。当你遇到更复杂的代码时，你需要一个更准确的心智模型来帮助你推理程序的真实行为。有很多这样的模型可供我们使用。详细描述它们会占用数章篇幅，超出本书范围，但大致可分为两类：高层模型和低层模型。高层模型适用于在生命周期和借用层面思考代码，低层模型则适用于推演不安全代码和裸指针。下面两节描述的变量模型足以应对本书大部分内容。

### 高层模型

在高层模型中，我们不把变量视为保存字节的场所。相反，我们只将它们视为值在程序中实例化、移动和使用时赋予这些值的名称。当你向一个变量赋值时，该值从此就由该变量命名。当后续访问该变量时，你可以想象从该变量的前一次访问画一条线到新访问，这就在两次访问之间建立了依赖关系。如果变量中的值被移动，则不能再从它画出任何线。

在这个模型中，变量只在持有合法值时才存在；你无法从值未初始化或已被移动的变量画出线，因此它实际上并不存在。使用这个模型，你的整个程序由许多这样的依赖线组成，通常称为*流*（flow），每条流都追踪某个特定值实例的生命周期。当存在分支时，流可以分叉和汇合，每个分支都追踪该值的一个不同生命周期。编译器可以检查在程序的任何给定点，所有可以并行存在的流之间是否兼容。例如，不能有两条对某个值进行可变访问的并行流。也不能存在一条借用某个值的流，而同时没有一条拥有该值的流。清单 2-2 展示了这两种情况的示例。

```rust
let mut x;
// 这种访问是非法的，因为无处可画流：
// assert_eq!(x, 42);
❶ x = 42;
    // 这没问题，可以从上面赋的值画一条流：
❷ let y = &x;
    // 这建立了来自 x 的第二条可变流：
❸ x = 43;
    // 这延续了来自 y 的流，而 y 又源自 x：
❹ assert_eq!(*y, 42);
```

*清单 2-2：借用检查器会捕获的非法流*

首先，我们不能在 x 初始化之前使用它，因为我们无处画流。只有当我们向 x 赋值后，才能从它画出流。这段代码有两条流：一条是独占（`&mut`）流，从 ❶ 到 ❸；一条是共享（`&`）流，从 ❶ 经过 ❷ 到 ❹。借用检查器检查每条流的每个顶点，并检查是否存在其他不兼容的流并发存在。在这种情况下，当借用检查器检查 ❸ 处的独占流时，它会看到终止于 ❹ 的共享流。由于你不能同时对某个值进行独占使用和共享使用，借用检查器（正确地）拒绝了这段代码。注意，如果 ❹ 不存在，这段代码可以正常编译！共享流会在 ❷ 处终止，当在 ❸ 处检查独占流时，不存在冲突的流。

如果声明了一个与之前同名的新变量，它们仍被视为不同的变量。这称为*遮蔽*（shadowing）——后面的变量通过相同的名称“遮蔽”了前面的变量。这两个变量共存，不过后续代码无法再命名先前的那个变量。这个模型大致对应于编译器（尤其是借用检查器）推演程序的方式，实际上也用于编译器内部以生成高效的代码。
