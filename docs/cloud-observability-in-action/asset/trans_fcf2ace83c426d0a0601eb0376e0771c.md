### 6.2.2 CNCF Pixie

Pixie ([https://px.dev/](https://px.dev/)) 是一个 Kubernetes 专用的实时调试平台，可在无需手动埋点或重新部署的情况下收集遥测数据，例如指标、追踪和剖析。Pixie 拥有一个前端，可帮助你查询和可视化这些数据。它由 New Relic 贡献给 CNCF，并于 2021 年 6 月被接受为沙箱项目。

为了在不更改代码的情况下收集数据，Pixie 大量使用 `eBPF` ([https://ebpf.io/](https://ebpf.io/))。`eBPF` 是一种 Linux 内核功能，允许你在验证后直接在内核中执行沙箱程序。

由于 `eBPF` 允许收集大量细粒度数据，例如完整的请求和响应体，因此它将所有数据存储在内存中。不过，你可以将遥测数据发送到任何 OpenTelemetry 兼容的端点 ([http://mng.bz/JgXV](http://mng.bz/JgXV)) 以实现长期数据保留。换句话说，历史数据在设计上不在 Pixie 的范围内。

为了查询遥测数据，Pixie 使用了一种相当巧妙的领域特定语言 `PxL` ([https://docs.px.dev/tutorials/pxl-scripts/write-pxl-scripts](https://docs.px.dev/tutorials/pxl-scripts/write-pxl-scripts))，它受 Python Pandas 启发。用户可以使用 `PxL` 按自己喜欢的方式查询和处理 Pixie 的底层数据。Pixie 的所有仪表板也完全可脚本化，允许用户构建最适合自己的视图和可视化。

Pixie 拥有一个活跃的社区和一个有趣且前景广阔的路线图。它提供多种集成，从 Slack 告警到通过 OpenTelemetry 导出在 Grafana 仪表板中使用。如果你正在运行 Kubernetes 集群，我建议你更仔细地了解一下 Pixie，因为它可以成为你工具箱中非常有用的工具。现在，让我们继续介绍一个分布式追踪领域的老牌开源前端。

### 6.2.3 Zipkin

Zipkin ([https://zipkin.io/](https://zipkin.io/)) 是一个开源分布式追踪系统，用 Java 编写，由 OpenZipkin 志愿者组织运营。Zipkin 拥有一个专注于追踪的 UI（见图 6.8），并集成了多种后端，包括 ES/OS、Apache Cassandra 和 MySQL，其他后端作为第三方扩展提供。Zipkin 项目也受 Google Dapper 启发，最初由 Twitter 创建，可追溯至 2015 年。

### 6.2.4 Apache SkyWalking

Apache SkyWalking ([https://skywalking.apache.org/](https://skywalking.apache.org/)) 是一个 ASF 开源项目，如今提供对分布式系统（如 Kubernetes 环境中的微服务）分布式追踪的支持。它始于 2015 年中国联通的分布式追踪系统，已被包括阿里巴巴、中国招商银行和华为在内的 100 多家公司采用。如果你想深入了解该主题，请查看 Liangjun Jiang 的“Application Performance Monitor and Distributed Tracing with Apache SkyWalking in Datahub” ([http://mng.bz/qr7r](http://mng.bz/qr7r)) 以了解其实际应用。至此，我们将介绍两个基于 ClickHouse 的一体化解决方案。
