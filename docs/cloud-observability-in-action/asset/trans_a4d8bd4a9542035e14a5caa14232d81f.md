## 9.1.3 开源 CP 工具

首先让我们看看持续分析领域的开源工具。这是一个大约在 2020 年左右爆发增长的领域，我们看到对其兴趣不断增加，以至于 `OpenTelemetry` 于 2022 年 9 月启动了一个活动（另见 `OTEP 139`，[http://mng.bz/JgjV](http://mng.bz/JgjV)）以探索如何将分析数据作为信号类型来支持。按字母顺序，我们现在将查看流行的开源持续分析工具。

### Parca

Parca ([https://www.parca.dev/](https://www.parca.dev/)) 是一款受 Prometheus 启发的开源持续分析工具，特别专注于使用 `eBPF` 进行零侵入式分析，因此您无需更改应用程序的任何内容或将任何库放入代码中即可使其工作。它使用 Prometheus 服务发现来查找分析源。Parca 支持长长的编程语言列表（[https://www.parca.dev/docs/parca-agent-language-support](https://www.parca.dev/docs/parca-agent-language-support)），包括 C、C++、Rust、Haskell、Java、Python、.NET 和 WebAssembly。

您可以自行安装并尝试，或使用 demo.parca.dev 上的零安装在线环境（[https://demo.parca.dev/](https://demo.parca.dev/)）来试用。图 9.4 显示了 Parca 中 Kubernetes 应用的 CPU 分析，本节末尾我们将使用 Parca 进行端到端演练。

![](OEBPS/Images/09-04.png)

图 9.4 Parca 演示环境的屏幕截图

### Pixie

Pixie ([https://px.dev/](https://px.dev/)) 是一个专注于 Kubernetes 集群的 CNCF 项目，我们在第 6 章中介绍过它。它不仅仅是关于持续分析；Pixie 还提供完整请求体（例如 HTTP API 的 JSON blob 返回值）以及资源和网络指标等其他有用项目。

由于 Pixie 收集了大量丰富的数据，Pixie 中的遥测数据保存在内存中且本地于 Kubernetes 集群。简而言之，您可以将 Pixie 视为“我的 Kubernetes 集群现在发生了什么？”的工具。就资源使用而言，Pixie 声称最大使用量不超过集群 CPU 的 5%。Pixie 可以帮助您查看特定 Pod 中、跨节点等的应用程序分析，而无需进行任何代码更改或重新部署应用程序。截至撰写时，Pixie 支持 Go、Rust 和 Java 等编译语言的持续分析。

### Pyroscope

Pyroscope ([https://pyroscope.io/](https://pyroscope.io/)) 是一款开源持续分析工具，附带针对多种编程语言的丰富客户端收集机制，包括 Go、Python、Java、Ruby、Rust、PHP、.NET 和 Node.js，以及 `eBPF` 支持。2023 年 6 月，Pyroscope 被 Grafana Labs 收购（[http://mng.bz/wvNP](http://mng.bz/wvNP)），并将成为 Grafana Cloud 中持续分析产品的基石。

Pyroscope 的制作方建议采用混合的分析收集方法：即使用 `eBPF` 对系统（例如 VM 或 Kubernetes 节点）进行分析，结合每个服务的特定语言插桩。此外，Pyroscope 配备 `FlameQL`，一种用于探索分析数据的查询语言。您可以使用 [https://demo.pyroscope.io/](https://demo.pyroscope.io/) 上的零安装在线环境试用 Pyroscope，或自行本地安装。

图 9.5 显示了 Pyroscope UI 的概览（以及叠加了基线火焰图缩放视图的覆盖层）。在图的上半部分，显示了分析的基于时间的可视化，当您点击任何分析时，可以生成并放大特定分析（本例中为内存使用）。

## 9.1.4 商业持续分析产品

持续分析领域有大量商业产品，从云服务提供商开始：
* AWS 提供 Amazon CodeGuru Profiler（[http://mng.bz/qrKr](http://mng.bz/qrKr)），旨在微调应用性能。它提供机器学习算法来查找代码中最昂贵的行，并提供进一步提高效率的方法。
* Azure 提供 Application Insights Profiler（[http://mng.bz/7Dov](http://mng.bz/7Dov)），可让您查看应用的性能跟踪。它捕获每个请求的中间值、最快和最慢响应时间，并帮助您识别特定请求的热点代码路径开销，支持 .NET 和 Java。
* Google 以其 Cloud Profiler（[http://mng.bz/mVYa](http://mng.bz/mVYa)）开创了这一领域。它是一种低开销的采样分析器，因此适用于生产环境。Cloud Profiler 支持常见语言和环境（例如 Go、Java、Node.js 和 Python）以及多种分析类型，包括 CPU 时间、堆和线程。

然后，还有一些独立软件厂商提供捆绑分析或独立产品。其中一些已以源代码可用方式发布，包括但不限于以下内容：
* Datadog 分析器（[https://docs.datadoghq.com/profiler/](https://docs.datadoghq.com/profiler/)）是整体产品的一部分，可帮助您查找 CPU、内存和 I/O 瓶颈；分析数据按函数、类名和代码行号进行细分。
* Dynatrace 的产品（[http://mng.bz/5w5O](http://mng.bz/5w5O)）是其整体套件的一部分，允许您进行 CPU 分析，包括深入到函数级别、内存转储分析和进程崩溃。
* g:Profiler（[https://granulate.io/continuous-profiling/](https://granulate.io/continuous-profiling/)）是一款 SaaS 产品（但也作为开源提供），支持 AWS、Azure 和 Google Cloud 环境。它支持多种语言（Clojure、Scala、C/C++、Ruby、Java、Python、JavaScript、PHP 和 Go），使用 `eBPF`，并声称利用率惩罚低于 1%。
* New Relic 具有名为 Real-time profiling for Java 的功能（[http://mng.bz/OP6n](http://mng.bz/OP6n)），支持火焰图以及 Thread profiler 工具 [https://docs.newrelic.com/docs/apm/apm-ui-pages/events/thread-profiler-tool/](https://docs.newrelic.com/docs/apm/apm-ui-pages/events/thread-profiler-tool/)，您可将其用于 Java、.NET、Python 和 Ruby。
* Prodfiler（[https://prodfiler.com/](https://prodfiler.com/)）自称是分布式轻量级持续全系统分析器，可让您深入了解 CPU 使用情况，支持火焰图，要求 Linux 内核版本 4.15 或更高，并在 Kubernetes 和 AWS ECS 等平台上可用。
* Splunk 提供 AlwaysOn（[http://mng.bz/5w5O](http://mng.bz/5w5O)）分析器。

持续分析领域的优秀概览和查询工具是 Mark Hansen 的 Profilerpedia（[https://profilerpedia.markhansen.co.nz/](https://profilerpedia.markhansen.co.nz/)），它是工具和分析器数据格式的目录。如果您想深入了解该主题，请考虑查看 Datadog 的 *The Busy Developer’s Guide to Go Profiling, Tracing and Observability*（[https://github.com/DataDog/go-profiler-notes/tree/main/guide](https://github.com/DataDog/go-profiler-notes/tree/main/guide)）。
