### Sloth
Sloth（[https://sloth.dev](https://sloth.dev)）也使用 Prometheus 生成 SLO。简而言之，它为每个 SLO 生成三个规则组，包含用于 SLI、信息性指标和告警的记录规则和告警规则。此外，它还提供所谓的 SLI 插件（[https://sloth.dev/sli-plugins/coredns-availability/](https://sloth.dev/sli-plugins/coredns-availability/)），让你能够抽象和扩展 SLI，包括 CoreDNS、Istio 和 Traefik 的插件。与 Pyrra 一样，它支持错误预算（SLO 的容错空间）和燃烧率（预算消耗速度）。

鉴于与 Pyrra 的相似性和大量重叠，我们不会深入探讨 Sloth 的工作原理。只需选择更符合你需求的工具即可。接下来，我们将介绍商业 SLO 和 SLI 工具。

### 10.2.3 商业 SLO 方案
在撰写本文时，SLO 正在成为主流，你可以期待越来越多的商业方案。以下是目前一些值得注意的方案：
* Nobl9（[https://www.nobl9.com/](https://www.nobl9.com/)）是一个完整的 SLO 解决方案。它具有最深入的集成和最广的覆盖范围，如果你认真对待 SLO，你会想要评估它。
* 从云提供商的角度来看，Google Cloud 通过其运营套件提供 SLO 支持（[http://mng.bz/vnEq](http://mng.bz/vnEq)）。
* 服务等级目标状态页面（[http://mng.bz/4Dwg](http://mng.bz/4Dwg)）和 SLO 摘要小部件都是 Datadog 告警方案的一部分。
* Honeycomb（[https://www.honeycomb.io/slos](https://www.honeycomb.io/slos)）在其套件中提供基于追踪的 SLO 方案。
* Dynatrace 允许你在其方案中定义 SLO（[http://mng.bz/QPBe](http://mng.bz/QPBe)）。
* New Relic 提供服务等级管理功能（[http://mng.bz/XNRM](http://mng.bz/XNRM)）。
* Splunk 提供 SLO 和 SLI 监控（[http://mng.bz/yQmE](http://mng.bz/yQmE)）支持。

SLO 商业方案领域正在快速发展，你可以期待未来会有越来越多的云提供商和独立软件厂商原生支持 SLO。

## 10.3 考虑因素
如同往常一样，开源标准占主导。在这个领域，OpenSLO（[https://openslo.com](https://openslo.com)）是定义 SLO 的相关（新兴）开放规范，以实现厂商无关的 SLO 跟踪和接口。

例如，在 OpenSLO 中，你会将本章前面 Pyrra 的演练示例（与清单 10.3 对比）表示如下：
```
apiVersion: openslo/v1
kind: SLO                             ❶
metadata:
  name: ho11y-api-query
  labels:
    prometheus: k8s
    role: alert-rules
spec:
  service: ho11y                      ❷
  indicator:
    metadata:
      name: ho11y-error
      displayName: ho11y error
    spec:
      ratioMetric:
        counter: true
        good:                         ❸
          metricSource:
            metricSourceRef: prometheus-datasource
            type: Prometheus
            spec:
              query: ho11y_total{job="svc",http_status_code~="2.."})
        total:
          metricSource:
            metricSourceRef: prometheus-datasource
            type: Prometheus
            spec:
              query: ho11y_total{job="svc"}
  objectives:
    - displayName: ho11y total errors
      target: 0.75                    ❹
```
❶ 我们正在定义一个 OpenSLO SLO 对象。
❷ 此 SLO 目标服务的引用
❸ 与 Pyrra 不同，我们在 Pyrra 中定义了错误，而在这里，我们定义“快乐路径”是什么样的。
❹ 此 SLO 跟踪的目标：75% 可用性（或非错误响应）

通常，系统会定义 SLO 和 SLI，例如 Kubernetes。参见“Kubernetes 可扩展性和性能 SLIs/SLOs”（[http://mng.bz/MBEm](http://mng.bz/MBEm)）作为示例。最后，如果你想开始在该领域贡献或只是想了解更多，请考虑查看优秀的 SLOconf（[https://www.nobl9.com/community/sloconf](https://www.nobl9.com/community/sloconf)）活动，这是 SRE 社区每年聚会，交流 SLO 相关更新和经验。

## 总结
* 可靠性法规即将到来，就像 15 年前的网络安全一样。
* 使用 SLO 来衡量和报告合规性的可靠性正成为金融、通信和航空领域的热门话题，并可能扩展到其他行业。
* 为了使 SLA 中的合同承诺可量化且自动化，请定义 SLI 来推动目标（SLO）。
* SLA 是服务提供商和服务消费者之间的合同构造。
