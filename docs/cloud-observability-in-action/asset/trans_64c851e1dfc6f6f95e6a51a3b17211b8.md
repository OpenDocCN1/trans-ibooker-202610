
注意 如果你对我在此提到的 `Log4j` 挑战不熟悉（或可能已经忘记了），`CVE-2021-44228`（[https://nvd.nist.gov/vuln/detail/CVE-2021-44228](https://nvd.nist.gov/vuln/detail/CVE-2021-44228)），非正式地称为 `Log4Shell`，是 `Log4j` 中于 2021 年 11 月发现的一个零日漏洞。它在许多地方造成了大量工作（应用安全补丁），从内部 IT 到云服务提供商，并作为此类事物可能产生多大运营影响的示例。

虽然从 API 和模型角度来看日志是稳定的，但在 `OpenTelemetry` 中，直到 2024 年中它们才可能在 `SDKs` 和发行版中得到全面支持。这意味着在你最终能够迁移到 `OpenTelemetry` 之前，你需要一个临时策略。

好了，理论就讲到这里。让我们看看日志路由的实际应用。首先是在容器环境中很受欢迎的选择：`Fluentd` 和 `Fluent Bit`。

### 4.1.1 Fluentd 和 Fluent Bit

CNCF 项目 `Fluentd`（[https://www.fluentd.org/](https://www.fluentd.org/)）和 `Fluent Bit`（[https://fluentbit.io/](https://fluentbit.io/)）是流行的云原生代理，最初起源于日志领域。最初只有 `Fluentd`（用 `Ruby` 和 `C` 编写），提供丰富的生态系统（超过 1,000 个插件），但代理的内存占用相对较大（数十 MB）。

2014 年，`Fluentd` 背后的团队 `Treasure Data` 认识到需要在受限环境（容器、物联网）中专门使用轻量级日志路由器。这种洞察促使开发了 `Fluent Bit`（用 `C` 编写），内存占用仅几百 KB，且插件比 `Fluentd` 少得多（少于 100 个）。

在撰写本文时，`Fluent Bit` 正在将其范围从仅日志扩展到其他信号类型，例如指标和追踪。详情请参阅 GitHub 议题“`Fluent Bit v2.0 Is Coming`”（[https://github.com/fluent/fluent-bit/discussions/5993](https://github.com/fluent/fluent-bit/discussions/5993)）。不过由于仍有许多 WIP 项目在进行中，本节我们将重点关注日志方面。让我们看一个容器化设置中的基本使用示例，并在过程中讨论一些特性。

为了演示日志路由，我们使用的是 `OpenSearch` 与 `Docker Compose`（[https://opensearch.org/docs/latest/opensearch/install/docker/](https://opensearch.org/docs/latest/opensearch/install/docker/)）的设置。现在不用担心 `OpenSearch`；我们将在第 5 章详细介绍它。只需将其视为日志可以发送到的地方，你可以在其中查找、搜索和查询日志行。例如，你可能对特定微服务在特定时间范围内（比如过去 24 小时）的所有 `ERROR` 级别日志行感兴趣。

在图 4.1 中，你可以看到我们的示例日志管道——我们使用 `ho11y`（[http://mng.bz/rWxg](http://mng.bz/rWxg)）作为在 Docker 容器中运行的日志信号源。容器公开端口 8765 用于其 HTTP API，并使用 `Fluentd` 日志驱动程序将日志行发送到 `Fluent Bit`（主要日志路由器），将日志行摄取到 `OpenSearch` 作为日志后端目标，然后你可以在 `OpenSearch Dashboards` 中查询和可视化。

图 4.1 使用 `Fluentd` 和 `Fluent Bit` 的示例日志管道

进入实现部分，我们再次使用 `Docker Compose` 来启动管道，其定义在 `ch04/fluent-bit/docker-compose.yaml` 文件中。让我们逐步回顾管道。我已在 `Docker Compose` 文件中配置 `ho11y` 容器，使其使用 `fluentd` 日志驱动程序（因为目前在那里还不直接支持使用 `Fluent Bit` 作为驱动程序）。

#### 列表 4.1 信号源 `ho11y` 的 Docker Compose 配置片段

```
ho11y:
    image: public.ecr.aws/mhausenblas/ho11y:stable
    ports:
      - 8765:8765           ❶
    logging:                ❷
      driver: fluentd
      options:
        tag: ho11y
        fluentd-address: localhost:8765 
    depends_on:             ❸
      - fluent-bit
```

❶ 在端口 `8765` 上公开 `ho11y` HTTP API 服务端口，使其可从主机访问（这样我们就可以使用 `curl` 调用它）

❷ 配置容器使用 `Fluentd` 日志驱动程序

❸ 定义 `ho11y` 容器依赖于 `Fluent Bit` 日志路由器，强制启动顺序

接下来是 `Fluent Bit` 配置，如以下列表所示。如你所见，这以一个名为 `fluent-bit.conf` 的文件作为参数，我们将在本章后面讨论。

#### 列表 4.2 Fluent Bit 的 Docker Compose 配置片段

```
fluent-bit:
    image: fluent/fluent-bit:1.9.8
    volumes:
      - ./fluent-bit.conf:/fluent-bit/etc/fluent-bit.conf   ❶
    ports:
      - "24224:24224"                                       ❷
      - "24224:24224/udp"
```

❶ 定义 `Fluent Bit` 配置（路由信息）的位置

❷ 确保打开端口 `24224`，以便我们可以监听来自 `Docker` 中 `Fluentd` 日志驱动程序的传入日志行

最后但同样重要，让我们看看日志后端 `OpenSearch` 如何配置（在以下列表的 `Docker Compose` 文件中）在单节点设置中以及前端/UI `OpenSearch Dashboards`。

#### 列表 4.3 OpenSearch（和 Dashboards）的 Docker Compose 配置片段

```
opensearch-node1:
    image: opensearchproject/opensearch:2.1.0
    container_name: opensearch-node1
    environment:
      - cluster.name=opensearch-cluster
      - node.name=opensearch-node1
      - bootstrap.memory_lock=true
      - "OPENSEARCH_JAVA_OPTS=-Xms512m -Xmx512m"
      - "DISABLE_INSTALL_DEMO_CONFIG=true"
      - "DISABLE_SECURITY_PLUGIN=true"
      - "discovery.type=single-node"
    volumes:
      - opensearch-data1:/usr/share/opensearch/data
    ports:
      - 9200:9200                                            ❶
 
  opensearch-dashboards:
    image: opensearchproject/opensearch-dashboards:2.1.0
    container_name: opensearch-dashboards
    ports:
      - 5601:5601                                            ❷
    environment:
      - 'OPENSEARCH_HOSTS=["http://opensearch-node1:9200"]'  ❸
      - "DISABLE_SECURITY_DASHBOARDS_PLUGIN=true"
```

❶ 公开端口 `9200`，以便我们可以摄取日志行（来自 `Fluent Bit`）

❷ 公开端口 `5601`，使 `OpenSearch Dashboards`（前端/UI）可从主机访问

❸ 配置 `OpenSearch Dashboards`（前端）使用 `OpenSearch`（日志后端）

在这一点上，我们已经有效地实现了图 4.1 所示的日志管道。现在，让我们更仔细地查看 `Fluent Bit` 配置本身。如列表 4.4 所示，我在 `Fluent Bit` 中使用 `Forward`（[https://docs.fluentbit.io/manual/pipeline/inputs/forward](https://docs.fluentbit.io/manual/pipeline/inputs/forward)）输入插件，从 `Fluentd`（来自 `Docker` 运行时）接收日志流，并通过 `OpenSearch` 输出部分配置 `Fluent Bit` 将日志行路由到 `OpenSearch`。

#### 列表 4.4 Fluent Bit 配置

```
[INPUT]
    Name forward            ❶
    Listen 0.0.0.0          ❷
    Port 24224              ❸
 
[OUTPUT]
    Name opensearch         ❹
    Match **                ❺
    Host opensearch-node1   ❻
    Port 9200
    Index ho11y             ❼
    Suppress_Type_Name on   ❽
```

❶ 在这里，我们配置 `Forward` 插件，使其能够从 `Fluentd`（来自 `Docker` 日志驱动程序）接收日志项。

❷ `Forward` 插件将监听所有网络接口（即 `0.0.0.0`）。

❸ `Forward` 插件的默认端口（`Fluentd` 连接到的端口）

❹ 目标配置——在我们的例子中，是 `OpenSearch` 插件作为日志项的后端（下游）

❺ 在这里，我们定义确实接收任何日志项（我们可以在这里更具选择性，决定路由到 `OpenSearch` 的日志项，但目前我们使用全部）。
