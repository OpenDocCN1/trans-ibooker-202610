
## 第 9 章：平台跳跃谜题开发

游戏现在有了一个有趣（尽管仍然基础）的平台跳跃谜题的开端，但与我们早期的迭代相比，我们也简化了解决方案，并且如图 [9-33](#334805_2_En_9_Chapter.xhtml#Fig33) 所示，平台跳跃组件并不具有特别的挑战性。回顾一下，在第 [8](#334805_2_En_8_Chapter.xhtml) 章中添加手电筒如何通过增加第二种挑战（要求玩家识别并利用环境中的物体作为工具）来增加原始机制的逻辑挑战；我们可以给平台跳跃组件添加类似的第二种挑战，如图 [9-34](#334805_2_En_9_Chapter.xhtml#Fig34) 所示。

图 9-34 ¶ 引入阻挡通往上层平台的力场（#1）可以显著增加平台跳跃组件的挑战性。在该设计中，玩家必须激活开关（#2 中用灯泡表示）以禁用力场并到达第一和第三个形状。

力场的引入开启了多种有趣的可能性来增加挑战。玩家必须在撞上力场之前，把握时机从移动平台跳向开关，并且必须按顺序激活形状（要求玩家先激活右上角，然后是右下角，最后是左上角）。想象一下，当开关被拨动时，力场关闭有一个时间限制，如果在力场重新启用前未激活所有形状，谜题将重置。

我们现在已经获取了一个基于逻辑序列的基本机制，并将其改造为支持动作平台跳跃体验。在该开发阶段，机制变得更有趣，并开始感觉更像一个可玩的关卡，但它仍然缺乏背景设定和语境；这是一个探索我们可能想用这个游戏讲述何种故事的好机会。我们对科幻冒险感兴趣？也许是生存恐怖体验？又或者是一系列没有关联叙事的谜题关卡？背景设定不仅有助于确定游戏的视觉形象，还能指导我们为玩家创建何种挑战（例如，游戏中的“敌人”是否在对抗玩家，游戏玩法将继续专注于解决逻辑谜题，还是两者兼有？）。一个将游戏机制与背景设定联系起来的良好练习是：选择一个地点（例如，飞船内部），开始探索该虚构空间中的游戏玩法，并以符合该背景设定的方式定义挑战元素。对于一款设定在飞船上的游戏，也许出了什么故障，玩家必须巧妙利用环境物体中和安全激光，从船的一端前往另一端。尝试将飞船背景设定应用到当前游戏机制，并调整关卡中的元素以契合该主题：激光只是一种选择，但你能想出不涉及解锁序列的其他游戏机制用途吗？尝试将游戏机制应用到各种不同的环境中，开始建立将抽象游戏玩法应用到特定背景设定的舒适度。

还请记住，在关卡设计中包含物体物理并不总是创造优秀游戏的必要条件；有时你可能想要颠覆或完全忽略你创造的游戏世界中的物理定律。你的游戏体验的最终质量取决于你多有效地协调和平衡游戏设计的九大要素；这不关乎强制实施任何单一设计选项。你的游戏可能完全抽象，涉及以与物理世界无关的方式在空间中移动的形状和形式，但你对色彩、音频和叙事的运用仍可能结合创造出一种让玩家感觉强烈临场感的体验。然而，如果你发现你的游戏环境试图通过使用人们会联想到现实世界中事物的物体来传达物理感，那么探索物体物理如何增强体验是值得的。

## 摘要

完成本章后，你将能够：

*   理解 `Particle`（粒子）、`ParticleEmitter`（粒子发射器）和 `ParticleSystem`（粒子系统）的基础知识
*   认识到许多有趣的物理效果可以基于一组专用粒子进行建模
*   近似 `Particle` 的基本行为，使这些粒子集合的渲染类似于简单的爆炸效果
*   实现一个简单直接的 `ParticleSystem`，使其与物理组件的 `RigidShape`（刚体形状）系统集成

## 简介

到目前为止，在你的游戏引擎中，假设游戏世界可以由一组几何体描述，其中所有对象都是具有纹理或动画精灵的 `Renderable`（可渲染）实例，并可能由光源照亮。这个游戏引擎功能强大，能够描述现实世界中很大一部分物体。然而，事实也是，你的游戏引擎很难描述许多日常现象，例如火花、火焰、爆炸、泥土、灰尘等。这些观察中的许多都是物质改变物理状态或极小实体集合对物理扰动做出反应产生的瞬态效果。总的来说，这些观察通常被称为特效，通常不适合用具有固定形状几何体和纹理来表示。

`ParticleSystem` 通过发射一组具有特定属性（可能包括位置、大小、颜色、生命周期和精心选择的纹理贴图）的粒子来描述特效。这些粒子被定义为具有特定行为：一旦发射，它们的属性会更新以模拟物理效果。例如，火焰粒子可能被发射为向上移动并呈红色。随着时间的推移，粒子可能会变小、减缓向上运动、颜色向黄色变化，并在一定数量的更新后最终消失。通过精心设计的 `update()` 函数，这组粒子的渲染可以类似于燃烧的火焰。

在本章中，你将学习、设计并创建一个简单灵活的 `ParticleSystem`，它包含实现常见效果（如爆炸和魔法咒语效果）所需的基本功能。此外，你将实现一个 `ParticleShader`（粒子着色器），以正确地将粒子集成到场景中。粒子将与 `RigidShape` 对象发生碰撞并相应地交互。你还将发现 `ParticleEmitter` 的必要性并定义它，以在一段时间内生成粒子，例如篝火或火把。
