
换句话说，给定二维空间中的两个凸形状，逐个遍历两个凸形状的所有边。对于每一条边，推导出一条垂直于该边的线（或轴），将两个凸形状的所有边投影到这条线上，并计算投影边的重叠情况。如果你能找到一条垂直线，使得没有任何投影边重叠，则这两个凸形状不发生碰撞。

图 [9-7](#334805_2_En_9_Chapter.xhtml#Fig7) 使用两个轴对齐矩形演示了这一描述。在这种情况下，有两条线垂直于给定两个形状的边，即 X 轴和 Y 轴。

![Figure 9-7 ¶ A line where projected edges do not overlap](images/334805_2_En_9_Chapter/334805_2_En_9_Fig7_HTML.png)

当将形状的所有边投影到这两条线/轴上时，请注意 Y 轴上的投影结果重叠，而 X 轴上没有重叠。由于存在一条垂直于其中一个矩形边的线，使得投影边不重叠，SAT 得出结论：这两个给定矩形不发生碰撞。

源自 SAT 的算法的主要优势在于，对于非碰撞形状，它具有提前退出的能力。一旦检测到没有重叠投影边的轴，算法即可报告无碰撞，无需继续测试其他轴。在图 [9-7](#334805_2_En_9_Chapter.xhtml#Fig7) 的情况下，如果算法从处理 X 轴开始，则无需执行 Y 轴的计算。

## 基于 SAT 的简单算法

基于 SAT 推导的算法通常包含四个步骤。请注意，该算法适用于检测任意凸形状之间的碰撞。为清晰起见，在以下解释中，每个步骤都附带一个由两个矩形组成的简单示例：

*   **步骤 1. 计算面法线**：计算用于投影边的垂直轴或面法线。以矩形为例，图 [9-8](#334805_2_En_9_Chapter.xhtml#Fig8) 说明了有四条边，每条边都有一个对应的垂直轴。例如，`A1` 是对应轴，因此垂直于边 `e[A1]`。请注意，在你的 `RigidRectangle` 类中，`mFaceNormal`（即面法线）是垂直轴 `A1`、`A2`、`A3` 和 `A4`。

![Figure 9-8 ¶ Rectangle edges and face normals](images/334805_2_En_9_Chapter/334805_2_En_9_Fig8_HTML.png)

*   **步骤 2. 投影顶点**：将两个凸形状的每个顶点投影到面法线上。对于给定的矩形示例，图 [9-9](#334805_2_En_9_Chapter.xhtml#Fig9) 说明了将所有顶点投影到图 [9-8](#334805_2_En_9_Chapter.xhtml#Fig8) 中的 `A1` 轴上。

![Figure 9-9 ¶ Project each vertex onto face normals (shows A1)](images/334805_2_En_9_Chapter/334805_2_En_9_Fig9_HTML.png)

*   **步骤 3. 确定边界**：确定每个凸形状投影顶点的最小和最大边界。继续矩形示例；图 [9-10](#334805_2_En_9_Chapter.xhtml#Fig10) 显示了两个矩形各自的最小和最大位置。请注意，最小/最大位置是相对于给定轴的方向定义的。

![Figure 9-10 ¶ Identify the min and max bound positions for each rectangle](images/334805_2_En_9_Chapter/334805_2_En_9_Fig10_HTML.png)

*   **步骤 4. 判断重叠**：判断两个最小/最大边界是否重叠。图 [9-11](#334805_2_En_9_Chapter.xhtml#Fig11) 显示两个投影边界确实重叠。在这种情况下，算法无法得出结论，必须继续处理下一个面法线。请注意，如图 [9-8](#334805_2_En_9_Chapter.xhtml#Fig8) 所示，处理面法线 `B1` 或 `B3` 将得出无碰撞的确定性结论。

给定的算法能够在无额外信息的情况下判断碰撞是否发生。回顾一下，检测到碰撞后，物理引擎还必须解决潜在的相互穿透，并为碰撞形状推导响应。这两项计算都需要额外信息——即图 [9-4](#334805_2_En_9_Chapter.xhtml#Fig4) 中介绍的碰撞信息。下一节将介绍一种高效的基于 SAT 的算法，该算法计算支撑点，既可告知碰撞检测的真/假结果，又可作为推导碰撞信息的基础。

## 高效的 SAT 算法：支撑点

如图 [9-12](#334805_2_En_9_Chapter.xhtml#Fig12) 所示，形状 A 的面法线的支撑点被定义为形状 B 上的顶点位置，该顶点到形状 A 对应边的距离最负。当沿 `A1` 方向测量时，形状 B 上的顶点 `S[A1]` 到边 `e[A1]` 的距离负值最大，因此 `S[A1]` 是面法线 `A1` 的支撑点。负距离意味着测量是有方向的，且支撑点必须位于面法线的反方向。

![Figure 9-12 ¶ Support points of face normals](images/334805_2_En_9_Chapter/334805_2_En_9_Fig12_HTML.png)

通常，给定面法线的支撑点在每个更新周期可能不同，因此必须在每次碰撞调用时重新计算。此外，也是非常重要的是，面法线完全可能没有定义的支撑点。

### 面法线可能不存在支撑点

仅当沿面法线测量的距离为负值时，支撑点才被定义。例如，在图 [9-12](#334805_2_En_9_Chapter.xhtml#Fig12) 中，形状 B 的面法线 `B1` 在形状 A 上没有对应的支撑点。这是因为形状 A 上的所有顶点在沿 `B1` 测量时，到对应边 `e[B1]` 的距离均为正值。正距离意味着形状 A 的所有顶点都在边 `e[B1]` 的前方。换句话说，整个形状 A 都在形状 B 的边 `e[B1]` 前方；因此，这两个形状在物理上不接触；因此，它们不发生碰撞。

由此可见，在计算两个形状之间的碰撞时，如果任意面法线没有对应的支撑点，则这两个形状不发生碰撞。再一次，提前退出能力是一个重要优势——算法一旦检测到第一个未定义支撑点的情况，即可返回判定。

为便于讨论和实现，支撑点与对应边之间的距离称为支撑点距离，并作为正数计算。这样，支撑点距离实际上是沿负面法线方向测量的。本书后续讨论将遵循这一约定。
