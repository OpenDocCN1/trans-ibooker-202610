
# 第 2 部分：融入背景设定

你可以继续构建机制，使关卡更有趣、更具挑战性（例如，你可能会在能量场的关闭开关上加一个计时器，要求玩家在有限时间内与所有锁部件碰撞）。然而，在概念开发的这个阶段，往往有助于从游戏玩法中抽离出来，开始考虑游戏背景设定和类型，利用这些元素来帮助指导游戏机制接下来如何演变。

回顾第 [11](#334805_2_En_11_Chapter.xhtml) 章，项目以一组支持科幻设定的概念探索结束。图 [12-2](#334805_2_En_12_Chapter.xhtml#Fig2) 展示了一个未来工业环境设计、一个身穿太空服的英雄角色，以及看起来像飞行机器人的实体。

![图 12-2 ¶ 来自第 11 章的概念图](`images/334805_2_En_12_Chapter/334805_2_En_12_Fig2_HTML.jpg`)

图 [12-2](#334805_2_En_12_Chapter.xhtml#Fig2) ¶ 来自第 [11](#334805_2_En_11_Chapter.xhtml) 章的概念图

请注意，你一直在创建的游戏机制并没有什么特别之处会必然将你引向科幻方向；游戏机制是抽象的交互结构，通常可以与任何类型的设定或视觉风格相结合。在本例中，作者选择了一个发生在飞船上的设定，因此本章将使用该主题作为游戏原型的设定。随着你推进设计过程，请考虑探索备选设定：第 [11](#334805_2_En_11_Chapter.xhtml) 章的游戏机制如何适应丛林设定、当代都市地点、中世纪奇幻世界或水下大都市？

## 语境图像让设定栩栩如生

现在你已经描述了一个基本叙事和虚构框架，大致为“玩家必须完成一系列平台解谜关卡，在飞船爆炸前拯救它”，只需将早期原型中的几个形状替换为一些包含的概念元素。图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 引入了一个类人英雄角色、更像飞船组件的平台，以及一个带有锁门的屏障墙，以取代机制设计中的抽象锁。

![图 12-3 ¶ 引入多个支持游戏设定和不断演变叙事的视觉设计元素](`images/334805_2_En_12_Chapter/334805_2_En_12_Fig3_HTML.jpg`)

图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) ¶ 引入多个支持游戏设定和不断演变叙事的视觉设计元素

虽然你只做了少量微小替换，且视觉元素尚未锚定在环境中，但图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 传达了更多的虚构语境，并且比图 [12-1](#334805_2_En_12_Chapter.xhtml#Fig1) 的抽象形状对临场感的贡献大得多。英雄角色现在暗示了一种尺度，随着玩家将相对大小与人体参照对比，这种尺度自然会被语境化，从而让整个游戏环境的相对大小在玩家心中聚焦。第 [10](#334805_2_En_10_Chapter.xhtml) 章所述的英雄角色物理实现也成为游戏的重要组成部分：模拟重力、动量等将玩家在移动角色穿越游戏世界时，以内在的方式与英雄角色连接起来。通过按图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 所述实现设计，你仅通过添加一些视觉元素和物体物理，就已经完成了一些令人印象深刻的认知壮举，从而支持临场感。

## 定义可玩空间

此时，你已充分描述了游戏的核心机制和设定，可以开始将单个屏幕扩展为完整的关卡概念。在这个阶段，拥有最终视觉风格并非关键，但包含一些概念艺术将有助于指导关卡如何成长。（图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 根据物体尺度，很好地直观展示了单个屏幕上将进行的游戏玩法量。）这也是在可运行原型中“封锁”图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 中元素的好阶段，以开始体会移动手感（例如英雄角色奔跑速度、跳跃高度等）、环境中物体的尺度、相机缩放级别等。目前无需包含锁组件或能量场等交互和行为，因为你尚未设计关卡如何玩。目前你正在尝试基本的英雄角色移动、物体放置和碰撞。下一组任务包括布局完整关卡并调整所有交互。

图 [12-3](#334805_2_En_12_Chapter.xhtml#Fig3) 中的设计现状仍需一些工作以提供足够的挑战。虽然所有成熟关卡的要素都已就位，但当前难度微不足道，大多数玩家可能很快就能完成关卡。然而，有一个坚实的基础可以开始扩展跳跃和序列机制；首先，你可以扩展水平游戏空间，以包含更多可玩区域，并为角色机动提供额外空间，如图 [12-4](#334805_2_En_12_Chapter.xhtml#Fig4) 所示。

![图 12-4 ¶ 关卡设计扩展以包含额外可玩区域](`images/334805_2_En_12_Chapter/334805_2_En_12_Fig4_HTML.jpg`)

图 [12-4](#334805_2_En_12_Chapter.xhtml#Fig4) ¶ 关卡设计扩展以包含额外可玩区域

回顾第 [7](#334805_2_En_7_Chapter.xhtml) 章中的简单相机操作项目，你可以通过将角色移动到边界区域边缘来“推进”游戏画面，这允许你设计远超单个静态屏幕尺寸的关卡。当然，你可以选择将关卡限制在原始游戏屏幕尺寸内，并增加基于时机的敏捷性和逻辑序列挑战的复杂性（事实上，在空间限制内挑战自我是一个很好的设计练习），但为了本设计的目的，水平滚动呈现增加了趣味性和挑战性。
