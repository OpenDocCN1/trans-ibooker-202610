

在本章开始时，您的游戏引擎支持绘制方面有趣的复杂功能，范围涵盖从定义 WC 空间的能力，到使用 Camera 对象查看 WC 空间，再到在对象上绘制视觉上令人愉悦的纹理和动画。然而，当时并没有支持对象行为的基础设施。这一缺陷导致初始化和控制逻辑聚集在客户端层面的实现中。随着本章介绍并实现了对象行为抽象、数学算法和碰撞算法，您的游戏引擎功能现在更加平衡。您游戏引擎的客户端现在拥有封装特定行为和检测碰撞的工具。下一章将重新审视并增强 Camera 对象的功能。您将学习控制和操作 Camera 对象，以及在同一个游戏中使用多个 Camera 对象。

## 游戏设计考量

第 [1](#334805_2_En_1_Chapter.xhtml) 至 [5](#334805_2_En_5_Chapter.xhtml) 章介绍了在屏幕上绘制、移动和为对象添加动画的基础技术。第 [4](#334805_2_En_4_Chapter.xhtml) 章的 *Scene Objects*（场景对象）项目描述了一种简单的交互行为，并向您展示了如何根据矩形的位置更改游戏画面：回想一下，将矩形移动到左边界会导致关卡在视觉上发生变化，而 *Audio Support*（音频支持）项目则添加了情境音效以增强整体的临场感。虽然仅使用第 [1](#334805_2_En_1_Chapter.xhtml) 至 [5](#334805_2_En_5_Chapter.xhtml) 章的元素就可以构建一个引人入胜（尽管简单）的益智游戏，但当您能够整合对象检测和碰撞触发器时，事情会变得有趣得多；这些行为构成了许多常见游戏机制的基础，并提供了设计各种有趣游戏场景的机会。

从 *Game Objects*（游戏对象）项目开始，您可以看到屏幕元素如何开始协同工作以传达游戏背景；即使该项目中的交互仅限于角色移动，背景设定也开始呈现出一种传达场所感的雏形。主角角色似乎正飞越一个由许多机械机器人组成的移动场景，屏幕中心有一个小物体，您可以想象它可能会变成某种特殊的拾取物。

即使在开发的这个基本阶段，也可以头脑风暴潜在的游戏机制，这些机制可能构成完整游戏的基础。如果您仅基于 *Game Objects* 项目中发现的屏幕元素设计一个简单的游戏机制，您会选择什么样的行为，要求玩家执行什么样的动作？举个例子，假设主角角色必须避免与飞行机器人碰撞，也许有些机器人会检测并追逐主角试图阻止玩家的进度；也许主角一旦接触机器人就会受到某种惩罚。再假设屏幕中心的小物体允许主角在一段固定时间内无敌，而我们设计关卡要求临时无敌才能到达终点，从而创造一个更复杂、更有趣的游戏循环（例如，避开追逐的机器人以到达道具，激活道具获得临时无敌，利用无敌状态到达终点）。仅凭这些基本交互，我们就为探索机制和关卡设计打开了大门，这些设计会让人感觉非常熟悉，源自许多不同类型的游戏，而所有这些仅靠第 [6](#334805_2_En_6_Chapter.xhtml) 章涵盖的对象检测、追逐和碰撞行为即可实现。请使用 *Game Objects* 项目中显示的元素亲自尝试这个设计练习：您可能会设计什么样的简单条件和行为来使您的体验独一无二？您能想出多少种利用屏幕中心小物体的方法？第 [12](#334805_2_En_12_Chapter.xhtml) 章的最终设计项目将更详细地探讨这些主题。

这也是一个很好的机会，针对第 [1](#334805_2_En_1_Chapter.xhtml) 章讨论的其他九个游戏设计要素进行头脑风暴。如果游戏背景不是太空机器人呢？也许背景设定在森林、水下，甚至是完全抽象的东西。您如何融入音频以增强临场感并强化游戏背景？您可能会对自己想出的各种背景和场景感到惊讶。将自己限制在第 [6](#334805_2_En_6_Chapter.xhtml) 章涵盖的元素和交互中，实际上是一个有益的练习，因为设计约束通常能通过塑造和引导您的想法来帮助创作过程。即使是最先进的视频游戏，通常也以一套相当基础的核心游戏循环为基础。

*Vectors: Front and Chase*（矢量：前向与追逐）项目从游戏机制和临场感两个角度来看都很有趣。当然，许多游戏要求游戏世界中的对象检测主角角色，并会追逐或试图躲避玩家（如果对象有多种状态，甚至两者兼有）。该项目还演示了两种不同的追逐行为方法：瞬间追逐和平滑追逐，游戏背景通常会影响您选择实现哪种行为。在瞬间追逐和平滑追逐之间的选择，是微妙行为如何显著影响临场感的一个绝佳例子。例如，如果您设计的是一艘船在海洋上互动的游戏，您可能希望它们的追逐行为考虑现实世界的惯性和动量，因为船无法瞬间转向并响应运动变化；相反，它们平稳、逐渐地移动，表现出响应移动目标速度的明显延迟。物理世界中的大多数对象都会在一定程度上表现出相同的惯性和动量约束，但也存在一些情况，您可能希望游戏对象直接响应路径变化（或者，您可能想故意违背现实物理，创建一种不基于物理对象限制的行为）。关键是始终对您的设计选择保持深思熟虑，并记住几乎没有任何实现细节是微不足道到不会被玩家注意到的。

*Bounding Box and Collisions*（包围盒与碰撞）项目为您的设计武器库引入了关键的检测元素，允许您开始包含更健壮的因果机制，这些机制构成了许多游戏交互的基础。第 [6](#334805_2_En_6_Chapter.xhtml) 章讨论了在精度较低但性能更好的包围盒碰撞检测方法与精确但资源密集的逐像素检测方法之间进行选择的权衡。在许多情况下，包围盒方法已足够，但如果玩家认为碰撞是随意的，因为包围盒与实际视觉对象差异太大，这会对临场感产生负面影响。当结合 *Per-Pixel Collisions*（逐像素碰撞）项目的结果时，检测和碰撞将成为更强大的设计工具。虽然本例中的染料包用于指示首个碰撞点，但您可以想象围绕两个对象碰撞产生新对象来构建有趣的因果链（例如，玩家追逐对象，玩家与对象碰撞，对象“掉落”一个新对象，使玩家能够做以前做不到的事）。在游戏屏幕上移动的游戏对象通常都会有动画，因此 *Sprite Pixel Collisions*（精灵像素碰撞）项目描述了如何在对象边界不固定的情况下实现碰撞检测。
