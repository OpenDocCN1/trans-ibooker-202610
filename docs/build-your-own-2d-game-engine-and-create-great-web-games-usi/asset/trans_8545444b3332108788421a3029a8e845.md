
## 使用 WebGL 模板缓冲区进行阴影模拟

阴影可以通过确定待照明位置与环境中每个光源位置之间的可见性来模拟。如果某物体遮挡了该位置相对于光源的视线，或者该位置从光源处不可见，则该位置相对于该光源处于阴影中。从计算角度来看，这是一项开销很大的操作，因为通用可见性确定是一个 `O(n)` 操作，其中 `n` 是场景中的物体数量，并且必须为每个被照明的像素执行此操作。从算法角度来看，这是一个具有挑战性的问题，因为可见性解决方案必须在片段着色器的照明计算期间可用，同样是针对每个被照明的像素。

由于计算和算法上的挑战，许多视频游戏不再根据物理世界模拟阴影，而是基于专用硬件资源，仅为选定的物体近似或创建类阴影效果。在本节中，你将学习如何通过基于 WebGL 模板缓冲区选择专用的阴影投射者和接收者来近似阴影。

![图 8-24：英雄在小兵身上投射阴影而非背景上](images/334805_2_En_8_Chapter/334805_2_En_8_Fig24_HTML.png)

图 8-24：英雄在小兵身上投射阴影而非背景上

为了正确模拟和渲染图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 中的阴影，如图 [图 8-25](#334805_2_En_8_Chapter.xhtml#Fig25) 所示，有三个重要元素。

*   `Shadow caster`（阴影投射者）：这是导致阴影的物体。在图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 示例中，英雄物体是阴影投射者。
*   `Shadow receiver`（阴影接收者）：这是阴影出现其上的物体。在图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 示例中，小兵物体是阴影接收者。
*   `Shadow caster geometry`（阴影投射者几何体）：这是实际的阴影，换句话说，是因光线遮挡而在阴影接收者上形成的黑暗区域。在图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 示例中，真实英雄物体后方出现在小兵身上的英雄黑色印记即为阴影投射者几何体。

![图 8-25：阴影模拟的三个参与元素：投射者、投射者几何体和接收者](images/334805_2_En_8_Chapter/334805_2_En_8_Fig25_HTML.png)

图 8-25：阴影模拟的三个参与元素：投射者、投射者几何体和接收者

给定这三个参与元素，阴影模拟算法相当直接：计算阴影投射者几何体，像往常一样渲染阴影接收者，将阴影投射者几何体作为深色阴影投射者物体渲染在接收者之上，最后像往常一样渲染阴影投射者。例如，要渲染图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 中的阴影，首先根据光源位置、英雄物体（阴影投射者）和小兵物体（阴影接收者）的位置计算深色英雄阴影投射者几何体。之后，首先像往常一样渲染小兵物体（阴影接收者），接着将阴影投射者几何体作为具有深色恒定颜色的英雄物体进行渲染，最后像往常一样渲染英雄物体（阴影投射者）。

请注意，阴影实际上是一种视觉效果，物体上的颜色因光能被阻挡而显得更暗。重要的是要注意，当人类观察阴影时，并没有新的物体或几何体参与其中。这与上述算法形成鲜明对比，在该算法中，阴影是通过阴影投射者几何体（一个深色物体）来模拟的。这个深色物体在场景中并不实际存在。它是通过算法创建的，用于近似光线被遮挡的视觉感知。虽然这种创建和渲染额外几何体来模拟人类视觉感知结果的做法很有趣，但它也有自己的挑战。

![图 8-26：阴影投射者超出阴影接收者的边界](images/334805_2_En_8_Chapter/334805_2_En_8_Fig26_HTML.png)

图 8-26：阴影投射者超出阴影接收者的边界

幸运的是，WebGL 模板缓冲区专门设计用于解决这类情况。WebGL 模板缓冲区可配置为一个开/关开关的二维数组，其像素分辨率与网页浏览器中显示的画布相同。通过此配置，当启用模板缓冲区检查时，画布中可绘制的像素将仅限于那些对应的模板缓冲区像素处于开启状态的像素。

![图 8-27：WebGL 模板缓冲区](images/334805_2_En_8_Chapter/334805_2_En_8_Fig27_HTML.png)

图 8-27：WebGL 模板缓冲区

在 WebGL 模板缓冲区的支持下，现在可以通过识别所有阴影接收者并将相应的阴影投射者与每个接收者分组，来相应地指定阴影模拟。在图 [图 8-24](#334805_2_En_8_Chapter.xhtml#Fig24) 示例中，英雄物体被分组为小兵阴影接收者的阴影投射者。在该示例中，为了让背景物体接收来自英雄的阴影，必须将其明确标识为阴影接收者，并将英雄物体分组为其阴影投射者。请注意，如果不明确将小兵物体分组为背景阴影接收者的阴影投射者，小兵就不会在背景上投射阴影。

正如将在后续实现讨论中详述的那样，阴影投射者和接收者的透明度以及投射光源的强度都会影响阴影的生成。重要的是要认识到，这种阴影模拟实际上是一种算法创建，其效果可用于近似人类感知。此过程并不描述阴影在现实世界中是如何形成的，因此完全有可能创建出非真实的戏剧性效果，例如投射透明或蓝色的阴影。
