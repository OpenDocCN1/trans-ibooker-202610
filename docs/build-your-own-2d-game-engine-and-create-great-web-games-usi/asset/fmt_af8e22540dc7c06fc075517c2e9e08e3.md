
# MyGame 对象平铺测试

`MyGame` 应测试对象平铺的正确性。为测试多层平铺，创建了两个单独的 `TiledGameObject` 和 `Camera` 实例。两个 `TiledGameObject` 实例位于距离摄像机不同距离（z 深度）处，并由不同组合的光源照亮。新增的第二个摄像机聚焦于其中一个 `Hero` 对象。

仅关注 `TiledGameObject` 实例的创建。因为一旦创建，`TiledGameObject` 实例的处理方式与 `GameObject` 实例相同。因此，仅详细检查 `MyGame` 类的 `init()` 函数。

## 初始化代码

```
init() {
    // Step A: set up the cameras
    this.mCamera = new engine.Camera(
        vec2.fromValues(50, 37.5), // position of the camera
        100,                       // width of camera
        [0, 0, 1280, 720]          // viewport (X, Y, width, height)
    );
    this.mCamera.setBackgroundColor([0.8, 0.8, 0.8, 1]);
    // sets the background to gray
    this.mHeroCam = new engine.Camera(
        vec2.fromValues(20, 30.5), // position of the camera
        14,                        // width of camera
        [0, 420, 300, 300],        // viewport (X, Y, width, height)
        2
    );
    this.mHeroCam.setBackgroundColor([0.5, 0.5, 0.9, 1]);
    // Step B: the lights
    this._initializeLights();  // defined in MyGame_Lights.js
    // Step C: the far Background
    let bgR = new engine.IllumRenderable(this.kBg, this.kBgNormal);
    bgR.setElementPixelPositions(0, 1024, 0, 1024);
    bgR.getXform().setSize(30, 30);
    bgR.getXform().setPosition(0, 0);
    bgR.getMaterial().setSpecular([0.2, 0.1, 0.1, 1]);
    bgR.getMaterial().setShininess(50);
    bgR.getXform().setZPos(-5);
    bgR.addLight(this.mGlobalLightSet.getLightAt(1));
    // only the directional light
    this.mBg = new engine.TiledGameObject(bgR);
    // Step D: the closer Background
    let i;
    let bgR1 = new engine.IllumRenderable(
        this.kBgLayer, this.kBgLayerNormal);
    bgR1.getXform().setSize(30, 30);
    bgR1.getXform().setPosition(0, 0);
    bgR1.getXform().setZPos(-2);
    for (i = 0; i < 4; i++) {
        bgR1.addLight(this.mGlobalLightSet.getLightAt(i)); // all lights
    }
    bgR1.getMaterial().setSpecular([0.2, 0.2, 0.5, 1]);
    bgR1.getMaterial().setShininess(10);
    this.mBgL1 = new engine.TiledGameObject(bgR1);
    ... identical to previous code ...
}
```

## 代码说明

在列出的代码中，两个摄像机首先在步骤 A 中创建，随后在 `_initializeLights()` 函数中创建并初始化所有光源。步骤 C 将 `bgR` 定义为一个带有 `IllumRenderable` 的 `TiledGameObject`，由一个光源照亮。步骤 D 基于另一个由四个光源照亮的 `IllumRenderable` 定义第二个 `TiledGameObject`。由于 `TileGameObject` 类的 `mShouldTile` 变量默认为 `true`，两个平铺对象都将平铺其绘制目标摄像机。

## 观察结果

现在可以运行项目并使用 `WASD` 键移动 `Hero` 对象。正如预期，两层平铺背景清晰可见。可通过选择并关闭光源 1（按 `1` 键后按 `H` 键）来关闭远处背景的照明。移动 `Hero` 对象以平移摄像机，验证两个摄像机中的平铺和背景移动行为是否正确。

一个有趣的观察是：虽然两层背景位于距离摄像机不同距离处，但当摄像机平移时，两张背景图像同步滚动。若非光源照明的差异，背景看起来将像是一张单独的图像。此例说明了模拟运动视差的重要性。

# 使用视差滚动模拟运动视差

**视差滚动** 通过定义并以不同速度滚动对象来模拟运动视差，传达这些对象位于距离摄像机不同距离的感觉。图 [11-5](#334805_2_En_11_Chapter.xhtml#Fig5) 通过俯视图展示了对象距离摄像机的概念距离。由于是鸟瞰图，摄像机 `WC` 边界的宽度显示为底部的一条水平线。`Hero` 对象最靠近摄像机，位于两层背景 `Layer1` 和 `Layer2` 前方。典型 2D 游戏中，绝大多数游戏对象将位于此默认距离。背景对象位于默认距离之后，更远离摄像机。可通过背景对象上的策略性绘制（如 `Layer1` 的草地和 `Layer2` 的远山）配合适当的滚动速度来传达距离感。注意位置 `P`[1] 和 `P`[2] 分别位于背景对象 `Layer1` 和 `Layer2` 上，直接在 `Hero` 对象后方。

![Figure 11-5 ¶ Top view of a scene with two background objects at different distances](images/334805_2_En_11_Chapter/334805_2_En_11_Fig5_HTML.png)

**Figure 11-5** ¶ 具有不同距离的两个背景对象的场景俯视图

图 [11-6](#334805_2_En_11_Chapter.xhtml#Fig6) 展示了摄像机静止时向左视差滚动的结果。`Layer1` 滚动速度快于 `Layer2`，因此位置 `P`[1] 相对于原始位置的位移大于 `P`[2]。持续滚动将使 `Layer1` 比 `Layer2` 移动得更快，从而正确传达 `Layer1` 更近的感觉。在视差滚动中，靠近摄像机的对象始终比较远的对象具有更大的滚动速度。

![Figure 11-6 ¶ Top view of parallax scrolling with stationary camera](images/334805_2_En_11_Chapter/334805_2_En_11_Fig6_HTML.png)

**Figure 11-6** ¶ 静止摄像机下的视差滚动俯视图

当摄像机运动时，实现视差滚动必须考虑对象的相对速度。图 [11-7](#334805_2_En_11_Chapter.xhtml#Fig7) 通过俯视图说明了移动摄像机与静止对象的情况。此例中，摄像机 `WC` 边界向右移动了 `d` 单位。由于移动发生在摄像机中，摄像机视图内所有静止对象将表现为以摄像机移动的反方向位移。例如，静止的 `Hero` 对象从中心向左位移至新 `WC` 边界的左边缘。为正确模拟运动视差，两个背景 `Layer1` 和 `Layer2` 必须以不同的相对距离位移。此时须计算相对距离，使较远对象看起来移动得更慢。摄像机移动结束时，在新的 `WC` 边界内，最靠近摄像机的 `Hero` 对象将表现为向左位移 `d` 单位，`Layer1` 对象位移 `0.75d`，`Layer2` 对象位移 `0.25d`。这样，对象的位移反映了它们距离摄像机的相对距离。为实现此效果，`Hero` 对象的平移量为零，`Layer1` 和 `Layer2` 对象必须分别向右平移 `0.25d` 和 `0.75d`。注意背景向右平移的量小于摄像机移动量，因此背景实际向左移动。例如，虽然 `Layer1` 对象向右平移 `0.25d`，但从向右移动 `d` 的摄像机视角看，结果是 `Layer1` 对象向左位移了 `0.75d`。
