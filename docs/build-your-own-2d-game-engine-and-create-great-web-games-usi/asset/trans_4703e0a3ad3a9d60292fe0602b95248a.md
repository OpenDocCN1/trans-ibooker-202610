## 使用精灵表绘制

如前所述，精灵表是由多个低分辨率图像组成的图像，每个低分辨率图像单独代表不同的对象。这些单独的图像中的每一个被称为 `sprite sheet element`（精灵表元素）。例如，图 [5-7](#334805_2_En_5_Chapter.xhtml#Fig7) 是一个包含 13 个元素的精灵表，这些元素来自 4 个不同的对象。前两行中的每一行包含同一对象在不同动画位置下的五个元素，而在最后一行，有三个不同对象的元素：角色 Dye、传送门爪牙和收集者爪牙。创建精灵表的美术人员或软件程序必须将每个精灵元素的像素位置传达给游戏开发者，方式与图 [5-7](#334805_2_En_5_Chapter.xhtml#Fig7) 所示大致相同。

![Figure 5-7 ¶ Example sprite sheet: minion_sprite.png composed of lower-resolution images of different objects](images/334805_2_En_5_Chapter/334805_2_En_5_Fig7_HTML.png)

*图 5-7 ¶ 精灵表示例：`minion_sprite.png` 由不同对象的低分辨率图像组成*

定义精灵表是为了优化内存和处理需求。例如，回想一下 WebGL 仅支持由分辨率为 2^(*x*) × 2^(*y*) 的图像定义的纹理。这一要求意味着，分辨率为 120x180 的 Dye 角色必须存储在 128x256 (2⁷ × 2⁸) 的图像中，才能将其创建为 WebGL 纹理。此外，如果图 [5-7](#334805_2_En_5_Chapter.xhtml#Fig7) 的 13 个元素作为单独的图像文件存储，则需要 13 次缓慢的文件系统访问来加载所有图像，而不是一次系统访问即可加载精灵表。

使用精灵表及其关联元素的关键在于记住：无论实际图像分辨率如何，纹理坐标 uv 值都定义在 0 到 1 的归一化范围内。例如，图 [5-8](#334805_2_En_5_Chapter.xhtml#Fig8) 重点展示了图 [5-7](#334805_2_En_5_Chapter.xhtml#Fig7) 中收集者爪牙的 uv 值，即第三行最右侧的精灵元素。图 [5-8](#334805_2_En_5_Chapter.xhtml#Fig8) 的顶部、中部和底部行显示了传送门元素的坐标值。

*   **像素位置**：左下角为 (315, 0)，右上角为 (495, 180)。
*   **UV 值**：左下角为 (0.308, 0.0)，右上角为 (0.483, 0.352)。
*   **在** **模型空间中使用**：通过将相应的 uv 值与每个顶点位置处的 xy 值关联，实现元素的纹理映射。

#### 使用 SpriteShader 将 GLSL 纹理着色器接入引擎

支持使用精灵表元素进行纹理映射的着色器必须能够识别图像的不同子区域。为支持此功能，您将实现 `SpriteShader` 以定义其自己的纹理坐标。由于此新着色器扩展了 `TextureShader` 的功能，将其作为子类实现是合乎逻辑的。

1.  在 `src/engine/shaders` 文件夹中创建一个新文件，命名为 `sprite_shader.js`。

2.  定义 `SpriteShader` 类及其构造函数以扩展 `TextureShader` 类：

```javascript
class SpriteShader extends TextureShader {
    constructor(vertexShaderPath, fragmentShaderPath) {
        // 调用超类构造函数
        super(vertexShaderPath, fragmentShaderPath);
        this.mTexCoordBuffer = null; // 包含纹理坐标的 gl 缓冲区
        let initTexCoord = [
            1.0, 1.0,
            0.0, 1.0,
            1.0, 0.0,
            0.0, 0.0
        ];
        let gl = glSys.get();
        this.mTexCoordBuffer = gl.createBuffer();
        gl.bindBuffer(gl.ARRAY_BUFFER, this.mTexCoordBuffer);
        gl.bufferData(gl.ARRAY_BUFFER,
            new Float32Array(initTexCoord), gl.DYNAMIC_DRAW);
        // DYNAMIC_DRAW：表示缓冲区内容可能会改变！
    }
    // ... 后续实现 ...
}
```

`SpriteShader` 在 WebGL 中定义了自己的纹理坐标缓冲区，并通过 `mTexCoordBuffer` 保存对该缓冲区的引用。请注意，在 WebGL `bufferData()` 函数中创建此缓冲区时，指定了 `DYNAMIC_DRAW` 选项。这与在 `vertex_buffer.js` 中定义系统默认纹理坐标缓冲区时使用的 `STATIC_DRAW` 选项形成对比。动态选项通知 WebGL 图形系统，该缓冲区的内容将发生变化。

3.  定义一个函数以设置 WebGL 纹理坐标缓冲区：
