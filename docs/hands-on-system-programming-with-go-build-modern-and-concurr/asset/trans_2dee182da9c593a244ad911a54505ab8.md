

# 信号量

信号量是用于解决并发问题的工具。它们拥有一定数量的可用配额，用于限制对资源的访问；此外，各个线程可以从中请求一个或多个配额，并在完成后释放它们。如果可用配额的数量为一，则意味着该信号量一次仅支持一次访问，其行为类似于互斥锁。如果配额多于一，我们称之为最常见的类型——加权信号量。

在 Go 中，信号量可以使用容量等于配额的通道来实现，向通道发送消息以获取配额，从通道接收消息以释放：

```go
type sem chan struct{}

func (s sem) Acquire() {
    s <- struct{}{}
}

func (s sem) Release() {
    <-s
}
```

前面的代码展示了如何用几行代码使用通道实现信号量。以下是一个使用示例：

```go
func main() {
    s := make(sem, 5)
    for i := 0; i < 10; i++ {
        go func(i int) {
            s.Acquire()
            fmt.Println(i, "start")
            time.Sleep(time.Second)
            fmt.Println(i, "end")
            s.Release()
        }(i)
    }
    time.Sleep(time.Second * 3)
}
```

完整示例请访问 <https://play.golang.org/p/BR5GN2QopjQ>。

从前面的示例中我们可以看到，程序在第一轮获取时处理了一些请求，在第二轮处理其余请求，不允许同时有超过五个执行过程。

在本章中，我们讨论了 Go 并发中的两个主要角色——`goroutine` 和 `channel`。我们首先解释了什么是 `thread`，`thread` 和 `goroutine` 的区别是什么，以及为什么它们如此方便。`Thread` 笨重且需要 `CPU 核心`，而 `goroutine` 轻量级且不绑定核心。我们看到了如何通过在函数前加上 `go` 关键字来轻松启动一个新的 `goroutine`，以及如何一次性启动一系列不同的 `goroutine`。我们了解到并发函数的参数是在创建 `goroutine` 时求值，而不是在它实际开始运行时。我们还看到，如果没有任何额外工具，要让不同的 `goroutine` 保持同步是非常困难的。

最后，我们展示了一些实际案例，包括一个速率受限的 Google Maps 客户端和一个同时 `ping` 网络中所有地址的工具。

## 同步原语

我们了解了 `channel` 如何专注于 `goroutine` 间的通信，现在我们将关注 `sync` 包提供的工具，其中包含用于 `goroutine` 间同步的基本原语。首先我们将看到如何使用锁实现对同一资源的并发访问。

### 并发访问与锁

Go 为可加锁和解锁的对象提供了一个通用接口。加锁意味着获取其控制权，而解锁则释放它供他人使用。该接口为每个操作暴露了一个方法。以下是代码示例：

```go
type Locker interface {
    Lock()
    Unlock()
}
```

#### 互斥锁

锁最简单的实现是 `sync.Mutex`。由于其方法使用指针接收者，因此不应复制或按值传递。如果可能，`Lock()` 方法会获取 `mutex` 的控制权，否则阻塞 `goroutine` 直到 `mutex` 可用。`Unlock()` 方法释放 `mutex`，如果在未加锁的 `mutex` 上调用，会返回运行时错误。

这里有一个简单的示例，我们启动一堆 `goroutine` 使用锁来查看哪个先执行：

```go
func main() {
    var m sync.Mutex
    done := make(chan struct{}, 10)
    for i := 0; i < cap(done); i++ {
        go func(i int, l sync.Locker) {
            l.Lock()
            defer l.Unlock()
            fmt.Println(i)
            time.Sleep(time.Millisecond * 10)
            done <- struct{}{}
        }(i, &m)
    }
    for i := 0; i < cap(done); i++ {
        <-done
    }
}
```

完整示例请访问：<https://play.golang.org/p/resVh7LImLf>

我们使用 `channel` 在任务完成时向主 `goroutine` 发信号，并退出应用程序。让我们创建一个外部计数器并使用 `goroutine` 并发地增加它。

在不同 `goroutine` 上执行的操作不是线程安全的，正如我们从以下示例中看到的：

```go
done := make(chan struct{}, 10000)
var a = 0
for i := 0; i < cap(done); i++ {
    go func(i int) {
        if i%2 == 0 {
            a++
        } else {
            a--
        }
        done <- struct{}{}
    }(i)
}
for i := 0; i < cap(done); i++ {
    <-done
}
fmt.Println(a)
```

我们期望有 5000 次加一和 5000 次减一，最终指令打印 `0`。然而，每次运行应用程序得到的值都不同。之所以发生这种情况，是因为这类操作不是线程安全的，所以两个或更多操作可能同时发生，最后一个操作会覆盖其他操作。这种现象称为 `race condition`（竞态条件）；即多个操作尝试写入同一结果。
