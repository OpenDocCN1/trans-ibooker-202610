
这是一个非常通用的容器；它可以用于任何类型的 `variable`，且 `variable` 类型应当能够从一种变为另一种。如果具体类型发生变化，会导致 `method` `panic()`；同样的情况也适用于 `nil` `empty interface`。

## 内部原理

`sync.Value` 类型将其数据存储在一个非导出的 `interface{}` 中，如源代码所示：

```go
type Value struct {
    v interface{}
}
```

它使用 `unsafe` 包中的一个类型将该结构转换为另一个结构，后者与 `interface{}` 具有相同的数据结构：

```go
type ifaceWords struct {
    typ  unsafe.Pointer
    data unsafe.Pointer
}
```

具有完全相同内存布局的两种类型可以通过这种方式相互转换，从而绕过 Go 的类型安全。这使得可以对指针使用 `atomic` 操作，并执行线程安全的 `Store()` 和 `Load()` 操作。

为了获取写入值的锁，`atomic.Value` 在类型字段中使用带有 `unsafe.Pointer(^uintptr(0))` 值（即 `0xffffffff`）的比较并交换操作；它会更改值并将类型替换为正确的类型。

同样地，加载操作会循环等待，直到类型不再是 `0xffffffff`，然后尝试读取值。

利用这种权宜之计，`atomic.Value` 能够使用其他 `atomic` 操作来存储和加载任意值。

## 总结

在本章中，我们了解了 Go 标准包中用于同步的工具。它们位于两个包中：`sync` 提供高级工具（如互斥锁），而 `sync/atomic` 执行低级操作。

首先，我们了解了如何使用锁来同步数据。我们看到了如何使用 `sync.Mutex` 来锁定资源，而不论操作类型；以及如何使用 `sync.RWMutex` 允许并发读取并阻塞写入。使用后者时应当小心，因为连续的读取可能会延迟写入。

接下来，我们了解了如何跟踪正在运行的操作，以便等待一系列 goroutine 结束，使用的是 `sync.WaitGroup`。它充当当前 goroutine 的线程安全计数器，并通过 `Wait()` 方法使当前 goroutine 休眠，直到计数器归零。

此外，我们还检查了用于执行一次性功能的 `sync.Once` 结构，它允许实现线程安全的单例模式，例如。然后我们使用 `sync.Pool` 来复用实例，而不是在可能的情况下创建新实例。池所需的只是一个返回新实例的函数。

`sync.Cond` 结构体表示一个特定条件，并使用一个锁来更改它，允许 goroutine 等待该条件的变化。可以使用 `Signal()` 将变化通知单个 goroutine，或使用 `Broadcast()` 通知所有 goroutine。该包还提供了线程安全的 `sync.Map`。

最后，我们了解了 `atomic` 的功能，它们主要是整数的线程安全操作：加载、保存、添加、交换和 CAS。我们还看到了 `atomic.Value`，它使得可以并发地更改 `interface{}` 的值，并且不允许在首次更改后改变其类型。

## 理解 context

Context 是一个相对较新的组件，在 1.7 版本加入标准库。它是用于 goroutine 间同步的接口，最初由 Go 团队内部使用，最终成为语言的核心部分。

### 接口

包中的主要实体是 `Context` 本身，它是一个接口。它只有四个方法：

```go
type Context interface {
    Deadline() (deadline time.Time, ok bool)
    Done() <-chan struct{}
    Err() error
    Value(key interface{}) interface{}
}
```

让我们来了解这四个方法：

*   `Deadline()`：返回 context 应该被取消的时间，以及一个布尔值，当没有截止时间时该值为 `false`
*   `Done()`：返回一个只接收的空结构体通道，用于发出 context 应该被取消的信号
*   `Err()`：当 `done` 通道打开时返回 `nil`；否则返回 context 取消的原因
*   `Value()`：返回当前 context 中与键关联的值，如果该键没有值则返回 `nil`

`Context` 拥有的方法比标准库中的其他接口多，后者通常只有一两个方法。其中三个方法紧密相关：

*   `Deadline()` 是取消的时间
*   `Done()` 发出 context 完成的信号
*   `Err()` 返回取消的原因

最后一个方法 `Value()` 返回与特定键关联的值。包的其余部分是一系列函数，允许你创建不同类型的 context。让我们浏览包中的各种函数，看看创建和装饰 context 的各种工具。

### 默认 context

`TODO()` 和 `Background()` 函数无需任何输入参数即可返回 `context.Context`。返回的值是一个空 context，尽管它们的区别仅在于语义上。

#### Background

`Background()` 是一个空 context，它不会被取消，没有截止时间，也不持有任何值。它主要被 `main()` 函数用作根 context，或用于测试目的。以下是该 context 的示例代码：

```go
func main() {
    ctx := context.Background()
    done := ctx.Done()
    for i := 0; ; i++ {
        select {
        case <-done:
            return
        case <-time.After(time.Second):
            fmt.Println("tick", i)
        }
    }
}
```

完整示例请见：<https://play.golang.org/p/y_3ip7sdPnx>。

我们可以看到，在示例中，循环会无限进行下去，因为 context 永远不会完成。

#### TODO

`TODO()` 是另一个空 context，当 context 的作用域不明确或 context 类型尚不可用时应使用它。它的使用方式与 `Background()` 完全相同。事实上，在内部实现上，它们是同一个东西；区别仅在于语义。如果我们查看源代码，它们具有完全相同的定义：

```go
var (
    background = new(emptyCtx)
    todo       = new(emptyCtx)
)
```

该代码的来源可在 <https://golang.org/pkg/context/?m=all#pkg-variables> 找到。

这些基本 context 可以使用包中的其他函数进行扩展。它们将作为装饰器，为 context 添加更多功能。

### 取消、超时和截止时间

我们刚才看到的 context 永远不会被取消，但该包提供了不同的选项来添加此功能。

#### 取消
