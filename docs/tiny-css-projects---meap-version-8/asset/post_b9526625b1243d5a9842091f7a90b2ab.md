## 5.5 Transition on hover and focus-within

To start with we need to create a media query which checks if the device supports the hover interaction and the browser window is at least 700px wide and that our user does not have prefers-reduced-motion enabled on their machine.

### Prefers reduced motion

Users may want to opt out of motion heavy animations. They can do this by enabling a setting on their devices which is conveyed to the browser via the prefers-reduced-motion property. We want to make sure we respect our user’s settings and we will therefore include that the setting is not set (has a value of no-preference) as part of our query determining whether to animate our content. For more information about prefers-reduced-motion checkout the Accessibility and the reduced motion query section in chapter 3.

Our media query therefore looks as follows: @media (hover: hover) and (min-width: 700px) and (prefers-reduced-motion: no-preference) { }. Notice that we can chain multiple parameters that need to be met for the CSS found in the query to be applied.

To hide everything but the header, we will shift the content downwards to the bottom of the card using the transform property with a value of translateY(). TranslateY() allows us to move content vertically outside of the flow of the page, meaning that the content around the element being moved is completely unaffected by the movement, and will not reposition itself or get out of the way.

To calculate the distance the element needs to move, we will use the calc() function again. We will move the header downward the height of the card (350px) minus 8rem (the top margin of the container + padding-top of the container + size of the header).

The inner portion of the card is therefore moved downward as seen in Figure 5.17.

![](img/b56145aa9b751926a7aedbd7172bc818_149_0.png)

Figure 5.17 Moving the content down

Since we are going to animate showing the content when the user hovers off the section, we do not want the trailing content at the bottom to remain because if the user hovers on the content bleeding out of the picture, the content will move upward into the picture, lose the hover and then move back down again. This behavior will repeat creating a flicker. We will therefore set a height of 5rem for our inner container and hide the overflow when the paragraph and link are hidden.

Notice that in the second card, a little bit of the paragraph content will still be visible when the content should be hidden. We will therefore also hide the non header content using opacity, when it should not be seen. Additionally, we move that content down 1rem using translateY which will allow us to give it a little bit of motion when we animate it back in on hover.

All together, the CSS used to hide the content and shorten the inner container is as follows (Listing 5.15). To select all of the content that is not the header we can use the :not() pseudo-class.

### Listing 5.15 Hiding the non header content

```
@media (hover: hover) and (min-width: 700px) and (prefers-reduced-motion: no-preference) {
    #A
    main > section > div {
        transform: translateY(calc(350px - 8rem));
        height: 5rem;
        overflow: hidden;
    }
    main > section > div > *:not(h2) {
        opacity: 0;
        transform: translateY(1rem);
    }
}
```

#B Moving and shortening the inner content container
#C Hiding all of the non H2 content

Now that the content is hidden (Figure 5.19) we can focus on showing it again.

![](img/b56145aa9b751926a7aedbd7172bc818_151_0.png)

### Figure 5.19 Hiding content

To show the content again, we need to undo everything we did to hide it on both hover and on focus. Because we are not removing the links from the DOM, they are only visually hidden. Programmatically they still exist and a user can tab to a link via keyboard. We therefore need to show the content both when the user hovers over the card and when a link gains focus. Because we want to act on an ancestor (the content container) when a child (the link) is in focus, we can use the :focus-within pseudo-class. This pseudo-class allows us to conditionally apply styles based on whether a descendant of the element is currently in focus.

So both when the link is in focus or when the section is being hovered over, we move the container back into place by setting the translateY() parameter to 0 (no vertical displacement), and setting the height of the inner container to 350px (height of the outer container) minus 4rem (total of the vertical padding and margin of the container).

We also need to reinstate the paragraph and link, whose opacity had been set to 0 and who had been moved downward by 1rem.

Finally we finish our hover and focus-within effect by adding a transition to elements being shown and hidden. Because we have predefined states we are changing between and we only want the animation to run once when the change occurs, we do not need to use keyframes, we can simply instruct the CSS to animate all of the changes when they happen using the transition property to which we assign a value of all 700ms ease-in-out. This will make it so that all of the changes are animated, the animation will take 700 milliseconds to complete and it will start slow, accelerate, and then slow down before completing.

Our hover and focus-within CSS therefore looks as follows (Listing 5.16).

### Listing 5.16 Showing content on hover and on focus-within

```
@media (hover: hover) and (min-width: 700px) and (prefers-reduced-motion: no-preference) {
  main > section > div {
    transform: translateY(calc(350px - 8rem));
    height: 5rem;
    overflow: hidden;
    transition: all 700ms ease-in-out; #E
  }

  div > *:not(h2) {
    opacity: 0;
    transform: translateY(1rem);
    transition: all 700ms ease-in-out; #E
  }

  section:hover div,      #A
  section:focus-within div {      #B
    transform: translateY(0);
    height: calc(350px - 4rem);
  }

  section:hover div > *:not(h2),      #C
  section:focus-within div > *:not(h2){      #D
    opacity: 1;
    transform: translateY(0);
  }
}
```

#A on section hover move container back into place

#B on section focus-within move container back into place

#C on hover move all non h2 elements inside the container back into place with full opacity

#D on section focus-within move all non h2 elements inside the container back into place with full opacity

#E Animating the changes

## 5.6 Summary

- We used the grid property as a way to layout our cards horizontally. By using both media queries and grid-template-columns we adjusted the layout to be 4 columns wide if the minimum browser window size is 950px wide, if it is between 700px and up to 950px then set to 2 columns, anything else it will default its default state of stacked
- The `text-transform` property can visually change text to uppercase without impacting the accessibility of the content; when the content is copied it won’t be all uppercase
- Use the `text-transform: uppercase` sparingly and not on large areas of content
- The `background-clip` property with a value of text can clip a background image around the text
- The `background-clip` property still needs to be prefixed and this property can change whilst it’s being implemented
- We can use a media query to check whether a device supports hover and adjust our layout so that it prevents the user from seeing the content if their device does not support hover
- We can chain multiple conditions on the same media query using `and`
- We can use `prefers-reduced-motion` in our media query to respect user preferences regarding animations and motion.
- The `:not()` pseudo-class represents elements that do not match a list of selectors.
- `translateY()` will move content vertically without affecting reflow
- We can use the `transition` property to animate style change between states
- To conditionally apply styles based on an element’s descendent being in focus we use the `focus-within` pseudo-class
