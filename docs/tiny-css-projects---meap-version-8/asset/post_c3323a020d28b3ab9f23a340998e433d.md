## 11.3 Sourcing Icons

Anytime we are using iconography from someone else’s brand, we need to consider

- 1. Are we authorized to use the icon?
- 2. Are there any restrictions to how the icon can be used?

In the case of social media icons, their brand is being represented in our work and we therefore must follow their guidelines as to when, how, and in what context we can use their brand.

With icons that do not represent a brand (like the icon we used for the mailto link or share button), unless we created the icon ourselves, we are subject to the copyright laws same as any other image, sound, video, etc we might use in our projects.

> DISCLAIMER We are not lawyers. This is not intended to be legal advice. When in doubt, contact a legal professional.

### 11.3.1 Media Icons

An effective way to find how a branded icon can be used is to look for that brand’s guide by doing a web search for terms such as “style guide” or “brand guide”. Many social media outlets will have specific instructions on how the brand can be represented including icon and logo

downloads. Table 11.1 lists the social media platforms we included in our component and links to their brand information.

### 11.3.2 Icon libraries

Looking for individual icons can be a bit tedious especially on large projects, so it is not uncommon to use icon fonts and libraries to supply us with our icons. As mentioned above, these are subject to terms of use. Each library and icon font will have their own rule as to where and how they can be used. Some may also require attribution, we therefore must take care to be aware of any rules we need to follow while sourcing our icons.

For this project, we sourced our non brand related icons from Material Symbols (https://fonts.google.com/icons). Since we only needed 2 (share - and email -@), we downloaded the individual SVGs and included them in our icon folder rather than importing the entire library into the project.

## 11.4 Styling the block

Since we are using BEM for our naming convention, our block name will be "share". Therefore the container `div` that wraps the entire component will have a class of `share`. This block name will also be included in all of our future classes using the BEM naming convention mentioned in section 11.1.3, which will scope our CSS to that component and help prevent any styling collisions between our component and any other parts of the application it would be used in.

As seen in listing 11.2, we define the `font-family`, `background`, and `border-radius`, for the block. We also give the component a `display` value of `inline-flex`. `inline-flex` works the same way as `flex` but makes the element an inline-level element rather than a block-level element. By making our component behave as an inline element (same as links, spans, buttons... ), we give it the most versatility in terms of placement when it is included into an

application. Furthermore, buttons by default are inline elements, and when closed, what is presented is essentially a button, so we will give it the same flow behavior as a button.

### 11.5.1 Share button

The class name given to the button will include the block name followed by 2 underscores and then the element. In our case we will call this element “button”. Our class name will therefore be: share__button. By prefixing our class name with share__ we ensure that the only button we will be styling is the one within our block.

We want to override the defaults provided by the browser and align the icon and text within (Listing 11.3). We remove the background, and border, adjust the font size and padding, and curve our corners.

To align the icon and text, we give the button a display value of flex, and then use `align-items` to vertically align the icon and text. To add white space between the icon and text, we use the `gap` property.

## Listing 11.3 Styling the share button

```
.share_button {
  background: none;
  border: none;
  font-size: 1rem;
  padding: 0 2rem 0 1.5rem;
  border-radius: 36px;
  display: flex;
  align-items: center;
  gap: 1ch;
}
```
