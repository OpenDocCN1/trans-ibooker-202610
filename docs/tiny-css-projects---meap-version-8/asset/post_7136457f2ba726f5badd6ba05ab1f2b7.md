From food, to books, to entertainment, and everything in between, many of us will regularly buy items online. Common to this experience is the checkout cart. We make our selections by adding them to a virtual cart or basket with which we can review our chosen items before making our final purchase. In this chapter we will look at how to style a checkout cart so that it works on both narrow and wide screens.

In this chapter we will look at how to handle tables in both narrow and wide screens. Tables are incredibly useful for displaying data however, they can be a bit difficult to style for mobile devices. We will therefore look at a CSS solution for narrow screens.

We will first handle some theming. Regardless of the width of our screen, elements such as input fields, links, or buttons will look the same, so we will style these first. Defining a theme early on in putting a UI together can significantly help reduce redundant code and increase our ability to keep our styles consistent, so whether a checkout cart or any other page or application, this process can be translated to any number of designs.

We will then focus on the layout moving from narrow to wide. Because on narrow screens, such as phones, we tend to stack things, and as we grow larger, we add rules to make use of the full width available to us. It is often easier to start with mobile and add to our styles as the screen gets wider rather than start wide and have to override previously set layout elements as we grow smaller. We will create styles to accommodate 3 sizes of screens:

- Narrow (most phones): maximum width of 549 pixels
- Medium (tablets and small screens): between 500px and 955px
- Wide (desktops and high resolution tablets): wider than 955px

## 8.1 Getting Started

Regardless of the screen size, we are going to use the same HTML. We will have one stylesheet, and use media queries to adjust how our elements look depending on the screen size. Media queries are used to conditionally apply styles to elements; we will explore these in more detail later in the chapter.

Our HTML consists of two sections, one for the cart and one for the summary, which are wrapped in a container that we will use on wide screens to place the sections side by side. The cart section contains a heading and a table which contains each of the items in the cart. The summary section contains a heading, a definition list, and 2 links. ## 8.2 Theming

Although our layout has 2 clearly defined sections (the cart and the summary), and needs to work across screen sizes, there are styles that are not going to change regardless of where they are or the size of the screen. These include

- Fonts used
- Buttons and link styles
- Input and error message styles
- Header size and color

These types of styles can be referred to as our theme, and to keep them consistent across our page, we generally want to write them once and apply them everywhere. Let’s start with our fonts.

### 8.2.1 Typography

Currently our `font-family` is our browser’s default. In my case it is Times New Roman, but this may be different for you depending on your operating system, browser, and system settings. Figure 8.3 shows the default typeface and developer tools indicating that Times New Roman is being used. In most browsers, right clicking on the page and selecting inspect will open the developer tools. Since the font-family is not being explicitly set some browsers will obscure it and you may need to excitedly tell the browser to show all properties via a checkbox at the top of the computed list of properties or via the browser tools settings.

Instead of Times New Roman we are going to import Raleway from Google Fonts. We are then going to create a rule targeting the body tag, to apply the font. For this we will use the font-family property, assigning it "Raleway" as a value. We also apply a fallback of sans-serif. Should Raleway fail to load, we ensure that a comparable alternative will be used (Raleway is a sans-serif font). By applying the style to the body tag, we make full use of cascading and the font will be applied everywhere.

With the font-family applied, we are now going to set the default color for our text. Also on the body, use the color property to assign a color to the text. We are going to use a value of #171717, which looks almost black. We aren’t using black with this design because it is a very soft design and pure black can be quite harsh.
