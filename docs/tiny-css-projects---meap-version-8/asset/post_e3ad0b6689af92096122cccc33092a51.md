## 10.3.4 :where() and :is() pseudo-classes

At this junction, we are going to look at two pseudo classes that will help us keep our code clean and concise :is() ¹¹ and :where() ¹². Both work similarly in that they take a list of selectors and will apply the rule if any of the selectors within the list match. It is incredibly helpful when writing long lists of selectors. Instead of writing:

```
input:focus, textarea:focus, select:focus, button:focus { ... }
```

We can instead use :where or :is and write an equivalent like so:

```
:where(input, textarea, select, button):focus { ... }
```

The :is() pseudo class would be applied in the same manner. The difference between :is() and :where() is in their level of specificity. :where() is least specific and therefore easy to override. :is() on the other hand takes the specificity value of the most specific selector inside of the list.

> NOTE Specify For a refresher of how specificity is calculated check out the Specificity section in chapter 1. We will also go into a bit more depth about how to calculate specificity when using :where() and :is() later in this chapter.

Caution must therefore be used in using :is() because if we have an id selector inside of our list of selectors (id selectors are most specific), we can quickly create rules that become very difficult if not impossible to override.

We will use both :where() and :is() in conjunction with other pseudo classes such as :checked, :hover, :focus, and the ::before pseudo element to finish styling our checkbox and radio inputs.

## 10.3.5 Styling checked radio and checkbox inputs

To add the inner disk of the checked radio and the checkmark for the checkbox, we are going to apply a similar methodology as we did for the unchecked styles where we created some base styles that applied to both and then added the finishing touches to each element individually when the styles diverged. Same as before, we will first create a box. We will then place that box in the center of the existing styles, and finally shape it to be either a disk or checkbox.

To create this second box to be placed inside of our current element we will use the ::before pseudo-element. This is when the :where() pseudo class we introduced in the last section comes into play. We will use it to select both of our input types and then add the ::before pseudo elements. Our selector will therefore look like this: :where(input[type="radio"], input[type="checkbox"] )::before { ... }.

We can now create our box. Our content will be empty, so we will use a content property value of "", we will give it a display of block so that we can assign a width and a height.

When we created the outer box earlier, we gave it a height and width of 1em. We used an em unit so that control would scale in size relative to the text size. We will do that here as well. We want the radio inner disk and check mark to be smaller than their container so we will set our height and width to 0.625em. Assuming the font size applied to the input is 16px, our box size in pixels with be 10px by 10px (16 × 0.625 = 10).

We do not need to do anything to position our inner box because remember how we set the input display to inline-grid and then added the place-content property with a value of center (Listing 10.11)? The grid layout will automatically place the inner box in the center of the input.

## 10.3.6 Using the :checked pseudo-class

We are not going to blankety apply the same background color to our element all the time. We are going to use our accent color when the element is checked, and our hover color when it is being hovered over.

The :checked pseudo-class selector can be used on an input of type radio or checkbox, or to the option element in a drop down list (<select>) to apply styles when the element is checked. However, the ability to use it on option is browser dependent.

When we apply the background color for checked and on hover, if the selectors have the same level of specificity (our example will) the order in which we write these rules matters. If we write the checked rule first and the hover rule second, the hover color will be applied to a checked input on hover because the hover rule will override the checked rule by nature of it being later in the CSS file. We therefore want to make sure the hover rule is placed before the checked rule in the CSS file. Figure 10.18 illustrates these 2 scenarios.
