# Figure 5.19 Hiding content

To show the content again, we need to undo everything we did to hide it on both hover and on focus. Because we are not removing the links from the DOM, they are only visually hidden. Programmatically they still exist and a user can tab to a link via keyboard. We therefore need to show the content both when the user hovers over the card and when a link gains focus. Because we want to act on an ancestor (the content container) when a child (the link) is in focus, we can use the :focus-within pseudo-class. This pseudo-class allows us to conditionally apply styles based on whether a descendant of the element is currently in focus.

So both when the link is in focus or when the section is being hovered over, we move the container back into place by setting the translateY() parameter to 0 (no vertical displacement), and setting the height of the inner container to 350px (height of the outer container) minus 4rem (total of the vertical padding and margin of the container).

We also need to reinstate the paragraph and link, whose opacity had been set to 0 and who had been moved downward by 1rem.

Finally we finish our hover and focus-within effect by adding a transition to elements being shown and hidden. Because we have predefined states we are changing between and we only want the animation to run once when the change occurs, we do not need to use keyframes, we can simply instruct the CSS to animate all of the changes when they happen using the transition property to which we assign a value of all 700ms ease-in-out. This will make it so that all of the changes are animated, the animation will take 700 milliseconds to complete and it will start slow, accelerate, and then slow down before completing.
