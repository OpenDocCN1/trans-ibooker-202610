With our input fields styled, we can now handle only showing them when appropriate. In Figure 10.33 we see that the inputs have valid values, and yet the error messages still show. To hide only show them when the field is invalid, we will start by hiding the error message by default. We therefore apply a `display` property value of `none` to the `span` contained in the error `div`. Then we use the `:invalid` to conditionally show it only when the field is invalid.

As we previously touched on chapter 8, the validity of the field in this case is determined based on the properties we set on the field itself. Let’s look at the name input HTML again: `<input type="text" id="name" name="name" maxlength="250" required aria-describedby="nameError">`. We included a `required` and a `maxlength` attribute, therefore if there is no value in the field, or if the value’s length is greater than 250 characters, the field value will be invalid and styles applied to it using the `:invalid` pseudo class will be applied.

The email element (`<input type="email" id="email" name="email" maxlength="250" required aria-describedby="emailError">`) also has a `maxlength` and a `required` attribute so it would be invalid under the same conditions as the name field. It also has a type of `email` however. In HTML, some field types have validation built in. Email is one of those, therefore, if we were to enter an email address value of "myEmail", it would also show as invalid.
