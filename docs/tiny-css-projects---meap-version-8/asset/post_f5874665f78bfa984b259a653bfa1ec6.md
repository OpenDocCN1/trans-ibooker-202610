## 8.2.3 Input fields

You may have noticed under the input fields in the table the phrase "Must be a whole number between 0 and 99." This is related to field validation. In the HTML we have set a min and max value the field can take: <input name="grapes" type="number" min="0" max="99" ...>. If the number we type in the field is outside of the range, the field is invalid. We can use pseudo classes to conditionally style the field based on its validity. We are therefore going to style our field differently based upon whether it is valid.

We will assume that by default the field is valid and then override the styles for invalid fields. So let's first start with some basic styles for our field. These are going to be the same as our base button styles. Instead of copy and pasting, we can add input to the list of existing selectors as demonstrated in Listing 8.8. This helps ensure that some of the basics we intend to keep throughout our theme remain the same everywhere and reduce the number of places we need to update code if the style were to change.

### Listing 8.7 Adding input to base button styles

```
button,
.button,
input {
  background: none;
  border-radius: 4px;
  ...
}
```

Now let’s handle invalid fields. When a user inputs an entry that is invalid we want to notify them. Our HTML already has rules set as to what a valid value means. We indicated a min of 0 and max of 99. Since we did not indicate a step, the browser will default the value to one. This means that the only valid numbers for our input are integers between 0 and 99 inclusive. All other entries will register in the DOM tree as invalid. In CSS we can specifically select invalid form elements via the :invalid pseudo-class.

To clearly mark our input as invalid we are going to change the border color from gray to red (#9d1616). We will also increase the width of the left border to add a non-color-based visual differentiation.

> **NOTE Use of Color** Although color can be very helpful in conveying information such as status it cannot be the only differentiating factor because color-blind or visually impaired users may not be able to distinguish between the colors on the page. Furthermore, if the device being used has a monochrome or limited color display, color differences may not be visible².

### Listing 8.8 Adding input to base button styles

```
input:invalid {
  border-left: solid 5px #9d1616;
  border-color: #9d1616;
}
```

Next we are going to style our error message. We are going to give the text the same color red we used for our borders, make the text bold, but slightly smaller than other elements on the page. To make sure it is clearly identified as an error we will also add an error icon before the text.

To add the error icon we are going to use the pseudo element :before.

> **REMEMBER** A pseudo-class is added to a selector to target a specific state while a pseudo-element allows us to select a part of the element.

To add the image we will use the content property with the url() function to which we will pass the file’s URL. We will then float the image to the left, allowing our error text to wrap around it. We will set the width of the image to 1 rem to make it proportional to the text and give it some margin to allow some breathing room between it and the text.

The last piece we need is to hide the error message by default and only show it when the immediately adjacent input is invalid. We are using adjacency in the HTML to pair the input field with the error message. Listing 8.9 shows our input and error HTML.

### Listing 8.9 Input and Error HTML

```
<td data-name="Quantity">
<input name="grapes" type="number" aria-label="Pounds of grape baskets" min="0" max="99" id="grapes" value="-1" aria-errormessage="grapeError">
<p class="error" id="grapeError" role="alert" aria-live="polite">Must be a whole number between 0 and 99</p>
</td>
```

To hide it by default we will give the error div a display of none. We will then use the adjacent sibling combinator (+) to find the error message immediately following an invalid input, and change its display to block. Listing 8.10 shows the full CSS for error messages.

### Listing 8.10 Adding input to base button styles

```
.error {
  color: #9d1616;
  font-size: .875em;
  font-weight: bold;
  display: none; #A
}

.error:before {
  content: url('./img/icons/error.svg'); #B
  width: 1em;
  float: left; #C
  margin-right: .25rem; #D
}

input:invalid + .error { #E
  display: block;
}
```

- #A Hide error messages by default
- #B Add error icon
- #C Float the icon so text will wrap around it
- #D Add breathing room between the icon and the text
- #E Use adjacent sibling combinator (+) to display error messages that immediately follow an invalid input

## 8.2.4 Table

Next we are going to style the table. We are only going to concern ourselves with elements that relate to the theme such as colors and borders. The layout and responsiveness will come later in this chapter.

Our table is divided into three sections:
- 1. The header – `thead`
- 2. The body – `tbody`
- 3. The footer – `tfoot`

We will address each in order.

We are going to start by styling our table headers. Because they are not as important as the content found in the table itself, we give them a slightly smaller font size and lighter color than the rest of the text. We are also going to decrease their default font weight of bold to normal. By subduing them a little bit we are helping create a visual hierarchy in the table and emphasizing what the user cares the most about (the items in their shopping cart).

In our body, we are going to emphasize the item name (found in the second column) by making the text bold. To add the bold property to the item, we are going to use the pseudo class `:nth-of-type`, to specifically target the second cell of each row in the body: `tbody td:nth-of-type(2)`.

> **PSEUDO CLASS** Remember, a pseudo class matches elements based on their state. In this case their position among the same siblings (other table cells) inside of the parent container (the row).

We are also going to use `:nth-of-type`, passing in a value of `even` this time, to select the even numbered rows in the body, to create stripes. We will then add a top border to all of the rows, regardless of where they are in the table.

Finally we are going to bold the grand total in the footer. Our CSS will look as follows (Listing 8.11):

### Listing 8.11 Adding input to base button styles

  font-weight: normal;
  font-size: .875em;

tbody td:nth-of-type(2), #B
tfoot td { #C

}

tr {
  border-top: solid 1px #aeb7b7;
}

tbody tr:nth-of-type(even) { #D
  background: #f2fcfc;      #D
