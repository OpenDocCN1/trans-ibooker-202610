# 5.5 Transition on hover and focus-within

To start with we need to create a media query which checks if the device supports the hover interaction and the browser window is at least 700px wide and that our user does not have prefers-reduced-motion enabled on their machine.

# Prefers reduced motion

Users may want to opt out of motion heavy animations. They can do this by enabling a setting on their devices which is conveyed to the browser via the prefers-reduced-motion property. We want to make sure we respect our user’s settings and we will therefore include that the setting is not set (has a value of no-preference) as part of our query determining whether to animate our content. For more information about prefers-reduced-motion checkout the Accessibility and the reduced motion query section in chapter 3.

Our media query therefore looks as follows: @media (hover: hover) and (min-width: 700px) and (prefers-reduced-motion: no-preference) { }. Notice that we can chain multiple parameters that need to be met for the CSS found in the query to be applied.

To hide everything but the header, we will shift the content downwards to the bottom of the card using the transform property with a value of translateY(). TranslateY() allows us to move content vertically outside of the flow of the page, meaning that the content around the element being moved is completely unaffected by the movement, and will not reposition itself or get out of the way.

To calculate the distance the element needs to move, we will use the calc() function again. We will move the header downward the height of the card (350px) minus 8rem (the top margin of the container + padding-top of the container + size of the header).
