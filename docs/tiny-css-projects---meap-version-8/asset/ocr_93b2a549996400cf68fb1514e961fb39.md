Next, we are going to give the inputs some padding, custom borders, and border-radius. In this particular case, these styles are going to be for stylistic purposes. Most applications will have a general style, or look and feel. The styles we choose to apply to our fields should be in the same vein as the rest of our application’s general theme. By doing this we help the form blend with the page and look like it belongs. From a marketing perspective, keeping with your theme will also help reinforce brand recognition. For this project we have chosen a very round theme so we will give our fields exaggerated round corners.

Lastly, we will also give our fields a display value of block (inputs have a display property value of inline by default) and make them take the full width of our container. We will use the calc() 5 function to calculate the full width of the container (100%) minus the padding we have added to the input field (2rem on each side for a total of 4 in width). Remember the box model? Padding adds to the width of the element. Therefore, we must remove the total quantity of left and right padding from our width. A width of 100% would equate a width of 100% of the available width of the container, then the padding value would be added. We would therefore be 4rem larger than our allotted space if we did not subtract the padding.

Our code looks as follows (Listing 10.7).
