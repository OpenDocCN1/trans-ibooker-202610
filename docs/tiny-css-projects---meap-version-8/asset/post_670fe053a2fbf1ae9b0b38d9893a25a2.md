## 8.2.6 Cards

To give the layout some depth and separation between the sections we are going to style each of our sections' containers as cards. Cards are a commonly used pattern in UI design to visually separate content by encapsulating it inside of a visual box or container reminiscent of a playing card. This is the same concept to the card we created for our profile information in Chapter 6.

To pull off our card design we are going to add a very pale teal background to the body, and outline the sections using a shadow which will make it look like they are hovering slightly above the body. To create the shadow we will use the box-shadow property which allows us to control the amount of shadow we want to add in the x and y axis, as well as the amount of blur (how fuzzy), the distance it should spread, and the color the shadow should be. Figure 8.14 details how the property values are applied.

```
box-shadow: 2px 2px 7px 0 #aeb7b7;
```

![](img/b56145aa9b751926a7aedbd7172bc818_230_0.png)

Figure 8.14 box-shadow property values

Optionally, we can also set a value of inset before the offsets to indicate that the shadow should be turned inward within the element rather than around the outside.

To finish the look of our card, we will also curve the corners using a 4px border radius. The same value we used for our links, buttons, and inputs.

Figure 8.15 shows our styled sections, but notice at the bottom of the summary card, the links are bleeding out rather than pushing the card to be taller and being encased in it. This is because links have a display value of inline by default.

## 8.3 Mobile Layout

We will start mobile first and work our way outward. The first thing we are going to do is make our table responsive.

### 8.3.1 Table Mobile View

A traditional table layout does not work very well on mobile because tables need a lot of width which phone screens do not have. To accommodate narrow screens we will therefore make the table rows and cells act more like cards than a table.

We will start by using a media query to specifically apply a set of rules to the table when the viewport is less than or equal to 549px. Media queries start with an @, then we specify the condition that must be met for the code within to take effect. In our case our media query will be `@media (max-width: 549px) { }`.

Inside this media query, we will define what we want the table to look like on narrow screens. As a quick refresher, Figure 8.16 shows what our table currently looks like and what we are trying to achieve.

![](img/b56145aa9b751926a7aedbd7172bc818_234_0.png)

Figure 8.16 Table before and after on mobile

To view the narrow screen or mobile version, in most browser dev tools we can set tools to simulate the screen of a particular device. Not all tools will have the phone image around but it will constrain the size of the browser window to fit the device’s dimensions. In chrome, to select a particular device, we toggle the device toolbar by clicking the icon with the phone on it at the top of the dev tools and then choose the device we want to use as seen in Figure 8.17. It is worth noting that this is a very limited simulation and should not replace testing on the device proper.

To place the header information before each piece of content, we aren’t going to be using the header. Instead in our HTML, we have added some data attributes to the cells: <td data-name="Item">Red Grapes, 1lb</td>. We move the table header offscreen using absolute positioning. We do not want to use a display none, as the information available in the header is still needed by assistive technologies. By absolute positioning it offscreen (using a very large negative value), we hide it visually but not programmatically.

Next we use the data-name attribute information, which we display in each cell. To display the attribute value we use the attr() function, which takes an attribute name and returns a value. For our use case, our content property will look as follows: td[data-name]:before { content: attr(data-name) ":"; }. Figure 8.19 breaks it down in detail.
