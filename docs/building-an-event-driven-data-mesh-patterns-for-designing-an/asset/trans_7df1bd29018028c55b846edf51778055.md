
从现有数据库和系统中引导数据是开始使用数据网格的重要部分。您可以快速轻松地将数据发布到事件流中，以便消费者可以开始在自己的领域中试用它。它还能引发关于谁拥有连接器、进而谁拥有数据、领域以及管理功能请求以更改可用数据及其表示方式的讨论。

通常，引导式数据反映了源系统的内部领域模型。来自关系数据库的高度规范化数据往往难以使用，下游用户需要进行复杂且代价高昂的反规范化。事件频率、事件大小和紧密的内部耦合仍然是引导式数据产品需要关注的问题。

引导式数据产品仍然是通往一流数据产品（具有明确架构、反规范化数据结构以及与内部数据模型隔离）途中的垫脚石。但它们仍然是数据网格迭代增长的重要部分。

## 运营、分析与两者之间的一切

数据网格最初是为了解决分析领域固有的数据访问和可靠性问题而提出的。然而，它已被证明是为运营系统以及那些难以分类为其中一类的系统提供动力的一种强大非标签解决方案。可靠地访问干净、定义明确、低延迟的数据是战略灵活架构的基石。您可以自由创建、测试和试用新业务系统，而无需为数据访问而苦苦挣扎。您的系统将不再像弗兰肯斯坦的怪物那样，仅仅为了访问底层数据而被拼凑在一起。

事件流在为对时间敏感的应用程序提供动力方面发挥着关键作用。运营系统（尤其是有人参与循环的系统）从低延迟状态事件中获益匪浅。分析系统则通过从运营系统的相同来源获取数据而获益，缓解了历史上困扰数据领域的“类似却又不同”的数据来源问题。

## 摘要

事件驱动的数据网格是对未来的投资。要成功采用它，需要识别组织中的数据痛点，以便开始应用四项原则。通过帮助同事了解数据网格如何解决他们长期存在的数据问题，获得他们的支持。

进行迭代工作。您的数据网格不会一夜之间突然出现。试用新解决方案，从错误中吸取教训，并进行迭代改进。一路上发现价值对于保持人们投入并从数据产品中获益至关重要。

最后，在构建数据网格的过程中庆祝成功。道路将曲折曲折，有时您可能会感觉倒退。与同行分享您的磨难与考验，并共同努力寻找共同点和新的前进方向。祝您未来之旅顺利。
