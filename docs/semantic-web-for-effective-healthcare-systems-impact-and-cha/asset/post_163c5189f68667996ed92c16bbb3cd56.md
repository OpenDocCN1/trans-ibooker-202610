
## 10.3.1 RDF Model and Technology

The RDF model is based on describing the resources using properties that are also the attributes or characteristics. The properties are uniquely identified using the Uniform Resource Identifier (URI) and the resources corresponding to the property are identified using the property type which has its matching values. The property type links a resource to a value that could be another resource or an atomic value or literals like a data value having text strings or integers. A description is a group of properties linked to the same resource. RDF is founded on its capacity to represent a resource and its descriptions using a syntax-independent model [43–45, 47].

The resource, its property type and the property value form a triple in which the resource is the subject, its property type is the relationship or predicate and the property value is the object. The RDF model consisting of the triple forms the foundation of the RDF technology and is the basis for the integration of data from various heterogeneous data sources. The RDF technology allows the data from varied sources to be formatted as a semantic description containing the description of resources and the relationship between the resources. Such liberty in representing data is the reason why RDF technology is popular in knowledge representation for knowledgebase systems and artificial intelligence. The basic requirement for RDF technology is that the resources are identified by the URI and the fundamental conditions for data exchange, that is, the data is represented as a set of triples. Duplication of triples is to be strictly avoided but it does not matter in which position the triple is placed [48, 49].

## 10.3.2 Metadata and URI

The word metadata was probably first used by Philip Bagley in 1968, in his book “Extension of Programming Language Concepts” in which he describes metadata as a secondary data element like an identifier or an access code that contains information about the contents of the primary data element. He terms such information containing secondary elements as the metadata elements. Earlier to it, the word metadata was used to describe publications, library catalogs, subject indexes, various classifiers, and article abstracts. From the early stages of the development of computer systems, although the word metadata was not specifically mentioned, the features of metadata were visible in the properties of source code, compiler design and file storage. It became more pronounced while in the use of database description and conceptual modelling languages. Later in document retrieval systems, the document indices were provided together with descriptors of the document for quicker retrieval. The Report Program Generator by IBM was used to generate formatted reports that could be metadata. Later with the advent of the world wide web and the use of Hypertext Markup Language, the markup tags became metadata resources. These metadata resources were exploited by the recent semantic web technologies for knowledge representation, data search and logical inferencing. Metadata has now become a necessary element to describe properties associated with a subject domain [50].

Metadata can be categorized into different types based on the function of the metadata. Descriptive metadata describes the content of the resources and the assistance rendered by the metadata in finding or understanding the resources. The administrative metadata contains information regarding the creation or the management of the resources. The preservation metadata is about the long-term support for the metadata or its future migration or about matching the digital files. The technical metadata has information of the digital files that is essential to decrypt and extract them. The technical and preservation metadata could be treated as part of the administrative metadata. Structural metadata consists of information about the relationship between the parts of the resources. The rights metadata has information with regards to licensing, copyrights and the like. Markup languages are also considered as a type of metadata that contains flags or formatting information that help in situating paragraphs, titles, headings, lists, name, date and so on [51, 52]. There can also be other categories of metadata that could deal with information regarding statistics, references, indices and others.

There is more than one approach to manage metadata. Some metadata management approaches for the structured and semi-structured databases are annotations, provenance, quality parameters, schema and mapping, security, superimposed information and time. Since there is wide heterogeneity in the kinds of metadata that require a high degree of specialization for the management of the metadata, the inter-operability of the metadata is quite a challenging task. Moreover, there was no distinction between data and metadata that can be made while querying. In other words, the system cannot distinguish whether the result of a query is data or metadata. Many attempts were made to arrive at a clean and simple approach for a uniform model and to query data. The RDF is considered predominantly as the solution to representing interlinked data. RDF was primarily introduced as a means of representing the metadata available on the web. The metadata that is on the web may not be only web data but could also be other data. So, in RDF, the web data is considered as resources and the web data is represented using a unique URI [53].

In 1992 the Internet Engineering Task Force (IETF), which is entrusted with overseeing the required infrastructure for the development of the internet, established the URI working group to solve the issues concerning standardizing Uniform Resource Locator (URL) schemes to avoid causing congestion in servers and reproducing intercontinental traffic. The URI working group came up with a model to standardize the resource identifiers by Uniform Resource Name (URN) and Uniform Resource Characteristics (URC). After a lot of work was done on the URN and URC, it was realized that the URL which is part of the URI was the only standard format achieved. So, in July 1995, the IETF disbanded the URI working group and formed the URN working group in July 1996 to work on naming schemes and resolution systems. The URC which describes languages, formats, character sets, version numbers, author names, and so on, has not developed any particular scheme so far [54–56].

URI makes use of the syntax and semantics from the notions presented by the world wide web global information initiative to provide a simple and extendible method of identifying resources. “Functional Recommendations for Internet Resource Locators” [57] and “Functional Requirements for Uniform Resource Names” [58] were the recommendations used in the design of the URI. The URI is characterized by the uniformity that allows the use of different types of resource identifiers even if the methods used to get the identifiers may be different. Moreover, there is uniformity in the use of semantic interpretation of common syntactic resolutions of varied resource identifiers and new types of identifiers might be used without disturbing the existing identifiers. The reuse of the identifiers in various contexts allows newer applications and systems to make use of the large and widely used existing identifiers. The use of the word resource does not limit itself to only the use of existing resources in the web but rather to anything that might be identified as a resource by the URI. A resource, therefore, need not be only what is in the web but it can be anything from a real-world material like books, reports, surveys and the like or also something belonging to the abstract world like a type of relationship, a mathematical operator and so on. The identifier distinguishes one resource from the other without any emphasis on the identification method. The identifier need not represent the identified resource or the URI will access the identified resource [59].
