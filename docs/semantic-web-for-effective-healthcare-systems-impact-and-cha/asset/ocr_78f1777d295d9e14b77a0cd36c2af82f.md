An intelligent database is one that can not only store data in a perfectly linked relational manner but one that will also be able to produce knowledge for solving various problems. The relational database system has benefits such as being able to share data without compromising data consistency and integrity. Without a tool to extract knowledge from the data, the database cannot be useful for any knowledgebase system. A knowledgebase system is one in which data is stored in the form of knowledge that could be useful to the system. Structured query language (SQL) is a tool that could be utilized to convert data in a relational database system to knowledge. To do that the data is stored in relational database tables and the SQL queries are used to extract knowledge out of the database. So, the system does not operate as a knowledge base system but rather a database system from which knowledge can be extracted [12]. Although the possibility of building an intelligent system using an already existing database system seems to be attractive, their limitations in terms of knowledge and their time and space complexities are far greater than the advantages.

A method of circumventing the problem of using SQL in a programming language is the use of Horn clauses. ProLog is built on Horn clauses and is used to define and query a rational database that is limited to First-Order Logic. The non-terminal relation symbols that restrict first-order formulas could be expressed as sets of Horn clauses by making use of a fix-point operator that is applied to positive existential queries. One drawback of using Horn clauses is that adding a relation tuple to a database using the Horn clause program cannot delete the output of the query. To overcome the deficiency, an extension of the Horn clause to include negated terminal relation symbols could be thought of but universal quantification cannot be express by it. The other possibility is to let arbitrary first-order formulas with non-terminals as programs which are no solution at all [13].

Attempts were also made to infuse taxonomy and semantic interpretation using Horn clauses by making use of the idea of concepts and relations. It was a step towards merging Semantic Networks with logical programming and a relational database to create the knowledge base for a system. These attempts were seen as a stop-gap solution to the problem of constraint satisfaction. The use of domains of concepts greatly helped the reduction of time and space complexities by avoiding redundant computation and backtracking checks through an early deduction of failures [14].
