The big challenge arises when conjunctive queries are to be made to RDF data which is a triple since most existing query languages will require performing multiple joins and unions that can greatly slow down the scalable query access. But since the relational database systems had the advantage of being highly evolved over decades of usage, some modified versions are still used to store RDF data [60, 61].

RDF Stores are storage systems to hold information in RDF format for faster search and retrieval. It has better capabilities for processing Big Data of the very flexible RDF knowledge and therefore, it has been researched and developed in many different ways. A large number of semantic and knowledge processing applications make use of the RDF stores due to its capacity for devices interoperability. The data model of the RDF stores allows the application user to be presented with ways of viewing the information rather than to present the user with the data itself. Since the information has to be abstracted for such use, there has been a large variation in the data structure used by different RDF Stores. While some RDF Stores rely on the traditional relational database structures many others make use of advanced and complex structures like the RDF specific indexing schema [62].

RDF store models can be classified in three ways. The simplest classification is those in which the RDF resides in the local drive and those in which the RDF is obtained by a federated search in which the RDF is obtained from different web pages. Practically, the federated search boils down to storing the RDF in the local drive for use in the knowledgebase system. A more common classification is one that identifies RDF store as centralized and distributed storage. Centralized storage makes use of the relational database technology to store data in a centralized system from which it can be queried for search and retrieval. For quicker search and retrieval, the data might be indexed in which case the RDF triples might also include the index value. While the centralized storage can provide efficiency with regards to performance and speed, they are limited by the amount of data that can be handled by such systems. The distributed storage systems on the other hand are scalable. Principally, the distributed storage system has multiple machines running centralized storage that are linked using a conceptual layer to coordinate the distribution of data among them [61, 63–65].

A more generalized classification of the RDF storage systems is by broadly distinguishing them as native and non-native systems. The native storage systems contrive a separate storage backend for the knowledgebase systems. The native systems can be further classified as those that make use of the main memory and those that use disk storages. The main memory storage relies on parsing and loading the RDF files in a portion of the main memory which may be indexed for faster retrieval. The disk storage models make persistent use of indices which causes an operational bottleneck. The non-native RDF stores make use of the existing well-developed database systems to store RDF data. These RDF stores use either a relational database or a NoSQL backend for storage and retrieval of information. The relational database that is used by non-native RDF stores could be a schema-based or a schema-free approach. In comparison, the native approach is more efficient than the non-native approach for a knowledgebase system although it requires a lot of effort in the design and implementation of such systems [60, 62, 66].

## 10.4 Knowledgebase Systems and Knowledge Graphs

The knowledgebase is a storage of knowledge in a structured form using knowledge representation techniques on which a knowledgebase system can be built [67]. Knowledge can be defined in so many different ways that there is no single definition that encompasses its complete meaning [68–70]. For knowledgebase systems, knowledge can be defined as processed information that is used to solve a given problem. So, the various solutions to the problem for which the system is designed are representatively stored in a knowledgebase of the system. The system then retrieves the relevant knowledge from the knowledge base when required.

### 10.4.1 Knowledgebase Systems

Knowledgebase Systems are systems that hold solutions to problems of a particular domain in their knowledge base. The knowledge-based systems sprouted out of expert systems that were itself an offshoot of Artificial Intelligence [71]. Knowledgebase systems and expert systems were terms interchangeably used because the expert systems that were developed earlier contained knowledge of experts coded in the system, they performed tasks like human experts and were used to solve problems [72]. Later when the term “knowledgebase systems” were used, probably for the first time in 1988 by E. Feigenbaum et al. in the book “The Rise of the Expert Company,” it was done interchangeably with expert systems [73]. In later developments, Expert Systems were considered different from Knowledge-based systems in the sense that Expert Systems had knowledge of experts built into the system as a separate entity while Knowledgebase systems could acquire and infer new knowledge. While some consider Expert Systems as a type of Knowledgebase system since they are modelled on human cognitive processes and provide functions of Knowledgebase systems such as decision making [74], some others consider Knowledgebase systems as a category of the Expert Systems since knowledge and knowledge base are part of the Knowledgebase systems similar to Expert Systems [75, 76].

The evolution of the early Expert Systems to the current Knowledgebase systems occurred in different stages. The early Expert Systems that were developed in the late 1970s and the early 1980s, which include systems like MYCIN, a clinical decision support system to diagnose bacterial infection, CASNET, to diagnose glaucoma, PROSPECTOR to identify sites for drilling, and Rt that was used to configure computer systems, used the forward chaining and backward chaining techniques with symbolic logic representation to help in inferences and decision making. These systems were limited in their task because the requirements of complex tasks like planning and design could not be met with the inefficient sophistication and inflexible inferencing of these systems. The next stage of evolution that happened in the late 1980s to the late 1990s saw the commercialization of Knowledgebase systems through various applications that were developed such as predicting and forecasting for commercial planning, assigning work for railway crew members and other job scheduling applications, planning power systems and development of rail routes, finance, design and planning in manufacturing sectors, computer-aided process planning, configuring tools and managing a crisis. The development of the knowledge base in these applications lacked sophistication and so the system was neither efficient nor robust although they were helpful to a great extent. The next generation of Knowledgebase systems had more research and development in the building of the knowledge base. The knowledge base was developed as a generic component that could be attached to any system. Together with the development of a formal theory of knowledge, the methodology for the creation of the knowledge base had a more efficient and reliable knowledge acquisition, representing and inferencing technique [77]. Currently, the Knowledgebase systems have reached a certain degree of maturity to the foundation of Computational Intelligence Systems that are built on intricate theories involving engineering economics, operations research, statistical analysis, and decision theory. These systems make use of various recently evolved techniques such as Knowledge Engineering, Natural Language Processing, Machine Learning, Software Agents, Reasoning Engines and so on for the creation of the knowledge base.
