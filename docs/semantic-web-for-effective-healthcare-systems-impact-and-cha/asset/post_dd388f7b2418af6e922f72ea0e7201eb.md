The decision making process is very difficult in the field of medicine. The researcher must analyze a lot of input from the heterogeneous knowledge sources. It is also a collaborative process where the experts used to share their information about the clinical data to make the correct decision. The communication level must be semantic rather than the syntactic and also the context of the information does not affect the meaning [2].

This system gives valuable suggestions for the patient’s diet menu by considering their clinical information and also it recommending a meal plan for diabetic patients [23].

Beale and Heard developed a framework for a clinical information ontology-based model. All kind of clinical information is stored based on the ontology including the number of categories of requirements, ranging from the semantic to the performance of the software at runtime. It constantly created new specialties, different roles, public and private organizations in patients’ health recommendation system supported in critical issues. Jayaweera and Johannesson created a patient’s ontology repository for information retrieval in the field of healthcare system. ## 3.3 Architectural Design

This research work focuses on the importance of ontology based system for the patient monitoring system. The domain ontology has been constructed to preserve the details of the patient health issues. This system consists of four phases includes Domain ontology construction, Pre-processing, Rule construction, and Reasoning of Query. After the validity of the query, the most relevant result must be produced automatically. The correctness of the query must be validated with the support of reasoner. Figure 3.1 shows the conceptual diagram for Patient’s Monitoring System and explains the different phases of the system.

In the pre-processing, the system utilizes a Parts of Speech (POS) tagger, which helps to identify the search terms from the user input query. The stemming process must be applied to find the root word and the search has been established within the ontology. If the word is already stored in the ontology, the system will give the result for the query. Otherwise, the ontology has to be updated automatically with the new keyword. Then the parse tree has to be constructed to understand the query in a better way. From the pre-processed keyword, the similarity measure must be done with the words in the ontology. TF-IDF (Term Frequency—Inverse Document Frequency) method is used for weight calculation and distance measure between words.

The ontology system also supports rule which helps to infer new knowledge. In OWL (Web Ontology Language), rules are expressed with the help of SWRL (Semantic Web Rule Language) is the rule language of the semantic web. With the support of Description Logic, there is a necessitate writing SWRL rules for the given concept and the relationship with the classes. Reasoner is used to derive the information from the knowledge base with the help of the inference engine. Reasoners detect inconsistent ontologies. The entire searched keyword is checked for the correctness with the three reasoners, namely, Fact++, HermiT, and Pellet. Pellet is the best reasoner by comparing the other two reasoners because of its debugging feature. The inference engine supports to generate new rule on the search keyword. The correctness of the inference is validated by the reasoned. Finally, the information has been retrieved by SPARQL. SPARQL is the query language used to retrieve the data in the RDF (Resource Description Framework) format.

### 3.3.1 Phases of Patient Monitoring System

The ontology includes the domain classes and their relations to retrieve a new relationship among the classes. Ontology is used to extract the information from the domain knowledge, representing a relationship between classes, knowledge repository, discovering knowledge, reusing knowledge, integrating different classes based on the requirement [14].

The domain knowledge of classes is called concepts. The properties represent the different features of classes and attributes of the class is called as properties and restrictions or role restrictions are also acceptable. The Classes also classified into different kind of subclasses and super classes. For example, the gender class can be divided into male, female, and transgender subclasses.

In general, creating an ontology is an iterative process which includes defining classes, arranging the classes in a taxonomic such as subclass–superclass hierarchy, defining properties and the values for these properties, finding the values for instances. The expert’s knowledge is involved for describing the attributes of the domain object, finding their relationship between the objects and classes. The iteration may go as follows

- 1. Select the domain and Start construction the first pass of the ontology.
- 2. Find the objects, classes and its relationship to redefine the ontology.
- 3. If it is required to change the ontology based on the given circumstance then find the different alternations and reconstruct the ontology.
- 4. Refine the process if it is required.

There are always viable alternatives for the selected domain. The existing ontology must be identified before creating the new ontology. The reusability property is always supported by the ontology for any kind of domain. Few basic rules in patient ontology construction are described as follows:

## Step 1: Find and analyze the domain and objective of the ontology

The initial step is to find the domain and objective of the ontology. In this research, patient information is chosen as the core ontology. In the field of medicine, patient's details and their disease information is managed in the ontology. This ontology can be reused in the applications of medical filed. Naturally, the concepts describing different types of people information like their name, age, gender, address, type of disease, etc.

## Step 2: Find the reusable ontology

Reusability of ontology is one of the best property in any domain. It is always required to analyze the existing ontology which is created by someone in the same domain and try to reuse the ontology in the appropriate field. For example, Ontolingua ontology library or the DAML ontology library, and some popular domain ontologies like UNSPSC, RosettaNet, DMOZ, etc.

## Step 3: Identify the required classes in the ontology

It is necessary to find out all classes and its objects which are required to construct the domain ontology. The next two steps are closely knotted to each other, namely, developing the class hierarchy and defining the object and data properties of classes.

## Step 4: Define the classes and the class hierarchy

The definition of class hierarchy depends on the top-down approach, bottom-up approach, and hybrid approach. In the top-down approach, the core class is identified first, and then the iteration starts by finding the subsequent classes. A bottom-up approach is defined as the characterization of the precise concepts with levels of hierarch, finally, it will reach the merging of child classes into more specific parent class. In hybrid approach is a grouping of the top-down and bottom-up approaches. It is also necessary to check the following criteria.

- Validating the defined class hierarchy is accurate
- Checking the position of the child in a class hierarchy
- Checking the Multiple inheritance
