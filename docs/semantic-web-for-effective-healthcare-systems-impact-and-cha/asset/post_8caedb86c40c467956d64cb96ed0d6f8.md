
## 12.7 Information Retrieval of Rare Diseases Through a Web Search and Other Methods

### 12.7.1 What Is Information Retrieval (IR)?

Information retrieval is a task where the clinicians or researchers use symptoms as queries for diagnosing the disease correctly. Several features define the standard web information retrieval which consists of all the developing approaches for the rare disease domain. Lately, the IR systems have gained much importance for all the clinicians and researchers that allow them to work on the difficult rare diseases in a highly comprehensive manner. There can be both offline retrieval and Google web search ways. Offline retrieval can be achieved from a specialized collection of rare diseases [6, 25].

The main objective of IR systems is to acquaint with the challenges and characteristics of the diagnosis of rare diseases.

### 12.7.2 Listed Below Are Some of the Methods for Information Retrieval

#### 12.7.2.1 Web Search for a Diagnosis

Recently, the use of the web for retrieving information has been a very important tool for studying various rare diseases. Google Search, PubMed, and Semantic Web are the most widely used interfaces. Other highly specialized interfaces, e.g., FindZebra, Omim.org, etc. have also been used. But PubMed proves to be the major database of all the medical abstracts in the world. These search engines not just help in compiling the differential diagnosis but also provides the list of most likely rare diseases [6–25]. FindZebra is a specified search engine for rare diseases powered by open-source search technology. It uses freely available online medical data and information. The FindZebra search engine is available at http://www.findzebra.com/ [25]. It emphasizes authoritative resources and that can improve the performance for searching the required information. It is a very straightforward and open-source experimental IR system providing functionalities for rare diseases diagnosis. The limitations occur in constructing the appropriate queries based upon the descriptions of the symptoms of the disease. The collection of the queries also proves to be a very challenging task. Initiatives are being undertaken for efficient data acquisition and improving the IR system’s performance [6, 25]. The increasing number of patient registries for diseases prove to be a major challenge because of its closed data, its model, and the mechanism for sharing data. Semantic Web-based solutions have been developed to connect the different registries, integrate access, and querying. The Semantic web interconnections between registries allow us to query single or even multiple instances as required. It also helps us improvise the way we share knowledge, publish, access, and express across the web, and federate the data from various registries [26].

#### 12.7.2.2 Cause of Diagnostic Errors in Web-Based Tools

Researchers have identified insufficient knowledge as the main cause of an error in diagnosis or effective medications provided. Graber et al. classified the most common 3 errors as follows [6]:

- I. Context errors: The prospects for diagnosis are very restrictive. For example, gastrointestinal causes are not considered for chest pain symptoms.
- II. Premature closure: As soon as a probable diagnosis is identified other possibilities are no longer considered.
- III. Availability errors: A more familiar or common diagnosis is preferred.

Thus, the web-based approaches need to be developed to confront such mistakes and offer fast access to the available information [6].

#### 12.7.2.3 Nonprofessional Use of Web Tool for Diagnosis

Clinicians not only use the web but also the internet for diagnosis. 77% of online diagnoses tend to use search engines like Google, Yahoo, or Bing [6]. Others rely on health websites and places like Wikipedia or Facebook. Non-professionals nowadays are also using these tools to search results for diagnostic conclusions, which may help overcome unnecessary anxiety about the disease [6].

#### 12.7.2.4 Performance of Web Search Tools

Studies have shown that the various search tools had a great influence on the quality of results obtained. Google, PubMed, and FindZebra provided with all the necessary information like the list of most of the rare diseases along with their symptoms and known diagnosis [6]. The versions of these search engines were timely updated.

FindZebra turned out to be the highest performing with better results and mostly widely search tools followed by Google, Pubmed, and OMIM [6].

#### 12.7.2.5 Design of Watson

The purpose of Watson was to build a computer-based system that would consist of the codes and questionnaires that would help the medical professionals to diagnose the disease. The design of this model was overall simple and can be broken down into five different stages as follows [6]:

- I. Question and topic analysis: Here, language processing is carried out to identify the type of question to construct a structured search query.
- II. Hypotheses generation: The search query then generates a list of all the possible hypotheses, e.g., “The disease is beta-thalassemia.”
- III. Evidence and hypotheses scoring: For each hypothesis, different dimensions are scored as evidence (e.g., gender, symptoms, demographics), and the evidence scores are then collected together to score the hypothesis:
- IV. Ranking: The hypotheses are then together combined. A ranking list of hypotheses is created which is based on these hypothesis scores.
- V. Answer and confidence: In the last stage, a ranked list of all answers is generated and a level of each hypothesis is calculated [6].
