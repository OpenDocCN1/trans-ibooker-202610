In 1992 the Internet Engineering Task Force (IETF), which is entrusted with overseeing the required infrastructure for the development of the internet, established the URI working group to solve the issues concerning standardizing Uniform Resource Locator (URL) schemes to avoid causing congestion in servers and reproducing intercontinental traffic. The URI working group came up with a model to standardize the resource identifiers by Uniform Resource Name (URN) and Uniform Resource Characteristics (URC). After a lot of work done on the URN and URC, it was realized that the URL which is part of the URI was the only standard format achieved. So, in July 1995, the IETF disbanded the URI working group and formed the URN working group in July 1996 to work on naming schemes and resolution systems. The URC which describes languages, formats, character sets, version numbers, author names, and so on, has not developed any particular scheme so far [54–56].

URI makes use of the syntax and semantics from the notions presented by the world wide web global information initiative to provide a simple and extendible method of identifying resources. “Functional Recommendations for Internet Resource Locators” [57] and “Functional Requirements for Uniform Resource Names” [58] where the recommendation used in the design of the URI. The URI is characterized by the uniformity that allows the use of different types of resource identifiers even if the methods used to get the identifiers may be different. Moreover, there is uniformity in the use of semantic interpretation of common syntactic resolutions of varied resource identifiers and new types of identifiers might be used without disturbing the existing identifiers. The reuse of the identifiers in various contexts allows newer applications and systems to make use of the large and widely used existing identifiers. The use of the word resource does not limit itself to only for the use of existing resource in the web but rather to anything that might be identified as a resource by the URI. A resource, therefore, need not be only what is in the web but it can be anything from a real-world material like books, reports, surveys and the like or also something belonging to the abstract world like a type of relationship, a mathematical operator and so on. The identifier distinguishes one resource from the other without any emphasis on the identification method. The identifier need not represent the identified resource or the URI will access the identified resource [59].
