
Although SPARQL adopts various structures of SQL, SPARQL uses the navigation-based approach on an RDF graph unlike the joins between tables used by SQL implementation. While certain keywords like SELECT, FROM, and WHERE and arguments such as LIMIT, DISTINCT, OFFSET, ORDER BY, GROUP BY, and HAVING are adopted from the SQL and implemented with modification in SPARQL, keywords such as OPTIONAL, FILTER, and UNION are unique of SPARQL. Additionally, since SPARQL deals with graph datasets, the keyword FROM NAMED is used to identify the specific sets of triples under a common identifier. SPARQL also allows query of remote datasets using the SERVICE keyword [104].

SPARQL queries can be broadly classified into belonging to two frameworks. The centralized RDF query processing systems work on the efficiency and scalability of the SPARQL queries. While these systems greatly reduce communication overhead, they are limited to the power and memory of a single system [105, 106]. The distributed or federated RDF query processing involves combined access to decentralized knowledge bases spread among multiple clusters. The key benchmarking components of such clusters are data storage capacity, indexing capability, language support and generation of optimized queries [106]. The federated query models or the federated information systems can be of multi-database query languages, federated knowledge bases or mediator based information systems [107]. A subclassification that can be used in both the centralized and distributed query processing models is the link traversal framework that is based on the principle of linked data to dynamically discover knowledge from a distributed knowledge base. The link traversal can effectively reduce the size and cost of query searches [108].

## 10.5 Knowledge Base for CDSS

CDSS are computer systems that help in the decision making of healthcare workers and patients. Knowledgebase CDSS is a category of CDSS that has a knowledge base and interface systems. The inference engine or the reasoner is a part of the knowledge base that helps in processing the data that comes from the interface systems. CDSS has several functional advantages such as diagnostics, alarm systems, disease management, prescription, drug control, retrenchment predictions and so on. The effectiveness of the CDSS depends on the comfortable retrieval of relevant, accurate, reliable and expedient knowledge available for decision making [109, 110]. A CDSS, apart from its conceptual architecture, consist of modular tasks and responsibilities that function independently of the application environment and therefore they are designed to be portable, reusable and maintainable on its own [111].

### 10.5.1 Curation of Knowledge Base for CDSS

The process of selecting, organizing, and managing entities of a knowledge base is a complex task. The data has to be extracted from structured and unstructured sources and integrated into the existing knowledge base accurately and efficiently capable of creating visualized reports. A manual curation process has the efficiency of producing validated and timely knowledge [112], but the cost and scalability of the manually populated knowledge base make it inefficient. Collaborative curation can mitigate the shortcoming to some extent but it does not solve the problem [113].

Due to the scarcity of human resources for the manual curation process, it is estimated that it takes an average of 1 year to translate the knowledge from the source to the knowledge base [114]. The existing computational population and curation methods have scalability limitation when it comes to harnessing a huge volume of knowledge available. The computational complexity involved in the deductive process results in proportionally very small knowledge bases [115].

There are studies conducted on the application of RDF Knowledge Graphs for information retrieval from literature or more with other huge sources of clinical data like the Electronic Health Records [116].

There has been a lot of research in building a knowledge base from semi-structured and unstructured data. The traditional ontology-based information extraction tries to populate the existing knowledge base using the canonical identifiers already found in the knowledge base. Information extraction does not include new entities or relationships. The open information extraction includes new entities and relationships that are discovered in the literature. For CDSS, the categorization of information extraction as targeted and non-targeted is more relevant since, the knowledge base is meant only for clinical decision support. Therefore, the method of information retrieval from medical journal only and using only medical jargoned entities is a targeted or focused information extraction, while those that apply to all documents without any distinction is non-targeted or unfocussed [114].

### 10.5.2 Proposed Model for Curation

RDF Knowledge Graph that works as the knowledge base of a CDSS is built using knowledge extraction from medical literature. The earlier methods of knowledge extraction were rule-based and its result was found to be too noisy leading to unreliable knowledge. Moreover, the rules need to be constantly broken to get sufficient knowledge from unstructured text. Later the statistical method based on algorithms of artificial intelligence was used for a more accurate knowledge extraction, but due to a lack of cost and time efficiency, the newer rule-based techniques are preferred for knowledge extraction. The hybrid system comprising of both the rule-based and the artificial intelligence algorithms are considered better than using just either of them [117, 118].

OpenIE can be used to construct RDF Knowledge Graphs from texts [120–124] from which relevant knowledge can be queried using SPARQL for the curation of the CDSS knowledge base. The URI of the texts that have been already referred to is held in a table to avoid repetition of information extraction from the same text. The RDF Knowledge Graph that is constructed from the text is only stored temporarily until the SPARQL query results are added to the knowledge base to reduce the space complexity of the system.

In the proposed model, as shown in Algorithm 10.1, the system will query the RDF Knowledge Graph that is temporarily constructed using SPARQL with the keywords that are used in the CDSS. If any RDF triples are returned, they are added to the knowledge base of the CDSS. Otherwise, the system checks for any new document that is to be considered and which is not in the URI table of already checked documents.

**Algorithm 10.1 Curating the CDSS knowledge base using RDF knowledge graph.**

```
URI table U = {u₁, u₂, ..., uₙ}
RDF Knowledge Graph G = {V,E} where V = {v1,v2,...,vn} and E = {e1,e2,...,en}
RDF triple S = {s, p, o} (subject(s), predicate(p), object(o))
CDSS Keyword K = {k₁, k₂,...kₙ}
1 Read uᵢ (URI of a new document)
2 If uᵢ ∈ U GOTO Step 9
3 Else use OpenIE to create G
4 For every K
5 use SPARQL query to find kᵢ in G
6 For every S found
7 If S not in CDSS knowledge base
8 Append S to CDSS knowledge base
9 If another document exists GOTO Step 1
10 Else STOP
```

### 10.5.3 Evaluation Methodology

There are many measures that are used to evaluate the knowledge base. These measures are based on whether the RDF triple is relevant or irrelevant to the particular knowledge base. Accordingly, a contingency matrix of positives and negatives can be formed as shown in Table 10.1. If the RDF triple that is retrieved by the query is relevant, it is true positive; otherwise, it is a false positive. Similarly, if a relevant triple is not retrieved, then it is a false negative and if it is not relevant and not retrieved, it is a true negative. For the knowledge bases curation, measures such as precision, recall, accuracy, F-measure, G-measure, error rate, miss rate, fallout and so on could be used on the RDF triples that are retrieved from the relevant RDF triples in the document [125, 126].

Evaluation of the queried result is done also using community benchmarking campaigns such as the Text Retrieval Conference (TREC), Initiative for the Evaluation of XML Retrieval (INEX), DBpedia-Entity Test Collection and so on which makes use of text collections consisting of a dataset, a set of information needs and the corresponding relevance assessments [127].
