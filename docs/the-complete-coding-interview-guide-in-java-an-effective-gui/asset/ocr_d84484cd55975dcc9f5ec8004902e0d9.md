# What are the main restrictions in terms of working with exceptions in overriding and overloading methods?

First, let's discuss the overriding methods. *If we talk about unchecked exceptions, then we must say that there are no restrictions on using them in overriding methods.* Such methods can throw an unchecked exception, hence, any `RuntimeException`. On the other hand, *in the case of checked exceptions, the overriding methods can throw only the checked exception of the overridden method or a subclass of that checked exception.* In other words, an overriding method cannot throw a checked exception that has a broader scope than the checked exception thrown by the overridden method. For example, if the overridden method throws `SQLException`, then the overriding method can throw subclasses such as `BatchUpdateException`, but it cannot throw super classes such as `Exception`.

Second, let's discuss the overloading methods. *Such methods do not impose any kind of restrictions.* This means that we can modify the `throw` clause as required.
