DHA enables enterprises to raise the security bar of their organization to hardware monitored and attested security, with minimal or no impact on operation costs.

The DHA service integrates with MDM solutions and does the following:

+   - Combines the info DHA service that's received from devices (through existing MDM device management communication channels) with the DHA report.
+   - Makes more secure and trusted security decisions, based on attested hardware and protected data.
+   - When leveraging DHA in a compliance policy, Windows 10 must be rebooted before it gets into a compliant state in Microsoft Intune.

In the Device Health section of the Windows compliance policy, there are three settings:

Update these settings as follows:

+   - Require BitLocker: Require – The device can protect data that's stored on the drive from unauthorized access when the system is off or hibernating.
+   - Require Secure Boot to be enabled on the device: Require – The system is forced to boot to a factory trusted state. The core components that are used to boot the machine must have correct cryptographic signatures that are trusted by the organization that manufactured the device. These signatures are verified by UEFI firmware before it lets the machine start. If any files are tampered with, which breaks their signature, the system doesn't boot.
