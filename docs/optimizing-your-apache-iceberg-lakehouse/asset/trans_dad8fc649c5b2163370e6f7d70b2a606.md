在第 1 章中描述的探索环境中，创建一个模式和一个空的 Iceberg 表。

```
CREATE SCHEMA optimize_ice.ch2;
USE optimize_ice.ch2;

CREATE TABLE my_iceberg_tbl (
  id integer,
  name varchar(55),
  description varchar(255)
) WITH (type='iceberg', format='parquet');
```

使用 [示例 1-5](#ch01.html#ch02_er_example_5_1776772288055142) 中的查询来查看与新创建的 `my_iceberg_tbl` 表对应的 [`$snapshots`](https://trino.io/docs/current/connector/iceberg.html#snapshots-table) 元数据表的内容。

### 示例 1-5. 查询 `$snapshots` 元数据表。

```
SELECT
 snapshot_id, parent_id,
 substring(manifest_list,
           position('/metadata/' IN manifest_list) + 10)
  AS manifest_list
FROM
 "my_iceberg_tbl$snapshots";
```

[示例 1-5](#ch01.html#ch02_er_example_5_1776772288055142) 查询的结果显示在 [表 1-2](#ch01.html#ch02_er_table_2_1776772288049520) 中，并确定存在一个快照，与表创建操作一致。

[`$manifests`](https://trino.io/docs/current/connector/iceberg.html#manifests-and-all-manifests-tables) 元数据表提供了当前快照中使用的清单的详细概述。此元数据表有多个列，但让我们关注有助于我们了解每个清单引用的数据文件的特征的列。

运行 [示例 1-6](#ch01.html#ch02_er_example_6_1776772288055158) 中的查询，查看链接到最新清单列表的清单文件详情。结果显示在 [表 1-5](#ch01.html#ch02_er_table_5_1776772288049574) 中。

### 示例 1-6. 查询 `$manifests` 元数据表。

```
SELECT
 substring(path,
           position('/metadata/' IN path) + 10)
  AS path,
 added_snapshot_id AS add_snap,
 added_data_files_count AS add_file_cnt,
 added_rows_count AS add_row_cnt
FROM
 "my_iceberg_tbl$manifests";
```

表 1-5. 初始清单文件列表。

| `path` || `add_snap` || `add_file_cnt` || `add_row_cnt` |

| --- | --- | --- | --- |

| `76849afc...5e27-m0.avro` || `1621...6722` || `1` || `3` |

| --- | --- | --- | --- |

[表 1-5](#ch01.html#ch02_er_table_5_1776772288049574) 按列表示的以下详细信息。

*   `path` - 创建的清单文件的名称。
*   `add_snap` - 创建此特定清单文件时创建的快照标识符。请注意，它与 [表 1-4](#ch01.html#ch02_er_table_4_1776772288049558) 中的第二行中的标识符相同。
*   `add_file_cnt` - 此清单文件仅与一个数据文件相关联。
*   `add_row_cnt` - 与为给定快照插入到此表中的 3 行一致。

运行 [示例 1-7](#ch01.html#ch02_er_example_7_1776772288055174) 中的查询，查看当前快照的所有引用文件的详情。结果显示在 [表 1-6](#ch01.html#ch02_er_table_6_1776772288049592) 中。

### 示例 1-7. 查询 [`$files`](https://trino.io/docs/current/connector/iceberg.html#files-table) 元数据表。

```
SELECT
  substring(file_path,
            position('/data/' IN file_path) + 6)
    AS file_path,
  record_count as recs, 
  value_counts AS value_cnts, 
  null_value_cnts AS null_value_cnts, 
  lower_bounds, upper_bounds
FROM
  "my_iceberg_tbl$files";
```

表 1-6. 初始数据文件列表。

| `file_path` || `recs` || `value_cnts` || `null...cnts` || `lower_bounds` || `upper_bounds` |

| --- | --- | --- | --- | --- | --- |

| `20...aa.parquet` || `3` || `{ `  

` 1 = 3, `  

` 2 = 3, `  

` 3 = 3 `  

`}` || `{ `  

` 1 = 0, `  

` 2 = 0, `  

` 3 = 0 `  

`}` || `{ `  

` 1 = 101, `  

` 2 = Jessica, `  

` 3 = Consor... `  

`}` || `{ `  

` 1 = 103, `  

` 2 = Paul, `  

` 3 = Son of... `  

`}` |

| --- | --- | --- | --- | --- | --- |

[表 1-6](#ch01.html#ch02_er_table_6_1776772288049592) 按列表示的以下详细信息。

*   `file_path` - 与 [表 1-5](#ch01.html#ch02_er_table_5_1776772288049574) 中的清单文件链接的单个数据文件的名称。其余列与此特定文件相关。
*   `recs` - 标识此数据文件有三条记录，这也显示为 [表 1-5](#ch01.html#ch02_er_table_5_1776772288049574) 中的 `add_row_cnt`。
*   `value_cnts` - 每列中的值数量。每列都有三个值。
*   `null_value_cnts` - 每列中 `null` 值的数量。每列的计数均为零。
*   `lower_bounds` - 每列中的最低值。例如，第一列 `id` 的下界为 `101`。
*   `upper_bounds` - 每列中的最高值。仍以同一示例为例，`id` 列的上界为 `103`。
