### 混合方法

根据你的组织需求、场景成熟度以及数据平台战略，你可能会采用混合方法来构建你的数据湖。例如，虽然大多数组织以云数据仓库作为其中央数据存储库运行，但创新中心正在使用精选的一组场景在数据湖架构上工作，并逐步扩展到公司其他部门。或者，虽然大多数组织采用数据湖仓架构，但一些团队仍依赖需要数年时间才能迁移的传统基础设施。

你的场景的细微差别可能如此专属或特定于你的组织，以至于超出了本书的范围。然而，本章中讨论的原则将帮助你提出正确的问题并就数据湖架构做出明智的选择。

大数据生态系统和云数据湖架构是一个快速创新的领域。我相当确定在我完成本章时，指针已经在某些方面被移动了。

### 总结

在本章中，我们深入研究了云数据湖的三种关键架构，并了解了它们与传统云数据仓库架构的比较。首先，我们介绍了现代数据仓库架构，其中你在数据湖中收集和处理数据，以将原始数据相对较低价值密度的数据转换为高价值结构化数据，并将高价值数据加载到云数据仓库中以支持 BI 场景。接下来，我们在此基础上构建了数据湖仓架构，该架构可直接在数据湖上支持 BI 场景（除数据工程和数据科学场景外），从而消除了对云数据仓库的需求。然后，我们探讨了数据网格架构，该架构提供了一种分散的方法来管理和运营数据湖，使其能够可持续地扩展到组织中不断增长的需求和数据快速扩散。最后，我们将所有这些与成熟度、技能组合和组织规模等因素放在一起，以帮助你为你的组织制定正确的云数据湖架构。在第 3 章中，我们将更专注于云数据湖的“数据”部分：组织、管理和保护数据湖中数据的考虑因素，以及治理数据。

在本章中，我们将深入探讨云数据湖架构实现的细节。正如你所回忆的那样，云数据湖架构由多种 IaaS、PaaS 和 SaaS 产品组成，这些产品被组装成端到端解决方案。将这些单独的服务视为乐高积木，你的解决方案就是你用乐高积木搭建的结构。你可能会搭建堡垒、龙或宇宙飞船——选择仅受你的创造力（和业务需求）限制。然而，有一些基础你需要理解，这正是本章要探讨的内容。

### 设置云数据湖基础设施

大多数云数据湖架构属于以下两类之一：

- 你想从零开始在云上构建你的云数据湖。你没有先前的数据湖或数据仓库实现，并且从一张干净的白纸开始。
- 你想将你的数据湖从本地系统或其他云提供商迁移到云。在这种情况下，你已有现有的实现，要么是数据仓库，要么是数据湖，你将把它迁移到云。

无论哪种情况，你通往云的旅程的第一步在很大程度上保持不变。你将选择云提供商，你将选择服务，你将设置你的基础设施。云包含多种可供你选择的服务，每种都有其优势和机会，因此在迁移到云之前，首先要记住的是，在进行这一转变时，并没有银弹或规定的 12 步流程。然而，通过与许多客户合作以及我自己参与云迁移，我将客户旅程提炼为一个决策框架，该框架由以下关键步骤组成，如图 3-1 所示：

1. 确定你的目标。
2. 规划你的架构和交付成果。
3. 实现云数据湖，要么从零开始，要么通过将现有系统迁移到云。
4. 运营化和发布。

### 确定你的目标

正如我们在第 1 章中看到的，数据湖对于释放关键洞察以指导和转型业务至关重要。然而，鉴于多种可能性，确定数据将为你的组织提供的具体目标非常重要。这些目标有助于你决定为业务优先考虑何种类型的数据和处理。
