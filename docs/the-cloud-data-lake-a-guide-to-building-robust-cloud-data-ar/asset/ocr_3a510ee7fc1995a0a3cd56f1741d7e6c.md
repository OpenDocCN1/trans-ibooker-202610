# Merge-on-read tables

A pictorial representation of the transactions on the merge-on-read tables is shown in Figure 6-9. Although this is mostly similar to copy-on-write tables, as shown in Figure 6-8, the key difference here is that the source of truth is distributed.

![](bbox=[0.143, 0.172, 0.858, 0.551])

| Query type | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| Snapshot | A, B, C, D | A1, B, C, D1 | A2, B, C, D1, E, F | A2, B, C, D1, E, F |
| Incremental | A, B, C, D | A1, D1 | A2, E, F |  |
| Read optimized | A, B, C, D | A, B, C, D | A, B, C, D | A2, B, C, D1, E, F |

*Figure 6-9. Transactions on merge-on-read tables*

In the merge-on-read tables, there is a dataset in a columnar data format optimized for reads, and writes are stored in delta logs in a write-optimized format, which are then compacted into the primary dataset in a columnar format. Three types of queries are supported on these tables: a snapshot query that returns the version of the dataset as of a particular time, a delta query that returns only the data that changed, and a read-optimized query that returns the dataset from the columnar format, which offers faster performance but does not include the data that has not yet been compacted.
