## 决策框架的阶段4：运营化

当你构建和发布软件时，无论是网站、移动应用还是软件应用，主要关注点都是代码，任何需求和功能的变化都可以通过修改代码来实现。然而，在数据开发中，代码、数据或配置的变化都可能改变消费模式的行为。

将数据湖运营化涉及以下组件：

### 管理新需求或变更请求

你几乎可以肯定，数据湖上运行的用例数量会持续增长，收到新请求只是时间问题。你可以使用类似阶段1的流程来对需求进行分类和排查。

### 故障排除与调试

与软件产品一样，确保你有事件管理的流程和工作流。最佳做法是为数据平台建立类似软件系统支持的待命支持系统。你为数据平台设置的SLA、SLO和SLI对于确定客户问题的参与优先级至关重要。我还建议你跟踪各种事件及其相关根本原因，以确保你能够识别技术债务积累的领域并系统地解决它们。这些可能涉及性能调优或识别规模瓶颈等领域。第4章和第5章提供了更多关于调整云数据湖以实现规模和性能的方法的上下文和信息。

在前六章中，我讨论了设计、构建和实施云数据湖解决方案的各个方面。在本章中，我将这些知识整合在一起，向你展示在构建云数据湖解决方案时如何应用这些概念。我引入了一个四步框架：评估、定义、实施和运营化。你可以按原样使用此框架，也可以根据需要进行定制。我强烈建议你花时间评估业务和客户需求，并以此指导设计和实施。你在早期阶段所做的尽职调查可确保后续运营更顺畅。最后，每个阶段都会出现新的发现，因此请回到之前阶段的产出，并根据需要进行调整。

## 经验教训2：能力越大，责任越大——数据也不例外

数据为组织带来强大能力和多样化场景，其中一个重要方面是以负责任的方式端到端管理数据，遵守道德商业实践，并确保为客户提供公平公正的体验。

让我们看一个例子。在数据战略和云数据湖就位后，Klodars公司利用社交媒体趋势，并将其与销售和客户数据关联，以了解消费模式。它发现30至45岁的客户倾向于点击社交媒体上的活动和广告，从其网站购买雨伞和雨具。这帮助其营销部门定向开展活动，并为该年龄段的客户提供折扣和促销。虽然这对业务有帮助，但Klodars无意中优化了针对该年龄段客户的业务，可能产生边缘化老年客户的副作用。老年客户不在该网站购买的原因之一，可能是他们没有像其他人群那样活跃地使用社交媒体，结果对公司不利。从长远来看，这也会影响业务，因为一旦30至45岁市场饱和，Klodars就没有扩展的途径了。

尽管这是我为了说明负责任数据战略问题而编造的例子，但它与现实相距不远。根据《华盛顿邮报》的文章《医疗算法中的种族偏见：白人患者优于病情更重的黑人患者》，一家名为Optum的医疗服务提供商利用数据来了解哪些患者群体可以从额外医疗护理中受益。不幸的是，该公司目前正在接受调查，因为其算法涉嫌因数据集偏向于我们人口中的某一群体而损害了黑人患者的健康需求。
