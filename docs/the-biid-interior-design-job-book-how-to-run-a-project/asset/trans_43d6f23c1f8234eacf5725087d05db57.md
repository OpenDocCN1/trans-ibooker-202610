## P1 Notes on emails

### Emails

### 电子邮件

电子邮件的使用如今如此普遍，以至于已几乎成为书面沟通的默认方式。它们具有即时性的优势，但危险也就潜伏于此。此类沟通存在未能像应有的那样经过仔细考虑的风险，须牢记它们属于专业服务的一部分。

与信函一样，电子邮件不仅应传递其信息，还应作为未来参考的自解释记录，可能是在很久以后，由不熟悉该项目的人查阅。

因此，将其按信函格式编排非常有用，应完整包含发件人和收件人的姓名及地址、项目文件编号、主题等。信函正文应使用完整句子书写，并检查拼写。任何附件都应在电子邮件底部按名称列出，因为附件在电子邮件被复制或转发时常会丢失。

设计师应抵制在起草电子邮件后立即点击‘发送’按钮的冲动，并应像对待信函一样给予其同样周到的考虑。

### Form of address

### 称呼形式

普遍认为，无论对象是谁，通信中都应保持正式（也许客户除外，如果设计师与其关系友好的话）。在通信中以名字称呼非专业人士，例如供应商、承包商、制造商，可能表明设计师与这些人的关系并非完全保持适当距离，因此应避免。

## P1 Notes on discussion record

## P1 关于讨论记录的说明

### Discussion record

### 讨论记录

所有非正式会议和电话交谈的相关细节均应在发生时仔细记录在讨论记录（有时称为“出席记录”）中，并归入项目文件。与信函一样，记录不应晦涩难懂，而应使将来任何第三方阅读时都能理解。涉及多位参与者的正式会议最好制作会议纪要（参见“k 会议纪要范例”，第 213 页）。

编写此类记录的主要原因是提醒设计师（及其员工）关注与工作相关的关键讨论，同时也作为影响设计师工作的事项记录。它还可作为需采取行动的提醒。

> 当设计师因疏忽被起诉时，撰写讨论记录通常已为时过晚。

### Use

### 用途

讨论记录是书面证据，可在客户就合同条款产生争议时使用，并在后来解释设计师的表现时发挥重要作用。事后很久才根据设计师记忆撰写的讨论记录，应在记录上注明此情况，但作为证据不够理想。

### Client’s instructions

### 客户指示

讨论中客户给出的指示应立即通过客户指示予以确认（参见“d 客户指示范例”，第 140 页）。同样，设计师向承包商发出的口头指示也应立即通过设计师指示予以确认（参见“k 设计师指示范例”，第 215 页）。

## P1 Notes on document issue

## P1 关于文件发放的说明

### Document issue

### 文件发放

所有对外发放的文件都应随附文件发放单，以便收件人确认已收到所有发送的文件，并作为项目文件的记录。发送的文件副本也应归入文件。

设计师们常认为草稿文件的副本无需归档，待完成后再行归档。这是一个错误，因为在日后可能需要确定文件在发放时的状态。

如有需要，可向文件发放单添加额外页面。

## P1 Notes on print register

## P1 关于打印登记簿的说明

### Print register

### 打印登记簿

图纸打印通常构成向客户收取的可报销费用的大部分，因此将项目中的所有打印工作（无论是内部打印还是由服务局制作）汇总到打印登记簿中非常有用，以便在向客户开票时轻松查阅。

大多数设计师按与当前服务局费率相当的费率收取内部打印费用。对于大型事务所，这有时可以证明租赁或购买专用打印机是合理的。

## P1 Notes on time sheets

## P1 关于工时表的说明

### Time sheets

### 工时表

所有参与项目工作的事务所成员（包括董事/合伙人）都应保存工时表。它们可作为向客户收费的基础、用于利润分析、作为计算未来类似项目收费建议的基础，以及作为员工薪酬的基础。

时间应精确至最近的半小时，并记录该时间内执行的任务。Microsoft Excel 可提供一种便捷的方法，并可使用“审阅”功能将任务作为注释显示在任何单元格中。

重要的是，这些表格应及时填写（至少每天一次），如 Munkenbeck v Harold 案所言（参见“适用判例法”，第 276 页）。裁决者和法院不愿意接受作为证据的工时表，如果它们看起来是事后重建的，并且没有安排每天执行的任务。

按时间计费的项目工时每月汇总一次，乘以相关每小时费率，并计入下一张客户发票。
