404 错误通常意味着你的 Django 代码是正确的，但被请求的对象不存在。500 错误通常意味着你编写的代码中存在错误，例如 `views.py` 中的函数错误。Django 目前在两种情况下都返回相同的通用错误页面，但我们可以编写自己的 404 和 500 错误页面模板，使其与 Learning Log 的整体外观相匹配。这些模板应放在根模板目录中。

## 创建自定义模板

在 `learning_log` 文件夹中，创建一个名为 `templates` 的新文件夹。然后创建一个名为 `404.html` 的新文件；该文件的路径应为 `learning_log/templates/404.html`。以下是此文件的代码：

**404.html**

```
{% extends "learning_logs/base.html" %}

{% block page_header %}
  <h2>The item you requested is not available. (404)</h2>
{% endblock page_header %}
```

此简单模板提供了通用的 404 错误页面信息，但样式与网站其余部分相匹配。

使用以下代码再创建一个名为 `500.html` 的文件：

**500.html**

```
{% extends "learning_logs/base.html" %}

{% block page_header %}
  <h2>There has been an internal error. (500)</h2>
{% endblock page_header %}
```

这些新文件需要对 `settings.py` 进行轻微更改。

**settings.py**

```
--snip--
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        --snip--
    },
]
--snip--
```

此更改告诉 Django 在根模板目录中查找错误页面模板以及任何其他与特定应用无关的模板。

## 持续开发

你可能希望在初始推送到生产服务器后继续开发 Learning Log，或者你可能希望开发自己的项目进行部署。在这样做时，更新项目的过程相当一致。

首先，你将对本地项目进行必要的更改。如果你的更改导致任何新文件，请使用命令 `git add .` 将这些文件添加到 Git 仓库中（确保在命令末尾包含点）。任何需要数据库迁移的更改都需要此命令，因为每次迁移都会生成一个新的迁移文件。

其次，使用 `git commit -am "commit message"` 将更改提交到你的仓库。然后使用命令 `platform push` 将你的更改推送到 Platform.sh。访问你的生产项目并确保你期望看到的更改已生效。

在此过程中很容易犯错，所以当出现问题时不要感到惊讶。如果代码无法工作，请回顾你所做的工作并尝试找出错误。如果找不到错误或无法弄清楚如何撤销它，请参考附录 C 中寻求帮助的建议。不要害羞地寻求帮助：每个人都是通过提出你可能提出相同的问题来学习构建项目的，所以有人会很乐意帮助你。解决出现的每个问题都有助于你稳步提高技能，直到你能够构建有意义、可靠的项目并回答其他人的问题。

## A 安装和故障排除

![](img/8f15563c16d2a98c4d3115150679b092_740_0.png)

有许多版本的 Python 可用，并且在每个操作系统上设置它的方法也各不相同。如果第 1 章中的方法不起作用，或者如果你想安装与当前安装的版本不同的 Python 版本，本附录中的说明可以帮助你。

### Windows 上的 Python

第 1 章中的说明向你展示了如何使用 https://python.org 上的官方安装程序安装 Python。如果使用安装程序后无法运行 Python，本节中的故障排除说明应该可以帮助你让 Python 运行起来。

#### 使用 py 而不是 python

如果你运行了最近的 Python 安装程序，然后在终端中发出 **python** 命令，你应该会看到终端会话的 Python 提示符（>>>）。当 Windows 不识别 python 命令时，它要么会打开 Microsoft Store，因为它认为 Python 未安装，要么你会收到诸如“未找到 Python”之类的消息。如果 Microsoft Store 打开，请关闭它；使用 https://python.org 上的官方 Python 安装程序比微软维护的安装程序更好。

最简单的解决方案，无需对系统进行任何更改，是尝试 **py** 命令。这是一个 Windows 实用程序，可找到系统上安装的最新版本的 Python 并运行该解释器。如果此命令有效并且你想使用它，只需在本书中看到 **python** 或 **python3** 命令的地方使用 **py** 即可。

#### 重新运行安装程序

python 不起作用的最常见原因是人们在运行安装程序时忘记选择将 Python 添加到 PATH 选项；这是一个很容易犯的错误。PATH 变量是一个系统设置，告诉 Python 在哪里查找常用程序。在这种情况下，Windows 不知道如何找到 Python 解释器。

在这种情况下最简单的修复方法是再次运行安装程序。如果 https://python.org 上有更新的安装程序可用，请下载新的安装程序并运行它，确保选中 **Add Python to PATH** 复选框。
