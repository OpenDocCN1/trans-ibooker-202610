The process of mapping parts of the service’s internal data/object model into the interface’s external object model usually takes a mix of algorithmic application and creative designs needs to implement two key runtime support elements. First, the service API needs to be able to discover which formats the client prefers, and 2) the service API needs to use that information render internal data in the preferred format.

HTTP defines the `Accept` header to allow clients to include their format preferences when the send a request. When the service API sees an `Accept` header, it needs parse the value of that header and make a proper selection. You can review of the HTTP specification on `Accept` header for details on how to interpret its contents.

A simple exchange might look like this:

```
    *** REQUEST
    GET /todo/list HTTP/1.1
```
