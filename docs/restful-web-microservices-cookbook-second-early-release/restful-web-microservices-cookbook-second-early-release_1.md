欢迎来到“RESTful Web 微服务”的世界。

这是一个颇有深意的名号——值得解释和探究。这正是我们在本前言中要做的事。我现在要告诉您，我打算稍微*打破常规*，在本书的前部内容中放入大量相关的文字（前部内容就是这些使用罗马数字页码的页面）。细节我会留到下一节（[RESTful Web 微服务简介](#)）再讲。那么，在深入细节之前，我们先处理一些准备工作。

## 关于本书

本书的目标是让软件设计人员、架构师、开发人员和维护人员能够构建利用 Web 优势的微服务，同时降低创建可靠的高层服务的成本和风险，这些服务依赖其他只能通过网络访问的 API 和服务。

为此，我汇集了 70 多个食谱和模式，这些内容是我几十年来帮助客户在开放网络上设计、构建和部署成功的业务服务时学习和使用的。我猜想读者至少会对其中一些食谱感到熟悉——可能名字不同或以不同形式出现。我也希望读者能从中找到针对类似问题的新颖方法。

> **注意**
>
> 多年来，我发现软件设计的挑战很少改变。这些问题的*解决方案*则经常因技术进步和潮流趋势而变化。本书将聚焦于这些挑战，而把最新的技术和潮流选择留给读者。

由于这是一本模式书，这里不会有太多可运行代码。不过，会有大量图表、代码片段和网络消息示例，并附有说明来指出问题所在。这些挑战和讨论始终与技术及平台无关。无论您是打算在自有数据中心构建基于 SOAP 的服务，还是在云端运行事件驱动服务，这里的食谱都会以能够将其转化为适用于目标环境的代码和组件的方式呈现。

## 谁应该阅读本书

本书的主要读者是负责规划、架构和实现微服务的人员。对一些人来说，这意味着专注于创建企业级的服务提供者和消费者。对另一些人来说，这意味着构建能够存在于开放网络上，并以可扩展且可靠的方式为全球消费者运行的服务。

无论您是在自己的硬件上本地托管解决方案，还是创建将在云端运行的软件，这里的食谱都能帮助您理解挑战，并提供一套技术来预判问题并内建恢复机制，以应对意外情况的发生。

## 内容概览

这一章对架构师和服务设计者尤其有帮助，也为后续各种食谱奠定了基调。

# 第 3 章：超媒体客户端模式

下一章将重点讨论创建服务/API 消费端应用程序时面临的挑战。我特别指出要先讨论客户端应用，*再*谈微服务本身的食谱。任何打算创建一个稳定可靠、既能在 Web 上也能在企业内部运行的开放服务平台的程序，都需要一套通用的方法来创建灵活且有弹性的服务消费者。

# 第 4 章：超媒体服务模式

有了扎实的设计原则基础和架构合理的客户端应用，就可以更轻松地构建和发布稳定的服务提供者，并随着时间的推移安全更新，而不会破坏现有的服务/API 消费者。这一组食谱不仅关注可靠服务设计的原则，还着眼于支持运行时错误恢复和可靠性模式的重要性，以确保即使系统某些部分发生故障，您的服务也能保持正常运行。

# 第 5 章：分布式数据模式

本章重点讨论在在线分布式环境中支持持久化数据所面临的挑战。这里的大多数食谱旨在通过确保数据完整性来提高数据服务的响应性、可扩展性和可靠性——即使在运行时更改内部数据模型和实现也是如此。

# 第 6 章：运行时注册表模式

注册表这一章介绍了在支持实时发现和使用依赖服务时需要应对的一系列挑战。当今大多数解决方案都依赖在设计时和构建时解析依赖关系，但 Web 上的 RESTful 微服务还需要支持运行时服务解析——尤其是在主依赖失败而需要改用实时备用服务的情况下。

# 第 7 章：超媒体工作流模式

最后一组食谱重点讨论在 Web 上创建和管理服务工作流。开放服务工作流面临的关键挑战是创建一套安全可靠的解决方案，将多个互不相关的服务整合到一个弹性的工作流中，以解决单个服务都不知道的问题。我把这一章放在最后，因为它依赖于本书前面介绍的许多食谱。

# 第 8 章：结束语

最后一章是对全书内容的简短总结，也是一种“前向指引”，帮助您在将这些食谱应用到自己的环境时确定自己的“下一步”。

### HTTP 协议

本书中的大多数配方都是为 HTTP 协议实现而开发的。有关 HTTP 的强大功能和挑战的更多信息，我推荐 Chris Shiflett 的《HTTP Developer’s Handbook》（2003）¹。Shiflett 的文本在帮助我学习 HTTP 协议的内部细节方面非常有帮助。出版于 2003 年，它仍然是一本宝贵的书籍，我强烈推荐。

### API 设计

有关为分布式服务*设计* API 的详细信息，我建议读者查看我的《Building Hypermedia APIs with HTML5 and Node》（2011）²。对于那些寻找专注于编码 API 的书籍的人，我较新的书籍《Design and Build Great Web APIs》（2020）³提供了对完整 API 生命周期详细的手把手指南。

### API 客户端

编码 API/服务客户端的工作本身就是一项技能。有关创建灵活的超媒体驱动客户端应用程序过程的深入了解，我将读者引向我的《RESTful Web Clients》（2017）⁴。

### 微服务

有关微服务本身的详细信息，我强烈推荐 Sam Newman 的《Building Microservices, 2nd Edition》（2021）⁵。我也鼓励读者查看我与 Leonard Richardson 合著的书籍《RESTful Web APIs》（2013）⁶。

## 关于这些配方

本书的大部分内容是一套 70 多个配方，用于识别和解决你在为网络构建开放、可发现、可扩展的微服务组合时将面临的常见挑战。配方按主题分组（设计、客户端、服务器、数据、注册表和工作流），并且每个章节中的每个配方都遵循相同的一般模式：

### 问题

这是你在设计和构建服务时可能遇到的问题的简短描述。

### 解决方案

本节是对可用于解决所述问题的建议解决方案（或解决方案）的叙述。

### 图表

许多配方都附有一张或多张图表来说明解决方案。这可能是要涵盖的一系列步骤、用于对实施解决方案做出决策的逻辑图，甚至是显示如何构建解决方案的运行时状态图。

### 示例

在某些情况下，配方将包含一个示例。这可能是 HTTP 消息交换（请求/响应）甚至是伪代码的简短片段，以显示与解决方案相关的内部工作流。

### 讨论

配方还将包含更长的讨论部分，其中涵盖权衡、缺点和优点。通常这是配方中最重要的部分，因为很少有这些挑战只有一个可能的解决方案。

### 相关配方

许多配方将以一个或多个在本书其他地方介绍的其他相关配方的列表结束。一些配方依赖于其他配方或使其他配方成为可能，这就是你将了解配方如何在实际运行系统中相互作用的地方。
