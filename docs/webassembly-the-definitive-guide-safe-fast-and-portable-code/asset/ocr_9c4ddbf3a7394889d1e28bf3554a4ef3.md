Both deployment strategies have their pros and cons. The Blazor Server model does not burden the client with downloading a large binary runtime, but does have the issue of latency in the interactions between the backend and frontend user interface components. That could potentially be problematic on slow and flaky networks or distantly-remote clients. The Blazor WebAssembly model does not generally have the access to the complete .NET platform in order to make the runtime download a manageable size. Debugging is also an issue with the Blazor WebAssembly for the time being but that should clearly be an issue Microsoft should be able to address given their attitude toward giving developers good tools.
