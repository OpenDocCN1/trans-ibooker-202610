Here, we created a **msgs** variable and then created the first thread, which pushes value to the **msgs**. Then, we created the second thread, which pops values from the array and detaches them. Even if we protect all the functions by using a locking mechanism, one of the threads can check the array's size and can be interrupted by the OS. At this time, another thread can change the array. When the first thread continues its work, it can try to push to the full array or pop from the empty array. So, synchronization is only effective in a pair with a good design.

# Deadlock

There is one more synchronization issue. Let's go back to the philosophers' dinner example. The original issue was that one philosopher has only one chopstick. So, they can eat their sushi one by one by sharing chopsticks with each other. Although it will take a long time for them to finish their sushi, all of them will be well-fed. But if each of them grabs a chopstick at the same time and doesn't want to share the second chopstick, they won't be able to eat their sushi as each of them will be waiting for the second chopstick forever.
