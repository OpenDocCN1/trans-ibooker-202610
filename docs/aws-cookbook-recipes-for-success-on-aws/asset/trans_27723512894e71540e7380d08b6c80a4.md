### 注意

根据 [Textract 开发者指南](https://oreil.ly/Xh9Bk)，每个 `BoundingBox` 属性的值在 0 和 1 之间。该值是相对于整体图像宽度（适用于 `left` 和 `width`）或高度（适用于 `height` 和 `top`）的比率。例如，如果输入图像为 700 × 200 像素，边界框的左上角坐标为 (350,50) 像素，则 API 返回 `left` 值为 0.5 (350/700)，`top` 值为 0.25 (50/200)。

## 讨论

您过去可能曾使用传统的光学字符识别 (OCR) 软件，在扫描纸质文档时利用 OCR 输出获取基于文本的内容输出。[Amazon Textract](https://aws.amazon.com/textract) 利用机器学习模型更进一步，实现了更准确的文本识别，并提供了可用于应用程序的额外特征和上下文信息。通过使用本配方，您能够确定图像中文本字符串的位置。您可以在 Textract 中使用类似功能，将图像（或扫描表单）中的特定文本部分转发给不同团队进行人工审核，或自动将表单的特定部分发送给应用程序中的不同微服务进行处理或持久化。应用程序开发人员在使用 Textract 之前无需训练模型；Textract 预先使用许多数据集进行了训练，可提供 [高度准确](https://oreil.ly/X07aq) 的字符识别。

### 挑战

确定图像中两个不同单词的位置，并计算它们之间的距离。

# 第 9 章 账户管理

## 9.0 简介

虽然前几章侧重于在 AWS 账户 *内部* 部署和配置资源，但我们想提供一些配方，展示在整个账户层面可以做什么。

随着您继续扩大 AWS 使用规模，您会发现拥有可用的工具和服务来减轻管理负担非常有用，尤其是当您开始向环境中添加额外的 AWS 账户时。我们看到越来越多的人选择使用 AWS 账户作为其特定应用程序的“容器”。一些公司为公司内部的业务单元提供生产和非生产工作负载的单独账户；一些甚至设置“共享服务”账户，为公司内部的业务单元提供内部服务，以跨其可能管理的许多账户共享通用资源。您的 AWS 账户 [跨区域](https://oreil.ly/INVpe)，可为您提供全球能力，如 [图 9-1](#ch09.html#aws_account_perspective) 所示。

![](assets/awsc_0901.png)

我们喜欢将 AWS 提供的工具和服务视为构建块，您可以使用它们自定义云环境以满足特定需求。其中一些可在账户层面使用，随着您扩展规模（即添加额外团队成员或额外 AWS 账户），它们能为您提供对环境的更多管理能力。您可以通过使用 [AWS Organizations](https://aws.amazon.com/organizations) 组织和合并多个账户的账单，并通过 [AWS Single Sign-On](https://aws.amazon.com/single-sign-on) 提供集中式访问管理，这两者您都将在本章的配方中探索，此外还有一些配方可帮助您在账户层面配置和维护安全环境。

### 提示

## 9.1 使用 EC2 全局视图进行账户资源分析

### 问题

您获得了一个客户的 AWS 账户。您需要导出一个 CSV 文件，其中包含 AWS 账户跨所有区域内所有已预置的计算实例、磁盘卷和网络资源。

### 解决方案

在 AWS 控制台中导航至 EC2 全局视图。导出账户中资源的 CSV 文件（请参阅 [图 9-2](#ch09.html#generating_a_csv_of_resources_with_ectw)）。

![](assets/awsc_0902.png)

#### 先决条件

*   已部署资源的 AWS 账户

#### 步骤

1.  在 AWS 控制台中搜索并单击 EC2 全局视图，如 [图 9-3](#ch09.html#searching_for_global_view) 所示。

    ![](assets/awsc_0903.png)

2.  导航至“全局搜索”菜单并单击“下载 CSV”（请参阅 [图 9-4](#ch09.html#downloading_a_csv_from_global_view)）。

    ![](assets/awsc_0904.png)

##### 验证检查

在工作站上使用您喜欢的编辑器打开下载的 CSV 文件。从那里，您应该能够浏览 AWS 账户中的资源。

### 讨论

作为工作的一部分，您可能经常需要在新的 AWS 账户中工作。如果您处于实验室环境或黑客马拉松中，使用全局视图是了解 AWS 账户包含内容的好方法。在开始对账户进行更改之前，了解跨所有区域已部署的内容非常重要。掌握这些知识将使您能够确保不会错误地导致任何中断。

虽然您应该使用 [AWS Config](https://aws.amazon.com/config) 等工具和 AWS 账单控制台分别检查 AWS 账户中资源的配置并关注账单，但了解您可以轻松生成 EC2 和 VPC 资源列表也是很好的。在不同时间进行常规 CSV 导出可用于提供某个时间点的快照。

#### 挑战

使用全局搜索功能列出所有默认 VPC 安全组。然后您可以仔细检查入站规则中多余的权限。

## 9.2 使用标签编辑器一次性修改多个资源的标签

### 问题

您需要向 AWS 账户中尚不存在该标签的多个资源添加标签。

### 解决方案

在 AWS 控制台中启动标签编辑器。查找所有具有 `Environment` 键但值不存在的资源。添加标签（请参阅 [图 9-5](#ch09.html#adding_a_tag_to_multiple_resources)）。

![](assets/awsc_0905.png)

#### 先决条件

*   已部署并打标签的资源的 AWS 账户

#### 步骤

1.  在 AWS 控制台中搜索标签编辑器，然后单击“资源组和标签编辑器”，如 [图 9-6](#ch09.html#searching_for_tag_editor_in_the_aws_con) 所示。

    ![](assets/awsc_0906.png)

2.  在左侧菜单中，在“标记”标题下单击“标签编辑器”（请参阅 [图 9-7](#ch09.html#launching_tag_editor-id0000013)）。

    ![](assets/awsc_0907.png)

3.  将“资源类型”设置为“所有支持的资源类型”，输入标签键 `Environment`，使用下拉菜单为值选择“（未标记）”，然后单击“搜索资源”（请参阅 [图 9-8](#ch09.html#launching_tag_editor-id0000039)）。

    ![](assets/awsc_0908.png)

4.  等待片刻让搜索完成。然后查看结果，选择您想要打标签的资源，并单击“管理所选资源的标签”（请参阅 [图 9-9](#ch09.html#viewing_search_results_in_tag_editor)）。

    ![](assets/awsc_0909.png)
