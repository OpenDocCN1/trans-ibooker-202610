## Part I. Preparing Data

分析平台，尤其是像 Microsoft Fabric 这样全面的平台，如果没有可靠、一致的数据流，根本毫无用处。将数据导入系统不仅仅是必要的第一步；这是一个关键流程，需要你了解各种源连接、摄取方法和最佳存储位置。在一个为端到端分析而设计的平台中，数据可能来自无数系统，你需要熟练使用各种工具，从 Power BI 中的简单连接到像数据流这样复杂的摄取功能。此外，借助强大的专用存储服务，如湖屋、仓库和事件中心，你需要选择合适的位置存放数据，以最大化性能并管理你的分析工作负载。

在本部分中，我们将探讨你如何掌握所有这些任务，以在 Fabric 中构建坚实的数据基础。

我们首先引导你了解进入 Fabric 门户的主要入口，在那里你将管理和创建新的数据连接。接下来，我们介绍使用熟悉的 Power BI Desktop 应用程序和 Fabric 门户 Web 体验创建这些新连接的实际操作过程。之后，我们介绍发现和监控资产的两个主要途径：OneLake 目录和实时中心，它们提供了数据资产的高层视图。然后，我们介绍核心的 OneLake 服务，即几乎所有数据的统一存储层，展示如何使用、共享和重用来自此集中位置的数据。最后，我们深入探讨三种主要存储服务——湖屋、仓库和事件中心之间的差异，帮助你为数据选择正确的位置，并以展示如何设置 OneLake 与事件中心之间的集成作为结尾。

在此基础上，我们从摄取过渡到数据准备。因为原始数据通常包含重复项、缺失值或不一致的格式，我们将探讨在 Fabric 中直接清理、丰富和转换数据的各种技术。我们首先展示如何使用视图、函数和存储过程创建可重用逻辑，从而在数据到达 Power BI 之前就定义转换。我们还介绍连接、聚合和筛选等基本操作，并提供将数据组织成星型模式的指导，这是一种标准建模模式，旨在实现快速、直观的分析和报告。

在这一旅程的最后部分，我们超越准备工作，专注于查询和分析你构建的数据。我们介绍可视化查询编辑器，这是一款基于 Web 的工具，可让你使用可视化界面更改和分析数据结构。对于更喜欢基于代码的方法的人，我们深入 Fabric 的 Transact-SQL（T-SQL）世界，利用众所周知的 SQL 语言进行深度分析。最后，我们介绍 Real-Time Intelligence 中使用的 KQL 语言，为你提供在 Fabric 环境中查询和可视化流数据的技能。
