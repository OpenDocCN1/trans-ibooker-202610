Both methods are suitable for creating a star schema; they use different approaches to achieve the same goal of organizing and transforming your data. Regardless of the approach you choose, you will need to create a fact table (e.g., Sales) and dimension tables (e.g., Customer, Product, Date, and Store).

Each dimension should have a unique key, known as the primary key, and the fact table should store foreign keys that reference those dimensions. In Figure 3-36, you can see a fact table in a lakehouse.
