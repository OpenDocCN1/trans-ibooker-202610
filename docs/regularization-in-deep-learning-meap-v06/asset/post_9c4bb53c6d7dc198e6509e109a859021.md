Figure 6.15 Illustrating the hard parameter sharing scheme for three tasks. The architecture starts with a common set of shared layers used by all tasks for common representation learning, then branches into three separate sequences of layers for task-specific learning. When all learning tasks are related to each other, such architecture offers better generalization performance (with fewer parameters and thus lower risk of overfitting) as well as higher learning efficiency (again, with fewer learnable parameters compared with three separate networks). Note that the individual task-specific losses could be combined directly via using a weighting scheme following some prior preference or using an adaptive approach.

On the other hand, the soft parameter sharing scheme adds a soft constraint to encourage a similar representation among related weights of all learning tasks, instead of enforcing them to adopt the exact same value. The constraint often takes the form of a distance-based penalty measure among the model weights, such as the l1 norm as in the Lasso penalty and l2 norm as in the ridge penalty. Regularizing the distance among the weights of the model encourages these weights to be similar in value. This scheme thus offers more flexibility for the architectural design each learning task as it only loosely couples the shared feature representations. See figure 6.16 for an illustration, where the soft constraints, as indicated by the double arrows, are applied to encourage a similar representation among the corresponding features.

![](img/ee98e91e6845f41077b163bec833ee40_206_0.png)

Figure 6.16 Illustrating the soft parameter sharing scheme for three tasks. The architecture consists of three dedicated sequences of network for each task respectively. The same input data is fed into the network three times as in the case of single task learning. However, the network applies a soft constraint (i.e., lasso or ridge penalty as indicated by the double arrows in between sequences) on the parameters of certain hidden layers so as to encourage a similar representation when jointly learning all three tasks.

The hard parameter sharing scheme is intuitive to implement as we only need to modify the model's architecture as a tree structure, consisting of a trunk and a few branches. The soft parameter sharing, however, requires modifying the loss function to overlay the soft constraints. Let us look at how this could be achieved.

### 6.3.2 Modifying the loss function to achieve soft parameter sharing

Assume that we have three learning tasks: A, B, and C. Denote the $i^{th}$ layer's weights of task $j$ by $W_i^{(j)}$, where $j \in \{A,B,C\}$. One way to impose the soft constraint on the similarities among corresponding weights is to augment the cost function with an additional term: the sum of squared Frobenius norm (also called the Euclidean norm) across all shared layers. The balance factor \(\lambda_i\) for the \(i^{th}\) layer could be set the same across all shared layers, and \(||\cdot||_F^2\) denotes the squared Frobenius norm.

![](img/ee98e91e6845f41077b163bec833ee40_207_0.png)

Figure 6.17 Modifying the cost function to achieve soft parameter sharing, where we add the layer-wise sum of squared Frobenius norm across all shared layers to the mean squared error to obtain the final cost. Note that the balancing factor could be set to the same value across all shared layers.

Note that this approach of augmenting the cost function by regularizing the consistency of corresponding positional weights is also considered as regularization via the objective function, a topic to be entertained in the next chapter. Indeed, many regularization techniques fall into more than one category, and the boundary will only become less clear as more exciting approaches get proposed. Among the many regularization techniques that promote the model’s generalization performance, we intend to cover the most popular and methodologically interesting ones.

One interesting approach is called cross-stitch networks, originally proposed by Misra et al. in their 2016 paper named “Cross-stitch Networks for Multi-task Learning”, where the so-called cross-stitch units are used to allow the model to automatically learn and determine how task-specific networks leverage the knowledge from other auxiliary tasks. As shown in figure 6.18, a cross-stitch unit is linear combination of the outputs from the previous layer, which can be a pooling layer or a fully-connected layer. By learning the extent of linear combinations across all shared layers, the cross-stitch network is able to automatically identify the layer-specific sharing scheme and determine the sharing of representations across all the tasks.

![](img/ee98e91e6845f41077b163bec833ee40_208_0.png)

Figure 6.18 Illustrating the cross-stitch network, where the orange boxes represent cross-stitch units that linearly transform the outputs from the previous layers. By treating the level of linear transformation as a learnable parameter, the network is able to automatically determine the optimal sharing of representations across all shared layers.

### 6.3.3 MTL in action

In order to perform learning over multiple tasks, we will use the Standard cars dataset, which consists of 16,185 images of 196 classes of cars along with the corresponding metadata such as the make, model, and year. These multiple categories of labels allow us to apply an MTL model for joint estimation.

Before we dive into the specifics, it is important to understand the differences between MTL and the typical binary-class classification, as well as multi-class classification. Binary-class classification is the simplest case, where we aim at predicting one of the two possible outcomes in a single task, i.e., predicting whether it is a red car or not. Multi-class classification involves a single target variable, still a single task, that assumes more than two possible values, such as the brand of the car. Multi-task learning could be a combination of the two, where the goal is to predict both the color (red or not) and the brand (BMW, Audi, Mercedes, etc.) of a car at the same time. We can also rename MTL as multi-label multi-class classification, since it involves predicting more than one label, each consisting of two or more possible values. def getting_metadata(url, filename):
    labels = urllib2.urlopen(url)
    file = open(filename, 'wb')
    file.write(labels.read())
    file.close()
    print("Metadata downloaded and saved.")
