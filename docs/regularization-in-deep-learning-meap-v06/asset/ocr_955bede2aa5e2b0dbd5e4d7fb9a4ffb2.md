After taking out (xy)test, the rest of (xy) is further often split into a training set (xy)train and a validation set (xy)val. (xy)train is the only part of the original (xy) used for model training and parameter estimation. The model goes through an optimization process to fit the given training set (xy)train as much as possible. Since a typical machine learning model involves some hyper-parameters which are manually pre-defined, the effect of different configurations of hyper-parameters are assessed by (xy)val. (xy)val is another proxy for a future unseen test set, similar to (xy)test; the difference is that (xy)val is used for hyper-parameter tuning as part of the overall model training process, while (xy)test is only used for assessing generalization capability of the trained model and not used for model training. In some cases, (xy)val is treated as part of (xy)train, so the whole dataset is split into two subsets: (xy)train for model training and (xy)test for model assessment.

Obviously, there is a potential risk of selection bias in choosing (xy)train, (xy)val and (xy)test; we may just happen to be lucky in choosing a (xy)train and produce a model that generalizes well to both (xy)val and (xy)test. The risk in choosing (xy)train and (xy)val is addressed by cross validation, a technique that systematically repeats the split multiple times. To reduce such risk, nested cross validation could be employed.

Splitting the original dataset into (xy)train, (xy)val, and (xy)test is performed at the beginning of a model training workflow. Depending on the size of the dataset, the split ratio could be 6:2:2 for a small dataset and 8:1:1 for a large dataset.

Figure 2.4 illustrates splitting the same dataset into three mutually exclusive and collectively exhaustive subsets commonly practiced as a rule of thumb: training set, validation set, and test set. Since each subset serves a different purpose, it is essential to repeat the randomized split multiple times to avoid selection bias. When the test set is used for model selection, i.e. identifying the optimal model that has the lowest error in the test set, the test set performance is considered to be the best proxy for the true performance on future unseen data. Note that a strict assessment (as in many modeling competitions) would require a single, sufficient and representative test set, which avoids exposing the test set for model training, i.e., data leakage.
