
## 4.3.4 Define the optimization procedure

To update the model parameters, we can utilize the optimizers provided by PyTorch, including SGD and its variants. Using the default optimizers makes it easy to scale the optimization to even millions of parameters. A typical optimizer such as SGD includes two input arguments: the model parameters to be updated and the learning rate to use. Once an optimizer is instantiated, we can invoke its step() method to update the weights after back-propagating the cost and calculating the gradients using the backward() method.

Recall that the optimization procedure is an iterative process. The prediction function generates an output based on the current weights in each iteration. The cost function then takes the prediction and the target label to calculate a cost. The optimization step derives the gradient of the cost for each weight and updates all the weights using the gradient descent type of algorithm. This process repeats until convergence, i.e., the weights or cost remain largely the same and do not change much as the training iteration proceeds.

The following code snippet defines the optimization procedure by instantiating an optimizer using SGD, which will be used to support the iterative updates of model weights.

```
from torch import optim
optimizer = optim.SGD(model.parameters(), lr = 0.01)
```

## 4.3.5 Update the weights via iterative training

We can now put together the above components into one entire training loop. Based on the predefined model and data loader, the following code listing defines the training function that performs SGD optimization via one complete pass through the training dataset. We also track the cost evolution as the weights get updated across different training batches, and this process is then repeated based on the specified number of epochs.

### Listing 4.9 Define the training function

```
def train(model, loaders, verbose=True):
    model.train()#A
    total_img = len(loaders['train'].dataset) #B
    for batch, (X, y) in enumerate(loaders['train']): #C
        X, y = X.to(device), y.to(device) #D
        pred = model(X) #E
        cost = cost_func(pred, y) #F
        optimizer.zero_grad() #G
        cost.backward() #H
        optimizer.step() #I
        if(batch) % 100 == 0: #J
            loss, current_img_idx = cost.item(), batch * len(X)
            print(f"cost: {cost:>7f} [{current_img_idx:>5d}/{total_img:>5d}]")
```

- #A Control the behavior of certain layers by specifying the training mode
- #B Extract the total number of images to track training progress
- #C Extract and iterate through each batch of training data
- #D Pass to GPU for faster processing
- #E Call the forward method (under the hood) to produce prediction
- #F Calculate the current cost
- #G Clear existing gradients, which will accumulate otherwise
- #H Perform backpropagation and compute gradients
- #I Update weights using SGD
- #J Print cost at every 100th batch; each batch has 100 image-label pairs

```
def test(model, loaders, verbose=True):
    model.eval() #A
    total_img = len(loaders['test'].dataset) #B
    correct = 0
    with torch.no_grad(): #C
        for X, y in loaders['test']:
            X, y = X.to(device), y.to(device)
            pred = model(X)
            correct += (pred.argmax(1) == y).type(torch.float).sum().item()
    correct /= total_img #D
    if verbose:
        print(f"Test accuracy: {correct:>0.3f}")
```

## 4.4 More on generalization

Earlier, we mentioned that the SGD is widely used in deep neural network models due to its good generalization performance. We did not explicitly use any regularization in the process. Thus, the SGD algorithm seems to pose an implicit regularization effect, apart from the broad model class of neural networks and the particular input data type (i.e., structured image data). The implicit regularization from SGD would promise a further decrease in test error even when the training error reaches zero, thus leading to the “double descent” in the test loss curve. The effect of implicit regularization is recently studied by Smith et al. (2021) in their paper “On the Origin of Implicit Regularization in Stochastic Gradient Descent”, which we will discuss in a later chapter.

Now let us examine this property more closely. The code listing below defines a simple neural network with just one fully connected hidden layer. Setting a simple architecture makes it easy to focus on the performance impact when we change the model complexity, i.e., tweaking the number of nodes in the hidden layer. In the model initialization codes in the `__init__` function, we use `nn.Linear()` to define two fully connected layers, one as the hidden layer and the other as the output layer. Note how we specify the input size as 1*28*28 for the hidden layer and output size as a default value of 10 for the output layer; these are based on the property of MNIST data. We also place the hidden layer size `num_nodes` as an explicit input parameter in the initialization function to create models of different sizes later. The `forward()` function does a similar job as in our previous example. The only thing to note is that we directly flatten the input data at the beginning to cater to the fully connected layer since the convolutional layer is not used here.

### Listing 4.11 Define the single layer neural network model class

```
import torch.nn as nn
import torch.nn.functional as F
class SimpleNN(nn.Module):
    def __init__(self, num_nodes, num_classes=10): #A
        super(SimpleNN, self).__init__()
        self.fc = nn.Linear(1 * 28 * 28, num_nodes) #B
        self.out = nn.Linear(num_nodes, num_classes) #C

    def forward(self, x): #D
        x = x.view(x.shape[0], -1) #F
        x = F.relu(self.fc(x))
        output = self.out(x)
        return output
```

- #A Model initialization codes
- #B The single fully connected layer
- #C The final fully connected layer which outputs 10 classes
- #D Model architecture codes
- #F Flatten all dimensions except for the batch size
