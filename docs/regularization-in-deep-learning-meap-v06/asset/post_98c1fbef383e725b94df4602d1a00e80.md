One way to visually examine if the learning rate is properly set is to plot the model cost as a function of the number of iterations. We can plot the cost after every iteration of gradient descent by setting the number of iterations on the horizontal axis and the cost on the vertical axis. By checking if the cost is steadily decreasing, this plot provides us with a tool to assess the appropriateness of the learning rate hyper-parameter. When the cost decreases very slowly, it shows the model has more or less converged to a stationary point. This monitoring tool also helps us detect if the cost is consistently increasing, which is an obvious sign of divergence.

Figure 2.19 summarizes the cost curves as a function of the number of iterations under different learning rates.

![](img/ee98e91e6845f41077b163bec833ee40_59_0.png)

**Figure 2.19** Plotting the cost as a function of the number of iterations with different learning rates. A high learning rate may lead to divergence, a low learning rate is likely to cause slow convergence, and a good learning rate would steadily reduce the cost until convergence.

In most implementations of gradient descent, a threshold is usually preset to determine if the model has converged, such as the change in the cost or weights. In addition, different learning rates may end up with different costs upon model convergence due to non-convex cost function and multiple local minima. To this end, we often employ a multi-start optimization procedure that involves multiple optimization runs, each with a randomly selected starting point.

Setting a reasonable learning rate is both art and science. It is usually one of the top hyper-parameters tuned in deep neural networks. A more dynamic tuning schedule for the learning rate could be in between: setting a relatively large learning rate at the initial training stage for faster convergence and gradually reducing it as the training reaches convergence. Besides, a large initial learning rate also has an implicit regularization effect. We will explore more on this topic in a later chapter.

## 2.5 Improving the predictive performance

The predictive performance is inherently determined by the model's complexity, such as the number of weights used. For example, an underfitting model tends to have too few weights, while an overfitting model has too many weights. One way to boost the predictive performance on the training set is thus to increase the number of adjustable weights used in the model. However, this needs to be appropriately calibrated using the validation set and assessed using the test set.

### 2.5.1 Augmented representation via feature engineering

Since the weight vector **w** only contains two elements corresponding to the intercept and slope, the fitted line will struggle to match a potentially nonlinear pattern in the data. However, a linear model is still preferred in some cases due to its direct explainability: change in the prediction is directly and linearly reflected from a change in the input feature. An explainable model can tell us what drives the prediction result we are seeing. Such direct interpretability is not offered by powerful but black-box models such as neural networks. The model is no longer linear in its weights when using neural networks due to the nonlinear transformation introduced on the weights (more on this chapter 4). From the model's predictive performance perspective, the nonlinear transformations in neural networks tend to land in better and more disentangled representations of the original feature space, which is not readily achievable if we are limited to a linear class of models.

However, what if we want to keep the explainability of a linear model but still boost its predictive power? A typical approach employs feature engineering, which generates an additional set of features based on the original ones. Additional features such as higher-degree polynomials could introduce a certain degree of curvature to the fitted line. In that case, the model will have the flexibility to be more expressive and learn a potentially nonlinear pattern. The more artificial features of different degrees of the polynomial we introduce, the more flexible the model.

Polynomial is a form of the **basis function** that can transform the original feature into another feature space. In the toy example, we only have one original feature in **X**. Adding additional polynomial terms will enlarge the feature space, leading to a model prediction based on more than one feature. With more polynomial features generated, the model's predictive power could be potentially boosted.

### 2.5.2 Quadratic basis function

Since the raw relationship between the input data and the target value in figure 2.5 looks quadratic, we will use the quadratic basis function to augment the feature space. The quadratic basis function transforms the original one-dimensional input space into a new space consisting of three basis functions from the zeroth degree up to the second degree of polynomial. Note that the zeroth degree corresponds to the vector of ones added using the bias trick and plays the intercept role in the linear model.

By introducing the polynomial transformation, the prediction function now becomes \(\hat{\mathbf{y}} = \mathbf{\Phi}(\mathbf{X})\mathbf{w}\), where the new design matrix becomes \(\mathbf{\Phi}(\mathbf{X}) = [\mathbf{1} \mathbf{x} \mathbf{x}^2]\) and \(\hat{\mathbf{y}}\) contains a vector of functions \(w_0 + w_1 x_i + w_2 x_i^2\) for any given input feature \(x_i = 1, ..., n\). This results in an enlarged design matrix from shape \((n,1)\) to shape \((n,3)\), as shown in figure 2.20.

### LINEARITY IN THE WEIGHTS

It is worth noting that the nonlinear transformation introduced by the basis function only applies to the input design matrix X and not to the weight vector W. The resulting model still belongs to a linear class of models, since W remains linear. Another scenario is when the output variable ŷ gets transformed using a link function, resulting in the so-called generalized linear model (GLM). In both cases, the parameters in W remain unchanged and linear, making the fitted model a linear one.

Although the added flexibility leads to a lower cost, such flexibility may result in an over-parameterized model prone to overfitting. From our discussion in chapter 1, based on the classical statistical learning perspective, a model that overfits the training set is less likely to generalize well to the test set. To formalize this discussion, we will take a closer look at empirical risk minimization. This is an essential concept in statistical learning theory to help us better connect cost minimization to model generalization.
