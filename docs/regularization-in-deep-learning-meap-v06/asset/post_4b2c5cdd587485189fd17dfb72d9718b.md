
In addition, regularization can also be categorized as implicit or explicit. Implicit regularization refers to a particular operation that indirectly plays a regularizing role. For example, stochastic gradient descent (SGD) is a typical optimizer used to train deep learning models. By optimizing the model based on one or a small batch of data points in each iteration, the model is exposed to more diverse data variations and thus learns to be more robust by considering these variations. By decorrelating the nearby updates, SGD could indirectly regularize the model to be generalizable to the test set. On the other hand, explicit regularizers specifically target tweaking specific components during model training, such as controlling model complexity. Figure 1.18 lists some standard implicit and explicit regularization techniques. One particular technique is Dropout, which acts both as an implicit and explicit regularizer. We will delve into this technique in a later section.

Lastly, as shown in figure 1.19, regularization can also be categorized as strong or weak, depending on its effect. For example, explicit regularizers such as Lasso directly remove unimportant features by setting their coefficients to zero. This could be considered as having a strong regularizing effect. On the other hand, techniques such as data augmentation aim to provide different versions of the same dataset, hoping that the model could learn from the similarities and become robust to the variations in between, resulting in a more gentle, indirect, and thus weak regularizing effect.

## 1.8 Summary

- Regularization includes a suite of techniques used to generalize the trained model to the unseen test set
- Regularization can be applied across the four components of a model training pipeline: data, model, cost and optimization; it can be explicit or implicit, strong or weak
- Underfitting refers to an under-capacitated model that suffers from a high bias and fails to capture the underlying pattern, and overfitting refers to an over-capacitated model that suffers from a high variance and may accidentally learn a spurious relationship
- Model training needs to balance the bias and the variance and arrive at the right level of model complexity

The main goal of building machine learning models is to emulate and automate a specific manual process. Examples include predicting the housing price or forecasting future temperature. *Supervised learning* is a type of machine learning tasks that focuses on the mapping relationship between the input data and the target output created in advance based on manual annotation. Such mapping is achieved by learning a mathematical function that specifies the underlying pattern, mapping the input to the output based on a set of parameters that govern the mapping function. The specific mathematical function represents our _inductive bias_, a prior belief on the properties of the function, in the form of a hypothesis. In this process of learning from examples, the model parameters are optimized so that the shape of the learned function becomes more representative of the real one. A supervised learning model could then take in new input data and predict the corresponding output. Instead of explicitly programming the mapping rule, the model automatically learns the mapping logic, thus being more intelligent than traditional rule-based software engineering practices. As long as the proper input and output are provided, we can outsource the whole mapping and rule identification task to the supervised learning algorithm, which is very useful, especially in the presence of complex processes.

It is important to note that a model essentially represents a simplifying assumption to represent the underlying data generating process. The assumption is often accompanied by an _inductive bias_, such as the smoothness of the data generating function: one value should smoothly transition to another without sudden jumps. The pre-specified inductive bias, when properly used, could introduce a surprising generalization effect. The hypothesis on the true function could also come from our prior belief about the underlying data generating processes, such as regularities or other properties we wish to borrow from similar tasks via the transfer learning framework.

### 2.1 The data

All machine learning models start with some given training data. In supervised learning, the training data consists of input-output pairs. Suppose there are _n_ pairs in total, and we focus on the _i_th pair of data, denoted by (**x**<sub>_i_</sub>, _y<sub>i</sub>_). The parenthesis means that each and every entry in the training set has to come with a pair, consisting of both the input **x**_<sub>i</sub>_ and output _y<sub>i</sub>_. The input vector **x**_<sub>i</sub>_, which is a one-dimensional array, is bolded to highlight the fact that it contains one or more features. The input features in **x**_<sub>i</sub>_ are used as predictors by the model to come up with a scalar prediction $\hat{y}_i$ (single dimension and thus unbolded) for the _i_th observation.

### Common terminology

There are multiple names to express X_i, including features or predictors (often used in machine learning), covariates or independent variables (often used in statistics), attributes (often used in database language), or just columns of a data table. Correspondingly, y_i can be referred to as target, label, outcome or dependent or response variable. In this book, we will use these terms interchangeably. In addition, all features in X_i of a single entry are jointly referred to as an observation, and all observations jointly form the design matrix. The model is sometimes referred to as (mapping) function, hypothesis or classifier (more often used in classification tasks).
