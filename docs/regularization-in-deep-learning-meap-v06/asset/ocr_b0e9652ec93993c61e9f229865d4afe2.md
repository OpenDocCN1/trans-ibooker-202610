Figure 6.9 Expressing the convolution operation using the feed-forward style. The input entries in the square matrix are sequentially mapped to the nodes in the input layer, from left to right, from top to bottom. We give two examples where w1 is mapped to in the figure. Similarly, the output feature map is also flattened into a straight-line layer consisting of four nodes. We use color-encoding to differentiate the four input patches and the resulting output features, along with the corresponding notations for each node and weight. The weights are drawn using different types of lines for differentiation, where every single weight is repeated/shared four times across four input nodes, and the number of connections is significantly less than that in a typical FCN.

What is particularly interesting is observing how the weights connect the input and output nodes. On one hand, the number of weights used is now much less compared with a typical FCN, which requires 16x4=64 weights. Fewer weights ease both computation and training load. On the other hand, weight sharing is explicitly enforced for specific input nodes. Consider w1 as represented by the solid line in the figure. All four nodes of different colors share this same weight and end up in different output nodes. Such arrangement contributes to learning geometric structures (edges, shapes, etc.) that are otherwise difficult to be captured using standalone weights in a typical FCN. Introducing inductive bias in the architectural design of the network thus plays an important role in determining the model's learning capacity.

Note that pooling operations such as max-pooling or average-pooling are also examples of introducing inductive bias in the model design, although there is no learnable weight involved in the operation.
