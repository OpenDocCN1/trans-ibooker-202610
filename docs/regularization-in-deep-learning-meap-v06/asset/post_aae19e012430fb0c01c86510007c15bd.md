We can also express the overall convolution operation of a 3x3 kernel in a way similar to the following, which describes the mechanism of a cross-correlation operation, another type of operation that largely resembles a convolution operation and eases the illustration of the mathematical operations. The only difference is that CNN flips the filter both horizontally and vertically, causing $IN_{i+x,j+y}$ to be $IN_{i-x,j-y}$ instead.

$Out_{i,j} = b + \sum_{x=0}^2 \sum_{y=0}^2 IN_{i+x,j+y} W_{x,y}$

In this expression, $IN$ denotes the input matrix, $W$ the kernel matrix of weights, and the $Out$ the resulting feature map that again serves as the input matrix for the following layer. There are two sets of zero-based indexes: $(i,j)$ as the global index that moves across input patches and $(x,y)$ as the local index that moves across elements of an input patch. $(i,j)$ uniquely locates each feature in the feature map $Out$, with $Out_{0,0} = 3$ as in the convolution example in figure 6.5. Since $IN$ is 6x6 and $W$ is 3x3, if the kernel sequentially convolves with each input patch, i.e., using a stride of 1, the resulting output $Out$ is 4x4, making both $i$ and $j$ in the range of 0 and 3. We will discuss the change of dimensions shortly.

For each convolution operation, both $x$ and $y$ vary between 0 and 2, resulting in a total of 9 combinations, or 9 element-wise multiplications between the input patch and the kernel matrix. The index pair $(x,y)$ thus uniquely identifies the input entry $IN_{i+x,j+y}$ (on top of the global input patch index $(i,j)$) and the weight entry $W_{x,y}$, performing the element-wise multiplication $IN_{i+x,j+y}W_{x,y}$ and summation $\sum_{x=0}^2 \sum_{y=0}^2 IN_{i+x,j+y}W_{x,y}$. We also note a bias term $b$ is added as a global adjustment to the output feature.

There are several hyper-parameters we can set for the convolution operator in terms of how the kernel convolves with the input patches. Specifically, we can change the stride to control the amount of movement of the filter across the image. For example, the previous example uses a stride of 1 since the kernel moves (left to right, top to bottom) one pixel at a time. By setting the stride parameter to 2, the kernel will skip the following pixel and "jump" to the one after. A bigger stride will result in a smaller feature map since the number of element-wise multiplications between the kernel and the input patches reduces.

In addition, since the pixels on the border of the image are only convolved once with the kernel, we can adjust the padding parameter to account for this and ensure the same number of interactions with the kernel for all pixels. For example, we can surround the edges of the input image with an additional layer of pixels whose values are all zero. This is called zero padding, or same padding, which adds a padding of zeros around the outside of the input image, and is particularly useful if we want to preserve the shape/dimension of the input image in the resulting output feature map, so as to capture the information along the edges of the input image. Padding introduces zeros around the edges to enlarge the virtual size of the input matrix.

Note that another advantage of padding is that the dimensions of the image are preserved from layer to layer, and we don't have to worry too much about the dimensions of the tensors.

Figure 6.6 illustrates these two tuning parameters, where we set a padding of 1 and a stride of 2. These parameters are set in advance when defining a convolution layer. They essentially influence the shape of the resulting output array and belong to the increasingly long list of hyperparameters in a neural network. Although achieving the best hyperparameter configuration is a tedious process that requires trial and error, we would normally go with settings that seem to work well in many domains. For example, using 3x3 kernel, zero padding, and a stride of 1 when learning low-level local structures in the early hidden layers.

How do we figure out the output dimension of a convolutional layer? To achieve this, we would need the size of the input array and the kernel, along with its parameter setting for padding and stride. One useful formula to calculate the output shape D_out is given as follows:

$D_{out} = \lfloor(D_{in} - k + 2p)/s\rfloor + 1$

where $D_{in}$ denotes the width or height of the input image that assumes a square array, $k$ is the width or height of the kernel, $p$ is the padding along the horizontal or vertical borders of the input image, and $s$ is the stride of the kernel. The result is then rounded down to the nearest integer using the flooring operator $\lfloor \rfloor$, followed by the addition of one. Feel free to try plugging this formula in the examples above and verify if it is correct.

Let us apply this formula to the previous example to better understand the dimensional translations between the input and the output. As in the example in figure 6.6, we have an input size $D_{in} = 5$, a kernel size $k = 3$, a padding size $p = 1$, and a stride $s = 2$. Apply the formula gives $D_{out} = 3$, a 3x3 feature map in the output. See figure 6.7 for an illustration of the change of dimension between the input and the output.

The formula thus allows us to obtain the dimension of the output based on how the convolution operation is parameterized over the input matrix.

It turns out the convolution operation corresponds to a special type of FCN that adopts weight sharing, as we will show in the following section.

### 6.1.4 Weight sharing in the convolution operation

Consider a 2x2 kernel matrix used to convolve with a 4x4 input matrix using no padding (also called *valid padding*) and a stride of 2. Using such parameterization, the kernel will convolve with four input patches, which are mutually exclusive and collectively exhaustive of the full input matrix. See figure 6.8 for an illustration.

![](img/ee98e91e6845f41077b163bec833ee40_188_0.png)

Figure 6.8 Convolving a 2x2 kernel with a 4x4 input matrix using no padding and a stride of 2. The four input patches are color-coded and labeled by the multiplication between the corresponding weights and inputs for clarity. The output is a 2x2 feature map, where we show the result of summing the element-wise multiplication between the kernel and the input patch for the top left cell.

In this figure, we have explicitly labeled the input matrix with the corresponding weights to be multiplied with. All input patches convolve with the *same* kernel matrix, whose weights are shared across the corresponding input entries. For example, $w_1$ is shared across the upper-left entries of all four input patches. Instead of pairing each input entry with the respective unique weight as in FCN, the convolution operation shares weights across multiple input entries.

Let us visualize the weight-sharing mechanism in the context of FCN. In figure 6.9, we draw the same convolution operation as in figure 6.9, although using a flattened feed-forward fashion as in FCN. Note that the conversion in this figure contains quite some information that needs to be unpacked. First, we color-code the four input patches in the input matrix, which corresponds to the four features (of the same color) in the output feature map. Next, we flatten all these components (input layer, kernel, and output layer) in a feed-forward manner as in a typical FCN. For the input matrix, each entry is sequentially mapped to the corresponding node in the input layer, starting from left to right, from top to bottom. For example, the upper-left entry is mapped to the first input node, as shown by the dash-dotted line in the figure. The same positional mapping applies to the output layer. Finally, the kernel manifests as connecting lines representing the weights of the network. Each weight assumes a different type of line for differentiation, avoiding the already congested color space.
