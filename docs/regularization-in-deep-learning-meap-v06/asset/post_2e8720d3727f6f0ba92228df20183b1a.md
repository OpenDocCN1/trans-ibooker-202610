The side-effect of promoting sparsity via dropout is similar to using group Lasso in the node-level selection, although dropout does not involve an explicit regularization term on the nodes.

In the next section, we will look at implementing the dropout operation from scratch, and apply it in both FCN and CNN using the MNIST dataset.

## 6.2.3 Dropout in action

The dropout operation consists of dropping some nodes according to a preset probability and scaling up the weights of the rest of the nodes. Here, we specify the probability of dropping nodes (which is also a hyper-parameter) and not the probability of keeping nodes. This applies to both the example we will cover in the following and the dropout layer available in PyTorch.

When implementing dropout, the first part involves generating an indicator list of Boolean numbers to be multiplied with the nodes within the layer of assessment, be it the input layer or hidden layer. When a node is multiplied by zero, or equivalently a `FALSE` value in Python, the resulting feature value of the node will become zero and flow into the following operation, which amounts to dropping out or masking this node. It also ensures that no error gradients will flow back during backpropagation to the neurons that were dropped. The list of Booleans has the same length as the number of nodes and is generated by comparing a list of random numbers with the preset dropout probability, where the random numbers follow a uniform distribution between 0 and 1.

The second part is to scale up the feature value of the nodes, which is equivalent to scaling up their outgoing weights. The reason is that after dropping out some nodes, the rest of the nodes need to be scaled up in value in order to compensate for those dropped nodes. In particular, suppose the dropout ratio is p, then each of the remaining nodes will be multiplied by 1/(1 - p).

The following code listing implements the dropout class that can be applied to the input layer or any hidden layer. Upon instantiating the class, it accepts a default dropout ratio of 0.5, which usually vary in the range of 0.5 to 1. The scaling factor is also calculated and stored as an attribute when the __init__() function is triggered automatically. Next, the forward() function specifies how the dropout operation is performed and is automatically triggered when applying this class. Specifically, we first create an indicator list called `selected_ind` to determine which nodes to mask/mute. The list of Boolean numbers is created by comparing a list of uniformly generated numbers in the range of 0 and 1 to the preset dropout_rate. The indicator list is later converted to a floating data type and wrapped in a variable, whose gradient propagation is disabled as there is no learning involved. Finally, we mask the nodes according to the indicator list and scale up the rest of the survivor nodes.

### Listing 6.1 Defining a customized dropout class

```
class Dropout(nn.Module):
    def __init__(self, dropout_rate=0.5):
        super(Dropout, self).__init__()
        self.dropout_rate = dropout_rate
        if self.dropout_rate < 1: #A
            self.scaling_fct = 1.0 / (1.0-dropout_rate) #A
        else: #A
            self.scaling_fct = 0.0 #A

    def forward(self, input):
        if not self.training: #B
            return input

        selected_ind = torch.Tensor(input.shape).uniform_(0,1) > self.dropout_rate #C
        if input.is_cuda: #D
            selected_ind = Variable(selected_ind.type(torch.cuda.FloatTensor),
                requires_grad=False) #D
        else: #D
            selected_ind = Variable(selected_ind.type(torch.FloatTensor),
                requires_grad=False) #D

        return torch.mul(selected_ind, input) * self.scaling_fct #E
```

- #A define the scaling factor to remaining nodes to compensate for dropped nodes
- #B only apply dropout during training mode
- #C indicator tensor of same size to label the selected nodes
- #D use GPU if available
- #E drop out some nodes and scale up the rest

Next, we define the FCN model as a class called MLP(). As shown in the following code list, we use the sequential container from PyTorch to chain together multiple layers via its add_module() function. The dropout_rates argument is a list with two entries, which correspond to the dropout probability for the input layer and all hidden layers respectively. After specifying the connection between the input layer and the first hidden layer, all the remaining layers are configured in a for loop, making it convenient to scale to architectures with different configurations of fully-connected hidden layers. Since we are using MNIST dataset, our network starts with an input dimension of 1x28x28 pixels and an output dimension of 10 classes.

### Listing 6.2 Defining the FCN model

```
class MLP(nn.Module):
    def __init__(self, hidden_layers=[800, 800], dropout_rates=[0, 0]):
        super(MLP, self).__init__()
        self.model = nn.Sequential()
        self.model.add_module("input", nn.Linear(28*28, hidden_layers[0]))
        self.model.add_module("dropout_input", Dropout(dropout_rate=dropout_rates[0]))
        self.model.add_module("tanh", nn.Tanh())
        # add hidden layers
        for i, d in enumerate(hidden_layers[:-1]):
            self.model.add_module("dropout_hidden_"+str(i+1),
            Dropout(dropout_rate=dropout_rates[1]))
            self.model.add_module("hidden_"+str(i+1), nn.Linear(hidden_layers[i],
            hidden_layers[i+1]))
            self.model.add_module("tanh_hidden_"+str(i+1), nn.Tanh())
        self.model.add_module("final", nn.Linear(hidden_layers[-1], 10))

    def forward(self, x):
        # flatten to one-dimensional array
        x = x.view(x.size()[0], 28*28)
        x = self.model(x)
        return x
```

Note that we used dropout before the non-linear activation function kicks in, which provides a slight boost in computational efficiency. In practice, however, a dropout layer is typically placed after the activation layer.

class MLPClassifier:
