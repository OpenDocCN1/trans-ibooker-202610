## 6.3 Implicit regularization in multi-task learning

In the following section, we will visit another type of generalization-inducing model architecture: multi-task learning.

Up till now, we have been focusing on optimizing over a single particular metric, such as the mean squared error. This involves training a single model or an ensemble of models for the specific task at hand, often through many rounds of fine-tuning and estimation. However, when we are exposed to more than one task, this approach would ignore the potentially useful information from other related tasks. In this case, we can consider building shared representations among these similar tasks using multi-task learning (MTL) in order to improve the generalization performance on the original task. In other words, the domain-specific characteristics embedded in related tasks could help the model trained by MTL generalize better.

MTL refers to a learning paradigm where multiple tasks are learned in parallel as opposed to being treated as independent tasks using a single-task approach. When simultaneously learning multiple tasks, the knowledge and experiences acquired in one task could (hopefully) be shared and transferred to other similar tasks, which is one of the fundamentals in human learning process. Indeed, we as humans often apply the knowledge acquired through related tasks when learning a new task. As a dedicated field in machine learning, MTL offers benefits in terms of learning efficiency and predictive accuracy. By leveraging the information embedded in the signals of auxiliary tasks, MTL could exploit the similarities and relations among multiple learning problems and thus contribute to test set generalization. The improved generalization performance is a result of the implicitly induced regularization effect when optimizing the model’s performance over all learning tasks.

MTL can also be viewed as a form of overlaying inductive bias, causing the model to prefer certain hypotheses (a set of models in the entire space of all possible models) over others. The inductive bias is provided by the joint training of the auxiliary tasks, since a model trained using MTL is tilted towards hypotheses that are able to explain more than one task, thus leading to better generalization. By biasing the model to favor representations which other tasks also prefer, it will also help the model generalize well to new tasks outside the training data, as long as the tasks are similar in nature and originate from the same data generating process.

In addition, MTL can be considered as a form of implicit data augmentation, which effectively increases the sample size used in the training procedure. This interpretation comes from the fact that all the learning tasks are often perturbed by different levels of noise. When training a model on one task, the ultimate goal in a typical single-task training process is to learn a good enough representation that ignores the data-dependent noise and captures the underlying pattern, which helps it generalize well to the test set. Since different tasks are exposed to different noises, jointly learning two tasks will allow the model to acquire a more general representation and overcome task-specific noises. By lowering the risk of overfitting to a single learning task, simultaneously learning more than one task allows the model to average out the noise patterns and thus generalize better to both tasks.

Another added benefit is called eavesdropping, where the model boosts its preference over certain features that are difficult to be learned in one task but easily identified in another task. When learning one task, the potentially complex dependence structure in the feature space may impede the model from spotting certain important features, which may stand out when learning another related task. By learning these two tasks together, the model eavesdrops in a way from the other task and utilizes this outside knowledge in the current learning task, thus boosting its learning performance. See the review paper “An Overview of Multi-Task Learning in Deep Neural Networks” by Sebastian Ruder for a more detailed review on the use of MTL in deep learning.

It should be noted that most MTL deep learning models assume that the tasks come from the same data generating process. Although this assumption benefits the sharing nature among multiple related tasks, it may not always hold in practice. It becomes a challenge to build a robust MTL model when the learning tasks are unrelated or merely loosely related to each other. Part of this challenge can be addressed by allowing the MTL model to learn what to share, such as the cross-stitch networks introduced later. Besides the level of sharing, allowing the model to automatically learn the hierarchical structure with levels of granularities also helps improving the model’s generalization performance. Even if our goal is to learn one task only, leveraging on the knowledge of other tasks, even sometimes adversarial, could often help deliver a better predictive performance.

### 6.3.1 Two MTL approaches in deep neural networks

There are two main approaches when performing MTL using deep neural networks: hard parameter sharing that enforces all tasks to share a common set of weights, and soft parameter sharing that encourages different tasks to learn a similar representation, often achieved by imposing certain constraints on the corresponding weights. Let us look at them in detail.

As the most popular sharing scheme in neural networks, hard parameter sharing encourages different tasks to learn a common representation by enforcing them to completely share a set of weights in the hidden layers among all tasks, while maintaining a few task-specific layers in the final output. This common set of weights are then used to combine with downstream task-specific layers, which are independently learned for each task. By imposing a representation that supports all tasks, hard parameter sharing induces an implicit regularization effect and reduces the chance of overfitting. In other words, by asking the model to learn multiple tasks jointly, our model is forced to find a representation that captures all jointly learned tasks and this reduces the chance of overfitting the original single task. In particular, when these tasks are believed to share a certain level of commonality, such as predicting gender and age from the same human face, we could impose such inductive bias in the model by enforcing a common backbone architecture for all tasks.

Figure 6.15 illustrates the hard parameter sharing scheme. We start with a sequential block that covers all the shared layers across the three tasks. These shared layers are designed to learn the commonalities among all tasks, i.e., the set of features that are task-wide predictive. Upon reaching the last shared layer, the network expands to three branches, dedicated to each task respectively. These task-specific layers are responsible for learning within-task characteristics which are considered to be unique to the specific learning task. Compared with having three separate networks for each learning task, the hard parameter sharing architecture is more computationally efficient due to fewer learnable parameters, besides the added benefit of less overfitting and better generalization performance.
