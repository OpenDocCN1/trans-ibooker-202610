## 2.1.1 Sampling from the underlying data distribution

Note that the actual training dataset (X,y) is often assumed to originate from a underlying data generating distribution, i.e., (X,y) ~ P(x,y). In practice, P(x,y) is unknown to us. The problem would be solved by itself if we have access to P(x,y). Also, (X,y) is just one collection of observations, which are assumed to be independently and identically distributed (i.i.d.) after drawing these random samples from P(x,y). If we keep drawing samples and generating additional datasets from the true distribution P(x,y), we will likely get a different incarnation of training dataset than (X,y). In fact, this is exactly the motivation behind data augmentation, a technique to create additional artificial samples (called bootstrapped samples) for training purposes. By artificially generating additional training sets, the model will be exposed to more realizations of the dataset and will hopefully learn to become more robust to changes in the data. The resulting sample may not always contribute to the model learning since it may contain more irrelevant samples than the original dataset, but in general exposing more variations in the training datasets helps improving the model training. The relationship between the actual snapshot of the training set (X,y) and the true data generating distribution P(x,y) is illustrated in figure 2.3.

It is also likely to change if we were to sample another training set from the underlying data distribution P(x,y). Meanwhile, it should also be noted that both X and y could contain continuous or discrete variables. In our example later, we focus on the linear regression model, which assumes a continuous y.

Let us observe the sampling variability in codes. Recall that earlier we used the function `np.random.rand()` to create random numbers. This function essentially draws a specified amount of random numbers uniformly within the range of [0,1]. In other words, it follows a uniform distribution between zero and one, where each candidate number gets sampled with equal probability. We could, however, change the range to another. We could also assume a different probability distribution such as the normal distribution, which has a different distributional profile characterized by its mean (central tendency) and variance (spread). The code listing below demonstrates these differences.

As seen from the drawing outputs, all three vectors contain a different set of numbers. Drawing a list of five numbers can have infinitely many possibilities. On one hand, we do not have access to the type of the true underlying distribution. It could be a uniform distribution with certain range, normal distribution with a specific mean and variance, or any other type of complex distribution governed by certain parameters. On the other hand, even if we know the underlying data generating distribution in terms of its type and parameters, each sampling will also result in a different set of numbers due to the random nature of sampling itself. However, we would easily train a good model in the second case, since we could simply keep generating different versions of the training data and feed to the model; the prediction problem could be easily solved even with a simple model.

## 2.1.2 The train-test split

The main objective of a machine learning model is to produce good prediction results on a future unseen dataset, called test set. However, the test set is unavailable to us, and the dataset (X,y) is all we have. To better gauge the model’s predictive performance on the test set, a common practice is to allocate a small portion of (X,y), denoted as (X,y)test, as a proxy for future unknown test set. This has two flavors of meaning. First, (X,y)test will not be used to train the model. In fact, we should not expose any of (X,y)test to the model during training; doing so would risk peeking into the future. Second, (X,y)test serves as a proxy for the model’s generalization performance on the future, possibly different test sets. This means that (X,y)test may or may not be a good proxy due to possible data drift, i.e., distributional difference in the datasets, leaving us an additional level of uncertainty in addition to model estimation.

After taking out (X,y)test, the rest of (X,y) is further often split into a training set (X,y)train and a validation set (X,y)val. (X,y)train is the only part of the original (X,y) used for model training and parameter estimation. The model goes through an optimization process to fit the given training set (X,y)train as much as possible. Since a typical machine learning model involves some hyper-parameters which are manually pre-defined, the effect of different configurations of hyper-parameters are assessed by (X,y)val. (X,y)val is another proxy for a future unseen test set, similar to (X,y)test; the difference is that (X,y)val is used for hyper-parameter tuning as part of the overall model training process, while (X,y)test is only used for assessing generalization capability of the trained model and not used for model training. In some cases, (X,y)val is treated as part of (X,y)train, so the whole dataset is split into two subsets: (X,y)train for model training and (X,y)test for model assessment.

Obviously, there is a potential risk of selection bias in choosing (X,y)train, (X,y)val and (X,y)test; we may just happen to be lucky in choosing a (X,y)train and produce a model that generalizes well to both (X,y)val and (X,y)test. The risk in choosing (X,y)train and (X,y)val is addressed by cross validation, a technique that systematically repeats the split multiple times. To reduce such risk, nested cross validation could be employed.

Splitting the original dataset into (X,y)train, (X,y)val, and (X,y)test is performed at the beginning of a model training workflow. Depending on the size of the dataset, the split ratio could be 6:2:2 for a small dataset and 8:1:1 for a large dataset.

Figure 2.4 illustrates splitting the same dataset into three mutually exclusive and collectively exhaustive subsets commonly practiced as a rule of thumb: training set, validation set, and test set. Since each subset serves a different purpose, it is essential to repeat the randomized split multiple times to avoid selection bias. When the test set is used for model selection, i.e. identifying the optimal model that has the lowest error in the test set, the test set performance is considered to be the best proxy for the true performance on future unseen data. Note that a strict assessment (as in many modeling competitions) would require a single, sufficient and representative test set, which avoids exposing the test set for model training, i.e., data leakage.
