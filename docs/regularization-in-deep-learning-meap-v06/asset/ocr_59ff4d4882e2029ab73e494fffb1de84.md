These inductive biases are important accelerators to help the model understand different spatial connections of the objects and other visual properties specific to the current object recognition task. Other invariance properties, such as size invariance and illumination invariance, could also be similarly developed in the resulting model by providing corresponding augmented training data via data augmentation.

Note that rotational and scaling invariance properties can also be learned using the max pooling operation in CNN. For example, when the input image contains different degrees of rotation or scales, different filters in the hidden layer will get activated in terms of outputting a relatively large value. The max pooling layer will select the maximal activation from all filters, thus displaying invariance to possible rotation or scaling in the input image. Following the same reasoning, the max pooling, together with convolution operation to be discussed shortly, also contributes to translational invariance in CNN.

To achieve these desired properties, we need to constrain the connections in the FCN in a way that facilitates the network to learn local structures and pick up invariance properties. Specifically, we would like to embed relational inductive biases specific to different types of layers in a neural network. On the one hand, we exploit the locality of geometric objects in the input data so that the resulting CNN model is invariant to spatial translations. On the other hand, the sequentiality of objects (e.g., tokens in natural language processing, observations in a time series) is exploited in a recurrent neural network (RNN) so that the resulting model is invariant to temporal translations.

Before delving into how we can constrain the FCN to display the desired property, let us look at the convolution operation in more detail. In fact, as you will see in the following section, CNN is a special type of constrained FCN due to the convolution operation.

# 6.1.3 Understanding the convolution operator

The convolution operator is one of the main drivers for achieving the translational invariance property. Recall the convolution workflow figure in chapter 4, which is also shown in figure 6.5 here for ease of reference. The key takeaway is that we define a kernel/filter to sequentially convolve with different input patches and produce the resulting features in the feature map. Every single convolution consists of element-wise multiplications between the kernel and the input patch, followed by a summation operation.
