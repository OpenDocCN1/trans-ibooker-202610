
### 2.6.3 Understanding bias and variance using bootstrap

The model bias refers to the gap between the expected model prediction (_f_) and the underlying true target _g_ : _Bias_[_f_] = _g_ − E[_f_]. The expectation here is again considering all different realizations of the dataset (**X**,**y**) sampled from the same joint data generating distribution P(**x**,**y**). A biased model is said to underfit the training data, since the relationship between the input features and the output label is not properly captured. A less biased model, on the other hand, could better capture the regularities and represent the underlying complexity well.

In figure 2.22, the squared bias term could be thought of as the error due to a simplifying assumption in the model, such as approximating an inherently nonlinear pattern _g_ using an under-capacitated linear model _f_. Such an assumption will lead to insufficient representation of the true pattern in the data. Improving the model complexity, such as using feature augmentation, will likely improve the model’s fitting capacity and thus reduce its bias due to better approximation. However, doing so may risk overfitting the data.

Variance, on the other hand, measures the expected movement of _f_ around its mean: _Var_[_f_] = E[(_f_ − E[_f_])<sup>2</sup>]. Such movement also refers to the model’s sensitivity to possible changes in the data. As a result of overfitting the random noise, a model with high variance will be too complex and sensitive to small fluctuations in the data. Note that the level of complexity for a high-variance model _f_ is in terms of the current dataset and not the real complexity of the underlying function _g_; the latter is often much more complex in reality.

Since both bias and variance are highly dependent on the currently available dataset (**X**,**y**), one way to quantify the model’s bias and variance for other versions of (**X**,**y**) is to use the _bootstrap_ procedure. Bootstrap is a technique to generate artificial datasets by randomly sampling from the original dataset (**X**,**y**) with replacement. These artificial datasets now serve as additional realizations from P(**x**,**y**) and can be used to perform the same model fitting procedure for multiple times. The resulting multiple fits could then be used to estimate the bias and the variance of the original model _f_. See figure 2.23 for a visual illustration of the estimated bias and variance using bootstrap.

The bootstrap procedure is a powerful technique to engineer artificial datasets. It belongs to the more generic idea of ensembling, where multiple fits are performed and aggregated to produce the final prediction. The additional fit could come from a new dataset or a new model architecture, which surprisingly corresponds to a regularizing effect via the data or the model. ### 2.6.4 Reduced generalization with high model complexity

The classical view on generalization essentially states that the two reducible sources of error, namely the bias and the variance, cannot be reduced simultaneously. When the bias is high and the variance is low, the model is relatively simple and tends to underfit the training data, which often happens at the initial stage of training. In this scenario, a common direction towards empirical risk minimization is to train a more complex model. Increasing model complexity often leads to relatively large decrease in the bias and a slight increase in the variance term, thus reducing the overall combined cost. This increased bias means that our model will be biased and off-target in expectation. However, the overall benefit in empirical risk minimization still outweighs the downside from a possibly biased estimation when building a generalizable model.

The classical view on generalization also indicates that a high-variance model is less likely to generalize to the future test set. When a model becomes arbitrarily complex, it tends to overfit the training data and even has the potential to perfectly interpolate the training data, resulting in zero training error. However, such a model tends to have a high variance as it also fits the noise in the training data. Therefore, when using the model to score new data points, a slight change in these data points would result in a very different output, making the prediction sensitive and unstable. In contrast, a good model reaches a proper tradeoff between the bias and the variance, avoiding potential underfitting or overfitting. The model that balances the bias and the variance is also reflected as the “sweet spot” in figure 1.7 back in chapter 1.

To see the increased variance as the model becomes complex, we will employ additional feature engineering by increasing the number of polynomial basis functions to a higher degree. Instead of running the same codes multiple times, each with a different polynomial degree, it is better to wrap the polynomial transformation into a more general function. Designing a reusable function makes it flexible in specifying the degree of polynomial to be performed in the transformation. The following function achieves this by first creating a matrix as a placeholder based on the pre-defined degree of the polynomial, followed by filling in the matrix using polynomial functions.

### Listing 2.12 Generate the new design matrix based on polynomial terms

```
def polynomial(x, num_basis=2):
    Phi = np.zeros((x.shape[0], num_basis)) #A
    for i in range(num_basis): #B
        Phi[:, i:i+1] = x**i
    return Phi
#A Create the matrix of zeros as placeholder
#B Fill in each column based on the sequence of polynomials
```

We can create a new design matrix using this utility function by passing in the original design matrix and specifying the number of basis functions. A good model should be expressive enough to represent the underlying pattern in the data and simple enough to avoid fitting potentially spurious patterns due to random noise.

### 2.7 Summary

- Model training starts with data, which is often divided into three subsets: training set, validation set, and test set, although the validation set may be absorbed as part of the training set for model training
- The test set is used to assess the model’s generalization performance and calculate the empirical risk, a proxy to the true risk
- Feature engineering such as adding polynomial basis can increase model complexity by turning a linear fit into a nonlinear fit
- The bias trick is a convenient technique often used to ease the implementation of machine learning models
- The mean squared error is a widely used cost for regression task and also called the empirical risk in linear regression
- Optimization can be completed in one shot if the closed-form solution is available; otherwise, the gradient descent family of methods is most widely used
- There are three types of gradient descent method: the batch gradient descent, the mini-batch gradient descent, and the stochastic gradient descent; the difference lies in the number of examples used in each gradient descent update
- Setting a proper learning rate is crucial in ensuring model convergence
- The risk can be decomposed into three sources of error: the irreducible variance from the random noise, and the reducible squared bias and variance of the model
- The classical view on generalization states a tradeoff between the bias and the variance: a complex model has a lower bias but higher variance than a simpler model and is less likely to generalize well to the test set due to the high variance
