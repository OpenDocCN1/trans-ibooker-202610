### 重新定义数据科学

但在此之前，理解*数据科学*的最好方式是追溯这个术语的历史。

### 数据科学简史

我们可以将*数据科学*追溯到统计学的起源，早在 17 世纪甚至 8 世纪。为了简洁起见，让我们从 20 世纪 90 年代开始。分析师、统计学家、研究人员、“量化分析师”和数据工程师通常保持着各自不同的角色。工具栈通常由电子表格、R、MATLAB、SAS 和 SQL 组成。

当然，2000 年后事情开始迅速变化。互联网和联网设备开始产生海量数据。伴随 Hadoop 的兴起，Google 将分析和数据收集推向了难以想象的高度。随着 2010 年的临近，Google 的高管坚称统计学家将在下一个十年拥有“性感”的工作。接下来发生的事情具有预见性。

2012 年，《哈佛商业评论》将称为*数据科学*的这个概念主流化，并宣称它是“21 世纪最性感的工作”。在 HBR 文章发表后，许多公司和企业工人争相填补*数据科学*的空白。管理咨询公司准备就绪，并着手向财富 500 强领导者介绍如何将*数据科学*引入他们的组织。SQL 开发者、分析师、研究人员、量化分析师、统计学家、工程师、物理学家以及众多其他专业人士都将自己重新包装为“数据科学家”。科技公司觉得“分析师”、“统计学家”或“研究人员”等传统职位名称听起来过时了，便将这些职位重命名为“数据科学家”。

自然而然地，财富 500 强公司的高管层在 C 级高管的压力下不得不加入*数据科学*的行列。最初的推理是大量数据正在被收集，因此*大数据*成为一种趋势，需要*数据科学家*从中获取洞察。大约在这个时候，“数据驱动”一词成为各行各业的座右铭。企业世界认为，与人不同，数据是客观且无偏见的。

> **提醒 - 数据并非客观且无偏见！**
>
> 直到今天，许多专业人士和管理人员仍陷入数据客观且无偏见的谬误。希望读完本书后，你明白这并非事实，如果需要回顾原因，请参阅*第 3 章*。

公司的管理层和 HR 部门无法争夺被 FAANG（Facebook、Amazon、Apple、Netflix 和 Google）抢走的专业深度学习博士，同时仍然面临勾选*数据科学*这一框的压力，因此做出了一个有趣的举动。他们将现有的分析师、SQL 开发者和 Excel 老手团队重新包装为“数据科学家”。Google 的首席决策科学家 Cassie Kozyrkov 在 *2018* 年的一篇发表于 *Hackernoon* 的博客文章中描述了这个公开的秘密：


在我担任过的每一个数据科学家职位中，我早已在HR“品牌重塑沙皇”对员工数据库进行小修小补之前，以不同的名字从事这项工作。我的职责丝毫未变。我并非例外；我的社交圈里全是曾经的统计学家、决策支持工程师、定量分析师、数学教授、大数据专家、商业智能专家、分析负责人、研究科学家、软件工程师、Excel老手、冷门博士生存者……他们都是今天自豪的数据科学家。

—卡西·科齐尔科夫

从技术上讲，数据科学并未排除上述任何专业人士，因为他们都在利用数据获取洞察。当然，科学界也曾有反对声音，不愿将数据科学加冕为一门真正的科学。毕竟，你能想到一门不使用数据的科学吗？2011年，皮特·沃登（现任Google TensorFlow负责人）在一篇O’Reilly文章中，为数据科学运动撰写了一篇有趣的辩护文。他还清晰阐述了反对者关于缺乏定义的论点：

> [关于数据科学缺乏定义，这一点] 可能是最深层的反对意见，也是最具杀伤力的反对意见。数据科学范围内和外部的边界并无广泛接受的定义。这仅仅是统计学的时髦重新包装吗？我不这么认为，但我也没有一个完整的定义。我相信，近期数据的丰富在世界上激发了某种新事物，当我环顾四周时，我看到一群具有共同特征却不符合传统类别的人。这些人倾向于在企业与机构主导的狭窄专业领域之外工作，他们处理从寻找数据、大规模处理数据、可视化数据到将其撰写成故事的一切工作。他们似乎也倾向于先看看数据能告诉他们什么，然后挑选有趣的线索去追踪，而非传统科学家先选定问题、再寻找数据来揭示问题的方法。

—皮特·沃登

讽刺的是，皮特也无法给出 *数据科学* 的定义，但他清楚论证了数据科学虽有缺陷却仍有用。他还强调了研究放弃科学方法，转而采纳曾被回避的做法（如数据挖掘，我们在第3章中讨论过）这一转变。

在《哈佛商业评论》那篇文章发表后的几年里，数据科学经历了一个有趣的转向。或许这与其说是转向，不如说是与“AI”和“机器学习”的合并。无论如何，当机器学习和深度学习在2014年左右主导头条新闻时，数据被出售为创建人工智能的“燃料”。这自然扩大了数据科学的范围，并与AI/机器学习运动形成了交汇。特别是，ImageNet挑战赛重新激发了对“AI”的兴趣，并带来了机器学习和深度学习的复兴。像Waymo和Tesla这样的公司，凭借深度学习的进步，承诺在几年内实现自动驾驶汽车，进一步助推了媒体头条和训练营报名人数。

对神经网络和深度学习的这场突发兴趣产生了一个有趣的副作用。决策树、支持向量机、逻辑回归等回归技术，在学术界和专业统计领域潜伏了数十年后，乘着深度学习的东风走入了公众视野。与此同时，Scikit-learn 等库为进入该领域设定了较低的门槛。这隐藏的代价是，培养出了一批并不理解这些库或模型如何工作，却仍在使用它们的数据科学专业人士。

由于 *数据科学* 这一学科的演进速度快于人们对其定义的感知需求，因此“数据科学家”角色变得完全不可预测并不罕见。我遇到过几位在财富500强公司担任“数据科学家”头衔的人。有些人编程技术高超，甚至可能有软件工程背景，却对统计显著性一无所知。另一些人则局限在Excel中，几乎不懂SQL，更别提Python或R了。我遇到一些自学了几个Scikit-learn函数的数据科学人员，很快就发现自己举步维艰，因为那只是他们所知道的全部。

这对你意味着什么？你如何在如此充满流行语且混乱的环境中蓬勃发展？这全取决于你感兴趣的问题或行业类型，以及不要急于依赖雇主来定义角色。你不必成为 *数据科学家* 就能从事数据科学。鉴于你现在拥有的知识，有许多领域可以供你发挥优势。你可以是 *分析师*、*研究员*、*机器学习工程师*、*顾问*、*咨询师*，以及许多其他不一定被称为 *数据科学家* 的角色。

但首先，让我们探讨一些你可以继续学习并在数据科学就业市场中找到自身优势的方法。

## 寻找你的优势

一名实践中的数据科学专业人士需要的不仅仅是对统计学和机器学习的理解才能蓬勃发展。在大多数情况下，指望为机器学习和其他项目轻松获得现成数据是不合理的。相反，你会发现自己在追逐数据源、编写脚本和软件、抓取文档、抓取Excel工作簿，甚至创建自己的数据库。至少95%的编码工作与机器学习或统计建模完全无关，而是创建、移动和转换数据，使其可用。

除此之外，你还必须了解大局以及所在组织的动态。你的经理在定义你的角色时可能会做出假设，识别这些假设非常重要，这样你才能认识它们如何影响你。当你依赖客户和领导提供行业专业知识时，你应处于能够提供技术知识并阐述什么是可行的角色。让我们看看你可能需要的一些硬技能和软技能。

## SQL 精通

SQL，也称为 *结构化查询语言*，是一种用于检索、转换和写入表数据的查询语言。*关系型数据库* 是组织数据最常见的方式，将数据存储在彼此相连的表中，很像 Excel 中的 VLOOKUP。MySQL、Microsoft SQL Server、Oracle、SQLite 和 PostgreSQL 等关系型数据库平台都支持 SQL。如你所注意到，SQL 与关系型数据库紧密耦合，以至于“SQL”常被用于关系型数据库的品牌名称中，例如“MySQL”和“Microsoft SQL Server。”

示例8-1是一个简单的SQL查询，用于从`CUSTOMER`表中检索`CUSTOMER_ID`和`NAME`字段，仅针对`STATE`为“TX”的记录。

## *示例8-1. 一个简单的SQL查询*

```
SELECT CUSTOMER_ID, NAME
FROM CUSTOMER
WHERE STATE = 'TX'
```

简单来说，作为数据科学专业人士，不精通SQL就很难有所作为。企业使用数据仓库，而SQL几乎总是获取数据的手段。SELECT、WHERE、GROUP BY、ORDER BY、CASE、INNER JOIN和LEFT JOIN都应该是你熟悉的SQL关键字。了解子查询、派生表、公用表表达式和窗口函数，能让你从数据中获得最大效用。

SQL在让Python或其他编程语言轻松与数据库通信方面也至关重要。如果你想从……向数据库发送SQL查询


Python，你可以将数据作为 Pandas DataFrames、Python 集合和其他结构带回来。

示例 8-2 展示了如何在 Python 中使用 SQLAlchemy 库运行一个简单的 SQL 查询。它将记录作为命名元组返回。请务必下载此 SQLite 数据库文件并将其放在你的 Python 项目中，同时运行 pip install sqlalchemy。

## 示例 8-2. 在 Python 中使用 SQLAlchemy 运行 SQL 查询

```
from sqlalchemy import create_engine, text

engine = create_engine('sqlite:///thunderbird_manufacturing.db')
conn = engine.connect()

stmt = text("SELECT * FROM CUSTOMER")
results = conn.execute(stmt)

for customer in results:
    print(customer)
```

## Pandas 和 NoSQL 呢？

我经常收到关于 SQL "替代品"（如 NoSQL 或 Pandas）的问题。这些实际上并非替代品，而是数据科学工具链中其他位置的不同工具。以 Pandas 为例。在示例 8-3 中，我可以创建一个 SQL 查询来从表 CUSTOMER 中提取所有记录，并将其放入 Pandas DataFrame 中。

## 示例 8-3. 将 SQL 查询导入 Pandas DataFrame

```
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine('sqlite:///thunderbird_manufacturing.db')
conn = engine.connect()

df = pd.read_sql("SELECT * FROM CUSTOMER", conn)
print(df) # prints SQL results as DataFrame
```

在那里，SQL 被用来弥合关系型数据库与我的 Python 环境之间的差距，并将数据加载到 Pandas DataFrame 中。如果我有 SQL 能够处理的高要求计算，那么在数据库服务器上使用 SQL 进行处理，比在本地计算机上使用 Pandas 更高效。简单来说，Pandas 和 SQL 可以协同工作，并非竞争技术。

NoSQL 也是如此，它包括 Couchbase 和 MongoDB 等平台。虽然有些读者可能不同意并提出合理的论点，但我认为将 NoSQL 与 SQL 相比，就像是在比较苹果和橘子。是的，它们都存储数据并提供查询功能，但我不认为这使它们成为竞争对手。它们具有针对不同用例的不同特性。NoSQL 代表 "不仅仅是 SQL"，更适合存储非结构化数据，如图片或自由形式文本文章。SQL 更适合存储结构化数据。SQL 维护数据完整性的积极性高于 NoSQL，尽管这要以计算开销和较低的可扩展性为代价。

## SQL，数据世界的通用语言

2015 年，许多人曾猜测 NoSQL 和 Apache Spark 等分布式数据处理技术将取代 SQL 和关系型数据库。具有讽刺意味的是，SQL 对数据用户来说如此重要，以至于这些平台出于需求添加了 SQL 层。这些分层技术包括 Presto、BigQuery 和 Apache Spark SQL 等。大多数数据问题并非大数据问题，在查询数据方面，没有什么能像 SQL 那样有效。因此，SQL 继续蓬勃发展，并保持其作为数据世界通用语言的地位。

## 编程熟练度

通常，许多数据科学家并不擅长编码，至少没有达到软件工程师的水平。然而，他们具备编码能力变得越来越重要。这提供了一个获得竞争优势的机会。学习面向对象编程、函数式编程、单元测试、版本控制（例如 GIT 和 GitHub）、大 O 算法分析、密码学，以及你遇到的其他相关计算机科学概念和语言特性。

理由如下。假设你基于给定的一些示例数据创建了一个有前途的回归模型，比如逻辑回归或神经网络。你请求 IT 部门内部的程序员将其 "插入" 到现有软件中。

他们怀疑地审视你的提案。"我们需要用 Java 重写这个，而不是 Python，" 他们不情愿地说。"你的单元测试在哪里？" 另一个人问道。"你没有定义任何类或类型吗？我们必须将这段代码重构为面向对象的。" 此外，他们不理解你模型的数学原理，并且有理由担心它在未见过的数据上会表现异常。由于你没有定义单元测试（在机器学习中这并不容易），他们不确定如何验证模型的质量。他们还询问如何管理两个版本的代码（Python 和 Java）。

你开始感到手足无措，并说 "我不明白为什么 Python 脚本不能直接插入。" 其中一人若有所思地停顿了一下，回答说 "我们可以用 Flask 创建一个 Web 服务，从而避免用 Java 重写。然而，其他担忧并不会消失。然后我们还要担心可扩展性和高流量对 Web 服务的冲击。等等……也许我们可以将其部署到 Microsoft Azure 云作为虚拟机规模集，但我们仍然需要设计后端。听着，无论你采取什么方法，这都必须重新设计。"

这正是为什么许多数据科学家的工作从未离开他们的笔记本电脑。事实上，将机器学习投入生产变得如此难以捉摸，以至于近年来它成了独角兽和热门话题。数据科学家和软件工程师之间存在巨大的差距，因此数据科学专业人士自然面临着必须成为软件工程师的压力。

这听起来可能令人难以承受，因为数据科学的范围已经负荷过重，包含许多学科和要求。然而，这并非为了表明你需要学习 Java。你可以用 Python（或你偏好的任何实用语言）成为一名高效的软件工程师，但你必须精通它。学习面向对象编程、数据结构、函数式编程、并发以及其他设计模式。两本针对这些 Python 主题的好书包括 Luciano Ramalho 撰写的 *精通 Python，第 2 版* 和 Al Sweigart 撰写的 *超越 Python 基础*。

## Jupyter Notebooks 呢？

数据科学家经常因为编写糟糕的代码而名声不佳。这有很多原因，但一个可能的罪魁祸首可能是 Jupyter Notebooks 鼓励的工作流程。

你可能会想知道为什么我在这本书的整个过程中都没有使用（或鼓励使用）Jupyter Notebooks。Jupyter Notebooks 是一个流行的平台，用于编写数据科学代码，但它允许你将笔记、可运行的代码片段以及控制台/图表输出放在一个地方。它们可以是一个有用的工具，并提供了一种方便的方式来用数据讲述故事。

话虽如此，除非你的雇主要求，否则 Notebooks 并不是进行数据科学工作的必要条件。本书涵盖的所有内容都是在没有 Notebooks 的情况下使用纯 Python 完成的。我这样做是有意为之，因为我不想让读者承担设置额外工具的负担。这可能违背常规，但你可以在不接触 Notebooks 的情况下拥有健康的职业生涯。

理由如下：Notebooks 鼓励不良的编程习惯。Notebooks 鼓励强调线性而非模块化的工作流程，这意味着它们不利于编写可重用的代码。可重用性可以说是软件编程最基本的目标。此外，包含代码片段的 Notebook 单元可以按任意顺序运行，或多次重新运行。如果不小心，你可能会创建混乱的状态和错误，最好的情况是产生明显的错误，最坏的情况是产生不易被察觉的微妙计算错误。特别是如果你是初学者，这是一种令人沮丧的学习 Python 的方式，因为这些技术陷阱对新手来说并不明显。这也是一种提出并呈现发现的方式，却只能发现这是 bug 的结果，因此好得难以置信。

## 锚定偏差与第一门编程语言

技术专家对技术和平台（尤其是编程语言）产生偏爱并投入情感是很常见的。请不要这样做！这种部落主义不仅无效，而且忽视了每种编程语言都针对不同特性和用例这一现实。另一现实是，有些编程语言流行起来，而有些则不然，这往往与语言设计的优劣无关。如果一家大公司不为其提供支持付费，那么它的生存机会就渺茫。

我们在第3章讨论过不同类型的认知偏差。另一种是锚定偏差，它指出我们可能会对所学的第一件事（例如编程语言）产生偏爱。如果你觉得有义务学习一门新语言，请保持开放的心态并给它一个机会！没有一种语言是完美的，重要的是它能完成工作。

不过，如果语言的支持存疑——因为它已濒临停止维护、不再接收更新或缺乏企业维护者——则需谨慎。示例包括 Microsoft 的 VBA、Red Hat 的 Ceylon 和 Haskell。

### JAVA 数据科学库

虽然 Java 不像 Python 数据科学库那样流行，但它确实有几个受到强力支持的等效库。ND4J 是 JVM 上的 NumPy，SMILE 是 Scikit-learn，TableSaw 是 Pandas 的 Java 等效库。

Apache Spark 实际上是基于 Java 平台编写的，具体使用 Scala。有趣的是，Apache Spark 一直试图推动 Scala 成为数据科学的主流语言，尽管它并未达到 Scala 社区可能希望的程度。这就是为什么投入了大量精力来添加 Python、SQL 和 R 的兼容性，而不仅仅是 Java 和 Scala。

### 数据可视化

你应该具备一定程度的另一项技术技能是数据可视化。要习惯制作图表、图形和绘图，它们不仅能向管理层讲述故事，还能帮助你自己的数据探索工作。你可以用 SQL 命令汇总数据，但有时条形图或散点图能在更短的时间内让你更好地了解数据。

说到使用什么工具进行数据可视化，这就难回答得多了，因为选择太多。如果你在传统办公环境中工作，Excel 和 PowerPoint 通常是首选的可视化工具，你知道吗？它们完全足够好！我不是什么都用它们，但它们确实能完成大部分任务。需要在中小型数据集上做散点图？或者直方图？不成问题！将数据复制粘贴到 Excel 工作簿后，几分钟内就可以生成一个。这非常适合一次性的图表可视化，当 Excel 管用时，使用它毫无羞耻感。

不过，有些情况下你可能希望通过脚本生成图表，以便可重复、可重用，或与你的 Python 代码集成。

matplotlib 已成为事实标准有一段时间了，当 Python 是你的平台时，它很难避开。Seaborn 在 matplotlib 之上提供了一个包装器，使其更易于用于常见图表类型。SymPy（本书中我们大量使用）使用 matplotlib 作为其后端。不过，有些人认为 matplotlib 如此成熟，以至于接近遗留状态。

像 [Plotly](https://plotly.com/python/) 这样的库正在兴起，使用起来很不错，它基于 JavaScript D3.js 库。就我个人而言，我正在使用 Manim 取得成功。它生成的 3Blue1Brown 风格可视化效果非同凡响，对客户具有“哇！”效果，而且考虑到其强大的动画功能，API 使用起来出乎意料地简单。不过，它是一个年轻的库，尚未成熟，这意味着随着每次发布的演进，你可能会遇到破坏性代码更改。

探索上述所有解决方案不会出错，如果你的雇主/客户没有偏好，你可以找到最适合你的一个。

像 [Tableau](https://www.tableau.com/products/desktop) 这样的商业许可平台，在某种程度上是可行的。它们旨在创建专门用于可视化的专有软件，并创建拖放界面，以便非技术用户也能使用。Tableau 甚至有一份名为《让你组织中的每个人都成为数据科学家》的白皮书，这对前面提到的数据科学家定义问题并无帮助。我发现使用 Tableau 的挑战在于，它只擅长可视化，并且需要昂贵的许可证。虽然你可以通过 TabPy 以某种方式集成 Python，但除非你的雇主想要使用 Tableau，否则你可能会选择使用前面提到的功能强大的开源库。

## 软件许可可能充满政治色彩

想象一下，你创建了一个 Python 或 Java 应用程序，它请求用户输入几个值，检索和整理不同的数据源，运行一些高度定制的算法，然后呈现一个可视化和一个显示结果的表格。你在经过几个月的辛苦工作后在会议上展示它，但随后一位经理举手问道：“为什么不直接在 Tableau 中完成呢？”

对于某些经理来说，这是一个难以接受的事实，因为他们知道自己为企业软件许可花费了数千美元，而你却走进来，使用一个功能更强大（尽管使用起来更复杂）且无许可成本的开源解决方案。你可以强调，Tableau 不支持这些算法或你必须创建的集成工作流。毕竟，Tableau 只是一个可视化软件。它不是一个从头开始编码的平台，用于创建定制的、高度量身定制的解决方案。

领导层通常被告知 Tableau、Alteryx 或其他商业工具可以做一切事情。毕竟，他们为之花费了大量资金，并且可能从供应商那里听到了精彩的销售推介。当然，他们想要证明成本的合理性，并让尽可能多的人使用该许可证。他们可能还额外花费预算培训员工使用该软件，并希望其他人能够维护你的工作。

对此要敏感。如果管理层要求你使用他们付费购买的工具，那么探索一下你是否可以使其正常工作。但是，如果它在你的特定任务中存在局限性或可用性妥协，请礼貌且坦率地指出。

## 了解你的行业

让我们比较两个行业：电影流媒体（例如 Netflix）和航空航天国防（例如 Lockheed Martin）。它们有共同点吗？几乎没有！两者都是技术驱动型公司，但一个是为消费者流媒体电影，另一个是在制造携带武器的飞机。

在就人工智能和系统安全提供建议时，我首先指出的一点是，这两个行业对风险的容忍度非常不同。一家电影流媒体公司可能宣称他们有一个“AI”系统，可以学习向消费者推荐什么电影，但当它给出糟糕的推荐时，后果有多严重？最坏的情况是，你有一个略显恼火的消费者，浪费了2小时观看一部他不喜欢的电影。

但是航空航天国防公司呢？如果一架战斗机上搭载了一台会自动射击目标的“AI”，如果它出错了，后果会有多严重？我们现在谈论的是人的生命，而不是电影推荐！

这两个行业之间的风险容忍度差距很大。当然，航空航天国防公司在实施任何实验性系统时会保守得多。这意味着官僚程序和安全工作组会评估并叫停他们认定风险不可接受的项目，这也是理所当然的。然而，有趣的是，硅谷初创公司在人工智能方面的成功（大多集中在电影推荐等低风险应用中）在国防行业高管和领导层中引发了 FOMO（“错失恐惧症”）。这可能是因为这两个领域之间风险容忍度的差异没有得到充分强调。

当然，这两个行业之间存在广泛的风险严重程度谱系，从“用户恼火”到“生命损失”。银行可能使用 AI 来确定谁有资格获得贷款，但这存在歧视某些人口群体的风险。刑事司法系统已经在假释和监控系统中尝试使用 AI，却遇到了同样的歧视问题。社交媒体可能使用 AI 来确定哪些用户帖子是可接受的，但在抑制“无害”内容（误报）时会惹恼用户，在未抑制“有害”内容（漏报）时会惹恼立法者。

这表明了解你所在的行业很重要。如果你想进行大量机器学习，你可能希望在低风险行业工作，在那里误报和漏报不会危险或惹恼任何人。但如果这些都不吸引你，而你想要在“自动驾驶”汽车、航空和医疗等大胆应用上工作，那么请做好准备，你的机器学习模型会被拒绝很多次。

在这些高风险行业，如果需要特定的博士学位和其他正式资格，请不要感到惊讶。即使拥有专业博士学位，误报和漏报也不会神奇地消失。如果你不想


要追求如此专注的专业化，你很可能最好除了机器学习之外，还要学习软件工程、优化、统计学和业务规则系统/启发式等其他工具。

## 高效学习

在2008年的一部单口喜剧特辑中，喜剧演员布莱恩·里根将自己的缺乏好奇心与那些阅读报纸的人形成对比。他指出头版新闻永远不会结束，并表示他无意翻到指定页面去了解结局。“经过9年的审判，陪审团终于做出裁决，内容见第22页C栏……我想我永远不会知道了，”他轻蔑地开玩笑说。接着他将自己与那些翻阅页面的人对比，后者欢呼道：“我想学习！我想成为事物的学习者！”

尽管布莱恩·里根可能本意是自贬，但他也许说对了某件事。仅仅为了学习而学习一个话题几乎毫无动力，而缺乏兴趣并不总是件坏事。如果你拿起一本微积分教材却没有学习目的，你可能最终会感到沮丧和挫败。你需要心中有一个项目或目标，如果你觉得某个话题不感兴趣，何必费心去学习它呢？就我个人而言，当我允许自己对无法找到相关性的主题失去兴趣时，这令人感到无比解放。更令人惊讶的是，我的生产力直线飙升。

这并不意味着你应该缺乏好奇心。然而，外面有那么多信息，确定学习优先级是一项非常宝贵的技能。你可以问为什么某样东西有用，如果得不到明确的答案，就允许自己继续前进！每个人都在谈论自然语言处理吗？这并不意味着你必须去学！大多数企业其实并不需要自然语言处理，所以可以说它不值得你花费精力或时间是可以的。

无论你是工作中有项目，还是自行创建项目进行自学，都要有具体的奋斗目标。只有_你_才能决定什么值得学习，你可以摒弃FOMO，去追求_你_认为有趣且相关的事物。

## 实践者与顾问

这可能是一种概括，但知识专家分为两种类型：实践者和顾问。要找到自己的优势，请辨别你想成为哪一种，并相应地调整你的职业发展。

在数据科学和分析领域，实践者是编写代码、创建模型、挖掘数据并尝试直接创造价值的人。顾问就像咨询顾问，告诉管理层他们的目标是否合理，协助制定战略，并提供方向。有时实践者可以一步步成长为顾问。有时顾问从未做过实践者。每种角色都有其优缺点。

实践者可能喜欢编码、进行数据分析，以及执行能够直接创造价值的具体工作。实践者的好处在于他们真正发展并掌握了硬技能。然而，将自己埋在代码、数学和数据中，容易忽略大局，并与组织和行业的其他部分脱节。我听到管理人员的一个常见抱怨是，他们的“数据科学家”想要处理他们感兴趣的问题，但这些问题并不为组织增加价值。我还听到实践者的抱怨，他们希望获得曝光和向上流动，但在组织中却感到被边缘化和隐藏。

诚然，顾问在某些方面工作更轻松一些。他们向管理人员提供建议和信息，并帮助企业制定战略方向。他们通常不是编写代码或挖掘数据的人，而是帮助管理层招聘从事这些工作的人。职业风险不同，因为他们不需要像实践者那样担心赶冲刺截止日期、处理代码错误或模型表现不佳。但他们确实需要担心保持知识渊博、可信和相关。

要成为一名有效的顾问，你必须非常渊博，了解别人不知道的事情。这些信息必须是关键且相关的，并根据客户的需求进行精细调整。为了保持相关性，你每天都要读、读、再读……寻找并整合他人忽略的信息。仅仅熟悉机器学习、统计学和深度学习是不够的。你还需要关注客户所在行业以及其他行业，跟踪谁在成功、谁在不成功。你还必须学会将正确的解决方案与正确的问题相匹配，在许多人都在寻找“银弹”的商业环境中。要做到所有这些，你必须是一名有效的沟通者，以一种能帮助客户的方式分享信息，而不仅仅是展示你的知识。

顾问最大的风险是提供最终被证明是错误的信息。有些顾问非常擅长将责任转移到外部因素上，比如“行业内没有人预见到这一点”或“这是一个六西格玛事件！”——意味着一件不期望的事件发生的概率是五亿分之一，但它还是发生了。另一个风险是不具备实践者的硬技能，并与业务的技术方面脱节。这就是为什么在家定期练习编码和建模，或者至少将技术书籍作为阅读的一部分是个好主意。

归根结底，一名好的顾问试图成为客户与其最终目标之间的桥梁，通常填补存在的巨大知识差距。这不是为了收取最多工时并制造无谓的工作，而是真正找出困扰客户的问题，帮助他们安然入睡。

## 成功并不总是关于盈利能力

辨别你的客户如何定义“成功”。企业追求人工智能、机器学习和数据科学是为了取得成功，对吧？但什么是成功？

是盈利能力吗？不总是。在我们高度投机的经济中，成功可能是另一轮风险投资融资、实现客户增长或收入增长，或者估值很高，即使公司亏损数百万或数十亿美元。这些指标都与盈利能力无关。

为什么会这样？风险投资对长期布局的容忍度使盈利能力边缘化，认为盈利能力将在遥远的未来实现。然而，这可能正在制造类似于2000年互联网泡沫的泡沫。

归根结底，公司要实现长期成功，必须实现盈利能力，但并不是每个人都有这个目标。许多创始人和投资者只是想乘着增长浪潮，在泡沫破裂前套现，通常是在公司通过首次公募股票（IPO）向公众出售时。

这对你意味着什么？无论你是实践者还是顾问，无论是在初创公司还是财富500强工作，都要认识是什么在驱动你的客户或雇主。他们是在寻求更高的估值？实际的盈利能力？内在价值还是感知价值？这将直接影响你的工作内容以及客户想要听到什么，你可以据此判断自己是否有能力帮助他们。

如果你想了解更多关于风险投资、投机性估值以及初创文化影响的信息，《华尔街日报》作家艾利奥特·布朗和莫琳·法瑞尔合著的*《崇拜“我们”》*非常出色。

当项目围绕工具而非问题进行规划时，项目不太可能成功。这意味着作为顾问，你必须提高倾听技巧，识别客户难以提出的问题，更不用说拥有答案的问题了。如果一家主要快餐连锁店雇佣你来协助“AI战略”，而你看到他们的HR正急于招聘深度学习人才，那么你的工作就是问：“你们试图用深度学习解决什么问题？”如果得不到明确答案，你希望鼓励管理层退后一步，评估他们作为一个行业实际上面临的真正问题是什么。他们在员工排班效率方面存在问题吗？那么他们不需要深度学习。他们需要线性规划！这对一些读者来说可能显得很基本，但当今许多管理人员确实难以做出这些区分。我不止一次遇到供应商和顾问，他们将自己的线性规划解决方案贴上“AI”标签，这在语义上可能与“深度学习”混为一谈。

## 数据科学工作中的注意事项

要了解数据科学就业市场，将其与一部深刻的美国电视节目进行比较可能很有帮助。

2010年，有一部美国电视剧Better Off Ted。其中一集名为“Jabberwocky”（第1季第12集），深刻地反映了企业流行语的问题。在剧中，主角Ted在他的公司编造了一个名为“Jabberwocky”的虚构项目来隐瞒资金。结果有趣地是，他的经理、CEO，最终整个公司都开始“参与”“Jabberwocky”项目，甚至不知道它是什么。事情不断升级，成千上万名员工在假装从事“Jabberwocky”工作，而没有人停下来问他们到底在做什么。原因：没有人愿意承认自己不在圈内，对某件重要的事情一无所知。

“贾伯沃基效应”是一种轶事理论，即一个行业或组织可以延续一个流行语/项目，即使没有人令人满意地定义它是什么。组织可能会周期性地陷入这种行为，允许术语在没有定义的情况下流通，而群体行为则允许这种含糊不清。常见示例可能包括区块链、人工智能、数据科学、大数据、比特币、internet of


事物、量子计算、NFT’s、身处“数据驱动”、云计算和“数字颠覆”。即使是具体、高知名度且明确的项目，也可能变成少数人理解、许多人谈论的神秘热词。

要制止“虚词怪兽效应”（Jabberwocky Effect），你必须成为推动有效对话的催化剂。要对项目或举措的方法和手段（而非仅仅是品质或结果）保持好奇。就职位而言，公司是雇你来做“虚词怪兽”工作，还是做实际且具体的项目？他们是否成了热词的受害者，因“错失恐惧症”（FOMO）而雇佣你？或者，他们是否确实有具体且功能性的需求需要雇佣你？做出这种甄别，可能意味着良好匹配且顺利进行，与职业生涯中令人沮丧的阻碍之间的区别。

有了这个背景，让我们现在来看看数据科学工作中需要注意的几个方面，先从角色定义开始。

## 角色定义

假设你被聘为数据科学家。面试很成功。你询问了关于角色的问题，并得到了直接的回答。你得到了工作机会，最重要的是，你应该知道自己将从事哪些项目。

你始终希望进入一个定义明确、目标具体的角色。不需要猜测自己应该做什么。更好的是，你应该拥有有清晰愿景且了解业务需求的领导层。你将成为明确目标的执行者，并了解你的客户。

相反，如果你被雇佣是因为部门想要“数据驱动”或在“数据科学”方面获得竞争优势，这则是一个危险信号。你很可能会被负担得去寻找待解决的问题，并推销你发现的任何“易得之果”。当你寻求战略指导时，你会被要求将“机器学习”应用于业务。当然，当你只有一把锤子时，看什么都像钉子。

数据科学团队在没有目标或待解决的问题之前就被迫拥有一个解决方案（例如机器学习），因此感到压力。一旦找到问题，就发现利益相关者认可和资源对齐很困难，注意力开始在不同的“易得之果”之间跳跃。

问题在于，你是基于热词而非职能被雇佣的。糟糕的角色定义往往会传递到接下来讨论的其他问题。让我们继续讨论组织焦点。

## 组织焦点与认可

另一个需要注意的因素是组织在具体目标上有多一致，以及所有相关方是否都已认可。

自数据科学兴起以来，许多组织重组以建立中央数据科学团队。高管们的愿景是让数据科学团队四处游走、提供建议，并帮助其他部门实现“数据驱动”并采用机器学习等创新技术。他们还可能被要求打破部门间的数据孤岛。虽然这在纸上听起来不错，但许多组织发现这充满挑战。

原因如下：管理层建立了数据科学团队，但没有明确的目标。因此，这个团队被指派去寻找待解决的问题，而不是被授权去解决已知问题。如前所述，这就是为什么数据科学团队臭名昭著地在拥有目标之前就有了解决方案（例如机器学习）。他们尤其不具备成为打破“数据孤岛”的推动力的条件，因为这完全不在其专业领域内。

## 打破数据孤岛是IT工作！

利用数据科学团队在组织中“打破数据孤岛”是错误的。数据孤岛通常是由于缺乏数据仓库基础设施，部门将数据存储在电子表格和秘密数据库中，而不是集中式支持的数据库。

如果“数据孤岛”被视为一个问题，你需要服务器、云实例、认证的数据库管理员、安全协议以及一个IT特遣队来把这一切整合在一起。这不是数据科学团队能胜任的事情，因为他们很可能没有所需的专业知识、预算和组织权威来完成这件事，除非是在非常小的公司。

一旦发现问题，就发现利益相关者认可和资源对齐很困难。如果发现机会，就需要强有力的领导力来完成以下事项：

- 拥有明确定义的目标和路线图
- 获得收集数据和支持基础设施的预算
- 获得数据访问权限并谈判数据所有权
- 包括利益相关者认可和领域知识
- 为利益相关者预算时间和会议

在聘用数据科学团队之后完成上述要求要比之前困难得多，因为数据科学团队的角色是在被动中界定和预算的。如果更高层的领导没有与所有必要方对齐资源和认可，数据科学项目将不会成功。这就是为什么从哈佛商业评论到MIT斯隆管理评论，不乏指责组织未为数据科学做好准备的文章。

最好是在组织上与其客户处于同一部门的数据科学团队工作。信息、预算和沟通会更自由、更紧密地共享。这样一来，紧张感就会减少，因为通过让每个人都“在同一队”而不是竞争关系，跨部门政治得到了缓解。

## 数据访问是政治问题

组织对其数据的保护并非秘密，但这不仅仅是出于安全或不信任的担忧。数据本身是一种高度政治化的资产，许多人甚至不愿向同事提供访问权限。即使是同一组织内部的部门，也不会出于这个原因互相共享数据：他们不希望别人做他们的工作，更不希望别人做错。解释数据可能需要_他们的_全职专业知识，并且需要_他们的_领域知识。毕竟，他们的数据就是他们的生意！如果你要求访问_他们的_数据，那就是在要求进入_他们的_生意。

此外，数据科学家可能会高估自己解释外部数据集并使用其所需领域专业知识的能力。要克服这一障碍，你必须与每个具有专业知识的合作伙伴建立信任和认可，协商知识转移，并在必要时赋予他们项目中的重要角色。

## 充足的资源

另一个需要注意的风险是无法获得完成工作所需的资源。被抛入一个角色却没有所需的东西，这很困难。当然，足智多谋是一种宝贵的特质。但即使是最足智多谋的软件工程师/数据科学明星也可能很快发现自己力不从心。有时你需要花钱的东西，而你的雇主无法为此预算。

假设你需要一个数据库来进行预测工作。你与第三方数据库的连接很差，经常停机和断开连接。你最不想听到的是“让它运行起来”，但这就是你的处境。你考虑在本地复制数据库，但要做到这一点，你需要每天存储40 GB的数据，因此你需要一台服务器或云实例。现在你明显力不从心了，一个“数据科学家”变成了没有IT预算的IT部门！

在这种情况下，你必须思考如何在不损害项目的前提下走捷径。你是否只保留滚动的最新数据并删除其余数据？你是否可以创建一些错误处理Python脚本，在断开连接时重新连接，同时将数据分成批次，以便从上一个成功的批次继续？

如果这个问题/解决方案听起来很具体，是的，我确实不得不这样做，而且确实有效！想出变通方案并精简流程而不产生更多成本，这很令人满意。但是，不可避免地，对于许多数据项目，你可能需要数据管道、服务器、集群、基于GPU的工作站以及台式机无法提供的其他计算资源。换句话说，这些东西可能需要花钱，而你的组织可能无法为此预算。

## 数学建模在哪里？

如果你在想为什么被雇来做回归、统计学、机器学习和其他应用数学，却发现自己在做私自承担的IT工作，这在当前的企业环境中并不少见。

然而，你正在处理数据，这隐含地可能导致类似IT的工作。重要的是，要确保你的技能仍然与工作和所需成果相匹配。我们将在本章余下部分讨论这一点。

## 合理的目标

这是一个需要注意的重要问题。在充斥着炒作和夸大承诺的环境中，很容易遇到不合理的目标。

有些情况下，经理雇佣数据科学家，期望他们轻松入职并为组织增加指数级价值。如果组织仍在做手动工作且自动化机会无处不在，这当然可能发生。例如，如果组织的所有工作都在电子表格中进行，预测完全靠猜测，这对数据科学专业人士来说是一个将流程简化为数据库并用甚至简单的回归模型取得进展的绝佳机会。

另一方面，如果组织雇佣数据科学家将“机器学习”实现到其软件中，特别是识别图像中的对象，这就难得多。一位知识渊博的数据科学家必须向管理层解释，这是一项至少需要数十万美元的项目！不仅需要收集图片，还需要人工劳动



必须雇人为图片中的物体打标签。而这仅仅是数据收集！

数据科学家头18个月常常花在向管理层解释为什么还没有交付成果，这是因为他们仍在努力收集和清洗数据，而这占据了机器学习工作量的95%。
管理层可能因此对这种情况感到失望，因为他们受到了一个流行叙事的误导，认为“机器学习”和“AI”将消除手动流程，结果却发现他们只是用一套手动流程换取了另一套：即获取标注数据。

所以要警惕那些设定不合理目标的环境，并寻找外交方式来管理与管理层的期望，尤其是在他人向他们承诺了“轻松按钮”时。很多声称来自声誉良好的商业期刊和高价管理咨询公司，声称超级智能AI近在咫尺。缺乏技术专长的管理人员可能会陷入这种被炒作的叙事中。

## CUI BONO?

拉丁语表达 cui bono 意为“谁受益？”当你试图理解“杰伯沃基效应”（Jabberwocky Effect）全盛期的行为时，这是一个值得提出的好问题。当媒体宣传关于人工智能的故事时，谁从中受益？无论你的答案是什么，媒体也从点击量和广告收入中受益。高价管理咨询公司围绕“AI战略”创造更多可计费工时。芯片制造商可以推广深度学习来销售更多显卡，云平台可以为机器学习项目销售更多数据存储和CPU时间。

所有这些各方有什么共同点？他们不仅仅是把“AI”作为销售产品的手段，而且他们与客户的成功没有长期利益关系。他们在销售单位，而不是项目成果，就像在淘金热期间出售铲子一样。

不过，我并不是说这些媒体和供应商的动机是不道德的。他们的工作就是为公司赚钱、养家糊口。推广其产品的声明甚至可能是合法且可实现的。但是，不能否认的是，一旦声明被推广出来，就很难收回，即使后来意识到它无法实现。许多企业可能会转变方向并重新分配精力，而不是承认他们的声明未能实现。所以只需意识到这种动态，并始终问一句 cui bono？

## 与现有系统竞争

这种警告可能属于“合理目标”的范畴，但我认为这种情况足够常见，值得单列一类。一种微妙但有问题的角色是与实际上并未损坏的现有系统竞争。这些情况可能出现在缺乏事情可做、需要显得忙碌的工作环境中。

你的雇主几年前聘请供应商安装了一个销售预测系统。你的经理现在要求你通过提高准确率1%来改进预测系统。

你看到这里的统计学问题了吗？如果你读过第3章，1%不应该具有统计显著性，而随机性很容易在你不费吹灰之力的情况下就给你带来1%。相反，随机性可能朝相反方向波动，而你无法控制的市场力量可能会抵消你实施的任何努力。糟糕的销售季度和你无法控制的因素（例如竞争对手进入你公司的市场）会使收入减少-3%，而不是你不可避免地 p-hack 出来的 1%。

这里的总体问题在于，除了工作冗余之外，结果不在你的影响范围内。这可能会变成一种不太理想的情况。如果你竞争的现有系统已经损坏且粗陋，或者完全是手动操作且没有自动化，那倒还好。但与一个并未损坏的系统竞争，就是给自己找麻烦。如果可能，一看到这种项目，就赶紧跑路。

## “你在这里...做什么？”

数据科学家可能被雇佣到一个不产生价值的角色中，尽管工作出色且努力工作？是的。个人无法控制的因素可能会抵消即使是最好的工作，因此保持敏锐观察很重要。

1999年由迈克·贾奇执导的喜剧电影 *办公室空间* 成为美国许多公司职员的邪典经典。在电影中，IT员工兼主角彼得·吉本斯在精神上脱离了向8位不同经理汇报的编程工作。当裁员顾问问他一天在做什么时，他诚实地回答说他“大约只有15分钟是真正的实际工作”。我不会为未读者剧透电影的其余部分，但就像任何伟大的喜剧一样，结果可能与你预期的不一样。

为了阐述前一个例子，替换一个并未损坏的系统，正是已故人类学家大卫·格雷伯所描述的 *垃圾工作*（恕我直言）。根据格雷伯的说法，*垃圾工作*是指薪酬工作，其完全毫无意义、不必要或有害，以至于连员工本人都无法证明其存在的合理性，却不得不假装否则。在他的著作和2013年的病毒式文章中，格雷伯理论认为这些工作变得如此普遍，以至于对劳动力和经济造成了心理打击。

尽管格雷伯的研究充斥着自我选择偏见和轶事发现，缺乏经验证据是一个可被批评的论点，但要声称这些 *垃圾工作* 不存在却很困难。为格雷伯辩护的是，这在经验上很难衡量，且很少有员工会在调查中诚实回答，因为担心危及自己的职业生涯。

数据科学职业能免受这些问题的影响吗？谷歌首席决策科学家卡西·科齐尔科夫（Cassie Kozyrkov）分享了一个奇怪的轶事，有助于回答这个问题：

> 几年前，一位在科技公司担任工程总监的朋友抱怨他那群没用的数据科学家。“我认为你雇佣数据科学家的方式就像毒枭为自家后院买老虎一样，”我告诉他。“你不知道自己想要老虎干什么，但所有其他毒枭都有一只。”
> >
> > ——卡西·科齐尔科夫

哎呀。管理层是否可能雇佣数据科学家来提升组织的感知可信度和企业地位？如果你发现自己处于一个不旨在创造价值的工作中，请从战略上思考如何推动积极变革。你能否创造机会，而不是等待他人提供？你能否有意义地对你识别出的项目承担责任，从而发展你的职业生涯？如果这不可能，请赋予自己权力去追求更好的机会。

## 角色并非你所期望的

当你开始一份工作并发现它不是你所期望的那样时，你会怎么做？例如，你被告知你的角色将是统计学和机器学习，但你发现自己反而在做类似IT的工作，因为组织的数据基础根本不足以进行机器学习。

你或许能“将柠檬变成柠檬水”。你当然可以接受你的“数据科学家”角色转变为IT角色，并在过程中获得一些数据库和编程技能。你甚至可能成为不可或缺的“SQL专家”或“技术大师”，并且在职业上感到自在。当你简化企业的数据运营和工作流程时，你正在为企业未来更好地应对更复杂的应用做好准备。当你的运营顺利运行时，你可以分配时间在感兴趣的领域学习并专业成长。

另一方面，如果你期望做统计分析和机器学习，却发现自己在调试损坏的电子表格、Microsoft Access 和 VBA 宏，你可能会感到失望。在这种情况下，至少要成为变革的倡导者。推动工具现代化，倡导使用 Python 和现代数据库平台，如 MySQL 或甚至 SQLite。如果你能做到这一点，那么至少你将处于一个允许更多创新的平台上，并且离应用本书中的概念更近一步。这也将惠及组织，因为工具支持和灵活性将提高，而 Python 人才比 Microsoft Access 和 VBA 等过时技术更容易获得。





## 什么是影子 IT？

Shadow IT (or Shadow “Information Technology”) is a term describing office workers who create systems outside their IT department. These systems can include databases, scripts, and processes, as well as vendor and employee-made software without the IT department’s involvement.

影子 IT（或影子“信息技术”）是一个术语，用来描述在 IT 部门之外创建系统的办公室工作人员。这些系统可以包括数据库、脚本和流程，以及供应商和员工制作的未经 IT 部门参与的软件。

Shadow IT used to be frowned on in organizations, as it is unregulated and operating outside the IT department’s scope of control. When finance, marketing, and other non-IT departments decide to hand-spin their own rogue IT operations, it certainly can create hidden costs to the organization in inefficiency and security concerns. Nasty politics can ensue where IT departments and non-IT departments clash, accusing each other of not staying in their lane or simply co-opting roles for job security.

在组织中，影子 IT 过去常常不被看好，因为它缺乏监管，且在 IT 部门的控制范围之外运行。当金融、营销及其他非 IT 部门决定自行搞起“流氓 IT”操作时，这肯定会给组织带来低效率和安全隐患等隐形成本。当 IT 部门和非 IT 部门发生冲突时，会引发肮脏的政治斗争，双方互相指责对方不守本分，或者单纯为了保住工作而揽职。

However, one benefit of the data science movement is it has made shadow IT more accepted as a necessity for innovation. Non-IT folks can prototype and experiment with creating datasets, Python scripts, and regression tools. The IT department can then pick up these innovations and support them formally as they mature. This also allows the business to become more nimble. A business rule change can be a quick edit to a Python script or in-house database, rather than filing a ticket with the IT help desk. Whether that change should be subject to rigorous testing and red tape is certainly a cost trade-off for responsiveness.

不过，数据科学运动的一项好处是，它使得影子 IT 作为创新的必需品被更广泛接受。非 IT 人员可以在创建数据集、Python 脚本和回归工具方面进行原型设计和实验。随后，IT 部门可以将这些创新拾起来，在其成熟后提供正式支持。这也让企业变得更加敏捷。业务规则变更可以是对 Python 脚本或内部数据库的快速编辑，而不是向 IT 帮助台提交工单。该变更是否应经过严格测试和繁文缛节，这肯定是响应速度与成本之间的权衡。

Overall, if you find yourself in a Shadow IT role (which is likely) make sure you understand the risks and play nice with the IT department. If you are successful, it can be empowering and rewarding to support your business this way. If you sense possible conflict with your IT department, be upfront with your leadership and let them know. If you can truthfully say your work is “prototyping” and “exploration” then your leadership can argue it is outside the IT purview. Never go rogue without your leadership’s support though, and let them deal with the interdepartmental politics.

总的来说，如果你发现自己身处影子 IT 角色（很可能如此），请务必了解风险，并与 IT 部门友好相处。如果你成功了，以这种方式支持业务会令人感到自信且有成就感。如果你感觉到与 IT 部门可能存在冲突，要向领导坦诚并告知他们。如果你能诚实地说自己的工作是“原型设计”和“探索”，那么你的领导可以主张这不在 IT 部门的职权范围内。不过，在没有领导支持的情况下绝不能独断专行，让他们来处理跨部门政治。

## Does Your Dream Job Not Exist?

## 你的梦想工作不存在吗？

While you can always walk away when a role, always be sure to assess how realistic your expectations are too. Are the cutting-edge technologies you are pursuing perhaps too cutting-edge?

虽然你随时可以离开某个职位，但也务必评估一下你的期望有多现实。你追求的前沿技术，也许太过“前沿”了吗？

Take natural language processing for example. You want to build chatbots using deep learning. However, the number of actual jobs that do this are scarce, as most companies do not have practical need for chatbots. Why? Chatbots are simply not there yet. While companies like OpenAI have interesting research like GPT-3, that is mostly what it amounts to: interesting research. GPT-3 in the end is a probability-based pattern recognizer chaining words together, and therefore it has no common sense. There is research demonstrating this, including some by Gary Marcus at New York University.

以自然语言处理为例。你想用深度学习构建聊天机器人。然而，实际从事这项工作的职位寥寥无几，因为大多数公司并没有聊天机器人的实际需求。为什么？聊天机器人尚未成熟。虽然 OpenAI 等公司有 GPT-3 等有趣的研究，但这大多不过是有趣的研究罢了。归根结底，GPT-3 只是一个基于概率的模式识别器，将单词串联在一起，因此它没有常识。有研究证明了这一点，包括纽约大学 Gary Marcus 的一些研究。

https://cs.nyu.edu/~davise/papers/GPT3CompleteTests.html

This means creating chatbots with broader applications is an open problem, and has yet to be a value proposition for a great majority of businesses. If natural language processing is something you really want to pursue, and you are finding a disconnect with career opportunities, your best bet might be to go into the academic world and do research. While there are companies like Alphabet that do academic-like research, many of those employees came from academia.

这意味着创建具有更广泛应用的聊天机器人是一个开放问题，对于绝大多数企业来说，尚未成为价值主张。如果你真正想追求自然语言处理，却发现与职业机会存在脱节，那么你的最佳选择可能是进入学术界进行研究。虽然 Alphabet 等公司也进行类似学术的研究，但这些员工中的许多人来自学术界。

So again, keep your expectations realistic as you navigate the job market. If your expectations exceed what the job market can provide, strongly consider the academic route. You also should consider this route when the type of jobs you want frequently requires a PhD or specific academic credentials, and this becomes a barrier to doing your dream job.

因此，在求职过程中，请保持期望现实。如果你的期望超出了就业市场所能提供的，请强烈考虑学术路线。当你想要的工作类型经常要求博士学位或特定的学术资格，而这成为你从事梦想工作的障碍时，也应考虑这条路线。

## Where Do I Go Now?

## 我该何去何从？

Now that we covered the data science landscape, how to gain an edge with further skill development, and career issues to watch out for, where do we go from here? And what is the future of data science?

既然我们已经涵盖了数据科学版图、如何通过进一步的技能发展获得优势，以及需要留意的职业问题，那么接下来我们该去哪里？数据科学的未来又是什么？

First consider the burdens of having a data scientist job title. It carries an implicit requirement to have knowledge without boundaries, mostly due to the lack of standardized definition with a restricted scope. If we learned anything from the last 10 years watching the data science movement, definition matters. A data scientist is evolving to be a software engineer with proficiency in statistics, optimization, and machine learning. A data scientist may not even have that “data scientist” title anymore. While this is a much broader umbrella of requirements than when the data scientist was declared the “sexiest job of the 21st century” it is becoming necessary to have these skills.

首先，考虑拥有数据科学家职位名称所带来的负担。它隐含地要求具备无边界的知识，这主要是因为缺乏范围受限的标准化定义。如果我们在过去10年中从观察数据科学运动学到了什么，那就是定义很重要。数据科学家正在演变为精通统计学、优化和机器学习的软件工程师。数据科学家甚至可能不再拥有“数据科学家”这个头衔了。虽然与数据科学家被命名为“21世纪最性感的工作”时相比，这是一个范围更广泛的要求伞状结构，但掌握这些技能正在变得必要。

Another option is to specialize in favor of more focused titles, and this has been happening increasingly for the past few years. Roles like computer vision engineer, data engineer, data analyst, researcher, operations research analyst, and advisor/consultant are making a comeback. We are seeing less of the “data scientist” role and this trend is likely to continue in the next 10 years, primarily due to role specialization. It is certainly an option to follow this trend.

另一种选择是朝着更专注的职称进行专业化，过去几年这种趋势越来越明显。计算机视觉工程师、数据工程师、数据分析师、研究员、运筹分析师以及顾问/咨询师等角色正在卷土重来。我们看到的“数据科学家”角色越来越少，而且这一趋势在未来10年很可能会继续，主要是因为角色专业化。遵循这一趋势当然是一个选择。

It is critical to note that the labor market has changed drastically, and this is why you need the competitive edges listed in this chapter. While data scientists were seen as unicorns in 2014 commanding 6-figure salaries, nowadays a given “data scientist” job at any company can easily receive hundreds or thousands of applications while only offering a 5-figure salary. Data science degrees and boot camps have created an enormous boom of supply in data science professionals. Therefore it is competitive landing jobs marketed as “data scientist” or “data science” in general. This is why going after roles like “analyst”, “operations research”, and “software developer” is not necessarily a bad idea! Vicki Boykis, a machine learning engineer at Tumblr, probably says it best on her blog article Data Science is Different Now:

必须指出，劳动力市场已经发生了巨大变化，这就是为什么你需要本章列出的竞争优势。2014年，数据科学家被视为独角兽，拿着六位数的薪水；如今，任何公司的一个“数据科学家”职位都可能收到数百甚至数千份申请，却只提供五位数的薪水。数据科学学位和训练营在数据科学专业人才供应方面制造了巨大的繁荣。因此，找到标榜为“数据科学家”或一般“数据科学”的工作很有竞争力。这就是为什么去追求“分析师”、“运筹”和“软件开发人员”等职位并不一定是个坏主意！Tumblr 的机器学习工程师 Vicki Boykis 在她的博客文章《Data Science is Different Now》中或许说得最好：

> Remember that the ultimate goal... is to beat the hordes doing data science degrees, bootcamps, and working through tutorials.
>
> You want to get your foot in the door, **get a data-adjacent position**, and move towards whatever your dream job is, while finding out as much as you can about the tech industry in general.

## Conclusion

## 结论

This was a different chapter from the rest in this book, but it is important if you want to navigate the data science job landscape and effectively apply the knowledge in this book. It might be disconcerting to learn statistical tools and machine learning, only to find much of the job landscape will pivot you into other work. When this happens, take the opportunity to continue learning and gaining skills. When you integrate your essential math knowledge with a programming and software engineering proficiency, your value will increase tenfold just from having an understanding of the IT and data science gap.

本章与本书其他章节不同，但如果你想在数据科学就业版图中导航，并有效应用本书中的知识，它就很重要。学习统计工具和机器学习，却发现大部分就业版图会将你引向其他工作，这可能会让人不安。当这种情况发生时，抓住机会继续学习和获得技能。当你将基本的数学知识与编程和软件工程熟练度相结合时，仅仅了解 IT 和数据科学之间的差距，你的价值就会增加十倍。

Remember to eschew the hype in favor of practical solutions, and do not get so caught up in the technical purview that you become blindsided by market forces. Understand management and leadership motivations, as well as the motivation of people in general. Understand *why* things work, not just *how* they work. Be curious *why* a technique or tool solves a problem, not just *how* the technical aspects of it operate.

请记住，要摒弃炒作，转而采用实际解决方案，不要过于沉迷于技术范畴以至于被市场力量蒙蔽。要了解管理层和领导的动机，以及人们普遍的动机。要理解事情*为什么*有效，而不仅仅是*如何*有效。要好奇一种技术或工具*为什么*能解决问题，而不仅仅是*它的技术方面如何运作*。

Learn not for the sake of it, but to develop capabilities and pair the right tool to the right problem. One of the most effective ways to learn is to pick a problem (not a tool!) you find interesting. Pulling that thread leads to another thing to be curious about, and then another, and then another. You have a goal in mind, so continue going down the right rabbit holes and know when to pull yourself out of others. It is absolutely rewarding to take this approach, and it is amazing how much expertise you can gain in a short amount of time.

学习不是为了学习而学习，而是为了发展能力，并将合适的工具与合适的问题配对。最有效的学习方法之一是选择一个你感兴趣的问题（不是工具！）。沿着这个线索追寻下去，会引出另一个值得好奇的事物，然后是另一个，再另一个。你心中有一个目标，所以继续钻研正确的“兔子洞”，并知道何时从其他“兔子洞”中抽身出来。采取这种方法绝对很有收获，你会惊讶于在短时间内能获得多少专业知识。
