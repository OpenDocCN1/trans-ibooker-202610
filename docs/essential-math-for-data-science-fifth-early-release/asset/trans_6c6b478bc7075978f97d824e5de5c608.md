## 锚定偏差与第一门编程语言

技术专家对技术和平台（尤其是编程语言）产生偏爱并投入情感是很常见的。请不要这样做！这种部落主义不仅无效，而且忽视了每种编程语言都针对不同特性和用例这一现实。另一现实是，有些编程语言流行起来，而有些则不然，这往往与语言设计的优劣无关。如果一家大公司不为其提供支持付费，那么它的生存机会就渺茫。

我们在第3章讨论过不同类型的认知偏差。另一种是锚定偏差，它指出我们可能会对所学的第一件事（例如编程语言）产生偏爱。如果你觉得有义务学习一门新语言，请保持开放的心态并给它一个机会！没有一种语言是完美的，重要的是它能完成工作。

不过，如果语言的支持存疑——因为它已濒临停止维护、不再接收更新或缺乏企业维护者——则需谨慎。示例包括 Microsoft 的 VBA、Red Hat 的 Ceylon 和 Haskell。

### JAVA 数据科学库

虽然 Java 不像 Python 数据科学库那样流行，但它确实有几个受到强力支持的等效库。ND4J 是 JVM 上的 NumPy，SMILE 是 Scikit-learn，TableSaw 是 Pandas 的 Java 等效库。

Apache Spark 实际上是基于 Java 平台编写的，具体使用 Scala。有趣的是，Apache Spark 一直试图推动 Scala 成为数据科学的主流语言，尽管它并未达到 Scala 社区可能希望的程度。这就是为什么投入了大量精力来添加 Python、SQL 和 R 的兼容性，而不仅仅是 Java 和 Scala。

### 数据可视化

你应该具备一定程度的另一项技术技能是数据可视化。要习惯制作图表、图形和绘图，它们不仅能向管理层讲述故事，还能帮助你自己的数据探索工作。你可以用 SQL 命令汇总数据，但有时条形图或散点图能在更短的时间内让你更好地了解数据。

说到使用什么工具进行数据可视化，这就难回答得多了，因为选择太多。如果你在传统办公环境中工作，Excel 和 PowerPoint 通常是首选的可视化工具，你知道吗？它们完全足够好！我不是什么都用它们，但它们确实能完成大部分任务。需要在中小型数据集上做散点图？或者直方图？不成问题！将数据复制粘贴到 Excel 工作簿后，几分钟内就可以生成一个。这非常适合一次性的图表可视化，当 Excel 管用时，使用它毫无羞耻感。

不过，有些情况下你可能希望通过脚本生成图表，以便可重复、可重用，或与你的 Python 代码集成。

matplotlib 已成为事实标准有一段时间了，当 Python 是你的平台时，它很难避开。Seaborn 在 matplotlib 之上提供了一个包装器，使其更易于用于常见图表类型。SymPy（本书中我们大量使用）使用 matplotlib 作为其后端。不过，有些人认为 matplotlib 如此成熟，以至于接近遗留状态。

像 [Plotly](https://plotly.com/python/) 这样的库正在兴起，使用起来很不错，它基于 JavaScript D3.js 库。就我个人而言，我正在使用 Manim 取得成功。它生成的 3Blue1Brown 风格可视化效果非同凡响，对客户具有“哇！”效果，而且考虑到其强大的动画功能，API 使用起来出乎意料地简单。不过，它是一个年轻的库，尚未成熟，这意味着随着每次发布的演进，你可能会遇到破坏性代码更改。

探索上述所有解决方案不会出错，如果你的雇主/客户没有偏好，你可以找到最适合你的一个。

像 [Tableau](https://www.tableau.com/products/desktop) 这样的商业许可平台，在某种程度上是可行的。它们旨在创建专门用于可视化的专有软件，并创建拖放界面，以便非技术用户也能使用。Tableau 甚至有一份名为《让你组织中的每个人都成为数据科学家》的白皮书，这对前面提到的数据科学家定义问题并无帮助。我发现使用 Tableau 的挑战在于，它只擅长可视化，并且需要昂贵的许可证。虽然你可以通过 TabPy 以某种方式集成 Python，但除非你的雇主想要使用 Tableau，否则你可能会选择使用前面提到的功能强大的开源库。

## 软件许可可能充满政治色彩

想象一下，你创建了一个 Python 或 Java 应用程序，它请求用户输入几个值，检索和整理不同的数据源，运行一些高度定制的算法，然后呈现一个可视化和一个显示结果的表格。你在经过几个月的辛苦工作后在会议上展示它，但随后一位经理举手问道：“为什么不直接在 Tableau 中完成呢？”

对于某些经理来说，这是一个难以接受的事实，因为他们知道自己为企业软件许可花费了数千美元，而你却走进来，使用一个功能更强大（尽管使用起来更复杂）且无许可成本的开源解决方案。你可以强调，Tableau 不支持这些算法或你必须创建的集成工作流。毕竟，Tableau 只是一个可视化软件。它不是一个从头开始编码的平台，用于创建定制的、高度量身定制的解决方案。

领导层通常被告知 Tableau、Alteryx 或其他商业工具可以做一切事情。毕竟，他们为之花费了大量资金，并且可能从供应商那里听到了精彩的销售推介。当然，他们想要证明成本的合理性，并让尽可能多的人使用该许可证。他们可能还额外花费预算培训员工使用该软件，并希望其他人能够维护你的工作。

对此要敏感。如果管理层要求你使用他们付费购买的工具，那么探索一下你是否可以使其正常工作。但是，如果它在你的特定任务中存在局限性或可用性妥协，请礼貌且坦率地指出。

## 了解你的行业

让我们比较两个行业：电影流媒体（例如 Netflix）和航空航天国防（例如 Lockheed Martin）。它们有共同点吗？几乎没有！两者都是技术驱动型公司，但一个是为消费者流媒体电影，另一个是在制造携带武器的飞机。

在就人工智能和系统安全提供建议时，我首先指出的一点是，这两个行业对风险的容忍度非常不同。一家电影流媒体公司可能宣称他们有一个“AI”系统，可以学习向消费者推荐什么电影，但当它给出糟糕的推荐时，后果有多严重？最坏的情况是，你有一个略显恼火的消费者，浪费了2小时观看一部他不喜欢的电影。

但是航空航天国防公司呢？如果一架战斗机上搭载了一台会自动射击目标的“AI”，如果它出错了，后果会有多严重？我们现在谈论的是人的生命，而不是电影推荐！

这两个行业之间的风险容忍度差距很大。当然，航空航天国防公司在实施任何实验性系统时会保守得多。这意味着官僚程序和安全工作组会评估并叫停他们认定风险不可接受的项目，这也是理所当然的。然而，有趣的是，硅谷初创公司在人工智能方面的成功（大多集中在电影推荐等低风险应用中）在国防行业高管和领导层中引发了 FOMO（“错失恐惧症”）。这可能是因为这两个领域之间风险容忍度的差异没有得到充分强调。

当然，这两个行业之间存在广泛的风险严重程度谱系，从“用户恼火”到“生命损失”。银行可能使用 AI 来确定谁有资格获得贷款，但这存在歧视某些人口群体的风险。刑事司法系统已经在假释和监控系统中尝试使用 AI，却遇到了同样的歧视问题。社交媒体可能使用 AI 来确定哪些用户帖子是可接受的，但在抑制“无害”内容（误报）时会惹恼用户，在未抑制“有害”内容（漏报）时会惹恼立法者。

这表明了解你所在的行业很重要。如果你想进行大量机器学习，你可能希望在低风险行业工作，在那里误报和漏报不会危险或惹恼任何人。但如果这些都不吸引你，而你想要在“自动驾驶”汽车、航空和医疗等大胆应用上工作，那么请做好准备，你的机器学习模型会被拒绝很多次。
