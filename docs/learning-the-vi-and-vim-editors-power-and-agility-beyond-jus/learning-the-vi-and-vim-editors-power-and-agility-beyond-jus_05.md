## 第 4 章 超越基础

你已经了解了基本编辑命令 `i`、`a`、`c`、`d` 和 `y`。本章在你已知的编辑知识基础上进行扩展。它涵盖：

* 对额外编辑功能的描述，并回顾通用命令形式
* `vi` 和 Vim 命令行选项，包括以不同方式打开文件进行编辑
* 使用存储 yank 和删除的寄存器
* 在文件中标记你的位置
* 其他高级编辑

## 更多命令组合

# 启动 vi 和 Vim 时的选项

到目前为止，你已通过以下命令从 shell 调用编辑器：

```
$ vi file
```

或

```
$ vim file
```

`vim` 命令还有其他可能有用的选项。你可以直接打开文件到特定行号或模式。你还可以以只读模式打开文件。另一个选项可以恢复系统崩溃时你正在编辑的文件的所有更改。

以下各节描述的选项适用于 `vi` 和 Vim。

## 前进到特定位置

当你开始编辑现有文件时，可以调入文件，然后移动到模式的第一次出现处或特定行号。你也可以直接在命令行上通过搜索或行号指定第一次移动。你可以使用 `-c` `command` 来执行此操作；为了与早期版本的 `vi` 保持向后兼容，你也可以使用 `+` `command`：

`$ vim -c` `n file`

:

打开 `file` 在第 n 行。

`$ vim -c /` `pattern file`

:

在 `pattern` 的第一次出现处打开 `file`。

`$ vim +` `file`

:

在最后一行打开 `file`。

在文件 `practice` 中，要打开文件并直接前进到包含单词 `Screen` 的行，请输入以下内容：

| 按键 | 结果 |
| --- | --- |
| `$ vim -c /Screen practice` | ```
With a screen editor you can scroll
the page, move the cursor, delete
lines, and insert characters, while
seeing the results of your edits as
you make them. Screen editors are
very popular, since they allow you
to make changes as you read
``` |

使用选项 `-c /` `pattern` 给出 `vim` 命令，可直接进入包含 `Screen` 的行。

如本例所示，你的搜索模式不一定位于屏幕顶部。有趣的是，光标放在行的第一个字符上，而不是匹配文本的第一个字符上！如果 `pattern` 中包含空格，必须用单引号或双引号将整个模式括起来：^1

```
-c /"you make"
```

或用反斜杠转义空格：

```
-c /you\ make
```

此外，如果你想使用 第 6 章，“全局替换” 中描述的通用模式匹配语法，可能需要使用单引号或反斜杠来保护一个或多个特殊字符，以免被 shell 解释。

如果必须在完成编辑会话之前离开，使用 `-c /` `pattern` 会很有帮助。你可以通过插入 `ZZZ` 或 `HERE` 等模式来标记位置。然后，当你返回文件时，你只需记住 `/ZZZ` 或 `/HERE`。

编辑器打开你的文件并使用 `-c` 提供的模式进行模式搜索后，你只需使用 `n` 即可继续到该模式的下一个出现位置。

### 注意

通常，在 `vi` 和 Vim 中编辑时，`wrapscan` 选项是启用的。如果你自定义了环境，使 `wrapscan` 始终禁用（参见 “重复搜索” 部分），你可能无法使用 `-c /` `pattern`。如果你尝试这样打开文件，编辑器将在最后一行打开文件并显示消息，“Address search hit BOTTOM without matching pattern。”该消息可能因 `vi` 和 Vim 的不同版本而有所不同。

## 只读模式

有时你想查看文件但又想保护该文件免受意外按键和更改的影响。（你可能想调入一个较长的文件来练习 `vi` 移动，或者你可能想滚动浏览命令文件或程序。）你可以以只读模式进入文件并使用所有常规移动命令，但无法更改文件。

要以只读模式查看文件，请输入以下之一：

```
$ vim -R file
```

或：

```
$ view file
```

（`view` 命令与 Vim 一样，可以使用任何用于前进到文件特定位置的命令行选项。^2）如果你确实决定对文件进行一些编辑，可以通过在 `write` 命令中添加感叹号来覆盖只读模式：

```
:w!
```

或：

```
:wq!
```

请注意，如果你编辑的文件没有写权限，你也将处于只读模式。在这种情况下，如果你拥有该文件，`:w!` 或 `:wq!` 仍然有效；`vi` 会暂时更改文件的权限以允许你写入。否则，保存文件将失败。

如果你在写入文件时遇到问题，请参阅 “保存文件时出现的问题” 部分中的问题清单。

## 恢复缓冲区

在编辑文件时偶尔会发生系统故障。通常，在最后一次写入（保存）后所做的任何编辑都会丢失。然而，有一个选项 `-r`，可以让你在系统崩溃时恢复编辑的缓冲区。

### vi 中的恢复

在使用原始 `vi` 的传统 Unix 系统上，系统重新运行后首次登录时，你会收到一封邮件，说明你的缓冲区已保存。此外，如果你输入以下命令：

```
$ ex -r
```

或：

```
$ vi -r
```

你将获得系统已保存的任何文件的列表。

使用文件名与 `-r` 选项一起恢复编辑的缓冲区。例如，要在系统崩溃后恢复文件 `practice` 的编辑缓冲区，请输入：

```
$ vi -r practice
```

立即恢复文件是明智的，以免你无意中对文件进行编辑，然后必须在保留的缓冲区和新编辑的文件之间解决版本偏差。

你可以通过使用命令 `:pre`（`:preserve` 的简写）强制系统在没有崩溃的情况下保留你的缓冲区。你可能会发现它很有用，如果你对文件进行了编辑，然后发现由于没有写权限而无法保存编辑。（你也可以只将文件的副本写入另一个名称或你拥有写权限的目录。参见 “保存文件时出现的问题” 部分。）

### Vim 中的恢复



Vim 中的恢复工作方式略有不同。Vim 通常将其工作文件（称为 *交换文件*）保存在正在编辑的文件同一目录下。对于 `practice`，Vim 的工作文件将命名为 `.practice.swp`。

如果下次编辑 `practice` 时该文件存在，Vim 会询问你是否要恢复。你应该这样做，并将文件写回。然后你应 *立即退出* 并手动删除 `.practice.swp`；Vim 不会为你执行此操作。完成后，你可以重新进入 Vim 并正常继续编辑文件。

`:set` 命令的 `directory` 选项让你控制 Vim 将交换文件放置的位置。有关更多信息，请参阅 “Vim 8.2 选项” 部分中 表 B-2 中的 `directory` 条目。

# 使用寄存器
你已经看到，在编辑过程中，最后一次删除（`d` 或 `x`）或 yank（`y`）会被保存在未命名寄存器中。你可以访问该寄存器的内容，并使用 put 命令（`p` 或 `P`）将保存的文本放回文件中。

最后九次删除存储在编号寄存器中。你可以访问这些编号寄存器中的任何一个来恢复最近九次删除中的任意一次（或全部）。（然而，仅删除行的一部分的小型删除不会保存在编号寄存器中。这些删除只能在你进行删除后立即使用 `p` 或 `P` 命令恢复。）

你也可以将 yank（复制的文本）放入由字母标识的寄存器中。你可以用 yank 的文本填充最多 26 个寄存器（命名为 a–z），并在编辑会话的任何时候使用 put 命令恢复该文本。

## 恢复删除
一次性删除大块文本的能力很好，但如果你错误地删除了需要的 53 行怎么办？你可以恢复过去的任意 *九次* 删除，因为它们保存在编号寄存器中。最后一次删除保存在寄存器 1 中，倒数第二次保存在寄存器 2 中，以此类推。

要恢复删除，输入 `"`（双引号），通过编号标识被删除的文本，然后给出 put 命令。要恢复倒数第二次删除（来自寄存器 2），输入：

```
"2p
```

寄存器 2 中的删除内容会被放置在光标之后。

如果你不确定哪个寄存器包含要恢复的删除内容，就不必反复输入 `"` `n` `p`。你可以使用 `"1p` 来放置第一次删除的文本；如果不对，使用 `u` 撤销它。然后你可以使用重复命令（`.`）放置下一个，`u` 撤销它，以此类推。在此过程中，编辑器会自动递增寄存器编号。因此，你可以使用以下方法搜索编号寄存器：

```
"1pu.u.u                etc.
```

将每个后续寄存器的内容依次放入文件中。每次输入 `u` 时，恢复的文本会被移除；当输入点（`.`）时，*下一个* 寄存器的内容会被恢复到你的文件中。不断输入 `u` 和 `.` 直到恢复到你要查找的文本。

## yank 到命名寄存器
你已经看到，在进行其他编辑之前，必须先 put（`p` 或 `P`）未命名寄存器的内容，否则寄存器会被覆盖。你也可以使用 `y` 和 `d` 与一组 26 个命名寄存器（a–z），这些寄存器专门用于复制和移动文本。如果你命名一个寄存器来存储 yank 的文本，你可以在编辑会话的任何时候检索该命名寄存器的内容。

要 yank 到命名寄存器，请在 yank 命令前加上双引号（`"`）和你想要加载的寄存器名称的字符。例如：

```
"dyy            Yank the current line into register d
"a7yy           Yank the next seven lines into register a
```

加载命名寄存器并移动到新位置后，使用 `p` 或 `P` 将文本放回：

```
"dP             Put the contents of register d before the cursor
"ap             Put the contents of register a after the cursor
```

没有办法将寄存器的一部分放入文本中——要么全部，要么全不。

在下一章，你将学习如何编辑多个文件。一旦你学会如何在不离开编辑器的情况下在文件间切换，你就可以使用命名寄存器在文件间有选择地传输文本。使用 Vim 的多窗口功能时，你也可以使用未命名删除寄存器在文件间传输数据。

### 注意
未命名和命名删除寄存器在同一 Vim 会话中共享，因此你可以在一个 Vim 会话中的多个窗口编辑的文件之间轻松复制/粘贴文本。但这些缓冲区在多个 Vim 会话之间 *不* 共享！（例如，你可能同时用 `gvim` 打开了多个文件。）然而，`gvim` 可以像任何其他图形应用程序一样访问系统剪贴板。因此，你可以使用 GUI 级别的复制和粘贴在文件间移动文本而不会有问题。

你也可以使用几乎相同的方法将文本删除到命名寄存器中：

```
"a5dd           Delete five lines into register a
```

如果你使用大写字母指定寄存器名称，你的 yank 或删除的文本会 *追加* 到对应小写寄存器的当前内容中。这让你可以选择移动或复制的内容。例如：

`"zd)`
从光标处删除到当前句子的末尾并将文本保存到寄存器 `z` 中。

`2)`
向前移动两个句子。

`"Zy)`
将下一句添加到寄存器 `z`。你可以一直向命名寄存器添加更多文本，但请注意：如果一次忘记，并且在未以大写形式指定其名称的情况下对寄存器进行 yank 或删除，你将覆盖该寄存器，丢失已累积的内容。

# 标记你的位置
在编辑会话期间，你可以用一个不可见的“书签”标记文件中的位置，在其他地方进行编辑，然后返回到标记的位置。为什么需要这样做？Will Gallego 解释道：

> 我最喜欢的标记用途之一是删除/yank/修改大块文本。例如，假设我想删除大量行。我可能不想数清这些行然后执行 `numdd`，而是跳到底部，用类似 `ma` 的方式标记它（mark，然后 `a` 使用寄存器 `a` 作为位置），然后跳到想要开始删除的位置并按 `d\`a` 删除当前行及所有行直到并包括 `a` 的位置。`yy` 和其他相关命令也可以类似使用。

在命令模式下标记位置的方法如下：

`m` `x`
用 `x` 标记当前位置（`x` 可以是任意字母）。（原始的 `vi` 仅允许小写字母。Vim 区分大小写字母。）

`'` `x` (apostrophe)
将光标移动到由 `x` 标记的行第一个字符。

`` ` `` `x` (backquote)
将光标移动到由 `x` 标记的字符。



`` ` `` (反引号)
:
返回到上一个标记或上下文的确切位置。

`''` (撇号)
:
返回到上一个标记或上下文所在行的开头。

### 注意
标记仅在当前会话期间设置；它们不会存储在文件中。
