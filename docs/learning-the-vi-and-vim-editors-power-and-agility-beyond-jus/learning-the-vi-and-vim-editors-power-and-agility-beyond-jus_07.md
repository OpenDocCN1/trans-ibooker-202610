## 第 6 章. 全局替换

有时，在文档中途或在草稿结束时，你可能会注意到在指代某些事物的方式上存在不一致。或者，在手册中，文件中到处出现的某个产品名称突然被重新命名（市场营销！）。经常会发生这种情况，你需要回去更改已写的内容，并在多个地方进行类似或相同的更改。

进行这些更改的方法是使用一种称为 `global replacement` 的强大功能。通过一个命令，你可以自动在文件中出现的所有位置替换一个词（或一组字符）。

在全局替换中，`ex` 编辑器检查文件的每一行以查找给定的字符模式。在找到模式的所有行上，`ex` 将模式替换为 `new string` 字符。对于现在，我们将搜索模式视为简单的字符串；稍后在本章中，我们将研究一种称为 `regular expressions` 的强大的模式匹配语言。

全局替换实际上使用了两个 `ex` 命令：`:g`（global）和 `:s`（substitute）。由于全局替换命令的语法可能相当复杂，让我们分阶段来看它。

## 替换命令

替换命令的语法为：

```
:s/old/new/
```

这会将当前行上模式 `old` 的第一次出现更改为 `new`。`/`（斜杠）是命令各部分之间的分隔符，当它是行上的最后一个字符时是可选的。（实际上，你可以使用任何标点字符作为分隔符；这将在本章后面讨论。）

`:s` 命令允许在替换字符串后跟选项。例如，具有以下语法的替换命令：

```
:s/old/new/g
```

会将当前行上 `old` 的每次出现都更改为 `new`，而不仅仅是第一次出现。此语法中的 `g` 选项也代表 `global`。（`g` 选项影响行上的每个模式；不要将其与稍后讨论的 `:g` 命令混淆，后者影响文件的每一行。）

通过在 `:s` 命令前加上地址，你可以将范围扩展到多行。例如，此命令会将第 50 行到第 100 行中 `old` 的每次出现更改为 `new`：

```
:50,100s/old/new/g
```

以下命令会将整个文件中 `old` 的每次出现更改为 `new`：

```
:1,$s/old/new/g
```



你也可以使用 `%` 代替 `1,$` 来指定文件中的每一行。因此，前面的命令也可以这样给出：

```
:%s/old/new/g
```

全局替换比逐个查找字符串的每个实例并单独替换要快得多。因为该命令可用于进行许多不同类型的更改，并且功能非常强大，所以我们首先说明简单的替换，然后逐步扩展到复杂、上下文相关的替换。

# 确认替换

使用搜索和替换命令时，谨慎行事是有道理的。有时得到的结果并不如预期。你可以通过输入 `u` 来撤消任何搜索和替换命令，前提是该命令是你所做的最近一次编辑。但你并不总是能在来不及撤消之前发现不期望的更改。

保护编辑文件的一种方法是，在执行全局替换之前使用 `:w` 保存文件。这样至少你可以不保存编辑内容就退出文件，并回到更改之前的状态。你也可以使用 `:e!` 将上次保存的文件版本重新读入。（无论如何，保存文件都是一个好主意。）

谨慎行事并确切知道文件中将要更改的内容是明智的。如果你想查看搜索结果并在每次替换之前确认，可以在替换命令末尾添加 `c` 选项（表示“confirm”）：

```
:1,30s/his/the/gc
```

`ex`（在 Vim 中）会显示找到字符串的整行，高亮要替换的文本，并提示确认：

```
copyists at his school
~
~
~
replace with the (y/n/a/q/l/^E/^Y)? 
```

如果你想进行替换，必须输入 `y`（表示 yes）。如果你不想更改，只需按 `n`（表示 no）。

引用 Vim 文档，以下是可能响应的含义：

| `y` || 替换此匹配项 |
| --- | --- |
| `n` || 跳过此匹配项 |
| `a` || 替换此匹配项及所有剩余匹配项 |
| `q` || 停止替换 |
| `l` || 替换此匹配项然后退出（“last”） |
| CTRL-E || 向上滚动屏幕 |
| CTRL-Y || 向下滚动屏幕 |
| ESC || 停止替换 |

Vim 提供了除 `g` 和 `c` 之外的许多其他选项。输入命令 `:help s_flags` 可获取更多信息。

`vi` 命令 `n`（重复上次搜索）和点号 `.`（重复上次命令）的组合也是一种极其有用且快速的方式，可以逐页浏览文件并进行你可能不想全局执行的重复更改。例如，如果你的（人工）编辑告诉你你在应该使用 *that* 的地方使用了 *which*，你可以逐一检查 *which* 的每个出现，只更改那些不正确的地方：

| `/which` || 搜索 *which* |
| --- | --- |
| `cwthat` `ESC` || 改为 *that* |
| `n` || 重复搜索 |
| `n` || 重复搜索，跳过一次更改 |
| `.` || 重复更改（如果合适） |
|  || （等等。） |

# 在整个文件中全局操作

`ex` 提供了一个强大的命令，可让你在文件的相关行上应用第二个命令。这就是 *global* 命令，`:g`，其形式为：

```
:g/pattern/ command
```

收到此命令后，`ex` 会遍历整个编辑缓冲区，记住匹配 `pattern` 的每一行。然后，对于每条匹配的行，它都会执行给定的 `command`。以下是两个示例：

`g/# FIXME/d`

删除所有包含“FIXME”注释的行。

`g/# FIXME/s/FIXME/DONE/`

将所有“FIXME”注释实例更改为“DONE。”

全局命令（`:g`）最常与替换命令（`s`）一起使用，正如我们即将看到的那样。但你也可以将其与其他 `ex` 命令组合，我们将在本章后面描述。

# 上下文相关替换

最简单的全局替换是将一个词或短语替换为另一个词或短语。如果你输入的文件中有几个拼写错误（*editer* 代替 *editor*），可以执行全局替换：

```
:%s/editer/editor/g
```

这会在整个文件中将 *editer* 的每个出现替换为 *editor*。

使用全局命令 `:g`，你可以搜索一个模式，然后一旦找到包含该模式的行，就对与模式不同的字符串进行替换。你可以将其视为上下文相关替换。

语法如下：

```
:g/pattern/s/old/new/g
```

第一个 `g` 告诉命令对文件中的所有匹配 `pattern` 的行进行操作。在包含 `pattern` 的那些行上，`ex` 要将匹配 `old` 的字符替换（substitute，`s`）为 `new` 中的字符。最后一个 `g` 表示替换要在该行上全局进行。这意味着 `old` 的所有匹配项都会被 `new` 替换，而不仅仅是每行相关行的第一个匹配项。

例如，在撰写本书时，嵌入 AsciiDoc 中的 HTML 指令 `<span class="keycap">` 和 `</span>` 会在 ESC 周围放置一个框以显示 Escape 键。你希望 ESC 全部为大写，但又不想更改文本中可能出现的 *Esc*ape 的任何实例。要仅在包含 `class="keycap"` 标记的行上将 *Esc* 的实例更改为 *ESC*，你可以输入：

```
:g/class="keycap"/s/Esc/ESC/g
```

如果用于查找行的模式与你想要更改的模式相同，就不必重复它。命令：

```
:g/string/s//new/g
```

搜索包含 `string` 的行并对该相同的 `string` 进行替换。

请注意：

```
:g/editer/s//editor/g
```

与以下效果相同：

```
:%s/editer/editor/g
```

使用第二种形式可以节省一些输入。正如我们之前提到的，你可以将 `:g` 命令与 `:d`、`:m`、`:co` 以及除 `:s` 之外的其他 `ex` 命令组合。正如我们将展示的那样，你可以通过这种方式进行全局删除、移动和复制。

# 模式匹配规则

在进行全局替换时，Unix 编辑器如 `vi` 和 Vim 允许你不仅搜索固定字符字符串，还可以搜索称为 *regular expressions* 的可变单词模式。

当你指定字面字符字符串时，搜索可能会找到你不想匹配的其他出现。搜索文件中单词的问题在于一个词可以用不同的方式使用，或者一个词可能嵌入在另一个词中（考虑 “stopper” 中的 “top”）。正则表达式可以帮助你在上下文中搜索单词。请注意，正则表达式可与搜索命令 `/` 和 `?` 以及 `ex` 命令 `:g` 和 `:s` 一起使用。

在大多数情况下，相同的正则表达式可与其他 Unix 程序一起使用，例如 `grep`、`sed` 和 `awk`。^(1)

正则表达式由普通字符与称为 *metacharacters* 的若干特殊字符组合而成。^(2) 下文列出了元字符及其用途。

## 搜索模式中使用的元字符

以下是元字符及其作用：

`.` (period, dot)

匹配除换行符外的任何 *single* 字符。记住空格被视为字符。例如，`p.p` 匹配字符字符串如 *pep*、*pip* 和 *pcp*。

`*`

匹配其前面紧跟的单个字符的零个或多个（尽可能多）。例如，`slo*w` 匹配 *slow*（一个 *o*）或 *slw*（没有 *o*）。（它也匹配 *sloow*、*slooow* 等。）

`*` 可以跟在元字符后面。例如，由于 `.`（dot）表示任何字符，`.*` 表示“匹配任意数量的任意字符”。

这是一个具体示例：命令 `:s/End.*/End/` 删除 *End* 之后的所有字符（它用空内容替换行的剩余部分）。

`^`



### `^`
当在正则表达式开头使用时，要求以下正则表达式出现在行的开头。例如，`^Part` 在行开头出现时匹配 *Part*，而 `^...` 匹配一行的前三个字符。当不在正则表达式开头时，`^` 代表它本身。

### `$`
当在正则表达式结尾使用时，要求前面的正则表达式出现在行的末尾；例如，`here:$` 仅在 *here:* 出现在行末时匹配。当不在正则表达式结尾时，`$` 代表它本身。

`^` 和 `$` 被称为 *锚点*，因为它们分别将匹配锚定到行的开头或结尾。

### `\`
将下一个特殊字符视为普通字符。例如，`\.` 匹配实际的句点而不是“any single character”，而 `\*` 匹配实际的星号而不是“any number of a character”。`\`（反斜杠）阻止对特殊字符的解释。这种阻止称为“escaping the character”。使用 `\\` 来获取字面反斜杠。

### `[ ]`
匹配方括号之间包含的任意 *one* 字符。例如，`[AB]` 匹配 *A* 或 *B*，而 `p[aeiou]t` 匹配 *pat*、*pet*、*pit*、*pot* 或 *put*。你可以通过用连字符分隔范围中的第一个和最后一个字符来指定连续字符的范围。例如，`[A-Z]` 匹配从 *A* 到 *Z* 的任意大写字母，而 `[0-9]` 匹配从 *0* 到 *9* 的任意数字。

你可以在括号内包含多个范围，也可以指定范围和单独字符的混合。例如，`[:;A-Za-z()]` 匹配四种不同的标点符号，加上所有英文字母。

#### Note
当正则表达式和 `vi` 最初开发时，它们仅用于 ASCII 字符集。在当今的全球市场中，现代系统支持 *locales*，它们为 `a` 和 `z` 之间的字符提供不同的解释。为了获得准确的结果，你应该在正则表达式中使用 POSIX 括号表达式（稍后讨论），并避免 `a-z` 这种形式的范围。

大多数元字符在括号内会失去其特殊含义，因此如果你想将它们用作普通字符，就无需转义它们。在括号内，你仍需要转义的三个元字符是 `\`、`-` 和 `]`。连字符 (`-`) 作为范围限定符获得含义；要使用实际的连字符，也可以将其放在括号内的第一个字符处。（这对 `]` 也是如此。）

插入符号 (`^`) 只有在括号内的第一个字符时才有特殊含义，但在这种情况下，其含义与正常的 `^` 元字符不同。作为括号内的第一个字符，`^` 会反转其含义：括号匹配列表中 *not* 的任意一个字符。例如，`[⁰-9]` 匹配任何不是数字的字符。

### `\( \)`
将 `\(` 和 `\)` 之间包围的子模式保存到一个特殊的保存空间，或一个 *hold buffer*。^(3) 在单行中可以这样保存最多九个子模式。例如，模式

```
\(That\) or \(this\)
```

保存 *That* 到保存缓冲区编号 1 并保存 *this* 到保存缓冲区编号 2。匹配保存的子模式的文本可以通过序列 `\1` 到 `\9` 在替换中“replayed”。例如，要将 *That or this* 改写为 *this or That*，你可以输入：

```
:%s/\(That\) or \(this\)/\2 or \1/
```

你也可以在搜索或替换字符串中使用 `\`*`n`* 记法。例如：

```
:s/\(abcd\)\1/alphabet-soup/
```

将 *abcdabcd* 改为 *alphabet-soup*。

### `\< \>`
匹配单词开头 (`\<`) 或结尾 (`\>`) 的字符。单词的结尾或开头由标点符号或空格决定。例如，表达式 `\<ac` 仅匹配以 *ac* 开头的单词，如 *action*。表达式 `ac\>` 仅匹配以 *ac* 结尾的单词，如 *maniac*。这两个表达式都不匹配 *react*。请注意，与 `\(…\)` 不同，这些不需要成对使用。

在原始 `vi` 中，还有一个额外的元字符：

### `~`
匹配上一次搜索中使用的任何正则表达式。例如，如果你搜索了 *The*，你可以用 `/~n` 搜索 *Then*。请注意，你只能在普通搜索（使用 `/`）中使用此模式。它不能用作替换命令中的模式。然而，它在替换命令的替换部分中具有类似的含义。（这将在稍后“替换字符串中使用的元字符”部分中描述。）

`~` 的这种用法是原始 `vi` 中一个相当不稳定的功能。使用它之后，保存的搜索模式被设置为 `~` 之后输入的 *new* 文本，而不是人们可能期望的组合新模式。虽然此功能存在，但几乎没有什么值得推荐使用的。并且 `Vim` 并不会这样行为。

请注意，`Vim` 支持扩展正则表达式语法。有关更多信息，请参阅“扩展正则表达式”部分。

## POSIX Bracket Expressions
我们刚刚描述了使用括号来匹配所包含的任意一个字符，例如 `[a-z]`。POSIX 标准引入了额外的设施来匹配非英文字母的字符。例如，法语 *è* 是一个字母字符，但典型的字符类 `[a-z]` 不会匹配它。此外，标准还提供了在匹配和整理（排序）字符串数据时应作为单个单元处理的字符序列。

POSIX 还规范了术语。在 POSIX 标准中，括号内的字符组称为 *bracket expressions*。在括号表达式中，除了字面字符 *a*、*!* 等之外，还可以有额外的组件。这些组件是：

### Character classes
POSIX 字符类由 `[:` 和 `:]` 包围的关键字组成。关键字描述不同类别的字符，例如字母字符、控制字符等（参见表 6-1）。

### Collating symbols
整理符号是一个应作为单元处理的多个字符序列。它由 `[.` 和 `.]` 包围的字符组成。

### Equivalence classes
等价类列出应视为等价的一组字符，例如 *e* 和 *è*。它由 `[=` 和 `=]` 包围的来自区域设置的命名元素组成。

这三种构造 *must* 出现在括号表达式的方括号内。例如，`[[:alpha:]!]` 匹配任何单个字母字符或感叹号，`[[.ch.]]` 匹配整理元素 *ch* 但不匹配仅字母 *c* 或字母 *h*。在法语区域设置中，`[[=e=]]` 可能匹配 *e*、*è* 或 *é* 中的任何一个。类和匹配字符显示在表 6-1 中。

表 6-1. POSIX 字符类

| 类 || 匹配字符 |
| --- | --- |
| `[:alnum:]` || 字母数字字符 |
| --- | --- |
| `[:alpha:]` || 字母字符 |
| `[:blank:]` || 仅空格和制表符字符 |
| `[:cntrl:]` || 控制字符 |
| `[:digit:]` || 数字字符 |
| `[:graph:]` || 可打印且可见（非空格）字符 |
| `[:lower:]` || 小写字符 |
| `[:print:]` || 可打印字符（包括空白） |
| `[:punct:]` || 标点字符 |
| `[:space:]` || 所有空白字符（空格、制表符、换行符、垂直制表符等） |
| `[:upper:]` || 大写字符 |
| `[:xdigit:]` || 十六进制数字 |



现代系统对安装时选择的区域设置很敏感；你可以使用 POSIX 括号表达式，可以预期得到合理的结果，特别是当只尝试匹配小写或大写字母时。^(4)

# 用于替换字符串中的元字符

当你进行全局替换时，前面讨论的正则表达式元字符仅在命令的搜索部分（第一部分）中保留其特殊含义。

例如，当你输入以下内容时：

```
:%s/1\.  Start/2.  Next, start with $100/
```

请注意，替换字符串将字符 `.` 和 `$` 按字面处理，无需对其进行转义。同理，假设你输入：

```
:%s/[ABC]/[abc]/g
```

如果你希望将 *A* 替换为 *a*，*B* 替换为 *b*，*C* 替换为 *c*，你会感到惊讶。由于在替换字符串中方括号像普通字符一样表现，此命令会将 *A*、*B* 或 *C* 的每次出现都更改为五字符字符串 *\[abc\]*。

要解决这类问题，你需要一种指定可变替换字符串的方法。幸运的是，还有一些额外的元字符在 *替换* 字符串中具有特殊含义：

`\*n*`

:
将 `\*n*` 替换为之前由 `\(` 和 `\)` 保存的第 *n* 个子模式匹配的文本，其中 *n* 为 1 到 9 的数字，且之前保存的子模式（保存在 hold 缓冲区中）按行从左到右计数。请参阅前面章节 “搜索模式中使用的元字符” 中对 `\(` 和 `\)` 的说明。

`\`

:
将以下特殊字符视为普通字符。反斜杠在替换字符串和搜索模式中都是元字符。要指定真正的反斜杠，请连续输入两个 (`\\`)。

`&`

:
用搜索模式匹配的整个文本替换 `&`。这在你想避免重新输入文本时很有用：

```
:%s/Washington/&, George/
```

替换结果将为 *Washington, George*。`&` 也可以替换可变模式（由正则表达式指定）。例如，要将 1 到 10 行的每一行用括号括起来，输入：

```
:1,10s/.*/(&)/
```

搜索模式匹配整行，而 `&` “重放”该行，并包含在你的文本中。

`~`

:
找到的字符串被 *最后* 一个替换命令指定的替换文本替换。这对于重复编辑很有用。例如，你可以在一行中输入 `:s/thier/their/`，然后在另一行中用 `:s/thier/~/` 重复更改。搜索模式不必相同。例如，你可以在一行中输入 `:s/his/their/`，然后在另一行中用 `:s/her/~/` 重复替换。^(5)

`\u` or `\l`

:
使替换字符串中的下一个字符分别变为大写或小写。例如，要将 *yes, doctor* 改为 *Yes, Doctor*，你可以输入：

```
:%s/yes, doctor/\uyes, \udoctor/
```

这是一个毫无意义的例子，因为直接输入带首字母大写的替换字符串更容易。与任何正则表达式一样，`\u` 和 `\l` 在可变字符串中使用时最有用。例如，我们之前使用的命令：

```
:%s/\(That\) or \(this\)/\2 or \1/
```

结果是 *this or That*，但我们需要调整大小写。我们将使用 `\u` 将 *this*（当前保存在 hold 缓冲区 2 中）的第一个字母大写，并使用 `\l` 将 *That*（当前保存在 hold 缓冲区 1 中）的第一个字母小写：

```
:s/\(That\) or \(this\)/\u\2 or \l\1/
```

结果是 *This or that*。不要将数字一与小写 `l` 混淆；数字一在后面。

`\U` or `\L` and `\e` or `\E`

:
`\U` 和 `\L` 与 `\u` 或 `\l` 类似，但所有后续字符都会转换为大写或小写，直到替换字符串结束或遇到 `\e` 或 `\E`。如果没有 `\e` 或 `\E`，替换文本的所有字符都会受 `\U` 或 `\L` 影响。例如，要将 *Fortran* 大写，可以输入：

```
:%s/Fortran/\UFortran/
```

或者，使用 `&` 字符重复搜索字符串：

```
:%s/Fortran/\U&/
```

所有模式搜索都是 *大小写敏感* 的。也就是说，搜索 *the* 找不到 *The*。你可以通过在模式中同时指定大写和小写来解决这个问题：

/[Tt]he

你也可以通过输入 `:set ic` 指示编辑器忽略大小写。有关更多详细信息，请参阅章节 “:set 命令”。

## 更多替换技巧

你应该了解有关替换命令的一些额外重要事实：

* 简单的 `:s` 等同于 `:s//~/`。换句话说，重复上一次替换。当你在文档中反复进行相同的更改，但不想使用全局替换时，这可以节省大量时间和输入。

* 如果你认为 `&` 的意思是“同样的东西”（即刚刚匹配的内容），这个命令相对容易记忆。你可以在 `&` 后加上 `g` 使替换在整行上全局进行，甚至可以与行范围一起使用：

```
:%&g                            Repeat the last substitution everywhere
```

* `&` 键可作为 `vi` 模式命令来执行 `:&` 命令，即重复上一次替换。这比 `:s` ENTER 节省更多输入——一次击键对比三次。

* `:~` 命令与 `:&` 命令类似，但有细微差别：使用的搜索模式是 *任何* 命令中最后使用的正则表达式，而不一定是最后一次替换命令中使用的那个。例如，在以下序列中：

```
:s/red/blue/
:/green
:~
```

`:~` 等价于 `:s/green/blue/`。^(6)

* 除了 `/` 字符外，你可以使用任何非字母数字、非空格字符作为分隔符，除了反斜杠、双引号和竖线 (`\`, `"`，和 `|`)。当你需要更改路径名时，这特别方便。例如：

```
:%s;/user1/tim;/home/tim;g
```

* 当启用 `edcompatible` 选项时，编辑器会记住上一次替换使用的标志（`g` 表示全局，`c` 表示确认）并将其应用于下一次。

这在你在文件中移动并希望进行全局替换时最有用。你可以先进行第一次更改：

```
:s/old/new/g
:set edcompatible
```

此后，后续的替换命令都是全局的。

请注意，尽管名称如此，没有已知的 Unix `ed` 版本实际以这种方式工作。

## 模式匹配示例

除非你已经熟悉正则表达式，否则前面关于特殊字符的讨论可能看起来令人望而生畏。几个额外的例子应该能使事情更清晰。在下面的示例中，正方形（□）标记空格；它不是特殊字符。

让我们逐步了解你如何在替换中使用一些特殊字符。假设你有一个长文件，想在整个文件中将单词 *child* 替换为 *children*。你首先使用 `:w` 保存编辑缓冲区，然后尝试此全局替换：

```
:%s/child/children/g
```

当你继续编辑时，你注意到诸如 *childrenish* 这样的词的出现。你无意中匹配了单词 *childish*。使用 `:e!` 返回到上次保存的缓冲区后，你现在尝试：

```
:%s/child□/children□/g
```

请注意，*child* 后面有一个空格。但此命令会遗漏 *child.*、*child,*、*child:* 等出现情况。经过一番思考，你记得方括号允许你从列表中指定一个字符，于是你意识到一个解决方案：

```
:%s/child[□,.;:!?]/children[□,.;:!?]/g
```



# vi/Vim 正则表达式示例

## 捕获组与词边界

此搜索 `child` 后跟一个空格（用 □ 表示）或标点字符 `,.;:!?` 中的任意一个。你期望将其替换为 `children` 后跟相应的空格或标点符号，但你最终在 `children` 的每次出现后都得到了一堆标点符号。你需要在 `\(` 和 `\)` 之间保存空格和标点符号。然后你可以用 `\1` 来“重放”它们。以下是下一个尝试：

```
:%s/child\([□,.;:!?]\)/children\1/g
```

当搜索匹配 `\(` 和 `\)` 之间的字符时，右侧的 `\1` 会恢复相同的字符。语法可能看起来非常复杂，但这个命令序列可以为你节省大量工作。*你在学习正则表达式语法所花费的任何时间都将得到千倍的回报！*

不过命令仍然不完美。你已经注意到 `Fairchild` 的出现也被更改了，所以你需要一种方法来匹配 `child`，当它不是另一个单词的一部分时。

事实证明，`vi` 和 `Vim`（但并非使用正则表达式的所有其他程序）都有一种特殊的语法来表示“仅当模式是一个完整单词时”。字符序列 `\<` 要求模式匹配在单词的开头，而 `\>` 要求模式匹配在单词的结尾。两者结合使用可将匹配限制为整个单词。因此，在示例任务中，`\<child\>` 找到单词 `child` 的所有实例，无论其后跟标点符号还是空格。以下是你应该使用的替换命令：

```
:%s/\<child\>/children/g
```

最后一种可能性是：

```
:%s/\<child\>/&ren/g
```

## 搜索通用词类

假设你的子程序名称以前缀 `mgi`、`mgr` 和 `mga` 开头：

```
mgibox routine,
mgrbox routine,
mgabox routine,
```

如果你想在更改名称 `box` 为 `square` 的同时保留前缀，以下任一替换命令都可以解决问题。第一个示例说明了如何使用 `\(` 和 `\)` 来保存实际匹配的模式。第二个示例展示了如何搜索一个模式但更改另一个模式：

```
:g/mg\([ira]\)box/s//mg\1square/g
```

```
mgisquare routine,
mgrsquare routine,
mgasquare routine,
```

全局替换会跟踪是否保存了 `i`、`r` 或 `a`。这样，`box` 仅在 `box` 是子程序名称的一部分时才会被更改为 `square`：

```
:g/mg[ira]bo$/s/box/square/g
```

```
mgisquare routine,
mgrsquare routine,
mgasquare routine,
```

这与之前的命令具有相同的效果，但安全性稍差，因为它可能会更改同一行上 `box` 的其他实例，而不仅仅是子程序名称中的实例。

## 按模式块移动

你也可以移动由模式分隔的文本块。例如，假设你有一本 150 页的参考手册，使用 XML 的专用版本编写。每页都由三个段落组成，具有相同的三个标题：`<syntax>`、`<description>` 和 `<parameters>`。以下是其中一个参考页面的示例：

```
<reference>
<description>Get status of named file</description>
<shortname>STAT</shortname>
<syntax>
int stat(const char *filename, struct stat *data);
...
retval = stat(filename, data);</syntax>
<description><para>
Writes the fields of a system data structure into the
structure pointed to by data.
These fields contain (among other
things) information about the file's access
privileges, owner, and time of last modification.
</para></description>
<parameters>
<param><name>filename</name>
<para>A character string variable or constant containing
the Unix pathname for the file whose status you want
to retrieve.
You can give the ...
</para></param></parameters>
</reference>
```

假设你决定将 `<description>` 移到 `<syntax>` 段落之上。通过模式匹配，你可以用一个命令移动所有 150 页上的文本块！

```
:g /<syntax>/.,/<description>/-1 move /<parameters>/-1
```

此命令的工作方式如下。首先，`ex` 找到并标记每行匹配第一个模式的行（即包含单词 `<syntax>` 的行）。其次，对于每个被标记的行，它将 `.`（点号，当前行）设置为该行并执行命令。此命令将从当前行（点号）到包含单词 `<description>` 的行之前一行（`/<description>/-1`）的文本块移动到包含 `<parameters>` 的行之前（`/<parameters>/-1`）。^(7)

请注意，`ex` 只能将文本放置在指定行的下方。

要告诉 `ex` 将文本放置在一行的上方，你首先用 `-1` 减去，然后 `ex` 将你的文本放置在上一行的下方。

在这种情况下，一个命令就能节省数小时的工作时间。这是一个真实的例子——我们曾经使用类似的模式匹配来重新排列一本包含数百页的参考手册。

按模式定义块也可以同样很好地与其他 `ex` 命令一起使用。例如，如果你想删除参考章节中的所有 `<description>` 段落，你可以输入：

```
:g/<description>/,/<parameters>/-1d
```

这种非常强大的更改隐含在 `ex` 的行寻址语法中，但即使是经验丰富的用户也并不容易察觉。因此，每当你面临复杂的重复编辑任务时，花时间分析问题并确定是否可以应用模式匹配工具来完成工作。

## 更多示例

由于通过示例学习模式匹配是最好的方法，这里列出了一些模式匹配示例，并附有解释。仔细研究语法，以便你理解其工作原理。然后你应该能够将这些示例适应到自己的情况。

1. 在单词 `ENTER` 周围放置 `troff` 斜体代码：

```
:%s/ENTER/\\fI&\\fP/g
```

请注意，在替换中需要两个反斜杠（`\\`），因为 `troff` 斜体代码中的反斜杠将被解释为特殊字符。(`\fI` 单独会被解释为 *fI*；你必须输入 `\\fI` 才能得到 `\\fI`。)

2. 修改文件中的路径名列表：

```
:%s/\/home\/tim/\/home\/linda/g
```

斜杠（在全局替换序列中用作分隔符）当它是模式或替换的一部分时必须用反斜杠转义；使用 `\/` 来得到 `/`。实现相同效果的另一种方法是使用不同的字符作为模式分隔符。例如，你可以使用冒号作为分隔符来进行之前的替换。（分隔符冒号和 `ex` 命令冒号是两个不同的实体。）因此：

```
:%s:/home/tim:/home/linda:g
```

这样更易读。

3. 在单词 `ENTER` 周围放置 HTML 斜体代码：

```
:%s:ENTER:<I>&</I>:g
```

这里注意使用 `&` 来表示实际匹配的文本，以及如上所述使用冒号作为分隔符而不是斜杠。

4. 将 1 到 10 行中的所有句点更改为分号：

```
:1,10s/\./;/g
```

点号在正则表达式语法中有特殊含义，必须用反斜杠转义（`\.`）。

5. 将单词 `help`（或 `Help`）的所有出现更改为 `HELP`：

```
:%s/[Hh]elp/HELP/g
```

或：

```
:%s/[Hh]elp/\U&/g
```

`\U` 将其后的模式更改为全大写。其后的模式是重放的搜索模式，即 `help` 或 `Help`。

6. 用单个空格替换一个或多个空格：

```
:%s/□□*/□/g
```

确保你理解星号作为特殊字符的工作方式。跟在任何字符之后（或跟在匹配单个字符的正则表达式之后，例如 `.` 或 `[[:lower:]]`）的星号匹配该字符的 `zero or more` 个实例。因此，你必须指定 `two` 个空格后跟星号来匹配一个或多个空格（一个空格，加上零个或多个空格）。

7. 用恰好两个空格替换冒号后跟的一个或多个空格：



## 7. 用恰好两个空格替换冒号后一个或多个空格

```
:%s/:□□*/:□□/g
```

## 8. 用恰好两个空格替换句点或冒号后一个或多个空格

```
:%s/\([:.]\)□□*/\1□□/g
```

方括号内的两个字符中的任意一个都可以匹配。该字符使用 `\(` 和 `\)` 保存到暂存缓冲区，并在右侧由 `\1` 恢复。请注意，在方括号内，像句点这样的特殊字符无需转义。

## 9. 统一单词或标题的各种用法

```
:%s/^Note[□:s]*/Notes:□/g
```

方括号包含三个字符：空格、冒号和字母 `s`。因此，模式 `Note[□s:]` 匹配 `Note`□、`Notes` 或 `Note:`。在模式后添加星号，使其也能匹配 `Note` 后面没有空格的情况以及 `Notes:` 这种已经正确的拼写。如果没有星号，`Note` 将完全被遗漏，而 `Notes:` 会被错误地改为 `Notes:`□*:*。同时，这会将多个空格截断为一个，因此 `Note:`□□ 变为 `Notes:`□。

## 10. 删除所有空行

```
:g/^$/d
```

你实际匹配的是行首 `^` 后跟行尾 `$`，中间没有任何内容。

## 11. 删除所有空行，以及只包含空白字符的行

```
:g/^[□tab]*$/d
```

在示例中，制表符显示为 `tab`。一行看起来可能是空的，但实际上可能包含空格或制表符。前一个示例不会删除此类行。这个示例与前一个示例一样，搜索行的开始和结束。但与中间没有任何内容不同，模式尝试查找任意数量的空格或制表符。如果没有匹配到空格或制表符，该行就是空的。要删除包含空白字符但不为空的行，你必须匹配至少包含一个空格或制表符的行：

```
:g/^[□tab][□tab]*$/d
```

## 12. 删除每行开头的所有空格

```
:%s/^□□*\(.*\)/\1/
```

使用 `^□□*` 搜索每行开头的一个或多个空格；然后使用 `\(.*\)` 将行的其余部分保存到第一个暂存缓冲区。使用 `\1` 恢复没有前导空格的行。这可以用 `s/^□□*//` 更简单地完成。

## 13. 删除每行末尾的所有空格

```
:%s/□□*$//
```

对每一行，删除行尾的一个或多个空格。

由于 `^` 和 `$` 锚点，此示例和前一个示例中的替换在任何给定行上只发生一次，因此替换字符串后不需要跟随 `g` 选项。

## 14. 在从当前行到下一行以 `}` 开始的行，每行开头插入一个 `//□`

```
:.,/^}/s;^;//□;
```

我们真正做的是“替换”行首为 `//□`。当然，行首是一个逻辑构造，而不是实际字符，实际上并没有被替换！

这会使用 C++ `//` 注释，将从当前行 dot 到下一行以右大括号开始的所有行注释掉。通常，你会将光标放在函数定义的第一个行，以注释掉整个函数。

请注意，当替换文本包含一个或多个斜杠时，使用分号作为 substitute 命令的分隔符。

## 15. 在接下来的六行末尾添加一个句点

```
:.,+5s/$/./
```

行地址表示当前行加五行。`$` 表示行尾。与前一个示例一样，`$` 是一个逻辑构造。你实际上并没有替换行尾。

## 16. 反转列表中所有由连字符分隔的项目的顺序

```
:%s/\(.*\)□-□\(.*\)/\2□-□\1/
```

使用 `\(.*\)` 将行上的文本保存到第一个暂存缓冲区，但仅保存到找到 □-□ 为止。然后使用 `\(.*\)` 将行的其余部分保存到第二个暂存缓冲区。恢复已保存的行部分，反转两个暂存缓冲区的顺序。此命令对多个项目的效果如下所示：

```
more - display files
```

变为：

```
display files - more
```

以及：

```
lp - print files
```

变为：

```
print files - lp
```

这可以更简洁地完成：

```
:%s/\(.*\)\(□-□\)\(.*\)/\3\2\1/
```

## 17. 将文件中每个字母改为大写

```
:%s/.*/\U&/
```

或：

```
:%s/./\U&/g
```

替换字符串开头的 `\U` 标志告诉编辑器将替换内容改为大写。`&` 字符将搜索模式匹配的文本作为替换内容重放。

这两个命令是等效的；然而，第一种形式速度快得多，因为它每行只进行一次替换 `.*` 匹配整行，每行一次，而第二种形式会导致每行重复替换 `.` 只匹配单个字符，由于尾部的 `g`，替换会重复。

## 18. 反转文件中行的顺序

```
:g/.*/mo0
```

搜索模式匹配所有行，一行包含零个或多个字符。每行一次一个地移动到文件顶部，即移动到虚拟行零之后。随着每条匹配的行被放在顶部，它会一次一个地将之前移动的行向下推，直到最后一行位于顶部。由于所有行都有开头，可以更简洁地实现相同结果：

```
:g/^/mo0
```

## 19. 在文本文件数据库中，对所有未标记为 Paid in full 的行附加短语 Overdue

```
:g!/Paid in full/s/$/ Overdue/
```

或等价的：

```
:v/Paid in full/s/$/ Overdue/
```

要影响除匹配模式的行之外的所有行，你可以在 `:g` 命令后添加 `!`，或者直接使用 `v` 命令。

## 20. 对于任何不以数字开头的行，将该行移动到文件末尾

```
:g!/^[[:digit:]]/m$
```

或：

```
:g/^[^[:digit:]]/m$
```

作为方括号内的第一个字符，脱字符会否定其含义，因此这两个命令具有相同的效果。第一个命令的意思是“不要匹配以数字开头的行”，第二个命令的意思是“匹配不以数字开头的行”。

请注意，这两个命令之间存在相当微妙的差异。第一个命令会影响空行；第二个命令不会。为什么呢？ `/^[[:digit:]]/` 匹配以数字开头的行。`:g` 后的 `!` 否定了这一点，匹配不以数字开头的行。这包括空行。然而，`/^[^[:digit:]]/` 匹配以非数字字符开头的行；要匹配，行上必须存在字符。

## 21. 将手动编号的章节标题例如 1.1、1.2 等更改为 HTML `<h1>` 标题标记

```
:%s;^[1-9]\.[1-9] \(.*\);<h1>\1</h1>;
```

搜索字符串匹配非零数字，后跟句点，后跟另一个非零数字，后跟空格，后跟任意内容。刚才显示的命令找不到包含两个或更多数字的章节号。为此，按如下方式修改命令：

```
:%s;^[1-9][0-9]*\.[1-9] \(.*\);<h1>\1</h1>;
```

现在它匹配 10 到 99 章节 1 到 9 位数字，后跟一位数字，100 到 999 章节 1 到 9 位数字，后跟两位数字，依此类推。该命令仍然可以找到 1 到 9 章节 1 到 9 位数字，后面没有数字的情况。

## 22. 从文档的章节标题中删除编号。你想将示例行更改为

```
2.1 Introduction
10.3.8 New Functions
```

变为以下行：

```
Introduction
New Functions
```

这是执行此操作的命令：



```
:%s/^[1-9][0-9]*\.[1-9][0-9.]*□//
```

搜索模式与前一个示例中的相似，但现在数字的长度各不相同。至少，标题包含 *数字*、*句点*、*数字*，因此你从前一个示例的搜索模式开始：

```
[1-9][0-9]*\.[1-9]
```

但在此示例中，标题可能继续包含任意数量的数字或句点：

```
[0-9.]*
```

23. 将单词 *Fortran* 改为短语 *FORTRAN（FORmula TRANslation 的缩写）*：

```
:%s/\(For\)\(tran\)/\U\1\2\E□(acronym□of□\U\1\Emula□\U\2\Eslation)/g
```

首先，由于我们注意到单词 *FORmula* 和 *TRANslation* 使用了原始单词的一部分，我们决定将搜索模式保存为两部分：`\(For\)` 和 `\(tran\)`。第一次恢复时，我们将两部分合并使用，并将所有字符转换为大写：`\U\1\2`。接下来，我们使用 `\E` 取消大写；否则，剩余的替换文本将全部为大写。替换继续进行实际输入的单词，然后我们恢复第一个保存缓冲区。该缓冲区仍然包含 *For*，因此我们再次先转换为大写：`\U\1`。紧接着，我们将单词的其余部分转为小写：`\Emula`。最后，我们恢复第二个保存缓冲区。其包含 *tran*，因此我们在“重放”前加上大写，之后转为小写，并输入单词的其余部分：`\U\2\Eslation)`。

# 对模式匹配的最终回顾

我们通过介绍涉及复杂模式匹配概念的示例任务来结束本章。与其立即解决这些问题，我们将逐步朝着解决方案努力。

## 删除未知文本块

假设你有几行具有以下一般形式：

```
the best of times; the worst of times:  moving
The coolest of times; the worst of times:  moving
```

你关心的行总是以 *移动* 结尾，但你永远不知道前两个词可能是什么。你希望将任何以 *移动* 结尾的行更改为：

```
The greatest of times; the worst of times:  moving
```

由于更改必须发生在某些行上，你需要指定一个上下文敏感的全局替换。使用 `:g/moving$/` 匹配以 *移动* 结尾的行。接下来，你意识到搜索模式可以是任意数量的任意字符，因此元字符 `.*` 浮现在脑海中。但除非以某种方式限制匹配，否则它们会匹配整行。以下是你的第一次尝试：

```
:g/moving$/s/.*of/The□greatest□of/
```

你决定，这个搜索字符串将从行首匹配到第一个 *of*。由于你需要指定单词 *of* 来限制搜索，你只需在替换中重复它。以下是结果行：

```
The greatest of times:  moving
```

出了问题！替换吞掉了到第二个 *of* 的行，而不是第一个。原因如下：当有选择时，“匹配任意数量的任意字符” 的操作会匹配 *尽可能多的文本*。^(9) 在这种情况下，由于单词 *of* 出现了两次，你的搜索字符串找到的是：

```
the best of times; the worst of
```

而不是：

```
the best of
```

你的搜索模式需要更严格：

```
:g/moving$/s/.*of□times;/The□greatest□of□times;/
```

现在 `.*` 匹配所有字符，直到短语 *of times;* 的实例。由于只有一个实例，它必须是第一个。

不过，有时使用 `.*` 元字符会不方便，甚至不正确。例如，你可能发现自己需要输入很多词来限制搜索模式，或者你无法通过特定词来限制模式（如果行中的文本差异很大）。下一节介绍这种情况。

## 切换文本数据库中的项目

假设你想切换 (文本) 数据库中所有姓氏和名字 的顺序。行看起来像这样：

```
Name: Feld, Ray; Areas: PC, Unix; Phone: 765-4321
Name: Joy, Susan S.; Areas: Graphics; Phone: 999-3333
```

每个字段名称以冒号结尾，每个字段由分号分隔。以顶行为例，你想将 *Feld, Ray* 改为 *Ray Feld*。我们将展示一些看起来很有希望但不起作用的命令。每个命令之后，我们都会展示更改前后的行：

```
:%s/: \(.*\), \(.*\);/: \2 \1;/

Name: Feld, Ray; Areas: PC, Unix; Phone: 765-4321             Before
Name: Unix Feld, Ray; Areas: PC; Phone: 765-4321              After
```

我们已将第一个保存缓冲区的内容以 **`bold`** 高亮，并将第二个保存缓冲区的内容以 *`italic`* 高亮。请注意，第一个保存缓冲区包含的内容比你想要的多。由于它没有被后续模式充分限制，保存缓冲区能够保存到第二个逗号。现在你尝试限制第一个保存缓冲区的内容：

```
:%s/: \(....\), \(.*\);/: \2 \1;/

Name: Feld, Ray; Areas: PC, Unix; Phone: 765-4321             Before
Name: Ray; Areas: PC, Unix Feld; Phone: 765-4321              After
```

这里你已成功将姓氏保存在第一个保存缓冲区中，但现在第二个保存缓冲区保存了行上最后一个分号之前的所有内容。现在你也限制第二个保存缓冲区：

```
:%s/: \(....\), \(...\);/: \2 \1;/

Name: Feld, Ray; Areas: PC, Unix; Phone: 765-4321             Before
Name: Ray Feld; Areas: PC, Unix; Phone: 765-4321              After
```

这在姓氏为四个字母且名字为三个字母的特定情况下给了你想要的结果。（之前的尝试也包含同样的错误。）为什么不回到第一次尝试，但这次对搜索模式的结尾更具选择性呢？

```
:%s/: \(.*\), \(.*\); Area/: \2 \1; Area/

Name: Feld, Ray; Areas: PC, Unix; Phone: 765-4321             Before
Name: Ray Feld; Areas: PC, Unix; Phone: 765-4321              After
```

这可行，但我们将通过引入一个额外的顾虑继续讨论。假设 *Area* 字段并不总是存在或并不总是第二个字段。刚才显示的命令在这样的行上将不起作用。

我们引入这个问题是为了说明一个观点。每当你重新思考一个模式匹配时，通常最好朝着细化变量（元字符）努力，而不是使用特定文本来限制模式。你在模式中使用的变量越多，你的命令就越强大。

在当前示例中，再次思考你想要切换的模式。每个单词以大写字母开头，后跟任意数量的小写字母，因此你可以像这样匹配名称：

```
[[:upper:]][[:lower:]]*
```

姓氏也可能有不止一个大写字母（例如 *McFly*），因此你希望在第二个及之后的字母中搜索这种可能性：

```
[[:upper:]][[:alpha:]]*
```

对名字也使用这种方法也没坏处（你永远不知道什么时候会出现 *McGeorge Bundy*）。你的命令现在变为：

```
:%s/: \([[:upper:]][[:alpha:]]*\), \([[:upper:]][[:alpha:]]*\);/: \2 \1;/
```

相当吓人，不是吗？它仍然不涵盖像 *Joy, Susan S.* 这样的名字的情况。由于名字字段可能包含中间名首字母，你需要在第二个括号对内添加一个空格和一个句点。但够了。有时，指定你想要的确切内容比指定你 *不想要* 的内容更困难。在你的示例数据库中，姓氏以逗号结尾，因此姓氏字段可以被视为 *不是* 逗号的字符字符串：

```
[^,]*
```

此模式匹配字符直到第一个逗号。同样，名字字段是 *不是* 分号的字符字符串：

```
[^;]*
```

将这些更高效的模式放回之前的命令中，你得到：

```
:%s/: \([^,]*\), \([^;]*\);/: \2 \1;/
```



同样的命令也可以作为上下文敏感的替换输入。如果所有行都以 `Name` 开头，你可以这样写：

```
:g/^Name/s/: \([^,]*\), \([^;]*\);/: \2 \1;/
```

你还可以在第一个空格后添加一个星号，以便匹配冒号后面有额外空格（或没有空格）的情况：

```
:g/^Name/s/: *\([^,]*\), \([^;]*\);/: \2 \1;/
```

## 使用 `:g` 重复命令

在我们通常看到的 `:g` 命令用法中，它会选择行，然后通常由同一条 `ex` 命令行上的后续命令进行编辑——例如，我们使用 `:g` 选择行然后对其进行替换，或者选择它们并删除它们：

```
:g/mg[ira]box/s/box/square/g
:g/^$/d
```

然而，在 *UnixWorld* 的两部分教程中^(10)，Walter Zintz 对 `:g` 命令提出了一个有趣的观点。该命令选择行，但相关的编辑命令并不一定需要实际影响所选的行。

相反，他演示了一种技术，可以让你重复执行 `ex` 命令任意次数。例如，假设你想将文件第 12 行到第 17 行的内容复制 10 份放到当前文件的末尾。你可以输入：

```
:1,10g/^/ 12,17t$
```

这是 `:g` 的一种非常出乎意料的用法，但它有效！`:g` 命令选择第 1 行，执行指定的 `t` 命令，然后继续到第 2 行执行下一个复制命令。当到达第 10 行时，`ex` 将已完成 10 次复制。

## 收集行

这是另一个高级 `:g` 示例，同样基于 Zintz 教程中提供的建议。假设你正在编辑一个由多个部分组成的文档。此文件的第 2 部分如下所示，使用省略号表示省略的文本并显示行号以供参考：

```
301  Part 2
302  Capability Reference
303  .LP
304  Chapter 7
305  Introduction to the Capabilities
306  This and the next three chapters ...

400  ... and a complete index at the end.
401  .LP
402  Chapter 8
403  Screen Dimensions
404  Before you can do anything useful
405  on the screen, you need to know ...

555  .LP
556  Chapter 9
557  Editing the Screen
558  This chapter discusses ...

821  .LP
822  Part 3
823  Advanced Features
824  .LP
825  Chapter 10
826  ....
```

每章编号出现在单独一行，章节标题出现在下一行，而章节正文（以 **粗体** 强调）则从其下一行开始。你想做的第一件事是复制每个章节的开头行，并将其发送到一个已存在的名为 `begin` 的文件。

执行此操作的命令如下：

```
:g /^Chapter/ .+2w >> begin
```

在发出此命令之前，你必须位于文件的顶部。首先，你在行首搜索 `Chapter`，但随后你希望在每个章节的开头行上运行命令——`Chapter` 下面的第二行。因为以 `Chapter` 开头的行现在被选为当前行，所以行地址 `.+2` 表示其下面的第二行。等效的行地址 `+2` 或 `++` 也适用。你希望将这些行写入名为 `begin` 的现有文件，因此使用追加操作符 `>>` 发出 `w` 命令。

假设你只想发送第 2 部分内的章节开头。你需要限制 `:g` 选择的行，因此将命令改为如下：

```
:/^Part 2/,/^Part 3/g /^Chapter/ .+2w >> begin
```

这里，`:g` 命令选择以 `Chapter` 开头的行，但它只在从以 `Part 2` 开始的行到以 `Part 3` 开始的行这一文件部分中搜索。如果你执行刚才显示的命令，文件 `begin` 的最后几行将如下所示：

```
This and the next three chapters ...
Before you can do anything useful
This chapter discusses ...
```

这些是第 7、8 和 9 章的开头行。

除了你刚刚发送的行之外，你还想将章节标题复制到文档末尾，以便制作目录表。你可以使用竖线在第一个命令后附加第二个命令，如下所示：

```
:/^Part 2/,/^Part 3/g /^Chapter/ .+2w >> begin | +t$
```

请记住，对于任何后续命令，行地址都相对于前一个命令。第一个命令已标记（在第 2 部分内）以 `Chapter` 开头的行，而章节标题出现在这些行的下一行。因此，要在第二个命令中访问章节标题，行地址为 `+`（或等效的 `+1` 或 `.+1`）。然后使用 `t$` 将章节标题复制到文件末尾。
