
# vi/Vim 正则表达式示例

## 捕获组与词边界

此搜索 `child` 后跟一个空格（用 □ 表示）或标点字符 `,.;:!?` 中的任意一个。你期望将其替换为 `children` 后跟相应的空格或标点符号，但你最终在 `children` 的每次出现后都得到了一堆标点符号。你需要在 `\(` 和 `\)` 之间保存空格和标点符号。然后你可以用 `\1` 来“重放”它们。以下是下一个尝试：

```
:%s/child\([□,.;:!?]\)/children\1/g
```

当搜索匹配 `\(` 和 `\)` 之间的字符时，右侧的 `\1` 会恢复相同的字符。语法可能看起来非常复杂，但这个命令序列可以为你节省大量工作。*你在学习正则表达式语法所花费的任何时间都将得到千倍的回报！*

不过命令仍然不完美。你已经注意到 `Fairchild` 的出现也被更改了，所以你需要一种方法来匹配 `child`，当它不是另一个单词的一部分时。

事实证明，`vi` 和 `Vim`（但并非使用正则表达式的所有其他程序）都有一种特殊的语法来表示“仅当模式是一个完整单词时”。字符序列 `\<` 要求模式匹配在单词的开头，而 `\>` 要求模式匹配在单词的结尾。两者结合使用可将匹配限制为整个单词。因此，在示例任务中，`\<child\>` 找到单词 `child` 的所有实例，无论其后跟标点符号还是空格。以下是你应该使用的替换命令：

```
:%s/\<child\>/children/g
```

最后一种可能性是：

```
:%s/\<child\>/&ren/g
```

## 搜索通用词类

假设你的子程序名称以前缀 `mgi`、`mgr` 和 `mga` 开头：

```
mgibox routine,
mgrbox routine,
mgabox routine,
```

如果你想在更改名称 `box` 为 `square` 的同时保留前缀，以下任一替换命令都可以解决问题。第一个示例说明了如何使用 `\(` 和 `\)` 来保存实际匹配的模式。第二个示例展示了如何搜索一个模式但更改另一个模式：

```
:g/mg\([ira]\)box/s//mg\1square/g
```

```
mgisquare routine,
mgrsquare routine,
mgasquare routine,
```

全局替换会跟踪是否保存了 `i`、`r` 或 `a`。这样，`box` 仅在 `box` 是子程序名称的一部分时才会被更改为 `square`：

```
:g/mg[ira]bo$/s/box/square/g
```

```
mgisquare routine,
mgrsquare routine,
mgasquare routine,
```

这与之前的命令具有相同的效果，但安全性稍差，因为它可能会更改同一行上 `box` 的其他实例，而不仅仅是子程序名称中的实例。

## 按模式块移动

你也可以移动由模式分隔的文本块。例如，假设你有一本 150 页的参考手册，使用 XML 的专用版本编写。每页都由三个段落组成，具有相同的三个标题：`<syntax>`、`<description>` 和 `<parameters>`。以下是其中一个参考页面的示例：

```
<reference>
<description>Get status of named file</description>
<shortname>STAT</shortname>
<syntax>
int stat(const char *filename, struct stat *data);
...
retval = stat(filename, data);</syntax>
<description><para>
Writes the fields of a system data structure into the
structure pointed to by data.
These fields contain (among other
things) information about the file's access
privileges, owner, and time of last modification.
</para></description>
<parameters>
<param><name>filename</name>
<para>A character string variable or constant containing
the Unix pathname for the file whose status you want
to retrieve.
You can give the ...
</para></param></parameters>
</reference>
```

假设你决定将 `<description>` 移到 `<syntax>` 段落之上。通过模式匹配，你可以用一个命令移动所有 150 页上的文本块！

```
:g /<syntax>/.,/<description>/-1 move /<parameters>/-1
```

此命令的工作方式如下。首先，`ex` 找到并标记每行匹配第一个模式的行（即包含单词 `<syntax>` 的行）。其次，对于每个被标记的行，它将 `.`（点号，当前行）设置为该行并执行命令。此命令将从当前行（点号）到包含单词 `<description>` 的行之前一行（`/<description>/-1`）的文本块移动到包含 `<parameters>` 的行之前（`/<parameters>/-1`）。^([7](#ch06.html#idm46601103772928))

请注意，`ex` 只能将文本放置在指定行的下方。

要告诉 `ex` 将文本放置在一行的上方，你首先用 `-1` 减去，然后 `ex` 将你的文本放置在上一行的下方。

在这种情况下，一个命令就能节省数小时的工作时间。这是一个真实的例子——我们曾经使用类似的模式匹配来重新排列一本包含数百页的参考手册。

按模式定义块也可以同样很好地与其他 `ex` 命令一起使用。例如，如果你想删除参考章节中的所有 `<description>` 段落，你可以输入：

```
:g/<description>/,/<parameters>/-1d
```

这种非常强大的更改隐含在 `ex` 的行寻址语法中，但即使是经验丰富的用户也并不容易察觉。因此，每当你面临复杂的重复编辑任务时，花时间分析问题并确定是否可以应用模式匹配工具来完成工作。

## 更多示例

由于通过示例学习模式匹配是最好的方法，这里列出了一些模式匹配示例，并附有解释。仔细研究语法，以便你理解其工作原理。然后你应该能够将这些示例适应到自己的情况。

1. 在单词 `ENTER` 周围放置 `troff` 斜体代码：

```
:%s/ENTER/\\fI&\\fP/g
```

请注意，在替换中需要两个反斜杠（`\\`），因为 `troff` 斜体代码中的反斜杠将被解释为特殊字符。(`\fI` 单独会被解释为 *fI*；你必须输入 `\\fI` 才能得到 `\\fI`。)

2. 修改文件中的路径名列表：

```
:%s/\/home\/tim/\/home\/linda/g
```

斜杠（在全局替换序列中用作分隔符）当它是模式或替换的一部分时必须用反斜杠转义；使用 `\/` 来得到 `/`。实现相同效果的另一种方法是使用不同的字符作为模式分隔符。例如，你可以使用冒号作为分隔符来进行之前的替换。（分隔符冒号和 `ex` 命令冒号是两个不同的实体。）因此：

```
:%s:/home/tim:/home/linda:g
```

这样更易读。

3. 在单词 `ENTER` 周围放置 HTML 斜体代码：

```
:%s:ENTER:<I>&</I>:g
```

这里注意使用 `&` 来表示实际匹配的文本，以及如上所述使用冒号作为分隔符而不是斜杠。

4. 将 1 到 10 行中的所有句点更改为分号：

```
:1,10s/\./;/g
```

点号在正则表达式语法中有特殊含义，必须用反斜杠转义（`\.`）。

5. 将单词 `help`（或 `Help`）的所有出现更改为 `HELP`：

```
:%s/[Hh]elp/HELP/g
```

或：

```
:%s/[Hh]elp/\U&/g
```

`\U` 将其后的模式更改为全大写。其后的模式是重放的搜索模式，即 `help` 或 `Help`。

6. 用单个空格替换一个或多个空格：

```
:%s/□□*/□/g
```

确保你理解星号作为特殊字符的工作方式。跟在任何字符之后（或跟在匹配单个字符的正则表达式之后，例如 `.` 或 `[[:lower:]]`）的星号匹配该字符的 `zero or more` 个实例。因此，你必须指定 `two` 个空格后跟星号来匹配一个或多个空格（一个空格，加上零个或多个空格）。
