我们无法在讨论 Unix 文化中的 `vi` 时不承认 Unix 社区中或许是最持久的争论：`vi` 与 `Emacs`。^([3](#app03.html#idm46601067390464))

关于哪个更好的讨论在 `comp.editors`（以及其他新闻组）中年复一年地出现。（这在[图 C-10](#app03.html#vi8-app-c-fig-10)中得到了很好的说明。）

![](assets/lvv8_ac10.png)

支持 `vi` 的一些更好论点如下：

* `vi` 可在每个 Unix 系统上使用。如果你正在安装系统或在系统间迁移，你可能无论如何都得使用 `vi`。
* 你通常可以让手指保持在键盘的主行上。对于盲打用户来说这是一个很大的优势。
* 命令通常是一个（有时是两个）普通字符；它们比 `Emacs` 所需的所有控制键和元字符要容易得多。
* `vi` 通常比 `Emacs` 更小、资源消耗更少。启动时间明显更快，有时快达十倍。
* 现在 `Vim`（以及其他 `vi` 克隆）已添加诸如增量搜索、多个窗口和缓冲区、图形界面、语法高亮和智能缩进，以及通过扩展语言实现的编程能力等功能，两者之间的功能差距已显著缩小，甚至可以说完全消失了。

为了完整起见，还应提及一点。虽然 GNU `Emacs` 一直有 `vi` 仿真包，但它们通常并不太好。然而，`viper-mode` 据称是优秀的 `vi` 仿真。它可以作为希望学习 `Emacs` 的用户的桥梁。

总之，请始终记住你是程序实用性的最终评判者。你应该使用能让你最高效的工具，对于许多任务来说，`vi` 和 `Vim` 都是优秀的工具。

# 附录 D. vi 和 Vim：源代码与构建

万一你的系统上尚未安装 `vi` 或 `Vim`，本附录描述了如何获取这两个编辑器的源代码，以及大多数流行操作系统的预编译可安装二进制文件。

## 与原版不同

许多年里，原版 `vi` 的源代码在没有 Unix 源代码许可的情况下无法获得。虽然教育机构能够以相对低廉的成本获得许可，但商业许可一直很昂贵。这一事实促使 `Vim` 以及许多其他 `vi` 克隆的诞生。

2002 年 1 月，V7 和 32V UNIX 的源代码在类开源许可下发布。^([1](#app04.html#idm46601067348960)) 这使得几乎所有为 BSD Unix 开发的代码都可以访问，包括 `ex` 和 `vi`。

原始代码在现代系统（如 GNU/Linux）上无法“开箱即用”编译，移植它也很困难。^([2](#app04.html#idm46601067346064)) 幸运的是，这项工作已经完成。如果你想使用原始的、“真正的” `vi`，你可以下载源代码自行构建。有关更多信息，请参阅 [*https://github.com/n-t-roff/heirloom-ex-vi*](https://github.com/n-t-roff/heirloom-ex-vi)。

我们只是在 Ubuntu GNU/Linux 系统上按照 `README` 文件中的说明操作，就毫无问题地构建了“传家宝” `vi`。

## 如何获取 Vim

大多数现代类 Unix 操作系统使用 `Vim` 作为 `vi` 的标准版本。^([3](#app04.html#idm46601067330896)) 也就是说，当你执行 `vi` 时，得到的是 `Vim`。

此类系统中的许多系统略微落后于最新 `Vim`。例如，截至本出版物（第八版，2021 年底），当前版本为 `Vim` 8.2，而大多数系统仍使用 `Vim` 8.0。

本节简要讨论如何在 GNU/Linux（本例中为 Ubuntu）上安装最新版本的 `Vim`（或你喜欢的任何版本）。对于其他 GNU/Linux 发行版，过程基本相同。

如果 `vi` 或 `vim` 命令无法启动你的编辑器，要么它未安装，要么你的路径不包含 `Vim` 的可执行目录。请确保你的 `PATH` 环境变量包含以下目录。（如果失败，可能 `Vim` 未安装。请继续阅读安装 `Vim` 的说明。）

/usr/bin               This should be in your $PATH anyway
/bin                   So should this
/opt/local/bin
/usr/local/bin
