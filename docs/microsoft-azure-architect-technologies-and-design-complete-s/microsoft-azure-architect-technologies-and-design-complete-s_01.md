## 简介

我曾与一位对云并不太了解的同事交谈，于是我从两个角度进行了解释：一个是消费者视角，另一个是商业视角。从消费者视角来看，云主要基于软件即服务（SaaS），个人将文件存储在 OneDrive、Google Drive、Dropbox 等平台上，或者像使用 Netflix 或 Spotify 那样消费并非存储在自己家中计算机上的内容。因此，从消费者视角看，云主要是对过去需要个人自行拥有计算能力和本地存储空间的产品进行消费。

从商业视角来看，云具有完全不同的含义，云服务的商业用户消耗计算资源，目的是为消费者提供云服务。向消费者提供这些服务需要强大的计算能力，因为客户在接收云服务时已经变得难以容忍和缺乏耐心。一次小规模的中断、电影播放中意外的暂停，或者文件下载延迟，都可能导致客户流失，有时甚至会成为新闻。拥有额外或闲置的计算能力以实现即时扩展已成为企业的必需品，但购买和管理这种能力并不具备成本效益。

我喜欢将云的诞生归因于美国的“黑色星期五”事件。黑色星期五发生在感恩节后的第二天，是一年中最大、最繁忙的购物日之一。亚马逊为了确保能够承受这一天以及整个周末的流量激增，专门为这一天增加了大量的计算能力。周末过后，他们不得不面对一个问题：这些多余的计算机该怎么办？凭借创业心态，很可能有人想到了如何利用这些服务器赚钱，于是将其出租给公司的想法应运而生。这就是亚马逊网络服务（AWS）提供的“基础设施即服务”（IaaS）的诞生，也就是我们今天所说的云。

从商业视角来看，云只是一个让公司或个人租用托管在云提供商私有数据中心内的计算机的地方。微软、亚马逊以及某种程度上谷歌等云提供商，都在为那些希望向客户提供高性能产品体验的公司提供云平台。正是这一切，让我们进入了 IT 和计算的新时代，即云时代。

2013 年，我写了一本书，名为《Windows Azure 与 ASP.NET MVC 迁移》。在那本书的引言中，我提到了 Windows Server 2003 的退役。我当时的主要观点是，避免将原本面向 Windows Server 2003 的应用程序直接迁移到云上。相反，应抓住机会进行重启、重新编写，并为应用程序开启新的起点。从编码角度，我推荐使用一些新技术，如 REST、LINQ 和 ORM；从 XML 转向 JSON；并使用如 .NET Core 这样的跨平台编程语言。从操作系统和计算资源的角度，正如人们所料，我引导读者使用 Microsoft Azure 和 Azure 应用服务等计算产品。

当时在 2013 年，我便认识到云的出现及其重要性，并预见到这个新平台将变得多么意义重大。我做出这一预测，是因为我亲身体会到为现有本地 IT 解决方案增加新计算能力的复杂性、时间和精力，更不用说成本了。我看到，在云中，现在只需点击一个按钮，就可以向 Web 场添加 1 台、10 台、20 台或 200 台新服务器。而最令人印象深刻的是，当我不再需要它们时，按下另一个按钮即可将其移除。写下这段话时，仅仅因为回忆起第一次体验这种自动缩放能力，我确实起了鸡皮疙瘩。

岁月流转，云的进展从未放缓，更多功能不断推出，让 IT 专业人员的生活更简单，也让软件产品的成本更可控。这句话并不意味着，甚至暗示理解云产品和功能是简单的——远非如此。但毫无疑问，云的出现提供了一个平台，可以将产品交付给那些有着全新且更高期望的客户。本书将帮助您更好地理解 Microsoft Azure 平台和功能，重点在于帮助您成功通过 Azure 解决方案架构师专家（AZ-303 和 AZ-304）考试。

## 本书结构

优秀的设计确实就是一切。除非你在执行之前先进行规划，否则结果很可能达不到预期。事实上，在很多情况下，即使规划得当，结果也可能不尽如人意，甚至无法成功。在规划一个大项目时，需要考虑众多的优先事项和领域。当你将现有的本地工作负载迁移到 Azure，或直接在 Azure 上创建新的应用程序和基础设施时，情况也是如此。在这两种场景下，安全、网络、计算和数据存储都会成为焦点。本书章节按优先级顺序排列，这意味着当你规划迁移或部署时，请务必确保每个阶段都包含在计划中。这些 IT 组件的分析、设计和实施顺序至关重要，这也是本书以这种方式构建的原因。

安全性迄今为止是最重要的关注点。在将计算工作负载放入网络之前，网络必须已经存在；并且请记住，在将工作负载放入网络之前，需要先确保网络的安全。接下来，你的数据、合规性与治理、消息传递概念、开发概念，以及初始部署应用程序和推进更新，都不能被忽视或遗漏。一旦部署完成，应用程序的生命周期实际上才刚刚开始；监控它，并设计和测试故障转移与灾难恢复计划，是生产级 IT 解决方案的必备要素。

遵循章节流程所呈现的这种设计模式，将帮助你成为一名优秀的 Azure 解决方案架构师专家。请注意，当你参加 Azure 解决方案架构师专家考试时，需要签署一份保密协议（NDA），声明你不会讨论考试中的任何问题或内容。这一点非常重要，这样才能保证你通过考试所获得的证书的完整性和价值。本书将帮助你学习 Azure 解决方案架构师专家应具备的技能并积累相应的经验。通过学习并实践本书中的技巧，你通过考试的概率将大幅提升。关键在于，本书致力于在 Azure 平台上培养你的经验和技能；凭借这些技能和经验，你便能够掌握相关技能组合并获得认证。

第 1 章：“获得 Azure 解决方案架构师专家认证” 本章概述了获得 Azure 解决方案架构师专家认证的路径，详细描述了新的 AZ-100、AZ-200、AZ-300 和 AZ-400 各自的角色，并具体定义了 AZ-300 和 AZ-301 的知识要求。我简要介绍了自己如何获得该认证，并在最后概述了 12 种最常见的 Azure 产品。了解这 12 种产品的内部机制、功能及其依赖关系，是顺利通过 AZ-303 和 AZ-304 考试的必修课程。本章介绍了这些产品，其内部机制将在后续相关章节中展开。

第 2 章：“安全与身份” 开始吧！假设你已拥有 Azure 订阅，那么是时候迈出下一步，将你的公司迁入云端。最初，你需要设置有权访问订阅的人员，并决定他们能做什么、不能做什么。但在深入探讨这两个主题时，你会发现它们是另一个世界、星系乃至整个宇宙。不要低估本章；请完整阅读，因为它会涉及通过考试所需的主题，而且不止于此。

第 3 章：“网络” 此时，你已经对 Azure 的安全和身份功能，尤其是那些围绕 Azure 资源管理的功能有了充分了解。现在，是时候开始规划并构建你的应用程序所运行的基础设施了。Azure 平台运行在全球最先进的数据中心内，遍布全球 50 多个区域。每个数据中心都是一个隔离的网络，拥有安全的互联网连接，并与其他区域的 Azure 资源保持超高速连接。通过在 Azure 数据中心内设置自己的虚拟网络，你可以获得更高水平的安全性和灵活性。通过 ExpressRoute 和 VPN 建立混合连接，或者仅使用 HTTPS，既简单又经济高效。本章将讨论所有这些主题，以及更多其他内容。

第 4 章：“计算” 既然安全和网络已明确并配置就绪，是时候深入 Azure 的核心了。计算是云的中心，也是企业迁移到 Azure 的原因。企业需要 CPU 和内存来运行其软件应用程序或处理数据。计算是 Azure 的核心，因为它被安全和网络的产品与功能所环绕。在本章中，你将了解众多 Azure 计算产品和功能，例如 Azure 虚拟机（VM）。Azure VM（即 IaaS）是最受欢迎的计算产品类型（Azure VM 是 Azure 最早的产品之一），但绝不是唯一或最后一种。Azure App Service、Azure Kubernetes Service（AKS）、Azure Functions、Azure Batch 和 Service Fabric 也为特定的业务场景提供计算能力。除了深入学习这些计算产品外，你还会了解每种计算产品最适合哪种场景。诸如 PaaS、事件驱动、无服务器（FaaS）、高性能计算（HPC）、微服务和容器化（CaaS）等概念也将变得清晰。

第 5 章：“数据与存储” 如果你已经读到这里，那么你离参加考试已经不远了。安全、网络和计算占据了 Azure 解决方案架构师专家考试题目的绝大部分，这些是最需要关注和专注的概念。然而，数据与存储也非常重要。没有它们，你迄今所实施的安全流程到底在保护什么？允许节点、工作站和客户端之间相互连接的网络功能又有什么价值？你为什么需要计算资源来运行工作负载和应用程序代码？原因在于，有一些数据需要处理，而这些数据需要存在于某个地方，以便计算资源从中获取。这些数据需要能被全球任何地方访问，并对任何未经适当身份验证和授权的人加以保护。应用程序代码是在计算资源上运行并完成工作的，但如果没有可供处理的工作，代码就没有存在的必要。数据及其存储方式和存储位置，是你学习和/或迁移 IT 解决方案到云端的下一个合乎逻辑的步骤。

第 6 章：“混合云、合规性与消息传递” 继续介绍一些额外的重要概念。Microsoft Azure 相对于所有其他云服务提供商的一大优势是其混合云能力。在 Azure 平台上运行混合解决方案的概念在第 1 章中就已介绍。此外，第 2 章讨论了混合 Azure 身份解决方案，第 3 章讨论了混合网络，第 4 章讨论了混合计算（又称云爆发）。当你读到本章时，混合解决方案的概念应该已经了然于心。在本章中，你将重温混合云，并可能获得一些新的见解。对于希望处理金融交易、承接政府合同以及遵守 GDPR 法律的公司来说，合规性是一个重大问题。在 Azure 上运行这类工作负载时，有许多 Azure 功能和示例模型可以帮助你实现合规。最后，你将了解一系列 Azure 产品，这些产品用于管理来自 IoT 或离线事务处理的消息的存储和管理。诸如 Service Bus、Event Hub 和 Azure Storage Queues 等服务在此时对你来说应该并不陌生。准备好更深入地了解它们以及其他消息传递产品，以及更多的技术细节和使用场景吧。





### 第7章 “为云开发”
考试中关于开发和编码的问题不会很多。Azure 解决方案架构师专家考试更侧重于在哪种场景下使用哪种工具，以及如何以最高效、最具成本效益的方式使用它们。尽管如此，你可以设计出最复杂的安全、网络、计算、数据存储和消息传递解决方案，但如果代码不稳定、不可靠或存在许多缺陷，那么一切都不会真正正常运行。你在保护一个实际上无法正常工作的应用程序，而运行在高度调优、精准定位的计算资源上也无法弥补糟糕的代码。本章将介绍一些最佳云编码模式的相关细节，以便你万一遇到此类情况时至少能有一些背景知识。

### 第8章 “迁移和部署”
在本章中，你可能会开始意识到一切都在逐渐汇聚成形。安全性、网络、计算、数据存储、数据存储服务、消息传递服务以及你的应用程序都已准备就绪。你的 RBAC 控制已实施完毕，那些需要访问不同 Azure 产品的人已经获得了访问权限。VNet 中包含了一些 Azure 虚拟机，分布在多个子网中，并由 NSG 和 Azure 防火墙保护。你的数据库正闲置着等待数据处理，你的应用程序代码已经过测试、批准并准备投入运行。你心跳加速，充满兴奋，所有艰辛的工作即将得到回报。是时候将你的数据和应用程序代码迁移到 Azure 平台了。是时候收获努力的成果了——看着你的客户和员工从 Azure 平台提供的所有好处中受益。一旦你完成本章以及之前的所有章节，你也会经历这些时刻。

### 第9章 “监控和恢复”
走到这一步，实际上你已经取得了大多数人未能取得的成就。你现在已经在 Azure 平台上运行着一个功能正常的应用程序。无论你是迁移过来的还是从零开始创建的，你的应用程序都是安全的，你已经优化了计算和数据消耗，而且你确信符合公司运营所在国家的所有法规。这值得庆祝。花一秒钟反思并庆祝你的成就吧。实际上，花一分钟也可以，但只有一分钟，然后你要认识到你并没有完全完成。尽管你已经做了很多，而且做得非常好，但你还需要确保你在 Azure 上运行的解决方案继续正常工作。如果它们停止运行，你需要快速确定原因。如果事实证明要恢复运行需要花费大量时间，你需要一个 BCDR 计划。虽然这是最后一章，但完成它之后，你的旅程实际上才刚刚开始。
