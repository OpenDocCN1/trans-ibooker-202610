You might be wondering why you were all of a sudden instructed to create an Azure resource group in West Europe (AM2). It may have become obvious when, in step 4, you saw the list of available target locations. The fact is, this replication is intended to be used for BCDR scenarios, and if you wanted to create a failover instance of your application, you would logically put it in a location closest to your users. It wouldn’t be logical to use the infrastructure in South Central US (SN1) as a failover for your infrastructure in North Europe (DB3). You might be able to create a configuration like that, but it wouldn’t be performant for your clients that were used to the performance without having to make the connection across the Atlantic Ocean during a failover. Also, as you saw, the target location in the drop-down list is in the same geography.

In Chapter 3, you learned about data centers, zones, regions, and geographies. Within geographies there are regions that are referred to as sister, twin, or most commonly named paired regions. This list you were presented with was considered the paired regions for the selected source location, as illustrated in Figure 8.19. From an Availability Zone perspective, moving Azure VMs or other products that support them is better left to the logic that runs on the platform. When you create an Azure virtual machine and choose Availability Zone as the availability option, you then pick which zone to place the VM into, for example, Zone 1, Zone 2 or Zone 3. You can also set the zone at the time of creation by using an Azure CLI command similar to the following:

```
az vm create -n MyVm -g MyResourceGroup --image Centos --zone 1
```

There is neither a `--zone` attribute available for the `az vm update` command, nor the option to update it via the Azure Portal. Therefore, you must conclude it is not possible and it makes sense not to expose such capabilities and leave it to the platform. If you choose Availability Sets from the availability option, then you are going into the VMSS direction where the zones are managed by the platform and cannot be changed.
