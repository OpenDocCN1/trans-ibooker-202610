

生产应用程序常见的难题是配置、设置以及运行应用程序所需的其他数据应存储和管理在何处。这包括诸如数据库访问凭证、第三方服务激活令牌、网络路由器和交换机配置文件、防火墙配置、缓存设置参数、数据库配置信息以及服务器配置文件等内容。

这些信息通常存储在需要使用它的地方。例如，如[Figure 4-3](#ch04.html#fig_3_configuration_throughout_an_application_and_its_in)所示，网络设备（防火墙、交换机、路由器）将其配置信息存储在设备本身中，Web 服务器配置与 Web 服务器一起存储，数据库配置与数据库一起存储。 使用这些功能所需的凭证存储在正在使用各种设备和服务的应用程序中。

![](assets/oitc_0403.png)

将设置和管理服务所需的信息直接与该信息的使用者一起存储似乎是一个不错的模式。然而，这种方法存在几个问题：

Security/vulnerability

: 

当你将凭证与使用这些凭证的用户一起存储时，如果应用程序遭到入侵，则你存储的凭证所对应的引用服务也会遭到入侵。从安全角度来看，这是不良做法。

Consistency/reusability

: 

当你将各个配置文件存储在设备本身中时，就没有关于系统如何设置和配置的集中知识。这意味着你无法比较例如一个网络路由器与另一个网络路由器的配置以查看它们有何不同，或将一个更新以匹配另一个。反过来，这意味着你无法轻松地将一个配置中使用的最佳实践应用到另一个配置中。

Availability/safety

: 

将配置文件存储在设备本身中也意味着这些信息没有冗余或备份。例如，如果一台网络交换机出现故障并需要更换，新交换机应如何配置？当配置文件存储在设备本身中时，如果设备出现故障（或遭到入侵）并需要移除，配置就会丢失。如果没有在设备外部维护备份，更换它就需要额外的工作来重建配置的要求。

Traceability

: 

如果有人更改了所需资源配置，并且该更改最终导致应用程序中断，在没有集中知识的情况下，很难发现最近发生了什么变化，这意味着很难找到并修复损坏并减轻停机时间。可追溯性长期以来被认为在软件代码中很有价值，但在基础设施配置和设置中同样重要。可追溯性并不是关于指责导致问题的人；而是关于识别发生了什么以便更快地解决问题，并在长期内创建流程和系统以确保相同的问题不再发生。

当配置信息与资源本身一起存储时，安全性、可靠性、一致性和可追溯性都会受到阻碍——正如我们在[Chapter 1](#ch01.html#what_is_the_modern_it_complexity_dilemma)中看到的那样，这可能产生严重后果。

创建、更新、管理和验证或重用基础设施配置越困难，你的应用程序中的技术债务就越大，整体运营复杂性也越大。为了解决这个问题，需要一个集中管理和控制配置的系统。

## 维护集中化的单一事实来源

控制和减少与配置相关的复杂性的最佳方法是集中维护配置信息，放在应用程序和基础设施资源本身之外。这种依赖于*single* *source of* *truth*的模型保护了你的应用程序配置，并简化了问题诊断和解决流程。信息的集中化允许重用和可重复性；正如我们所见，这降低了复杂性并提高了一致性，从而增强了可靠性。

[Figure 4-4](#ch04.html#fig_4_centralized_configuration_management)说明了这种方法。在集中式配置管理系统中，所有组件的配置都存储在单个、公共的位置。然后，当对其中任何配置进行更改时，新版本会被推送到每个对应的设备，更新其内部副本。系统相关的所有配置的权威版本都一起存储在设备之外，可以作为一个集合进行操作。这种集中存储模型使得跟踪配置及其所做的任何更改变得容易。此外，所有更改都在一个众所周知的位置进行，该位置比远程设备本身更容易访问。

![](assets/oitc_0404.png)

### 集中式事实来源与单一事实来源

维护单一事实来源并不一定意味着维护集中式事实来源。这两个概念不同，各有不同的优缺点：

*   *centralized source of truth* 是指所有配置和管理信息都维护在单个、集中的位置。
*   *single source of truth* 是指特定信息或信息类型仅维护在一个位置。它可以复制到许多备用位置（备份、不同位置等）并推送到消耗它的位置（需要配置的资源），但只有一个副本在单个位置维护和管理，并且该版本是权威版本。

为了更好地理解这种区别，请查看[Figure 4-5](#ch04.html#fig_5_multiple_single_sources_of_truth_are_decentralized)。在单一事实来源中，特定资源的 information 使用单一管理工具在单个位置管理。任何需要对配置进行更改的人都必须在此唯一位置进行更改。更改完成后并经过任何必要的审批流程后，它们将被推送到需要配置的资源。

![](assets/oitc_0405.png)

单一事实来源的优势在于一致性和可靠性。所有进行更改的人都使用一致的流程进行更改，并且所有更改都跟踪在单个位置。然而，不同资源可以使用不同的位置来管理其“单一来源”。正如[Figure 4-5](#ch04.html#fig_5_multiple_single_sources_of_truth_are_decentralized)所示，不同团队（网络团队、应用团队、数据库团队）可以独立地以不同方式管理其配置，同时仍受益于配置来自单个外部来源的优势。也就是说，各个团队可以将应用程序的配置文件存储在与其它团队不同的位置。每个配置都有一个“单一来源”，但配置之间没有集中管理。

集中式事实来源是单一事实来源的进一步发展。在集中式事实模型中，整个系统的所有配置都使用单一配置工具维护在单个位置。这在[Figure 4-6](#ch04.html#fig_6_centralized_configuration_across_teams_and_resourc)中有所说明。

![](assets/oitc_0406.png)

在这里，所有资源配置都在一个位置管理，所有团队都使用相同的工具对系统所有部分进行所有配置更改。

除了单一事实来源的所有优势外，集中式事实来源还使得比较配置以查看它们有何不同变得容易：“路由器 123 的安全设置与路由器 382 的不同吗？为什么？”
