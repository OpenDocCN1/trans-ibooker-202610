# Block Sizes and Key Lengths

Getting into the technical side of things, we’ll begin with *blocks*. In the context of cryptography, these refer to an often fixed-sized amount of data which is to be operated on by an algorithm at one time. The AES, for example, processes data in 128 bit blocks only (which is the same as 16 bytes). Encrypted files use as many blocks that are needed to include all of the plaintext/unencrypted data. If a plaintext fails to fill the last block, the remainder is filled with the so-called padding (i.e., random data in most cases) using a *padding scheme*, which we briefly touched upon in previous chapter. We’ll examine this concept in depth later in this chapter, too.

Now, just to reiterate: *key length* refers to the number of bits available to a key/password in a specific cryptographic system (see Table 3-5). A theoretical 2-bit key length would offer a whopping two different key alternatives.

The now-obsolete DES offers a 56-bit key length, providing an initially impressive 7.2 x 10¹⁶ combinations. The strongest form of AES, as in its 256-bit variety, gives us a hefty 1.1 x 10⁷⁷ key combinations, which, again, is very hard to break (Oppitz & Tomsu, 2018).
