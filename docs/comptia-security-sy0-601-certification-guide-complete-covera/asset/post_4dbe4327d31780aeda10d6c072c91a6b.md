
- **Buffer Overflow**: A buffer overflow occurs when a program tries to store more data than it can hold in a temporary memory storage area. - **Integer Overflow**: An integer overflow is a condition that occurs when the result of an arithmetic operation, such as multiplication or addition, exceeds the maximum size of the integer type used to store it.

- **SQL Injection Attack:** When you use a SQL database, you can run queries against the SQL database using Transact-SQL. An example would be, if I want to know the customers that I have in my SQL database, I can run the following Transact-SQL query: `Select * from Customers`. This will display all of the customers in my SQL database. A SQL injection attack is where the SQL command is modified to gain information from the database by ending the statement with 1=1 or placing an apostrophe in a data field. Since one equals one, the statement is true, and information will be acquired.

A stored procedure is a pre-written SQL script that might ask you for a list of all customers who have purchased items over $1,000 in the last 7 days. When this is written, it is saved as a stored procedure called *ABC*. When I run the ABC stored procedure, it will give me all of the information I require, and an attacker won’t be able to modify the script inside. This is the best way to stop a SQL injection attack. The other way is to use input validation, which is not as effective.

- **Improper Error Handling:** Applications have a tendency to create errors and the applications themselves do not validate the information returned in errors. Web servers host applications where the frontend is the webserver, and the backend is a SQL database that can hold credit card information. Attackers can use *fuzzing*, where they send random input to an application with the hope that they can get good information from the errors, such as the server IP address. They can also insert commands into SQL scripts. To prevent this, we can use input validation, and in the SQL server, we can use a sealed script called a *stored procedure*, which is much better than input validation.

- **Input Validation:** Input validation is where data is entered either using a web page or wizard; both are set up to only accept data in the correct format within a range of minimum and maximum values. Have you ever completed a web form quickly and maybe put your zip code into another field? This results in an error in the form and it fails to process the submit button. The webform then has a list at the top, in red, of the incorrect parameters, with a red star next to each of them. Once you have corrected the entries, the form will accept these and submit them. Input validation can prevent SQL injection, buffer overflow, and integer overflow attacks.

> **Exam tip**
> `strcpy` could create a buffer overflow as it could submit a huge number of characters.

- **LDAP Injection Attack:** LDAP filters request directory service information—for example, if you use `(cn=heather, ou=managers, dc=packtpub, dc=com)`. This would be a search on the packtpub domain for a user called Heather who is a manager.

An attacker can create an LDAP filter to query the directory service such as Active Directory for information.

## Example 1: Authentication Bypass

One of the common LDAP injection attacks is an authentication bypass in which the attacker can use an LDAP filter, as follows:

```
(&(user=ID*)(userID*))(|(userID=*)(password=anything))
```

This will allow the attacker to gain access without a valid username or password.

## Example 2: Check for a User in a Department

The attacker will try and use an LDAP filter, such as the following example, in which they attempt to determine if there is a user called Ian who works in sales:

```
(&(userID=Ian Neil)department=sales(objectclass=user))
```

The best way to prevent an LDAP injection attack is to use a Block-List Input Validation, preventing the use of the following characters:

| ( | ) | & | * |
|---|---|---|---|
| < | > | + | ; |
| \ | / | (blank) | " or = |

If these characters appear as an input, we will "escape" them. This means that it will be interpreted as data and not code.

It should be mandatory for all companies to use LDAPS that will encrypt your directory service traffic. More information on LDAPS can be found in *Chapter 6* under *Secure Protocols and their Use Cases*. We should also use least privilege.

# Structure of the SARS-CoV-2 spike glycoprotein (closed state)

The trimeric spike (S) glycoprotein decorates the SARS-CoV-2 virion surface and mediates host cell entry by binding to the angiotensin-converting enzyme 2 (ACE2) receptor. Each protomer is composed of an N-terminal S1 subunit responsible for receptor binding and a C-terminal S2 subunit that drives membrane fusion. The closed, prefusion conformation shown here is stabilized by inter-protomer contacts at the apex and by the fusion peptide proximal region.

Key structural domains are color-coded: the N-terminal domain (NTD) in blue, the receptor-binding domain (RBD) in the 'down' position in orange, and the S2 subunit in green. The membrane anchor and cytoplasmic tail are omitted for clarity. This model was generated using cryo-EM density maps (PDB: 6VXX) and rendered with PyMOL.

- **NTD**: N-terminal domain, involved in sugar binding
- **RBD (down)**: receptor-binding domain in the inactive conformation
- **S2**: fusion machinery, including the heptad repeat regions
- **HR1 / HR2**: heptad repeats that mediate six-helix bundle formation

> > "The spike glycoprotein is the primary target of neutralizing antibodies and the basis for most current vaccine designs."
