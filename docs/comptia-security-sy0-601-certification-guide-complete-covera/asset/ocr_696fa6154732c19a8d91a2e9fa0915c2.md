Once **Company B** confirms that Mr. Yellow's extended attributes are valid, the **Company A** domain controller sends a cookie to Mr. Yellow's laptop. This cookie is used next time for authentication.

> **Tip**
> When the exam mentions authentication using extended attributes, this can only mean federation services. Cookies used for authentication would also be federation services.

# Shibboleth

Shibboleth is an open-source federation service product that uses SAML authentication. It would be used in a small federation service environment. Shibboleth can use cookies.

# Attestation

This is when an Identity Provider (IdP) provides a mechanism that can prove the identify of a user. When using Oauth, a token is provided; and, when using Kerberos, a ticket is provided, Federation services provides a cookie, and certificate-based authentication provides a private key. When we try to prove the authenticity of a piece of code, we could use code signing to prove it is the original code.

# Single Sign-On (SSO)

SSO is used in a domain environment. This is where someone logs in to the domain and then can access several resources, such as the file or email server, without needing to input their credentials again. Think of it as an all-inclusive holiday, where you book into your hotel and the receptionist gives you a wristband that you produce when you want to consume food and drink. Federation services and Kerberos (Microsoft authentication protocol) are both good examples of SSO. You log in once and access all your resources without needing to insert your credentials again. You need to be online to use SSO; if you are offline, SSO will not work.
