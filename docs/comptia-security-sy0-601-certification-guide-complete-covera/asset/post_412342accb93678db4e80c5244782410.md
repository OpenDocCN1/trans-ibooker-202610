## Secure Data Destruction

It is very important that we dispose of data in the most secure manner to ensure that it cannot be stolen. We are going to look at sanitizing data on paper followed by data on media.

### Paper Data

When we are disposing of data, the best way of doing this, in order, is as follows:

- **Burn**: When we burn paper, we might have an incinerator on site or might get a third party carry out this task and provide us with a destruction certificate.
- **Pulping**: If burning is not available, pulping, which turns the data into paper mache, is the best option.
- **Shredding**: This is the third best way of disposing of data; a cross-cut shredder is best.

### Media Data

When disposing of data that is stored on media such as a hard drive or DVD/CD ROM, the best ways to dispose of the data are as follows:

- **Shredding**: You can shred a metal hard drive into powder, and this is the best method.
- **Pulverizing**: This is where you take a sledge hammer and smash it into small pieces.
- **Degaussing**: This is where an electrical charge is sent across the disk.

All of the above will render the media unusable. If you want to reuse the media, you need to choose wiping or formatting as the method of sanitization.

### Third-Party Solutions

Some Small to Medium Enterprises (SMEs) may not have incinerators or the proper facilities to carry out data destruction. Therefore, they have a contract with a third party who has the facilities for secure data destruction. The data destruction company will provide a proof of destruction certificate so that the SME can provide proof if audited by the regulators.

> **Exam tip**
> If you want to reuse a hard drive, then you need to sanitize it by either wiping or formatting it.

## Non-Persistence

Non-persistence is when the computer system becomes corrupt, and you can roll it back to a former state. Let’s look at each of these in turn, starting with *revert to known state*:

- **Revert to Known State:** In a Windows environment, you can save the system state, and the system’s settings, to removable media. If the computer is corrupt, then you can repair the computer and then insert the media and revert to the system state data.
- **Last Known Good Configuration:** This is where the system has recorded the configuration state as you log in. This can be reverted to at a later stage.
  
  **Example:** In a Windows environment, when you successfully log in, all of the computer’s settings are saved in a clone set (duplicate). Should the operating system not boot up, we restart the computer while pressing F8 and invoke the last known configuration.
- **Live Boot Media:** A copy of the operating system is saved to a USB flash drive or DVD. Then you will be able to boot from the removable media.

## Diversity

Companies need to use diversity within their organization so that they can be prepared for any disasters. Let’s look at diversity starting with technologies.

### Technology Diversity

This is where a company might use more than one type of operating system for their servers. Some might run Windows Server whilst other might run Linux. This ensures that they can still function should one of the operating systems become vulnerable to attack. You might have some web servers using Internet Information Servers (IIS) in a Windows environment, while others might be using Apache that runs on the Linux operating system. Once again, if one web server is exploited the other can keep a company’s web presence running.

### Vendor Diversity

We need to purchase the same technologies from different vendors just in case one of the businesses either goes out of business or faces failure. An example of this would be purchasing broadband from two different companies. This is because it is a critical area of a business and should one provider suffer a disaster, then the other would provide the service.

### Crypto Diversity

This is where a company can use different algorithms to protect their data. We know that symmetric encryption such as AES is designed to encrypt large amounts of data as it uses a block cipher, but we also know it is weak as the key size is small. AES is only 256-bit and vulnerable to attack. We may decide to diversify by using RSA to protect data where the key sizes are larger. Another example is that we might encrypt financial transactions using RSA 4096-bit keys. As an alternative, we could use blockchain to protect financial transactions as it uses the public ledger, making it harder to commit financial fraud.
