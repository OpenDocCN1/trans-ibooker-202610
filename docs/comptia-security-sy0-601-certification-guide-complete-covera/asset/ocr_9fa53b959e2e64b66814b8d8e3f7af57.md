# Application/Programming Attacks

Programming attacks use scripts or overload the characters or integers expected. Let's look at these in turn:

+   - **SSL Stripping**: This is an attack where the attackers carry out an SSL downgrade attack, where they manage to bypass the certificate-based protection and turn the session into an HTTP attack. This is where they can now capture data such as credit card numbers.
+   - **Resource Exhaustion**: This is where an attack on an application consumes all available memory and CPU cores. It could also be where all IP addresses have been allocated on a DHCP server.
+   - **Dynamic Link Library (DLL) Injection**: This is a technique used for running code within the address space of another process by forcing it to load a DLL. This makes the application run differently from how it was designed to. For example, you could install a malware DLL in another process.
+   - **Cross-Site Request Forgery (CSRF)**: This is known as CSRF, or XSRF. The user must be authenticated to the webserver where the user clicks on a link, like, or share button to perform an action.

CSRF could be used to make purchases, make a bank transfer, or change a password.

**Example:** The diagram below shows a person who is going to make a bank transfer that sends $100 to Ian using a web banking application. The attacker could use an exploit URL that could change the transaction as follows:

```
http://bank.com/transfer.do?acct=George&amount=100000
```

This would change the payment to George's account for an amount of $100,000.

Another example would be an email enticing someone to click on a link for a free holiday:

```
<a> href="http://bank.com/transfer.do?acct=GEORGE&amount=1000">Free Holiday </a>
```
