机密计算使组织能够在数据和代码使用过程中防止未经授权的访问。硬件信任根和证明作为机密计算的基石，使组织能够在充分利用公有云的同时实施零信任，因为它们有能力验证云环境。在下一章中，您将了解 Azure 机密计算（ACC）平台，包括其各种功能和支持服务，这些功能和服务使组织能够在 Azure 上运行各种机密工作负载。

## 第 2 章。用例和场景

本章探讨机密计算的各种用例及其如何在不同场景中保护数据隐私。这些场景包括受监管行业中敏感工作负载的平移式迁移、主权政府工作负载、数据干净室、机密 AI 和其他用例。

### 平移式迁移

当今的机密计算技术使组织（尤其是高度监管行业的组织）能够以最小的努力将现有敏感工作负载迁移到公有云，或为已经在公有云中运行的工作负载增加进一步保护。借助 VM 级别和容器级别隔离技术，组织现在可以将其最敏感的基于 VM 和容器的工作负载迁移到支持机密计算的基础架构，无需对代码进行任何更改，从而加速这些技术的采用。

### 主权政府工作负载

政府和公共机构由于其管理的数据具有敏感性，因此需要高度的数据主权。此外，内部风险和间谍活动等威胁的存在，为政府在考虑使用公有云时带来了巨大的障碍，因为这样做需要信任云运营商。机密计算通过实施确保数据和代码免受未经授权访问（甚至云运营商也无法访问）的方法，减少了对云运营商固有信任的需求。机密计算使高度机密的工作负载能够在云中运行，并使政府在云中迁移和运行工作负载时能够采用永不信任、始终验证的安全思维。Microsoft Azure 通过 Microsoft Cloud for Sovereignty 满足这些要求。

### 数据干净室

数据干净室的目标是允许多个数据提供者与模型和算法提供者共享数据，以便从更广泛的、此前不可用的数据集中获得洞察，同时保持治理和隐私规则。机密计算通过提供加密验证来实现数据干净室，该验证证明数据提供者无法访问数据或相关模型，即使正在对其进行计算。这通过保证不允许任何方访问数据或模型，强化了零信任原则。

### 机密 AI

机密 AI 是一组基于硬件的技术，例如通用 CPU 和 GPU，用于建立可信执行环境（TEE），旨在保护 AI 生命周期中的数据和模型，即使在数据和模型使用过程中也是如此。其目标是在 AI 数据处理的所有阶段（包括数据收集、预处理、训练和 AI 模型部署）中保护数据。机密计算在促进机密 AI 解决方案方面发挥着关键作用，因为它可以在性能开销极小的情况下访问敏感数据集，同时解决与同态加密等技术相比的安全性和合规性问题。图 2-2 说明了机密 AI 的各种用例。

机密计算使数据提供者能够为其数据集的非常具体的目的授权使用，例如训练或调整已商定的模型，同时在计算过程中保持数据的机密性。数据提供者还可以通过证明请求证明，证明其数据集仅在 TEE 中处理。

近年来，生成式 AI 已成为创新和颠覆的重要领域。大语言模型（LLM）如生成式预训练变换器（GPT）、大语言模型 Meta AI（LLaMA）及其他许多模型的普及程度呈指数级增长。由于这些模型及相关工作负载高度依赖 GPU，Microsoft 和 NVIDIA 正在密切合作，如博客文章“Azure Confidential Computing with NVIDIA GPUs for Trustworthy AI”中所述，将 GPU 加速计算引入 Azure 上的机密计算。

这一点很重要，因为当数据在 CPU 与 GPU 之间传输时，数据始终处于加密状态，并且只能在 GPU 内硬件保护的隔离安全区中解密。在那里，数据可以被处理以构建 AI 模型或生成 AI 推理输出。如需更深入地了解 NVIDIA 的 GPU 安全模型，请阅读白皮书“Confidential Compute on NVIDIA Hopper H100”。

### 其他用例

Azure 机密计算是一项宝贵的技术，适用于各行各业的广泛场景，包括政府、金融服务、医疗保健等许多领域。以下列表概述了机密计算影响巨大的各个行业。如需了解机密计算的其他用例，请阅读“用例和场景”。

### 政府

- 数字身份
- 关键基础设施
- 反腐败
- 网络犯罪防范
- 司法程序和案件管理
- 已部署和断开连接的操作

### 金融服务

- 反洗钱
- 数字货币
- 安全支付处理
- 欺诈预防
- 基于合并银行记录的信用风险评估和资格
- 资本市场/保护量化对冲基金代码和模型
- 专有分析/算法

### 医疗保健

- 疾病诊断
- 保险欺诈预防
- 药物开发
- 接触者追踪
- 记录和证据管理
- 保险欺诈、浪费和滥用预防
