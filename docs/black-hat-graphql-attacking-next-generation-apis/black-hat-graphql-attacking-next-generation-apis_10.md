## 引言

![](img/2f244b00cd9f8f37cfc22f928aaa471a_22_0.png)

2015 年，我们第一次在多伦多市中心的咖啡馆见面，希望建立一个本地黑客社区。那次会面是多伦多官方 DEFCON 分会的起源。从那时起，我们一直合作破解 Web 应用、汽车、锁、智能建筑和 API。近年来，我们将注意力集中在另一个挑战上：广阔的 GraphQL 攻击性安全领域。

作为一种相对较新的技术，GraphQL 查询语言改变了 API 范式，吸引了许多希望优化性能、扩展性和易用性的公司。然而，完全理解这种查询语言的安全影响需要时间。我们的合作解锁了关于 GraphQL 及其生态系统的大量新见解。事实上，本书中引用的许多漏洞和利用从未被发表过。我们通过联合研究发现了其中一些，包括独特的、从未见过的弱点。此外，我们自己也是本书中重点介绍的许多 GraphQL 安全工具、教育安全平台和利用的作者和维护者。

本书为攻击性安全工程师以及防御者提供了实用资源。通过弥合黑客社区与 GraphQL 生态系统之间的差距，我们旨在改进这一日益流行的技术，加强使用它的众多行业的安全性，并教育工程师如何攻击和防御他们的 GraphQL API。

## 本书适合谁

本书适合任何有兴趣通过应用攻击性安全测试学习如何破解和保护 GraphQL API 的人。无论您是一名听说过 GraphQL 并希望提升黑客专业技能的渗透测试员，一名希望提高如何防御 GraphQL API 知识的安全分析师，还是计划构建 GraphQL 支持应用的软件工程师，您都应能从本书中获得大量有用信息。通过学习如何攻击 GraphQL API，您可以制定加固程序，将自动化安全测试构建到集成和交付管道中，并有效验证控制措施。

本书假设您之前没有接触过 GraphQL。如果您已经了解该技术，前三章将强化语言的一些基础知识，并讨论高级主题。然后您可以从第 4 章开始深入攻击性安全方面。

## 本书的实验室和代码仓库

您可以在专为 GraphQL 黑客定制的安全实验室中练习本书涵盖的所有内容，我们特别策划了该实验室。我们强烈建议通过运行各种工具并查询 GraphQL API 来实验贯穿 10 章的材料。您将在第 2 章设置实验室。

此外，我们鼓励您克隆本书的代码仓库，位于 https://github.com/dolevf/Black-Hat-GraphQL。仓库包含按章节排序的工件，例如 GraphQL 代码示例、利用、查询等。我们还承认，随着安全社区更好地学习如何黑客攻击和保护 GraphQL API，将会出现新的工具和研究论文。因此，我们在仓库中创建了一个特殊部分，用于记录这些资源供您使用，位于 tools 文件夹下。

## 本书内容

本书在前三章中阐述了基础和高级 GraphQL 概念，并指导您设置安全专业人员进行 GraphQL API 安全测试所需的实验室工具。通过

第 4 章，您将对 GraphQL 作为技术的工作原理有扎实的理解。本书其余部分保留用于学习和实践 GraphQL 渗透测试的艺术，这将使您能够自信地在未来的安全工作中测试 GraphQL API。本书末尾的附录 A 中，您可以找到 GraphQL 安全测试备忘单，以及附录 B 中关于如何进一步了解 GraphQL 的额外课外资源。以下摘要提供了每章的更多细节。

在第 1 章：GraphQL 入门中，您将了解该技术并学习它与其他 API 协议的不同之处。特别是，我们将通过使用每种方式的示例演示 GraphQL 与 REST API 之间的差异。这应该能说明它们的相对优势和劣势，并阐明为什么 GraphQL 在 API 领域 slowly 逐渐获得市场份额。您还将运行您的第一个 GraphQL 查询。

第 2 章：设置 GraphQL 安全实验室收集了目前最好的 GraphQL 安全工具，供您长期渗透测试实验室环境使用。我们将指导您安装和配置它们。其中一些工具是我们自己编写的，而其他工具则由其他安全专业人员慷慨地作为开源软件发布。

如果您是 GraphQL 新手，请密切关注第 3 章：GraphQL 攻击面。本章有两个目标：向您介绍该技术的许多组件，并使您能够在黑客背景下思考这些概念。在本章中，您将了解 GraphQL 语言和类型系统。在学习类型系统后，您将了解 GraphQL 模式在幕后是如何工作的。在学习语言系统后，您将知道如何针对 GraphQL API 构建和执行查询。我们还将概述 GraphQL 中常见的弱点，为第 4 章至第 9 章做准备。

在第 4 章：侦察中，我们将使用数据收集和目标映射来应用工具和技术，以尽可能多地了解我们的目标。如果不做这项功课，我们就会在黑暗中射击并浪费宝贵时间。您将学习信息收集技术，这将使您能够对 GraphQL 目标的基础设施做出有根据的猜测并提高成功机会。

在第 5 章：拒绝服务中，您将学习如何实现性能下降或完全服务器停机。拒绝服务是 GraphQL 中最普遍的漏洞之一，本章涵盖了通过执行特殊查询使服务器不稳定的众多技术。您还将了解 GraphQL API 如何以更具弹性思维的方式构建，使用防御性 GraphQL 安全控制。

知识就是力量，正如您将在第 6 章：信息泄露中了解的那样，某些 GraphQL 设计决策可能导致信息泄露漏洞。我们将利用不安全的配置并滥用 GraphQL 功能来重建加固目标上的模式。我们还将利用 GraphQL 服务器中的错误和调试机制来推断目标的重要信息。

您应该期望在任何托管有价值数据的应用程序或 API 中找到授权和身份验证控制，但这些并不总是



easy to implement securely. **第 7 章：身份验证和授权绕过** 将教你如何测试这两个重要控制中的绕过，从而使我们能够冒充用户、执行未经授权的操作以及查看未经授权的信息。

处理用户输入是必要的恶。 大多数应用程序都需要它，但我们永远不应信任它，因为它可能是恶意的。 **第 8 章：注入** 将涵盖几种注入类型以及它们如何通过接受用户输入的 GraphQL 接口引入。 我们将使用手动技术以及自动化工具来发现服务器、数据库和客户端浏览器中的注入型漏洞。

在 **第 9 章：请求伪造和劫持** 中，我们将讨论跨站请求伪造和服务器端请求伪造，这两种基于伪造的漏洞会影响客户端和服务器。 我们还将讨论跨站 WebSocket 劫持：一种用于窃取用户会话的攻击，影响 GraphQL 订阅。 通过使用多种 HTTP 方法发送 GraphQL 查询，我们将针对客户端并强制服务器代表我们请求敏感信息。

在 **第 10 章：披露的漏洞和利用** 中，我们将探索十多个漏洞披露报告并审查影响 GraphQL API 的利用代码。 我们将剖析这些工件以强化前几章的要点并揭示漏洞如何影响运行生产环境 GraphQL API 的大型公司。

作为计算机安全爱好者，我们很荣幸通过与行业分享我们的知识为黑客社区做出贡献。 借助我们的视角，你也可以帮助企业更好地保护其 GraphQL 应用程序。 请记住，本书的内容仅用于教育目的。 我们强烈鼓励你在对应用程序进行任何渗透测试之前获得正式授权。
