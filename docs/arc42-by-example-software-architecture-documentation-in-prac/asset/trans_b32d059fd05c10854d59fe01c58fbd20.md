## 持久性

`biking2` 使用 H2 (https://www.h2database.com/html/main.html) 数据库存储关系数据，并使用文件系统存储二进制图像文件和大型 ASCII 文件（尤其是所有 GPS 文件）。

在开发和生产环境中，H2 数据库会被保留且不是基于内存的。该文件的位置通过 `biking2.database-file` 属性配置，开发期间的默认值是 `./var/dev/db/biking-dev`，其相对 VM 的工作目录。

所有对数据库的访问都通过 JPA 进行，其使用 Hibernate 作为提供者。有关应用中使用的所有实体，请参阅 `Domain Models`。JPA Entity Manager 不会被直接访问——只能通过 Spring Data JPA 提供的设施访问；即通过仓库。所有以文件形式存储的数据都相对于 `biking2.datastore-base-directory` 存储，默认值为 `./var/dev`。其中包含三个目录：
* `bikingPictures`：包含从 Daily Fratze 收集到的所有图片
* `galleryPictures`：包含所有上传的图片
* `tracks`：包含上传的 GPS 数据以及将 TCX 文件转换为 GPX 文件的结果

## 用户界面

打包在最终构件中的 `biking2` 默认用户界面是一个使用 AngularJS 编写的 JavaScript SPA，并配有默认的 Bootstrap 模板。

要使用实时位置更新界面，请选择众多 MQTT 客户端之一。

还有一个用 Java 编写的第二个用户界面，名为 `bikingFX` ([https://info.michael-simons.eu/2014/10/22/getting-started-with-javafx-8-developing-a-rest-client-application- from-scratch/](https://info.michael-simons.eu/2014/10/22/getting-started-with-javafx-8-developing-a-rest-client-application-%20from-scratch/))。

## JavaScript 和 CSS 优化

JavaScript 和 CSS 依赖尽可能通过 Maven 依赖以 webjars 形式管理（[https://www.webjars.org](https://www.webjars.org)），无需 `brew`、`npm`、`bower` 等。

此外，`biking2` 使用 `wro4j`（[https://alexo.github.io/wro4j/](https://alexo.github.io/wro4j/)），以及一个小型 Spring Boot Starter（[https://github.com/michael-simons/wro4j-spring-boot-starter](https://github.com/michael-simons/wro4j-spring-boot-starter)）来优化 JavaScript 和 CSS 网络资源。

## 事务处理

`biking2` 依赖 Spring Boot 创建处理 JPA EntityManager 中本地事务所需的所有 bean。`biking2` 不支持分布式事务。

## 会话处理

`biking2` 仅提供无状态的公共 API；没有会话处理。

## 安全

`biking2` 为其 API 端点提供安全性，但仅通过 HTTP 基本访问认证（[https://en.wikipedia.org/wiki/Basic_access_authentication](https://en.wikipedia.org/wiki/Basic_access_authentication)）。对于 MQTT 模块，它使用 MQTT 的默认安全模型。安全性可以通过在 SSL 代理后面运行应用程序或在嵌入式 Tomcat 容器中配置 SSL 支持来提高。对于此处管理的数据类型，保持应用程序简单是一种商定的权衡。有关更多信息，请参阅安全部分。

## 安全

系统没有任何危及生命的部分。

## 通信和集成

`biking2` 在与应用程序相同的 VM 上使用内部 Apache ActiveMQ 代理来提供 STOMP 通道和 MQTT 传输。该代理是易失性的，因此在应用程序重启期间消息不会被持久化。

## 合理性和有效性检查

数据类型和范围通过 `JSR-303`（[https://beanvalidation.org/1.0/spec/](https://beanvalidation.org/1.0/spec/)）对表示 `Domain Models` 的类上的注解进行检查。这些类直接绑定到外部 REST 接口。

有三项重要的业务检查：
1. 已退役的自行车不能被修改（即不能有新的里程）。在 `BikesController` 中检查。
2. 对于每个月，每辆自行车只能添加一次里程。在 `BikeEntity` 中检查。
3. 新的里程必须大于上一次的里程。也在 `BikeEntity` 内部检查。

## 异常/错误处理

处理不一致数据（关于数据模型约束）以及验证失败的错误会被映射为 HTTP 错误。这些错误由前端的控制器代码处理。技术错误（硬件、数据库等）未被处理，可能导致应用程序失败或数据丢失。

## 日志和追踪

Spring Boot 默认将日志配置为标准输出。在这方面默认配置未被更改，因此所有框架日志（尤其是 Spring 和 Hibernate）都以标准格式输出到标准输出，可通过特定于操作系统的手段捕获或忽略。

所有业务组件都使用 Java 简单日志门面（SLF4J）。日志的实际配置通过 Spring Boot 配置。没有手动包含特殊实现；相反，`biking2` 通过传递依赖于 `spring-boot-starter-logging`。

记录器的名称与实例化记录器的类的包名相对应，以便在日志中立即识别模块。

## 可配置性

Spring Boot 提供大量配置选项。这些是配置 Spring Boot 的主要选项，并且有可用的启动器：通用应用程序属性（[https://docs.spring.io/spring-boot/docs/current/reference/html/common-application-properties.html](https://docs.spring.io/spring-boot/docs/current/reference/html/common-application-properties.html)）。
