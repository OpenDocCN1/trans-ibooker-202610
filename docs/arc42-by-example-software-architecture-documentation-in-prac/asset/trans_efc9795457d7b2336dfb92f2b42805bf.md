`HtmlSanityCheck` (`HtmlSC`) 检查 HTML 中的语义错误，例如损坏的链接和缺失的图像。它是为了支持将 HTML 作为输出格式创建的作者而创建的。此操作可以解释如下：

1. 作者使用 `AsciiDoc` ([https://asciidoctor.org/docs/what-is-asciidoc/](https://asciidoctor.org/docs/what-is-asciidoc/))、`Markdown` ([https://www.daringfireball.net/projects/markdown/syntax](https://www.daringfireball.net/projects/markdown/syntax)) 等格式以及其他格式编写，这些格式由相应的生成器转换为 HTML。
2. `HtmlSC` 检查生成的 HTML 是否存在损坏的链接、缺失的图像和其他语义问题。
3. `HtmlSC` 创建一个类似于众所周知的单元测试报告的测试报告。

### 基本用法

`HtmlSC` 的使用说明如下：

1. 用户配置一个或多个 HTML 文件的位置（目录和文件名）以及相应的图像目录。
2. `HtmlSC` 对 HTML 执行各种检查，并将结果报告到控制台或作为 HTML 报告。

`HtmlSC` 可以从命令行运行或作为 `Gradle` 插件运行。

## II.4 解决方案策略

#### 注

您需要提供基本解决方案思路和策略的简要总结和说明。这些关键思想应为开发和架构过程中的每个人所熟悉。

简要说明如何实现最重要的质量要求。

以下步骤将解释解决方案设计的基础：

1. 主要使用 `Groovy` 编程语言，部分使用 `Java` 实现 `HtmlSC`，并保持外部依赖最小化。
2. 我们将此实现封装为 `Gradle` 插件，以便在自动化构建中使用。详细信息请参阅 `Gradle` 用户指南（[https://docs.gradle.org/current/userguide/userguide.html](https://docs.gradle.org/current/userguide/userguide.html)）。`Maven` 插件仍在开发中。
3. 应用模板方法模式（[https://sourcemaking.com/design_patterns/template_method/](https://sourcemaking.com/design_patterns/template_method/)）以启用多个检查算法（参见检查算法的概念）以及 HTML（文件）和文本（控制台）输出。
4. 依赖标准 `Gradle` 和 `Groovy` 约定进行配置，并拥有单个配置文件。对于 `Maven` 插件，这可能会导致问题。
