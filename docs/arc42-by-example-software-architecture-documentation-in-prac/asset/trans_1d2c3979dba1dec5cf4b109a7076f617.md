# 致谢

### Dr. Gernot Starke

很久以前，2004 年一个冬天的日子里，我与我的老朋友 Peter Hruschka 一起坐下，讨论我们共同喜爱的主题之一——软件系统的结构和概念。我们反思了一个我们在工作中经常遇到的问题，与客户、领域或技术无关：开发人员熟悉实现/技术；管理者熟悉预算和风险管理。但当被迫传达或甚至记录系统的架构时，他们常常开始发明自己特定的表达结构、设计、概念和决策的方式。

Peter 谈到了他在需求工程方面的经验：他向我介绍了一个名为 VOLERE 的需求模板，一个预先结构化的柜子或文档，其中包含特定需求文档中可能重要的所有内容的占位符。因此，在处理需求时，工程师无需长时间思考即可将结果放在正确的位置——只要其他人了解 VOLERE 的结构，就能稍后检索它们。这个需求模板在业界已使用多年——甚至有一本关于其使用方法和底层方法的书籍。

“如果我们只有软件架构的类似模板，”Peter 抱怨道，并继续说，“无数 IT 项目可以节省大量时间和金钱。”我开发者灵魂默默希望：“如果这很棒，它甚至可以消除文档的丑陋。”我们两人互相看着对方，并在那一瞬间决定创造正是这样：一个软件架构文档和沟通的模板，具有高度实用性，允许简单高效的文档编写，可供各种利益相关者使用，并能促进软件架构文档化。当然，它必须是开源的——组织可以完全免费使用。

这就是 arc42 之旅的开始。从那时起，Peter 和我已在各种领域的数十个不同的 IT 系统中使用了 arc42。它在世界各地的小型、中型和大型组织中获得了显著的认可。我们已撰写了许多相关文章，向超过 1,000 名 IT 专业人士教授它，并将其纳入我们多本与软件架构相关的书籍中。谢谢你，Peter，陪我开启这段疯狂的旅程。当然，还有你的烹饪讲座。感谢我的客户——与你们一起处理你们复杂的、庞大的、困难的、有趣的，有时甚至令人紧张的问题，我学到了难以置信的知识。由于我一生中签署了所有那些保密协议，我不被正式允许点名提及你们所有人。

感谢我的妻子 Cheffe Uli 和我的孩子 Lynn 和 Per，允许爸爸再次坐在那把大红椅子上思考另一个书籍项目……你们是最棒的，我认为自己非常幸运拥有你们！感谢我的父母，他们在 1985 年，当计算机被视为介于犯罪和巫术之间的东西时，鼓励我买一台 Apple II，顺便说一下，而且在我想要学习计算机科学而不是当时更严肃的东西时也没有反对。你们很棒！

### Michael Simons

我于 2015 年底在一门培训课程上遇到了 Dr. Gernot 和 Peter Hruschka 作为讲师。该培训课程名为“Mastering Software Architectures”，我从他们两人那里学到了很多东西；不仅是他们分享的知识，还有他们分享知识的方式。到培训结束时，我可以称自己为“Certified Professional for Software Architecture”，但我真正带走的是希望像 Peter 和 Dr. Gernot 建议的那样结构化、记录和传达我自己的项目，这就是为什么我的宠物项目 biking2 的当前文档被创建的原因。

从那时起，我多次使用基于 arc42 的文档：用于内部产品，也用于项目和咨询工作。我收到的最好反馈大致是：“哇，我们现在对这个模块发生了什么有了实际的想法。”帮助那个特殊项目很多的是，我们完全使用 Asciidoctor 以及我在博客中深入描述的“代码即文档和文档即代码”方法。所以，敬 Dr. Gernot 和 Peter：感谢你们的灵感和 arc42 的想法。

### Ralf D. Müller

很久以前，我发现 arc42 模板是一个 MS Word 文档。花不了多久我就看到了它的有用性并开始在我的项目中使用它。很快，我发现 MS Word 作为一名开发架构师来说并不是最好的格式。我开始尝试各种基于文本的格式，例如 Markdown 和 AsciiDoc，也尝试了维基。JAX 大会是我与 Dr. Gernot 交流想法的机会。他告诉我 Jürgen Krey 已经创建了 arc42 模板的 AsciiDoc 版本。我们开始将此模板视为黄金主模板——这是在 5 年前——2014 年，并尝试从此模板生成当时所需的所有其他格式，主要是 MS Word 和 Confluence。arc42-generator 诞生了，一段美妙的旅程即将开始。这段旅程的当前高峰是 docToolchain——arc42-generator 的演进。阅读本书了解其架构的更多信息。
