## 手动配置Telegraf

如果您希望从插件UI所示环境之外的其他环境收集输入，可以手动配置Telegraf配置文件（telegraf.conf），以从多个输入源捕获数据并将数据发送到InfluxDB。具体做法是配置telegraf.conf文件，使其包含一个输入插件，该插件与influxdb_v2输出插件协同工作，将指标写入InfluxDB bucket。让我们看一个示例来加深理解。

- 1. 首先，我们需要从Telegraf插件页面（https://v2.docs.influxdata.com/v2.0/reference/telegraf-plugins/）找到我们感兴趣的输入插件。有各种各样的插件可用于从应用程序和第三方系统收集指标并与InfluxDB一起使用。对于图5-42，我们选择了OpenWeatherMap作为我们的输入插件。

![](img/6646c41cea18bb4f7d3c2c6513a4d992_170_0.png)

图5-42. OpenWeatherMap输入插件

- 2. 点击“查看”将打开GitHub上的Telegraf输入插件页面。您可以阅读该插件的功能说明，并将配置复制粘贴到您的telegraf.conf文件中。

- 3. InfluxDB输出配置可在“Load Data - Telegraf”页面获取。下载配置并粘贴到telegraf.conf中，以将数据发送到InfluxDB v2.0实例，如图5-43所示。

## Telegraf输出配置

可以在“Tokens”选项卡上生成$INFLUX_TOKEN。

```
[[outputs.influxdb_v2]]
## The URLs of the InfluxDB cluster nodes.
##
## Multiple URLs can be specified for a single cluster, only ONE of the
## urls will be written to each interval.
## urls exp: http://127.0.0.1:9999
urls = ["http://localhost:9999"]

## Token for authentication.
token = "$INFLUX_TOKEN"

## Organization is the name of the organization you wish to write to; must exist.
organization = "monitoringcloudnativeapps"

## Destination bucket to write into.
bucket = "ui-loaddata-bucket"
```

InfluxDB基于LSM-Tree⁸概念在LevelDB中的SSTable，LevelDB实际上在InfluxDB的早期版本中用作存储引擎。InfluxDB自己的存储引擎基于时间结构化合并（TSM）树，是一个集合

InfluxDB具有与SQL类似的结构，两者之间的比较将显示它们的数据元素相似。让我们详细了解InfluxDB中的一些重要概念：

| SQL数据库 | InfluxDB |
|---|---|
| 表 | 测量 |
| 行 | 点 |
| 索引列 | 标签 |
| 未索引列 | 字段 |
| 存储过程 | 连续查询 |

**测量（_measurement）**：InfluxDB表中的测量列描述了该表的内容。测量通常是一个字符串，作为标签、字段和时间戳等其他元素的容器。例如，表5-1中的测量值为**cpu**，这表明该表与cpu指标的测量有关。

**时间戳（_time）**：数据在InfluxDB中始终以对应的_time值存储，这是该数据的时间戳。由于它是一个时间序列数据库，日期和时间通常以RFC3339 UTC格式存储。

**字段（_field）**：字段通常是一个表示字段名称的字符串。在前面的示例中，_field为usage_system。

**字段值（_value）**：字段值可以是字符串、整数、浮点数或布尔值，表示字段的值。例如，在第一行中，_field usage_system在该特定时间的_value为46.19。

**字段集**：字段与其对应字段值的键/值对称为字段集。

**标签键**：在前面的示例中，字段**cpu**是标签键。

9 RFC3339是日期和时间的人类可读格式（2020-01-01T00:00:00.00Z），用作时间序列数据库中的时间戳。更多详情，请参阅https://www.ietf.org/rfc/rfc3339.txt。
