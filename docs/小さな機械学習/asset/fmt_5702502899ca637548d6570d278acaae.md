
```
test -f tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/hello_world.bin \
  &&  echo "Binary was successfully created" || echo "Binary is missing"
```

このコマンドを実行すると、コンソールに`Binary was successfully created`。

`Binary is missing`が表示された場合、ビルドプロセスに問題があったことになる。もしそうなら、`make`コマンドの出力の中に、何が問題だったのかの手がかりが発見できるかもしれない。

### バイナリに署名する

バイナリをデバイスにデプロイするには、暗号鍵で署名する必要がある。それでは、バイナリをSparkFun Edgeにフラッシュできるように署名するコマンドをいくつか実行してみよう。ここで使用するスクリプトは、Makefileの実行時にダウンロードされるAmbiq SDKのものである。

以下のコマンドを入力し、開発に使えるダミーの暗号鍵をセットアップする：

```
cp tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info0.py \
  tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info.py
```

次に、以下のコマンドを実行して署名付きバイナリを作成する。必要に応じて、`python3`を`python`で置き換える：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_image_blob.py \
  --bin tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/hello_world.bin \
  --load-address 0xC000 \
  --magic-num 0xCB -o main_nonsecure_ota \
  --version 0x0
```

これで`main_nonsecure_ota.bin`ファイルが作成される。次のステップで使用するスクリプトでデバイスをフラッシュするために使用できるファイルの最終バージョンを作成するために、このコマンドを実行する：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_wireupdate_blob.py \
  --load-address 0x20000 \
  --bin main_nonsecure_ota.bin \
  -i 6 \
  -o main_nonsecure_wire \
  --options 0x1
```

これで、コマンドを実行したディレクトリに`main_nonsecure_wire.bin`というファイルができるはずだ。これがデバイスにフラッシュするファイルだ。

### バイナリをフラッシュする

SparkFun Edgeは、現在実行中のプログラムを1メガバイトのフラッシュメモリーに保存する。ボードに新しいプログラムを実行させたい場合は、そのプログラムをボードに送信する必要があり、ボードはそれをフラッシュ・メモリーに保存し、以前に保存されたプログラムを上書きする。

このプロセスはフラッシングと呼ばれている。その手順を説明しよう。

#### プログラマを基板に取り付ける

ボードに新しいプログラムをダウンロードするには、SparkFun USB-C Serial Basicシリアル・プログラマを使用する。このデバイスにより、コンピューターはUSB経由でマイクロコントローラーと通信できる。

このデバイスをボードに取り付けるには、以下の手順を実行する：

1. SparkFun Edgeの側面に6ピンのヘッダがある。
2. SparkFun USB-C Serial Basicをこれらのピンに差し込み、各デバイスのBLKとGRNと書かれたピンが正しく並んでいることを確認する。

[図6-13に](#ch06.html#sparkfun_edge_serial_basic)正しい配置を示す。

![](assets/timl_0613.png)

#### プログラマをコンピュータに取り付ける

次に、ボードをUSBでコンピューターに接続する。ボードをプログラミングするには、コンピューターがデバイスに付けている名前を特定する必要がある。これを行う最良の方法は、接続前と接続後のコンピュータのデバイスをすべてリストアップし、どのデバイスが新しいかを確認することである。

###### 警告

プログラマ用のオペレーティング・システムのデフォルト・ドライバに関する問題が報告されている人もいるので、先に進む前に[ドライバを](https://oreil.ly/Wkxaf)インストールすることを強く勧める。

USBでデバイスを接続する前に、以下のコマンドを実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

以下のようなリストが出力されるはずだ：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
```

プログラマをコンピューターのUSBポートに接続し、コマンドをもう一度実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

次の例のように、追加の項目が出力されるはずである。新しい項目の名前は違うかもしれない。この新しい項目はデバイスの名前である：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
/dev/cu.wchusbserial-1450
```

この名前は、デバイスを参照するために使用される。ただし、プログラマがどのUSBポートに接続されているかによって、この名前が変わることがあるので、コンピュータからボードを取り外して再度接続した場合は、名前を調べ直す必要があるかもしれない。

###### チップ

ユーザによっては、リストに2つのデバイスが表示されるという報告がある。2つのデバイスが表示された場合、正しい方は "wch "で始まる。

デバイス名を特定したら、後で使えるようにシェル変数`DEVICENAME`に入れておく：

```
export DEVICENAME=<your device name here>
```

これは、後でデバイス名を必要とするコマンドを実行するときに使用する変数である。

#### スクリプトを実行してボードをフラッシュする

ボードをフラッシュするには、新しいバイナリを受け取るための特別な「ブートローダー」状態にする必要がある。その後、ボードにバイナリを送信するスクリプトを実行することができる。

まず、ボーレートを指定する環境変数を作成する。ボーレートとは、データをデバイスに送信する速度である：

```
export BAUD_RATE=921600
```

次のコマンドをターミナルにペーストする。コマンドの`${DEVICENAME}`と`${BAUD_RATE}`は、前のセクションでセットした値に置き換えられる。必要であれば、`python3`を`python`で置き換えることを忘れないこと：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/ \
  uart_wired_update.py -b ${BAUD_RATE} \
  ${DEVICENAME} -r 1 -f main_nonsecure_wire.bin -i 6
```

次に、ボードをブートローダーの状態にリセットし、ボードをフラッシュする。ボード上で、[図6-](#ch06.html#sparkfun_edge_buttons)14に示すように、`RST`と`14`と記されたボタンを探す。

![](assets/timl_0614.png)

以下の手順を実行する：

1. ボードがプログラマに接続され、全体がUSB経由でコンピューターに接続されていることを確認する。
2. ボード上で、`14`と書かれたボタンを押し続ける。そのまま押し続ける。
3. `14`と書かれたボタンを押したまま、`RST`と書かれたボタンを押してボードをリセットする。
4. コンピュータでEnterキーを押してスクリプトを実行する。`14`ボタンを押し続ける。

これで画面に次のようなものが表示されるはずだ：


## プログラミングをテストする

これでバイナリがデバイスにデプロイされたはずである。`RST`と書かれたボタンを押して、ボードを再起動する。デバイスの4つのLEDがシーケンスで点滅するのが見えるはずだ。よくやった！

## デバッグデータを見る

デバッグ情報は、プログラムの実行中にボードによって記録される。これを見るには、ボーレート115200を使ってボードのシリアル・ポート出力をモニターすればよい。macOSとLinuxでは、以下のコマンドが動作するはずだ：

```
screen ${DEVICENAME} 115200
```

たくさんの出力が飛び交うのが見えるだろう！スクロールを止めるには、Ctrl-Aを押した直後にEscを押す。その後、矢印キーを使って出力を探索することができる。出力には、`x`のさまざまな値に対して推論を実行した結果が含まれている：

```
x_value: 1.1843798*2^2, y_value: -1.9542645*2^-1
```

`screen`でデバッグ出力の表示を停止するには、Ctrl-Aを押し、すぐにKキーを押し、次にYキーを押す。

###### 注

`screen`というプログラムは、他のコンピューターに接続するための便利なユーティリティー・プログラムだ。今回は、SparkFun Edgeボードがシリアルポート経由でロギングしているデータをリッスンするために使用する。Windowsを使っている場合は、このプログラムを使って同じことができる。[`CoolTerm`](https://oreil.ly/sPWQP)を使って同じことができる。

## 自分で変更を加える

さて、基本的なアプリケーションをデプロイしたので、いろいろと遊んでみたり、変更してみたりしてみよう。アプリケーションのコードは`tensorflow/lite/micro/examples/hello_world`フォルダに発見できる。編集して保存し、前の手順を繰り返して、変更したコードをデバイスにデプロイする。

いくつか試してみてほしいことがある：

* 1サイクルあたりの推論回数を調整することで、LEDの点滅を遅くしたり速くしたりする。
* `output_handler.cc`を修正して、シリアル・ポートにテキスト・ベースのアニメーションを記録する。
* 追加LEDやサウンド・ジェネレーターなど、他のコンポーネントを制御するためにサイン波を使用する。

# STマイクロエレクトロニクス STM32F746Gディスカバリー・キット

[STM32F746Gは](https://oreil.ly/cvm4J)、比較的強力なArm Cortex-M7プロセッサ・コアを搭載したマイクロコントローラ開発ボードである。

このボードは、組み込みアプリケーションのビルドとデプロイを容易にするために設計された組み込みオペレーティングシステムであるArmの[Mbed OSを](https://os.mbed.com)実行している。つまり、このセクションの命令の多くを、他のMbedデバイス用にビルドするのに使えるということだ。

STM32F746GにはLCDスクリーンが付属しており、より精巧なビジュアル・ディスプレイを作ることができる。

## STM32F746Gの出力を扱う

さて、LCD全体を使って遊べるようになったので、素敵なアニメーションを描くことができる。画面の`x軸`を推論の数、`y軸`を予測の現在値にしよう。

この値があるべき場所に点を描き、0から2πの入力範囲をループするように、その点がスクリーン上を動き回るようにする。[図6-15は](#ch06.html#stm_hello_world_animation)そのワイヤーフレームである。

それぞれの推論には一定の時間がかかるので、`constants.cc`で定義されている`kInferencesPerCycle`を微調整することで、ドットの動きの速さと滑らかさを調整することができる。

[図6-16は](#ch06.html#STM32F746_hello_world)、プログラミングが実行されている[アニメーション*.gifの*](https://oreil.ly/1EM7C)静止画である。

![](assets/timl_0615.png)

[図6-16は](#ch06.html#STM32F746_hello_world)、プログラミングが実行されている[アニメーション*.gifの*](https://oreil.ly/1EM7C)静止画である。

![](assets/timl_0616.png)

STM32F746Gの出力処理を実装したコードは[`hello_world/disco_f746ng/output_handler.cc`](https://oreil.ly/bj4iL)にあり、元のファイル`hello_world/output_handler.cc`の代わりに使用される。

それを見てみよう：

```
#include "tensorflow/lite/micro/examples/hello_world/output_handler.h"
#include "LCD_DISCO_F746NG.h"
#include "tensorflow/lite/micro/examples/hello_world/constants.h"
```

まずはヘッダファイルだ。`output_handler.h`は、このファイルのインタフェースを指定している。`LCD_DISCO_F746NG.h`はボードの製造元から提供されたもので、LCDスクリーンの制御に使用するインタフェースを宣言している。また、`kInferencesPerCycle`と`kXrange`にアクセスする必要があるため、`constants.h`もインクルードしている。

次に、大量の変数をセットアップする。`LCD_DISCO_F746NG`これは`LCD_DISCO_F746NG.h`で定義されており、LCDを制御するためのメソッドを提供している：

```
// The LCD driver
LCD_DISCO_F746NG lcd;
```

`LCD_DISCO_F746NG`クラスの詳細は[Mbedの](https://oreil.ly/yiPHS)サイトに掲載されている。

次に、ビジュアルのルック＆フィールをコントロールする定数を定義する：
