## ロギング・データ

サンプルコードをビルドしてフラッシュしたら、以下の指示に従ってデータをキャプチャする。

まず、新しいターミナル・ウィンドウを開く。そして以下のコマンドを実行し、ターミナルのすべての出力を`output.txt`という名前のファイルにロギングし始める：

```
script output.txt
```

次に、同じウィンドウで、`screen`を使ってデバイスに接続する：

```
screen ${DEVICENAME} 115200
```

加速度センサーからの測定値は画面に表示され、トレーニングスクリプトが期待するのと同じカンマ区切り文字形式で`output.txt`に保存される。

同じジェスチャーの複数のパフォーマンスを1つのファイルにキャプチャーすることを目指すべきである。ジェスチャーの単一のパフォーマンスのキャプチャを開始するには、`RST`と書かれたボタンを押す。`-,-,-`という文字がシリアルポートに書き込まれる。この出力は、ジェスチャーのパフォーマンスの開始を識別するためにトレーニングスクリプトで使用される。ジェスチャーを実行した後、`14`と書かれたボタンを押して、データのロギングを停止する。

同じジェスチャーを何度もログに記録したら、Ctrl-Aキーを押し、すぐにKキーを押し、次にYキーを押して、`screen`を終了する。`screen`を終了したら、以下のコマンドを入力し、`output.txt`へのデータ・ロギングを停止する：

```
exit
```

`output.txt`というファイルができ、そこには1人の人が1つのジェスチャーをしたときのデータがコンテナで入っている。全く新しいモデルを訓練するには、元のデータセットと同じような量のデータを集めることを目指すべきである。このデータセットには、10人による各ジェスチャーの約15回のパフォーマンスが含まれている。

自分のモデルが自分以外の人のために機能することを気にしないのであれば、おそらく自分の演技だけをキャプチャしても大丈夫だろう。とはいえ、演技のバリエーションは多ければ多いほどいい。

トレーニングスクリプトとの互換性を保つため、キャプチャしたデータファイルのファイル名を以下の形式に変更する必要がある：

```
output_<gesture_name>_<person_name>.txt
```

例えば、"ダニエル "が行ったと仮定した "三角形 "のジェスチャーのデータは、以下のような名前付けになる：

```
output_triangle_Daniel.txt
```

トレーニングスクリプトは、データが各ジェスチャー名のディレクトリに整理されていることを期待する：

```
data/
├── triangle
│   ├── output_triangle_Daniel.txt
│   └── ...
├── square
│   ├── output_square_Daniel.txt
│   └── ...
└── star
    ├── output_star_Daniel.txt
    └── ...
```

`negative`という名前のディレクトリに、「unknown」カテゴリのデータも用意する必要がある。この場合、元のデータセットのデータファイルを再利用すればよい。

モデル・アーキテクチャは4つのクラス（3つのジェスチャーと「unknown」）の確率を出力するように設計されているため、自分で3つのジェスチャーを用意する必要があることに注意する。ジェスチャーを増やしたり減らしたりしてトレーニングしたい場合は、トレーニングスクリプトを変更し、モデルアーキテクチャを調整する必要がある。

## トレーニングスクリプトを修正する

新しいジェスチャーでモデルをトレーニングするには、トレーニングスクリプトに変更を加える必要がある。

まず、以下のファイル内のジェスチャー名をすべて置き換える：

*   [`data_load.py`](https://oreil.ly/1Tplr)
*   [`data_prepare.py`](https://oreil.ly/O7eym)
*   [`data_split.py`](https://oreil.ly/w8ORq)

次に、以下のファイル内の人名をすべて置き換える：

*   [`data_prepare.py`](https://oreil.ly/3swnY)
*   [`data_split_person.py`](https://oreil.ly/xhVh7)

もし人名の数が違っていて(元のデータセットは10人)、トレーニング中に人別にデータを分割したい場合は、新しい分割を決める必要があることに注意。数人のデータしかない場合は、トレーニング中に人別に分割することはできないので、`data_split_person.py`を気にする必要はない。

## トレーニング

新しいモデルをトレーニングするには、データファイルディレクトリをトレーニングスクリプトのディレクトリにコピーし、この章の前半で説明したプロセスに従う。

数人からのデータしかない場合は、1人ごとではなくランダムにデータを分割すべきである。これを行うには、トレーニングの準備時に`data_split_person.py`の代わりに`data_split.py`を実行する。

新しいジェスチャーをトレーニングするのだから、最高の精度を得るためにモデルのハイパーパラメータで遊ぶ価値がある。例えば、エポックを多くするか少なくするか、層の配置やニューロンの数を変えるか、あるいは畳み込みハイパーパラメータを変えてトレーニングすることで、より良い結果が得られるかどうかを見ることができる。`TensorBoard`を使って進捗をモニターすることができる。

許容できる精度のモデルができたら、それがうまく機能するようにプロジェクトにいくつか変更を加える必要がある。

## 新しいモデルを使う

まず、`xxd -i`でフォーマットされた新しいモデルのデータを`magic_wand_model_data.cc`にコピーする必要がある。また、`g_magic_wand_model_data_len`の値を、`xxd`によって出力された数値と一致するように更新する。

次に、配列`should_continuous_count`、`accelerometer_handler.cc`の各ジェスチャーに必要な連続予測回数を指定する値を更新する必要がある。この値は、ジェスチャーの実行にかかる時間に対応する。オリジナルの "wing "ジェスチャーが15の連続カウントを必要とすることを考えると、新しいジェスチャーがそれに比べてどれくらい時間がかかるかを見積もり、配列の値を更新する。最も信頼できるパフォーマンスが得られるまで、これらの値を繰り返し調整することができる。

最後に、`output_handler.cc`のコードを更新して、新しいジェスチャーの正しい名前を表示する。これが終わったら、コードをビルドしてデバイスをフラッシュできる。

## マイコン向けTensorFlow Liteとは？

最初の質問は、フレームワークが実際に何をするのか、ということだろう。それを理解するためには、（かなり長い）名前を少し分解して、コンポーネントを説明することが役に立つ。

### TensorFlow

TensorFlowの名前自体は、マシン学習を研究している人なら聞いたことがあるかもしれない。[TensorFlowは](https://tensorflow.org)Googleのオープンソース機械学習ライブラリで、"An Open Source Machine Learning Framework for Everyone "をモットーとしている。Google社内で開発され、2015年に初めて一般公開された。それ以来、このソフトウェアを中心に大規模な外部コミュニティが形成され、Google内部よりもGoogle外部の貢献者の方が多くなっている。Linux、Windows、macOSのデスクトップとサーバプラットフォームを対象としており、クラウドでのモデルのトレーニングとデプロイに関する多くのツール、例、最適化を提供している。このライブラリは、Google社内で同社の製品を動かすために使われている主要なマシンラーニング・ライブラリであり、コア・コード自体は社内版も公開版も同じだ。

また、Googleやその他のソースから入手できる例やチュートリアルも数多くある。これらは、音声認識からデータセンターの電力管理やビデオ分析に至るまで、あらゆるモデルの学習方法や使用方法を教えてくれる。

TensorFlowがローンチされたときの最大のニーズは、デスクトップ環境でモデルをトレーニングして実行する機能だった。例えば、RAMの単位がギガバイトで、ストレージ領域がテラバイトのクラウドサーバでは、バイナリのサイズが数百メガバイトでも問題ない。もうひとつの例は、立ち上げ時の主要インタフェース言語が、サーバで広く使われているスクリプト言語であるPythonだったことだ。

しかし、こうしたエンジニアリングのトレードオフは、他のプラットフォームではそれほど適切ではなかった。AndroidやiPhoneのデバイスでは、アプリのサイズに数メガバイトでも追加すると、ダウンロード数や顧客満足度が劇的に低下する可能性がある。これらの電話プラットフォーム向けにTensorFlowを構築することはできるが、デフォルトではアプリケーションのサイズに20MBが追加され、多少の作業をしても2MB以下に縮小されることはない。

### TensorFlow Lite

このようなモバイルプラットフォーム向けの低サイズ要件に対応するため、Googleは2017年にTensorFlow Liteと呼ばれるTensorFlow本家のコンパニオンプロジェクトを開始した。このライブラリは、モバイルデバイス上で効率的かつ簡単にニューラルネットワークモデルを実行することを目的としている。フレームワークのサイズと複雑さを軽減するため、これらのプラットフォームではあまり一般的でない機能を削除している。例えば、トレーニングはサポートしておらず、クラウドプラットフォームで以前にトレーニングされたモデルで推論を実行するだけだ。また、メインラインのTensorFlowで利用可能なデータ型（`double`など）をフルサポートしていない。さらに、`tf.depth_to_space`のように、あまり使われていない演算子も存在しない。最新の互換性情報は[TensorFlowのWeb](https://oreil.ly/otEIp)サイトで発見できる。

これらのトレードオフと引き換えに、TensorFlow Liteはわずか数百キロバイトに収まるため、サイズに制約のあるアプリケーションへの組み込みが非常に容易になっている。また、`Arm Cortex-A`シリーズCPU用に高度に最適化されたライブラリがあり、アクセラレータ用のAndroidの`Neural Network API`や、`OpenGL`によるGPUもサポートしている。もうひとつの利点は、ネットワークの8ビット量子化をうまくサポートしていることだ。モデルは数百万のパラメータを持つ可能性があるため、32ビットfloat型から8ビット整数への75％のサイズ削減だけでも価値があるが、より小さなデータ型で推論をより高速に実行できる特殊化コードパスもある。

### マイコン向けTensorFlow Lite
