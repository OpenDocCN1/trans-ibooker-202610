
オーディオ処理の経験があれば、[MFCC（mel-frequency cepstral coefficients）の](https://oreil.ly/HTAev)ようなアプローチに馴染みがあるかもしれない。これは、我々が扱っているようなスペクトログラムを生成するための一般的なアプローチだが、実はこの例では、関連するが異なるアプローチを使用している。このメソッドは、Google全体のプロダクションで使われているものと同じであるため、多くの実用的な検証が行われているが、研究文献としては発表されていない。ここでは、どのように動作するかを大まかに説明するが、詳細については[コードそのものを](https://oreil.ly/NeOnW)参照するのが一番である。

このプロセスは、与えられたタイムスライス（ここでは30msのオーディオデータ）に対して、フーリエ変換（高速フーリエ変換またはFFTとしても知られている）を生成することから始まる。このFFTは、30msのウィンドウの両端にあるサンプルの影響を減らすベル型の関数である[Windowsで](https://oreil.ly/jhn8c)フィルタリングされたデータに対して生成される。フーリエ変換は、周波数ごとに実数成分と虚数成分を持つ複素数を生成するが、我々が気にするのは全体のエネルギーだけなので、2つの成分の2乗を合計し、平方根を適用して各周波数バケットの大きさを得る。

`N`個のサンプルがあれば、フーリエ変換は`N/2`個の周波数の情報を作り出す。毎秒16,000サンプルのレートで30msの場合、480サンプルが必要で、FFTアルゴリズムは2のべき乗入力を必要とするため、512サンプルにゼロをパッドし、256の周波数バケットを得る。これは必要以上に大きいので、縮小するために、隣接する周波数を平均して40のダウンサンプリングバケットにする。しかし、このダウンサンプリングは直線的なものではなく、人間の知覚に基づくメル周波数スケールを使って、低い周波数に重みをつけ、より多くのバケットを利用できるようにし、高い周波数はより広いバケットに統合する。[図8-26は](#ch08.html#feature_generation)そのプロセスの図である。

![](assets/timl_0826.png)

この特徴ジェネレーターの珍しい点は、ノイズ除去ステップを含んでいることだ。これは、各周波数バケットの値の実行平均を保持し、現在の値からこの平均を減算することで機能する。これは、バックグラウンドのノイズは時間と共にかなり一定になり、特定の周波数に現れるというものだ。走行平均を減算することで、ノイズの影響をある程度除去し、関心のある急速に変化する音声をそのまま残すことができる。やっかいなのは、特徴ジェネレーターが各バケツの走行平均を追跡するためのステートを保持することである。

ノイズ除去で初期化されたもう一つの部分は、奇数周波数バケットと偶数周波数バケットに異なる係数を使用したことである。その結果、最終的に生成された特徴画像（図[8-22](#ch08.html#features_yes_0)～図[8-25](#ch08.html#features_no_1)）で見られるような、特徴的な櫛歯パターンが生じる。初期化当初はバグだと思ったが、オリジナルの実装者に話を聞くと、実は性能を向上させるために意図的に追加されたものだという。このアプローチについては、Yuxuan Wangらによる["Trainable Frontend for Robust and Far-Field Keyword Spotting "](https://oreil.ly/QZ4Yb)の4.3節に詳しい。また、我々のモデルで経験的にテストしたところ、奇数バケツと偶数バケツの扱いの違いを取り除くことで、評価精度が顕著に低下した。

次に、チャンネルごとの振幅正規化（`PCAN`）オートゲインを使用して、走行平均ノイズに基づいて信号をブーストする。最後に、すべてのバケット値に対数スケールを適用し、比較的大きな周波数がスペクトルの静かな部分をかき消さないようにする。

この処理を合計49回繰り返し、30msのウィンドウを20msずつ進め、1秒間のオーディオ入力データをカバーする。これにより、幅40要素（周波数バケットごとに1つ）、高さ49行（タイムスライスごとに1行）の値の2D配列が生成される。

実装がとても複雑に聞こえるかもしれないが、心配はいらない。実装しているコードはすべてオープンソースなので、自分のオーディオプロジェクトで再利用するのは大歓迎だ。

## モデルアーキテクチャを理解する

今回使用するニューラルネットワーク・モデルは、小さな演算グラフとして定義されている。トレーニング時にこれを定義するコードは [`create_tiny_conv_model()`](https://oreil.ly/fMARv) 関数で発見でき、[図8-27は](#ch08.html#model_visualization)その結果を視覚化したものである。

このモデルは、畳み込み層、完全連結層、そして最後にソフトマックス層で構成されている。図では畳み込み層に `DepthwiseConv2D` というラベルが貼られているが、これはTensorFlow Liteコンバータの癖に過ぎない（シングルチャンネルの入力画像を持つ畳み込み層は、深度方向の畳み込みとしても表現できることがわかった）。また、`Reshape_1` というレイヤーもあるが、これは実際の演算子ではなく、単なる入力プレースホルダーである。

![](assets/timl_0827.png)

畳み込み層は、入力画像から2次元パターンを見つけるために使われる。各フィルタは値の矩形配列で、入力を横切るスライディングウィンドウとして動かされ、出力画像は各点で入力とフィルタがどれだけ密接に一致しているかを表す。畳み込み演算子は、一連の矩形フィルタを画像上で移動させ、各フィルタの各ピクセルの結果を、そのフィルタが画像のそのパッチにどれだけ似ているかに対応させていると考えることができる。この場合、各フィルタは幅8ピクセル、高さ10ピクセルで、合計8個ある。図[8-28から](#ch08.html#filter0) [図8-35に](#ch08.html#filter7)、それらの様子を示す。

![](assets/timl_0828.png)![](assets/timl_0829.png)![](assets/timl_0830.png)![](assets/timl_0831.png)![](assets/timl_0832.png)![](assets/timl_0833.png)![](assets/timl_0834.png)![](assets/timl_0835.png)

これらのフィルターはそれぞれ、入力画像の小さなパッチと考えることができる。演算子はこの小さなパッチを、入力画像の似ている部分にマッチさせようとする。画像がパッチに似ているところでは、出力画像の対応する部分に高い値が書き込まれる。直感的に言えば、各フィルタリングは、モデルが扱うべき異なるクラスを区別するために、学習入力から探すことを学習したパターンである。

8つのフィルターがあるため、8つの異なる出力画像があり、それぞれが、入力を横切るそれぞれのフィルターのマッチ値に対応する。これらのフィルター出力は、実際には8つのチャンネルを持つ1つの出力画像に合成される。つまり、各フィルタを1ピクセルずつスライドさせるのではなく、毎回2ピクセルずつスライドさせるのだ。1つおきの位置をスキップしているので、出力画像は入力画像の半分のサイズになる。

視覚化すると、入力画像は縦49ピクセル、横40ピクセルで、シングルチャンネルであることがわかる。入力画像に対して畳み込みフィルターをスライドさせるとき、水平方向と垂直方向の1ピクセルおきにスキップしているため、畳み込みの出力は半分のサイズ、つまり縦25ピクセル、横20ピクセルになる。しかしフィルターが8つあるので、画像は8チャンネルの深さになる。

次の演算子は完全連結層である。これは異なる種類のパターンマッチング処理である。入力に対して小さなウィンドウをスライドさせる代わりに、入力テンソルのすべての値に対して重みがある。結果は、すべての値を比較した後、入力が重みにどれだけ近いかを示す。これはグローバルなパターンマッチと考えることができ、入力として得られると期待される理想的な結果があり、出力はその理想的な（重みに保持された）値が実際の入力にどれだけ近いかを示す。このモデルでは各クラスに重みがあるので、「沈黙」、「不明」、「はい」、「いいえ」の理想パターンがあり、4つの出力値が生成される。入力 `25 * 20 * 8` には4,000個の値があるので、各クラスは4,000個の重みで表される。

最後の層はソフトマックスである。これは効果的に、最も高い出力と最も近い競合との差を大きくするのに役立ち、相対的な順位は変わらないが（完全接続層から最も大きな値を出したクラスが最も高いままである）、より有用なスコアを生成するのに役立つ。このスコアは非公式に確率と呼ばれることが多いが、厳密に言えば、入力データの組み合わせが実際にはどうなのか、もっとキャリブレーションを行わなければ、そのように確実に使うことはできない。例えば、検出器にもっと多くの単語があれば、「antidisestablishmentarianism」のような一般的でない単語は、「ok」のような単語よりも表示されにくくなる可能性が高いが、学習データの分布によっては、それは生のスコアには反映されないかもしれない。

これらの主要な層だけでなく、完全接続層と畳み込み層の結果に、出力を微調整するためのバイアスが追加され、それぞれの後に整流線形ユニット（`ReLU`）活性化関数がある。`ReLU`は、出力がゼロより小さくならないようにし、負の結果をゼロの最小値に設定する。このタイプの活性化関数は、ディープラーニングをより効果的にするブレークスルーのひとつである。

## モデル出力を理解する

モデルの最終結果はソフトマックス層の出力である。これは4つの数値で、"沈黙"、"不明"、"はい"、"いいえ "のそれぞれに1つずつある。これらの値は各カテゴリーのスコアであり、スコアが最も高いものがモデルの予測値であり、スコアはモデルが予測に持つ信頼度を表す。例として、モデル出力が `[10, 4, 231, 80]` の場合、スコアは231で、3番目のカテゴリーである「はい」が最も可能性の高い結果であると予測している。(我々はこれらの値を0から255の間の量子化された形で与えているが、これらは相対的なスコアであるため、通常は実数値に等価なものに変換する必要はない)。

ひとつ厄介なのは、この結果が最後の1秒の音声全体を分析したものであることだ。1秒間に1回しか実行しないとすると、前の秒と現在の秒の半分ずつの発話になってしまう可能性がある。どのようなモデルでも、単語の一部しか聞いていないときに単語をうまく認識することはできないので、そのような場合、単語検出は失敗する。これを克服するためには、1秒間に1回以上の頻度でモデルを実行し、1秒間のウィンドウで単語全体をキャッチできる可能性をできるだけ高くする必要がある。実際には、良い結果を得るためには、1秒間に10回から15回実行する必要があることが発見された。

これだけの数の結果がこれほど速く送られてくるのであれば、いつスコアが十分に高いかをどのように判断すればいいのだろうか？私たちは後処理クラスを実装し、時間の経過とともにスコアを平均化し、同じ単語で短時間に複数の高スコアが出たときだけ認識をトリガーするようにしている。この実装は [`RecognizeCommands`](https://oreil.ly/FuYfL) class。これにはモデルからの生の結果が入力され、蓄積と平均化アルゴリズムを使って、カテゴリーのどれかがしきい値を超えたかどうかを判断する。これらの後処理された結果は、 [`CommandResponder`](https://oreil.ly/b8ArK)に送られ、プラットフォームの出力能力に応じてアクションを起こす。

モデル・パラメータはすべてトレーニング・データから学習されるが、コマンド・レコグナイザーが使用するアルゴリズムは手作業で作成されているため、認識をトリガーするために必要なスコア値や、ポジティブな結果を得るために必要な時間ウィンドウの[ような閾値は](https://oreil.ly/tfNfr)すべて手作業で選ばれている。つまり、最適であるという保証はないということだ。もし自分のアプリケーションで結果が悪い場合は、自分で微調整してみるといいだろう。

より洗練された音声認識モデルは通常、この章で紹介する単層畳み込みネットワークではなく、（再帰的ニューラルネットワークのような）ストリーミングデータを取り込むことができるモデルを使う。ストリーミングがモデル設計に組み込まれているということは、正確な結果を得るために後処理をする必要がないということだ。

# 自分のデータでトレーニングする

作りたい製品が「はい」と「いいえ」だけに反応すればいいということはあまりないだろうから、気になる音声に敏感に反応するモデルをトレーニングしたいはずだ。先ほど使用したトレーニングスクリプトは、独自のデータを使ってカスタムモデルを作成できるように設計されている。このプロセスで最も大変なのは、十分な大規模データセットを集めることと、それがあなたの問題に適切であることを確認することだ。データの収集とクリーニングの一般的なアプローチについては[第16](#ch16.html#chapter_optimizing_energy_usage)章で説明するが、この章では独自のオーディオモデルをトレーニングする方法をいくつか取り上げる。

## 音声コマンドデータセット

`train.py`スクリプトはデフォルトでSpeech Commandsデータセットをダウンロードする。これは100,000以上の1秒間のWAVファイルからなるオープンソースのコレクションで、様々な話者の様々な短い単語をカバーしている。Googleによって配布されているが、発話は世界中のボランティアから収集されている。Aakanksha Chowdheryらによる["Visual Wake Words Dataset "](https://oreil.ly/EC6nd)に詳細がある。

このデータセットには、「はい」と「いいえ」のほかに、8つの命令語（on、off、up、down、left、right、stop、go）と、0から9までの10桁の数字が含まれている。これらの単語にはそれぞれ数千の例がある。マービンのように、もっと少ない例しかない単語もある。命令語は、それらを認識するための妥当なモデルを訓練できるほど十分な発話があることを意図している。その他の単語は、未知のカテゴリーを構成するために使われることを意図しており、そのためモデルは、訓練されていない単語が発語されたときに、それをコマンドと間違えるのではなく、見分けることができる。

トレーニングスクリプトはこのデータセットを使用するため、例文の多いコマンド単語の組み合わせで簡単にモデルをトレーニングすることができる。引数 `--wanted_words` を、トレーニングセットに含まれる単語をカンマで区切ったリストで更新し、ゼロからトレーニングを実行すれば、有用なモデルを作成できることが発見できるはずだ。気をつけるべき主な点は、10個の命令語および／または数字に限定すること、そうしないと正確な学習を行うのに十分なサンプルが得られないこと、そして、2つ以上の単語が必要な場合は、`--silence_percentage` と `--unknown_percentage` の値を小さく調整することである。最後の2つの引数は、学習中に無音サンプルと未知サンプルをどれだけ混ぜるかをコントロールする。無音サンプルは実際には完全な無音ではなく、データセットの `background` フォルダにあるWAVからランダムに選ばれた、録音された背景ノイズの1秒間のスニペットである。未知のサンプルは、トレーニングセットに含まれるが、`wanted_words` リストにはない単語から選ばれた発話である。データセットに比較的発話数の少ない雑多な単語が含まれているのはこのためだ。これは音声認識で特に問題となる。というのも、本番演算子はしばしば、トレーニングでは遭遇したことのないような単語や雑音がたくさんある環境で動作する必要があるからだ。一般的な英語だけでも何千もの異なる単語があり、有用であるためには、モデルはトレーニングされていない単語を無視できなければならない。そのため、未知のカテゴリーが実際には非常に重要なのだ。

以下は、既存のデータセットを使って、さまざまな単語を学習した例である：

```
python tensorflow/examples/speech_commands/train.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --wanted_words="up,down,left,right" --silence_percentage=15 \
  --unknown_percentage=15 --quantize=1
```

## 自分のデータセットでトレーニングする
