## 自分で変更を加える

アプリケーションをデプロイしたところで、コードを変更して遊んでみるのも面白いかもしれない。Arduino IDEでソースファイルを編集できる。保存すると、新しい場所にサンプルを再保存するようプロンプトが表示される。変更が終わったら、Arduino IDEのアップロードボタンをクリックして、ビルドとデプロイを行うことができる。

変化を起こすために、ここでいくつかの実験を試してみよう：

* 1サイクルあたりの推論回数を調整することで、LEDの点滅を遅くしたり速くしたりする。
* `output_handler.cc`を修正して、シリアル・ポートにテキスト・ベースのアニメーションを記録する。
* 追加LEDやサウンド・ジェネレーターなど、他のコンポーネントを制御するためにサイン波を使用する。

# スパークファン・エッジ

[`SparkFun Edge`](https://oreil.ly/-hoL-)開発ボードは、小型デバイスで機械学習を体験するためのプラットフォームとして特別に設計された。Arm Cortex M4プロセッサーコアを搭載した電力効率の高いAmbiq Apollo 3マイクロコントローラーを搭載している。

[図6-11に](#ch06.html#sparkfun_edge_leds)示すように、4つのLEDバンクを備えている。これらを使って、サイン値を視覚的に出力する。

![](assets/timl_0611.png)

## SparkFun Edgeで出力を処理する

ボードのLEDバンクを使って簡単なアニメーションを作ることができる。

LED（赤、緑、青、黄）は物理的に以下の順番で並んでいる：

```
                         [ R G B Y ]
```

以下の表は、`y`の値が異なる場合のLEDの点灯方法を示している：

| 範囲 || LEDが点灯する |
| --- | --- |
| `0.75 <= y <= 1` || `[ 0 0 1 1 ]` |
| --- | --- |
| `0 < y < 0.75` || `[ 0 0 1 0 ]` |
| `y = 0` || `[ 0 0 0 0 ]` |
| `-0.75 < y < 0` || `[ 0 1 0 0 ]` |
| `-1 <= y <= 0.75` || `[ 1 1 0 0 ]` |

各推論には一定の時間がかかるので、`constants.cc`で定義されている`kInferencesPerCycle`を微調整することで、LEDのサイクル速度を調整することができる。

[図6-12は](#ch06.html#sparkfun_edge_gif_still)、プログラミングが実行されている[`アニメーション.gif`](https://oreil.ly/cXdPY)の静止画である。

![](assets/timl_0612.png)

SparkFun Edgeの出力処理を実装するコードは[`hello_world/sparkfun_edge/output_handler.cc`](https://oreil.ly/tegLK)にあり、元のファイル`hello_world/output_handler.cc`の代わりに使用される。

さっそく歩いてみよう：

```
#include "tensorflow/lite/micro/examples/hello_world/output_handler.h"
#include "am_bsp.h"
```

まず、いくつかのヘッダファイルをインクルードする。`output_handler.h`は、このファイルのインタフェースを指定する。もう1つのファイル`am_bsp.h`は、`Ambiq Apollo3 SDK`と呼ばれるものに由来する。AmbiqはSparkFun EdgeのApollo3というマイクロコントローラーのメーカーである。SDK（`ソフトウェア開発キット`の略）は、マイクロコントローラーの機能管理に使用できる定数や関数を定義したソースファイルの集まりである。

ボードのLEDを制御する予定なので、マイコンのピンをオン・オフできるようにする必要がある。そのためにSDKを使う。

### 注

Makefileは、最終的にプロジェクトをビルドする際に自動的にSDKをダウンロードする。興味のある方は、[SparkFunのWeb](https://oreil.ly/RHHqI)サイトで詳細を読んだり、コードをダウンロードして調べることができる。

次に、`HandleOutput()`関数を定義し、その最初の実行時に何をするかを示す：

```
void HandleOutput(tflite::ErrorReporter* error_reporter, float x_value,
                  float y_value) {
  // The first time this method runs, set up our LEDs correctly
  static bool is_initialized = false;
  if (!is_initialized) {
    // Set up LEDs as outputs
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_RED, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_BLUE, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_GREEN, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_YELLOW, g_AM_HAL_GPIO_OUTPUT_12);
    // Ensure all pins are cleared
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_RED);
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_BLUE);
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_GREEN);
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
    is_initialized = true;
  }
```

ふぅ、セットアップが大変だ！我々は、`am_bsp.h`が提供する`am_hal_gpio_pinconfig()`関数を使用して、ボードの組み込みLEDに接続されたピンを設定し、出力モード（定数`g_AM_HAL_GPIO_OUTPUT_12`で表される）にしている。各LEDのピン番号は、`AM_BSP_GPIO_LED_RED`のような定数で表される。

次に、`am_hal_gpio_output_clear()`を使ってすべての出力をクリアし、LEDをすべて消灯する。Arduino実装と同じように、`static` `is_initialized`という名前の変数を使い、このブロックのコードが一度だけ実行されるようにしている。次に、`y`の値が負の場合、どのLEDを点灯させるかを決定する：

```
// Set the LEDs to represent negative values
if (y_value < 0) {
  // Clear unnecessary LEDs
  am_hal_gpio_output_clear(AM_BSP_GPIO_LED_GREEN);
  am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
  // The blue LED is lit for all negative values
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_BLUE);
  // The red LED is lit in only some cases
  if (y_value <= -0.75) {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
  } else {
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_RED);
  }
```

まず、`y`の値が負になったばかりの場合に備えて、正の値を示すために使用される2つのLEDをクリアする。次に、`am_hal_gpio_output_set()`を呼び出して青色LEDを点灯させる。青色LEDは、値が負の場合に常に点灯する。最後に、もし値が-0.75より小さければ、赤色LEDを点灯させる。そうでない場合は消灯する。

次に、同じことを`y`の正の値について行う：

```
  // Set the LEDs to represent positive values
} else if (y_value > 0) {
  // Clear unnecessary LEDs
  am_hal_gpio_output_clear(AM_BSP_GPIO_LED_RED);
  am_hal_gpio_output_clear(AM_BSP_GPIO_LED_BLUE);
  // The green LED is lit for all positive values
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_GREEN);
  // The yellow LED is lit in only some cases
  if (y_value >= 0.75) {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
  } else {
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
  }
}
```

LEDはこれで終わりだ。最後にすることは、現在の出力値をシリアル・ポートで聞いている人に記録することだ：

```
// Log the current X and Y values
error_reporter->Report("x_value: %f, y_value: %f\n", x_value, y_value);
```

### 注

我々の`ErrorReporter`は、[`micro/debug_log.cc`](https://oreil.ly/ACaFt)のオリジナル実装を置き換える[`micro/sparkfun_edge/debug_log.cc`](https://oreil.ly/ufEv9)のカスタム実装により、SparkFun Edgeのシリアル・インタフェース経由でデータを出力することができる。

## 例題を実行する

これでサンプルコードをビルドし、SparkFun Edgeにデプロイすることができる。

### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は[`README.md`](https://oreil.ly/EcPZ8)をチェックしてほしい。

コードをビルドしてデプロイするには、以下のものが必要だ：

* スパークファン・エッジ・ボード
* USBプログラマ（SparkFunシリアルベーシックブレークアウトをお勧めする。）
* 適合するUSBケーブル
* Python 3といくつかの依存関係

まず、ターミナルを開き、TensorFlowリポジトリをクローンし、そのディレクトリに移動する：

```
git clone https://github.com/tensorflow/tensorflow.git
cd tensorflow
```

次に、バイナリをビルドし、デバイスにダウンロードするためのいくつかのコマンドを実行する。タイピングの手間を省くため、これらのコマンドは[`README.md`](https://oreil.ly/PYmUu)からコピー＆ペーストできる。

### バイナリをビルドする

以下のコマンドは、必要な依存関係をすべてダウンロードし、SparkFun Edge用のバイナリをコンパイルする：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  TARGET=sparkfun_edge hello_world_bin
```

### 注

バイナリは、SparkFun Edgeハードウェアで直接実行できる形式でプログラミングを含むファイルである。

バイナリーは`.bin`ファイルとして以下の場所に作成される：

```
tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/hello_world.bin
```

ファイルが存在するかどうかを確認するには、以下のコマンドを使うことができる：
