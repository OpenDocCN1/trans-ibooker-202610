
`command_responder.h`インクルードは、このファイルに対応するヘッダである。`am_bsp.h`は、前章で見たAmbiq Apollo3 SDKである。

関数定義内部で、最初に行うことは、LEDに接続されているピンを出力としてセットアップすることだ：

```
// This implementation will light up the LEDs on the board in response to
// different commands.
void RespondToCommand(tflite::ErrorReporter* error_reporter,
                      int32_t current_time, const char* found_command,
                      uint8_t score, bool is_new_command) {
  static bool is_initialized = false;
  if (!is_initialized) {
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_RED, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_BLUE, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_GREEN, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_YELLOW, g_AM_HAL_GPIO_OUTPUT_12);
    is_initialized = true;
  }
```

アポロ3 SDKの`am_hal_gpio_pinconfig()`関数を呼び出し、定数`g_AM_HAL_GPIO_OUTPUT_12`で表される4つのLEDピンすべてを出力モードに設定する。`is_initialized` `static`変数を使用し、これを一度だけ実行するようにする！

次に、青色LEDのオン・オフを切り替えるコードだ。Arduinoの実装と同じように、`count`変数を使ってこれを行う：

```
static int count = 0;
// Toggle the blue LED every time an inference is performed.
++count;
if (count & 1) {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_BLUE);
} else {
  am_hal_gpio_output_clear(AM_BSP_GPIO_LED_BLUE);
}
```

このコードは、`am_hal_gpio_output_set()`、`am_hal_gpio_output_clear()`関数を使い、青色LEDのピンのオン／オフを切り替える。

推論ごとに`count`変数をインクリメントすることで、実行した推論の合計数を記録する。`if`条件付き内部では、`&`演算子を使って、`count`変数と数値`1`との二項AND演算を行う。

`count`、`1`とのANDを実行することで、最小ビットを除く`count`のすべてのビットをフィルタリングする。最小ビットが`0`、つまり`count`が奇数の場合、結果は`0`となる。C++の`if statement`、これは`false`と評価される。

そうでない場合、結果は`1`となり、偶数を示す。`1`は`true`と評価されるので、LEDは偶数で点灯し、奇数で消灯する。これがトグルする理由である。

次に、最近聞いた単語に応じて適切なLEDを点灯させる。デフォルトでは、すべてのLEDを消灯させるので、ある単語が最近聞かれなかった場合、LEDはすべて消灯する：

```
am_hal_gpio_output_clear(AM_BSP_GPIO_LED_RED);
am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
am_hal_gpio_output_clear(AM_BSP_GPIO_LED_GREEN);
```

次に、単純な`if`、どのコマンドを聞いたかによって適切なLEDを点灯させる：

```
if (is_new_command) {
  error_reporter->Report("Heard %s (%d) @%dms", found_command, score,
                         current_time);
  if (found_command[0] == 'y') {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
  }
  if (found_command[0] == 'n') {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
  }
  if (found_command[0] == 'u') {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_GREEN);
  }
}
```

先に見たように、`is_new_command`は、`RespondToCommand()`が純粋に新しいコマンドで呼び出された場合のみ`true`。したがって、新しいコマンドが聞かれなかった場合、LEDは消灯したままになる。そうでない場合は、`am_hal_gpio_output_set()`関数を使って適切なLEDを点灯させる。

## 例を実行する

ここまでで、サンプルコードがSparkFun EdgeのLEDを点灯させる方法を説明した。次に、このサンプルを立ち上げて動かしてみよう。

### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は[`README.md`を](https://oreil.ly/U3Cgo)チェックしてほしい。

コードをビルドしてデプロイするには、以下のものが必要だ：

* スパークファン・エッジ・ボード
* USBプログラマ（SparkFunシリアルベーシックブレークアウトをお勧めする。）
* 適合するUSBケーブル
* Python 3といくつかの依存関係

### 注

[第6章](#ch06.html#ch_6)では、正しいバージョンのPythonがインストールされているかどうかを確認する方法を紹介する。もし既にやっているなら、素晴らしいことだ。そうでない場合は、[「例の実行](#ch06.html#running_hello_world_sparkfun_edge)」に戻って確認する価値がある。

ターミナルでTensorFlowリポジトリをクローンし、そのディレクトリに移動する：

```
git clone https://github.com/tensorflow/tensorflow.git
cd tensorflow
```

次に、バイナリをビルドし、デバイスにダウンロードするためのいくつかのコマンドを実行する。タイピングの手間を省くため、これらのコマンドは[`README.md`から](https://oreil.ly/xY-Rj)コピー＆ペーストできる。

### バイナリをビルドする

次のコマンドは、必要な依存関係をすべてダウンロードし、SparkFun Edge用のバイナリをコンパイルする：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  TARGET=sparkfun_edge TAGS=cmsis-nn micro_speech_bin
```

バイナリーは`.bin`ファイルとして以下の場所に作成される：

```
tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/micro_speech.bin
```

ファイルが存在するかどうかをチェックするには、以下のコマンドを使うことができる：

```
test -f tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/micro_speech.bin \
  &&  echo "Binary was successfully created" || echo "Binary is missing"
```

このコマンドを実行すると、コンソールに`Binary was successfully created`と表示されるはずだ。`Binary is missing`が表示されたら、ビルド・プロセスに問題があったことになる。もしそうなら、`make`コマンドの出力の中に、何が問題だったかを知る手がかりがある可能性が高い。

### バイナリに署名する

バイナリをデバイスにデプロイするには、暗号鍵で署名する必要がある。それでは、バイナリをSparkFun Edgeにフラッシュできるように署名するコマンドをいくつか実行してみよう。ここで使用するスクリプトは、Makefileの実行時にダウンロードされるAmbiq SDKのものである。

以下のコマンドを入力し、開発に使えるダミーの暗号鍵をセットアップする：

```
cp tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info0.py \
  tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info.py
```

次に、以下のコマンドを実行して署名付きバイナリを作成する。必要に応じて、`python3`を`python`で置き換える：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_image_blob.py \
  --bin tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/micro_speech.bin \
  --load-address 0xC000 \
  --magic-num 0xCB -o main_nonsecure_ota \
  --version 0x0
```

これで`main_nonsecure_ota.bin`ファイルが作成される。次のステップで使用するスクリプトでデバイスをフラッシュするために使用できるファイルの最終バージョンを作成するために、このコマンドを実行する：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_wireupdate_blob.py \
  --load-address 0x20000 \
  --bin main_nonsecure_ota.bin \
  -i 6 -o main_nonsecure_wire \
  --options 0x1
```

これで、コマンドを実行したディレクトリに`main_nonsecure_wire.bin`というファイルができるはずだ。これがデバイスにフラッシュするファイルだ。

### バイナリをフラッシュする

SparkFun Edgeは、現在実行中のプログラミングを1メガバイトのフラッシュメモリーに保存する。ボードに新しいプログラムを実行させたい場合は、そのプログラムをボードに送信する必要があり、ボードはそれをフラッシュ・メモリーに保存し、以前に保存されたプログラムを上書きする。

#### プログラマを基板に取り付ける

ボードに新しいプログラムをダウンロードするには、SparkFun USB-C Serial Basicシリアル・プログラマを使用する。このデバイスにより、コンピューターはUSB経由でマイクロコントローラーと通信できる。

このデバイスをボードに取り付けるには、以下の手順を実行する：

1. SparkFun Edgeの側面に6ピンのヘッダがある。
2. SparkFun USB-C Serial Basicをこれらの行に差し込み、各デバイスのBLKとGRNと書かれたピンが[図7-14の](#ch07.html#sparkfun_edge_serial_basic_2)ように正しく並んでいることを確認する。

![](assets/timl_0613.png)

#### プログラマをコンピュータに取り付ける

ボードをUSB経由でコンピューターに接続する。ボードをプログラミングするには、コンピューターがデバイスに付けている名前を発見する必要がある。これを行う最良の方法は、ボードを接続する前と後のコンピュータのすべてのデバイスをリストアップし、どのデバイスが新しいかを確認することである。

#### 警告

プログラマ用のオペレーティング・システムのデフォルト・ドライバに関する問題が報告されている人もいるので、先に進む前に[ドライバを](https://oreil.ly/kohTX)インストールすることを強く勧める。

USBでデバイスを接続する前に、以下のコマンドを実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

以下のようなリストが出力されるはずだ：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
```

プログラマをコンピューターのUSBポートに接続し、コマンドをもう一度実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

次の例に示すように、出力に項目が追加されているはずである。新しい項目は違う名前かもしれない。この新しい項目はデバイスの名前である：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
/dev/cu.wchusbserial-1450
```

この名前は、デバイスを参照するために使用される。ただし、プログラマがどのUSBポートに接続されているかによって、この名前が変わることがあるので、コンピュータからボードを取り外して再度接続した場合は、名前を調べ直す必要があるかもしれない。

#### チップ

ユーザによっては、リストに2つのデバイスが表示されるという報告がある。2つのデバイスが表示された場合、正しい方は "wch "で始まる。

デバイス名を確認したら、後で使えるようにシェル変数に入れておく：

```
export DEVICENAME=<your device name here>
```

これは、後でデバイス名を必要とするコマンドを実行するときに使用する変数である。

#### スクリプトを実行してボードをフラッシュする

ボードをフラッシュするには、新しいバイナリを受け取る準備をする特殊化「ブートローダー」状態にする必要がある。その後、ボードにバイナリを送信するスクリプトを実行する。

まず、ボーレートを指定する環境変数を作成する。ボーレートとは、データをデバイスに送信する速度である：

```
export BAUD_RATE=921600
```

次のコマンドをターミナルに貼り付ける！コマンドの`${DEVICENAME}`と`${BAUD_RATE}`は、前のセクションでセットした値に置き換えられる。必要であれば、`python3`を`python`で置き換えることを忘れないこと：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/uart_wired_update.py \
  -b ${BAUD_RATE} ${DEVICENAME} \
  -r 1 -f main_nonsecure_wire.bin \
  -i 6
```

次に、ボードをブートローダーの状態にリセットし、ボードをフラッシュする。ボード上で、[図7-15に](#ch07.html#sparkfun_edge_buttons_2)示すように、`RST`と`14`とマークされたボタンを見つける。以下の手順を実行する：

1. ボードがプログラマに接続され、全体がUSB経由でコンピューターに接続されていることを確認する。
2. ボード上で、`14`と書かれたボタンを押し続ける。そのまま押し続ける。
3. `14`と書かれたボタンを押したまま、`RST`と書かれたボタンを押してボードをリセットする。
4. コンピュータでEnterキーを押してスクリプトを実行する。`14`ボタンを押し続ける。

これで画面に次のようなものが表示されるはずだ：
