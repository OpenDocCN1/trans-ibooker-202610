# マイクロコントローラへのデプロイ

このセクションでは、私たちのコードを2つの身近なデバイスにデプロイする：

* [Arduino Nano 33 BLEセンス](https://oreil.ly/6qlMD)
* [スパークファン・エッジ](https://oreil.ly/-hoL-)

今回は大きな違いがひとつある。どちらのデバイスにもカメラが内蔵されていないため、使用するデバイスに合わせてカメラ・モジュールを購入することをお勧めする。各デバイスには`image_provider.cc`の実装があり、カメラモジュールとインタフェースして画像をキャプチャする。また、デバイス固有の出力コードも`detection_responder.cc`にある。

これは素晴らしくシンプルなので、独自の構想ベースのMLアプリケーションを作成する際に、優れたテンプレートとなるだろう。

まずはArduinoの実装を調べてみよう。

## Arduino

ArduinoボードであるArduino Nano 33 BLE Senseは、互換性のあるサードパーティ製ハードウェアやライブラリの膨大なエコシステムにアクセスできる。私たちは、Arduinoで動作するように設計されたサードパーティのカメラモジュールと、カメラモジュールとインタフェースし、カメラモジュールが出力するデータを理解するためのArduinoライブラリを使用している。

### どのカメラモジュールを購入するか

この例では、[Arducam Mini 2MP Plus](https://oreil.ly/LAwhb)カメラモジュールを使用している。Arduino Nano 33 BLE Senseに簡単に接続でき、Arduinoボードの電源から給電できる。大きなレンズを持ち、高品質の2メガピクセルの画像を撮影することができるが、より小さな解像度を得るためにオンボードの画像再スケーリング機能を使用する。特に電力効率に優れているわけではないが、高画質なので、野生動物を記録するような画像キャプチャ・アプリケーションを構築するのに理想的だ。

### Arduinoで画像をキャプチャする

Arducamモジュールをいくつかのピンを介してArduinoボードに接続する。画像データを取得するには、ArduinoボードからArducamに画像をキャプチャするよう指示するコマンドを送る。Arducamはそれを実行し、内部データ・バッファに画像を保存する。次に、Arducamの内部バッファから画像データを読み取り、Arduinoのメモリに保存するコマンドを送信する。これらすべてを行うために、Arducamの公式ライブラリを使う。

Arducamのカメラモジュールは2メガピクセルのイメージセンサーを持ち、解像度は1920×1080だ。私たちの人物検出モデルの入力サイズは96×96しかないので、すべてのデータは必要ない。実際、Arduino自体には2メガピクセルの画像を保持するのに十分なメモリーはなく、数メガバイトのサイズになる。

幸いなことに、Arducamのハードウェアには、出力を160×120ピクセルというかなり小さな解像度にリサイズする機能がある。私たちのコードでは、中央の96×96ピクセルのみを残すことで、これを簡単に96×96ピクセルに切り詰めることができる。しかし、問題を複雑にしているのは、Arducamのリサイズされた出力は、画像の一般的な圧縮形式である[JPEGを使って](https://oreil.ly/gwWDh)エンコーディングされていることだ。つまり、Arducamの出力を使う前にデコードする必要がある。これはオープンソースのライブラリを使ってできる。

最後のタスクは、Arducamのカラー画像出力をグレースケールに変換することだ。グレースケールのデータをモデルの入力テンソルに書き込む。

画像プロバイダーは[`arduino/image_provider.cc`に](https://oreil.ly/kGx0-)実装されている。このコードはArducamカメラ・モジュールに特有なので、詳細は説明しない。その代わりに、高レベルで何が起こっているのかを順を追って説明しよう。

`GetImage()`関数は、画像プロバイダーと世界とのインタフェースである。アプリケーションのメインループで呼び出され、画像データのフレームを取得する。最初に呼び出されるときは、カメラを初期化する必要がある。これは`InitCamera()`関数の呼び出しで行われる：

```
  static bool g_is_camera_initialized = false;
  if (!g_is_camera_initialized) {
    TfLiteStatus init_status = InitCamera(error_reporter);
    if (init_status != kTfLiteOk) {
      error_reporter->Report("InitCamera failed");
      return init_status;
    }
    g_is_camera_initialized = true;
  }
```

`InitCamera()`関数は`image_provider.cc`で定義されている。この関数はデバイス固有のものなので、ここでは説明しない。Arduinoと通信するためにArduinoのハードウェアを設定し、通信がうまくいっていることを確認する。最後に、160×120ピクセルのJPEG画像を出力するようにArducamに指示する。

`GetImage()`が次に呼び出す関数は`PerformCapture()`である：

```
TfLiteStatus capture_status = PerformCapture(error_reporter);
```

こちらも詳細は省く。カメラモジュールにコマンドを送り、画像をキャプチャして内部バッファに画像データをストアするよう指示するだけだ。そして、画像がキャプチャされたことの確認を待つ。この時点で、Arduinoの内部バッファには画像データが待機しているが、Arduino自体にはまだ画像データはない。

次に呼び出す関数は`ReadData()`である：

```
  TfLiteStatus read_data_status = ReadData(error_reporter);
```

`ReadData()`関数はArducamから画像データをフェッチするためにより多くのコマンドを使用する。関数が実行されると、グローバル変数`jpeg_buffer`にカメラから取得したJPEGエンコードされた画像データが格納される。

JPEGエンコーディングされた画像を手に入れたら、次のステップはそれを生の画像データにデコードすることだ。これは`DecodeAndProcessImage()`関数で行われる：

```
  TfLiteStatus decode_status = DecodeAndProcessImage(
      error_reporter, image_width, image_height, image_data);
```

この関数は`JPEGDecoder`というライブラリを使ってJPEGデータをデコードし、モデルの入力テンソルに直接書き込む。その過程で、画像を切り抜き、160×120ピクセルのデータの一部を捨てて、画像のほぼ中央にある96×96ピクセルだけが残るようにする。また、画像の16ビットのカラー表現を8ビットのグレースケールに縮小する。

画像が取り込まれ、入力テンソルに格納されたら、推論を実行する準備が整った。次に、モデルの出力がどのように表示されるかを示す。

### Arduinoで検出に応答する

Arduino Nano 33 BLE SenseにはRGB LEDが内蔵されている。これは、赤、緑、青のLEDを個別に制御できる単一コンポーネントである。検知レスポンダの実装は、推論が実行されるたびに青色LEDを点滅させる。人が検出されると緑色のLEDが点灯し、人が検出されないと赤色のLEDが点灯する。

実装は[`arduino/detection_responder.cc`に](https://oreil.ly/-WsSN)ある。ざっと見てみよう。

`RespondToDetection()`関数は、"人 "と "人ではない "の2つのスコアを受け付ける。最初に呼び出されたとき、青、緑、黄色のLEDをセットアップして出力する：

```
void RespondToDetection(tflite::ErrorReporter* error_reporter,
                        uint8_t person_score, uint8_t no_person_score) {
  static bool is_initialized = false;
  if (!is_initialized) {
    pinMode(led_green, OUTPUT);
    pinMode(led_blue, OUTPUT);
    is_initialized = true;
  }
```

次に、推論が完了したことを示すために、すべてのLEDのスイッチを切り、青色LEDを短時間点滅させる：

```
  // Note: The RGB LEDs on the Arduino Nano 33 BLE
  // Sense are on when the pin is LOW, off when HIGH.

  // Switch the person/not person LEDs off
  digitalWrite(led_green, HIGH);
  digitalWrite(led_red, HIGH);

  // Flash the blue LED after every inference.
  digitalWrite(led_blue, LOW);
  delay(100);
  digitalWrite(led_blue, HIGH);
```

Arduinoの内蔵LEDとは異なり、これらのLEDは`LOW`で点灯し、`HIGH`で消灯する。これは、LEDがどのようにボードに接続されているかの要因に過ぎない。

次に、どちらのカテゴリースコアが高いかによって、適切なLEDを点灯させたり消灯させたりする：

```
  // Switch on the green LED when a person is detected,
  // the red when no person is detected
  if (person_score > no_person_score) {
    digitalWrite(led_green, LOW);
    digitalWrite(led_red, HIGH);
  } else {
    digitalWrite(led_green, HIGH);
    digitalWrite(led_red, LOW);
  }
```

最後に、`error_reporter`インスタンスを使ってシリアルポートに得点を出力する：

```
  error_reporter->Report("Person score: %d No person score: %d", person_score,
                         no_person_score);
}
```

それで終わりだ！この関数のコアは基本的な`if`。同じようなロジックを使って、他のタイプの出力をコントロールすることも簡単にできる。このような複雑な視覚的入力がひとつのブール出力に変換されるのは、とてもエキサイティングなことだ："人 "か "人なし "だ。

### 例を実行する

ArducamをArduinoボードに接続する必要があるからだ。また、Arducamとインタフェースをとり、JPEG出力をデコードするライブラリをインストールして設定する必要がある。でも心配はいらない！

この例をデプロイするために必要なものは以下の通りだ：

* Arduino Nano 33 BLE Senseボード
* アルドゥカム ミニ2MPプラス
* ジャンパーケーブル（オプションでブレッドボードも使える）
* マイクロUSBケーブル
* Arduino IDE

最初の作業は、ジャンパーケーブルを使ってArduinoとArducamを接続することだ。これは電子工学の本ではないので、ケーブルの使い方の詳細には触れない。代わりに、[表9-](#ch09.html#arducam_pins)1にピンの接続方法を示す。ピンは各デバイスにラベルが貼ってある。

表 9-1. Arduino Nano 33 BLE SenseへのArduam Mini 2MP Plusの接続

| アルドゥカムピン || Arduinoピン |
| --- | --- |
| CS || D7（ラベルなし、D6のすぐ右側） |
| --- | --- |
| MOSI || D11 |
| MISO || D12 |
| SCK || D13 |
| GND || GND（GNDと書かれたピンはどちらでもよい） |
| VCC || 3.3 V |
| SDA || A4 |

ハードウェアのセットアップが終わったら、ソフトウェアのインストールを続けることができる。
