
しかし、よく見ると、いくつかの不完全な部分があることがわかる。予測された正弦波のピークと谷は、実際の正弦波のように完全に滑らかではない。ランダムに分布している学習データのばらつきが、モデルに学習されてしまったのだ。滑らかな正弦関数を学習する代わりに、モデルはデータの形状を正確に再現するように学習したのだ。

我々の目的では、このオーバーフィッティングは大きな問題ではない。我々の目標は、このモデルがLEDを緩やかにフェードオン／オフさせることであり、これを達成するために完璧に滑らかである必要はない。もしオーバーフィッティングのレベルが問題だと考えるなら、正則化のテクニックや、より多くのトレーニングデータを得ることで対処することができるだろう。

モデルには満足したので、デバイス上でデプロイできるようにしよう ！

# TensorFlow Lite用にモデルを変換する

この章の冒頭で、TensorFlow Liteについて簡単に触れた。TensorFlow Liteは、「エッジデバイス」（携帯電話からマイコンボードまであらゆるものを指す）でTensorFlowモデルを実行するためのツールセットである。

[第13章](#ch13.html#chapter_tensorflow_lite_for_microcontrollers)では、TensorFlow Lite for Microcontrollersについて詳しく説明する。今のところ、TensorFlow Liteには2つの主要なコンポーネントがあると考えることができる：

TensorFlow Liteコンバータ

: 

これは、TensorFlowモデルを、メモリに制約のあるデバイスで使用するために、スペース効率の高い特殊な形式に変換するもので、モデルサイズをさらに小さくし、小さなデバイスでも高速に実行できるようにする最適化を適用することができる。

TensorFlow Liteインタプリタ

: 

これは、与えられたデバイスに対して最も効率的な演算子を使用して、適切に変換されたTensorFlow Liteモデルを実行する。

TensorFlow Liteでモデルを使う前に、モデルを変換する必要がある。そのためにTensorFlow Lite ConverterのPython APIを使う。これは、`Keras`モデルを受け取り、`FlatBuffer`の形式でディスクに書き込む。`FlatBuffer`は、スペース効率が良いように設計された特殊なファイル形式だ。限られたメモリーしか持たないデバイスにデプロイするのだから、これは便利だ！FlatBufferについては[第12](#ch12.html#chapter_magic_wand_training)章で詳しく説明する。

TensorFlow Liteコンバータは、`FlatBuffer`の作成に加えて、モデルに最適化を適用することもできる。これらの最適化は、一般的にモデルのサイズ、実行時間、またはその両方を削減する。これは、精度の低下という代償を伴うこともあるが、多くの場合、その価値は十分に小さい。最適化については[第13](#ch13.html#chapter_tensorflow_lite_for_microcontrollers)章で詳しく説明する。

最も有用な最適化の1つは、`量子化`である。デフォルトでは、モデルの重みとバイアスは32ビット浮動小数点数として保存され、トレーニング中に高精度の計算ができるようになっている。量子化によって、これらの数値の精度を下げ、8ビット整数に収まるようにすることができる。さらに良いことに、CPUは浮動小数点数よりも整数で計算する方が簡単なので、量子化されたモデルはより高速に実行される。

量子化の最も素晴らしい点は、多くの場合、精度の損失が最小限に抑えられることだ。つまり、低メモリのデバイスにデプロイする場合、ほとんど常に価値があるということだ。

次のセルでは、コンバーターを使ってモデルの新しいバージョンを2つ作成し、保存する。1つ目はTensorFlow Lite FlatBuffer形式に変換されるが、最適化は行われない。2つ目は量子化されている。

セルを実行し、モデルをこれら2つのバリアントに変換する：

```
# Convert the model to the TensorFlow Lite format without quantization
converter = tf.lite.TFLiteConverter.from_keras_model(model_2)
tflite_model = converter.convert()

# Save the model to disk
open("sine_model.tflite", "wb").write(tflite_model)

# Convert the model to the TensorFlow Lite format with quantization
converter = tf.lite.TFLiteConverter.from_keras_model(model_2)
# Indicate that we want to perform the default optimizations,
# which include quantization
converter.optimizations = [tf.lite.Optimize.DEFAULT]
# Define a generator function that provides our test data's x values
# as a representative dataset, and tell the converter to use it
def representative_dataset_generator():
  for value in x_test:
    # Each scalar value must be inside of a 2D array that is wrapped in a list
    yield [np.array(value, dtype=np.float32, ndmin=2)]
converter.representative_dataset = representative_dataset_generator
# Convert the model
tflite_model = converter.convert()

# Save the model to disk
open("sine_model_quantized.tflite", "wb").write(tflite_model)
```

可能な限り効率的に実行される量子化モデルを作成するためには、`代表的なデータセット`、つまりモデルを学習させたデータセットの入力値の全範囲を表す数値のセットを提供する必要がある。

前のセルでは、テストデータセットの`x`値を代表データセットとして使うことができる。`representative_dataset_generator()`という関数を定義し、`yield`演算子を使って値を一つずつ返す。

これらのモデルが変換と量子化後も正確であることを証明するために、両方のモデルを使って予測を行い、テスト結果と比較する。これらはTensorFlow Liteモデルであるため、TensorFlow Liteインタプリタを使用する必要がある。

TensorFlow Liteインタプリタは、主に効率化のために設計されているため、`Keras` APIよりも使い方が若干複雑だ。`Keras`モデルで予測を行うには、`predict()`メソッドを呼び出し、入力の配列を渡せばいい。TensorFlow Liteでは、以下のようにする必要がある：

1. `Interpreter`オブジェクトをインスタンス化する。
2. モデルのメモリを確保するメソッドをいくつか呼び出す。
3. 入力テンソルに入力を書き込む。
4. モデルを呼び出す。
5. 出力テンソルから出力を読み取る。

これは大変なことのように聞こえるが、今はあまり気にしないでほしい。とりあえず、以下のセルを実行して両方のモデルで予測を行い、グラフにプロットする：

```
# Instantiate an interpreter for each model
sine_model = tf.lite.Interpreter('sine_model.tflite')
sine_model_quantized = tf.lite.Interpreter('sine_model_quantized.tflite')

# Allocate memory for each model
sine_model.allocate_tensors()
sine_model_quantized.allocate_tensors()

# Get indexes of the input and output tensors
sine_model_input_index = sine_model.get_input_details()[0]["index"]
sine_model_output_index = sine_model.get_output_details()[0]["index"]
sine_model_quantized_input_index = sine_model_quantized.get_input_details()[0]["index"]
sine_model_quantized_output_index = \
  sine_model_quantized.get_output_details()[0]["index"]

# Create arrays to store the results
sine_model_predictions = []
sine_model_quantized_predictions = []

# Run each model's interpreter for each value and store the results in arrays
for x_value in x_test:
  # Create a 2D tensor wrapping the current x value
  x_value_tensor = tf.convert_to_tensor([[x_value]], dtype=np.float32)
  # Write the value to the input tensor
  sine_model.set_tensor(sine_model_input_index, x_value_tensor)
  # Run inference
  sine_model.invoke()
  # Read the prediction from the output tensor
  sine_model_predictions.append(
      sine_model.get_tensor(sine_model_output_index)[0])
  # Do the same for the quantized model
  sine_model_quantized.set_tensor\
  (sine_model_quantized_input_index, x_value_tensor)
  sine_model_quantized.invoke()
  sine_model_quantized_predictions.append(
      sine_model_quantized.get_tensor(sine_model_quantized_output_index)[0])


# See how they line up with the data
plt.clf()
plt.title('Comparison of various models against actual values')
plt.plot(x_test, y_test, 'bo', label='Actual')
plt.plot(x_test, predictions, 'ro', label='Original predictions')
plt.plot(x_test, sine_model_predictions, 'bx', label='Lite predictions')
plt.plot(x_test, sine_model_quantized_predictions, 'gx', \
  label='Lite quantized predictions')
plt.legend()
plt.show()
```

![](assets/timl_0421.png)

グラフから、元のモデル、変換されたモデル、量子化されたモデルの予測はすべて、区別がつかないほど近いことがわかる。状況は良好だ！

量子化するとモデルが小さくなるので、変換された両方のモデルを比較してサイズの違いを見てみよう。以下のセルを実行してサイズを計算し、両者を比較する：

```
import os
basic_model_size = os.path.getsize("sine_model.tflite")
print("Basic model is %d bytes" % basic_model_size)
quantized_model_size = os.path.getsize("sine_model_quantized.tflite")
print("Quantized model is %d bytes" % quantized_model_size)
difference = basic_model_size - quantized_model_size
print("Difference is %d bytes" % difference)
```

次のような出力が表示されるはずだ：

```
Basic model is 2736 bytes
Quantized model is 2512 bytes
Difference is 224 bytes
```

量子化されたモデルは、オリジナル・バージョンよりも224バイト小さくなっている。約2.4キロバイトと、このモデルはすでに非常に小さく、重みとバイアスは全体のサイズのほんの一部しか占めていない。重みだけでなく、モデルには`計算グラフ`と呼ばれるDeep Learningネットワークのアーキテクチャを構成するすべてのロジックが含まれている。本当に小さなモデルの場合、これはモデルの重みよりも大きなサイズになる可能性があり、量子化はほとんど効果がないことを意味する。

より複雑なモデルはより多くの重みを持つため、量子化によるスペースの節約はより大きくなる。最も洗練されたモデルでは、4倍に近づくと予想される。

正確なサイズに関係なく、量子化されたモデルはオリジナルのバージョンよりも実行時間が短くなる。

## Cファイルに変換する

TensorFlow Lite for Microcontrollersで使用するモデルを準備する最後のステップは、アプリケーションに含めることができるCソースファイルに変換することである。

これまでこの章では、TensorFlow LiteのPython APIを使ってきた。つまり、`Interpreter`コンストラクタを使って、モデルファイルをディスクから読み込むことができた。

しかし、ほとんどのマイクロコントローラーはファイルシステムを持っていないし、たとえ持っていたとしても、限られたスペースを考えると、ディスクからモデルをロードするために必要な余分なコードは無駄になってしまう。その代わりに、エレガントなソリューションとして、バイナリにインクルードして直接メモリにロードできるCソース・ファイルでモデルを提供する。

ファイル中では、モデルはバイトの配列として定義されている。幸いなことに、`xxd`という便利なUnixツールがあり、与えられたファイルを必要な形式に変換することができる。

次のセルは、量子化されたモデルに対して`xxd`、出力を`sine_model_quantized.cc`というファイルに書き出し、スクリーンにプリントしている：

```
# Install xxd if it is not available
!apt-get -qq install xxd
# Save the file as a C source file
!xxd -i sine_model_quantized.tflite > sine_model_quantized.cc
# Print the source file
!cat sine_model_quantized.cc
```

出力は非常に長いので、ここですべてを再現することはしないが、ここに最初と最後だけを含むスニペットを掲載する：

```
unsigned char sine_model_quantized_tflite[] = {
  0x1c, 0x00, 0x00, 0x00, 0x54, 0x46, 0x4c, 0x33, 0x00, 0x00, 0x12, 0x00,
  0x1c, 0x00, 0x04, 0x00, 0x08, 0x00, 0x0c, 0x00, 0x10, 0x00, 0x14, 0x00,
  // ...
  0x00, 0x00, 0x08, 0x00, 0x0a, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x09,
  0x04, 0x00, 0x00, 0x00
};
unsigned int sine_model_quantized_tflite_len = 2512;
```

このモデルをプロジェクトで使用するには、ソースをコピー＆ペーストするか、ノートブックからファイルをダウンロードする。
