## モデルを改善する

元のモデルがデータの複雑さを学習するには小さすぎたという知識で武装し、我々はそれをより良くするよう試みることができる。モデルを設計し、そのパフォーマンスを評価し、改善を期待して変更を加える。

ネットワークを大きくする簡単な方法は、ニューロンをもう1層追加することだ。ニューロンの各層は、入力が期待される出力に近づくような変換を表す。ニューロンの層が多ければ多いほど、これらの変換はより複雑になる。

次のセルを実行して、先ほどと同じようにモデルを再定義するが、真ん中に16個のニューロンのレイヤーを追加する：

```
model_2 = tf.keras.Sequential()

# First layer takes a scalar input and feeds it through 16 "neurons." The
# neurons decide whether to activate based on the 'relu' activation function.
model_2.add(layers.Dense(16, activation='relu', input_shape=(1,)))

# The new second layer may help the network learn more complex representations
model_2.add(layers.Dense(16, activation='relu'))

# Final layer is a single neuron, since we want to output a single value
model_2.add(layers.Dense(1))

# Compile the model using a standard optimizer and loss function for regression
model_2.compile(optimizer='rmsprop', loss='mse', metrics=['mae'])

# Show a summary of the model
model_2.summary()
```

見ての通り、コードは基本的に最初のモデルと同じだが、`Dense` レイヤーが追加されている。`summary()` の結果を見るために、セルを実行してみよう：


16ニューロンのレイヤーが2つあるので、新しいモデルはかなり大きくなる。重みは(1 * 16) + (16 * 16) + (16 * 1) = 288個、バイアスは16 + 16 + 1 = 33個で、合計288 + 33 = 321個のパラメータがある。元のモデルには合計49パラメータしかなかったから、これはモデルサイズの555%増となる。うまくいけば、この余分な容量がデータの複雑さを表現するのに役立つだろう。

## テスト

先ほど、20％のデータをテスト用にセットした。議論したように、検証データとテストデータを別々に持つことは非常に重要である。検証のパフォーマンスに基づいてネットワークを微調整するため、誤ってモデルを検証セットに適合させすぎてしまい、新しいデータに一般化できなくなるリスクがある。新鮮なデータを保持し、モデルの最終テストに使用することで、このようなことが起こらないようにすることができる。

テストデータを使った後は、モデルをさらにチューニングしたいという衝動を抑える必要がある。もしテストパフォーマンスを向上させる目的でセットを変更したら、テストセットをオーバーフィットさせてしまうかもしれない。そうすると、テストするための新しいデータがなくなってしまうからだ。

つまり、もし我々のモデルがテストデータで悪いパフォーマンスを示したら、それは振り出しに戻る時だということだ。現在のモデルの最適化をやめて、まったく新しいアーキテクチャを考え出す必要がある。

それを念頭に置いて、次のセルではテストデータに対してモデルを評価する：

```
# Calculate and print the loss on our test dataset
loss = model_2.evaluate(x_test, y_test)

# Make predictions based on our test dataset
predictions = model_2.predict(x_test)

# Graph the predictions against the actual values
plt.clf()
plt.title('Comparison of predictions and actual values')
plt.plot(x_test, y_test, 'b.', label='Actual')
plt.plot(x_test, predictions, 'r.', label='Predicted')
plt.legend()
plt.show()
```

まず、テストデータを使ってモデルの`evaluate()` メソッドを呼び出す。これは損失と平均絶対値誤差のメトリックを計算して出力し、モデルの予測が実際の値からどの程度ずれているかを知らせてくれる。次に、予測値のセットを作り、実際の値とともにグラフにプロットする。

さて、セルを走らせてモデルのパフォーマンスを知ることができる！まず、`evaluate()` の結果を見てみよう：

```
200/200 [==============================] - 0s 71us/sample - loss: 0.0103 - mae: 0.0718
```

これは200のデータポイントが評価されたことを示しており、これはテストセット全体である。モデルは各予測に71マイクロ秒を要した。損失メトリックは0.0103で、これは非常に優れており、検証の損失0.0104に非常に近い。平均絶対誤差0.0718も非常に小さく、検証における等価性0.0806にかなり近い。

これは、我々のモデルがうまく機能しており、オーバーフィットしていないことを意味する！もしモデルが検証データをオーバーフィットしていたら、テストセットのメトリックは検証の結果よりもかなり悪くなっていただろう。

[図4-20に](#ch04.html#test_predicted_actual)示す、実際の値に対する予測値のグラフを見れば、我々のモデルがどれだけうまく機能しているかが一目瞭然だ。
