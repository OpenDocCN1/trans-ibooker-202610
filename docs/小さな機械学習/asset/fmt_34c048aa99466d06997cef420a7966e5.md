
```
  // Determine how many measurements to keep in order to
  // meet kTargetHz
  float sample_rate = IMU.accelerationSampleRate();
  sample_every_n = static_cast<int>(roundf(sample_rate / kTargetHz));
```

したがって、割り算の結果は4.76となる。従って、割り算の結果は4.76となる。これで、目標のサンプル・レート25Hzを達成するために、119Hzのサンプルのうちいくつをキープする必要があるかがわかる：4.76ごとに1サンプルだ。

端数のサンプル数を保持するのは難しいので、`roundf()`関数を使用して、最も近い数である5に丸める。信号をダウンサンプリングするには、5回に1回の測定を保持する必要がある。この結果、有効サンプルレートは23.8Hzとなり、我々のモデルがうまく機能するのに十分な近似値となる。この値を`sample_every_n`変数に保存し、後で使用する。

ダウンサンプリングのパラメータが決まったので、ユーザにアプリケーションの準備ができたことを知らせるメッセージを送り、`SetupAccelerometer()`関数から戻る：

```
  error_reporter->Report("Magic starts!");

  return kTfLiteOk;
}
```

次に、`ReadAccelerometer()`を定義する。この関数は新しいデータをキャプチャし、モデルの出力テンソルに書き込む。ジェスチャーがうまく認識された後、内部バッファをクリアするために使われるコードから始まり、その後のジェスチャーのためにスレーターをきれいにする：

```
bool ReadAccelerometer(tflite::ErrorReporter* error_reporter, float* input,
                       int length, bool reset_buffer) {
  // Clear the buffer if required, e.g. after a successful prediction
  if (reset_buffer) {
    memset(save_data, 0, 600 * sizeof(float));
    begin_index = 0;
    pending_initial_data = true;
  }
```

次に、IMUライブラリーを使って、ループの中で利用可能なデータをチェックする。利用可能なデータがあれば、それを読み取る：

```
  // Keep track of whether we stored any new data
  bool new_data = false;
  // Loop through new samples and add to buffer
  while (IMU.accelerationAvailable()) {
    float x, y, z;
    // Read each sample, removing it from the device's FIFO buffer
    if (!IMU.readAcceleration(x, y, z)) {
      error_reporter->Report("Failed to read data");
      break;
    }
```

Arduino Nano 33 BLE Senseボードの加速度センサーには、[*FIFOバッファと*](https://oreil.ly/kFEa0)呼ばれるものが搭載されている。これは加速度センサー自体にある特殊化されたメモリー・バッファで、最新の32個の測定値を保持する。加速度センサーのハードウェアの一部であるため、FIFOバッファはアプリケーション・コードが実行されている間でも測定値を蓄積し続ける。もしFIFOバッファがなければ、多くのデータが失われ、ジェスチャーの正確な記録が得られないかもしれない。

`IMU.accelerationAvailable()`を呼び出すとき、加速度センサーのFIFOバッファに新しいデータがあるかどうかをクエリしている。ループを使用して、バッファからすべてのデータを、残りがなくなるまで読み取り続ける。

次は、超シンプルなダウンサンプリングアルゴリズムを実装する：

```
    // Throw away this sample unless it's the nth
    if (sample_skip_counter != sample_every_n) {
      sample_skip_counter += 1;
      continue;
    }
```

ここで、`n`は`sample_every_n`に格納されている数である。このために、`sample_skip_counter`というカウンタを保持し、最後に保持したサンプルからいくつのサンプルが読み取られたかを知ることができる。読み取る測定ごとに、それが`n`番目かどうかのチェックする。もしそうでなければ、データをどこにも書き込まずにループを`continue`、事実上捨ててしまう。この単純な処理によって、データがダウンサンプリングされる。

もし実行がこの時点より先に進んだら、データを保持するつもりだ。そのために、`save_data`バッファーの連続した位置にデータを書き込む：

```
    // Write samples to our buffer, converting to milli-Gs
    // and flipping y and x order for compatibility with
    // model (sensor orientation is different on Arduino
    // Nano BLE Sense compared with SparkFun Edge)
    save_data[begin_index++] = y * 1000;
    save_data[begin_index++] = x * 1000;
    save_data[begin_index++] = z * 1000;
```

このモデルは、`x`、`y`、`z`の順番で加速度センサーの測定値を受け入れる。ここで、`x`の前に`y`の値をバッファに書き込んでいることに気づくだろう。これは、このモデルがSparkFun Edgeボードで取得されたデータで学習されたためである。この違いは、SparkFun Edgeのx軸がArduinoのy軸と等価であることを意味し、その逆も同様である。コード内でこれらの軸のデータを入れ替えることで、モデルが理解できるデータを供給していることを確認できる。

ループの最後の数行は、ループ内で使用されるいくつかのステート変数をセットする、いくつかの家事をしている：

```
    // Since we took a sample, reset the skip counter
    sample_skip_counter = 1;
    // If we reached the end of the circle buffer, reset
    if (begin_index >= 600) {
      begin_index = 0;
    }
    new_data = true;
  }
```

この新しいデータを取得した後、さらにいくつかのチェックを行う。今回は、推論を実行するのに十分なデータがあることを確認する。そうでない場合、あるいは新しいデータが今回取り込まれなかった場合は、何もせずに関数から戻る：

```
  // Skip this round if data is not ready yet
  if (!new_data) {
    return false;
  }

  // Check if we are ready for prediction or still pending more initial data
  if (pending_initial_data && begin_index >= 200) {
    pending_initial_data = false;
  }

  // Return if we don't have enough data
  if (pending_initial_data) {
    return false;
  }
```

新しいデータがないときに`false`を返すことで、呼び出し関数が推論をわざわざ実行しなくてもいいことがわかるようにしている。

ここまでくれば、新しいデータが得られたことになる。新しいサンプルを含む適切な量のデータを入力テンソルにコピーする：

```
  // Copy the requested number of bytes to the provided input tensor
  for (int i = 0; i < length; ++i) {
    int ring_array_index = begin_index + i - length;
    if (ring_array_index < 0) {
      ring_array_index += 600;
    }
    input[i] = save_data[ring_array_index];
  }

  return true;
}
```

これで完了だ！これで入力テンソルにデータが入力され、推論を実行する準備が整った。推論が実行された後、結果はジェスチャー予測に渡され、有効なジェスチャーが見つかったかどうかを判断する。結果は出力ハンドラに渡される。

### Arduinoでジェスチャーに反応する

出力ハンドラーは[`arduino/output_handler.cc`で](https://oreil.ly/kdVLW)定義されている。どのジェスチャーが検出されたかに応じてシリアル・ポートに情報を記録し、推論が実行されるたびにボードのLEDをトグルするだけだ。

この関数を初めて実行したとき、LEDは出力用に設定される：

```
void HandleOutput(tflite::ErrorReporter* error_reporter, int kind) {
  // The first time this method runs, set up our LED
  static bool is_initialized = false;
  if (!is_initialized) {
    pinMode(LED_BUILTIN, OUTPUT);
    is_initialized = true;
  }
```

次に、推論ごとにLEDの点灯と消灯を切り替える：

```
  // Toggle the LED every time an inference is performed
  static int count = 0;
  ++count;
  if (count & 1) {
    digitalWrite(LED_BUILTIN, HIGH);
  } else {
    digitalWrite(LED_BUILTIN, LOW);
  }
```
