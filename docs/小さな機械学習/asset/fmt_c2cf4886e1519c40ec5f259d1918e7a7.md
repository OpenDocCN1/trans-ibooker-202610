
```
  // Copy the requested number of bytes to the provided input tensor
  for (int i = 0; i < length; ++i) {
    int ring_array_index = begin_index + i - length;
    if (ring_array_index < 0) {
      ring_array_index += 600;
    }
    input[i] = save_data[ring_array_index];
  }
  return true;
```

変数`length`は、`ReadAccelerometer()`に渡される引数で、コピーすべきデータ量を決定する。`length`我々のモデルは入力として128個の3軸読み取りを取るので、`main_functions.cc`のコードは`ReadAccelerometer()`を384 (128 * 3)で呼び出している。

この時点で、入力テンソルは新鮮な加速度センサーのデータで満たされる。推論が実行され、その結果がジェスチャー・プレディクタによって解釈され、その結果が出力ハンドラに渡されてユーザに表示される。

## SparkFun Edgeでジェスチャーに反応する

[`sparkfun_edge/output_handler.cc`に](https://oreil.ly/ix1o1)ある出力ハンドラーは非常にシンプルだ。最初に実行するときは、LEDを出力するように設定する：

```
void HandleOutput(tflite::ErrorReporter* error_reporter, int kind) {
  // The first time this method runs, set up our LEDs correctly
  static bool is_initialized = false;
  if (!is_initialized) {
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_RED, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_BLUE, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_GREEN, g_AM_HAL_GPIO_OUTPUT_12);
    am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_YELLOW, g_AM_HAL_GPIO_OUTPUT_12);
    is_initialized = true;
  }
```

次に、推論ごとに黄色のLEDを点滅させる：

```
  // Toggle the yellow LED every time an inference is performed
  static int count = 0;
  ++count;
  if (count & 1) {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
  } else {
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
  }
```

その後、どのジェスチャーが検出されたかをチェックする。個々のジェスチャーごとにLEDを点灯させ、他のすべてのジェスチャーを消去し、美しいASCIIアートをシリアル・ポート経由で出力する。これが「翼」のジェスチャーを処理するコードだ：

```
  // Set the LED color and print a symbol (red: wing, blue: ring, green: slope)
  if (kind == 0) {
    error_reporter->Report(
        "WING:\n\r*         *         *\n\r *       * *       "
        "*\n\r  *     *   *     *\n\r   *   *     *   *\n\r    * *       "
        "* *\n\r     *         *\n\r");
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_BLUE);
    am_hal_gpio_output_clear(AM_BSP_GPIO_LED_GREEN);
```

シリアルポートのモニターでは、出力は次のようになる：

```
WING:
*         *         *
 *       * *       *
  *     *   *     *
   *   *     *   *
    * *       * *
     *         *
```

ジェスチャーごとに異なるシリアル出力とLEDが使用される。

## 例を実行する

ここまでで、SparkFun Edgeのコードがどのように動作するかを見てきた。次に、このコードをハードウェア上で動かしてみよう。

### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は[`README.md`を](https://oreil.ly/Ts6MT)チェックしてほしい。

コードをビルドしてデプロイするには、以下のものが必要だ：

* SparkFun Edgeボードに[Himax HM01B0ブレークアウトを](https://oreil.ly/f23oa)取り付けた。
* USBプログラマ（SparkFunシリアルベーシックブレークアウトをお勧めする。）
* 適合するUSBケーブル
* Python 3といくつかの依存関係

### 注

正しいバージョンのPythonがインストールされているかどうかわからない場合は、[「Running the Example](#ch06.html#running_hello_world_sparkfun_edge)」に確認方法が載っている。

ターミナルウィンドウを開き、TensorFlowリポジトリをクローンし、そのディレクトリに移動する：

```
git clone https://github.com/tensorflow/tensorflow.git
cd tensorflow
```

次に、バイナリをビルドし、デバイスにダウンロードするためのいくつかのコマンドを実行する。タイピングの手間を省くため、これらのコマンドは[`README.md`から](https://oreil.ly/MQmWw)コピー＆ペーストできる。

### バイナリをビルドする

以下のコマンドは、必要な依存関係をすべてダウンロードし、SparkFun Edge用のバイナリをコンパイルする：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
 TARGET=sparkfun_edge magic_wand_bin
```

バイナリーは`*.bin`ファイルとして以下の場所に作成される：

```
tensorflow/lite/micro/tools/make/gen/
 sparkfun_edge_cortex-m4/bin/magic_wand.bin
```

ファイルが存在するかどうかを確認するには、以下のコマンドを使うことができる：

```
test -f tensorflow/lite/micro/tools/make/gen/sparkfun_edge_ \
  cortex-m4/bin/magic_wand.bin &&  echo "Binary was successfully created" || \
  echo "Binary is missing"
```

このコマンドを実行すると、コンソールに`Binary was successfully created`。

`Binary is missing`が表示された場合、ビルドプロセスに問題があったことになる。もしそうなら、`make`コマンドの出力に、何がうまくいかなかったかを示すヒントがある可能性がある。

### バイナリに署名する

バイナリをデバイスにデプロイするには、暗号鍵で署名する必要がある。バイナリをSparkFun Edgeにフラッシュできるように署名するコマンドをいくつか実行してみよう。ここで使用するスクリプトは、Makefileの実行時にダウンロードされるAmbiq SDKのものである。

以下のコマンドを入力し、開発に使えるダミーの暗号鍵をセットアップする：

```
cp tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info0.py
  tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0/ \
  tools/apollo3_scripts/keys_info.py
```

次に、以下のコマンドを実行して署名付きバイナリを作成する。必要に応じて、`python3`を`python`で置き換える：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_image_blob.py \
  --bin tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/micro_vision.bin \
  --load-address 0xC000 \
  --magic-num 0xCB \
  -o main_nonsecure_ota \
  --version 0x0
```

これで`main_nonsecure_ota.bin`ファイルが作成される。次のステップで使用するスクリプトでデバイスをフラッシュするために使用できるファイルの最終バージョンを作成するために、このコマンドを実行する：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_wireupdate_blob.py \
--load-address 0x20000 \
--bin main_nonsecure_ota.bin \
-i 6 \
-o main_nonsecure_wire \
--options 0x1
```

これで、コマンドを実行したディレクトリに`main_nonsecure_wire.bin`というファイルができるはずだ。これがデバイスにフラッシュするファイルだ。

### バイナリをフラッシュする

SparkFun Edgeは、現在実行中のプログラミングを1メガバイトのフラッシュメモリーに保存する。ボードに新しいプログラムを実行させたい場合は、そのプログラムをボードに送信する必要があり、ボードがそれをフラッシュ・メモリーに保存し、以前に保存されたプログラムを上書きする。このプロセスはフラッシュと呼ばれている。

### プログラマを基板に取り付ける

ボードに新しいプログラムをダウンロードするには、SparkFun USB-C Serial Basicシリアル・プログラマを使用する。このデバイスにより、コンピューターはUSB経由でマイクロコントローラーと通信できる。

このデバイスをボードに取り付けるには、以下の手順を実行する：

1. SparkFun Edgeの側面に6ピンのヘッダがある。
2. SparkFun USB-C Serial Basicをこれらのピンに差し込み、各デバイスのBLKとGRNと書かれたピンが正しく並んでいることを確認する。

[図11-11に](#ch11.html#sparkfun_edge_serial_basic_4)正しい配置を示す。

![](assets/timl_0613.png)

### プログラマをコンピュータに取り付ける

次に、ボードをUSBでコンピューターに接続する。ボードをプログラミングするには、コンピューターがデバイスに付けている名前を特定する必要がある。これを行う最良の方法は、接続前と接続後のコンピュータのデバイスをすべてリストアップし、どのデバイスが新しいかを確認することである。

#### 警告

プログラマ用のオペレーティング・システムのデフォルト・ドライバに関する問題が報告されている人もいるので、先に進む前に[ドライバを](https://oreil.ly/vLavS)インストールすることを強く勧める。

USBでデバイスを接続する前に、以下のコマンドを実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

以下のようなリストが出力されるはずだ：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
```

プログラマをコンピューターのUSBポートに接続し、コマンドをもう一度実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

次の例のように、追加の項目が出力されるはずである。新しい項目の名前は違うかもしれない。この新しい項目はデバイスの名前である：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
/dev/cu.wchusbserial-1450
```

この名前は、デバイスを参照するために使用される。ただし、プログラマがどのUSBポートに接続されているかによって、この名前が変わることがあるので、コンピュータからボードを取り外して再度接続した場合は、名前を調べ直す必要があるかもしれない。

#### チップ

ユーザによっては、リストに2つのデバイスが表示されるという報告がある。2つのデバイスが表示された場合、正しい方は "wch "で始まる。

デバイス名を確認したら、後で使えるようにシェル変数に入れておく：

```
export DEVICENAME=<your device name here>
```

これは、後でデバイス名を必要とするコマンドを実行するときに使用する変数である。

### スクリプトを実行してボードをフラッシュする

ボードをフラッシュするには、新しいバイナリを受け取るための特別な「ブートローダー」状態にする必要がある。その後、ボードにバイナリを送信するスクリプトを実行することができる。

まず、ボーレートを指定する環境変数を作成する。ボーレートとは、データをデバイスに送信する速度である：

```
export BAUD_RATE=921600
```

次のコマンドをターミナルにペーストする。コマンドの`${DEVICENAME}`と`${BAUD_RATE}`は、前のセクションでセットした値に置き換えられる。必要であれば、`python3`を`python`で置き換えることを忘れないこと：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/uart_wired_update.py -b \
  ${BAUD_RATE} ${DEVICENAME} -r 1 -f main_nonsecure_wire.bin -i 6
```

次に、ボードをブートローダーの状態にリセットし、ボードをフラッシュする。

ボード上で、[図11-12に](#ch11.html#sparkfun_edge_buttons_4)示すように、`RST`と`14`とマークされたボタンを見つける。

![](assets/timl_0614.png)

以下の手順を実行する：

1. ボードがプログラマに接続され、全体がUSB経由でコンピューターに接続されていることを確認する。
2. ボード上で、`14`と書かれたボタンを押し続ける。*そのまま押し続ける。*
3. `14`と書かれたボタンを押したまま、`RST`と書かれたボタンを押してボードをリセットする。
4. コンピュータでEnterキーを押してスクリプトを実行する。*`14`ボタンを押し続ける。*

これで画面に次のようなものが表示されるはずだ：
