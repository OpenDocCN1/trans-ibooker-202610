`#define` のリストが表示されるはずだ。ここに示されているように、`#define OV2640_MINI_2MP_PLUS` 以外はすべてコメントアウトされていることを確認する：

### チップ

このサンプルはArducamライブラリのコミット#e216049を使用して開発された。もしライブラリで問題が発生した場合は、この特定のコミットをダウンロードして、まったく同じコードを使用していることを確認してほしい。

次のステップは、JPEGDecoderライブラリをインストールすることだ。これはArduino IDEからできる。`Tools`メニューで`Manage Libraries`オプションを選択し、`JPEGDecoder`を検索する。ライブラリのバージョン1.8.0をインストールする。

ライブラリをインストールしたら、Arduino Nano 33 BLE Senseと互換性のないオプションのコンポーネントを無効にするように設定する必要がある。`Arduino/libraries/JPEGDecoder/src/User_Config.h`を開き、このファイルの抜粋に示されているように、`#define LOAD_SD_LIBRARY` と`#define LOAD_SDFAT_LIBRARY` の両方がコメントアウトされていることを確認する：

 // the JPEGs
 // Commenting out the line is NOT essential but will save some FLASH space if
 // SD Card access is not needed. Note: use of SdFat is currently untested!

 //#define LOAD_SD_LIBRARY // Default SD Card library
 //#define LOAD_SDFAT_LIBRARY // Use SdFat library instead, so SD Card SPI can
                              // be bit bashed

![](assets/timl_0607.png)

アップロードが正常に完了すると、すぐにプログラミングが実行される。

テストするには、まずデバイスのカメラを人ではないものに向けるか、レンズを覆い隠す。次に青いLEDが点滅すると、デバイスはカメラからフレームをキャプチャし、推論を開始する。人物検出に使用している構想モデルは比較的大きいため、推論には長い時間がかかる。執筆時点では約19秒だが、その後TensorFlow Liteが高速化した可能性もある。

推論が完了すると、その結果は別のLEDが点灯することに変換される。カメラを人ではない何かに向けたのだから、赤いLEDが点灯するはずだ。

では、デバイスのカメラを自分に向けてみよう！次に青いLEDが点滅したら、デバイスは別の画像をキャプチャし、推論を開始する。およそ19秒後、緑のLEDが点灯するはずだ。

覚えておいてほしいのは、画像データは各推論の前に、青色LEDが点滅するたびにスナップショットとして取り込まれるということだ。その瞬間にカメラに向けられたものが、モデルに入力される。次に画像がキャプチャされ、青いLEDが再び点滅するまで、カメラがどこに向けられているかは問題ではない。

一見正しくない結果が出る場合は、照明の良い環境にいることを確認する。また、カメラの向きが正しいか、ピンが下向きになっているか、撮影した画像が正しい向きになっているかも確認する必要がある。加えて、これは精度と小ささを引き換えにした小さなモデルであることを覚えておくといいだろう。非常によく機能するが、常に100％正確というわけではない。

推論の結果は、Arduino Serial Monitorでも見ることができる。これを行うには、ツールメニューからシリアルモニターを開く。アプリケーションの実行中に何が起こっているかを示す詳細なログが表示される。また、"Show timestamp "ボックスにチェックを入れると、各プロセスの所要時間を見ることができる：

```
14:17:50.714 -> Starting capture
14:17:50.714 -> Image captured
14:17:50.784 -> Reading 3080 bytes from ArduCAM
14:17:50.887 -> Finished reading
14:17:50.887 -> Decoding JPEG and converting to greyscale
14:17:51.074 -> Image decoded and processed
14:18:09.710 -> Person score: 246 No person score: 66
```

このログから、カメラモジュールの画像データの取り込みと読み取りに約170ミリ秒、JPEGのデコードとグレースケールへの変換に180ミリ秒、推論の実行に18.6秒かかっていることがわかる。

## スパークファン・エッジ

SparkFun Edgeボードは、低消費電力に最適化されている。同様に効率的なカメラモジュールと組み合わせることで、バッテリーで動作する構想アプリケーションの構築に理想的なプラットフォームとなる。ボードのリボンケーブルアダプターを介してカメラモジュールを接続するのは簡単だ。

### どのカメラモジュールを購入するか

この例では、SparkFun社の[Himax HM01B0ブレークアウト・カメラ・モジュールを](https://oreil.ly/H24xS)使用している。これは320×320ピクセルのイメージセンサーをベースにしており、消費電力は極めて小さい：30フレーム/秒（FPS）でキャプチャした場合、2mW未満である。

### SparkFun Edgeで画像をキャプチャする

Himax HM01B0カメラモジュールで画像のキャプチャを開始するには、まずカメラを初期化する必要がある。これが終わると、新しい画像が必要になるたびにカメラからフレームを読み取ることができる。フレームは、カメラが現在見ることができるものを表すバイトの配列である。

このカメラでは、ビルドプロセスの一部としてダウンロードされるAmbiq Apollo3 SDKと、`sparkfun_edge/himax_driver`にあるHM01B0ドライバーの両方を多用することになる。

画像プロバイダーは` sparkfun_edge/image_provider.cc`に実装されている。このコードはSparkFunボードとHimaxカメラ・モジュールに特有なので、詳細については説明しない。その代わりに、高レベルで何が起こっているのかを順を追って説明しよう。

`GetImage()` 関数は、画像プロバイダーと世界とのインタフェースである。アプリケーションのメインループで呼び出され、画像データのフレームを取得する。最初に呼び出されるときは、カメラを初期化する必要がある。これは `InitCamera()`関数を呼び出すことで行われる：

```
 // Capture single frame.  Frame pointer passed in to reduce memory usage.  This
 // allows the input tensor to be used instead of requiring an extra copy.
 TfLiteStatus GetImage(tflite::ErrorReporter* error_reporter, int frame_width,
                       int frame_height, int channels, uint8_t* frame) {
   if (!g_is_camera_initialized) {
     TfLiteStatus init_status = InitCamera(error_reporter);
     if (init_status != kTfLiteOk) {
       am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
       return init_status;
     }
```

`InitCamera()` が`kTfLiteOk` 以外のステータスを返した場合、（`am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED)` を使って）ボードの赤色 LED を点灯させ、問題を示す。これはデバッグに役立つ。

`InitCamera()` 関数は`image_provider.cc`で定義されている。この関数は非常にデバイスに特化したものなので、ここでは説明しない。自分のコードで使いたい場合は、コピー＆ペーストすればいい。

Apollo3 SDKの関数を呼び出し、マイクロコントローラーの入出力を設定し、カメラモジュールと通信できるようにする。また、新しい画像データを送信するためにカメラが使用するメカニズムである割り込みも有効にする。これがすべてセットアップされると、カメラ・ドライバを使用してカメラの電源を入れ、継続的に画像のキャプチャを開始するように設定する。

カメラモジュールには自動露出機能があり、フレームがキャプチャされると自動的に露出設定が較正される。推論を行う前に較正を行うため、`GetImage()` 関数の次の部分ではカメラドライバの `hm01b0_blocking_read_oneframe_scaled()` 関数を使用していくつかのフレームをキャプチャする。キャプチャーされたデータには何もしない。カメラモジュールの自動露出関数に処理する材料を与えるためにこの処理を行うだけである：

```
     // Drop a few frames until auto exposure is calibrated.
     for (int i = 0; i < kFramesToInitialize; ++i) {
       hm01b0_blocking_read_oneframe_scaled(frame, frame_width, frame_height,
                                            channels);
     }
     g_is_camera_initialized = true;
   }
```

セットアップが終われば、あとは`GetImage()` 。`hm01b0_blocking_read_oneframe_scaled()` 、画像をキャプチャするために呼び出すだけだ：

```
 hm01b0_blocking_read_oneframe_scaled(frame, frame_width, frame_height,
                                      channels);
```

アプリケーションのメインループで`GetImage()` が呼び出されると、`frame` 変数は入力テンソルへのポインタなので、データはカメラドライバによって入力テンソルに割り当てられたメモリ領域に直接書き込まれる。また、幅、高さ、チャンネル数を指定する。

この実装で、カメラモジュールから画像データを取り込むことができる。次に、モデルの出力にどのように反応するかを見てみよう。

### SparkFun Edgeで検出に対応する

検出レスポンダの実装は、ウェイクワードの例のコマンドレスポンダと非常に似ている。推論が実行されるたびにデバイスの青色LEDをトグルする。人が検出されると緑色のLEDが点灯し、人が検出されないと黄色のLEDが点灯する。

実装は` sparkfun_edge/detection_responder.cc`にある。ざっと見てみよう。

`RespondToDetection()` 関数は、"人 "と "人ではない "の2つのスコアを受け付ける。最初に呼び出されたとき、青、緑、黄色のLEDをセットアップして出力する：

```
 void RespondToDetection(tflite::ErrorReporter* error_reporter,
                         uint8_t person_score, uint8_t no_person_score) {
   static bool is_initialized = false;
   if (!is_initialized) {
     // Setup LED's as outputs.  Leave red LED alone since that's an error
     // indicator for sparkfun_edge in image_provider.
     am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_BLUE, g_AM_HAL_GPIO_OUTPUT_12);
     am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_GREEN, g_AM_HAL_GPIO_OUTPUT_12);
     am_hal_gpio_pinconfig(AM_BSP_GPIO_LED_YELLOW, g_AM_HAL_GPIO_OUTPUT_12);
     is_initialized = true;
   }
```

この関数は推論ごとに1回呼び出されるため、次のコードのスニペットは、推論が実行されるたびに青色LEDの点灯と消灯を切り替える：

```
 // Toggle the blue LED every time an inference is performed.
 static int count = 0;
 if (++count & 1) {
     am_hal_gpio_output_set(AM_BSP_GPIO_LED_BLUE);
 } else {
     am_hal_gpio_output_clear(AM_BSP_GPIO_LED_BLUE);
 }
```

最後に、人が検出された場合は緑色のLEDを点灯させ、検出されなかった場合は青色のLEDを点灯させる。また、`ErrorReporter` インスタンスを使用してスコアを記録する：
