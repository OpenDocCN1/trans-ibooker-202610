
## 入力テンソルのシミュレーション

まず、モデルの入力テンソルをシミュレートするために、`input` という名前の `float` 配列を用意する。128 個の 3 軸読み取りがあるので、合計 384 個（128 * 3）の長さがある。配列のすべての値を `0.0` に初期化する。

次に `ReadAccelerometer()` を呼び出す。ここでは、`ErrorReporter` インスタンス、データを書き込む配列（`input`）、取得したいデータの合計量（384バイト）を指定する。最後の引数はブール値のフラグで、`ReadAccelerometer()`、さらにデータを読み取る前にバッファをクリアするかどうかを指示する。これは、ジェスチャーが正常に認識された後に実行する必要がある。

呼び出されると、`ReadAccelerometer()` 関数は渡された配列に384バイトのデータを書き込もうとする。加速度センサーがデータ収集を開始したばかりの場合、384バイトのデータがまだ利用できないかもしれない。この場合、関数は何もせず、`false` という戻り値を返す。データが利用できない場合に推論を実行しないために、これを利用することができる。

[`accelerometer_handler.cc` に](https://oreil.ly/MwM7g)ある加速度センサーハンドラのダミー実装は、呼び出されるたびに別の読み取りが可能になるようにシミュレートしている。さらに127回呼び出すことで、`true` を返すのに十分なデータが得られるようにする。

これらのテストを実行するには、以下のコマンドを使用する：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  test_gesture_accelerometer_handler_test
```

## ジェスチャー予測

推論が行われた後、出力テンソルは確率で満たされ、どのジェスチャーが行われたかを示す。しかし、マシン学習は厳密な科学ではないため、ひとつの推論が偽陽性になる可能性もある。

偽陽性の影響を減らすために、ジェスチャーが認識されるには、少なくとも一定数の連続した推論で検出されていなければならないと規定することができる。推論を1秒間に複数回実行することを考えると、結果が有効かどうかを素早く判断できる。これがジェスチャー予測器の仕事である。

モデルの出力テンソルを入力とする単一の関数、`PredictGesture()` を定義する。ジェスチャーが検出されたかどうかを判断するために、この関数は2つのことを行う：

1. ジェスチャーの確率が最低閾値を満たしているかどうかをチェックする
2. ジェスチャーが一定回数の推論にわたって一貫して検出されているかどうかをチェックする。

必要な推論の最小回数は、ジェスチャーによって異なる。また、高速なデバイスほど頻繁に推論を実行できるため、デバイスによっても異なる。SparkFun Edgeボード用に調整されたデフォルト値は、[`constants.cc` に](https://oreil.ly/ktGgw)ある：

```
const int kConsecutiveInferenceThresholds[3] = {15, 12, 10};
```

値は、ジェスチャーがモデルの出力テンソルに現れるのと同じ順序で定義される。Arduinoのような他のプラットフォームでは、このファイルのデバイス固有のバージョンがあり、それぞれのパフォーマンスに合わせて調整された値が含まれている。

[`gesture_predictor.cc` の](https://oreil.ly/f3I6U)コードを見て、これらがどのように使われているかを見てみよう。

まず、最後に見たジェスチャーと、同じジェスチャーが何回連続して記録されたかを追跡するための変数を定義する：

```
// How many times the most recent gesture has been matched in a row
int continuous_count = 0;
// The result of the last prediction
int last_predict = -1;
```

次に、`PredictGesture()` 関数を定義し、ジェスチャーカテゴリのいずれかが、直近の推論で0.8を超える確率であったかどうかを判定する：

```
// Return the result of the last prediction
// 0: wing("W"), 1: ring("O"), 2: slope("angle"), 3: unknown
int PredictGesture(float* output) {
  // Find whichever output has a probability > 0.8 (they sum to 1)
  int this_predict = -1;
  for (int i = 0; i < 3; i++) {
    if (output[i] > 0.8) this_predict = i;
  }
```

`this_predict` を使って、予測されたジェスチャーのインデックスを保存する。

変数 `continuous_count` は、最近検出されたジェスチャが連続して何回予測されたかを追跡するために使用される。どのジェスチャ・カテゴリも確率しきい値0.8を満たさない場合、進行中の検出プロセスをリセットする。`continuous_count` を `0` に、`last_predict` を `3`（「不明」カテゴリのインデックス）に設定することで、進行中の検出プロセスをリセットし、直近の結果が既知のジェスチャではなかったことを示す：

```
  // No gesture was detected above the threshold
  if (this_predict == -1) {
    continuous_count = 0;
    last_predict = 3;
    return 3;
  }
```

次に、直近の予測が直前の予測と一致する場合、`continuous_count` をインクリメントする。そうでなければ、`0` にリセットする。また、`last_predict` に最新の予測を格納する：

```
  if (last_predict == this_predict) {
    continuous_count += 1;
  } else {
    continuous_count = 0;
  }
  last_predict = this_predict;
```

`PredictGesture()` の次のセクションでは、`continuous_count` を使って、現在のジェスチャがまだ閾値を満たしているかどうかをチェックする。満たされていない場合は、不明なジェスチャを示す `3` を返す：

```
  // If we haven't yet had enough consecutive matches for this gesture,
  // report a negative result
  if (continuous_count < kConsecutiveInferenceThresholds[this_predict]) {
    return 3;
  }
```

この点を過ぎれば、有効なジェスチャーを確認したことになる。この場合、すべての変数をリセットする：

```
  // Otherwise, we've seen a positive result, so clear all our variables
  // and report it
  continuous_count = 0;
  last_predict = -1;
  return this_predict;
}
```

関数は現在の予測値を返すことで終了する。これはメインループから出力ハンドラーに渡され、出力ハンドラーは結果をユーザに表示する。

ジェスチャー予測器のテストは [`gesture_predictor_test.cc` に](https://oreil.ly/5BZzt)ある。最初のテストは予測の成功を示している：

```
TF_LITE_MICRO_TEST(SuccessfulPrediction) {
  // Use the threshold from the 0th gesture
  int threshold = kConsecutiveInferenceThresholds[0];
  float probabilities[4] = {1.0, 0.0, 0.0, 0.0};
  int prediction;
  // Loop just too few times to trigger a prediction
  for (int i = 0; i <= threshold - 1; i++) {
    prediction = PredictGesture(probabilities);
    TF_LITE_MICRO_EXPECT_EQ(prediction, 3);
  }
  // Call once more, triggering a prediction
  // for category 0
  prediction = PredictGesture(probabilities);
  TF_LITE_MICRO_EXPECT_EQ(prediction, 0);
}
```

`PredictGesture()` 関数には、最初のカテゴリーがマッチすることを強く示す確率のセットが入力される。しかし、これらの確率で `threshold` 回呼び出されるまでは、「未知」の結果を意味する `3` を返す。`threshold` が何回か呼び出されると、カテゴリ `0` に対する正の予測が返される。

次のテストは、あるカテゴリーの高確率の連続実行が、別のカテゴリーの高確率によって中断された場合に何が起こるかを示している：

```
TF_LITE_MICRO_TEST(FailPartWayThere) {
  // Use the threshold from the 0th gesture
  int threshold = kConsecutiveInferenceThresholds[0];
  float probabilities[4] = {1.0, 0.0, 0.0, 0.0};
  int prediction;
  // Loop just too few times to trigger a prediction
  for (int i = 0; i <= threshold - 1; i++) {
    prediction = PredictGesture(probabilities);
    TF_LITE_MICRO_EXPECT_EQ(prediction, 3);
  }
  // Call with a different prediction, triggering a failure
  probabilities[0] = 0.0;
  probabilities[2] = 1.0;
  prediction = PredictGesture(probabilities);
  TF_LITE_MICRO_EXPECT_EQ(prediction, 3);
}
```

この場合、カテゴリ `0` の連続した高確率のセットを投入するが、閾値を満たすには十分な数ではない。次に、カテゴリー `2` が最も高くなるように確率を変更する。その結果、カテゴリー `3` が予測され、「未知」のジェスチャーを意味する。

最後のテストは、`PredictGesture()` が閾値を下回る確率をどのように無視するかを示している。ループの中で、`0` の閾値を満たすように、正確な数の予測を投入する。しかし、カテゴリー `0` の確率が最も高いが、その値は0.7であり、`PredictGesture()` の内部しきい値0.8を下回っている。この結果、カテゴリー `3` 「不明」予測になる：

```
TF_LITE_MICRO_TEST(InsufficientProbability) {
  // Use the threshold from the 0th gesture
  int threshold = kConsecutiveInferenceThresholds[0];
  // Below the probability threshold of 0.8
  float probabilities[4] = {0.7, 0.0, 0.0, 0.0};
  int prediction;
  // Loop the exact right number of times
  for (int i = 0; i <= threshold; i++) {
    prediction = PredictGesture(probabilities);
    TF_LITE_MICRO_EXPECT_EQ(prediction, 3);
  }
}
```

これらのテストを実行するには、以下のコマンドを使用する：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  test_gesture_predictor_test
```

## ジェスチャーを検出する

これらのコンポーネントはすべて [`main_functions.cc` にまとめられて](https://oreil.ly/ggNtD)おり、プログラムのコア・ロジックが含まれている。最初に、通常の変数といくつかの追加変数がセットアップされる：

```
namespace tflite {
namespace ops {
namespace micro {
TfLiteRegistration* Register_DEPTHWISE_CONV_2D();
TfLiteRegistration* Register_MAX_POOL_2D();
TfLiteRegistration* Register_CONV_2D();
TfLiteRegistration* Register_FULLY_CONNECTED();
TfLiteRegistration* Register_SOFTMAX();
}  // namespace micro
}  // namespace ops
}  // namespace tflite

// Globals, used for compatibility with Arduino-style sketches.
namespace {
tflite::ErrorReporter* error_reporter = nullptr;
const tflite::Model* model = nullptr;
tflite::MicroInterpreter* interpreter = nullptr;
TfLiteTensor* model_input = nullptr;
int input_length;

// Create an area of memory to use for input, output, and intermediate arrays.
// The size of this will depend on the model you're using, and may need to be
// determined by experimentation.
constexpr int kTensorArenaSize = 60 * 1024;
uint8_t tensor_arena[kTensorArenaSize];

// Whether we should clear the buffer next time we fetch data
bool should_clear_buffer = false;
}  // namespace
```

変数 `input_length` はモデルの入力テンソルの長さを格納し、変数 `should_clear_buffer` は加速度センサーハンドラのバッファを次回実行時にクリアすべきかどうかを示すフラグである。バッファのクリアは、検出が成功した後に行われ、その後の推論にクリーンな状態を提供する。

次に、`setup()` 関数は、推論を実行する準備ができるように、通常のハウスキーピングをすべて行う：
