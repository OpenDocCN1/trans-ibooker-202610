
トレーニングスクリプトのデフォルトでは、Speech Commandsを使用するが、独自のデータセットを持っている場合は、`--data_dir` 引数を使用して、代わりにそれを使用することができる。指すディレクトリは、Speech Commandsのように、認識したいクラスごとに1つのサブフォルダがあり、それぞれにWAVファイルのセットがある。また、特殊化された*背景*サブフォルダも用意する必要がある。このサブフォルダには、アプリケーションが遭遇すると予想される背景ノイズをWAVで録音したものが入っている。また、デフォルトの1秒が使用ケースに合わない場合は、認識時間を選び、`--sample_duration_ms` 引数で指定する必要がある。次に、`--wanted_words` 引数を使用して、認識したいクラスをセットすることができる。名前とは裏腹に、これらのクラスはガラスが割れる音から笑い声まで、どんな種類の音声イベントでも構わない。各クラスのWAVが十分にある限り、学習プロセスは音声の場合と同じように機能するはずだ。

もし、*glassと* *laughという*名前のWAVのフォルダがルートの`/tmp/my_wavs`ディレクトリの中にあったとしたら、独自のモデルをトレーニングする方法はこうだ：

```
python tensorflow/examples/speech_commands/train.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --data_url="" --data_dir=/tmp/my_wavs/ --wanted_words="laughter,glass" \
  --silence_percentage=25 --unknown_percentage=25 --quantize=1
```

最も難しいのは、十分なデータを発見することだ。例えば、ガラスが割れる実際の音は、映画で聞き慣れた効果音とは大きく異なることがわかった。つまり、既存の録音を発見するか、自分で録音する必要がある。学習プロセスには、各クラスの何千もの例が必要になることがあり、実際のアプリケーションで発生する可能性のあるすべてのバリエーションをカバーする必要があるため、このデータ収集プロセスには苛立ちと費用と時間がかかる。

大規模な公開データセットで学習させたモデルを、別のデータを使って異なるクラスに対する重みを微調整するの*だ*。このアプローチでは、セカンダリー・データセットでゼロから学習する場合ほど多くの例を必要とせず、しばしば高精度の結果が得られる。残念ながら、音声モデルのための転移学習はまだ研究中である。

## 自分のオーディオを録音する

気になる言葉の音声をキャプチャする必要がある場合、話し手に促し、結果をラベル付きファイルに分割してくれるツールがあれば、かなり楽になる。Speech Commandsデータセットは、[Open Speech Recordingアプリを使って](https://oreil.ly/UWsG3)録音された。このアプリは、ユーザが一般的なウェブブラウザを使って発言を録音できるようにするホスティングアプリである。ユーザは、まずWebページが表示され、録音されることに同意するかどうか尋ねられる。同意すると、録音コントロールのある新しいページに送られる。録音ボタンを押すと、プロンプトとして単語が表示され、各単語に対してあなたが発した音声が録音される。要求された単語がすべて録音されると、結果をサーバに送信するよう求められる。

`README`にはGoogle Cloudで実行するための説明があるが、Pythonで書かれたFlaskアプリなので、他の環境にも移植できるはずだ。Google Cloudを使う場合は、[`app.yaml`](https://oreil.ly/dV2kv)ファイルを更新して、自分のストレージ・バケットを指すようにし、ランダムなセッション・キーを指定する必要がある（これはハッシュ化に使うだけなので、どんな値でも構わない）。どの単語を記録するかをカスタマイズするには、[クライアント側のJavaScriptで](https://oreil.ly/XcJIe)いくつかの配列を編集する必要がある。

録音されたファイルはOGG圧縮音声としてGoogle Cloudのバケットに保存されているが、トレーニングにはWAVが必要なので、変換する必要がある。また、録音された音声の中には、単語を言い忘れたり、小さく言い過ぎたりといったエラーが含まれている可能性が高いので、可能な限り自動的にそのようなミスをフィルタリングしておくと便利だ。`BUCKET_NAME` 、バケット名を変数に設定したら、まず以下のbashコマンドを使ってファイルをローカルマシンにコピーする：

```
mkdir oggs
gsutil -m cp gs://${BUCKET_NAME}/* oggs/
```

圧縮されたOGG形式の良い特性の一つは、静かな、あるいは無音のオーディオは非常に小さなファイルになることだ：

```
find ${BASEDIR}/oggs -iname "*.ogg" -size -5k -delete
```

OGGをWAVに変換する最も簡単な方法は、コマンドラインツールを提供している[FFmpegプロジェクトを](https://ffmpeg.org/)使用することである。以下は、OGGファイルのディレクトリ全体を必要な形式に変換するコマンドのセットである：

```
mkdir -p ${BASEDIR}/wavs
find ${BASEDIR}/oggs -iname "*.ogg" -print0 | \
  xargs -0 basename -s .ogg | \
  xargs -I {} ffmpeg -i ${BASEDIR}/oggs/{}.ogg -ar 16000 ${BASEDIR}/wavs/{}.wav
```

Open Speech Recordingアプリケーションは、各単語を1秒以上記録する。これにより、ユーザの発話タイミングが予想より多少早かったり遅かったりしても、確実に捉えることができる。トレーニングには1秒間の録音が必要であり、単語がそれぞれの録音の中央にある場合に最も効果的である。私たちは小さなオープンソースユーティリティを作成し、各録音の音量を経時的に見て、センタリングが正しくなるように試み、ちょうど1秒になるように音声をトリミングしている。ターミナルに以下のコマンドを入力して使う：

```
git clone https://github.com/petewarden/extract_loudest_section \
  /tmp/extract_loudest_section_github
pushd /tmp/extract_loudest_section_github
make
popd
mkdir -p ${BASEDIR}/trimmed_wavs
/tmp/extract_loudest_section/gen/bin/extract_loudest_section \
  ${BASEDIR}'/wavs/*.wav' ${BASEDIR}/trimmed_wavs/
```

これで、正しい形式と必要な長さのファイルが詰まったフォルダができあがるが、 訓練プロセスでは、WAVをラベルごとにサブフォルダに整理する必要がある。ラベルは各ファイルの名前にエンコーディングされているので、これらのファイル名を使って適切なフォルダにソートする[Pythonスクリプトの例が](https://oreil.ly/BpQBJ)ある 。

## データ補強

データ増強は、トレーニングデータを効果的に拡大し、精度を向上させるもう一つのメソッドである。実際には、録音された発話をトレーニングに使用する前に、音声変換を施すことを意味する。これらの変換には、音量の変更、バックグラウンドノイズの混入、クリップの開始または終了のわずかなトリミングなどが含まれる。トレーニングスクリプトはデフォルトでこれらの変換をすべて行うが、コマンドライン引数を使用することで、変換の頻度や強さを調整することができる。

### 警告

このような補強は、小さなデータセットをさらに進化させるのに役立つが、奇跡を起こすことはできない。あまりに強く変換をかけると、トレーニング入力が歪んでしまい、もはや人が認識できなくなってしまう。

コマンドライン引数のいくつかを使ってオーグメントをコントロールする方法を紹介しよう：

```
python tensorflow/examples/speech_commands/train.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --wanted_words="yes,no" --silence_percentage=25 --unknown_percentage=25 \
  --quantize=1 --background_volume=0.2 --background_frequency=0.7 \
  --time_shift_ms=200
```

## モデルアーキテクチャ

先に訓練した「はい」／「いいえ」モデルは、小さく高速に設計されている。わずか18KBで、1回の実行に必要な算術演算子は40万回だ。この制約に合わせるため、精度をトレードオフにしている。独自のアプリケーションを設計する場合、特に2つ以上のカテゴリーを認識しようとする場合は、異なるトレードオフをしたくなるかもしれない。`models.py`ファイルを修正し、`--model_architecture` 引数を使用することで、独自のモデルアーキテクチャを指定することができる。`create_tiny_conv_model0` のような独自のモデル作成関数を書く必要があるが、その代わりにモデルに必要なレイヤーを指定する。そして、`create_model0` の`if` 文を更新して、あなたのアーキテクチャに名前を付け、コマンドラインのarchitecture 引数として渡されたときに、新しい作成関数を呼び出す。ドロップアウトの処理方法など、既存の作成関数を参考にすることができる。独自のモデルコードを追加した場合の呼び出し方は以下の通りだ：

```
python tensorflow/examples/speech_commands/train.py \
 --model_architecture=my_model_name --window_stride=20 --preprocess=micro \
  --wanted_words="yes,no" --silence_percentage=25 \--unknown_percentage=25 \
  --quantize=1
```

# 第9章 人物検出 人物の検出アプリケーションを構築する

この作品はAIを使って翻訳されている。ご意見、ご感想をお待ちしている：[translation-feedback@oreilly.com](mailto:translation-feedback@oreilly.com)

日常生活に最も大きな影響を与える感覚はどれかと聞かれれば、多くの人は構図と答えるだろう。^([1](#ch09.html#idm45271175553096))

構想は非常に有用な感覚である。視覚のおかげで、数え切れないほど多くの自然生物が環境をナビゲートし、食料源を発見し、危険に遭遇するのを避けることができる。人間の場合、視覚は友人を認識し、記号情報をインタプリタし、周囲の世界を理解するのに役立っている。

つい最近まで、構想の力はマシンにはなかった。私たちのロボットのほとんどは、タッチセンサーや近接センサーで世界をつつきまわして、一連の衝突からその構造に関する知識を得るだけだった。人間であれば、あるオブジェクトの形状、特性、用途を、そのオブジェクトとまったく対話することなく、一目で説明することができる。ロボットにはそのような幸運はない。視覚情報はあまりにも乱雑で、構造化されておらず、インタプリタが困難なのだ。

畳み込みニューラルネットワークの進化により、*見る*ことができるプログラミングが簡単に作れるようになった。哺乳類の視覚野の構造にヒントを得たCNNは、圧倒的に複雑な入力を既知のパターンと形状のマップにフィルタリングし、視覚世界の意味を学習する。これらの断片を正確に組み合わせることで、与えられたデジタル画像に存在する実体を知ることができる。

今日、構想モデルはさまざまなタスクに使われている。自律走行車は構想を使って道路上の危険を発見する。工場用ロボットはカメラを使って不良部品を検出する。研究者たちは、医療画像から病気を診断できるモデルを訓練している。そして、あなたのスマートフォンは、写真の中の顔が完璧にピントが合っているかどうかを確認するために、顔をスポットする可能性がかなりある。

視覚を持つマシンは、これまで手の届かなかった家事を自動化し、私たちの家庭や都市を一変させるかもしれない。しかし、構想は親密な感覚である。私たちの多くは、自分の行動が記録されたり、自分の生活がクラウドにストリームされたりすることを好まない。

内蔵カメラで「見る」ことができる家電製品を想像してみてほしい。侵入者を発見できるセキュリティー・システム、放置されたことがわかるコンロ、部屋に誰もいないと電源が切れるテレビなどだ。いずれもプライバシーが重要である。たとえ人間が映像を見ることがなかったとしても、常時接続機器に組み込まれたインターネット接続カメラのセキュリティ上の意味合いは、ほとんどのコンシューマにとって魅力的なものではない。

しかし、TinyMLを使えばすべてが変わる。長時間放置されるとバーナーを止めるスマート・コンロを思い浮かべてほしい。インターネットに接続することなく、小さなマイクロコントローラーを使って、近くに料理人がいることを「知る」ことができれば、プライバシーのトレードオフなしに、スマート・デバイスの利点をすべて得ることができる。

さらに言えば、構想を持つ小型デバイスは、これまで視覚対応マシンが進まなかった場所に行くことができる。消費電力が極小であるため、マイクロコントローラーベースの構想は、小さなバッテリーで数カ月から数年稼働する可能性がある。ジャングルやサンゴ礁に設置すれば、オンラインでなくても絶滅の危機に瀕した動物のカウントができる。

同じ技術により、自己完結型の電子コンポーネントとして構想センサーを構築することが可能だ。このセンサーは、特定のオブジェクトが視界にあれば「1」を、なければ「0」を出力するが、カメラで収集した画像データを共有することはない。このタイプのセンサーは、スマートホームシステムから自家用車まで、あらゆる製品に組み込むことができる。自転車なら、後ろに車が来たらライトを点滅させることができる。エアコンは人の帰宅を知ることができる。また、画像データは内蔵センサーの外に出ることがないため、製品がインターネットに接続されていても安全性が保証される。

本章で紹介するアプリケーションは、カメラを取り付けたマイクロコントローラー上で動作する、事前に学習させた人物検出モデルを使って、人間が視界に入ったことを知るものだ。[第10章](#ch10.html#chapter_person_detection_training)では、このモデルがどのように機能するのか、そして、あなたが望むものを検知する独自のモデルを訓練する方法を学ぶ。

この章を読めば、マイクロコントローラでカメラデータを扱う方法、構想モデルで推論を実行し、出力を解釈する方法が理解できるだろう。実際にやってみると、その簡単さに驚くかもしれない！
