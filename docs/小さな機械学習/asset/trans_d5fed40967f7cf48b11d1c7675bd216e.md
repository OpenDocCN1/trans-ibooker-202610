
根据我们的经验，原因首先是程序栈溢出。这是本地变量存储的位置，而 TensorFlow Lite for Microcontrollers 因其对大型对象的大量使用，需要比许多其他嵌入式应用常见的大小更大的空间。因此，它比许多其他嵌入式应用需要更多的空间。不幸的是，确认所需的精确大小并不容易。很多情况下，最大的因素是需要传递给 `SimpleTensorAllocator` 的内存区域。[例如](https://oreil.ly/Pb9Pa)，它被分配为本地数组：

```
  // Create an area of memory to use for input, output, and intermediate arrays.
  // The size of this will depend on the model you're using, and may need to be
  // determined by experimentation.
  const int tensor_arena_size = 10 * 1024;
  uint8_t tensor_arena[tensor_arena_size];
  tflite::SimpleTensorAllocator tensor_allocator(tensor_arena,
                                                 tensor_arena_size);
```

如果使用相同的方法，则需要将栈大小设置为与该 arena 大小几乎相同，并为运行时使用的杂项变量额外增加几千字节。如果将 arena 保存在其他位置，例如作为全局变量，则所需的栈容量可能只有几千字节即可。所需的内存精确量因架构、编译器和正在运行的模型而异，因此不幸的是很难提前给出准确的值。如果出现神秘的崩溃，值得尝试尽可能增加该值，看看是否有帮助。

如果仍然存在问题，则应首先开始确定被覆盖的变量或内存区域。幸运的是，可以使用前面描述的日志记录或代码消除方法，将问题缩小到读取被认为已损坏的值。确定哪些变量或数组条目已损坏后，可以编写 `TRACE` 宏的变体，以输出该内存位置的值以及调用的文件和行号。可能需要一些专门化，例如将该内存地址存储在全局变量中，以便从更深的栈帧访问本地变量。这样，就像追踪常规崩溃一样，可以在程序运行时跟踪该位置的内容，确定是哪段代码覆盖了该位置。

# 总结

即使在训练环境中运行良好，在实际设备上失败时想出解决方案可能是一个漫长而令人沮丧的过程。本章介绍了当你陷入困境、原地打转时可以尝试的一套工具。不幸的是，调试几乎没有捷径，但我相信使用这些方法来解决问题，你就能查明嵌入式机器学习的问题。

当某个产品中的一个模型开始工作时，你会开始思考如何对其进行改编，或者为不同的问题创建全新的模型。[第19章](#ch19.html#ch19)将介绍如何将你自己的模型从 TensorFlow 训练环境迁移到 TensorFlow Lite 推理引擎。

# 第19章. 将模型从 TensorFlow 移植到 TensorFlow Lite。

本作品使用 AI 翻译。欢迎提供意见和反馈：[translation-feedback@oreilly.com](mailto:translation-feedback@oreilly.com)

到目前为止，你应该理解我们尽可能在新任务中重用现有模型的观点。从零开始训练全新的模型需要大量时间和实验，即使是专家也经常无法在事先预测最佳方法，因此需要尝试许多不同的原型。因此，本书的范围不包括创建新架构的完整指南，建议参考[第21章](#ch21.html#ch21)以获取进一步阅读。然而，资源受限的设备上机器学习也有其特有的方面，例如在受限算子上工作和预处理需求，因此本章将提供相关建议。

## 理解需要采取什么策略

本书由于作者隶属于 Google 团队，因此重点关注用 TensorFlow 创建的模型，但在单一框架内也有多种创建模型的方法。查看[语音命令学习脚本](https://oreil.ly/ZTYu7)可知，它直接使用 TensorFlow 的核心操作作为构建块来构建模型，并手动运行训练循环。该脚本最初写于 2017 年。在使用 TensorFlow 2.0 的最新示例中，似乎使用 Keras 作为高级 API 来处理许多细节。

其缺点是，模型使用的底层算子在仅查看代码时变得不可见。相反，它们作为层的一部分创建，每次调用即可表示大块的图。了解模型使用哪些 TensorFlow 算子对于理解模型是否能在 TensorFlow Lite 上运行以及资源需求如何至关重要非常关键。幸运的是，只要能获取到 `Session` 对象，就能从 Keras 中访问底层低级算子。[`tf.keras.backend.get_session()`](https://oreil.ly/4zurk).如果直接用 TensorFlow 编码，session 很可能已存储在变量中，因此以下代码也应该有效：

```
for op in sess.graph.get_operations():
  print(op.type)
```

如果将 session 赋给名为 `sess` 的变量，则会输出模型中所有操作的<|message|> 类型。此外，还可以访问诸如 `name` 之类的其他属性以获取更多信息。了解存在哪些 TensorFlow 算子将在 TensorFlow Lite 转换过程中大有帮助。否则，显示的错误将更难以理解。

## 查看 TensorFlow Lite 中现有 Op 的覆盖范围

TensorFlow Lite 仅支持 TensorFlow 算子的子集，并且存在一些限制。最新列表可在[操作兼容性指南](https://oreil.ly/Pix9U)中查看。这意味着在规划新模型时，首先需要确认它不依赖于不受支持的功能或运算。特别是，`LSTM`、`GRU` 以及其他循环神经网络目前仍不可用。此外，TensorFlow Lite 的完整移动版本与微控制器分支之间也存在差距。了解当前 TensorFlow Lite for Microcontrollers 支持哪些算子的最简单方法是查看[ `all_ops_resolver.cc`](https://oreil.ly/HNpmM)。

将训练会话中显示的运算与 TensorFlow Lite 支持的运算进行比较可能会有些令人困惑。例如，将作为变量存储的权重转换为常量，或将浮点运算优化为整数运算进行量化。此外，像反向传播这样仅在训练循环的一部分中存在的运算也会被完全移除。了解会发生什么问题的最佳方法是，在创建候选模型后立即在训练前尝试导出它，以便在花费大量时间进行训练过程之前调整其结构。

## 将预处理和后处理移至应用程序代码

深度学习模型通常有三个阶段。从磁盘加载图像和标签并解码 JPEG 等简单操作，到将语音数据转换为频谱图等复杂操作。接下来是核心神经网络，接收值数组并以类似格式输出结果。最后，后处理步骤需要理解这些值的含义。许多分类问题只是将向量中的分数与对应标签匹配，但查看[ `MobileSSD`](https://oreil.ly/QT_dS)等模型时，网络的输出是重叠边界框的集合，要使其有用，需要经过称为“非极大值抑制”的复杂过程。

核心神经网络模型通常计算量最大，由卷积和激活等相对较少的算子组成。预处理阶段和后处理阶段尽管计算负载相当低，但通常需要更多包含控制流的算子。这意味着将其烘焙到 TensorFlow Lite 模型中不如作为普通代码在应用程序中实现更合理。例如，机器视觉模型的神经网络部分接收特定尺寸的图像，例如高 224 像素 × 宽 224 像素。在训练环境中，使用 `DecodeJpeg` 算子后，使用 `ResizeImages` 算子将结果转换为正确尺寸。但是在设备上运行时，几乎肯定会从不需要解压缩的固定尺寸源获取输入图像，因此编写自定义代码来创建神经网络输入比依赖库的通用算子更合理。此外，可能需要处理异步捕获，因此将工作线程化可能会带来好处。对于语音命令，进行了大量工作来缓存 FFT 的中间结果，以便在流式输入运行时尽可能重用计算。

并非所有模型在训练环境中都有重要的后处理阶段，但在设备上运行时，通常希望利用随时间推移的一致性来改善向用户显示的结果。尽管模型只是分类器，但唤醒词检测代码每秒运行多次，并[使用平均化](https://oreil.ly/E68Q4)提高结果的准确性。这类代码也很难作为 TensorFlow Lite 算子表示，且优势不多，因此最好在应用程序级别实现。如查看[ `detection_postprocess.cc`](https://oreil.ly/IMlsT)所示，这是可能的，但将其表示为 TensorFlow 的小型操作在设备上实现并不高效，因此在导出过程中需要从底层 TensorFlow 图中进行布线。

所有这些都意味着需要尝试排除图的非核心部分，并确定哪些部分是哪些部分。我们发现[ `Netron`](https://oreil.ly/qoQNY)是探索 TensorFlow Lite 图、了解其中存在哪些处理以及它们是神经网络核心的一部分还是仅仅是处理步骤的合适工具。了解内部发生的情况后，应该能够分离核心网络，仅导出这些操作，并将剩余部分作为应用程序代码实现。

## 根据需要实现所需的操作

如果发现有绝对需要的 TensorFlow 算子而 TensorFlow Lite 不支持，可以将其作为*自定义*算子保存到 TensorFlow Lite 文件格式中，并在框架内自行实现。完整流程超出本书范围，但以下是主要步骤：

* 启用 `allow_custom_ops` 并运行 `toco`，使不受支持的算子作为自定义算子序列化到模型文件中。
* 编写实现该算子的内核，并在应用程序使用的 op 解析器中调用 `AddCustom()` 。
* 在 `Init()` 方法被调用时，解包以 `FlexBuffer` 格式存储的参数。

## 优化操作

即使使用受支持的算子构建新模型，也可能以未优化的方式使用它们。TensorFlow Lite 团队的优先级由特定用例决定，因此在运行新模型时可能会遇到尚未优化的代码路径。这一点在[第15](#ch15.html#optimizing_latency)章中有所涉及，正如建议在训练模型之前尽早检查导出兼容性一样，在规划开发计划之前，确认能否获得所需性能也很有价值。

## 总结

为成功完成任务而训练新的神经网络已经很困难，而找到能产生良好结果并在嵌入式硬件上高效运行的网络则更困难！本章介绍了你可能面临的一些挑战，并提出了克服它们的方法，但该领域是快速增长的研究领域，因此建议查看[第21章](#ch21.html#ch21)的一些资源，看看是否有为你的模型架构提供新灵感的来源。特别是，追踪 arXiv 上的最新研究论文是非常有帮助的领域。

克服所有这些挑战后，你应该拥有一个小型、快速、电力效率高的产品，准备好部署到现实世界。[第20章](#ch20.html#ch20)将讨论隐私和安全问题。

完成本书前几章的工作后，你应该能够构建依赖机器学习的嵌入式应用程序。然而，要将你的项目成功部署为产品，仍需克服许多挑战。其中一个重要挑战是保护用户的隐私和安全。本章将介绍我们在克服这些挑战时发现的一些有用方法。

## 隐私

设备上的机器学习依赖于传感器输入。这些传感器中有些，如麦克风和摄像头，[明显涉及隐私](https://oreil.ly/CEcsR)，有些如加速度传感器则可能被滥用。我们作为工程师都有责任保护用户免受产品可能造成的伤害，因此在设计每个阶段都必须考虑隐私。此外，处理敏感用户数据也有法律含义，这超出了我们的报道范围，应咨询律师。如果你隶属于大型组织，可能有隐私专家，或有流程能以专业知识帮助你。即使无法使用此类资源，也应在项目开始时花时间进行自己的隐私审查，并在启动前定期复查。关于“隐私审查”实际是什么，并没有广泛共识，但我们将讨论一些最佳实践。

### 隐私设计文档

[隐私工程](https://oreil.ly/MEwUE)领域仍非常新颖，很难找到关于如何处理产品隐私影响的文档。许多大型企业处理应用程序隐私保证的方式是创建隐私设计文档。这是一个可以涵盖产品重要隐私方面的单一位置。文档应包含本节后续子部分提出的所有主题的信息。

### 数据收集
