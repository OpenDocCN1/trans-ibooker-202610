
# トレーニング設定

- チェックポイントと要約は、引数で与えられたフォルダに保存される。`--train_dir`引数で与えられたフォルダに保存される。ここで結果を探す必要がある。
- `--dataset_dir` パラメータは、Visual Wake Words のビルドスクリプトから TFRecords を保存した場所と一致する必要がある。
- 使用するアーキテクチャは引数で定義される。`--model_name`引数で定義される。`mobilenet_v1` というプレフィックスは、MobileNetの最初のバージョンを使うようにスクリプトに指示する。それ以降のバージョンも試してみたが、中間活性化バッファにより多くのRAMを使用したため、今のところオリジナルにこだわっている。`025` は使用する深度乗数で、主に重みパラメータの数に影響する。この低い設定により、モデルは250KBのフラッシュメモリにセットされる。
- `--preprocessing_name` は、入力画像がモデルに入力される前にどのように修正されるかを制御する。 バージョンでは、画像の幅と高さを で指定されたサイズに縮小する（計算量を減らしたいので、ここでは96ピクセル）。また、ピクセル値を0～255の整数から`mobilenet_v1` `--train_image_size` \-1.0～+1.0の浮動小数点数にスケーリングする（ただし、pass:\[training\]の後で量子化する）。
- SparkFun Edgeボードで使用している[HM01B0カメラは](https://oreil.ly/RGciN)モノクロなので、最良の結果を得るためには、モノクロ画像でモデルをトレーニングする必要がある。その前処理を有効にするために、`--use_grayscale` フラグを渡す。
- `--learning_rate`、`--label_smoothing`、`--learning_rate_decay_factor`、`--num_epochs_per_decay`、`--moving_average_decay`、`--batch_size` のパラメータはすべて、学習プロセス中に重みがどのように更新されるかを制御する。ディープ・ネットワークのトレーニングはまだちょっとしたダークアートなので、これらの正確な値は、この特定のモデルについて実験を通して発見したものだ。これらのパラメータを微調整することで、学習をスピードアップさせたり、精度を少し上げたりすることができるが、どのように変更すればいいのかあまり参考にならないし、学習精度が収束しないような組み合わせになりやすい。
- `--max_number_of_steps` はトレーニングをいつまで続けるかを定義する。このしきい値を事前に設定する良い方法はない。モデルの精度がいつ上がらなくなるかを実験して判断し、いつ学習を打ち切るべきかを知る必要がある。私たちの場合、デフォルトを100万ステップとしている。なぜなら、この特定のモデルの場合、それが停止する良い点だとわかっているからだ。

スクリプトを開始すると、次のような出力が表示されるはずだ：

```
INFO:tensorflow:global step 4670: loss = 0.7112 (0.251 sec/step)
  I0928 00:16:21.774756 140518023943616 learning.py:507] global step 4670: loss
  = 0.7112 (0.251 sec/step)
INFO:tensorflow:global step 4680: loss = 0.6596 (0.227 sec/step)
  I0928 00:16:24.365901 140518023943616 learning.py:507] global step 4680: loss
  = 0.6596 (0.227 sec/step)
```

行の重複は気にしないでほしい。これは、TensorFlowのログ出力がPythonと相互作用する際の副作用に過ぎない。各行には、トレーニングプロセスに関する2つの重要な情報がある。グローバル・ステップは、トレーニングがどこまで進んでいるかのカウントだ。100万ステップと設定しているので、この場合、ほぼ5％が完了している。ステップ/秒の見積もりと合わせて、トレーニングプロセス全体のおおまかな期間を見積もるのに使えるので便利だ。この場合、1秒間に約4ステップを完了しているので、100万ステップには約70時間、つまり3日かかることになる。もうひとつの重要な情報は損失だ。これは、部分的に訓練されたモデルの予測値がどれだけ正しい値に近いかを示す指標で、値が小さいほど良い。これは多くのばらつきを示すが、モデルが学習中であれば平均してトレーニング中に減少するはずである。非常にノイズが多いため、短時間では数値が大きく変動するが、うまくいっている場合は、1時間ほど待ってからチェックすると、顕著な低下が見られるはずだ。TensorBoardを試す主な理由のひとつは、このような変動をグラフで見ることができることだ。

# テンソルボード

TensorBoardは、TensorFlowのトレーニング・セッションのデータを可視化できるウェブ・アプリケーションで、ほとんどのクラウド・インスタンスにデフォルトで含まれている。Google Cloud AI Platformを使用している場合、ノートブック・インターフェースの左のタブからコマンド・パレットを開き、下にスクロールして "Create a new tensorboard "を選択することで、新しいTensorBoardセッションを立ち上げることができる。すると、サマリーログの保存場所のプロンプトが表示される。トレーニングスクリプトで`--train_dir` に使用したパスを入力する。前の例では、フォルダ名は`vww_96_grayscale` である。よくあるエラーとして、パスの最後にスラッシュを追加すると、TensorBoardがディレクトリの発見に失敗する。

別の環境でコマンドラインからTensorBoardを起動する場合は、TensorBoardコマンドラインツールの引数`--logdir` 、ブラウザの[`http://localhost:6006`](http://localhost:6006)（または実行するマシンのアドレス）にこのパスを渡す必要がある。

TensorBoardのアドレスに移動するか、Google Cloud経由でセッションを開くと、[図10-12の](#ch10.html#tensorboard_graphs_10)ようなページが表示されるはずだ。スクリプトは5分ごとに要約を保存するだけなので、グラフに有用なものが表示されるには少し時間がかかるかもしれない。 [図10-12は](#ch10.html#tensorboard_graphs_10)、1日以上トレーニングした後の結果を示している。最も重要なグラフは `clone_loss` と呼ばれるもので、ロギング出力に表示されているのと同じ損失値の進行を示している。この例でわかるように、大きく変動しているが、全体的な傾向は時間とともに下降している。数時間のトレーニングでこのような推移が見られない場合は、モデルが良い解に収束していないことを示す良いサインであり、データセットかトレーニングパラメータのどちらかに問題がある可能性があるので、デバッグが必要かもしれない。

TensorBoardを開くと、デフォルトで`SCALARS`タブが表示されるが、トレーニング中に役立つ他のセクションは`IMAGES`である[（図10-13](#ch10.html#tensorboard_images)）。これは、歪みやその他の前処理を含む、モデルが現在学習中の画像のランダムな選択を表示する。この図では、画像が反転され、モデルに送られる前にグレースケールに変換されていることがわかる。この情報は損失グラフほど重要ではないが、データセットが期待通りのものであることを確認するのに役立つし、トレーニングが進むにつれてサンプルが更新されていくのを見るのは興味深い。

# モデルを評価する

損失関数は、モデルがどれだけうまくトレーニングできているかに相関するが、直接的に理解できるメトリックではない。私たちが本当に気にしているのは、モデルが何人を正しく検出できたかだが、これを計算させるには別のスクリプトを実行する必要がある。モデルが完全にトレーニングされるまで待つ必要はない。`--train_dir` フォルダーにあるチェックポイントの精度をチェックすることができる。これを行うには、以下のコマンドを実行する：

```
! python models/research/slim/eval_image_classifier.py \
    --alsologtostderr \
    --checkpoint_path=vww_96_grayscale/model.ckpt-698580 \
    --dataset_dir=data/visualwakewords \
    --dataset_name=visualwakewords \
    --dataset_split_name=val \
    --model_name=mobilenet_v1_025 \
    --preprocessing_name=mobilenet_v1 \
    --use_grayscale=True \
    --train_image_size=96
```

`--checkpoint_path` が有効なチェックポイント・データのセットを指していることを確認する必要がある。チェックポイントは3つのファイルに分かれて保存されているので、その値は共通の接頭辞でなければならない。例えば、`model.ckpt-5179.data-00000-of-00001`というチェックポイントファイルがある場合、接頭辞は`model.ckpt-5179`となる。スクリプトは次のような出力を生成する：

```
INFO:tensorflow:Evaluation [406/406]
I0929 22:52:59.936022 140225887045056 evaluation.py:167] Evaluation [406/406]
eval/Accuracy[0.717438412]eval/Recall_5[1]
```

ここで重要な数値は精度である。これは正しく分類された画像の割合を示しており、パーセンテージに変換すると、この場合は72％となる。例のスクリプトに従えば、完全に訓練されたモデルは、100万ステップ後に約84%の精度を達成し、約0.4の損失を示すと予想される。

# モデルをTensorFlow Liteにエクスポートする

モデルが満足のいく精度までトレーニングされたら、TensorFlowのトレーニング環境から、組み込みデバイスで実行できる形に結果を変換する必要がある。前の章で見てきたように、これは複雑なプロセスになる可能性があり、`tf.slim`も独自の皺寄せをいくつか加えている。

## GraphDef Protobufファイルにエクスポートする

Slimはスクリプトを実行するたびに`model_name` からアーキテクチャを生成するため、Slimの外部でモデルを使用するには、共通の形式で保存する必要がある。ここでは、SlimとTensorFlowの両方が理解できるGraphDef protobufシリアライゼーション形式を使用する：

```
! python models/research/slim/export_inference_graph.py \
    --alsologtostderr \
    --dataset_name=visualwakewords \
    --model_name=mobilenet_v1_025 \
    --image_size=96 \
    --use_grayscale=True \
    --output_file=vww_96_grayscale_graph.pb
```

これが成功すれば、ホーム・ディレクトリに新しい`vww_96_grayscale_graph.pb`ファイルができるはずである。このファイルにはモデル内の演算子のレイアウトが含まれているが、重みデータはまだ含まれていない。

## 重りを凍らせる

学習した重みを演算グラフとともに保存する処理は、フリーズと呼ばれる。これは、チェックポイントファイルから値をロードした後、グラフ内のすべての変数を定数に変換する。以下のコマンドでは、100万回目のトレーニングステップのチェックポイントを使用しているが、有効なチェックポイントパスを指定することができる。グラフ凍結スクリプトはTensorFlowのメインリポジトリに格納されているので、このコマンドを実行する前にGitHubからダウンロードしておく必要がある：

```
! git clone https://github.com/tensorflow/tensorflow
! python tensorflow/tensorflow/python/tools/freeze_graph.py \
    --input_graph=vww_96_grayscale_graph.pb \
    --input_checkpoint=vww_96_grayscale/model.ckpt-1000000 \
    --input_binary=true --output_graph=vww_96_grayscale_frozen.pb \
    --output_node_names=MobilenetV1/Predictions/Reshape_1
```

この後、`vww_96_grayscale_frozen.pb`というファイルが表示されるはずだ。

## 量子化とTensorFlow Liteへの変換

量子化はトリッキーで複雑な処理であり、まだ研究途上の分野であるため、これまで学習してきた浮動小数点グラフを8ビットエンティティに変換するには、かなりのコードを必要とする。量子化とは何か、そして量子化がどのように機能するかについては[第15章を](#ch15.html#optimizing_latency)発見してほしい。コードの大部分は、学習済みネットワークに投入するサンプル画像を準備することで、典型的な使用における活性化層の範囲を測定できるようにしている。推論エンジンに必要な量子化とTensorFlow Lite FlatBufferファイルへの変換は、`TFLiteConverter` クラスに頼っている：

```
import tensorflow as tf
import io
import PIL
import numpy as np

def representative_dataset_gen():

  record_iterator = tf.python_io.tf_record_iterator
      (path='data/visualwakewords/val.record-00000-of-00010')

  count = 0
  for string_record in record_iterator:
    example = tf.train.Example()
    example.ParseFromString(string_record)
    image_stream = io.BytesIO
        (example.features.feature['image/encoded'].bytes_list.value[0])
    image = PIL.Image.open(image_stream)
    image = image.resize((96, 96))
    image = image.convert('L')
    array = np.array(image)
    array = np.expand_dims(array, axis=2)
    array = np.expand_dims(array, axis=0)
    array = ((array / 127.5) - 1.0).astype(np.float32)
    yield([array])
    count += 1
    if count > 300:
        break

converter = tf.lite.TFLiteConverter.from_frozen_graph \
    ('vww_96_grayscale_frozen.pb', ['input'],  ['MobilenetV1/Predictions/ \
    Reshape_1'])
converter.inference_input_type = tf.lite.constants.INT8
converter.inference_output_type = tf.lite.constants.INT8
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = representative_dataset_gen

tflite_quant_model = converter.convert()
open("vww_96_grayscale_quantized.tflite", "wb").write(tflite_quant_model)
```

## Cソースファイルに変換する

コンバーターはファイルを書き出すが、ほとんどの組み込みデバイスはファイルシステムを持っていない。プログラムからシリアライゼーション・データにアクセスするには、それを実行ファイルにコンパイルし、フラッシュに格納しなければならない。そのための最も簡単な方法は、前の章で行ったように、ファイルをCのデータ配列に変換することである：
