## 自分で変更を加える

さて、基本的なアプリケーションをデプロイしたので、いろいろと遊んでみたり、変更してみたりしてみよう。アプリケーションのコードは`tensorFlow/lite/micro/examples/magic_wand`フォルダに発見できる。編集して保存し、前の手順を繰り返して、変更したコードをデバイスにデプロイする。

いくつか試してみてほしいことがある：

*   [`constants.cc`](https://oreil.ly/s5bdg)のしきい値を実験して、ジェスチャーをやりやすくしたり、やりにくくしたりする（その代償として、偽陽性や偽陰性が増える）。
*   身体的なジェスチャーを使ってタスクを実行できるようなプログラミングをコンピュータに書く。
*   検出結果をBluetoothで送信するようにプログラミングを拡張する。この方法は、[Ambiq SDKの](https://oreil.ly/Bci3a) `AmbiqSuite-Rel2.0.0/boards/apollo3_evb/examples/uart_ble_bridge`に例がある。マジックワンド・アプリケーションがビルドされると、SDKは、`TensorFlow/tensorFlow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0`にダウンロードされる。

# 第12章. 魔法の杖モデルをトレーニングする

この作品はAIを使って翻訳されている。ご意見、ご感想をお待ちしている：[translation-feedback@oreilly.com](mailto:translation-feedback@oreilly.com)

[第11章](#ch11.html#chapter_magic_wand_application)では、加速度センサーの生データを解釈するために20KBの事前学習済みモデルを使い、それを使って一連のジェスチャーのどれが行われたかを識別した。この章では、このモデルがどのように訓練されたかを紹介し、次に実際にどのように機能するかについて説明する。

ウェイクワードと人物検出モデルは、どちらも学習に大量のデータを必要とした。これは、解決しようとする問題が複雑であったためである。人の「はい」「いいえ」の言い方には膨大なバリエーションがあり、アクセント、イントネーション、ピッチなど、人の声をユニークなものにしているあらゆるバリエーションを思い浮かべてほしい。同じように、画像に写る人の姿も無限である。顔や全身、あるいは片手かもしれないし、どんなポーズで立っているかもしれない。

このように多様な入力検証を正確に分類するためには、モデルも同様に多様な訓練データセットで訓練する必要がある。これが、ウェイクワードと人物検出のトレーニングのデータセットが大規模であり、トレーニングに時間がかかる理由である。

魔法の杖のジェスチャー認識問題は、もっと単純だ。この場合、膨大な種類の自然な声や人間の外見やポーズを分類しようとするのではなく、3つの特定の意図的に選ばれたジェスチャーの違いを理解しようとしている。それぞれのジェスチャーのやり方には人によって多少の違いがあるだろうが、ユーザができるだけ正確で均一なジェスチャーを行うよう努力してくれることを期待している。

つまり、予想される検証入力のばらつきが少なくなるため、膨大なデータを必要とせず、正確なモデルを訓練するのが非常に簡単になる。実際、モデルのトレーニングに使用するデータセットには、各ジェスチャーの例が150ほどしか含まれておらず、サイズも1.5MBしかない。十分なデータを得ることは、機械学習プロジェクトで最も困難な部分であることが多いからだ。

この章の最初のパートでは、魔法の杖のアプリケーションで使われているオリジナルのモデルをトレーニングする方法を学ぶ。第2部では、このモデルが実際にどのように機能するかについて説明する。そして最後に、あなた自身のデータをキャプチャして、異なるジェスチャーを認識する新しいモデルをトレーニングする方法を見る。

### データを準備する

次に、"Prepare the data "セクションで、セルを実行してデータセットをダウンロードし、トレーニングセット、検証セット、テストセットに分割する。

最初のセルはデータセットをダウンロードし、学習スクリプトのディレクトリに抽出する。データセットは4つのディレクトリから構成され、各ジェスチャー（「ウィング」、 「リング」、「スロープ」）に1つずつ、そして明確なジェスチャーがないデータ用の 「ネガティブ」ディレクトリがある。各ディレクトリには、ジェスチャーのキャプチャプロセスの結果得られた生データを表すファイルが含まれる：

```
data/
├── slope
│   ├── output_slope_dengyl.txt
│   ├── output_slope_hyw.txt
│   └── ...
├── ring
│   ├── output_ring_dengyl.txt
│   ├── output_ring_hyw.txt
│   └── ...
├── negative
│   ├── output_negative_1.txt
│   └── ...
└── wing
    ├── output_wing_dengyl.txt
    ├── output_wing_hyw.txt
    └── ...
```

各ジェスチャーには10個のファイルがあり、後ほど説明する。各ファイルには、名前付けされた個人によって実演されたジェスチャーが含まれており、ファイル名の最後の部分がユーザIDに対応している。たとえば、`output_slope_dengyl.txt`というファイルには、`dengyl` というIDのユーザが実演した「スロープ」ジェスチャーのデータが含まれている。

各ファイルには、1行につき1つの加速度センサーの読み取り値で、あるジェスチャーの約15の個別パフォーマンスがあり、各パフォーマンスの先頭には行`-,-,-` が付けられている：

```
 -,-,-
-766.0,132.0,709.0
-751.0,249.0,659.0
-714.0,314.0,630.0
-709.0,244.0,623.0
-707.0,230.0,659.0
```

各パフォーマンスは、1秒間に25行、最大数秒分のデータのログで構成される。ジェスチャー自体はそのウィンドウ内のある点で行われ、残りの時間はデバイスが静止している。

測定値の取得方法により、ファイルにはゴミ文字も含まれている。最初のトレーニングスクリプトである[`data_prepare.py`](https://oreil.ly/SCZe9)は2番目のトレーニングセルで実行され、この汚いデータをクリーンアップする：

```
# Prepare the data
!python data_prepare.py
```

このスクリプトは、未加工のデータファイルをフォルダから読み取り、文字化けを無視し、サニタイズされた形でトレーニングスクリプトのディレクトリ`data/complete_data`内の別の場所に書き込むように設計されている。大規模データセットにエラーや破損、その他の問題が入り込むことはよくあることである。
