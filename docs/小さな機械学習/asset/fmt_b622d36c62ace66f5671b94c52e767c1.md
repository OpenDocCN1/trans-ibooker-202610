
`tiny_conv.cc`の一番下に`_content_tiny_conv_tflite_len`、配列の長さを表す変数が発見された。`tiny_conv_micro_features_model_data.cc`に戻って、`g_tiny_conv_micro_features_model_data_len`の値をこの変数の値に置き換える。これでファイルの更新は完了だ。

## ラベルを更新する

次に、`micro_features/micro_model_settings.cc`を開く。このファイルにはクラス・ラベルの配列が含まれている：

```
const char* kCategoryLabels[kCategoryCount] = {
    "silence",
    "unknown",
    "yes",
    "no",
};
```

新しいモデル用にこれを調整するには、"yes "と "no "を "on "と "off "に入れ替えればいい。ラベルとモデルの出力テンソル要素を順番にマッチさせるので、トレーニングスクリプトに提供されたのと同じ順番でリストすることが重要だ。

これが期待されるコードだ：

```
const char* kCategoryLabels[kCategoryCount] = {
    "silence",
    "unknown",
    "on",
    "off",
};
```

つ以上のラベルでモデルをトレーニングした場合は、それらをすべてリストに追加すればいい。

これでモデルの切り替えは終わった。残るステップは、ラベルを使用する出力コードを更新することだけだ。

## command_responder.ccを更新する

このプロジェクトには、Arduino、SparkFun Edge、STM32F746G用の`command_responder.cc`の異なるデバイス固有の実装が含まれている。以下のセクションで、それぞれをアップデートする方法を説明する。

### Arduino

`arduino/command_responder.cc`にあるArduinoコマンド・レスポンダは、"yes "という言葉を聞くとLEDを3秒間点灯させる。"on "か "off "のどちらかを聞いたときにLEDを点灯するように更新してみよう。ファイルin文で、以下の`if`：

```
// If we heard a "yes", switch on an LED and store the time.
if (found_command[0] == 'y') {
  last_yes_time = current_time;
  digitalWrite(LED_BUILTIN, HIGH);
}
```

`if`文は、コマンドの最初の文字が "y "であるかどうかをテストする。この "y "を "o "に変えると、どちらも "o "で始まるため、LEDは "on "か "off "のどちらかで点灯する：

```
if (found_command[0] == 'o') {
  last_yes_time = current_time;
  digitalWrite(LED_BUILTIN, HIGH);
}
```

コードを変更したら、デプロイして試してみよう。

### スパークファン・エッジ

`sparkfun_edge/command_responder.cc`にあるSparkFun Edgeコマンドレスポンダは、"yes "か "no "かによって異なるLEDを点灯させる。このファイルの中で、以下の`if`：

```
if (found_command[0] == 'y') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
}
if (found_command[0] == 'n') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
}
if (found_command[0] == 'u') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_GREEN);
}
```

オン」と「オフ」がそれぞれ異なるLEDを点灯するように、これらを更新するのは簡単だ：

```
if (found_command[0] == 'o' && found_command[1] == 'n') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
}
if (found_command[0] == 'o' && found_command[1] == 'f') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_RED);
}
if (found_command[0] == 'u') {
  am_hal_gpio_output_set(AM_BSP_GPIO_LED_GREEN);
}
```

どちらのコマンドも同じ文字で始まるため、2番目の文字を見て区別する必要がある。さて、"on "と話しかけると黄色のLEDが点灯し、"off "と話しかけると赤が点灯する。

変更が終わったら、[「例の実行](#ch07.html#micro_speech_sparkfun_edge_running_the_example)」で行ったのと同じ手順でコードをデプロイして実行する。

### STM32F746G

`disco_f746ng/command_responder.cc`にある STM32F746G コマンド・レスポンダは、どのコマンドを聞いたかによって異なる単語を表示する。ファイル in 文で、以下の`if`を見つける：

```
if (*found_command == 'y') {
  lcd.Clear(0xFF0F9D58);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard yes!", CENTER_MODE);
} else if (*found_command == 'n') {
  lcd.Clear(0xFFDB4437);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard no :(", CENTER_MODE);
} else if (*found_command == 'u') {
  lcd.Clear(0xFFF4B400);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard unknown", CENTER_MODE);
} else {
  lcd.Clear(0xFF4285F4);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard silence", CENTER_MODE);
}
```

代わりに「オン」と「オフ」に反応するように更新するのは簡単だ：

```
if (found_command[0] == 'o' && found_command[1] == 'n') {
  lcd.Clear(0xFF0F9D58);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard on!", CENTER_MODE);
} else if (found_command[0] == 'o' && found_command[1] == 'f') {
  lcd.Clear(0xFFDB4437);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard off", CENTER_MODE);
} else if (*found_command == 'u') {
  lcd.Clear(0xFFF4B400);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard unknown", CENTER_MODE);
} else {
  lcd.Clear(0xFF4285F4);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard silence", CENTER_MODE);
}
```

ここでも、両コマンドは同じ文字で始まるので、曖昧さをなくすために2番目の文字を見ている。次に、それぞれのコマンドに適切なテキストを表示する。

## スクリプトを実行する他の方法

Colabを使用できない場合、モデルをトレーニングするために推奨される他の方法が2つある：

*   GPUを搭載したクラウド仮想マシン（VM）では、次のようになる。
*   ローカル・ワークステーション

GPUを使ったトレーニングに必要なドライバーはLinuxでしか使えない。Linuxなしでは、トレーニングに4時間ほどかかる。このため、GPUを搭載した仮想マシン（）か、同様の機能を備えたLinuxワークステーションを使用することが推奨される。

仮想マシンやワークステーションのセットアップは本書の範囲を超えている。しかし、いくつかの推奨事項はある。仮想マシンを使用している場合、[Google Cloud Deep Learning VM Imageを](https://oreil.ly/PVRtP)起動することができ、GPUトレーニングに必要なすべての依存関係が事前に設定されている。Linuxワークステーションを使用している場合は、[TensorFlow GPU Dockerイメージに](https://oreil.ly/PFYVr)必要なものがすべて揃っている。

モデルをトレーニングするには、TensorFlowのナイトリービルドをインストールする必要がある。既存のバージョンをアンインストールし、動作が確認されているものに置き換えるには、以下のコマンドを使用する：

```
pip uninstall -y tensorflow tensorflow_estimator
pip install -q tf-estimator-nightly==1.14.0.dev2019072901 \
  tf-nightly-gpu==1.15.0.dev20190729
```

次に、コマンドラインを開き、コードを保存するディレクトリに移動する。以下のコマンドを使ってTensorFlowをクローンし、動作が確認されている特定のコミットを開く：

```
git clone -q https://github.com/tensorflow/tensorflow
git -c advice.detachedHead=false -C tensorflow checkout 17ce384df70
```

これで`train.py`スクリプトを実行してモデルを学習させることができる。これは "yes "と "no "を認識するモデルを訓練し、チェックポイントファイルを`/tmp`に出力する：

```
python tensorflow/tensorflow/examples/speech_commands/train.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --wanted_words="on,off" --silence_percentage=25 --unknown_percentage=25 \
  --quantize=1 --verbosity=INFO --how_many_training_steps="15000,3000" \
  --learning_rate="0.001,0.0001" --summaries_dir=/tmp/retrain_logs \
  --data_dir=/tmp/speech_dataset --train_dir=/tmp/speech_commands_train
```

トレーニング後、以下のスクリプトを実行してモデルをフリーズさせる：

```
python tensorflow/tensorflow/examples/speech_commands/freeze.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --wanted_words="on,off" --quantize=1 --output_file=/tmp/tiny_conv.pb \
  --start_checkpoint=/tmp/speech_commands_train/tiny_conv.ckpt-18000
```

次に、モデルをTensorFlow Lite形式に変換する：

```
toco
  --graph_def_file=/tmp/tiny_conv.pb --output_file=/tmp/tiny_conv.tflite \
  --input_shapes=1,49,40,1 --input_arrays=Reshape_2 \
  --output_arrays='labels_softmax' \
  --inference_type=QUANTIZED_UINT8 --mean_values=0 --std_dev_values=9.8077
```

最後に、このファイルを組み込みシステムにコンパイルできるCソースファイルに変換する：

```
xxd -i /tmp/tiny_conv.tflite > /tmp/tiny_conv_micro_features_model_data.cc
```

## モデルの仕組み

さて、自分のモデルをトレーニングする方法がわかったところで、それがどのように機能するのかを探ってみよう。これまでのところ、我々は機械学習モデルをブラックボックスとして扱ってきた。つまり、学習データを送り込むと、最終的に結果を予測する方法を見つけ出すものだ。モデルを使うのに、その内部で何が起こっているかを理解することは必須ではないが、問題のデバッグに役立つこともあるし、それ自体が興味深い。このセクションでは、モデルがどのようにして予測を導き出すかについて、いくつかの洞察を提供する。

### インプットを視覚化する

[図8-17は](#ch08.html#tensorboard_spectrogram_2)、、実際にニューラルネットワークに何が入力されているかを示している。これはシングルチャンネルの2D配列なので、モノクロ画像として視覚化できる。私たちは16KHzのオーディオサンプルデータを扱っている。このプロセスは、機械学習で「特徴生成」と呼ばれるものの一例であり、その目的は、扱うのが難しい入力形式（この場合、1秒間のオーディオを表す16,000個の数値）を、機械学習モデルが理解しやすいものに変えることだ。ディープラーニングのマシン構想のユースケースを研究したことがある人なら、このようなケースに遭遇したことはないかもしれない。なぜなら、画像は通常、それほど前処理をしなくてもネットワークが比較的簡単に入力として取り込めるからだ。

![](assets/timl_0810.png)

なぜ我々のモデルが前処理された入力を扱う方が簡単なのかを直感的に理解するために、図[8-18から](#ch08.html#audio_waveform_yes)図[8-21に](#ch08.html#audio_waveform_no_1)示すように、いくつかの音声録音の元の生の表現を見てみよう。

![](assets/timl_0818.png)![](assets/timl_0819.png)![](assets/timl_0820.png)![](assets/timl_0821.png)

ラベルがなければ、どのペアの波形が同じ単語を表しているのか区別がつかないだろう。図[8-22から](#ch08.html#features_yes_0)図[8-25は](#ch08.html#features_no_1)、同じ1秒間の録音を特徴生成にかけた結果を示している。

![](assets/timl_0822.png)![](assets/timl_0823.png)![](assets/timl_0824.png)![](assets/timl_0825.png)

これらはまだ解釈するのが簡単ではないが、「YES」のスペクトログラムはどちらもL字を反転させたような形をしており、「NO」の特徴は異なる形をしていることがわかるだろう。私たちは、生の波形よりもスペクトログラムの違いをより簡単に見分けることができるし、モデルにとっても同じことがより簡単にできることを直感的に理解してほしい。

もう一つの側面は、生成されるスペクトログラムがサンプルデータよりもずっと小さいことだ。各スペクトログラムは1,960個の数値で構成されるが、波形は16,000個である。スペクトログラムはオーディオデータの要約であり、ニューラルネットワークの作業量を減らすことができる。実際、[DeepMindのWaveNetの](https://oreil.ly/IH9J3)ように特別に設計されたモデルが、生のサンプルデータを代わりに入力として受け取ることは可能だが、結果として得られるモデルは、我々が使っているような手作業で設計された特徴量を与えたニューラルネットワークの組み合わせよりも多くのコンピューティングを伴う傾向があるため、組み込みシステムのようなリソースに制約のある環境では、ここで使われているアプローチを好む。

### フィーチャー・ジェネレーションはどのように機能するのか？
