### Colabを運営し続ける

放置されたプロジェクトがリソースを消費するのを防ぐため、Colabはランタイムがアクティブに使用されていない場合、それをシャットダウンする。トレーニングには時間がかかるので、これを防ぐ必要がある。いくつか考えなければならないことがある。

まず、Colabブラウザ・タブとアクティブに対話していない場合、Webユーザ・インタフェースはトレーニング・スクリプトが実行されているバックエンド・ランタイムから切断される。これは数分後に起こり、TensorBoardのグラフが最新のトレーニングメトリックで更新されなくなる。トレーニングはバックグラウンドで実行されている。

ランタイムが切断された場合、[図8-](#ch08.html#colab_reconnect_button)14に示すようにColabのユーザインタフェースに再接続ボタンが表示される。このボタンをクリックしてランタイムを再接続する。

![](assets/timl_0814.png)

ランタイムの切断は大した問題ではないが、Colabの次のタイムアウトには注意が必要だ。*連続90分間Colabと対話しないと、ランタイムインスタンスはリサイクルされる*。これは問題だ。インスタンスに保存されたデータとともに、トレーニングの進捗がすべて失われてしまう！

これを避けるためには、少なくとも90分に1回はColabと対話する必要がある。タブを開き、ランタイムが接続されていることを確認し、美しいグラフを見てみよう。90分経過する前にこの操作をする限り、接続はオープンなままだ。

#### 警告

Colabのタブが閉じられても、ランタイムはバックグラウンドで最大90分間動き続ける。ブラウザで元のURLを開きさえすれば、ランタイムに再接続し、以前と同じように続けることができる。

ただし、タブを閉じるとTensorBoardは消えてしまう。タブを再び開いたときにトレーニングがまだ実行されている場合、トレーニングが終了するまでTensorBoardを再び表示することはできない。

最後に、*Colabのランタイムの最大寿命は12時間である*。トレーニングが完了する前にColabはインスタンスをシャットダウンし、リセットしてしまう。トレーニングがこれほど長くなりそうな場合は、Colabを避け、[「スクリプトを実行する他の方法](#ch08.html#micro_speech_other_ways_to_run_training)」で説明する代替ソリューションのいずれかを使用する必要がある[。](#ch08.html#micro_speech_other_ways_to_run_training)幸いなことに、航跡語モデルのトレーニングにはそれほど長い時間はかからない。

グラフに18,000歩分のデータが表示されたら、トレーニングは完了だ！あとは、デプロイ用のモデルを準備するために、いくつかのコマンドを実行しなければならない。ご心配なく-この部分は*ずっと*短時間で終わる。

## グラフを凍結する

本書の前半で学んだように、トレーニングとは、モデルの重みとバイアスを、有用な予測が得られるまで繰り返し微調整するプロセスである。トレーニングスクリプトは、重みとバイアスを*チェックポイント*ファイルに書き込む。チェックポイントは100ステップに1回書き込まれる。つまり、トレーニングが途中で失敗しても、進捗を失うことなく最新のチェックポイントから再開することができる。

`train.py`スクリプトは引数`--train_dir` 、チェックポイントファイルの保存場所を指定して呼び出される。我々のColabでは、`/content/speech_commands_train`にセットされている。

チェックポイントファイルを見るには、Colabの左側パネルにあるファイルブラウザを開く。そのためには、[図8-15に](#ch08.html#colab_sidebar_button)示すボタンをクリックする。

![](assets/timl_0815.png)

このパネルでFilesタブをクリックし、ランタイムのファイルシステムを見る。`speech_commands_train/`ディレクトリを開くと、[図8-16の](#ch08.html#colab_files_checkpoints)ようにチェックポイントファイルが表示される。各ファイル名の数字はチェックポイントが保存されたステップを示す。

![](assets/timl_0816.png)

TensorFlowモデルは、主に2つのもので構成されている：

*   トレーニングの結果、重みとバイアスが生じる。

*   モデルの入力をこれらの重みとバイアスと組み合わせて、モデルの出力を生成する演算子のグラフ。

この時点で、モデルの演算子はPythonスクリプトで定義され、学習された重みとバイアスは最新のチェックポイントファイルにある。この2つを特定の形式を持つ1つのモデルファイルに統合し、推論を実行するために使用する必要がある。このモデルファイルを作成するプロセスを*フリーズと*呼び*、*重みを*フリーズした*グラフの静的表現を作成する。

モデルをフリーズさせるために、スクリプトを実行する。スクリプトは次のセルの「グラフのフリーズ」セクションで発見できる。スクリプトは次のように呼び出される：

```
!python tensorflow/tensorflow/examples/speech_commands/freeze.py \
  --model_architecture=tiny_conv --window_stride=20 --preprocess=micro \
  --wanted_words=${WANTED_WORDS} --quantize=1 \
  --output_file=/content/tiny_conv.pb \
  --start_checkpoint=/content/speech_commands_train/tiny_conv. \
  ckpt-${TOTAL_STEPS}
```

フリーズさせる正しい演算グラフをスクリプトに指示するために、トレーニングで使ったのと同じ引数をいくつか渡す。また、最終チェックポイントファイル（ファイル名の末尾がトレーニングステップ数の合計となるファイル）へのパスも渡す。

このセルを実行してグラフをフリーズさせる。フリーズしたグラフは`tiny_conv.pb`という名前のファイルに出力される。

このファイルは、完全に学習されたTensorFlowモデルである。TensorFlowで読み込んで推論を実行することができる。それは素晴らしいことだが、まだTensorFlow Liteではなく、通常のTensorFlowで使われる形式だ。次のステップは、モデルをTensorFlow Lite形式に変換することだ。

## TensorFlow Liteに変換する

変換も簡単なステップで、1つのコマンドを実行するだけだ。フリーズしたグラフ・ファイルができたので、TensorFlow Liteコンバーターのコマンドライン・インターフェイスである`toco` 。

モデルの変換」セクションで、最初のセルを実行する：

```
!toco
  --graph_def_file=/content/tiny_conv.pb --output_file= \
  /content/tiny_conv.tflite \
  --input_shapes=1,49,40,1 --input_arrays=Reshape_2
  --output_arrays='labels_softmax' \
  --inference_type=QUANTIZED_UINT8 --mean_values=0 --std_dev_values=9.8077
```

引数には、変換したいモデル、TensorFlow Liteモデル・ファイルの出力先、モデル・アーキテクチャに依存するその他の値を指定する。モデルはトレーニング中に量子化されたので、低精度値を実数にマッピングする方法をコンバーターに指示する引数（`inference_type`、`mean_values`、`std_dev_values` ）も提供する。

`input_shapes` 引数の width、height、channels パラメータの前に`1` が付いているのを不思議に思うかもしれない。これはバッチサイズである。トレーニングの効率化のために、多くの入力をまとめて送信するが、リアルタイムアプリケーションで実行する場合は、一度に1つのサンプルしか処理しない。そのため、バッチサイズは`1` に固定されている。

変換されたモデルは`tiny_conv.tflite`に書き込まれる。これでTensorFlow Liteモデルが完成だ！

このモデルがいかに小さいかを見るために、次のセルでコードを実行する：

```
import os
model_size = os.path.getsize("/content/tiny_conv.tflite")
print("Model is %d bytes" % model_size)
```

出力は、モデルが超小型であることを示している：`Model is 18208 bytes` 。

次のステップは、このモデルをマイクロコントローラーにデプロイできる形にすることだ。

## C配列を作成する

[`Cファイルへの変換`](#ch04.html#hello_world_training_convert_to_c_file)」では、`xxd` コマンドを使ってTensorFlow LiteモデルをC配列に変換した。次のセルでも同じことをしよう：

```
# Install xxd if it is not available
!apt-get -qq install xxd
# Save the file as a C source file
!xxd -i /content/tiny_conv.tflite > /content/tiny_conv.cc
# Print the source file
!cat /content/tiny_conv.cc
```

出力の最後には、ファイルの内容が出力される。C言語の配列とその長さを表す整数で、以下のようになる（表示される正確な値は多少異なるかもしれない）：

```
unsigned char _content_tiny_conv_tflite[] = {

  0x00, 0x00, 0x0e, 0x00, 0x18, 0x00, 0x04, 0x00, 0x08, 0x00, 0x0c, 0x00,

  0x00, 0x09, 0x06, 0x00, 0x08, 0x00, 0x07, 0x00, 0x06, 0x00, 0x00, 0x00,
```

このコードは`tiny_conv.cc`というファイルにも書かれており、Colabのファイルブラウザを使ってダウンロードできる。Colabランタイムの有効期限は12時間後なので、今すぐこのファイルをコンピュータにダウンロードすることをお勧めする。

# 我々のプロジェクトでモデルを使う

新しいモデルを使うには、3つのことをしなければならない：

1.  [`micro_features/tiny_conv_micro_features_model_data.cc`で](https://oreil.ly/EAR0U)、元のモデル・データを新しいモデルに置き換える。

2.  [`micro_features/micro_model_settings.cc`の](https://oreil.ly/bqw67)ラベル名を、新しい「on」と「off」のラベルで更新する。

3.  デバイス固有の`command_responder.cc`を更新し、新しいラベルに対して必要なアクションを取るようにする。

## モデルを交換する

モデルを置き換えるには、テキストエディタで`micro_features/tiny_conv_micro_features_model_data.cc`を開く。

#### 注

Arduinoサンプルで作業している場合、ファイルはArduino IDEのタブとして表示される。SparkFun Edgeで作業している場合は、TensorFlowリポジトリのローカルコピーでファイルを直接編集できる。 STM32F746Gで作業している場合は、Mbedプロジェクトディレクトリでファイルを編集する。

`tiny_conv_micro_features_model_data.cc`ファイルには、以下のような配列宣言がある：

```
const unsigned char
    g_tiny_conv_micro_features_model_data[] DATA_ALIGN_ATTRIBUTE = {
        0x18, 0x00, 0x00, 0x00, 0x54, 0x46, 0x4c, 0x33, 0x00, 0x00, 0x0e, 0x00,
        0x18, 0x00, 0x04, 0x00, 0x08, 0x00, 0x0c, 0x00, 0x10, 0x00, 0x14, 0x00,
        //...
        0x00, 0x09, 0x06, 0x00, 0x08, 0x00, 0x07, 0x00, 0x06, 0x00, 0x00, 0x00,
        0x00, 0x00, 0x00, 0x04};
const int g_tiny_conv_micro_features_model_data_len = 18208;
```

定数`g_tiny_conv_micro_features_model_data_len` の値が変更されていれば、配列の内容も置き換える必要がある。

そのためには、前のセクションの最後でダウンロードした`tiny_conv.cc`ファイルを開く。`tiny_conv_micro_features_model_data.cc`で定義されている配列に、その定義ではなく配列の内容をコピー＆ペーストする。配列の宣言ではなく、配列の内容を上書きしていることを確認する。
