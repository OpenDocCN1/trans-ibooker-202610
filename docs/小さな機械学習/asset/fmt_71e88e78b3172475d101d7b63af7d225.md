
```
// The colors we'll draw
const uint32_t background_color = 0xFFF4B400;  // Yellow
const uint32_t foreground_color = 0xFFDB4437;  // Red
// The size of the dot we'll draw
const int dot_radius = 10;
```

色は、`0xFFF4B400` のように16進値で提供される。`AARRGGBB` `AA` はアルファ値（または不透明度、`FF` は完全不透明）を表し、`RR` 、`GG` 、`BB` は赤、緑、青の量を表す。

### チップ

`0xFFF4B400` 。完全な不透明色で、赤が多く、緑がかなり多いため、きれいなオレンジがかった黄色になる。

Googleで検索して値を調べることもできる。

次に、アニメーションの形と大きさを定義するいくつかの変数を宣言する：

```
// Size of the drawable area
int width;
int height;
// Midpoint of the y axis
int midpoint;
// Pixels per unit of x_value
int x_increment;
```

変数の次に、`HandleOutput()` 関数を定義し、最初の実行時に何をするかを指示する：

```
// Animates a dot across the screen to represent the current x and y values
void HandleOutput(tflite::ErrorReporter* error_reporter, float x_value,
                  float y_value) {
  // Track whether the function has run at least once
  static bool is_initialized = false;

  // Do this only once
  if (!is_initialized) {
    // Set the background and foreground colors
    lcd.Clear(background_color);
    lcd.SetTextColor(foreground_color);
    // Calculate the drawable area to avoid drawing off the edges
    width = lcd.GetXSize() - (dot_radius * 2);
    height = lcd.GetYSize() - (dot_radius * 2);
    // Calculate the y axis midpoint
    midpoint = height / 2;
    // Calculate fractional pixels per unit of x_value
    x_increment = static_cast<float>(width) / kXrange;
    is_initialized = true;
  }
```

そこにはたくさんのことが書かれている！まず、`lcd` のメソッドを使って背景色と前景色をセットする。`lcd.SetTextColor()` という奇妙な名前のメソッドは、テキストだけでなく、描画するすべてのものの色をセットする：

```
// Set the background and foreground colors
lcd.Clear(background_color);
lcd.SetTextColor(foreground_color);
```

次に、円を描く位置を把握するために、実際に描ける範囲を計算する。これを間違えると、画面の端を越えて描画しようとし、予期せぬ結果を招くかもしれない：

```
width = lcd.GetXSize() - (dot_radius * 2);
height = lcd.GetYSize() - (dot_radius * 2);
```

その後、`y` の負の値が描画される画面の中央の位置を決定する。また、画面幅の何ピクセルが`x` の値の1単位に相当するかも計算する。浮動小数点数の結果を得るために、`static_cast` ：

```
// Calculate the y axis midpoint
midpoint = height / 2;
// Calculate fractional pixels per unit of x_value
x_increment = static_cast<float>(width) / kXrange;
```

前と同じように、`is_initialized` という名前の`static` 変数を使い、このブロックのコードが一度だけ実行されるようにする。

初期化が完了したら、出力を開始しよう。まず、以前の描画をクリアする：

```
// Clear the previous drawing
lcd.Clear(background_color);
```

次に、`x_value` 、ディスプレイのx軸のどこにドットを描くかを計算する：

```
// Calculate x position, ensuring the dot is not partially offscreen,
// which causes artifacts and crashes
int x_pos = dot_radius + static_cast<int>(x_value * x_increment);
```

次に`y` 。これは少し複雑で、`midpoint` の上に正の値を、下に負の値をプロットしたいからである：

```
// Calculate y position, ensuring the dot is not partially offscreen
int y_pos;
if (y_value >= 0) {
  // Since the display's y runs from the top down, invert y_value
  y_pos = dot_radius + static_cast<int>(midpoint * (1.f - y_value));
} else {
  // For any negative y_value, start drawing from the midpoint
  y_pos =
      dot_radius + midpoint + static_cast<int>(midpoint * (0.f - y_value));
}
```

ドットの位置が決まれば、あとはドットを描くだけだ：

```
// Draw the dot
lcd.FillCircle(x_pos, y_pos, dot_radius);
```

最後に、`ErrorReporter` を使って、`x` と`y` の値をシリアルポートに記録する：

```
// Log the current X and Y values
error_reporter->Report("x_value: %f, y_value: %f\n", x_value, y_value);
```

### 注

`ErrorReporter` 、STM32F746Gのシリアル・インタフェースを介してデータを出力することができる。これは、[`micro/debug_log.cc`に](https://oreil.ly/HpJ-t)あるオリジナルの実装を置き換えた、[`micro/disco_f746ng/debug_log.cc`という](https://oreil.ly/eL1ft)カスタム実装によるものである。

## 例題を実行する

次はプロジェクトをビルドしよう！STM32F746GはArmのMbed OSを搭載しているので、Mbedツールチェーンを使ってアプリケーションをデバイスにデプロイしよう。

### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は[`README.md`を](https://oreil.ly/WuhIz)チェックしてほしい。

始める前に、以下のものが必要だ：

* STM32F746Gディスカバリー・キット・ボード
* ミニUSBケーブル
* Arm Mbed CLI ([Mbedセットアップガイドに](https://oreil.ly/TkRwd)従う)
* Python 3と`pip`

Arduino IDEと同様に、Mbedはソースファイルをある方法で構造化する必要がある。TensorFlow Lite for Microcontrollers Makefileは、この方法を知っており、Mbedに適したディレクトリを生成してくれる。

そのためには、以下のコマンドを実行する：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  TARGET=mbed TAGS="CMSIS disco_f746ng" generate_hello_world_mbed_project
```

その結果、新しいディレクトリが作成される：

```
tensorflow/lite/micro/tools/make/gen/mbed_cortex-m4/prj/ \
  hello_world/mbed
```

このディレクトリには、Mbedがそれをビルドできるようにするための正しい方法で構造化された、サンプルのすべての依存関係が含まれている。

まず、そのディレクトリに移動し、そこでコマンドを実行できるようにする：

```
cd tensorflow/lite/micro/tools/make/gen/mbed_cortex-m4/prj/ \
  hello_world/mbed
```

次に、Mbedを使って依存関係をダウンロードし、プロジェクトをビルドする。

手始めに、以下のコマンドを使って、カレント・ディレクトリがMbedプロジェクトのルートであることをMbedに指定する：

```
mbed config root .
```

次に、Mbedに依存関係のダウンロードとビルドの準備を指示する：

```
mbed deploy
```

デフォルトでは、MbedはC++98を使ってプロジェクトをビルドする。しかし、TensorFlow LiteはC++11を必要とする。以下のPythonスニペットを実行し、C++11を使用するようにMbed構成ファイルを変更する。 コマンドラインに入力するか貼り付けるだけでよい：

```
python -c 'import fileinput, glob;
for filename in glob.glob("mbed-os/tools/profiles/*.json"):
  for line in fileinput.input(filename, inplace=True):
    print(line.replace("\"-std=gnu++98\"","\"-std=c++11\", \"-fpermissive\""))'
```

最後に、以下のコマンドを実行してコンパイルする：

```
mbed compile -m DISCO_F746NG -t GCC_ARM
```

この結果、以下のパスにバイナリができるはずである：

```
cp ./BUILD/DISCO_F746NG/GCC_ARM/mbed.bin
```

STM32F746GのようなMbed対応ボードを使う良い点の1つは、デプロイが本当に簡単なことだ。デプロイするには、STMボードに接続してファイルをコピーするだけだ。macOSでは、以下のコマンドでこれを行うことができる：

```
cp ./BUILD/DISCO_F746NG/GCC_ARM/mbed.bin /Volumes/DIS_F746NG/
```

あるいは、ファイルブラウザで`DIS_F746NG` ボリュームを発見し、ファイルをドラッグする。ファイルをコピーすると、フラッシュ処理が開始される。これが完了すると、デバイスの画面にアニメーションが表示されるはずだ。

このアニメーションに加え、プログラム実行中にデバッグ情報がボードに記録される。これを見るには、ボーレート9600でボードにシリアル接続を確立する。

macOSとLinuxでは、以下のコマンドを実行するとデバイスがリストされるはずだ：

```
ls /dev/tty*
```

以下のようになる：

```
/dev/tty.usbmodem1454203
```

デバイスを特定したら、以下のコマンドを使って接続する。`/dev/tty.devicename` を`/dev`に表示されているデバイス名に付け替える：

```
screen /<dev/tty.devicename> 9600
```

たくさんの出力が飛び交うのが見えるだろう。スクロールを止めるには、Ctrl-Aを押し、すぐにEscを押す。その後、矢印キーを使って出力を探索することができる。出力には、`x` のさまざまな値に対して推論を実行した結果が含まれている：

```
x_value: 1.1843798*2^2, y_value: -1.9542645*2^-1
```

`screen` でデバッグ出力の表示を止めるには、Ctrl-Aを押し、すぐにKキーを押し、次にYキーを押す。

# 第7章. ウェークワード検出：アプリケーションを作る

この作品はAIを使って翻訳されている。ご意見、ご感想をお待ちしている：[translation-feedback@oreilly.com](mailto:translation-feedback@oreilly.com)

TinyMLは新しい現象かもしれないが、その最も広範なアプリケーションは、おそらくすでにあなたの家や車の中、あるいはポケットの中で使われている。それが何かわかるだろうか？

ここ数年、デジタルアシスタントが台頭してきている。これらの製品は、画面やキーボードを使わずに情報に瞬時にアクセスできるように設計された音声ユーザインタフェース（UI）を提供する。Googleアシスタント、AppleのSiri、Amazon Alexaの間で、これらのデジタルアシスタントはほぼユビキタスになっている。フラッグシップモデルから新興市場向けに設計されたボイスファースト・デバイスまで、ほぼすべての携帯電話に何らかの種類が組み込まれている。また、スマートスピーカー、コンピューター、自動車にも搭載されている。

ほとんどの場合、音声認識、自然言語処理、ユーザのクエリに対するレスポンスの生成といった重労働は、大規模なMLモデルを実行する強力なサーバ上のクラウドで行われる。ユーザが質問をすると、音声のストリームとしてサーバに送られる。サーバはその意味を理解し、必要な情報を調べ、適切なレスポンスを返す。

しかし、アシスタントの魅力のひとつは、常にオンになっていて、あなたを助けてくれる準備ができていることだ。ヘイ、グーグル」や「アレクサ」と言えば、アシスタントを起動させ、ボタンを押すことなく必要なことを伝えることができる。つまり、あなたがリビングルームに座っていようが、高速道路を運転していようが、大自然の中でスマホを手にしていようが、24時間365日あなたの声を聞いていなければならないのだ。

サーバ上で音声認識を行うのは簡単だが、デバイスからデータセンターへ音声のストリームを送り続けるのは現実的ではない。プライバシーの観点から言えば、リモート・サーバに音声を1秒ごとに送信することは絶対的な災害となる。仮にそれがどうにか大丈夫だとしても、膨大な帯域幅を必要とし、モバイルデータプランを数時間で使い切ることになる。さらに、ネットワーク通信はエネルギーを消費するため、絶え間なくデータを送り続ければ、デバイスのバッテリーはあっという間に消耗してしまう。さらに、すべてのリクエストがサーバを往復するため、アシスタントはラグを感じ、反応が遅くなる。

アシスタントが本当に必要とする音声は、ウェイクワード（例えば「ヘイグーグル」）の直後のものだけだ。もし、データを送信せずにその単語を検出し、それを聞いたときにストリーミングを開始することができたらどうだろう？ユーザのプライバシーを守り、バッテリー寿命と帯域幅を節約し、ネットワークを待つことなくアシスタントを目覚めさせることができる。

そこでTinyMLの出番だ。ウェイクワードをリッスンする小さなモデルをトレーニングし、低消費電力のチップで実行することができる。これを携帯電話に組み込めば、常にウェイクワードを聞き続けることができる。魔法の言葉を聞くと、携帯電話の演算子（OS）に通知され、OSは音声のキャプチャを開始し、サーバに送信することができる。
