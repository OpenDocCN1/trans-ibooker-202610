
| 0.49 || 0.51 || どちらの州も大きくリードしていないため、結論は出ていない。 |

私たちの工場マシンの例では、個々の推論はデータのスナップショットのみを考慮する-それは様々なセンサーの読み取りに基づいて、過去10秒以内の異常状態の確率を教えてくれる。実世界のデータはしばしば乱雑であり、マシン学習モデルも完璧ではないため、一時的な不具合によって誤った分類がなされる可能性がある。例えば、一時的なセンサーの誤動作により、温度値が急上昇することがある。このような一時的で信頼性の低い入力は、現実を反映しない出力の分類をもたらすかもしれない。

このような瞬間的な不具合が問題を引き起こすのを防ぐために、一定期間にわたるモデルの全出力の平均を取ることができる。例えば、10秒ごとに現在のデータ・ウィンドウでモデルを実行し、各クラスの平滑化されたスコアを与えるために、最後の6つの出力の平均を取ることができる。こうすることで、一過性の問題は無視され、一貫した振る舞いのみに対応することになる。[第7章](#ch07.html#chapter_speech_wake_word_example)では、このテクニックをウェイクワード検出に役立てる。

各クラスのスコアが決まったら、何をするかはアプリケーションのコード次第だ。おそらく、異常な状態が1分間継続的に検出された場合、コードはマシンをシャットダウンする信号を送り、メンテナンス・チームにアラートを出すだろう。

## 評価とトラブルシューティング

我々のモデルをデプロイし、オンデバイスで動作させた後、実世界でのパフォーマンスが我々が期待したものに近づくかどうかを確認し始める。我々のモデルがテストデータ上で正確な予測を行うことはすでに証明されているが、実際の問題でのパフォーマンスは異なるかもしれない。

このようなことが起こる理由はたくさんある。例えば、トレーニングで使用したデータが、実際の演算子で利用可能なデータを正確に代表していない可能性がある。おそらく地域の気候のせいで、我々のマシンの温度はデータセットが収集されたものよりも一般的に低いのだろう。これは、我々のモデルによる予測に影響を与え、期待したほど正確でなくなるかもしれない。

もう一つの可能性は、モデルが気づかないうちにデータセットをオーバーフィットしてしまっていることだ。[モデルを訓練する](#ch03.html#ch3_train_the_model)」では、データセットにたまたま追加的なシグナルが含まれていて、モデルがそのシグナルを学習して認識できるようになった場合に、偶然このようなことが起こりうることを学んだ。

もしモデルが本番で機能しないのであれば、トラブルシューティングを行う必要がある。まず、モデルに届くデータに影響を与えている可能性のあるハードウェアの問題（センサーの不具合や予期せぬノイズなど）を規則で除外する。次に、モデルがデプロイされているデバイスからデータを取得し、元のデータセットと比較して、同じレベルであることを確認する。もしそうでなければ、環境条件やセンサーの特性に想定外の違いがあるのかもしれない。データに問題がなければ、オーバーフィッティングが問題なのかもしれない。

ハードウェアの問題を規則で除外した後、オーバーフィットの最善の解決策は、より多くのデータで訓練することである。デプロイしたハードウェアから追加データを取得し、元のデータセットと組み合わせて、モデルを再トレーニングすることができる。その過程で、正則化やデータ増強のテクニックを適用することで、今あるデータを最大限に活用することができる。

実世界で良好なパフォーマンスを得るには、モデル、ハードウェア、付随するソフトウェアについて、ある程度の反復が必要になることがある。問題が発生した場合は、他の技術的な問題と同様に扱うこと。トラブルシューティングには科学的なアプローチをとり、考えられる要因を排除し、データを分析して何が問題なのかを突き止める。

## 何を作っているのか

[第3章](#ch03.html#chapter_get_up_to_speed)では、ディープラーニング・ネットワークがどのように学習データのパターンをモデル化し、予測を行えるようになるかを説明した。ここでは、非常に単純なデータをモデル化するためにネットワークを訓練する。おそらく[正弦](https://oreil.ly/jxAmF)関数について聞いたことがあるだろう。三角法で直角三角形の性質を表すのに使われる。これから学習するデータは[正弦波で](https://oreil.ly/XDvJu)、正弦関数の結果を時間と共にプロットしたグラフである（[図4-1](#ch04.html#sine_wave)参照）。

## 機械学習ツールチェーン

このプロジェクトの機械学習部分を構築するために、我々は実際の機械学習実践者が使っているのと同じツールを使っている。このセクションではそれらを紹介する。

### PythonとJupyterノートブック

`Python`は、マシン学習の科学者やエンジニアが好んで使うプログラミング言語だ。`Python`は習得が簡単で、様々なアプリケーションに対応し、データや数学を含む有用なタスクのためのライブラリーが豊富にある。深層学習の研究の大部分は`Python`を使って行われており、研究者は作成したモデルの`Python`ソースコードを公開することが多い。

`Python`は、[`Jupyter`ノートブックと](https://jupyter.org/)呼ばれるものと組み合わせると特に素晴らしい。これは、文章、グラフィック、コードを混在させることができる特殊な文書形式で、ボタンをクリックするだけで実行できる。`Jupyter`ノートブックは、機械学習のコードや問題を記述、説明、探索する方法として広く使われている。

私たちは`Jupyter`ノートブック内でモデルを作成することになるが、このノートブックでは開発中にデータを可視化するために素晴らしいことができる。これには、モデルの精度と収束を示すグラフの表示も含まれる。

プログラミングの経験があれば、`Python`は読みやすく学びやすい。このチュートリアルに何の問題もなくついていけるはずだ。

### グーグル・コラボラトリー

ノートブックを実行するには、[Colaboratory](https://oreil.ly/ZV7NK)、略して`Colab`と呼ばれるツールを使う。`Colab`はGoogle製で、`Jupyter`ノートブックを実行するためのオンライン環境を提供している。機械学習の研究開発を奨励するツールとして無料で提供されている。

従来は、自分のコンピューターでノートブックを作成する必要があった。これには、`Python`ライブラリなど多くの依存関係をインストールする必要があり、頭痛の種だった。また、出来上がったノートブックを他の人と共有するのも困難だった。なぜなら、依存関係のバージョンが異なる可能性があり、ノートブックが期待通りに動かない可能性があったからだ。さらに、マシン学習は計算量が多いので、開発用コンピューターではモデルのトレーニングに時間がかかるかもしれない。

`Colab`を使えば、Googleのパワフルなハードウェア上でノートブックをゼロコストで実行できる。どのウェブブラウザからでもノートブックを編集・閲覧でき、他の人と共有することもできる。さらに、通常のコンピュータよりも高速にトレーニングを実行できる特殊化されたハードウェア上であなたのコードを実行するように`Colab`を設定することもできる。

### TensorFlowとKeras

[`TensorFlow`](https://tensorflow.org)  は、機械学習モデルの構築、トレーニング、評価、デプロイのためのツールセットである。元々はGoogleで開発された`TensorFlow`は、現在、世界中の何千もの貢献者によって構築、維持されているオープンソースプロジェクトである。`TensorFlow`は、機械学習のフレームワークとして最も人気があり、広く使われている。ほとんどの開発者は、`Python`ライブラリを介して`TensorFlow`とやりとりする。

`TensorFlow`は様々なことを行う。この章では、`TensorFlow`の高水準APIである[`Keras`](https://oreil.ly/JgNtS)を使い、ディープラーニング・ネットワークの構築と学習を簡単に行う。また、[`TensorFlow`](https://oreil.ly/LbDBK)モデルをモバイルデバイスや組み込みデバイスにデプロイするためのツールセットである[`TensorFlow Lite`を使って](https://oreil.ly/LbDBK)、デバイス上でモデルを実行する。

[第13章](#ch13.html#chapter_tensorflow_lite_for_microcontrollers)では、`TensorFlow`についてもっと詳しく説明する。今のところは、`TensorFlow`が非常にパワフルで業界標準のツールであり、初心者からディープラーニングのエキスパートになるまで、あなたのニーズに応え続けてくれることを知っておいてほしい。

### 依存関係をインポートする

最初の仕事は、必要な依存関係をインポートすることだ。`Jupyter`ノートブックでは、コードとテキストはセルに配置されている。コード・セルには実行可能な`Python`コードがあり、テキスト・セルには形式化されたテキストがある。

最初のコードセルは、"`Import dependencies`"の下にある。これは、モデルのトレーニングと変換に必要なすべてのライブラリをセットアップするものだ。これがそのコードだ：

```
# TensorFlow is an open source machine learning library
!pip install tensorflow==2.0
import tensorflow as tf
# NumPy is a math library
import numpy as np
# Matplotlib is a graphing library
import matplotlib.pyplot as plt
# math is Python's math library
import math
```

`Python`では、`import` ステートメントでライブラリをロードし、コードから使用できるようにする。コードとコメントから、このセルが以下のことを行っていることがわかる：
