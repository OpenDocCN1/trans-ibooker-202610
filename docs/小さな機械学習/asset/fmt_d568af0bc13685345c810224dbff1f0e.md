### チップ

プログラミングの出力がエラーで終わった場合、`Sending Reset Command.` が印刷されたかどうかをチェックする。もしそうなら、エラーにもかかわらず点滅は成功した可能性が高い。そうでなければ、点滅に失敗している可能性がある。この手順をもう一度実行してみてほしい（環境変数の設定は省略できる）。

### プログラミングをテストする

プログラミングが実行されていることを確認するには、`RST` ボタンを押す。青いLEDが点滅しているのが見えるはずだ。

プログラミングをテストするには、"イエス "と言ってみる。イエス」を検出すると、オレンジ色のLEDが点滅する。このモデルはまた、「ノー」と未知の単語が話されたときを認識するように訓練されている。赤のLEDは "no "を、緑のLEDは "unknown "を点滅させる。

もし、あなたの「はい」をプログラミングに認識させることができないなら、何回か続けて言ってみてほしい：「イエス、イエス、イエス」だ。

私たちが使っているモデルは小さく不完全なもので、"ノー "よりも "イエス "を検出する方が得意で、"不明 "と認識されることが多いことにお気づきだろう。これは、小さなモデルサイズに最適化すると、精度に問題が生じる可能性があることの一例である。このトピックについては[第8](#ch08.html#chapter_training_micro_speech)章で取り上げる。

### デバッグデータを見る

このプログラミングはまた、シリアルポートに正常に認識されたことを記録する。このデータを見るには、ボーレート115200を使ってボードのシリアル・ポート出力をモニターすればよい。macOSとLinuxでは、以下のコマンドが動作するはずだ：

```
screen ${DEVICENAME} 115200
```

初期化すると、以下のような出力が表示されるはずだ：

```
Apollo3 Burst Mode is Available

                               Apollo3 operating in Burst Mode (96MHz)
```

"yes "または "no "と言って、いくつかのコマンドを発行してみる。各コマンドのデバッグ情報がボードに表示されるはずだ：

```
Heard yes (202) @65536ms
```

`screen` でデバッグ出力の表示を停止するには、Ctrl-A キーを押した直後に K キーを押し、次に Y キーを押す。

### 自分で変更を加える

さて、基本的なアプリケーションをデプロイしたので、いろいろ遊んでみて、変更を加えてみよう。アプリケーションのコードは `tensorflow/lite/micro/examples/micro_speech` フォルダに発見できる。編集して保存し、前述の手順を繰り返して、変更したコードをデバイスにデプロイする。

* `RespondToCommand()` の `score` 引数は予想スコアを表示する。LEDをメーターとして使い、試合の強さを示す。
* 秘密のコードフレーズのように、「はい」と「いいえ」の特定のシーケンスにアプリケーションが反応するようにする。
* `yes` と `no` コマンドを使って、追加のLEDやサーボなど、他のコンポーネントを制御する。

### STM32F746Gのコマンドに応答する

STM32F746GのLCDドライバには、ディスプレイにテキストを書き込むためのメソッドが用意されている。この練習では、これらのメソッドを使って、どのコマンドが聞かれたかに応じて、以下のメッセージのいずれかを表示する：

* "イエスと聞いた！"
* 「聞いていない :("
* "未聴"
* 「沈黙を聞く

また、どのコマンドが聞こえたかによって、背景色も異なるようにセットする。

はじめに、いくつかのヘッダファイルをインクルードする：

```
#include "tensorflow/lite/micro/examples/micro_speech/command_responder.h"
#include "LCD_DISCO_F746NG.h"
```

最初の `command_responder.h` は、このファイルのインタフェースを宣言している。2番目の `LCD_DISCO_F746NG.h` は、デバイスのLCDディスプレイを制御するためのインタフェースを提供している。これについては、[Mbedの](https://oreil.ly/6oirs)サイトで詳しく読むことができる。

次に、`LCD_DISCO_F746NG` オブジェクトをインスタンス化する。このオブジェクトには、LCDをコントロールするためのメソッドが格納されている：

```
LCD_DISCO_F746NG lcd;
```

次の数行で `RespondToCommand()` 関数を宣言し、それが新しいコマンドで呼び出されたかどうかをチェックする：

```
// When a command is detected, write it to the display and log it to the
// serial port.
void RespondToCommand(tflite::ErrorReporter *error_reporter,
                      int32_t current_time, const char *found_command,
                      uint8_t score, bool is_new_command) {
  if (is_new_command) {
    error_reporter->Report("Heard %s (%d) @%dms", found_command, score,
                           current_time);
```

新しいコマンドであることがわかったら、`error_reporter` 、シリアルポートにログを記録する。

次に、各コマンドが発見されたときに何が起こるかを決定するために、大きな `if` 。最初に "yes "が来る：

```
if (*found_command == 'y') {
  lcd.Clear(0xFF0F9D58);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard yes!", CENTER_MODE);
```

`lcd.Clear()` 、スクリーンから以前のコンテンツを消去し、ペンキを塗り直すように新しい背景色をセットする。`0xFF0F9D58` 、豊かな緑色だ。

緑色の背景に、`lcd.DisplayStringAt()` を使ってテキストを描画する。最初の引数で `x` 座標を指定し、2番目の引数で `y` 座標を指定する。テキストをディスプレイのほぼ中央に配置するために、ヘルパー関数 `LINE()` を使って、画面上のテキストの5行目に対応する `y` 座標を決定する。

第3引数は表示する文字列で、第4引数はテキストの配置を決定する。ここでは、定数 `CENTER_MODE` を使って、テキストを中央揃えにするよう指定している。

残りの3つの可能性、「いいえ」、「不明」、「沈黙」（これは `else` ブロックで捕捉される）をカバーするために、`if` 文を続ける：

```
} else if (*found_command == 'n') {
  lcd.Clear(0xFFDB4437);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard no :(", CENTER_MODE);
} else if (*found_command == 'u') {
  lcd.Clear(0xFFF4B400);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard unknown", CENTER_MODE);
} else {
  lcd.Clear(0xFF4285F4);
  lcd.DisplayStringAt(0, LINE(5), (uint8_t *)"Heard silence", CENTER_MODE);
}
```

それで終わりだ！LCDライブラリーは、ディスプレイを簡単にハイレベルでコントロールできるので、結果を出力するのに必要なコードはそれほど多くない。このサンプルをデプロイして、実際に動作しているところを見てみよう。

### 例を実行する

これで、Mbedツールチェーンを使ってアプリケーションをデバイスにデプロイできるようになった。

### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は [`README.md`を](https://oreil.ly/1INIO) チェックしてほしい。

始める前に、以下のものが必要だ：

* STM32F746Gディスカバリー・キット・ボード
* ミニUSBケーブル
* Arm Mbed CLI ([Mbedセットアップガイドに](https://oreil.ly/tR57j)従う)
* Python 3と `pip`

Arduino IDEと同様に、Mbedはソースファイルを一定の方法で構造化する必要がある。TensorFlow Lite for Microcontrollers Makefileは、この方法を知っており、Mbedに適したディレクトリを生成してくれる。

そのためには、以下のコマンドを実行する：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  TARGET=mbed TAGS="cmsis-nn disco_f746ng" generate_micro_speech_mbed_project
```

その結果、新しいディレクトリが作成される：

```
tensorflow/lite/micro/tools/make/gen/mbed_cortex-m4/prj/ \
  micro_speech/mbed
```

このディレクトリには、Mbedがそれをビルドできるようにするための正しい方法で構造化された、サンプルのすべての依存関係が含まれている。

まず、ディレクトリに移動し、その中でコマンドを実行できるようにする：

```
cd tensorflow/lite/micro/tools/make/gen/mbed_cortex-m4/prj/micro_speech/mbed
```

次に、Mbedを使って依存関係をダウンロードし、プロジェクトをビルドする。

始めに、以下のコマンドを使って、カレントディレクトリがMbedプロジェクトのルートであることをMbedに知らせる：

```
mbed config root .
```

次に、Mbedに依存関係のダウンロードとビルドの準備を指示する：

```
mbed deploy
```

デフォルトでは、MbedはC++98を使ってプロジェクトをビルドする。しかし、TensorFlow LiteはC++11を必要とする。以下のPythonスニペットを実行し、C++11を使用するようにMbed構成ファイルを変更する。 コマンドラインに入力するか貼り付けるだけでよい：

```
python -c 'import fileinput, glob;
for filename in glob.glob("mbed-os/tools/profiles/*.json"):
  for line in fileinput.input(filename, inplace=True):
    print(line.replace("\"-std=gnu++98\"","\"-std=c++11\", \"-fpermissive\""))'
```

最後に、以下のコマンドを実行してコンパイルする：

```
mbed compile -m DISCO_F746NG -t GCC_ARM
```

この結果、以下のパスにバイナリができるはずである：

```
./BUILD/DISCO_F746NG/GCC_ARM/mbed.bin
```

STM32F746Gボードのいいところは、デプロイが本当に簡単なことだ。デプロイするには、STMボードに接続してファイルをコピーするだけだ。macOS上では、以下のコマンドを使用してこれを行うことができる：

```
cp ./BUILD/DISCO_F746NG/GCC_ARM/mbed.bin /Volumes/DIS_F746NG/
```

あるいは、ファイルブラウザーで `DIS_F746NG` のボリュームを発見し、ファイルをドラッグオーバーする。

ファイルをコピーすると、フラッシュ・プロセスが開始される。

### デバッグデータを見る

このプログラミングはまた、シリアルポートへの認識成功のログも記録する。出力を見るには、ボーレート9600でボードにシリアル接続を確立する。

macOSとLinuxでは、以下のコマンドを実行するとデバイスがリストされるはずだ：

```
ls /dev/tty*
```

以下のようになる：

```
/dev/tty.usbmodem1454203
```

デバイスを特定したら、以下のコマンドを使って接続する。`/dev/tty.devicename` を `/dev` に表示されているデバイス名に付け替える：

```
screen /dev/<tty.devicename 9600>
```

"yes "または "no "と言って、いくつかのコマンドを発行してみる。各コマンドのデバッグ情報がボードに表示されるはずだ：

```
Heard yes (202) @65536ms
```

`screen` でデバッグ出力の表示を停止するには、Ctrl-Aを押し、すぐにKキーを押し、次にYキーを押す。

### 注

プラットフォームでシリアル接続を行う方法がわからない場合は、Windows、macOS、Linuxで動作する[CoolTermを試して](https://oreil.ly/FP7gK)みるといいだろう。CoolTermのPortドロップダウンリストにボードが表示されるはずだ。ボーレートを9600にセットする。
