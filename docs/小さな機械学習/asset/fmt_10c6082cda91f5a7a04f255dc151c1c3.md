# アーキテクチャを理解する

[MobileNetsは](https://oreil.ly/tK57G) 、できるだけ少ない重みパラメータと算術演算子で精度の高い計算ができるように設計されたアーキテクチャ群である。現在では複数のバージョンがあるが、我々の場合はオリジナルのv1を使っている。アーキテクチャの核となる概念は、深さ方向に分離可能な畳み込みである。これは古典的な2次元畳み込みの変形で、精度をあまり犠牲にすることなく、より効率的な方法で動作する。通常の畳み込みは、入力の全チャンネルに特定のサイズのフィルタを適用して出力値を計算する。つまり、各出力に関わる計算の数は、フィルタの幅×高さ×入力チャンネル数となる。深度方向の畳み込みは、この大きな計算を別々の部分に分割する。まず、各入力チャンネルは1つ以上の矩形フィルターでフィルタリングされ、中間値が生成される。次に、これらの値をポイントワイズ・コンボリューションを使って結合する。これにより、必要な計算回数が劇的に減少し、実際には通常の畳み込みと同様の結果が得られる。

モービルネットv1は、平均プールを持つ深さ方向に分離可能な畳み込み層を14層積み重ねたもので、その後に完全接続層があり、最後にソフトマックスが続く。幅倍率を0.25に指定し、各活性化層のチャンネル数を標準モデルに比べて75％縮小することで、1回の推論あたりの計算数を約6000万に減らす効果がある。要するに、通常の畳み込みニューラルネットワークの演算子に非常に似ており、各層が入力のパターンを学習する。初期の層はエッジ認識フィルターのような役割を果たし、画像内の低レベルの構造を見つけ、後の層はその情報をより抽象化されたパターンに合成し、最終的なオブジェクト分類に役立てる。

# 第11章. 魔法の杖アプリケーションを構築する

この作品はAIを使って翻訳されている。ご意見、ご感想をお待ちしている：[translation-feedback@oreilly.com](mailto:translation-feedback@oreilly.com)

これまでのところ、我々のアプリケーションの例では、人間が容易に理解できるデータを扱ってきた。私たちは脳の全領域を音声や構想の理解に充てているため、視覚や音声データをインタプリタし、何が起こっているのかを理解することは難しくない。

しかし、多くのデータはそう簡単には理解できない。マシンとそのセンサーは、人間の感覚に容易にマッピングできない膨大な情報の流れを生成する。視覚的に表現されたとしても、私たちの脳がデータのトレンドやパターンを把握するのは難しい。

例えば、[図11-](#ch11.html#jogging)1と[図11-2に](#ch11.html#walking_downstairs)示した2つのグラフは、運動をしている人の前ポケットに入れた携帯電話から取得したセンサーデータを示している。問題のセンサーは、加速度センサーで、3次元で加速度を測定する（これについては後で詳しく説明する）。[図11-](#ch11.html#jogging)1のグラフは、ジョギングをしている人の加速度計のデータであり、[図11-](#ch11.html#walking_downstairs)2のグラフは、同じ人が階段を下りているときのデータである。

ご覧のように、データは単純で親しみやすい活動を表しているにもかかわらず、2つの活動を区別するのは難しい。複雑な産業用マシンの演算子を区別しようとすることを想像してみてほしい。そのマシンには、あらゆる種類の不明瞭な特性を測定するセンサーが何百もあるかもしれない。

多くの場合、この種のデータを理解することができる手作りのアルゴリズムを書くことができる。例えば、人間の歩行の専門家なら、階段を上るときの兆候を認識し、その知識をコードの関数として表現できるかもしれない。この種の関数は、ヒューリスティックと呼ばれ、産業オートメーションから医療機器まで、あらゆる種類のアプリケーションで一般的に使用されている。

![](assets/timl_1101.png)![](assets/timl_1102.png)

ヒューリスティックを作成するには、2つのものが必要だ。1つ目はドメイン知識だ。ヒューリスティック・アルゴリズムは人間の知識や理解を式にしたものなので、それを書くには、データが何を意味するのかをすでに理解している必要がある。これを理解するために、体温から発熱の有無を判断するヒューリスティックを想像してみよう。これを作成した人は、発熱を示す体温変化についての知識を持っているに違いない。

ヒューリスティックを構築するための第二の条件は、プログラミングと数学の専門知識である。誰かの体温が高すぎるかどうかを判断するのはかなり簡単だが、他の問題ははるかに複雑な場合がある。複数のデータストリームの複雑なパターンに基づいてシステムの状態を見極めるには、統計解析や信号処理のような高度なテクニックの知識が必要になるかもしれない。例えば、加速度センサーのデータに基づいて、歩くか走るかを区別するヒューリスティックを作成することを考えてみよう。これを構築するには、加速度センサーのデータを数学的にフィルタリングして、歩数の推定値を得る方法を知る必要があるかもしれない。

ヒューリスティックは非常に有用であるが、ドメイン知識とプログラミングの専門知識が必要であるため、その構築には困難が伴う。第一に、ドメイン知識は常に利用できるとは限らない。例えば、小さな会社には、ある状態と別の状態を示すものを知るために必要な基礎研究を行うリソースがないかもしれない。同様に、領域知識があったとしても、すべての人がヒューリスティック・アルゴリズムを設計し、コードで実装するのに必要な専門知識を持っているわけではない。

機械学習は、これらの要件をショートカットする機会を与えてくれる。ラベル付けされたデータで学習されたモデルは、あるクラスか別のクラスを示すシグナルを認識するように学習することができる。例えば、あるモデルは、具体的にどの温度が重要かを教えてもらわなくても、発熱を示す人間の体温変動を学習することができる。必要なのは、"発熱 "または "非発熱 "とラベル付けされた体温データだけだ。さらに、マシン学習に必要なエンジニアリング・スキルは、高度なヒューリスティックを実装するのに必要なスキルよりも、間違いなく習得しやすい。

機械学習開発者は、ゼロから発見的アルゴリズムを設計する代わりに、適切なモデルアーキテクチャを発見し、データセットを収集し、ラベル付けし、学習と評価を繰り返しながらモデルを作成することができる。ドメイン知識は依然として非常に役立つが、何かを機能させるための前提条件ではなくなるかもしれない。そして場合によっては、出来上がったモデルは、手作業でコーディングされた最高のアルゴリズムよりも正確なこともある。

実際、最近の論文では^([1](#ch11.html#idm45271171344024))は、単純な畳み込みニューラルネットワークが、1回の心拍から患者のうっ血性心不全を100％の精度で検出できることを示した。これは、これまでのどの診断テクニックよりも優れたパフォーマンスである。細部までは理解できなくても、この論文は魅力的な読み取りである。

複雑なデータを理解するためにDeep Learningモデルをトレーニングし、それをマイクロコントローラーのプログラムに組み込むことで、複雑な環境を理解し、何が起こっているのかを高いレベルで教えてくれるスマートセンサーを作成することができる。これは、何十もの分野にわたって大きな意味を持つ。ここでは、潜在的な応用例をいくつか紹介しよう：

* 接続性の悪い遠隔地での環境モニタリング
* 問題にリアルタイムで適応する自動化された工業プロセス
* 複雑な外部刺激に反応するロボット
* 医療専門家を必要としない疾病診断
* 身体の動きを理解するコンピュータ・インタフェース

この章では、最後のカテゴリーであるデジタル "魔法の杖 "のプロジェクトを構築する。この杖は、所有者が振ることで様々な呪文を唱えることができる。入力として、人間には理解できないような複雑で多次元的なセンサーデータを受け取る。その出力は、いくつかのクラスの動きのいずれかが最近発生した場合にアラートを出す単純な分類となる。ディープラーニングがどのように奇妙な数値データを意味のある情報に変換し、魔法のような効果をもたらすのかを見てみよう。

## 何を作っているのか

私たちの「魔法の杖」は、いくつかの種類の呪文を唱えるのに使うことができる。そのためには、[図11-](#ch11.html#gesture_spells)3に示すように、「ウィング」、「リング」、「スロープ」と名 付けられた3つのジェスチャーのうちの1つで杖を振るだけでよい。

![](assets/timl_1103.png)

杖は呪文に反応し、LEDを点灯させる。電光の魔法だけでは物足りない場合は、シリアルポートに情報を出力することもできる。

物理的なジェスチャーを理解するために、魔法の杖アプリケーションはデバイスの加速度センサーを使い、空間を通過する動きに関する情報を収集する。加速度センサーは、現在経験している加速度の度合いを測定する。例えば、赤信号で止まって走り去ろうとしている車に加速度センサーを取り付けたとする。

信号が青になると、車は前進を開始し、制限速度に達するまで速度を上げる。この間、加速度計は車の加速度を示す値を出力する。車が一定の速度に達した後、車はもはや加速していないので、加速度計はゼロを出力する。

SparkFun EdgeとArduino Nano 33 BLE Senseの両ボードには、各ボードにはんだ付けされたコンポーネントの中に3軸加速度センサーが搭載されている。これらは3方向の加速度を測定するため、3D空間でのデバイスの動きを追跡するのに使用できる。魔法の杖を作るには、マイコンボードを棒の先に取り付け、魔術のように振ることができるようにする。そして加速度センサーの出力をDeep Learningモデルに入力し、既知のジェスチャーが行われたかどうかを分類する。

このアプリケーションを以下のマイクロコントローラプラットフォームにデプロイする手順を説明する：

* [Arduino Nano 33 BLEセンス](https://oreil.ly/6qlMD)
* [スパークファン・エッジ](https://oreil.ly/-hoL-)

[STマイクロエレクトロニクスのSTM32F746Gディスカバリー・キットには](https://oreil.ly/SSsVJ)加速度センサーが含まれていないため（魔法の杖の先に取り付けるには大きすぎる）、ここでは取り上げない。

## アプリケーションアーキテクチャ

我々のアプリケーションは、入力を取得し、推論を実行し、出力を処理し、その結果得られた情報を使って物事を進めるという、今ではお馴染みのパターンに再び従うことになる。

3軸加速度センサーは、デバイスのx軸、y軸、z軸の加速度を表す3つの値を出力する。SparkFun Edgeボードの加速度センサーは、これを1秒間に25回（25Hz）行うことができる。我々のモデルはこれらの値を直接入力として受け取るので、前処理は必要ない。

データが取り込まれ、推論が実行された後、このアプリケーションは有効なジェスチャーが検出されたかどうかを判断し、ターミナルに出力を出力し、LEDを点灯させる。

### モデル紹介

私たちのジェスチャー検出モデルは、約20KBの畳み込みニューラルネットワークで、生の加速度センサーの値を入力として受け取る。一度に128セットの`x`、`y`、`z`の値を取り込み、25Hzのレートで5秒分強のデータになる。各値は32ビットの浮動小数点数で、その方向の加速度を示す。

このモデルは、多数の人が行った4つのジェスチャーで訓練された。各ジェスチャー（「ウィング」、「リング」、「スロープ」）を表すものと、認識されないジェスチャーを表すものである。確率スコアは合計で1となり、0.8を超えると自信があるとみなされる。

1秒間に複数の推論を実行するため、ジェスチャーが実行されている間の1回の推論ミスが結果を歪めないようにする必要がある。そのためのメカニズムとして、ジェスチャーが一定数の推論によって確認された後にのみ、そのジェスチャーが検出されたとみなすことにする。各ジェスチャーの実行にかかる時間は異なるため、必要な推論の回数はジェスチャーごとに異なり、最適な回数は実験によって決定される。同様に、推論の実行速度はデバイスによって異なるため、これらの閾値もデバイスごとに設定される。

[第12章](#ch12.html#chapter_magic_wand_training)では、独自のジェスチャー・データでモデルをトレーニングする方法を探り、モデルがどのように機能するかをさらに深く掘り下げる。それまでは、このアプリケーションを通して歩き続けよう。
