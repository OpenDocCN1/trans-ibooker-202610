
```
am_hal_gpio_output_clear(AM_BSP_GPIO_LED_YELLOW);
am_hal_gpio_output_clear(AM_BSP_GPIO_LED_GREEN);
if (person_score > no_person_score) {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_GREEN);
} else {
    am_hal_gpio_output_set(AM_BSP_GPIO_LED_YELLOW);
}

error_reporter->Report("person score:%d no person score %d", person_score,
                        no_person_score);
```

それで終わりだ！この関数のコアは基本的な`if` 。同じようなロジックを使えば、他のタイプの出力を制御することも簡単にできる。このような複雑な視覚的入力がひとつのブール出力に変換されるのは、とてもエキサイティングなことだ："人 "か "人なし "だ。

### 例を実行する

SparkFun Edgeの実装がどのように機能するのかがわかったところで、実際に動かしてみよう。

#### チップ

この本が書かれた当時とビルド手順が変わっている可能性もあるので、最新の手順は[`README.mdを`](https://oreil.ly/kaSXN)チェックしてほしい。

コードをビルドしてデプロイするには、以下のものが必要だ：

* SparkFun Edgeボードに[Himax HM01B0ブレークアウトを](https://oreil.ly/jNtyv)取り付けた。
* USBプログラマ（SparkFun Serial Basic Breakoutをお勧めする。）
* 適合するUSBケーブル
* Python 3といくつかの依存関係

#### 注

正しいバージョンのPythonがインストールされているかどうかわからない場合は、[「Running the Example](#ch06.html#running_hello_world_sparkfun_edge)」に確認方法が載っている。

ターミナルで、TensorFlowリポジトリをクローンし、そのディレクトリに移動する：

```
git clone https://github.com/tensorflow/tensorflow.git
cd tensorflow
```

次に、バイナリをビルドし、デバイスにダウンロードするためのいくつかのコマンドを実行する。タイピングの手間を省くため、これらのコマンドは[`README.mdから`](https://oreil.ly/kaSXN)コピー＆ペーストできる。

#### バイナリをビルドする

次のコマンドは、必要な依存関係をすべてダウンロードし、SparkFun Edge用のバイナリをコンパイルする：

```
make -f tensorflow/lite/micro/tools/make/Makefile \
  TARGET=sparkfun_edge person_detection_bin
```

バイナリーは`*.bin`ファイルとして以下の場所に作成される：

```
tensorflow/lite/micro/tools/make/gen/
  sparkfun_edge_cortex-m4/bin/person_detection.bin
```

ファイルが存在するかどうかを確認するには、以下のコマンドを使うことができる：

```
test -f tensorflow/lite/micro/tools/make/gen \
  /sparkfun_edge_cortex-m4/bin/person_detection.bin \
  &&  echo "Binary was successfully created" || echo "Binary is missing"
```

このコマンドを実行すると、コンソールに`Binary was successfully created` と表示されるはずだ。

`Binary is missing` が表示された場合、ビルドプロセスに問題があったことになる。もしそうなら、`make` コマンドの出力に、何がうまくいかなかったかを示すヒントがある可能性がある。

#### バイナリに署名する

バイナリをデバイスにデプロイするには、暗号鍵で署名する必要がある。それでは、バイナリをSparkFun Edgeにフラッシュできるように署名するコマンドをいくつか実行してみよう。ここで使用するスクリプトは、Makefileの実行時にダウンロードされるAmbiq SDKのものである。

以下のコマンドを入力し、開発に使えるダミーの暗号鍵をセットアップする：

```
cp tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0 \
  /tools/apollo3_scripts/keys_info0.py \
tensorflow/lite/micro/tools/make/downloads/AmbiqSuite-Rel2.0.0 \
  /tools/apollo3_scripts/keys_info.py
```

次に、以下のコマンドを実行して署名付きバイナリを作成する。必要に応じて、`python3` を`python` で置き換える：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_image_blob.py \
  --bin tensorflow/lite/micro/tools/make/gen/ \
  sparkfun_edge_cortex-m4/bin/person_detection.bin \
  --load-address 0xC000 \
  --magic-num 0xCB \
  -o main_nonsecure_ota \
  --version 0x0
```

これで`main_nonsecure_ota.bin`ファイルが作成される。次のステップで使用するスクリプトでデバイスをフラッシュするために使用できるファイルの最終バージョンを作成するために、このコマンドを実行する：

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/create_cust_wireupdate_blob.py \
  --load-address 0x20000 \
  --bin main_nonsecure_ota.bin \
  -i 6 \
  -o main_nonsecure_wire \
  --options 0x1
```

これで、コマンドを実行したディレクトリに`main_nonsecure_wire.bin`というファイルができるはずだ。これがデバイスにフラッシュするファイルだ。

#### バイナリをフラッシュする

SparkFun Edgeは、現在実行中のプログラミングを1メガバイトのフラッシュメモリーに保存する。ボードに新しいプログラムを実行させたい場合は、そのプログラムをボードに送信する必要があり、ボードはそれをフラッシュ・メモリーに保存し、以前に保存されたプログラムを上書きする。

この本で前述したように、このプロセスはフラッシングと呼ばれている。

#### プログラマを基板に取り付ける

ボードに新しいプログラムをダウンロードするには、SparkFun USB-C Serial Basicシリアル・プログラマを使用する。このデバイスにより、コンピューターはUSB経由でマイクロコントローラーと通信できる。

このデバイスをボードに取り付けるには、以下の手順を実行する：

1. SparkFun Edgeの側面に6ピンのヘッダがある。
2. [図9-6に](#ch09.html#sparkfun_edge_serial_basic_3)示すように、SparkFun USB-C Serial Basicをこれらの行に差し込み、各デバイスのBLKとGRNと書かれたピンが正しく並んでいることを確認する。

![](assets/timl_0613.png)

#### プログラマをコンピュータに取り付ける

ボードをUSB経由でコンピューターに接続する。ボードをプログラミングするには、コンピューターがデバイスに付けている名前を発見する必要がある。これを行う最良の方法は、接続前と接続後のコンピュータのデバイスをすべてリストアップし、どのデバイスが新しいかを確認することだ。

##### 警告

プログラマ用のオペレーティング・システムのデフォルト・ドライバに関する問題が報告されている人もいるので、先に進む前に[ドライバを](https://oreil.ly/yI-NR)インストールすることを強く勧める。

USBでデバイスを接続する前に、以下のコマンドを実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

以下のようなリストが出力されるはずだ：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
```

次に、プログラマをコンピューターのUSBポートに接続し、以下のコマンドをもう一度実行する：

```
# macOS:
ls /dev/cu*

# Linux:
ls /dev/tty*
```

次の例のように、追加の項目が出力されるはずである。新しい項目の名前は違うかもしれない。この新しい項目はデバイスの名前である：

```
/dev/cu.Bluetooth-Incoming-Port
/dev/cu.MALS
/dev/cu.SOC
/dev/cu.wchusbserial-1450
```

この名前は、デバイスを参照する際に使用される。ただし、プログラマがどのUSBポートに接続されているかによって、この名前が変わることがあるので、ボードをコンピューターから一旦取り外し、再度接続した場合は、再度名前を調べる必要があるかもしれない。

##### チップ

一部のユーザから、リストに2つのデバイスが表示されるとの報告があった。2つのデバイスが表示された場合、正しい方は "wch "で始まる、`/dev/wchusbserial-14410.`

デバイス名を確認したら、後で使えるようにシェル変数に入れておく：

```
export DEVICENAME=<your device name here>
```

これは、後でデバイス名を必要とするコマンドを実行するときに使用する変数である。

#### スクリプトを実行してボードをフラッシュする

ボードをフラッシュするには、新しいバイナリを受け取る準備をする特殊化「ブートローダー」状態にする必要がある。その後、ボードにバイナリを送信するスクリプトを実行する。

まず、ボーレートを指定する環境変数を作成する。ボーレートとは、データをデバイスに送信する速度である：

```
export BAUD_RATE=921600
```

次のコマンドをターミナルに貼り付ける！コマンドの`${DEVICENAME}` と`${BAUD_RATE}` は、前のセクションでセットした値に置き換えられる。必要であれば、`python3` を`python` で置き換えることを忘れないこと。

```
python3 tensorflow/lite/micro/tools/make/downloads/ \
  AmbiqSuite-Rel2.0.0/tools/apollo3_scripts/uart_wired_update.py -b \
  ${BAUD_RATE} ${DEVICENAME} -r 1 -f main_nonsecure_wire.bin -i 6
```

次に、ボードをブートローダーの状態にリセットし、ボードをフラッシュする。ボード上で、[図9-7に](#ch09.html#sparkfun_edge_buttons_3)示すように、`RST` と`14` と記されたボタンを探す。

以下の手順を実行する：

1. ボードがプログラマに接続され、全体がUSB経由でコンピューターに接続されていることを確認する。
2. ボード上で、`14` と書かれたボタンを押し続ける。そのまま押し続ける。
3. `14` と書かれたボタンを押したまま、`RST` と書かれたボタンを押してボードをリセットする。
4. コンピュータでEnterキーを押してスクリプトを実行する。`14` ボタンを押し続ける。

### プログラミングをテストする

まず、`RST` ボタンを押して、プログラミングが実行されていることを確認する。

プログラミングが実行されている間、青いLEDは推論ごとに1回、点灯と消灯を繰り返す。人物検出に使用している構想モデルは比較的大きいため、推論を実行するのに時間がかかり、合計で約6秒かかる。

まず、デバイスのカメラを人ではないものに向けるか、レンズを覆い隠す。次に青いLEDがトグルすると、デバイスはカメラからフレームをキャプチャし、推論を開始する。約6秒後、推論の結果は別のLEDの点灯に変換される。カメラを人ではない何かに向けた点を考えると、オレンジ色のLEDが点灯するはずだ。

では、デバイスのカメラを自分に向けてみよう。次に青いLEDが点滅したら、デバイスは別のフレームをキャプチャし、推論を開始する。今度は緑のLEDが点灯するはずだ。

覚えておいてほしいのは、画像データは各推論の前に、青色LEDがトグルするたびにスナップショットとしてキャプチャされるということだ。その瞬間にカメラに向けられたものが、モデルに入力される。カメラがどこを向いているかは、次にフレームがキャプチャされ、青色LEDが再び点灯するまで関係ない。

不正確と思われる結果が出る場合は、照明の良い環境にいることを確認してほしい。また、これは精度と小ささを引き換えにした小さなモデルであることを覚えておくといいだろう。非常によく機能するが、常に100％正確というわけではない。

### デバッグデータを見る

プログラミングは検出結果をシリアルポートに記録する。それを見るには、ボーレート115200を使ってボードのシリアル・ポート出力をモニターすればよい。macOSとLinuxでは、以下のコマンドが動作するはずだ：

```
screen ${DEVICENAME} 115200
```

初期化すると、以下のような出力が表示されるはずだ：

```
Apollo3 Burst Mode is Available

                               Apollo3 operating in Burst Mode (96MHz)
```

ボードがフレームをキャプチャして推論を実行すると、デバッグ情報が表示されるはずだ：

```
Person score: 130 No person score: 204
Person score: 220 No person score: 87
```

`screen` でデバッグ出力の表示を停止するには、Ctrl-Aを押し、すぐにKキーを押し、次にYキーを押す。
