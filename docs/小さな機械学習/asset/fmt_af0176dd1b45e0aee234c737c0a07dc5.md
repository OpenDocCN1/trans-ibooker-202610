
# データ準備とトレーニング

データのクリーニングに加えて、スクリプトはいくつかの*合成データを*生成する。これは、実世界から取得したデータではなく、アルゴリズムによって生成されたデータを指す。この場合、`data_prepare.py`の `generate_negative_data()` 関数は、特定のジェスチャーに対応しない加速度センサーの動きと等価性のある合成データを作成する。このデータは "unknown "カテゴリの学習に使われる。

合成データの作成は、実世界のデータを取得するよりもはるかに速いため、トレーニングプロセスを補強するのに役立つ。しかし、実世界の変動は予測不可能なので、合成データからデータセット全体を作成することはあまりできない。我々の場合、「未知」のカテゴリーをより堅牢にするのには役立つが、既知のジェスチャーを分類するのには役立たないだろう。

番目のセルで次に実行するスクリプトは[`data_split_person.py`](https://oreil.ly/1U0FW)である：

```
# Split the data by person
!python data_split_person.py
```

このスクリプトは、データをトレーニングセット、検証セット、テストセットに分割する。データには作成者がラベル付けされているため、1つのセットをトレーニングに、もう1つのセットを検証に、そして最後のセットをテストに使うことができる。データは次のように分割される：

```
train_names = [
    "hyw", "shiyun", "tangsy", "dengyl", "jiangyh", "xunkai", "negative3",
    "negative4", "negative5", "negative6"
]
valid_names = ["lsj", "pengxl", "negative2", "negative7"]
test_names = ["liucx", "zhangxy", "negative1", "negative8"]
```

トレーニングに6人分、検証に2人分、テストに2人分のデータを使う。さらに、特定のユーザとは関係のないネガティブ・データも混ぜている。合計データは、3つのセットでだいたい60％／20％／20％の割合で分けられているが、これはマシン学習ではごく標準的な割合だ。

人別に分けることで、モデルが新しいデータにも一般化できるようにしようとしている。モデルはトレーニングデータセットに含まれていない個人のデータで検証・テストされるため、各人がどのように各ジェスチャーを行うかという個人差に対して堅牢である必要がある。

また、人ごとではなく、ランダムにデータを分割することも可能だ。この場合、トレーニング、検証、テストの各データセットには、各個人のジェスチャーのサンプルが含まれることになる。結果として得られるモデルは、たった6人のデータではなく、すべての人のデータでトレーニングされたことになり、人々の様々なジェスチャースタイルにより多く触れることになる。

しかし、検証セットとトレーニングセットにはすべての個人のデータも含まれているため、モデルが今まで見たことのない新しいジェスチャースタイルに一般化できるかどうかをテストする方法はない。このようにして開発されたモデルは、検証時やテスト時に高い精度を報告するかもしれないが、新しいデータでも同じように機能する保証はない。

続行する前に、"Prepare data "セクションで両方のセルを実行したことを確認する。

## TensorBoardをロードする

データが準備できたら、次のセルを実行してTensorBoardをロードし、トレーニング・プロセスをモニターできるようにする：

```
# Load TensorBoard
%load_ext tensorboard
%tensorboard --logdir logs/scalars
```

トレーニングログは、トレーニングスクリプトのディレクトリの`logs/scalars`サブディレクトリに書き出されるので、これをTensorBoardに渡す。

## トレーニングを開始する

TensorBoardがロードされたら、いよいよトレーニングを開始する。以下のセルを実行する：

```
!python train.py --model CNN --person true
```

[`train.py`](https://oreil.ly/S3w0X)スクリプトは、モデルアーキテクチャをセットアップし、[`data_load.py`](https://oreil.ly/aCZgu)を使用してデータをロードし、学習プロセスを開始する。

データがロードされると、`load_data.py`は、[`data_augmentation.py`](https://oreil.ly/zL6wm)で定義されたコードを使用してデータの拡張も行う。この関数`augment_data()`関数はジェスチャーを表すデータを受け取り、それぞれオリジナルから少し変更された新しいバージョンを作成する。この変更には、データポイントの時間的なシフトやワープ、ランダムノイズの追加、加速度の増加などが含まれる。この拡張されたデータは、モデルを訓練するために元のデータと一緒に使用され、私たちの小さなデータセットを最大限に活用するのに役立つ。

トレーニングが進むにつれて、今走ったセルの下にいくつかの出力が表示されるようになる。そこで、最も注目すべき部分をピックアップしてみよう。まず、Kerasはモデルのアーキテクチャを示す素晴らしい表を生成する：

## 結果を評価する

学習が完了したら、セルの出力を見ていくつかの有益な情報を得ることができる。まず、最終エポックでの検証精度が0.9743と非常に有望であることがわかる：

```
Epoch 50/50
1000/1000 [==============================] - 7s 7ms/step - loss: 0.0568 -

accuracy: 0.9835 - val_loss: 0.1185 - val_accuracy: 0.9743
```

これは素晴らしいことだ。特に、1人ごとのデータ分割を使用しているため、検証データはまったく異なる個人のセットから得られたことになる。しかし、モデルを評価するために検証精度に頼ることはできない。モデルのハイパーパラメータとアーキテクチャは、検証データセット上で手作業でチューニングされたものであるため、オーバーフィットしている可能性がある。

モデルの最終的なパフォーマンスをよりよく理解するために、Kerasの`model.evaluate()` 関数を呼び出して、テスト・データセットに対して評価することができる。次の行はその結果を示している：

```
6/6 [==============================] - 0s 6ms/step - loss: 0.2888 - accuracy: 0.9323
```

検証の数字ほど素晴らしくはないが、このモデルは0.9323という十分な精度を示しており、損失はまだ低い。このモデルは93%の確率で正しいクラスを予測する。

次の数行は、 によって計算された結果の*混同行列を示して*いる。 [`tf.math.confusion_matrix()`](https://oreil.ly/xlIKj)関数によって計算された：

```
tf.Tensor(
[[ 75   3   0   4]
 [  0  69   0  15]
 [  0   0  85   3]
 [  0   0   1 129]], shape=(4, 4), dtype=int32)
```

混同行列は、分類モデルの性能を評価するのに役立つツールである。これは、テストデータセットにおける各入力の予測クラスが、実際の値とどの程度一致しているかを示す。

混同行列の各列は、予測されたラベルに対応し、順番に（"wing"、"ring"、"slope"、"unknown "の順に）対応する。各行は上から順に実際のラベルに対応する。混同行列から、予測の大部分が実際のラベルと一致していることがわかる。最も顕著なのは、かなりの数の入力が「unknown」と誤分類されていることで、特に「ring」カテゴリーに属するものがそうである。

混同行列は、モデルの弱点がどこにあるかを教えてくれる。この場合、モデルが "ring "と "unknown "の違いをよりよく学習するためには、"ring "ジェスチャーのトレーニングデータをより多く取得することが有益かもしれないことを教えてくれる。

`train.py`が行う最後の点は、モデルをTensorFlow Lite形式に変換することで、浮動小数点型と量子化型の両方のバリエーションがある。以下の出力は、各バリアントのサイズを示している：

```
Basic model is 19544 bytes
Quantized model is 8824 bytes
Difference is 10720 bytes
```

我々の20KBのモデルは、量子化後は8.8KBに縮小される。これは*非常に*小さなモデルであり、素晴らしい結果だ。

# モデルの仕組み

これまでのところ、我々のモデルは畳み込みニューラルネットワーク（CNN）であり、約5秒間の時間に相当する128個の3軸加速度センサーの読み取りシーケンスを、4つの確率の配列に変換する。

CNNは、隣接する値の間に重要な情報が含まれている場合に使われる。説明の最初の部分では、データを見て、なぜCNNがそのデータを理解するのに適しているかを学ぶ。

## 入力を視覚化する

時系列の加速度計データでは、隣り合う加速度計の読み取りが、デバイスの動きに関する手がかりとなる。例えば、ある軸の加速度がゼロからプラスに急激に変化し、その後ゼロに戻った場合、デバイスはその方向に動き始めた可能性がある。[図12-](#ch12.html#gesture_single_axis_acceleration_graph)5はこの仮想的な例を示している。

![](assets/timl_1205.png)

どのようなジェスチャーも、一連の動作から構成されている。例えば、[図12-6に](#ch12.html#gesture_wing_gesture)示す「翼」のジェスチャーを考えてみよう。

![](assets/timl_1206.png)

デバイスはまず下に、そして右に動かされ、次に上に、そして右に動かされ、次に下に、そして右に動かされ、再び上に、そして右に動かされる。[図12-7は](#ch12.html#gesture_wing_gesture_graph)、"翼 "ジェスチャー中にキャプチャされた実データのサンプルで、単位はミリGsである。

![](assets/timl_1207.png)

このグラフを見て構成要素に分解することで、どのジェスチャーが行われているかを理解することができる。z軸の加速度から、「翼」のジェスチャーの形状から予想される方法でデバイスが上下に動かされていることがよくわかる。より微妙な点では、x軸の加速度が、ジェスチャーの幅を横切るデバイスの動きを示すように、z軸の変化とどのように相関しているかがわかる。一方、y軸はほぼ安定していることがわかる。

同様に、複数のレイヤーを持つCNNは、各ジェスチャーの特徴的な構成要素を通して、各ジェスチャーを見分ける方法を学習することができる。例えば、ネットワークは上下の動きを区別し、その2つが適切なz軸とy軸の動きと組み合わさると「翼」のジェスチャーを示すことを学習するかもしれない。

そのためにCNNは、レイヤーに配置された一連の*フィルタを*学習する。各フィルタは、データ中の特定のタイプの特徴を発見することを学習する。この特徴に気付くと、このハイレベルな情報をネットワークの次の層に渡す。例えば、ネットワークの第1層にあるフィルターは、上昇加速度の周期のような単純なものを発見することを学習するかもしれない。そのような構造を識別すると、この情報をネットワークの次の層に渡す。

後続のフィルタリング層は、それ以前の単純なフィルタの出力がどのように組み合わされ、より大きな構造を形成するかを学習する。例えば、上向きと下向きの加速度を交互に4回繰り返すと、「翼」のジェスチャーの「W」の形になる。
