the error reporting is still poor. For example, suppose the RPN script writer begins writing his script as follows:

```
PRINTS 'Enter side 1: '
INPUT side 1
```

Oops! In the second line, he entered an extra space when attempting to write `side1`. Given how the program `rpn.txt` is currently written, the symbolic name `side` will be entered into the symbol table and the `1` will be ignored, but later, when the script attempts to look up `side1` in the symbol table, that symbol will not be found.

With more sophisticated error handling, the interpreter might pinpoint the problem in line 2 (or rather, line 1 if we are using zero-based index numbers), pointing out that you can’t give two arguments to the INPUT directive.

But at minimum, our Python program should catch the exception that arises and then print a polite message, along with a line number indicating where the error was discovered. To do this, we’ll need to keep track of line numbers.

The beauty of this solution is that once line-number tracking is added, it’s easy to add a control structure, _jump if not zero_, as you’ll see in Section 14.10.2. Adding that one feature will greatly expand the capabilities of the RPN scripting language.
