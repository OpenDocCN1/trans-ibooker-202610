![Figure 4-2](images/fig4-2.png)

**图 4-2**

为了提供企业所需的所有洞察，大数据平台需要实现许多目标。大数据架构的设计必须使数据在自然环境中得到分析，而不是在海量数据表中重新创建数据。该架构必须允许读取和访问各种来源，如电子邮件、财务、音频、图像、GPS 等。架构的创建应实现四个 V（容量、速度、多样性和真实性），如[第 2 章](#c02.xhtml)所述。该架构还必须具有经济可扩展性、足够的响应时间、多种硬件选项（由于硬件故障），并具有内置安全性以防止未经授权访问机密详细数据。

## 大数据的战略意义——挑战

要将大数据作为组织的工具，必须首先解决一些关键的战略问题。如果在流程开始时忽视了战略问题，可能难以成功实施大数据。以下列表可作为思考实施大数据平台的起点：

### 战略挑战

-   确立目的适用性
-   提供整体系统架构规划

### 技术挑战

-   获取数据访问权
-   获取相关方法论和元数据的访问权
-   确立数据集的来源和血缘
-   就城市（准确性、保真度）、不确定性、误差、偏差、可靠性和校准来确立数据集质量
-   解决安全顾虑
-   技术可行性
-   现有数据仓库架构
-   不成熟的新系统或所选数据的可靠性
-   缺乏大数据的元数据和模式
-   缺乏工具
-   企业级产品和工具的可用性
-   高延迟
-   在集群内运行

### 资源或能力挑战

-   实施大规模大数据计划的能力
-   离散数据的整合
-   收集数据的质量和成本
-   预算限制
-   成本过高

### 人员挑战

-   大数据分析的实验和试验测试
-   网络传输的完整性
-   数据质量差
-   处理实时数据的能力

### 项目管理挑战

-   依赖多个可能无法协同工作的顾问
-   从正确的项目开始

### 变更管理挑战

-   制度变更管理
-   确保跨司法管辖区协作和通用标准
-   阻碍大数据收集和组织的不同部门系统
-   获取技术胜任的员工
-   陡峭的技术学习曲线
-   招聘合格人员
-   本质上是文化性的部门间障碍
-   不被接受或不被信任的数据
-   数据所有权，特别是与组织文化相关的方面
-   缺乏业务赞助
-   缺乏对商业案例的信心

### 合作伙伴挑战

-   与大数据生产者建立战略联盟
