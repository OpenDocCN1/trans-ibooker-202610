
MDS 将自身局限于将数据视为有界的批处理技术。相比之下，实时数据应用将数据视为无界的连续流。流式管道和实时分析数据库是将推动从 MDS 向实时数据栈演进的两大核心技术。虽然这些技术已存在一段时间，但快速成熟的托管云服务将使它们得到更广泛的部署。

在可预见的未来，流式技术将继续保持极速增长。这将伴随对流式数据业务效用的更清晰关注。直到目前，流式系统常被视为昂贵的新鲜玩意，或仅作为从 A 点到 B 点传输数据的“哑管道”。未来，流式处理将从根本上改变组织的技术和业务流程；数据架构师和工程师将引领这些根本性变革。

实时分析数据库支持对该数据的快速摄取和亚秒级查询。这些数据可以通过历史数据集进行丰富或关联。当结合流式管道和自动化，或具备实时分析能力的仪表盘时，全新层面的可能性将随之开启。你不再受限于缓慢运行的 ELT 流程、15 分钟一次的更新，或其他迟缓的环节。数据以连续流的形式移动。随着流式摄取变得更加普遍，批量摄取将变得越来越少见。为什么要在数据管道的源头制造批处理瓶颈？我们最终看待批量摄取的方式，将如同我们现在看待拨号调制解调器一样。

随着流式处理的兴起，我们预计数据转换将迎来一个“回归未来”的时刻。我们将从 ELT（数据库内转换）转向更像 ETL 的模式。我们暂时称之为*流式处理、转换和加载*（STL）。在流式上下文中，提取是一个持续的、连续的过程。当然，批量转换不会完全消失。批处理对于模型训练、季度报告等仍非常有用。但流式转换将成为常态。

虽然数据仓库和数据湖非常适合存储大量数据和执行临时查询，但它们并未针对低延迟数据摄取或快速移动数据上的查询进行良好优化。实时数据栈将由专为流式处理构建的 OLAP 数据库提供支持。如今，`Druid`、`ClickHouse`、`Rockset` 和 `Firebolt` 等数据库正引领潮流，为下一代数据应用的后端提供动力。我们预计流式技术将继续快速演进，新技术将层出不穷。

我们认为另一个适合颠覆的领域是数据建模，自 2000 年代初以来，该领域鲜有重大创新。你在[第 8 章](#ch08.html#queriescomma_modelingcomma_and_transfor)中了解到的传统面向批处理的数据建模技术，不适用于流式数据。新的数据建模技术将不在数据仓库中发生，而是发生在生成数据的系统中。我们预计数据建模将涉及某种上游定义层的概念——包括语义、指标、血缘和数据定义（参见[第 9 章](#ch09.html#serving_data_for_analyticscomma_machine)）——始于应用程序中数据生成之处。建模也将在数据流经完整生命周期的每个阶段发生，随着数据的流动和演变而进行。

## 数据与应用的融合

我们预计下一场革命将是应用层与数据层的融合。目前，应用位于一侧，而 MDS 位于另一侧。更糟糕的是，数据的创建未考虑其如何用于分析。因此，需要大量“胶带代码”来让系统相互通信。这种拼凑的、孤岛式的设置既笨拙又难看。

很快，应用栈将成为数据栈，反之亦然。应用将集成实时自动化和决策，由流式管道和 ML 提供支持。数据工程生命周期不一定会改变，但生命周期各阶段之间的时间将大幅缩短。大量创新将发生在改进实时数据栈工程体验的新技术和实践中。请关注旨在解决 OLTP 和 OLAP 混合用例的新兴数据库技术；特征存储也可能为 ML 用例扮演类似角色。

## 应用与 ML 之间的紧密反馈

另一个令我们兴奋的领域是应用与 ML 的融合。如今，应用和 ML 是分离的系统，就像应用和分析一样。软件工程师在这边做他们的事，数据科学家和 ML 工程师在那边做他们的事。

ML 非常适合数据以如此高速率和大量生成、以至于人类无法手动处理的场景。随着数据规模和速度的增长，这适用于所有场景。大量高速移动的数据，加上复杂的工作流和操作，都是 ML 的候选对象。随着数据反馈循环变短，我们预计大多数应用将集成 ML。随着数据移动得更快，应用与 ML 之间的反馈循环将更加紧密。实时数据栈中的应用是智能的，能够实时适应数据变化。这创造了一个不断变得更智能的应用和不断增加的业务价值的循环。

## 暗物质数据与……电子表格的崛起？！

我们讨论了快速移动的数据，以及随着应用、数据和 ML 更紧密地协作，反馈循环将如何缩短。本节可能看起来很奇怪，但我们需要解决当今数据世界中被广泛忽视的问题，尤其是工程师们。

使用最广泛的数据平台是什么？它是不起眼的电子表格。根据你读到的估算，电子表格的用户群在 7 亿到 20 亿人之间。电子表格是数据世界的暗物质。相当一部分数据分析在电子表格中运行，从未进入本书描述的那些复杂数据系统。在许多组织中，电子表格处理财务报告、供应链分析，甚至 CRM。

从本质上讲，什么是电子表格？*电子表格*是一种支持复杂分析的交互式数据应用。与纯代码工具（如 `pandas` [Python 数据分析库]）不同，电子表格面向整个用户谱系，从只会打开文件查看报告的人，到能编写复杂程序化数据处理脚本的高级用户。到目前为止，BI 工具未能为数据库带来可比拟的交互性。与 UI 交互的用户通常局限于在特定护栏内切片和切块数据，而非通用的可编程分析。

我们预测，一类新工具将会出现，它将电子表格的交互式分析能力与云 OLAP 系统的后端强大功能相结合。确实，已有一些候选者进入竞争行列。该产品类别的最终赢家可能继续沿用电子表格范式，也可能为与数据交互定义全新的界面习语。
