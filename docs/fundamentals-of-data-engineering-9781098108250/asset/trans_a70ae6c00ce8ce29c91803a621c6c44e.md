# 前言

这本书是如何诞生的？其起源深深植根于我们从数据科学转向数据工程的历程。我们常半开玩笑地称自己为*「康复中的数据科学家」*。我们都曾有过被分配到数据科学项目，却因缺乏适当基础而难以执行这些项目的经历。我们踏入数据工程领域，始于我们承担数据工程任务以构建基础和基础设施。

随着数据科学的兴起，公司大量投入资源招募数据科学人才，希望获得丰厚回报。然而，数据科学家往往要面对其背景和培训未涵盖的基本问题——数据收集、数据清洗、数据访问、数据转换和数据基础设施。这些正是数据工程旨在解决的问题。

## 本书不包含的内容

在介绍本书的内容和您将从中获得什么之前，让我们先快速说明一下本书*不*包含的内容。本书不讲解基于特定工具、技术或平台的数据工程。虽然许多优秀书籍从这一角度切入数据工程技术，但这类书籍的保质期较短。相反，我们专注于数据工程背后的基本概念。

## 本书的内容

本书旨在填补当前数据工程内容和资料的空白。虽然针对特定数据工程工具和技术的技术资源不胜枚举，但人们难以理解如何将这些组件组装成一个适用于现实世界的连贯整体。本书串联起端到端数据生命周期的各个环节。它将向您展示如何将各种技术拼接在一起，以满足分析师、数据科学家和机器学习工程师等下游数据消费者的需求。本书可作为 O’Reilly 讲解特定技术、平台和编程语言细节的书籍的补充。

本书的核心思想是*数据工程生命周期*：数据生成、存储、摄入、转换和服务。自数据诞生以来，我们见证了无数特定技术和供应商产品的兴衰更替，但数据工程生命周期阶段基本保持不变。有了这个框架，读者将获得将技术应用于现实业务问题的合理理解。

我们的目标是勾勒出跨越两个维度的原则。首先，我们希望将数据工程提炼为能够涵盖*任何相关技术*的原则。其次，我们希望提出能经受*时间*考验的原则。我们希望这些理念能反映过去二十年数据技术变革中的经验教训，并使我们的思维框架在未来十年甚至更久仍保持实用。

有一点须注意：我们毫不掩饰地采取云优先策略。我们将云视为一项根本性的变革性发展，将持续数十年；大多数本地数据系统和工作负载最终都将迁移到云托管。我们假设基础设施和系统是*临时性*和*可扩展*的，并且数据工程师将倾向于在云中部署托管服务。话虽如此，本书的大多数概念也适用于非云环境。

## 谁应该阅读本书

本书的主要目标读者是技术从业者、中高级软件工程师、数据科学家或有意转向数据工程的分析师；或是在特定技术内部深耕、但希望建立更全面视角的数据工程师。次要目标读者是与技术从业者紧密合作的数据利益相关者——例如，有技术背景、管理数据工程师团队的数据团队负责人，或希望将本地技术迁移到云解决方案的数据仓库总监。

理想情况下，您充满好奇并渴望学习——否则为什么要读这本书？您通过阅读关于数据仓库/数据湖、批处理和流处理系统、编排、建模、管理、分析、云技术发展等方面的书籍和文章，保持对数据技术和趋势的了解。本书将帮助您将所读内容编织成跨技术和范式的数据工程完整图景。

## 先决条件

我们假设读者对企业环境中常见的数据系统类型相当熟悉。此外，我们假设读者对 SQL 和 Python（或其他编程语言）有一定了解，并有云服务使用经验。

有大量资源可供有志成为数据工程师的人练习 Python 和 SQL。免费在线资源比比皆是（博客文章、教程网站、YouTube 视频），每年也有许多新的 Python 书籍出版。

云为获取数据工具的实操经验提供了前所未有的机会。我们建议有志成为数据工程师的人在 AWS、Azure、Google Cloud Platform、Snowflake、Databricks 等云服务上注册账号。请注意，这些平台许多都提供*免费套餐*选项，但读者在学习时应密切关注费用，并使用少量数据和单节点集群。

在企业环境之外熟悉企业数据系统仍然很难，这给尚未获得第一份数据工作的有志数据工程师设置了一定障碍。本书可以提供帮助。我们建议数据新手先阅读高层概念，然后查看每章末尾「附加资源」部分的材料。第二次阅读时，记下任何不熟悉的术语和技术。您可以利用 Google、Wikipedia、博客文章、YouTube 视频和供应商网站来熟悉新术语，填补理解上的空白。
