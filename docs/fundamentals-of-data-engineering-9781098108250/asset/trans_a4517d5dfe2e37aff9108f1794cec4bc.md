# Queries（查询）

查询是数据工程、数据科学和分析的基础部分。在了解转换的底层模式和技术之前，你需要理解什么是查询、它们如何在各种数据上工作，以及提升查询性能的技术。

本节主要关注表格和半结构化数据上的查询。作为数据工程师，你最频繁地查询和转换这些数据类型。在深入探讨查询、数据建模和转换的更复杂主题之前，让我们先回答一个简单的问题：什么是查询？

## What Is a Query?（什么是查询？）

我们经常遇到会写SQL但不熟悉查询底层工作原理的人。如果你是经验丰富的数据工程师，其中一些关于查询的入门材料可能比较熟悉；请随意跳过。

`query`允许你检索并操作数据。回顾我们在[第5章](#ch05.html#data_generation_in_source_systems)关于CRUD的对话。当查询检索数据时，它发出读取记录模式的请求。这是CRUD中的`R`（read）。你可能会发出查询获取表`foo`的所有记录，如`SELECT * FROM foo`。或者，你可能应用谓词（逻辑条件）按`id`为`1`的记录过滤数据，使用SQL查询`SELECT * FROM foo WHERE id=1`。

许多数据库允许你创建、更新和删除数据。这些是CRUD中的`CUD`；你的查询将创建、修改或销毁现有记录。让我们回顾一下使用查询语言时会遇到的其他常见缩写。

### Data definition language（数据定义语言）

从高层来看，你首先需要创建数据库对象，然后才能添加数据。你将使用`data definition language`（DDL）命令对数据库对象（如数据库本身、模式、表或用户）执行操作；DDL定义数据库中对象的状态。

数据工程师使用常见的SQL DDL表达式：`CREATE`、`DROP`和`UPDATE`。例如，你可以使用DDL表达式`CREATE DATABASE bar`创建数据库。之后，你也可以创建新表（`CREATE table bar_table`）或删除表（`DROP table bar_table`）。

### Data manipulation language（数据操作语言）

使用DDL定义数据库对象后，你需要在这些对象中添加和修改数据，这是`data manipulation language`（DML）的主要目的。作为数据工程师，你将使用的一些常见DML命令如下：

```
SELECT
INSERT
UPDATE
DELETE
COPY
MERGE
```

例如，你可以`INSERT`新记录到数据库表，`UPDATE`现有记录，并`SELECT`特定记录。

### Data control language（数据控制语言）

你很可能希望限制对数据库对象的访问，并精细控制`who`有权访问`what`。`data control language`（DCL）允许你通过使用SQL命令（如`GRANT`、`DENY`和`REVOKE`）控制对数据库对象或数据的访问。

让我们通过一个使用DCL命令的简短示例进行演示。一位名叫Sarah的新数据科学家加入你的公司，她需要对名为`data_science_db`的数据库拥有只读访问权限。你通过以下DCL命令授予Sarah访问该数据库的权限：

```
GRANT SELECT ON data_science_db TO user_name Sarah;
```

就业市场火热，Sarah在公司工作仅几个月就被一家大型科技公司挖走了。再见了，Sarah！作为一名注重安全的数据工程师，你移除Sarah读取数据库的能力：

```
REVOKE SELECT ON data_science_db TO user_name Sarah;
```

访问控制请求和问题很常见，理解DCL将帮助你解决你或团队成员无法访问所需数据的问题，并防止访问不需要的数据。

### Transaction control language（事务控制语言）

顾名思义，`transaction control language`（TCL）支持控制事务细节的命令。通过TCL，我们可以定义提交检查点、操作回滚的条件等。两个常见的TCL命令包括`COMMIT`和`ROLLBACK`。

![](assets/fode_0802.png)

虽然运行查询看起来很简单——写代码、运行、获取结果——但在底层发生了很多事情。当你执行SQL查询时，以下是发生的过程摘要：

1.  数据库引擎编译SQL，解析代码以检查语义是否正确，确保引用的数据库对象存在，且当前用户拥有访问这些对象的适当权限。

2.  SQL代码被转换为字节码。该字节码以高效、机器可读的格式表达必须在数据库引擎上执行的步骤。

3.  数据库的查询优化器分析字节码，确定如何执行查询，重新排序和重构步骤，以尽可能高效地利用可用资源。

4.  查询被执行，生成结果。

## The Query Optimizer（查询优化器）

查询的执行时间可能截然不同，取决于它们如何被执行。查询优化器的工作是通过将查询分解为适当的步骤并按高效顺序执行，来优化查询性能并最小化成本。优化器将评估连接、索引、数据扫描大小和其他因素。查询优化器尝试以成本最低的方式执行查询。

查询优化器是查询性能的基础。每个数据库都不同，以明显和微妙的不同方式执行查询。你不会直接与查询优化器打交道，但理解其部分功能将帮助你编写性能更好的查询。你需要知道如何分析查询性能，使用如执行计划或查询分析等工具，下一节将介绍。

## Improving Query Performance（提升查询性能）

在数据工程中，你不可避免地会遇到性能不佳的查询。知道如何识别和修复这些查询非常宝贵。不要与数据库对抗。学会发挥其优势，弥补其弱点。本节展示提升查询性能的各种方法。
