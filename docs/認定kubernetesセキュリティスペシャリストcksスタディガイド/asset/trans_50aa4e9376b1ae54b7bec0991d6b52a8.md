## 设置 Webhook 后端

Webhook 后端的设置与日志后端不同。需要指示 API 服务器将文件替换为向外部服务发送 HTTP(S) 请求。外部服务、webhook 以及进行身份验证所需的凭据的配置，与 [“ImagePolicyWebhook Admission Controller 插件的配置](#ch06.html#configuring-imagepolicywebhook-admission-controller-plugin)” 中所做的配置类似，使用 [`kubeconfig`](https://oreil.ly/bUnmO) 文件定义。

将标志 `--audit-webhook-config-file` 添加到文件 `/etc/kubernetes/manifests/kube-apiserver.yaml` 中的 API 服务器进程，并指向 kubeconfig 文件的位置。标志 `--audit-webhook-initial-backoff` 定义在向外部服务发出初始请求后重试前的等待时间。需要将标志 `--audit-policy-file` 分配给指向审计策略文件。

# 概要

Kubernetes 集群中事件的监控和日志记录是所有管理员的重要职责。我们使用 Falco 来识别和过滤与安全相关的事件。我们学习了各种配置文件的作用和语法，以及如何在日志中发现相关警报。

除了采用行为分析工具外，还希望设置到达 API 服务器的请求的审计日志记录。审计日志记录将配置的事件记录到控制平面节点上的文件或通过 HTTP(S) 调用到外部服务的后端之一。这里将介绍为 API 服务器进程启用审计日志记录的过程。

更安全容器的明智一步是使容器不可变。不可变容器仅支持只读文件系统，防止潜在攻击者安装恶意软件。如果在容器内运行的应用程序需要写入数据，请挂载卷。使用无发行版的容器镜像，以防止攻击者进入容器的 shell。

# 章节，“集群的设置”

1. 创建名为 `deny-egress-external.yaml` 的文件以定义网络策略。网络策略应将 Pod 选择器设置为 `app=backend`，并定义 `Egress` 策略类型。确保允许协议 UDP 和 TCP 的端口 53。Egress 策略的命名空间选择器应使用 `{}` 选择所有命名空间：

```
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-egress-external
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Egress
  egress:
  - to:
    - namespaceSelector: {}
    ports:
    - port: 53
      protocol: UDP
    - port: 53
      protocol: TCP
```

执行 `apply` 命令以从 YAML 文件实例化网络策略对象：

```
$ kubectl apply -f deny-egress-external.yaml
```
